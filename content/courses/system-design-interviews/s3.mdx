S3 (Simple Storage Service) é o **armazenamento de objetos** da AWS e a referência do tipo. Você guarda arquivos de qualquer tamanho (de bytes a 5 TB por objeto) em buckets, identificados por uma chave, e paga pelo que usar. Em quase todo desenho com imagens, vídeos, backups ou data lake, S3 é onde os bytes ficam.

## Modelo

- **Bucket:** contêiner com nome único global.
- **Objeto:** os bytes mais metadados, endereçado por uma **chave** como `fotos/2025/01/abc.jpg`. Não há diretórios de verdade: a barra é só parte do nome.
- **API HTTP:** `PUT`, `GET`, `DELETE`, `LIST`. Objetos são imutáveis: para alterar, você grava de novo.

Diferente de um sistema de arquivos, não existe edição parcial nem rename barato. Diferente de um banco, não há consulta por conteúdo.

## Propriedades importantes

| Propriedade | Valor típico |
| --- | --- |
| Durabilidade | 99,999999999% (11 noves), dados replicados entre zonas |
| Disponibilidade | 99,99% na classe padrão |
| Consistência | Forte para leitura após escrita e listagem |
| Escala | Praticamente ilimitada |
| Latência | Dezenas de ms (não serve para acesso de microssegundos) |
| Taxa por prefixo | Milhares de requisições por segundo por prefixo |

## Recursos que você vai citar

- **Upload multipart:** divide arquivos grandes em partes enviadas em paralelo e retomáveis.
- **URLs pré-assinadas:** o servidor gera um link temporário para o cliente enviar ou baixar direto do S3, sem passar o tráfego pela sua API.
- **Classes de armazenamento e lifecycle:** Standard, Infrequent Access, Glacier. Regras movem objetos esfriados para classes mais baratas ou os expiram.
- **Versionamento e replicação entre regiões** para proteção e latência.
- **Notificações de eventos:** um upload dispara Lambda, SQS ou SNS, ideal para pipelines (gerar miniaturas, transcodificar).
- **CDN na frente:** CloudFront serve objetos populares perto do usuário.

```text
cliente --(1) pede URL pré-assinada--> API
cliente --(2) PUT direto----------------> S3
S3 --(3) evento----> fila ---> worker (miniatura, vírus, indexação)
```

## Armadilhas

- **Metadados no lugar errado:** S3 é ruim para consultar. Guarde chave, dono e atributos num banco, e os bytes no S3.
- **Chaves sequenciais** num único prefixo podem limitar a taxa em volumes extremos; distribua prefixos.
- **Muitos objetos minúsculos** custam caro em requisições; agrupe.
- **LIST** em milhões de objetos é lento. Mantenha um índice próprio.
- Servir tudo sem CDN eleva custo de saída de dados e latência.

## Na entrevista

Regra simples: arquivo grande ou não estruturado vai para o S3, e o banco guarda só a referência. Cite URLs pré-assinadas para tirar o upload do caminho da API e lifecycle para controlar custo. Follow-ups: como retomar um upload interrompido (multipart), como garantir que o arquivo foi recebido antes de publicar o registro (evento ou confirmação do cliente) e como reduzir custo de dados antigos (classes frias).
