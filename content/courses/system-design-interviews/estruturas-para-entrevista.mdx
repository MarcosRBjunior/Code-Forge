Na hora de aprofundar, muitas soluções de system design se apoiam numa estrutura de dados específica. Saber qual estrutura resolve cada tipo de problema, e o que ela custa, transforma uma resposta vaga ("uso um índice") em uma resposta concreta ("uso um geohash com prefixo de 6 caracteres"). Estas são as que mais aparecem.

## Hash table e hash consistente

A base de caches, armazenamentos chave-valor e deduplicação. Leitura e escrita em tempo constante médio. Em escala distribuída, vira **hash consistente**, que decide em qual nó cada chave mora e minimiza remapeamento quando o cluster muda.

**Aparece em:** cache distribuído, chave-valor, balanceamento com afinidade.

## Árvore B e LSM-tree

Os dois motores de armazenamento mais comuns:

| | Árvore B | LSM-tree |
| --- | --- | --- |
| Escrita | Atualiza no lugar; mais lenta sob carga alta | Acumula em memória e grava em lote; muito rápida |
| Leitura | Rápida e previsível | Pode consultar vários arquivos; usa filtros para acelerar |
| Uso típico | Bancos relacionais | Bancos de escrita intensa (wide-column, chave-valor) |

Saber isso ajuda a justificar por que um banco aguenta muita escrita e outro é melhor para leituras com índices variados.

## Bloom filter

Estrutura probabilística que responde "este item **talvez** esteja no conjunto" ou "**com certeza** não está". Usa pouquíssima memória e nunca dá falso negativo, mas pode dar falso positivo.

```python
import hashlib

class BloomFilter:
    def __init__(self, size=1000, hashes=3):
        self.size = size
        self.hashes = hashes
        self.bits = [False] * size

    def _positions(self, item):
        for i in range(self.hashes):
            digest = hashlib.sha256(f"{i}:{item}".encode()).hexdigest()
            yield int(digest, 16) % self.size

    def add(self, item):
        for p in self._positions(item):
            self.bits[p] = True

    def might_contain(self, item):
        return all(self.bits[p] for p in self._positions(item))

bf = BloomFilter()
bf.add("https://exemplo.com/a")
print(bf.might_contain("https://exemplo.com/a"))  # True
print(bf.might_contain("https://exemplo.com/b"))  # quase certamente False
```

**Aparece em:** web crawler (já visitei esta URL?), LSM-trees (evitar ler arquivos que não têm a chave), verificação rápida de nomes já usados.

## Trie

Árvore de prefixos: cada nó representa um caractere, e o caminho da raiz forma a palavra. Encontrar todas as palavras com um prefixo é proporcional ao tamanho do prefixo. Para autocomplete, cada nó pode guardar os K termos mais populares abaixo dele, deixando a resposta pronta.

**Aparece em:** autocomplete, roteamento por prefixo de IP, dicionários.

## Geohash, quadtree e índices espaciais

Para "encontre motoristas a menos de 2 km", você precisa indexar duas dimensões.

- **Geohash** codifica latitude e longitude numa string; prefixos comuns indicam proximidade. Fácil de guardar em qualquer banco ou cache.
- **Quadtree** divide o mapa recursivamente em quatro quadrantes até cada um ter poucos pontos. Adapta-se à densidade (centro da cidade vira células pequenas).
- **Grades hexagonais** dividem o mundo em células de tamanho uniforme, úteis para agregações por região.

**Aparece em:** apps de corrida, busca de restaurantes, entrega.

## Skip list e sorted set

Uma lista ordenada com "atalhos" em vários níveis, com busca, inserção e consulta por posição em tempo logarítmico. É a base dos sorted sets de caches em memória, muito usados para rankings.

**Aparece em:** leaderboards, top K, filas por prioridade, janelas deslizantes de rate limiting.

## Estruturas para contagem aproximada

Quando contar exatamente custa caro demais:

- **HyperLogLog:** estima quantos itens distintos existem (usuários únicos) com alguns KB, erro em torno de 1%.
- **Count-Min Sketch:** estima a frequência de cada item num fluxo usando uma matriz pequena de contadores; superestima, nunca subestima.

**Aparece em:** analytics, top K de termos buscados, detecção de itens populares.

<Callout type="tip" title="Diga o custo junto com a estrutura">
Ao citar uma estrutura probabilística, mencione o erro aceito: "uso HyperLogLog, com cerca de 1% de erro, porque o painel não precisa de número exato e economizo gigabytes de memória".
</Callout>

## Outras que vale reconhecer

- **Heap:** manter os K maiores de um fluxo.
- **Árvore de Merkle:** comparar réplicas e achar diferenças trocando poucos hashes.
- **Log append-only:** base de filas, replicação e bancos.
- **Índice invertido:** palavra para lista de documentos; coração da busca textual.
