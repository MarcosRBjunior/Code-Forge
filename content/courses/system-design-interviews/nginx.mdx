Nginx é um servidor web de alto desempenho que, em desenho de sistemas, aparece sobretudo como **reverse proxy** e **load balancer**. Ele fica na frente dos seus servidores de aplicação, recebe as conexões dos clientes e as encaminha, adicionando terminação TLS, cache, compressão e limites de taxa.

## Por que ele é eficiente

Nginx usa um modelo orientado a eventos: poucos processos worker, cada um tratando milhares de conexões com I/O não bloqueante, em vez de uma thread por conexão. Por isso uma única instância lida com dezenas de milhares de conexões simultâneas com pouca memória.

## Papéis comuns

### Reverse proxy

```text
cliente --HTTPS--> [Nginx] --HTTP--> app 1
                      |-----------> app 2
                      |-----------> app 3
```

Benefícios: esconde a topologia interna, centraliza TLS, permite trocar servidores sem o cliente notar.

### Load balancer (camada 7)

Distribui requisições entre um grupo de servidores (`upstream`):

- **Round robin:** padrão, em rodízio.
- **Least connections:** envia ao servidor com menos conexões ativas.
- **IP hash:** o mesmo cliente cai sempre no mesmo servidor (afinidade simples).
- **Health checks passivos:** servidores que falham são removidos temporariamente. Os checks ativos ficam no Nginx Plus ou em módulos.

```text
upstream app {
    least_conn;
    server 10.0.0.1:8080;
    server 10.0.0.2:8080;
}
server {
    listen 443 ssl;
    location / { proxy_pass http://app; }
}
```

### Outros usos

- **Terminação TLS:** descriptografa na borda e fala HTTP simples com o back-end.
- **Servir arquivos estáticos** direto do disco, mais rápido que passar pela aplicação.
- **Cache de respostas** (`proxy_cache`) para conteúdo repetido.
- **Rate limiting** (`limit_req`) para proteger o back-end.
- **Compressão gzip/brotli** e suporte a HTTP/2.
- **Proxy de WebSocket** com o upgrade de conexão.

## Nginx versus balanceadores gerenciados

| Opção | Característica |
| --- | --- |
| Nginx | Controle total, configuração flexível, você opera e escala |
| ALB/NLB (AWS) | Gerenciado, integra com autoscaling e certificados |
| HAProxy | Foco em balanceamento, métricas ricas |
| API Gateway | Autenticação, quotas e roteamento orientado a API |

## Armadilhas

- **Ponto único de falha:** uma instância só derruba tudo. Use pares com IP virtual (keepalived) ou balanceador gerenciado na frente.
- **Afinidade de sessão** esconde o problema de estado: prefira aplicações stateless.
- Timeouts mal configurados causam erros 502 e 504.
- Uploads grandes exigem ajustar `client_max_body_size` e buffers.
- Reload de configuração com erro pode afetar o tráfego; valide antes (`nginx -t`).

## Na entrevista

Você quase nunca precisa detalhar a configuração. Basta posicionar o Nginx (ou "um load balancer") entre o cliente e os servidores, dizer o algoritmo e onde termina o TLS. Follow-ups: como evitar que o próprio balanceador seja gargalo ou ponto único de falha (vários, com DNS ou anycast), diferença entre camada 4 e 7 e como remover servidores doentes da rotação.
