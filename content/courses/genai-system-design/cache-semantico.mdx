Um cache tradicional usa a requisição exata como chave. Para LLMs isso rende pouco: "como troco minha senha?" e "como faço para mudar a senha?" são textos diferentes com a mesma resposta. O **cache semântico** troca a igualdade de strings por similaridade de significado: transforma a pergunta num vetor (embedding), procura perguntas já respondidas com vetor próximo e, se a similaridade passar de um limiar, devolve a resposta guardada sem chamar o modelo. Quando funciona, a resposta sai em milissegundos e custa quase nada.

## Como funciona

```text
pergunta -> normaliza -> cache exato (hash) --acerto--> resposta
                              | erro
                              v
                      embedding da pergunta
                              v
                indice vetorial (vizinho mais proximo)
                 similaridade >= limiar? --sim--> resposta guardada
                              | nao
                              v
                    chama o modelo -> grava (vetor, resposta, metadados, TTL)
```

Algumas decisões aparecem em qualquer implementação:

- **Duas camadas.** Um cache exato por hash na frente é barato e pega repetições literais (comuns em botões e sugestões prontas). O semântico vem depois.
- **Escopo da chave.** A mesma pergunta pode ter respostas diferentes por idioma, cliente, versão de prompt ou permissões do usuário. Esses atributos entram como filtro obrigatório na busca, nunca só a similaridade.
- **Limiar.** É o parâmetro mais delicado. Baixo demais devolve respostas para perguntas que só parecem iguais; alto demais quase nunca acerta.
- **Validade.** Respostas que dependem de dados que mudam (preço, estoque, status de pedido) precisam de TTL curto ou nem devem entrar no cache.

## O limiar na prática

O programa abaixo usa um embedding de brinquedo (contagem de palavras com sinônimos normalizados) só para ilustrar o mecanismo, sem bibliotecas externas. O que importa é o efeito do limiar: com valores diferentes, mudam os acertos e os **falsos positivos**, isto é, respostas devolvidas para perguntas que pediam outra coisa.

```python
import math
from collections import Counter

SINONIMOS = {"troco": "trocar", "cancelo": "cancelar", "mudar": "trocar", "alterar": "trocar", "redefinir": "trocar", "faco": "", "para": "",
             "como": "", "eu": "", "o": "", "a": "", "minha": "", "meu": "", "de": "", "posso": ""}

def emb(texto):
    palavras = [SINONIMOS.get(p, p) for p in texto.lower().replace("?", "").split()]
    return Counter(p for p in palavras if p)

def cos(a, b):
    num = sum(a[k] * b[k] for k in a)
    return num / (math.sqrt(sum(v * v for v in a.values())) * math.sqrt(sum(v * v for v in b.values())))

cache = {"como troco minha senha?": "Acesse Perfil > Seguranca > Trocar senha.",
         "como cancelo meu plano?": "Acesse Assinatura > Cancelar plano."}
vetores = {q: emb(q) for q in cache}

consultas = [  # (pergunta, pergunta do cache que seria a resposta certa ou None)
    ("como faco para mudar a senha?", "como troco minha senha?"),
    ("posso alterar minha senha agora", "como troco minha senha?"),
    ("como troco meu email?", None),
    ("como cancelo meu pedido?", None),
    ("quero redefinir a senha do app", "como troco minha senha?"),
]

for limiar in (0.45, 0.7, 0.9):
    acertos = falsos = 0
    for q, certo in consultas:
        melhor = max(vetores, key=lambda k: cos(emb(q), vetores[k]))
        if cos(emb(q), vetores[melhor]) >= limiar:
            if melhor == certo:
                acertos += 1
            else:
                falsos += 1
    print(f"limiar {limiar}: acertos={acertos} falsos positivos={falsos} chamadas ao modelo={len(consultas) - acertos - falsos}")

# Economia mensal hipotetica com 30% de acertos
req_mes, custo_llm, custo_cache = 50_000_000, 0.002, 0.00005
taxa = 0.30
economia = req_mes * taxa * (custo_llm - custo_cache) - req_mes * (1 - taxa) * custo_cache
print(f"economia mensal estimada: US$ {economia:,.0f}")

static final Map<String, String> SINONIMOS = new HashMap<>();
static {
    String[] pares = {"troco", "trocar", "cancelo", "cancelar", "mudar", "trocar", "alterar", "trocar", "redefinir", "trocar",
                      "faco", "", "para", "", "como", "", "eu", "", "o", "", "a", "", "minha", "", "meu", "", "de", "", "posso", ""};
    for (int i = 0; i < pares.length; i += 2) SINONIMOS.put(pares[i], pares[i + 1]);
}

// "embedding" de brinquedo: contagem das palavras normalizadas (o Counter do Python)
static Map<String, Integer> emb(String texto) {
    Map<String, Integer> contagem = new HashMap<>();
    for (String p : texto.toLowerCase().replace("?", "").split("\\s+")) {
        p = SINONIMOS.getOrDefault(p, p);
        if (!p.isEmpty()) contagem.merge(p, 1, Integer::sum);
    }
    return contagem;
}

static double norma(Map<String, Integer> x) {
    double s = 0;
    for (int v : x.values()) s += v * v;
    return Math.sqrt(s);
}

static double cos(Map<String, Integer> a, Map<String, Integer> b) {
    double num = 0;
    for (Map.Entry<String, Integer> e : a.entrySet()) num += e.getValue() * b.getOrDefault(e.getKey(), 0);
    return num / (norma(a) * norma(b));
}

using namespace std;

const map<string, string> SINONIMOS = {{"troco", "trocar"}, {"cancelo", "cancelar"}, {"mudar", "trocar"}, {"alterar", "trocar"},
                                       {"redefinir", "trocar"}, {"faco", ""}, {"para", ""}, {"como", ""}, {"eu", ""}, {"o", ""},
                                       {"a", ""}, {"minha", ""}, {"meu", ""}, {"de", ""}, {"posso", ""}};

// "embedding" de brinquedo: contagem das palavras normalizadas (o Counter do Python)
map<string, int> emb(const string& texto) {
    string limpo;
    for (char c : texto) {
        if (c != '?') limpo += (char)tolower((unsigned char)c);
    }
    map<string, int> contagem;
    istringstream in(limpo);
    string p;
    while (in >> p) {
        auto it = SINONIMOS.find(p);
        if (it != SINONIMOS.end()) p = it->second;
        if (!p.empty()) contagem[p]++;
    }
    return contagem;
}

double norma(const map<string, int>& x) {
    double s = 0;
    for (auto& [_, v] : x) s += v * v;
    return sqrt(s);
}

double cos(const map<string, int>& a, const map<string, int>& b) {
    double num = 0;
    for (auto& [k, v] : a) {
        auto it = b.find(k);
        if (it != b.end()) num += v * it->second;
    }
    return num / (norma(a) * norma(b));
}

int main() {
    vector<pair<string, string>> cache = {{"como troco minha senha?", "Acesse Perfil > Seguranca > Trocar senha."},
                                          {"como cancelo meu plano?", "Acesse Assinatura > Cancelar plano."}};
    vector<pair<string, map<string, int>>> vetores; // na ordem do cache, como o dict
    for (auto& [q, _] : cache) vetores.push_back({q, emb(q)});

    vector<pair<string, optional<string>>> consultas = {  // (pergunta, pergunta do cache que seria a resposta certa ou nada)
        {"como faco para mudar a senha?", "como troco minha senha?"},

        {"como troco meu email?", nullopt},

    };

    for (double limiar : {0.45, 0.7, 0.9}) {
        int acertos = 0, falsos = 0;
        for (auto& [q, certo] : consultas) {
            size_t melhor = 0;
            for (size_t k = 1; k < vetores.size(); k++) { // como o max(): no empate fica o primeiro
                if (cos(emb(q), vetores[k].second) > cos(emb(q), vetores[melhor].second)) melhor = k;

            if (cos(emb(q), vetores[melhor].second) >= limiar) {
                if (certo && vetores[melhor].first == *certo) acertos += 1;
                else falsos += 1;
            }
        }

    printf("economia mensal estimada: US$ %s\n", s.c_str());
}

    ["troco"] = "trocar", ["cancelo"] = "cancelar", ["mudar"] = "trocar", ["alterar"] = "trocar", ["redefinir"] = "trocar",

// "embedding" de brinquedo: contagem das palavras normalizadas (o Counter do Python)
static Dictionary<string, int> Emb(string texto) {
    var contagem = new Dictionary<string, int>();
    foreach (var palavra in texto.ToLowerInvariant().Replace("?", "").Split(new[] { ' ' }, StringSplitOptions.RemoveEmptyEntries)) {
        string p;
        if (!SINONIMOS.TryGetValue(palavra, out p)) p = palavra;
        if (p.Length > 0) contagem[p] = (contagem.ContainsKey(p) ? contagem[p] : 0) + 1;
    }
    return contagem;
}

static double Cos(Dictionary<string, int> a, Dictionary<string, int> b) {
    double num = 0;
    foreach (var par in a) {
        int vb;
        if (b.TryGetValue(par.Key, out vb)) num += par.Value * vb;
    }
    return num / (Math.Sqrt(a.Values.Sum(v => v * v)) * Math.Sqrt(b.Values.Sum(v => v * v)));
}

func emb(texto string) map[string]int {
	contagem := map[string]int{}
	for _, p := range strings.Fields(strings.ReplaceAll(strings.ToLower(texto), "?", "")) {

			p = s

		if p != "" {
			contagem[p]++
		}
	}
	return contagem
}

	s := 0.0

		fmt.Printf("limiar %v: acertos=%d falsos positivos=%d chamadas ao modelo=%d\n", limiar, acertos, falsos, len(consultas)-acertos-falsos)
	}

	// Economia mensal hipotetica com 30% de acertos
	reqMes, custoLlm, custoCache := 50_000_000.0, 0.002, 0.00005
	taxa := 0.30
	economia := reqMes*taxa*(custoLlm-custoCache) - reqMes*(1-taxa)*custoCache
	s := fmt.Sprintf("%.0f", economia)
	for i := len(s) - 3; i > 0; i -= 3 { // agrupa milhares, como o {:,}
		s = s[:i] + "," + s[i:]
	}
	fmt.Printf("economia mensal estimada: US$ %s\n", s)
}
```

Com limiar baixo, "como troco meu email?" e "como cancelo meu pedido?" recebem respostas de outras perguntas: falsos positivos, que são o pior tipo de erro, porque a resposta sai confiante e errada. Com limiar alto, quase nada acerta e o cache só custa. O valor certo sai de um conjunto rotulado de pares de perguntas do seu domínio, medindo precisão e taxa de acerto para vários limiares, exatamente como no programa. Repare também que o cálculo de economia desconta o custo de calcular o embedding e buscar no índice nas requisições que erram o cache.

## Trade-offs

| Decisão | A favor | Contra |
| --- | --- | --- |
| Limiar alto | Poucas respostas erradas | Taxa de acerto baixa |
| Limiar baixo | Mais economia | Respostas confiantes para a pergunta errada |
| Cache por usuário | Seguro para dados pessoais | Quase nenhum reaproveitamento |
| Cache global | Máximo reaproveitamento | Risco de vazar dados entre usuários |

<Callout type="warning" title="Cache semântico pode vazar dados">
Se uma resposta contém informação de um usuário ("seu pedido 123 chega amanhã") e vai para um cache global, outro usuário pode recebê-la. Só coloque no cache global respostas genéricas, ou particione pelo escopo de permissão.
</Callout>

## Onde ele rende e onde não rende

Rende em suporte ao cliente, FAQs e assistentes internos, onde muitas pessoas fazem as mesmas perguntas. Rende pouco em conversas longas, porque a resposta depende do histórico, e em tarefas criativas, em que o usuário espera variedade. Uma variação útil é cachear **etapas intermediárias** em vez da resposta final: resultados de recuperação de documentos, embeddings de documentos e o prefixo do prompt (cache de prefixo no servidor de inferência), que reduzem custo mesmo quando a resposta final precisa ser nova.

## Na entrevista

Proponha o cache semântico quando os requisitos indicarem perguntas repetidas, e mostre que você conhece os riscos: escolha do limiar com dados rotulados, filtros por escopo (idioma, versão de prompt, permissões), TTL para conteúdo volátil e invalidação ao mudar o prompt ou a base de conhecimento. Follow-ups comuns: "como você mede se o cache está ajudando?" (taxa de acerto, falsos positivos em amostras auditadas, economia líquida) e "o que acontece ao atualizar a documentação?" (invalidar entradas ligadas aos documentos alterados ou versionar a chave pela versão da base).
