Uma GPU moderna faz uma quantidade enorme de operações por segundo, mas gerar texto para um único usuário quase não aproveita isso. No decode, cada novo token exige ler todos os pesos do modelo da memória da GPU para fazer uma conta relativamente pequena. O gargalo é a **largura de banda de memória**, não a computação. Se você ler os pesos uma vez e usá-los para avançar 32 conversas ao mesmo tempo, o custo por token cai quase 32 vezes. É por isso que batching é a alavanca número um de eficiência em servidores de inferência.

## Prefill e decode

Toda requisição passa por duas fases:

- **Prefill:** o prompt inteiro é processado de uma vez, em paralelo. É intensivo em computação e define o tempo até o primeiro token.
- **Decode:** os tokens de saída saem um de cada vez, cada um dependendo dos anteriores. É limitado por memória e define a velocidade de geração.

Para não recalcular tudo a cada novo token, o servidor guarda, para cada token já visto, os vetores de chave e valor da atenção em todas as camadas. Esse é o **KV cache**. Ele transforma o decode de quadrático em linear, mas cobra em memória: cada sequência ativa ocupa espaço proporcional ao seu comprimento.

## Quanto cabe na GPU

O tamanho do KV cache por token depende da arquitetura: duas matrizes (chave e valor) por camada, multiplicadas pelo número de cabeças de chave/valor, pela dimensão de cada cabeça e pelos bytes de cada número. Com um modelo hipotético:

A conclusão de entrevista: **contexto longo reduz o batch**. Se você reserva memória para o contexto máximo de cada requisição, mesmo que a maioria use pouco, desperdiça a maior parte da GPU. Servidores modernos alocam o KV cache em blocos pequenos sob demanda (a ideia de *paged attention*, inspirada em memória virtual), o que elimina a fragmentação e ainda permite compartilhar blocos de um prefixo comum, como um prompt de sistema longo, entre várias requisições.

## Batching estático versus contínuo

No **batching estático**, o servidor junta N requisições, roda até a mais longa terminar e só então aceita o próximo grupo. Se uma resposta tem 400 tokens e as outras 30, os slots das curtas ficam ociosos esperando. No **batching contínuo** (também chamado de *in-flight* ou por iteração), o agendador decide a cada passo de decode: quem terminou sai, quem está na fila entra. A simulação abaixo compara os dois com o mesmo limite de 4 slots.

<CodeTabs>

```python
saidas = [30, 400, 25, 60, 35, 380, 40, 50, 20, 45, 30, 350]  # tokens de saida
SLOTS = 4

def estatico(saidas):
    fim, t = [], 0
    for i in range(0, len(saidas), SLOTS):
        lote = saidas[i:i + SLOTS]
        fim += [t + s for s in lote]
        t += max(lote)
    return t, fim

def continuo(saidas):
    fila = list(enumerate(saidas))
    ativos, fim, t = {}, [0] * len(saidas), 0
    while fila or ativos:
        while fila and len(ativos) < SLOTS:
            i, s = fila.pop(0)
            ativos[i] = s
        t += 1
        for i in list(ativos):
            ativos[i] -= 1
            if ativos[i] == 0:
                fim[i] = t
                del ativos[i]
    return t, fim

for nome, f in (("estatico", estatico), ("continuo", continuo)):
    total, fim = f(saidas)
    uso = sum(saidas) / (SLOTS * total)
    print(f"{nome:<9} passos={total:>5}  latencia media={sum(fim) / len(fim):6.1f}  uso dos slots={uso:.0%}")
```

```java
import java.util.*;
import java.util.function.Function;

static final int SLOTS = 4;

// devolve {total, fim[0], fim[1], ...}: Java não tem tuplas
static int[] estatico(int[] saidas) {
    List<Integer> fim = new ArrayList<>();
    int t = 0;
    for (int i = 0; i < saidas.length; i += SLOTS) {
        int[] lote = Arrays.copyOfRange(saidas, i, Math.min(i + SLOTS, saidas.length));
        for (int s : lote) fim.add(t + s);
        t += Arrays.stream(lote).max().getAsInt();
    }
    int[] r = new int[fim.size() + 1];
    r[0] = t;
    for (int k = 0; k < fim.size(); k++) r[k + 1] = fim.get(k);
    return r;
}

static int[] continuo(int[] saidas) {
    ArrayDeque<int[]> fila = new ArrayDeque<>();
    for (int i = 0; i < saidas.length; i++) fila.add(new int[]{i, saidas[i]});
    LinkedHashMap<Integer, Integer> ativos = new LinkedHashMap<>();
    int[] fim = new int[saidas.length];
    int t = 0;
    while (!fila.isEmpty() || !ativos.isEmpty()) {
        while (!fila.isEmpty() && ativos.size() < SLOTS) {
            int[] par = fila.pollFirst();
            ativos.put(par[0], par[1]);
        }
        t += 1;
        for (int i : new ArrayList<>(ativos.keySet())) {
            ativos.put(i, ativos.get(i) - 1);
            if (ativos.get(i) == 0) {
                fim[i] = t;
                ativos.remove(i);
            }
        }
    }
    int[] r = new int[fim.length + 1];
    r[0] = t;
    System.arraycopy(fim, 0, r, 1, fim.length);
    return r;
}

public static void main(String[] args) {
    int[] saidas = {30, 400, 25, 60, 35, 380, 40, 50, 20, 45, 30, 350};  // tokens de saida
    LinkedHashMap<String, Function<int[], int[]>> estrategias = new LinkedHashMap<>();
    estrategias.put("estatico", s -> estatico(s));
    estrategias.put("continuo", s -> continuo(s));
    for (Map.Entry<String, Function<int[], int[]>> e : estrategias.entrySet()) {
        int[] r = e.getValue().apply(saidas);
        int total = r[0];
        int[] fim = Arrays.copyOfRange(r, 1, r.length);
        double uso = (double) Arrays.stream(saidas).sum() / (SLOTS * total);
        double media = (double) Arrays.stream(fim).sum() / fim.length;
        System.out.println(String.format(Locale.US, "%-9s passos=%5d  latencia media=%6.1f  uso dos slots=%.0f%%",
                e.getKey(), total, media, uso * 100));
    }
}
```

```cpp
#include <map>

#include <string>

#include <vector>
using namespace std;

const int SLOTS = 4;

pair<int, vector<int>> estatico(const vector<int>& saidas) {
    vector<int> fim;
    int t = 0;
    for (size_t i = 0; i < saidas.size(); i += SLOTS) {
        vector<int> lote(saidas.begin() + i, saidas.begin() + min(i + SLOTS, saidas.size()));
        for (int s : lote) fim.push_back(t + s);
        t += *max_element(lote.begin(), lote.end());
    }
    return {t, fim};
}

pair<int, vector<int>> continuo(const vector<int>& saidas) {
    deque<pair<int, int>> fila;
    for (int i = 0; i < (int)saidas.size(); i++) fila.push_back({i, saidas[i]});
    map<int, int> ativos;
    vector<int> fim(saidas.size(), 0);
    int t = 0;
    while (!fila.empty() || !ativos.empty()) {
        while (!fila.empty() && (int)ativos.size() < SLOTS) {
            auto [i, s] = fila.front();
            fila.pop_front();
            ativos[i] = s;
        }
        t += 1;
        for (auto it = ativos.begin(); it != ativos.end();) {
            it->second -= 1;
            if (it->second == 0) {
                fim[it->first] = t;
                it = ativos.erase(it);   // apagar devolve o próximo: seguro durante o laço
            } else {
                ++it;
            }
        }
    }
    return {t, fim};
}

int main() {
    vector<int> saidas = {30, 400, 25, 60, 35, 380, 40, 50, 20, 45, 30, 350};  // tokens de saida
    vector<pair<string, pair<int, vector<int>> (*)(const vector<int>&)>> estrategias = {
        {"estatico", estatico}, {"continuo", continuo}};
    for (auto& [nome, f] : estrategias) {
        auto [total, fim] = f(saidas);
        double uso = (double)accumulate(saidas.begin(), saidas.end(), 0) / (SLOTS * total);
        double media = (double)accumulate(fim.begin(), fim.end(), 0) / fim.size();
        printf("%-9s passos=%5d  latencia media=%6.1f  uso dos slots=%.0f%%\n", nome.c_str(), total, media, uso * 100);
    }
}
```

```csharp
using System;
using System.Collections.Generic;
using System.Globalization;
using System.Linq;

const int SLOTS = 4;

static int Estatico(int[] saidas, List<int> fim)
{
    int t = 0;
    for (int i = 0; i < saidas.Length; i += SLOTS)
    {
        var lote = saidas.Skip(i).Take(SLOTS).ToArray();
        foreach (int s in lote) fim.Add(t + s);
        t += lote.Max();
    }
    return t;
}

static int Continuo(int[] saidas, List<int> fim)
{
    var fila = new Queue<int[]>(saidas.Select((s, i) => new[] { i, s }));
    var ativos = new Dictionary<int, int>();
    fim.AddRange(new int[saidas.Length]);
    int t = 0;
    while (fila.Count > 0 || ativos.Count > 0)
    {
        while (fila.Count > 0 && ativos.Count < SLOTS)
        {
            var par = fila.Dequeue();
            ativos[par[0]] = par[1];
        }
        t += 1;
        foreach (int i in ativos.Keys.ToList())
        {
            ativos[i] -= 1;
            if (ativos[i] == 0)
            {
                fim[i] = t;
                ativos.Remove(i);
            }
        }
    }
    return t;
}

static void Main()
{
    int[] saidas = { 30, 400, 25, 60, 35, 380, 40, 50, 20, 45, 30, 350 };  // tokens de saida
    var estrategias = new List<KeyValuePair<string, Func<int[], List<int>, int>>>
    {
        new KeyValuePair<string, Func<int[], List<int>, int>>("estatico", Estatico),
        new KeyValuePair<string, Func<int[], List<int>, int>>("continuo", Continuo),
```

```go
import "fmt"

const SLOTS = 4

func estatico(saidas []int) (int, []int) {
	fim, t := []int{}, 0
	for i := 0; i < len(saidas); i += SLOTS {
		j := i + SLOTS
		if j > len(saidas) {
			j = len(saidas)
		}
		lote := saidas[i:j]
		maior := lote[0] // Go 1.18 não tem max embutido
		for _, s := range lote {
			fim = append(fim, t+s)
			if s > maior {
				maior = s
			}
		}
		t += maior
	}
	return t, fim
}

func continuo(saidas []int) (int, []int) {
	fila := [][2]int{}
	for i, s := range saidas {
		fila = append(fila, [2]int{i, s})
	}
	ativos := map[int]int{}
	fim := make([]int, len(saidas))
	t := 0
	for len(fila) > 0 || len(ativos) > 0 {
		for len(fila) > 0 && len(ativos) < SLOTS {
			i, s := fila[0][0], fila[0][1]
			fila = fila[1:]
			ativos[i] = s
		}
		t += 1
		for i := range ativos { // apagar a chave atual durante o range é permitido em Go
			ativos[i] -= 1
			if ativos[i] == 0 {
				fim[i] = t
				delete(ativos, i)
			}
		}
	}
	return t, fim
}

func soma(xs []int) int {
	s := 0
	for _, x := range xs {
		s += x
	}
	return s
}

func main() {
	saidas := []int{30, 400, 25, 60, 35, 380, 40, 50, 20, 45, 30, 350} // tokens de saida
	estrategias := []struct {
		nome string
		f    func([]int) (int, []int)
	}{{"estatico", estatico}, {"continuo", continuo}}
	for _, e := range estrategias {
		total, fim := e.f(saidas)
		uso := float64(soma(saidas)) / float64(SLOTS*total)
		media := float64(soma(fim)) / float64(len(fim))
		fmt.Printf("%-9s passos=%5d  latencia media=%6.1f  uso dos slots=%.0f%%\n", e.nome, total, media, uso*100)
	}
}
```

Com a mesma GPU, o batching contínuo termina o trabalho em menos passos e reduz bastante a latência média, porque requisições curtas não esperam as longas. Na prática, os ganhos de throughput relatados para batching contínuo são de várias vezes, dependendo da variância dos comprimentos.

## Outros recursos do servidor

- **Prefill em pedaços (*chunked prefill*):** um prompt enorme pode travar o decode de todo o batch. Dividir o prefill em pedaços e intercalá-los com passos de decode mantém a latência por token estável.
- **Cache de prefixo:** se muitas requisições começam com o mesmo prompt de sistema, o KV cache desse trecho é calculado uma vez e reutilizado, reduzindo o TTFT.
- **Desagregação:** em escala, alguns sistemas rodam prefill e decode em pools de GPUs separados, já que têm perfis de recurso diferentes.
- **Quantização:** pesos e KV cache em menos bits liberam memória para batches maiores, com alguma perda de qualidade a ser medida.

| Técnica | Melhora | Custo |
| --- | --- | --- |
| Batch maior | Throughput | Latência por token sobe |
| Batching contínuo | Throughput e latência média | Agendador mais complexo |
| KV cache paginado | Ocupação de memória | Implementação no kernel de atenção |
| Quantização | Memória e velocidade | Possível perda de qualidade |

## Na entrevista

Ligue isso aos requisitos: contexto longo diminui a concorrência por GPU; prompt de sistema compartilhado se beneficia de cache de prefixo.
