"Projete um assistente que responde perguntas sobre os documentos internos da empresa" é a versão GenAI da clássica busca corporativa. O modelo sozinho não conhece wikis, contratos e chamados da empresa, e mesmo se conhecesse, não saberia quem pode ver o quê. A resposta padrão é **RAG** (geração aumentada por recuperação): buscar os trechos relevantes e entregá-los ao modelo como contexto, pedindo uma resposta com citações. O que diferencia um candidato forte é tratar a recuperação como o coração do sistema e levar permissões a sério.

## Requisitos

### Funcionais

- Perguntas em linguagem natural, respostas com citações clicáveis para os documentos de origem.
- Fontes: wiki, drive de arquivos, sistema de chamados, e-mail de listas. Novas fontes por conectores.
- O usuário só pode receber conteúdo que tem permissão para ver na fonte original.
- Documentos novos ou alterados ficam pesquisáveis em minutos.

### Não funcionais

- TTFT p95 abaixo de 2 segundos.
- Zero vazamento entre níveis de permissão, que é um requisito mais forte que qualquer meta de qualidade.
- Respostas fundamentadas: se a informação não estiver nos documentos, o sistema diz que não sabe.
- Multi-inquilino se for um produto SaaS: dados de clientes completamente isolados.

## Arquitetura

```text
         INGESTAO                                     CONSULTA
fontes --> conectores --> fila --> parser/limpeza      usuario
 (webhook + varredura)               |                    |
                                     v                    v
                              chunking + metadados   reescrita da pergunta
                              (ACL, inquilino, data)      |
                                     |                    v
                              servico de embeddings   busca hibrida ----------+
                                     |                 |- indice lexical      |
                                     v                 '- indice vetorial     |
                     indice lexical + indice vetorial    filtro de ACL        |
                     (particionados por inquilino)            |               |
                                                              v               |
                                                      reranker (top 50 -> 8)  |
                                                              v               |
                                                  LLM com trechos + citacoes  |
                                                              v               |
                                                  verificacao de citacoes ----+
```

## Componentes em detalhe

### Ingestão e chunking

Conectores recebem webhooks de mudança e fazem varreduras periódicas para pegar o que escapou. Cada documento é convertido em texto, limpo e dividido em trechos que respeitam a estrutura (títulos, parágrafos, tabelas), com sobreposição pequena. Cada trecho carrega metadados: `inquilino`, `doc_id`, versão, data, URL e a **lista de controle de acesso** copiada da fonte. Ao atualizar um documento, todos os trechos da versão antiga são substituídos de forma atômica.

### Busca híbrida e permissões

Busca vetorial é boa em sinônimos e paráfrases; busca lexical é boa em códigos, nomes próprios e siglas. Rodar as duas e fundir os rankings é mais robusto que qualquer uma sozinha. O filtro de permissão é aplicado **dentro** da busca, como pré-filtro, e não depois: filtrar depois do top-k pode deixar zero resultados visíveis e, pior, uma falha no filtro vaza conteúdo.

```java
import java.util.*;

static Map<String, Double> rrf(List<List<String>> rankings, int k) {
    Map<String, Double> pontos = new LinkedHashMap<>(); // guarda a ordem de inserção, como o dict
    for (List<String> ranking : rankings) {
        for (int pos = 1; pos <= ranking.size(); pos++) {
            String doc = ranking.get(pos - 1);
            pontos.put(doc, pontos.getOrDefault(doc, 0.0) + 1.0 / (k + pos));
        }
    }
    return pontos;
}

static Map<String, Double> rrf(List<List<String>> rankings) {
    return rrf(rankings, 60);
}

public static void main(String[] args) {
    List<String> lexical = List.of("d7", "d2", "d9", "d4");          // ranking da busca por palavras
    List<String> vetorial = List.of("d2", "d4", "d1", "d7", "d5");   // ranking da busca por embeddings
    Map<String, Set<String>> acl = Map.of("d1", Set.of("rh"), "d2", Set.of("todos"), "d4", Set.of("engenharia"),
            "d5", Set.of("todos"), "d7", Set.of("financeiro"), "d9", Set.of("todos"));
    Set<String> gruposUsuario = Set.of("todos", "engenharia");

    Map<String, Double> pontos = rrf(List.of(lexical, vetorial));
    Map<String, Double> visiveis = new LinkedHashMap<>();
    for (Map.Entry<String, Double> e : pontos.entrySet()) {
        if (!Collections.disjoint(acl.get(e.getKey()), gruposUsuario)) visiveis.put(e.getKey(), e.getValue());
    }
    List<Map.Entry<String, Double>> ordenados = new ArrayList<>(visiveis.entrySet());
    ordenados.sort((x, y) -> Double.compare(y.getValue(), x.getValue()));
    for (Map.Entry<String, Double> e : ordenados) {
        System.out.println(String.format(Locale.US, "%s  %.4f", e.getKey(), e.getValue()));
    }
    TreeSet<String> ocultos = new TreeSet<>(pontos.keySet());
    ocultos.removeAll(visiveis.keySet());
    System.out.println("ocultos por permissao: " + ocultos);
}
```

```cpp
// devolve os pares (doc, pontos) na ordem em que cada doc apareceu, como o dict do Python
vector<pair<string, double>> rrf(const vector<vector<string>>& rankings, int k = 60) {
    vector<pair<string, double>> pontos;
    for (const auto& ranking : rankings) {
        for (size_t i = 0; i < ranking.size(); i++) {
            int pos = (int)i + 1;
            auto it = find_if(pontos.begin(), pontos.end(), [&](const auto& par) { return par.first == ranking[i]; });
            if (it == pontos.end()) {
                pontos.push_back({ranking[i], 0.0});
                it = pontos.end() - 1;
            }
            it->second += 1.0 / (k + pos);
        }
    }
    return pontos;
}

int main() {
    vector<string> lexical = {"d7", "d2", "d9", "d4"};          // ranking da busca por palavras
    vector<string> vetorial = {"d2", "d4", "d1", "d7", "d5"};   // ranking da busca por embeddings
    map<string, set<string>> acl = {{"d1", {"rh"}}, {"d2", {"todos"}}, {"d4", {"engenharia"}}, {"d5", {"todos"}},
                                    {"d7", {"financeiro"}}, {"d9", {"todos"}}};
    set<string> gruposUsuario = {"todos", "engenharia"};

    auto pontos = rrf({lexical, vetorial});
    vector<pair<string, double>> visiveis;
    set<string> ocultos; // set já sai ordenado
    for (const auto& [d, p] : pontos) {
        bool permitido = false;
        for (const string& g : acl[d]) permitido = permitido || gruposUsuario.count(g);
        if (permitido) visiveis.push_back({d, p});
        else ocultos.insert(d);
    }
    stable_sort(visiveis.begin(), visiveis.end(), [](const auto& x, const auto& y) { return x.second > y.second; });
    for (const auto& [doc, p] : visiveis) {
        printf("%s  %.4f\n", doc.c_str(), p);
    }
    printf("ocultos por permissao: [");
    bool primeiro = true;
    for (const string& d : ocultos) {
        printf("%s'%s'", primeiro ? "" : ", ", d.c_str());
        primeiro = false;
    }
    printf("]\n");
}
```

```csharp
using System;
using System.Collections.Generic;
using System.Globalization;
using System.Linq;

// devolve os pares (doc, pontos) na ordem em que cada doc apareceu, como o dict do Python
static List<KeyValuePair<string, double>> Rrf(List<string>[] rankings, int k = 60) {
    var ordem = new List<string>();
    var soma = new Dictionary<string, double>();
    foreach (var ranking in rankings) {
        for (int pos = 1; pos <= ranking.Count; pos++) {
            string doc = ranking[pos - 1];
            if (!soma.ContainsKey(doc)) {
                ordem.Add(doc);
                soma[doc] = 0;
            }
            soma[doc] += 1.0 / (k + pos);
        }
    }
    return ordem.Select(d => new KeyValuePair<string, double>(d, soma[d])).ToList();
}

static void Main() {
    var lexical = new List<string> { "d7", "d2", "d9", "d4" };          // ranking da busca por palavras
    var vetorial = new List<string> { "d2", "d4", "d1", "d7", "d5" };   // ranking da busca por embeddings
    var acl = new Dictionary<string, HashSet<string>> {
        ["d1"] = new HashSet<string> { "rh" }, ["d2"] = new HashSet<string> { "todos" },
        ["d4"] = new HashSet<string> { "engenharia" }, ["d5"] = new HashSet<string> { "todos" },
        ["d7"] = new HashSet<string> { "financeiro" }, ["d9"] = new HashSet<string> { "todos" } };
    var gruposUsuario = new HashSet<string> { "todos", "engenharia" };

    var pontos = Rrf(new[] { lexical, vetorial });
    var visiveis = pontos.Where(par => acl[par.Key].Overlaps(gruposUsuario)).ToList();
    foreach (var par in visiveis.OrderByDescending(par => par.Value)) { // OrderBy é estável, como o sorted
        Console.WriteLine(string.Format(CultureInfo.InvariantCulture, "{0}  {1:F4}", par.Key, par.Value));
    }
    var ocultos = pontos.Select(par => par.Key).Except(visiveis.Select(par => par.Key))
                        .OrderBy(d => d, StringComparer.Ordinal);
    Console.WriteLine("ocultos por permissao: [" + string.Join(", ", ocultos.Select(d => "'" + d + "'")) + "]");
}
```

```go
import (
	"fmt"
	"sort"
)

// devolve os docs na ordem em que apareceram (o map do Go não guarda ordem) e os pontos de cada um
func rrf(k int, rankings ...[]string) ([]string, map[string]float64) {
	ordem := []string{}
	pontos := map[string]float64{}
	for _, ranking := range rankings {
		for i, doc := range ranking {
			pos := i + 1
			if _, ok := pontos[doc]; !ok {
				ordem = append(ordem, doc)
			}
			pontos[doc] += 1 / float64(k+pos)
		}
	}
	return ordem, pontos
}

func main() {
	lexical := []string{"d7", "d2", "d9", "d4"}        // ranking da busca por palavras
	vetorial := []string{"d2", "d4", "d1", "d7", "d5"} // ranking da busca por embeddings
	acl := map[string][]string{"d1": {"rh"}, "d2": {"todos"}, "d4": {"engenharia"}, "d5": {"todos"},
		"d7": {"financeiro"}, "d9": {"todos"}}
	gruposUsuario := map[string]bool{"todos": true, "engenharia": true}

	ordem, pontos := rrf(60, lexical, vetorial)
	visiveis := []string{}
	ocultos := []string{}
	for _, d := range ordem {
		permitido := false
		for _, g := range acl[d] {
			permitido = permitido || gruposUsuario[g]
		}
		if permitido {
			visiveis = append(visiveis, d)
		} else {
			ocultos = append(ocultos, d)
		}
	}
	sort.SliceStable(visiveis, func(i, j int) bool { return pontos[visiveis[i]] > pontos[visiveis[j]] })
	for _, doc := range visiveis {
		fmt.Printf("%s  %.4f\n", doc, pontos[doc])
	}
	sort.Strings(ocultos)
	fmt.Println("ocultos por permissao:", ocultos)
}
```

A fusão por posição recíproca (RRF) combina rankings sem calibrar escalas diferentes de score. Em produção, o filtro de ACL seria um predicado na própria consulta aos índices.

As permissões mudam: alguém sai de um grupo, um documento vira restrito. Por isso, a ACL dos trechos precisa ser atualizada por eventos da fonte, e para fontes críticas vale uma checagem final contra a fonte no momento da resposta.

### Geração com citações

O prompt instrui o modelo a responder apenas com base nos trechos numerados e a citar os números. Uma verificação pós-geração confere se cada citação aponta para um trecho realmente entregue e, opcionalmente, se a frase citada é sustentada pelo trecho. Sem trechos relevantes acima de um limiar, o sistema responde que não encontrou a informação, em vez de deixar o modelo improvisar.

<Callout type="warning" title="Permissão é requisito, não otimização">
Diga explicitamente que o filtro de ACL é aplicado na consulta ao índice, que o cache de respostas é particionado por escopo de permissão e que uma falha na verificação de acesso bloqueia a resposta.
</Callout>

## Gargalos e trade-offs

| Ponto | Opção A | Opção B |
| --- | --- | --- |
| Tamanho do trecho | Pequeno: busca precisa, pouco contexto | Grande: mais contexto, busca menos precisa |
| Reranker | Com: qualidade melhor | Sem: menos latência e custo |
| Índice | Um por inquilino: isolamento forte | Compartilhado com filtro: mais eficiente |
| Atualização | Por eventos: minutos | Varredura: simples, horas de atraso |

## Follow-ups

- **Como avaliar a qualidade?** Separe recuperação (o trecho certo veio no top-k?) de geração (a resposta é fiel aos trechos?). Use um conjunto de perguntas com documentos de referência.
- **E perguntas que exigem juntar vários documentos?** Decomposição da pergunta em subperguntas, busca para cada uma e síntese.
- **Como lidar com documentos desatualizados ou contraditórios?** Priorize por data e fonte oficial nos metadados e mostre a data nas citações.
- **E o custo do reranker?** Rerankear só o top 50 com um modelo pequeno; pular o reranker quando os scores já forem muito claros.
