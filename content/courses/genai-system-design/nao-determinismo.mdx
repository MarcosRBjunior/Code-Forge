Chame uma função de soma duas vezes com os mesmos argumentos e você recebe o mesmo número. Chame um LLM duas vezes com o mesmo prompt e pode receber duas respostas diferentes, às vezes uma certa e outra errada, às vezes um JSON válido e outro quebrado. Isso afeta tudo que o resto do sistema assume: testes, cache, reprodução de bugs, integração com código que espera um formato fixo. Na entrevista, saber de onde vem essa variação e como contê-la mostra que você já operou um sistema desses de verdade.

## De onde vem a variação

- **Amostragem.** A cada passo, o modelo produz uma distribuição de probabilidade sobre o próximo token. Com temperatura acima de zero, o token é sorteado dessa distribuição. A temperatura achata (valores altos) ou afia (valores baixos) a distribuição.
- **Ruído numérico.** Mesmo com temperatura zero, a ordem das operações em ponto flutuante varia com o tamanho do batch e o hardware. Num servidor com batching contínuo, sua requisição divide o lote com outras diferentes a cada vez, e pequenas diferenças numéricas podem mudar um token, o que muda todo o resto.
- **Mudanças fora do seu controle.** O provedor atualiza o modelo, a recuperação traz documentos diferentes porque a base mudou, o histórico tem um turno a mais.

A consequência prática: **não conte com determinismo bit a bit**, nem com temperatura zero. Projete o sistema para tolerar variação.

## O efeito da temperatura

O programa abaixo amostra o próximo token a partir de logits fixos (números hipotéticos) com três temperaturas e conta quantas vezes cada token sai em mil sorteios. A semente fixa só serve para a saída do exemplo ser reproduzível.

```python
import math, random

logits = {"aprovado": 2.0, "pendente": 1.2, "recusado": 0.3}

def distribuicao(t):
    exps = {k: math.exp(v / t) for k, v in logits.items()}
    s = sum(exps.values())
    return {k: e / s for k, e in exps.items()}

rng = random.Random(42)
for t in (0.2, 1.0, 2.0):
    d = distribuicao(t)
    amostras = rng.choices(list(d), weights=list(d.values()), k=1000)
    cont = {k: amostras.count(k) for k in logits}
    print(f"T={t}: " + "  ".join(f"{k}={cont[k]}" for k in logits))

# Quantas tentativas para garantir JSON valido em 99,9% dos casos?
p_valido = 0.95          # taxa hipotetica de saida valida por tentativa
alvo = 0.999
n = 1
while 1 - (1 - p_valido) ** n < alvo:
    n += 1
print(f"tentativas necessarias: {n} (sucesso {1 - (1 - p_valido) ** n:.5f})")
custo_medio = sum((1 - p_valido) ** i for i in range(n))
print(f"chamadas medias por requisicao: {custo_medio:.4f}")
```

const logits = { aprovado: 2.0, pendente: 1.2, recusado: 0.3 };

function distribuicao(t) {
  const exps = {};
  for (const [k, v] of Object.entries(logits)) exps[k] = Math.exp(v / t);
  const s = Object.values(exps).reduce((a, b) => a + b, 0);
  const d = {};
  for (const [k, e] of Object.entries(exps)) d[k] = e / s;
  return d;
}

// gerador com semente (mulberry32): o Math.random do JS não aceita semente
function mulberry32(semente) {
  return () => {
    semente = (semente + 0x6d2b79f5) | 0;
    let z = Math.imul(semente ^ (semente >>> 15), 1 | semente);
    z = (z + Math.imul(z ^ (z >>> 7), 61 | z)) ^ z;
    return ((z ^ (z >>> 14)) >>> 0) / 4294967296;
  };
}

// equivalente ao rng.choices(populacao, weights=pesos, k=k) do Python
function choices(rng, populacao, pesos, k) {
  const acum = [];
  let soma = 0;
  for (const p of pesos) acum.push((soma += p));
  const r = [];
  for (let i = 0; i < k; i++) {
    const x = rng() * soma;
    let j = 0;
    while (j < acum.length - 1 && acum[j] <= x) j++;   // bisect_right
    r.push(populacao[j]);
  }
  return r;
}

const rng = mulberry32(42);
for (const t of [0.2, 1.0, 2.0]) {
  const d = distribuicao(t);
  const amostras = choices(rng, Object.keys(d), Object.values(d), 1000);
  const cont = {};
  for (const k of Object.keys(logits)) cont[k] = amostras.filter((a) => a === k).length;
  console.log(`T=${t}: ` + Object.keys(logits).map((k) => `${k}=${cont[k]}`).join("  "));
}

// Quantas tentativas para garantir JSON valido em 99,9% dos casos?
const pValido = 0.95;          // taxa hipotetica de saida valida por tentativa
const alvo = 0.999;
let n = 1;
while (1 - (1 - pValido) ** n < alvo) {
  n += 1;
}
console.log(`tentativas necessarias: ${n} (sucesso ${(1 - (1 - pValido) ** n).toFixed(5)})`);
let custoMedio = 0;
for (let i = 0; i < n; i++) custoMedio += (1 - pValido) ** i;
console.log(`chamadas medias por requisicao: ${custoMedio.toFixed(4)}`);

import java.math.BigDecimal;
import java.math.RoundingMode;
import java.util.*;

static final LinkedHashMap<String, Double> logits = new LinkedHashMap<>();
static {
    logits.put("aprovado", 2.0);
    logits.put("pendente", 1.2);
    logits.put("recusado", 0.3);
}

static LinkedHashMap<String, Double> distribuicao(double t) {
    LinkedHashMap<String, Double> exps = new LinkedHashMap<>();
    for (Map.Entry<String, Double> e : logits.entrySet()) exps.put(e.getKey(), Math.exp(e.getValue() / t));
    double s = 0;
    for (double e : exps.values()) s += e;
    LinkedHashMap<String, Double> d = new LinkedHashMap<>();
    for (Map.Entry<String, Double> e : exps.entrySet()) d.put(e.getKey(), e.getValue() / s);
    return d;
}

// equivalente ao rng.choices(populacao, weights=pesos, k=k) do Python
static List<String> choices(Random rng, List<String> populacao, List<Double> pesos, int k) {
    double[] acum = new double[pesos.size()];
    double soma = 0;
    for (int i = 0; i < pesos.size(); i++) acum[i] = (soma += pesos.get(i));
    List<String> r = new ArrayList<>();
    for (int i = 0; i < k; i++) {
        double x = rng.nextDouble() * soma;
        int j = 0;
        while (j < acum.length - 1 && acum[j] <= x) j++;   // bisect_right
        r.add(populacao.get(j));
    }
    return r;
}

// %.Nf do Java arredonda o decimal curto (0.999875 vira 0.99988); o Python usa o valor binário exato
static String fixo(double x, int casas) {
    return new BigDecimal(x).setScale(casas, RoundingMode.HALF_EVEN).toPlainString();
}

public static void main(String[] args) {
    Random rng = new Random(42);
    for (double t : new double[]{0.2, 1.0, 2.0}) {
        LinkedHashMap<String, Double> d = distribuicao(t);
        List<String> amostras = choices(rng, new ArrayList<>(d.keySet()), new ArrayList<>(d.values()), 1000);
        StringJoiner partes = new StringJoiner("  ");
        for (String k : logits.keySet()) partes.add(k + "=" + Collections.frequency(amostras, k));
        System.out.println("T=" + t + ": " + partes);
    }

    // Quantas tentativas para garantir JSON valido em 99,9% dos casos?
    double pValido = 0.95;          // taxa hipotetica de saida valida por tentativa
    double alvo = 0.999;
    int n = 1;
    while (1 - Math.pow(1 - pValido, n) < alvo) {
        n += 1;

    System.out.println("tentativas necessarias: " + n + " (sucesso " + fixo(1 - Math.pow(1 - pValido, n), 5) + ")");
    double custoMedio = 0;

#include <algorithm>
#include <cmath>
#include <cstdio>
#include <random>
#include <string>
#include <utility>
#include <vector>
using namespace std;

// vetor de pares mantém a ordem de inserção, como o dict do Python
using Dist = vector<pair<string, double>>;
const Dist logits = {{"aprovado", 2.0}, {"pendente", 1.2}, {"recusado", 0.3}};

Dist distribuicao(double t) {
    Dist exps;
    for (auto& [k, v] : logits) exps.push_back({k, exp(v / t)});
    double s = 0;
    for (auto& [k, e] : exps) s += e;
    Dist d;
    for (auto& [k, e] : exps) d.push_back({k, e / s});
    return d;
}

// equivalente ao rng.choices(populacao, weights=pesos, k=k) do Python
vector<string> choices(mt19937& rng, const Dist& d, int k) {
    vector<double> acum;
    double soma = 0;
    for (auto& [nome, p] : d) acum.push_back(soma += p);
    uniform_real_distribution<double> unif(0.0, 1.0);
    vector<string> r;
    for (int i = 0; i < k; i++) {
        double x = unif(rng) * soma;
        size_t j = upper_bound(acum.begin(), acum.end(), x) - acum.begin();   // bisect_right
        r.push_back(d[min(j, acum.size() - 1)].first);
    }
    return r;
}

int main() {
    mt19937 rng(42);
    for (double t : {0.2, 1.0, 2.0}) {
        Dist d = distribuicao(t);
        vector<string> amostras = choices(rng, d, 1000);
        printf("T=%g:", t);
        for (size_t i = 0; i < logits.size(); i++) {
            const string& k = logits[i].first;
            printf("%s%s=%d", i ? "  " : " ", k.c_str(), (int)count(amostras.begin(), amostras.end(), k));
        }
        printf("\n");
    }

    // Quantas tentativas para garantir JSON valido em 99,9% dos casos?
    double pValido = 0.95;          // taxa hipotetica de saida valida por tentativa
    double alvo = 0.999;
    int n = 1;
    while (1 - pow(1 - pValido, n) < alvo) {
        n += 1;
    }
    printf("tentativas necessarias: %d (sucesso %.5f)\n", n, 1 - pow(1 - pValido, n));
    double custoMedio = 0;
    for (int i = 0; i < n; i++) custoMedio += pow(1 - pValido, i);
    printf("chamadas medias por requisicao: %.4f\n", custoMedio);
}

import (
	"fmt"
	"math"
	"math/rand"
	"strings"
)

type Par struct {
	k string
	v float64
}

// fatia de pares mantém a ordem de inserção, como o dict do Python (o map do Go embaralha)
var logits = []Par{{"aprovado", 2.0}, {"pendente", 1.2}, {"recusado", 0.3}}

func distribuicao(t float64) []Par {
	exps := []Par{}
	for _, p := range logits {
		exps = append(exps, Par{p.k, math.Exp(p.v / t)})
	}
	s := 0.0
	for _, e := range exps {
		s += e.v
	}
	d := []Par{}
	for _, e := range exps {
		d = append(d, Par{e.k, e.v / s})
	}
	return d
}

// equivalente ao rng.choices(populacao, weights=pesos, k=k) do Python
func choices(rng *rand.Rand, d []Par, k int) []string {
	acum := make([]float64, len(d))
	soma := 0.0
	for i, p := range d {
		soma += p.v
		acum[i] = soma
	}
	r := []string{}
	for i := 0; i < k; i++ {
		x := rng.Float64() * soma
		j := 0
		for j < len(acum)-1 && acum[j] <= x { // bisect_right
			j++
		}
		r = append(r, d[j].k)
	}
	return r
}

func main() {
	rng := rand.New(rand.NewSource(42))
	for _, t := range []float64{0.2, 1.0, 2.0} {
		d := distribuicao(t)
		amostras := choices(rng, d, 1000)
		cont := map[string]int{}
		for _, a := range amostras {
			cont[a]++
		}
		partes := []string{}
		for _, p := range logits {
			partes = append(partes, fmt.Sprintf("%s=%d", p.k, cont[p.k]))
		}
		fmt.Printf("T=%v: %s\n", t, strings.Join(partes, "  "))
	}

	// Quantas tentativas para garantir JSON valido em 99,9% dos casos?
	pValido := 0.95 // taxa hipotetica de saida valida por tentativa
	alvo := 0.999
	n := 1
	for 1-math.Pow(1-pValido, float64(n)) < alvo {
		n += 1
	}
	fmt.Printf("tentativas necessarias: %d (sucesso %.5f)\n", n, 1-math.Pow(1-pValido, float64(n)))
	custoMedio := 0.0
	for i := 0; i < n; i++ {
		custoMedio += math.Pow(1-pValido, float64(i))
	}
	fmt.Printf("chamadas medias por requisicao: %.4f\n", custoMedio)
}

Duas lições. Para tarefas com resposta certa (classificação, extração), temperatura baixa concentra a probabilidade no token mais provável. E retries com validação transformam uma taxa de sucesso de 95% em 99,9% com poucas tentativas extras e custo médio quase igual a uma chamada, desde que as falhas sejam independentes.

## Técnicas para conter a variação

### Saída estruturada

Peça JSON com um esquema explícito e valide. Muitos servidores e provedores oferecem decodificação restrita, que só permite tokens compatíveis com o esquema; quando não houver, valide e repita com a mensagem de erro no prompt. O código a jusante nunca deve fazer parsing otimista.

### Temperatura por tarefa

Temperatura baixa para extração, classificação e chamadas de ferramenta; mais alta para redação criativa e geração de alternativas. Isso é configuração do prompt no registro, não decisão espalhada pelo código.

### Votação e verificação

Para decisões importantes, gere várias respostas e escolha a mais frequente (autoconsistência), ou use um verificador: um teste automático (o código compila? a soma bate?), um segundo modelo ou uma regra de negócio. Custa mais chamadas e deve ser reservado para onde o erro é caro.

### Reprodutibilidade operacional

Registre tudo que influencia a resposta: versão do prompt, modelo e versão, parâmetros de amostragem, semente se houver, documentos recuperados e histórico. Você não vai reproduzir o mesmo texto, mas vai conseguir entender por que a resposta saiu daquele jeito.

## Testando um sistema não determinístico

| Abordagem | O que verifica | Limitação |
| --- | --- | --- |
| Asserções exatas | Nada útil, quebram à toa | Saída varia |
| Asserções de propriedade | Formato, campos, citações válidas, tamanho | Não mede qualidade do conteúdo |
| Conjunto de avaliação com notas | Qualidade agregada por critério | Exige rotulagem e manutenção |
| LLM como juiz | Qualidade em escala | O juiz também erra; calibre com humanos |

A ideia central é trocar "a resposta é igual à esperada" por "a taxa de respostas boas no conjunto não caiu". Rode cada caso mais de uma vez quando a variância importar e compare distribuições, não amostras únicas.

<Callout type="note" title="Temperatura zero não é contrato">
Mesmo com temperatura zero, variações numéricas e atualizações de modelo podem mudar a resposta. Use temperatura baixa para reduzir variação, não para garantir igualdade.
</Callout>
