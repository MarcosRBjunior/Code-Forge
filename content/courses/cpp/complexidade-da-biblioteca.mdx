Em Python você sabe de cabeça que `x in lista` é O(n), `x in set` é O(1) e `lista.pop(0)` é lento. Em C++ o entrevistador espera o mesmo nível de consciência, mas com nomes diferentes e algumas surpresas. Escolher o contêiner errado pode transformar uma solução O(n log n) em O(n²) sem que o código pareça ter mudado. Este capítulo é a tabela mental que você precisa ter pronta.

## O problema

Cada operação da STL tem complexidade garantida pelo padrão. Dizer "uso um `vector`" não basta: é preciso saber o que cada chamada custa dentro de um laço, porque o laço multiplica. Um `erase` no começo de um `vector` dentro de um `for` de n passos é O(n²).

## Tabela de referência

| Contêiner | Acesso por índice | Busca | Inserir / remover |
| --- | --- | --- | --- |
| `vector` | O(1) | O(n) (O(log n) se ordenado) | fim: O(1) amortizado; meio ou início: O(n) |
| `deque` | O(1) | O(n) | pontas: O(1); meio: O(n) |
| `list` | não tem | O(n) | O(1) com iterador |
| `set`, `map` | não tem | O(log n) | O(log n) |
| `unordered_set`, `unordered_map` | não tem | O(1) médio, O(n) pior caso | O(1) médio, O(n) pior caso |
| `priority_queue` | topo: O(1) | não tem | push e pop: O(log n) |
| `stack`, `queue` | topo ou frente: O(1) | não tem | O(1) |

Por que isso importa: `set` e `map` são árvores balanceadas, mantêm tudo ordenado e custam log n por operação. As versões `unordered_` usam tabela hash, são mais rápidas em média, mas não têm ordem e podem degradar se muitas chaves colidirem (existem entradas montadas para isso em competições, e um hash ruim em chave customizada faz o mesmo).

## Surpresas que valem pontos

Algumas operações não custam o que parecem. O `operator[]` de `map` **insere** a chave com valor padrão se ela não existe. Já `count` e `find` não alteram o mapa.

```cpp
#include <iostream>
#include <map>
#include <string>
using namespace std;

int main() {
    map<string, int> m;
    if (m["x"] == 0) cout << "x vale zero\n";
    cout << m.size() << "\n";
    m.count("y");
    cout << m.size() << "\n";
    auto it = m.find("z");
    cout << (it == m.end()) << " " << m.size() << "\n";
    m["y"] += 5;
    cout << m["y"] << " " << m.size() << "\n";
}
```

```text
Saída:
x vale zero
1
1
1 1
5 2
```

Só ler `m["x"]` já criou uma entrada. Para testar existência sem inserir, use `count` ou `find`. Isso afeta a corretude e o consumo de memória, não apenas o desempenho.

Outro detalhe é a busca em ordenados: `lower_bound(v.begin(), v.end(), x)` em `vector` é O(log n) porque os iteradores são de acesso aleatório. Em `set`, use o método `s.lower_bound(x)`, que anda na árvore. O algoritmo genérico `std::lower_bound(s.begin(), s.end(), x)` em um `set` funciona, mas é O(n) porque precisa avançar o iterador passo a passo.

```cpp
#include <algorithm>
#include <deque>
#include <iostream>
#include <set>
#include <vector>
using namespace std;

int main() {
    vector<int> v{1, 3, 5, 7, 9};
    auto it = lower_bound(v.begin(), v.end(), 6);
    cout << *it << " " << (it - v.begin()) << "\n";

    set<int> s(v.begin(), v.end());
    cout << *s.lower_bound(6) << "\n";

    v.erase(remove(v.begin(), v.end(), 5), v.end());
    for (int x : v) cout << x << " ";
    cout << "\n";

    deque<int> d{1, 2, 3};
    d.pop_front();
    d.push_front(0);
    cout << d.front() << " " << d.size() << "\n";
}
```

```text
Saída:
7 3
7
1 3 7 9 
0 3
```

O `erase` + `remove` (o idioma erase-remove) apaga todos os valores iguais em O(n) de uma vez. Chamar `erase` dentro de um laço, elemento a elemento, custa O(n) cada e vira quadrático.

## Armadilhas

- `string` concatenada com `+` em laço copia a cada passo. Use `+=` ou `push_back`, que são amortizados O(1).
- `list::size()` é O(1) desde o C++11, mas `std::distance` em um `set` ou `list` é O(n).
- `vector::insert(begin(), x)` é O(n). Se precisa mexer na frente, use `deque`.
- `push_back` em `vector` é O(1) amortizado: eventualmente realoca e copia tudo, mas a média por operação continua constante. Invalida referências e iteradores.
- `sort` é O(n log n); `unique` é O(n) e só funciona em dados ordenados (remove duplicatas adjacentes).
- `string::find` é O(n·m) no pior caso, em teoria.
