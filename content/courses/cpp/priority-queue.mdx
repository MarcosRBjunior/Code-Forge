Uma fila de prioridade devolve sempre o elemento mais importante, e não o mais antigo. Em Python você usa o módulo `heapq`, que só implementa heap mínimo sobre uma lista. JavaScript não tem nada pronto. C++ traz `std::priority_queue`, no cabeçalho `queue`, com inserção e remoção em O(log n) e consulta do topo em O(1). Ela aparece em top-k, mesclar listas ordenadas, escalonamento e algoritmo de Dijkstra.

## Padrão: heap máximo

Ao contrário do `heapq`, o `priority_queue` padrão é um heap **máximo**: o `top` é o maior elemento. Para obter um heap mínimo, passe um terceiro parâmetro de template com `greater`.

```cpp
#include <iostream>
#include <queue>
#include <vector>
#include <functional>
#include <string>

int main() {
    std::priority_queue<int> maxh;
    for (int x : {5, 1, 8, 3}) maxh.push(x);
    std::cout << maxh.top() << " " << maxh.size() << '\n';
    maxh.pop();
    std::cout << maxh.top() << '\n';

    std::priority_queue<int, std::vector<int>, std::greater<int>> minh;
    for (int x : {5, 1, 8, 3}) minh.push(x);
    while (!minh.empty()) {
        std::cout << minh.top() << ' ';
        minh.pop();
    }
    std::cout << '\n';

    std::priority_queue<std::pair<int, std::string>> pares;
    pares.push({2, "b"});
    pares.push({9, "z"});
    pares.push({9, "a"});
    std::cout << pares.top().first << pares.top().second << '\n';
    return 0;
}
```

```text
Saída:
8 4
5
1 3 5 8 
9z
```

Os pares são comparados primeiro pelo primeiro campo, depois pelo segundo. Por isso, com prioridade igual a 9, ganha `"z"` sobre `"a"`. Esse comportamento é útil: em Dijkstra você guarda `{distancia, no}` num heap mínimo, e a menor distância sai primeiro.

Como o `pop` não devolve o valor (igual a `stack` e `queue`), leia o `top` antes. Também não há iteração nem busca por elemento: você só enxerga o topo.

## Top-k com um heap pequeno

Para achar os `k` maiores de `n` números, a ideia é manter um heap **mínimo** de tamanho `k`. Cada número novo entra; se o heap passar de `k`, remove o menor. No fim, o heap contém os `k` maiores. O custo é O(n log k), melhor que ordenar tudo em O(n log n) quando `k` é pequeno.

```cpp
#include <iostream>
#include <queue>
#include <vector>
#include <functional>

struct Tarefa {
    int prioridade;
    int id;
};

struct Menor {
    bool operator()(const Tarefa& a, const Tarefa& b) const {
        return a.prioridade > b.prioridade;
    }
};

int main() {
    std::vector<int> v = {4, 9, 1, 7, 3, 8, 2};
    int k = 3;
    std::priority_queue<int, std::vector<int>, std::greater<int>> h;
    for (int x : v) {
        h.push(x);
        if ((int)h.size() > k) h.pop();
    }
    std::cout << "k-esimo maior: " << h.top() << '\n';

    std::priority_queue<Tarefa, std::vector<Tarefa>, Menor> fila;
    fila.push({5, 1});
    fila.push({2, 2});
    fila.push({7, 3});
    while (!fila.empty()) {
        std::cout << fila.top().id << ' ';
        fila.pop();
    }
    std::cout << '\n';
    return 0;
}
```

```text
Saída:
k-esimo maior: 7
2 1 3 
```

Depois do laço, o heap guarda os valores 7, 8 e 9, e o menor deles, no topo, é o terceiro maior. No segundo exemplo, o comparador `Menor` inverte o sentido: a regra do `priority_queue` é que o comparador diz "a vem depois de b", então usar `>` produz um heap mínimo. Essa inversão confunde muita gente, e vale a pena memorizar: **o comparador do `priority_queue` é o inverso do da ordenação**.

## Custos

| Operação | Custo |
|---|---|
| `push` | O(log n) |
| `pop` | O(log n) |
| `top`, `size`, `empty` | O(1) |
| construir a partir de n elementos | O(n) com o construtor de intervalo |

## Armadilhas

Não existe atualização de prioridade nem remoção de um elemento arbitrário. A técnica padrão é a remoção preguiçosa: insira a nova versão e, ao tirar do topo, ignore as entradas desatualizadas. Para valores que podem ser negativos, guardar o oposto (`-x`) em um heap máximo é um atalho de heap mínimo, mas cuidado com `INT_MIN`. E ao usar `greater` lembre de incluir `functional`.

## Na entrevista

Justifique a escolha: "preciso do menor a cada passo, então heap mínimo, O(log n) por operação". Follow-ups: "qual a complexidade de construir um heap com n elementos?"
