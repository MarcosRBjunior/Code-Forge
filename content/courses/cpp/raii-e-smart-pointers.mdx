Python e JavaScript têm coletor de lixo: você cria objetos e esquece. Em C++ não há coletor, e a pergunta "quem libera isso?" precisa ter resposta. A resposta moderna não é lembrar de chamar `delete`, e sim fazer o próprio objeto se encarregar disso. Essa técnica se chama RAII e é a ideia central da linguagem.

## Pilha e heap

Variáveis locais vivem na pilha (stack): são criadas ao entrar no escopo e destruídas ao sair, de graça e automaticamente. O heap guarda objetos que precisam viver além do escopo ou cujo tamanho só se conhece em tempo de execução. Alocar com `new` devolve um ponteiro, e cada `new` exige um `delete`. Esquecer causa vazamento (memory leak); chamar duas vezes causa double free; usar depois de liberar é comportamento indefinido.

O pior é que o `delete` pode ser pulado sem você perceber: um `return` antecipado ou uma exceção entre o `new` e o `delete` basta.

## RAII

RAII (Resource Acquisition Is Initialization) diz: adquira o recurso no construtor e libere no destrutor. Como o destrutor roda sempre que o objeto sai de escopo, inclusive durante uma exceção, o recurso nunca vaza. `vector`, `string`, `ifstream` e `lock_guard` já funcionam assim. Por isso, em C++ moderno, você quase nunca escreve `new` e `delete` manualmente.

## unique_ptr: dono único

`unique_ptr` é um ponteiro que possui o objeto e o deleta quando morre. Não pode ser copiado (haveria dois donos), apenas movido com `std::move`, o que transfere a posse. Crie sempre com `make_unique`. Tem custo praticamente zero em relação a um ponteiro cru.

```cpp
#include <iostream>
#include <memory>
#include <utility>
using namespace std;

struct Recurso {
    int id;
    Recurso(int i) : id(i) { cout << "abre " << id << "\n"; }
    ~Recurso() { cout << "fecha " << id << "\n"; }
};

int main() {
    auto a = make_unique<Recurso>(1);
    {
        auto b = make_unique<Recurso>(2);
        cout << "dentro\n";
    }
    auto c = move(a);
    cout << (a == nullptr) << "\n";
    cout << c->id << "\n";
}
```

```text
Saída:
abre 1
abre 2
dentro
fecha 2
1
1
fecha 1
```

O recurso 2 fecha ao sair do bloco; o 1 muda de dono para `c` e fecha só no fim de `main`. Depois do `move`, `a` fica nulo. Nenhum `delete` escrito.

## shared_ptr e weak_ptr

`shared_ptr` permite vários donos: um contador de referências sobe a cada cópia e desce a cada destruição; ao chegar a zero, o objeto é deletado. Use quando a posse é realmente compartilhada, como nós de um grafo com múltiplos pais. `weak_ptr` observa sem possuir, não incrementa o contador e serve para quebrar ciclos: dois objetos com `shared_ptr` um para o outro nunca chegam a zero e vazam. Para usar o objeto, chame `lock()`, que devolve um `shared_ptr` (nulo se o objeto já morreu).

```cpp
#include <iostream>
#include <memory>
using namespace std;

int main() {
    auto p = make_shared<int>(42);
    cout << p.use_count() << "\n";
    {
        auto q = p;
        cout << p.use_count() << " " << *q << "\n";
    }
    cout << p.use_count() << "\n";
    weak_ptr<int> w = p;
    cout << w.expired() << "\n";
    p.reset();
    cout << w.expired() << " " << (w.lock() == nullptr) << "\n";
}
```

```text
Saída:
1
2 42
1
0
1 1
```

## Qual usar

| Situação | Escolha |
| --- | --- |
| Objeto local ou dentro de outro | valor direto, sem ponteiro |
| Posse única no heap | `unique_ptr` com `make_unique` |
| Posse compartilhada | `shared_ptr` com `make_shared` |
| Observar sem possuir, ou quebrar ciclo | `weak_ptr` |
| Apenas usar, sem posse | referência ou ponteiro cru |

O ponteiro cru continua válido como "visitante": uma função que só lê o objeto recebe `T&` ou `T*`, sem se importar com quem é o dono.

## Armadilhas

- Misturar `new[]` com `delete` (sem colchetes) é comportamento indefinido; com `vector` o problema desaparece.
- Criar dois `shared_ptr` a partir do mesmo ponteiro cru gera dois contadores e dupla liberação.
- Ciclos de `shared_ptr` vazam; troque um dos lados por `weak_ptr`.
- `shared_ptr` custa mais (contador atômico); não o use por preguiça.
