Numa entrevista em C++ você costuma receber uma de duas coisas: uma classe `Solution` com um método a completar (o estilo LeetCode) ou uma folha em branco onde precisa escrever o programa inteiro, lendo a entrada e imprimindo a saída. Nos dois casos, ter um molde pronto na cabeça economiza minutos e evita esquecer detalhes como includes, tipos e casos de borda. Em Python você começaria com `def` e seguiria; em C++ alguns segundos de estrutura evitam erros de compilação no meio da explicação.

## O molde de função

Quando o enunciado já fornece a assinatura, o trabalho é organizar o corpo em três partes: tratar bordas, montar as estruturas auxiliares e executar o algoritmo. Mantenha nomes descritivos e evite variáveis globais, porque o avaliador pode chamar o método várias vezes no mesmo processo e um estado global sujo quebra os testes seguintes.

```cpp
class Solution {
public:
    vector<int> twoSum(vector<int>& nums, int target) {
        // 1. bordas
        if (nums.size() < 2) return {};
        // 2. estruturas auxiliares
        unordered_map<int, int> visto;   // valor -> índice
        // 3. algoritmo
        for (int i = 0; i < (int)nums.size(); i++) {
            auto it = visto.find(target - nums[i]);
            if (it != visto.end()) return {it->second, i};
            visto[nums[i]] = i;
        }
        return {};
    }
};
```

Repare em `(int)nums.size()`: converter o tamanho evita comparações entre com sinal e sem sinal. Funções auxiliares (uma DFS, por exemplo) podem ser métodos privados da classe ou lambdas dentro do método.

## O molde de programa completo

Quando você precisa escrever tudo, um esqueleto como este resolve quase todos os casos. Separar a lógica em uma função `resolver` facilita testar com valores fixos e mantém o `main` curto.

```cpp
#include <bits/stdc++.h>
using namespace std;

using ll = long long;

ll resolver(const vector<ll>& v) {
    if (v.empty()) return 0;
    ll melhor = v[0], atual = v[0];
    for (size_t i = 1; i < v.size(); i++) {
        atual = max(v[i], atual + v[i]);
        melhor = max(melhor, atual);
    }
    return melhor;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    vector<vector<ll>> testes{{-2, 1, -3, 4, -1, 2, 1, -5, 4}, {-3, -1, -2}, {}};
    for (const auto& t : testes) cout << resolver(t) << "\n";
}
```

```text
Saída:
6
-1
0
```

O que cada linha faz: `bits/stdc++.h` inclui toda a biblioteca padrão de uma vez (funciona no GCC, que é o que plataformas de entrevista usam; em outros compiladores, liste os includes). O `using ll = long long;` encurta o tipo mais usado. As duas linhas de `ios` deixam a leitura com `cin` muito mais rápida, assunto do próximo capítulo. A função testa três casos: o exemplo clássico do subarray máximo (Kadane), todos negativos e vetor vazio.

## Testar à mão com casos de borda

Antes de declarar a solução pronta, rode mentalmente (ou de verdade) os casos de borda. Uma bateria pequena com `assert` pega erros cedo e mostra ao entrevistador que você pensa em testes.

```cpp
#include <bits/stdc++.h>
using namespace std;

int buscaBinaria(const vector<int>& v, int alvo) {
    int lo = 0, hi = (int)v.size() - 1;
    while (lo <= hi) {
        int meio = lo + (hi - lo) / 2;
        if (v[meio] == alvo) return meio;
        if (v[meio] < alvo) lo = meio + 1;
        else hi = meio - 1;
    }
    return -1;
}

int main() {
    assert(buscaBinaria({}, 3) == -1);
    assert(buscaBinaria({3}, 3) == 0);
    assert(buscaBinaria({1, 3, 5}, 4) == -1);
    assert(buscaBinaria({1, 3, 5, 7}, 7) == 3);
    cout << "todos os testes passaram\n";
}
```

```text
Saída:
todos os testes passaram
```

Checklist de bordas que vale decorar: entrada vazia, um elemento, todos iguais, todos negativos, valores no limite do tipo, alvo ausente e entrada já ordenada ou invertida.

## Roteiro de comunicação

1. Reformule o problema e confirme restrições (tamanho de n, faixa dos valores, se há negativos).
2. Proponha a solução ingênua com a complexidade dela.
3. Melhore e explique a ideia antes de digitar.
4. Escreva o código seguindo o molde, comentando as invariantes.
5. Teste com um exemplo e com as bordas.
6. Diga a complexidade final de tempo e espaço.

## Armadilhas

- Esquecer o `return` no fim de uma função não `void`: é UB, e o compilador só avisa com `-Wall`.
- Estado global ou `static` que não é reiniciado entre testes.
- `using namespace std;` com nomes próprios como `count` ou `distance` gera ambiguidade; escolha outros nomes.
- Começar a digitar antes de combinar a abordagem com o entrevistador.

## Na entrevista

O molde serve para liberar sua atenção para o algoritmo. Mencione que usa `bits/stdc++.h` por velocidade e que, em código de produção, incluiria só os cabeçalhos necessários. Follow-ups comuns: "por que evitar variáveis globais aqui?" (o método pode ser chamado várias vezes) e "como você testaria esta função?" (casos de borda e um caso grande para desempenho).
