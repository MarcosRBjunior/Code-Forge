Em Python você passa `lambda x: x * 2` ou uma função anônima para `sorted(key=...)`; em JavaScript, uma arrow function para `sort` ou `filter`. Em C++ a necessidade é a mesma: `sort`, `count_if`, `find_if` e `priority_queue` pedem um pedacinho de lógica, e escrever uma função nomeada separada só para isso é cansativo. A lambda resolve: uma função anônima definida exatamente onde é usada, que ainda pode enxergar variáveis ao redor.

## Anatomia

A sintaxe tem três partes: `[captura](parâmetros) { corpo }`. O tipo de retorno é deduzido do `return`, e só precisa ser escrito (`-> tipo`) quando há retornos de tipos diferentes. A lambda é um objeto: pode ser guardada numa variável `auto` e chamada como função.

```cpp
#include <algorithm>
#include <iostream>
#include <vector>
using namespace std;

int main() {
    vector<int> v{5, 2, 8, 1};
    sort(v.begin(), v.end(), [](int a, int b) { return a > b; });
    for (int x : v) cout << x << " ";
    cout << "\n";

    int limite = 3;
    int maiores = count_if(v.begin(), v.end(),
                           [limite](int x) { return x > limite; });
    cout << maiores << "\n";

    int total = 0;
    for_each(v.begin(), v.end(), [&total](int x) { total += x; });
    cout << total << "\n";
}
```

```text
Saída:
8 5 2 1 
2
16
```

A primeira lambda não captura nada (`[]`) e define a ordem decrescente. A segunda copia `limite`. A terceira captura `total` por referência para acumular o resultado, algo que uma lambda por valor não conseguiria.

## Capturas

A lista de captura decide o que da vizinhança a lambda enxerga:

| Captura | Significado |
| --- | --- |
| `[]` | nada |
| `[x]` | `x` copiado no momento da criação |
| `[&x]` | `x` por referência (enxerga mudanças e pode alterar) |
| `[=]` | tudo que for usado, por cópia |
| `[&]` | tudo que for usado, por referência |
| `[c = 0]` | cria uma variável própria da lambda |

Por padrão, uma variável capturada por cópia é `const` dentro da lambda. Para modificar a cópia interna, marque a lambda como `mutable`; as mudanças ficam na cópia e persistem entre chamadas da mesma lambda, mas não afetam a variável original.

```cpp
#include <functional>
#include <iostream>
#include <string>
using namespace std;

int main() {
    int n = 10;
    auto porValor = [n]() { return n; };
    auto porRef = [&n]() { return n; };
    n = 20;
    cout << porValor() << " " << porRef() << "\n";

    auto contador = [c = 0]() mutable { return ++c; };
    int a = contador();
    int b = contador();
    int c = contador();
    cout << a << b << c << "\n";

    auto soma = [](auto x, auto y) { return x + y; };
    cout << soma(1, 2) << " " << soma(1.5, 2.0) << " "
         << soma(string("a"), string("b")) << "\n";

    function<int(int)> fat = [&](int k) -> int {
        return k <= 1 ? 1 : k * fat(k - 1);
    };
    cout << fat(5) << "\n";
}
```

```text
Saída:
10 20
123
3 3.5 ab
120
```

`porValor` congelou o 10 na criação; `porRef` viu o 20. A lambda com `auto` nos parâmetros é genérica: funciona como um template. E a recursão exige `std::function`, porque uma lambda `auto` não consegue citar a si mesma pelo nome.

## Armadilhas

- **Referência para algo que morreu**: capturar `[&]` e devolver a lambda de uma função, ou guardá-la para depois, deixa referências para variáveis locais já destruídas. Se a lambda sair do escopo, capture por valor.
- **`[=]` não copia membros de um objeto**: dentro de métodos ele captura `this`, e o código ainda enxerga o objeto original. Em C++20 isso foi marcado como obsoleto.
- **Capturar por cópia um vetor grande** a cada chamada custa caro; capture por referência se o tempo de vida permitir.
- **Comparadores inconsistentes**: no `sort`, a lambda precisa ser uma ordem estrita (`<` ou `>`, nunca `<=`), senão o comportamento é indefinido.
- **`std::function` é mais lenta** que uma lambda guardada em `auto`, porque apaga o tipo; use-a só quando precisar de recursão ou de armazenar lambdas diferentes na mesma variável.

## Na entrevista

O uso mais frequente é o comparador do `sort` e da `priority_queue`, e o predicado de `find_if` ou `remove_if`. Em DFS recursivo dentro de uma função, uma lambda recursiva com `function` evita criar atributos de classe. Prefira capturas explícitas (`[&grid, n]`) a `[&]` para mostrar controle sobre o que a lambda usa. Follow-ups comuns: "qual a diferença entre capturar por valor e por referência?" e "por que a lambda precisa de mutable para alterar uma variável copiada?" (porque o operador de chamada gerado é const por padrão).
