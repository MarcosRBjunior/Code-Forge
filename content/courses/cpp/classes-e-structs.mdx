Em Python você agrupa dados e comportamento numa `class` e o interpretador cuida do resto. Em C++ a ideia é a mesma, mas você decide quem pode mexer em cada campo, como o objeto nasce e o que acontece quando ele morre. Em entrevista isso aparece de duas formas: um `struct` pequeno para guardar um nó ou um par de valores, e uma classe completa em questões de design (um cache, um relógio, uma conta bancária).

## struct versus class

Há uma única diferença técnica: em `struct` os membros são públicos por padrão, em `class` são privados. O resto (métodos, construtores, herança) é idêntico. A convenção é usar `struct` para agregados simples de dados, sem invariantes a proteger, e `class` quando existe estado interno que só os métodos devem alterar.

Um campo privado existe para proteger uma regra. Numa conta bancária, o saldo nunca pode ficar negativo; se o campo fosse público, qualquer código de fora quebraria a regra. Por isso o saldo fica privado e a alteração passa por `sacar`, que valida.

## Construtores e a lista de inicialização

O construtor roda quando o objeto é criado. A forma idiomática de inicializar membros é a lista de inicialização, depois dos dois pontos. Ela constrói cada membro já com o valor final, em vez de construir vazio e atribuir depois, e é obrigatória para membros `const` e referências.

Um detalhe que pega muita gente: os membros são inicializados na ordem em que são declarados na classe, não na ordem em que aparecem na lista. Se um membro depende de outro, declare-os na ordem certa.

Métodos que não alteram o objeto devem ser marcados `const` depois dos parênteses. Isso permite chamá-los em objetos `const` e em referências `const&`, que você usa o tempo todo ao passar objetos para funções sem copiá-los.

```cpp
#include <iostream>
#include <string>
using namespace std;

struct Ponto {
    int x = 0;
    int y = 0;
};

class Conta {
public:
    Conta(string dono, int saldo) : dono_(dono), saldo_(saldo) {}
    void depositar(int v) { saldo_ += v; }
    bool sacar(int v) {
        if (v > saldo_) return false;
        saldo_ -= v;
        return true;
    }
    int saldo() const { return saldo_; }
    const string& dono() const { return dono_; }

private:
    string dono_;
    int saldo_;
};

int main() {
    Ponto p{3, 4};
    Ponto q;
    cout << p.x << "," << p.y << " " << q.x << "," << q.y << "\n";
    Conta c("Ana", 100);
    c.depositar(50);
    cout << c.dono() << " " << c.saldo() << "\n";
    cout << (c.sacar(500) ? "ok" : "negado") << "\n";
    cout << (c.sacar(30) ? "ok" : "negado") << " " << c.saldo() << "\n";
}
```

```text
Saída:
3,4 0,0
Ana 150
negado
ok 120
```

Note os valores padrão em `Ponto`: sem eles, `Ponto q;` deixaria `x` e `y` com lixo de memória. Em C++ variáveis locais de tipo primitivo não são zeradas automaticamente, diferente de Python, onde tudo tem valor.

## Destrutor e ciclo de vida

O destrutor roda automaticamente quando o objeto sai de escopo, na ordem inversa da construção. Essa previsibilidade é a base do RAII, assunto do próximo módulo: o objeto adquire um recurso no construtor e o libera no destrutor, sem você lembrar de nada.

```cpp
#include <iostream>
#include <string>
using namespace std;

struct Log {
    string nome;
    Log(string n) : nome(n) { cout << "cria " << nome << "\n"; }
    ~Log() { cout << "destroi " << nome << "\n"; }
};

int main() {
    Log a("a");
    {
        Log b("b");
    }
    Log c("c");
    cout << "fim\n";
}
```

```text
Saída:
cria a
cria b
destroi b
cria c
fim
destroi c
destroi a
```

O `b` morre ao fechar o bloco interno; `c` e `a` morrem ao fim de `main`, o último criado primeiro. Em JavaScript ou Python você dependeria do coletor de lixo e não saberia o momento exato.

## Operadores e ordenação

Para ordenar ou usar um objeto como chave de `set` e `map`, defina `operator<`. A forma mais curta é um método `const`:

```cpp
struct Aluno {
    string nome;
    int nota;
    bool operator<(const Aluno& o) const { return nota < o.nota; }
};
// vector<Aluno> v; sort(v.begin(), v.end());  // ordena por nota crescente
```

Esquecer o `const` no operador faz o `sort` ou o `set` falharem na compilação com mensagens enormes. Se aparecer um erro de template quilométrico perto de comparação, comece verificando isso.

## Armadilhas

- **Cópia silenciosa**: passar um objeto por valor (`void f(Aluno a)`) copia tudo. Use `const Aluno&` para leitura.
- **Membros não inicializados**: tipos primitivos ficam com lixo; sempre dê valor padrão ou inicialize na lista.
- **Getters sem const**: impedem o uso em referências constantes.
- **Regra dos três/cinco**: se você escrever destrutor, cópia ou movimentação à mão, provavelmente precisa definir as outras. Na dúvida, não escreva nenhuma e deixe os membros (`vector`, `string`, smart pointers) cuidarem de si.

## Na entrevista

Para estruturas de dados auxiliares, um `struct` com membros públicos basta e economiza digitação. Em questões de design (LRU Cache, estacionamento), use `class` com dados privados e uma interface pequena, e explique por que o estado é privado. Follow-ups comuns: "qual a diferença entre struct e class em C++?" (só a visibilidade padrão) e "por que o getter é const?" (para ser chamado em objetos constantes e garantir que não altera o estado).
