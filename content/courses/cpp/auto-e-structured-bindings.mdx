Quem vem de Python e JavaScript está acostumado a não declarar tipos. C++ continua estático, mas desde o C++11 o compilador pode deduzir o tipo por você com `auto`, e desde o C++17 você pode desmontar pares, tuplas e structs em variáveis com nome, como o `for k, v in d.items()` do Python. Os dois recursos tornam o código de entrevista bem mais curto, principalmente com iteradores e mapas.

## O problema

Os tipos da STL ficam longos. O iterador de um `map<string, vector<int>>` é `map<string, vector<int>>::iterator`, e digitar isso num quadro branco consome tempo e atenção. Já o resultado de `m.insert(...)` é um `pair<iterator, bool>`. Nada disso ajuda a explicar a ideia do algoritmo.

## auto: o tipo vem do valor

`auto x = expressão;` faz `x` ter o tipo da expressão. O tipo continua fixo: `auto x = 5;` é um `int` para sempre, e `x = "texto"` não compila. Duas regras importam:

- `auto` sozinho **copia** e descarta `const` e referência.
- `auto&` e `const auto&` mantêm a referência e evitam a cópia.

Essa segunda regra é a fonte do erro mais comum com `auto` em laços:

```cpp
#include <iostream>
#include <string>
#include <vector>
using namespace std;

int main() {
    vector<string> v{"a", "b"};
    for (auto s : v) s += "!";
    cout << v[0] << v[1] << "\n";
    for (auto& s : v) s += "!";
    cout << v[0] << " " << v[1] << "\n";

    auto x = 5;
    auto y = 2.5;
    auto z = x * y;
    auto w = 'a' + 1;
    cout << z << " " << w << "\n";

    const auto& ref = v[0];
    cout << ref << "\n";
}
```

```text
Saída:
ab
a! b!
12.5 98
a!
```

O primeiro laço modificou uma cópia de cada string e o vetor ficou intacto. No segundo, `auto&` altera os elementos de verdade. Note também que `'a' + 1` é um `int` (98), não um `char`, e `x * y` promove para `double`. Regra prática: use `const auto&` para ler elementos grandes, `auto&` para alterar e `auto` apenas para tipos pequenos como `int` e `char`.

## Structured bindings

Com colchetes você desmonta um objeto em vários nomes: `auto [a, b] = par;`. Funciona com `pair`, `tuple`, `array` e qualquer struct simples cujos membros sejam públicos. A forma mais útil em entrevista é percorrer mapas:

```cpp
#include <iostream>
#include <map>
#include <string>
#include <tuple>
using namespace std;

struct Ponto {
    int x, y;
};

int main() {
    map<string, int> m{{"b", 2}, {"a", 1}};
    for (const auto& [k, val] : m) cout << k << "=" << val << "\n";

    pair<int, string> p{1, "x"};
    auto [i, s] = p;
    cout << i << s << "\n";

    tuple<int, double> t{7, 0.5};
    auto [a, b] = t;
    cout << a << " " << b << "\n";

    Ponto pt{3, 4};
    auto [px, py] = pt;
    cout << px + py << "\n";

    auto [it, inserido] = m.insert({"a", 5});
    cout << inserido << " " << it->second << "\n";
}
```

```text
Saída:
a=1
b=2
1x
7 0.5
7
0 1
```

Os mapas guardam pares `(chave, valor)`, e o laço com `[k, val]` evita os feios `it->first` e `it->second`. A última linha usa o retorno de `insert`, um par com o iterador e um bool dizendo se houve inserção. Como a chave `"a"` já existia, nada foi inserido e o iterador aponta para o valor antigo (1).

## Armadilhas

- Structured bindings não são variáveis independentes quando usados com `auto&`: `auto& [k, v]` em um mapa permite alterar `v`, mas `k` é const.
- Com `auto [a, b] = ...` você ganha **cópias**. Para não copiar, use `const auto& [a, b]`.
- Não dá para pular elementos: todos os membros precisam de um nome. Convenção é usar `_` ou um nome descartável (e ignorar o aviso do compilador).
- `auto` dentro de lambdas como parâmetro cria uma lambda genérica (um template), não uma variável única.
- Não use `auto` quando o tipo é a informação importante. Em um enunciado, escrever `int soma = 0;` é mais claro que `auto soma = 0;`, e `auto n = v.size();` dá `size_t`, sem sinal.

## Na entrevista

Use `auto` para iteradores e retornos longos, e `for (const auto& [chave, valor] : mapa)` para percorrer mapas. Evite `auto` nos tipos numéricos de contadores, para não deixar um `size_t` sem sinal escapar sem você ver. Follow-ups típicos: "qual a diferença entre `auto` e `auto&`?" e "o que acontece com `const` ao usar `auto`?" (é descartado, a menos que você escreva `const auto`).
