A maioria dos bugs de C++ em entrevista não vem do algoritmo, e sim de detalhes da linguagem que em Python ou JavaScript simplesmente não existem: cópias escondidas, iteradores invalidados, divisão inteira, comparadores errados. Cada uma dessas armadilhas custa minutos de depuração no quadro, ou um teste escondido falhando. Este capítulo reúne as mais frequentes, com o sintoma e a correção.

## 1. Cópias escondidas

Passar `vector<int> v` como parâmetro copia o vetor inteiro a cada chamada. Numa DFS recursiva que recebe o grafo por valor, isso transforma O(V + E) em algo quadrático e estoura o tempo. A regra: contêineres vão por `const&` (só leitura) ou `&` (modificação). O mesmo vale para o laço `for (auto x : matriz)`, que copia cada linha.

## 2. Divisão inteira e mistura de tipos

`7 / 2` é 3, não 3.5, como o `//` do Python. Para obter um decimal, converta um dos operandos: `7 / 2.0` ou `(double)a / b`. E `-7 / 2` é -3 em C++ (trunca em direção a zero), enquanto em Python `-7 // 2` é -4. O mesmo vale para o resto: `-7 % 3` dá -1 em C++, e não 2. Em problemas com índices circulares, use `((x % n) + n) % n`.

```cpp
#include <iostream>
using namespace std;

int main() {
    cout << 7 / 2 << " " << 7 / 2.0 << "\n";
    cout << -7 / 2 << " " << -7 % 3 << "\n";
    int n = 5, x = -2;
    cout << ((x % n) + n) % n << "\n";
    int a = 1, b = 3;
    double media = (a + b) / 2;
    double certa = (a + b) / 2.0;
    cout << media << " " << certa << "\n";
}
```

```text
Saída:
3 3.5
-3 -1
3
2 2
```

Note que `media` e `certa` deram 2 aqui só porque a soma é par; com `a = 1, b = 2`, a primeira daria 1 e a segunda 1.5. A conversão para `double` depois da divisão inteira já chega tarde.

## 3. Iteradores invalidados

Apagar de um contêiner enquanto o percorre é UB se você continuar usando o iterador apagado. `erase` devolve o próximo iterador válido; use-o. Da mesma forma, `push_back` em um `vector` pode realocar e invalidar todas as referências e iteradores guardados.

```cpp
#include <iostream>
#include <map>
#include <vector>
using namespace std;

int main() {
    vector<int> v{1, 2, 3, 4, 5, 6};
    for (auto it = v.begin(); it != v.end();) {
        if (*it % 2 == 0) it = v.erase(it);
        else ++it;
    }
    for (int x : v) cout << x << " ";
    cout << "\n";

    map<int, int> m{{1, 10}, {2, 20}, {3, 30}};
    for (auto it = m.begin(); it != m.end();) {
        if (it->second > 15) it = m.erase(it);
        else ++it;
    }
    cout << m.size() << "\n";

    vector<int> w{1, 2, 3};
    int primeiro = w[0];
    w.push_back(4);
    cout << primeiro << " " << w[0] << "\n";
}
```

```text
Saída:
1 3 5 
1
1 1
```

O último bloco guarda o **valor** (uma cópia) antes do `push_back`, o que é seguro. Guardar `int& r = w[0]` e usar `r` depois do `push_back` seria UB.

## 4. Comparador que não é ordem estrita

Para `sort`, `set` e `priority_queue`, o comparador deve se comportar como `<`: retornar `false` para elementos iguais. Usar `<=` viola a regra e pode causar crash ou laço infinito no `sort`. Lembre também que `priority_queue` com `less` é um heap de **máximo**; para mínimo, use `greater<int>`.

## 5. Outras pegadinhas rápidas

- `map[k]` insere a chave se ela não existe; use `count` ou `find` para testar.
- `v.size() - 1` com vetor vazio dá um número enorme (sem sinal).
- `int` estoura acima de 2,1 bilhões; use `long long`.
- `string s = 'a' + "bc";` não concatena: soma um número a um ponteiro. Use `string(1, 'a') + "bc"`.
- `==` entre `double` raramente funciona; compare com tolerância.
- `memset(arr, 1, sizeof arr)` em um array de `int` não coloca 1 em cada posição (preenche bytes); use `fill` ou `vector<int>(n, 1)`.
- Variáveis globais começam zeradas; locais não. Inicialize sempre.
- Matriz como `vector<vector<int>> g(n, vector<int>(m))`: inverter `n` e `m` causa acessos fora dos limites silenciosos.

## Na entrevista

Antes de dizer "terminei", passe por um checklist curto: parâmetros por referência, tipos que podem estourar, divisão inteira, laços com `size()` sem sinal e casos vazios. Diga isso em voz alta; mostra maturidade. Follow-ups comuns: "por que este código fica lento em entradas grandes?" (muitas vezes, cópia por valor) e "o que acontece se você apagar durante a iteração?" (invalida o iterador; use o retorno de `erase`).
