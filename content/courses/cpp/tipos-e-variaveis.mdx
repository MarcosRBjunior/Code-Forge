Python e JavaScript decidem o tipo de um valor em tempo de execução. C++ é estaticamente tipado: cada variável tem um tipo fixo, escolhido no momento em que você a declara, e esse tipo define quantos bytes ela ocupa e qual faixa de valores aceita. Escolher mal o tipo é a origem de muitos bugs de entrevista, principalmente overflow.

## Os tipos que você realmente usa

| Tipo | Tamanho típico | Uso |
|---|---|---|
| `int` | 4 bytes | contadores, índices pequenos, valores até cerca de 2 bilhões |
| `long long` | 8 bytes | somas, produtos, valores grandes |
| `double` | 8 bytes | números com casas decimais |
| `bool` | 1 byte | verdadeiro ou falso |
| `char` | 1 byte | um caractere |
| `size_t` | 8 bytes, sem sinal | tamanhos e índices vindos da biblioteca |

O tamanho exato depende da plataforma, mas em GCC no x86-64 esses valores são os esperados. Em Python o `int` cresce sem limite; em JavaScript todo número é um `double`. Aqui o `int` tem teto, e passar dele é um erro silencioso.

```cpp
#include <iostream>
#include <climits>

int main() {
    std::cout << sizeof(int) << " " << sizeof(long long) << " " << sizeof(double) << '\n';
    std::cout << INT_MAX << '\n';
    std::cout << LLONG_MAX << '\n';
    long long grande = 1LL * INT_MAX * 2;
    std::cout << grande << '\n';
    return 0;
}
```

```text
Saída:
4 8 8
2147483647
9223372036854775807
4294967294
```

O sufixo `LL` torna o literal um `long long`. Sem ele, `INT_MAX * 2` seria calculado em `int` e estouraria antes de ser guardado na variável maior. Esse é o erro clássico: o tipo da conta é decidido pelos operandos, não pelo destino.

## Declarar, inicializar e deduzir

Variáveis locais não são zeradas automaticamente. Ler uma delas sem atribuir é comportamento indefinido, então inicialize sempre. A inicialização com chaves ainda recusa conversões que perdem informação.

```cpp
#include <iostream>
#include <string>

int main() {
    int a = 10;
    int b{20};
    auto c = 3.5;
    auto nome = std::string("grafo");
    const int LIMITE = 100;
    std::cout << a + b << " " << c << " " << nome << " " << LIMITE << '\n';
    return 0;
}
```

```text
Saída:
30 3.5 grafo 100
```

A palavra `auto` pede ao compilador que deduza o tipo a partir do valor inicial; ela continua estática, apenas poupa digitação. `const` impede reatribuição, e marcar como constante tudo que não muda documenta a intenção e pega erros em tempo de compilação.

## Sinal e tamanho: a armadilha do unsigned

`size()` de um contêiner devolve um tipo sem sinal. Subtrair de um valor sem sinal que já é zero não dá menos um: dá um número enorme.

```cpp
// std::vector<int> v;               // vazio
// for (int i = 0; i < v.size() - 1; i++) { ... }
// v.size() - 1 vale 18446744073709551615, o laço roda "para sempre"
// Correção: converta antes
// int n = (int)v.size();  for (int i = 0; i < n - 1; i++) { ... }
```

Do mesmo jeito, comparar um `int` negativo com um valor sem sinal faz o negativo virar enorme. O hábito seguro é guardar `int n = v.size();` no começo e usar `n` nas contas.

## Na entrevista

Diga o tipo que você escolhe e por quê: "uso `long long` para a soma porque 100 mil elementos de até 1 bilhão estouram um `int`". Isso mostra que você leu as restrições. Follow-ups frequentes: "qual o maior valor de um `int`?" (cerca de 2,1 bilhões, `INT_MAX`) e "o que acontece com uma variável local não inicializada?" (valor lixo, e ler esse valor é comportamento indefinido).
