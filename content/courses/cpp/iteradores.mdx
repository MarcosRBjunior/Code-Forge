Em Python, um laço `for x in coisa` funciona para lista, dicionário, conjunto ou gerador, porque todos seguem o mesmo protocolo de iteração. Em C++ esse papel é dos **iteradores**: objetos que apontam para uma posição dentro de um contêiner e sabem avançar para a próxima. Eles são a cola entre contêineres e algoritmos da STL, e entender como funcionam evita alguns dos bugs mais traiçoeiros da linguagem.

## O que é um iterador

Pense em um iterador como um ponteiro generalizado. Com `*it` você lê o elemento, com `++it` avança, e com `it == outro` compara posições. Todo contêiner oferece `begin()`, que aponta para o primeiro elemento, e `end()`, que aponta para a posição **depois** do último. O `end()` não é um elemento: desreferenciá-lo é comportamento indefinido. Ele serve de marca de parada e de valor de "não encontrado".

```cpp
#include <iostream>
#include <vector>
#include <map>
#include <string>

int main() {
    std::vector<int> v = {10, 20, 30, 40};
    for (auto it = v.begin(); it != v.end(); ++it) std::cout << *it << ' ';
    std::cout << '\n';

    for (auto it = v.rbegin(); it != v.rend(); ++it) std::cout << *it << ' ';
    std::cout << '\n';

    auto it = v.begin() + 2;
    std::cout << *it << " " << (it - v.begin()) << " " << *(it - 1) << '\n';

    std::map<std::string, int> idade = {{"ana", 30}, {"bia", 25}};
    for (auto m = idade.begin(); m != idade.end(); ++m)
        std::cout << m->first << ":" << m->second << ' ';
    std::cout << '\n';

    auto achou = idade.find("caio");
    std::cout << (achou == idade.end() ? "ausente" : "presente") << '\n';
    return 0;
}
```

```text
Saída:
10 20 30 40 
40 30 20 10 
30 2 20
ana:30 bia:25 
ausente
```

O laço por intervalo, `for (int x : v)`, é apenas açúcar sintático para esse laço com `begin` e `end`. Os iteradores reversos `rbegin` e `rend` percorrem de trás para a frente. Num `map`, o iterador aponta para um par, e `m->first` e `m->second` acessam chave e valor.

## Categorias e custo

Nem todo iterador sabe fazer tudo. A categoria determina quais operações são O(1).

| Categoria | Operações | Contêineres |
|---|---|---|
| Acesso aleatório | `it + k`, `it - outro`, `it[k]`, `<` | `vector`, `deque`, `string`, `array` |
| Bidirecional | `++`, `--` | `list`, `map`, `set` |
| Avanço | só `++` | `forward_list`, `unordered_map` |

Por isso `it + 3` funciona num `vector` mas não compila num `set`. Para esses casos existem `std::next(it, k)`, `std::prev(it)` e `std::distance(a, b)`, que funcionam com qualquer categoria, mas custam O(k) quando o iterador não é de acesso aleatório. É também por isso que `sort` exige acesso aleatório e não aceita `list`.

## Invalidação: o bug clássico

Um iterador fica **inválido** quando o contêiner muda de modo a mover ou destruir o elemento. Usar um iterador inválido é comportamento indefinido, e o programa pode até parecer funcionar.

```cpp
// std::vector<int> v = {1, 2, 3};
// auto it = v.begin();
// v.push_back(4);       // pode realocar: it agora aponta para memória liberada
// std::cout << *it;     // comportamento indefinido
//
// for (auto it = v.begin(); it != v.end(); ++it)
//     if (*it % 2 == 0) v.erase(it);   // errado: it fica inválido e ainda é incrementado
```

As regras a lembrar: no `vector`, qualquer inserção que realoca invalida tudo, e `erase` invalida a partir do ponto removido. No `map` e no `set`, só o iterador do elemento apagado fica inválido. A forma correta de apagar dentro do laço é usar o valor que `erase` devolve, que aponta para o próximo elemento.

```cpp
#include <iostream>
#include <vector>
#include <set>
#include <algorithm>
#include <iterator>

int main() {
    std::vector<int> v = {1, 2, 3, 4, 5, 6};
    for (auto it = v.begin(); it != v.end();) {
        if (*it % 2 == 0) it = v.erase(it);
        else ++it;
    }
    for (int x : v) std::cout << x << ' ';
    std::cout << '\n';

    std::vector<int> w = {1, 2, 3, 4, 5, 6};
    w.erase(std::remove_if(w.begin(), w.end(), [](int x) { return x % 3 == 0; }), w.end());
    for (int x : w) std::cout << x << ' ';
    std::cout << '\n';

    std::set<int> s = {5, 10, 15, 20};
    auto a = s.find(10);
    auto b = std::next(a, 2);
    std::cout << *b << " " << std::distance(s.begin(), a) << " " << *std::prev(s.end()) << '\n';
    return 0;
}
```

```text
Saída:
1 3 5 
1 2 4 5 
20 1 20
```

O primeiro laço só incrementa quando não apaga, porque `erase` já devolveu a próxima posição. A segunda forma, `remove_if` seguido de `erase`, é preferível em `vector`: faz tudo em O(n), enquanto apagar um a um no meio custa O(n) por remoção, O(n²) no total.

## Na entrevista

Use iteradores quando um algoritmo da STL pede, como em `sort(v.begin(), v.end())` ou `lower_bound`, e converta para índice com `it - v.begin()`. Follow-ups comuns: "por que o programa quebra ao apagar dentro do laço?" (iterador invalidado) e "por que `end()` aponta para depois do último?" (intervalo semiaberto: o vazio é `begin() == end()` e o tamanho é a diferença).
