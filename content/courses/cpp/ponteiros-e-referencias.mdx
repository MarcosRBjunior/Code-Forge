Em Python e JavaScript, variáveis de objetos já são referências: você passa uma lista para uma função e ela enxerga a mesma lista. Em C++ o padrão é o oposto, tudo é cópia, e você escolhe explicitamente quando quer compartilhar. Ponteiros e referências são as duas ferramentas para isso, e dominá-las é o que separa quem lê código C++ de quem escreve.

## Referência: um apelido

Uma referência (`int&`) é outro nome para uma variável que já existe. Ela precisa ser inicializada na declaração, não pode ser reapontada e nunca é nula. Por isso é a escolha padrão para parâmetros que a função precisa alterar ou que são grandes demais para copiar.

Regra prática para parâmetros: tipos pequenos (`int`, `char`, `double`) vão por valor; objetos grandes só para leitura vão por `const T&`; objetos que a função precisa modificar vão por `T&`.

## Ponteiro: um endereço

Um ponteiro (`int*`) guarda o endereço de memória de outro valor. O operador `&` pega o endereço, `*` acessa o valor apontado (desreferência) e `->` acessa um membro através do ponteiro. Diferente da referência, o ponteiro pode ser nulo (`nullptr`), pode ser reatribuído e pode percorrer um array com aritmética.

```cpp
#include <iostream>
using namespace std;

void trocaPtr(int* a, int* b) { int t = *a; *a = *b; *b = t; }
void trocaRef(int& a, int& b) { int t = a; a = b; b = t; }

int main() {
    int x = 1, y = 2;
    trocaPtr(&x, &y);
    cout << x << " " << y << "\n";
    trocaRef(x, y);
    cout << x << " " << y << "\n";
    int* p = &x;
    *p = 10;
    cout << x << "\n";
    int& r = y;
    r = 99;
    cout << y << "\n";
    int* n = nullptr;
    cout << (n == nullptr) << "\n";
}
```

```text
Saída:
2 1
1 2
10
99
1
```

A versão com referência é mais limpa na chamada (`trocaRef(x, y)`), por isso é preferida em C++ moderno. Ponteiros aparecem quando o valor pode não existir (retorno de uma busca) ou quando você precisa montar estruturas encadeadas.

## Estruturas encadeadas e aritmética

Listas ligadas e árvores, tão comuns em entrevista, são feitas de ponteiros para o próximo nó. Sempre teste contra `nullptr` antes de desreferenciar. Já um array se comporta como um ponteiro para o primeiro elemento: `p + 2` avança dois elementos (não dois bytes) e `p[1]` equivale a `*(p + 1)`.

```cpp
#include <iostream>
using namespace std;

struct No {
    int val;
    No* prox;
};

int main() {
    No c{3, nullptr};
    No b{2, &c};
    No a{1, &b};
    int soma = 0;
    for (No* p = &a; p != nullptr; p = p->prox) {
        soma += p->val;
        cout << p->val << (p->prox ? " -> " : "\n");
    }
    cout << "soma=" << soma << "\n";
    int arr[] = {10, 20, 30};
    int* p = arr;
    cout << *p << " " << *(p + 2) << " " << p[1] << "\n";
    cout << (&arr[2] - &arr[0]) << "\n";
}
```

```text
Saída:
1 -> 2 -> 3
soma=6
10 30 20
2
```

Os nós aqui moram na pilha, então não precisamos liberar nada. Quando usar `new`, a responsabilidade de chamar `delete` é sua; o capítulo seguinte mostra como evitar isso.

## const com ponteiros

Leia a declaração da direita para a esquerda. `const int* p` é um ponteiro para um int constante: você não altera o valor, mas pode reapontar. `int* const p` é um ponteiro constante: aponta sempre para o mesmo lugar, mas o valor pode mudar. Em 95% dos casos o que você escreve é `const T&` e `const T*`.

## Armadilhas

- **Ponteiro nulo**: desreferenciar `nullptr` é comportamento indefinido, normalmente um crash. Teste antes.
- **Ponteiro solto (dangling)**: guardar o endereço de uma variável local e usá-lo depois que a função retornou. O mesmo vale para uma referência a um elemento de `vector` depois de um `push_back`, que pode realocar a memória.
- **Retornar referência para local**: `int& f() { int x = 1; return x; }` devolve um apelido para algo que já morreu.
- **Ponteiro não inicializado**: contém lixo; inicialize com `nullptr`.
- **Usar `NULL` ou `0`**: prefira sempre `nullptr`, que tem tipo próprio.

## Na entrevista

Em problemas de lista ligada e árvore você manipula `No*` direto; escreva o teste de `nullptr` como primeira linha da função. Para o resto, prefira referências. Follow-ups comuns: "qual a diferença entre ponteiro e referência?" (ponteiro pode ser nulo e reatribuído; referência não) e "o que é um dangling pointer?" (aponta para memória que já foi liberada ou saiu de escopo).
