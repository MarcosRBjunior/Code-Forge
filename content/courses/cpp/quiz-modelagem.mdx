<Quiz question="Você está escrevendo uma struct No para uma lista ligada e esqueceu de inicializar o membro prox. O que o compilador garante sobre o valor dele numa variável local?" options={["É nullptr, pois o compilador inicializa ponteiros automaticamente","É zero, pois todo membro não inicializado recebe o valor padrão do tipo","Dá erro de compilação, pois o membro precisa ser inicializado","Tem valor indeterminado (lixo), pois locais não são inicializados"]} answer={3} explanation="Tipos primitivos e ponteiros locais não são inicializados automaticamente. <Quiz question="Uma função recebe um vector grande só para somar seus elementos. Qual assinatura é a mais adequada?" options={["Por valor sem const, pois o compilador evita a cópia ao ver que só lê","Por referência não constante (T&), pois aceita também argumentos temporários","Por referência rvalue (&&), pois aceita qualquer vetor sem copiá-lo","Por referência constante (const T&), sem copiar e só para leitura"]} answer={3} explanation="const T& evita a cópia e deixa claro que a função só lê. Passar por valor copiaria todos os elementos." />
<Quiz question="O que há de errado em int& f() { int x = 5; return x; }?" options={["Falta const no retorno, pois toda referência retornada precisa ser const","Devolve referência para uma variável local que já foi destruída","Nada, pois retornar referência é um idioma comum para evitar cópias","Referências não podem ser retornadas por funções em C++ moderno"]} answer={1} explanation="A variável local morre ao fim da função; a referência devolvida fica solta e usá-la é comportamento indefinido." />
<Quiz question="Duas estruturas se referenciam mutuamente com shared_ptr e, ao sair de escopo, o destrutor nunca é chamado. Qual a correção?" options={["Trocar um dos lados por weak_ptr", "Chamar delete manualmente nos dois", "Usar new em vez de make_shared", "Trocar ambos por ponteiros crus sem dono"]} answer={0} explanation="Um ciclo de shared_ptr mantém os contadores acima de zero. weak_ptr observa sem possuir e quebra o ciclo." />
<Quiz question="Uma função aloca com new, faz um cálculo que pode lançar exceção e só depois chama delete. Qual o risco e a correção?" options={["Nenhum risco, pois o delete sempre roda mesmo depois de uma exceção","Erro de compilação, pois new e throw não coexistem; use malloc no lugar","Corrupção da pilha, e a correção é capturar com catch (...) sem relançar","Vazamento se a exceção ocorrer antes do delete; usar unique_ptr resolve"]} answer={3} explanation="Se a exceção sair antes do delete, a memória vaza. Com RAII (unique_ptr, vector), o destrutor libera mesmo no desenrolar da pilha." />
<Quiz question="Ao chamar maior(3, 4.5) numa função template com um único parâmetro de tipo T para os dois argumentos, qual o resultado?" options={["Retorna 4.5, pois o int é promovido para double automaticamente","Retorna 4, pois T é fixado pelo primeiro argumento, que é int","Erro de compilação, pois T é deduzido como int e como double","Resulta em comportamento indefinido em tempo de execução"]} answer={2} explanation="A dedução exige um único T. Escreva maior com double explícito ou converta um dos argumentos." />
