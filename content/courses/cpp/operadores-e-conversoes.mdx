Quase todos os operadores de C++ têm o mesmo símbolo que em Python e JavaScript, o que dá uma falsa sensação de familiaridade. As diferenças aparecem em três lugares: divisão e resto com números negativos, operadores de bits e conversões automáticas entre tipos. Em entrevista, é aí que as respostas erradas nascem.

## Aritmética e resto

A divisão entre inteiros trunca em direção a zero. O resto tem o sinal do dividendo. Em Python, `-7 // 2` dá `-4` e `-7 % 2` dá `1`; em C++ os resultados são diferentes.

```cpp
#include <iostream>

int main() {
    std::cout << -7 / 2 << " " << -7 % 2 << '\n';
    std::cout << 7 / 2 << " " << 7 % 2 << '\n';
    int i = 5;
    int a = i++;
    int b = ++i;
    std::cout << a << " " << b << " " << i << '\n';
    std::cout << (6 & 3) << " " << (6 | 3) << " " << (6 ^ 3) << " " << (1 << 4) << " " << (32 >> 2) << '\n';
    return 0;
}
```

```text
Saída:
-3 -1
3 1
5 7 7
2 7 5 16 8
```

O `i++` devolve o valor antigo e depois incrementa; o `++i` incrementa primeiro. Como um mod positivo é comum em problemas com índices circulares, o padrão é `((x % m) + m) % m`, que funciona mesmo para `x` negativo.

Os operadores de bits trabalham em cada bit: `&` é E, `|` é OU, `^` é OU exclusivo, e `<<`, `>>` deslocam. Deslocar um bit à esquerda por `k` multiplica por 2 elevado a `k`, e `x & 1` testa se `x` é ímpar. Cuidado com a precedência: `a & b == c` é lido como `a & (b == c)`. Use parênteses.

## Conversões implícitas

Quando os operandos têm tipos diferentes, o menor é promovido ao maior. `int` com `double` vira `double`, e `int` com `long long` vira `long long`. O que surpreende é a mistura com tipos sem sinal.

```cpp
#include <iostream>
#include <cmath>

int main() {
    std::cout << 7 / 2 << " " << (double)7 / 2 << " " << 7 / 2.0 << '\n';
    std::cout << static_cast<int>(3.99) << " " << static_cast<int>(-3.99) << '\n';
    char c = 'a';
    std::cout << c + 1 << " " << static_cast<char>(c + 1) << '\n';
    std::cout << (-1 < 1u) << '\n';
    std::cout << (0.1 + 0.2 == 0.3) << " " << (std::fabs(0.1 + 0.2 - 0.3) < 1e-9) << '\n';
    return 0;
}
```

```text
Saída:
3 3.5 3.5
3 -3
98 b
0
0 1
```

Pontos que o código mostra. Converter decimal para inteiro descarta a parte fracionária, sem arredondar. A soma de um `char` com um `int` é um `int`, por isso aparece 98 e não `b`. A comparação `-1 < 1u` dá falso porque o `-1` é convertido para sem sinal e vira um valor gigantesco. E números decimais não são exatos: nunca compare `double` com `==`, compare a diferença com uma tolerância.

## static_cast em vez de cast de C

O estilo `(int)x` ainda funciona, mas `static_cast<int>(x)` é mais fácil de procurar e mais restrito, então erra em menos lugares. Em entrevista os dois são aceitos; só seja consistente.

## Curto-circuito e ternário

Os operadores `&&` e `||` avaliam da esquerda para a direita e param assim que o resultado é conhecido. Isso permite escrever `i < n && v[i] == x` sem acessar fora do limite. O operador ternário `cond ? a : b` funciona como em JavaScript e substitui um `if` simples dentro de uma expressão.

## Na entrevista

Se o problema envolve soma, produto ou contagem grande, cite o risco de overflow e declare o acumulador como `long long`. Ao dividir para obter média ou percentual, converta um operando para `double` antes. Follow-ups típicos: "por que `-7 % 3` não dá 2?" (o resto acompanha o sinal do dividendo) e "como testar se um número é potência de dois?" (`x > 0 && (x & (x - 1)) == 0`).
