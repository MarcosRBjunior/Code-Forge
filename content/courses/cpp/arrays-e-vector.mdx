A lista do Python e o array do JavaScript crescem sozinhos e checam índices. Em C++, o equivalente do dia a dia é o `std::vector`: um bloco contíguo de memória que cresce quando preciso, com acesso por índice em tempo constante. Quase toda solução de entrevista começa nele, e o "array cru" de C só aparece em casos específicos.

## vector: o que você usa em 90% dos casos

Um `vector` guarda elementos do mesmo tipo, um depois do outro na memória. Acessar `v[i]` é O(1). Adicionar no fim com `push_back` é O(1) amortizado: de vez em quando o vetor realoca para um bloco maior e copia tudo, mas em média o custo por inserção é constante.

```cpp
#include <iostream>
#include <vector>

int main() {
    std::vector<int> v;
    for (int i = 1; i <= 5; i++) v.push_back(i * i);
    std::cout << v.size() << " " << v.front() << " " << v.back() << '\n';
    v.pop_back();
    v.insert(v.begin() + 1, 100);
    v.erase(v.begin());
    for (int x : v) std::cout << x << ' ';
    std::cout << '\n';

    std::vector<int> zeros(4, 0);
    std::vector<int> copia = v;
    copia[0] = -1;
    std::cout << zeros.size() << " " << v[0] << " " << copia[0] << '\n';
    std::cout << (v == std::vector<int>{100, 4, 9, 16}) << '\n';
    return 0;
}
```

```text
Saída:
5 1 25
100 4 9 16 
4 100 -1
1
```

Pontos importantes. `vector<int> zeros(4, 0)` cria quatro zeros; `vector<int> v(n)` cria `n` zeros, e é assim que você aloca um array de tamanho dado pelo problema. Atribuir um vetor a outro copia todos os elementos, diferente de Python e JavaScript, onde a atribuição só copia a referência. E `==` compara o conteúdo.

## Custos: o que é barato e o que não é

| Operação | Custo |
|---|---|
| `v[i]`, `front`, `back`, `size` | O(1) |
| `push_back`, `pop_back` | O(1) amortizado |
| `insert` ou `erase` no meio ou no início | O(n), desloca elementos |
| copiar o vetor | O(n) |

Remover do início em um laço é a causa mais comum de solução lenta: cada `erase(v.begin())` desloca tudo. Se precisar de uma fila, veja `queue` e `deque`. Se a ordem não importa, troque o elemento removido pelo último e use `pop_back`.

## Vetores bidimensionais

Uma matriz é um vetor de vetores. Prefira criar já com o tamanho e o valor inicial.

```cpp
#include <iostream>
#include <vector>
#include <array>

int main() {
    int linhas = 3, colunas = 4;
    std::vector<std::vector<int>> grade(linhas, std::vector<int>(colunas, 0));
    for (int r = 0; r < linhas; r++)
        for (int c = 0; c < colunas; c++)
            grade[r][c] = r * colunas + c;
    std::cout << grade[2][3] << " " << grade.size() << " " << grade[0].size() << '\n';

    std::array<int, 3> fixo = {7, 8, 9};
    int cru[3] = {1, 2, 3};
    std::cout << fixo.size() << " " << sizeof(cru) / sizeof(cru[0]) << '\n';

    std::vector<int> v = {1, 2, 3};
    try {
        std::cout << v.at(10) << '\n';
    } catch (const std::out_of_range&) {
        std::cout << "fora do limite\n";
    }
    return 0;
}
```

```text
Saída:
11 3 4
3 3
fora do limite
```

`std::array<T, N>` tem tamanho fixo conhecido em tempo de compilação e vive na pilha; o array cru `int cru[3]` é o herdado de C, que não sabe o próprio tamanho quando passado a uma função. Em entrevista, vector cobre tudo.

## Armadilhas

O operador `[]` não verifica limites. Ler `v[10]` num vetor de três elementos é comportamento indefinido: pode devolver lixo, pode travar, pode parecer funcionar. O método `at(i)` verifica e lança `std::out_of_range`, útil para depurar. Outra armadilha: guardar uma referência ou iterador para um elemento e depois chamar `push_back`. Se o vetor realocar, essa referência fica inválida. E `vector<bool>` é uma especialização estranha que empacota bits; se precisar de flags confiáveis, use `vector<char>`.
