Em Python você lê com `input().split()` e converte com `int`; em JavaScript, normalmente com `readline` ou lendo tudo de `process.stdin`. Em plataformas como HackerRank, Codility ou nas entrevistas que pedem um programa completo, você precisa ler a entrada do jeito certo em C++: formatos variados (um número por linha, uma linha com vários números, texto com espaços), sem saber quantos itens virão e, às vezes, com um volume grande o bastante para que a leitura lenta estoure o tempo.

## cin com o operador de extração

`cin >> x` pula espaços em branco (espaço, tab e quebra de linha) e lê o próximo item no tipo de `x`. Isso faz o formato da entrada quase não importar: números separados por espaço ou por linha são lidos do mesmo jeito. Um padrão muito comum: primeiro `n`, depois `n` valores.

Os exemplos abaixo leem de um `istringstream`, uma string que se comporta como `cin`. Assim os programas rodam sem entrada externa; numa prova, troque `in` por `cin`.

```cpp
#include <iostream>
#include <sstream>
#include <vector>
using namespace std;

int main() {
    istringstream in("5\n3 1 4\n1 5\n");
    int n;
    in >> n;
    vector<int> v(n);
    for (int& x : v) in >> x;
    long long soma = 0;
    for (int x : v) soma += x;
    cout << "n=" << n << " soma=" << soma << "\n";

    istringstream resto("10 20 30");
    int y, total = 0;
    while (resto >> y) total += y;
    cout << "total=" << total << "\n";
}
```

```text
Saída:
n=5 soma=14
total=60
```

O `while (in >> y)` lê até acabar a entrada: a extração devolve o próprio fluxo, que vira `false` quando falha ou chega ao fim. É o equivalente a iterar sobre `sys.stdin` quando não se sabe quantos valores virão.

## Linhas inteiras com getline

`cin >> s` para no primeiro espaço, então uma frase como "ola mundo" vira duas palavras. Para ler a linha inteira, use `getline(cin, s)`. E para quebrar uma linha em pedaços, crie um `istringstream` sobre ela, o que funciona como o `split()` do Python. Com um terceiro argumento, `getline` usa outro separador, útil para CSV.

```cpp
#include <iostream>
#include <sstream>
#include <string>
#include <vector>
using namespace std;

int main() {
    istringstream in("3\nola mundo\nC++ na entrevista\n");
    int n;
    in >> n;
    in.ignore();
    string linha;
    getline(in, linha);
    cout << "[" << linha << "]\n";
    getline(in, linha);
    istringstream palavras(linha);
    string p;
    int cont = 0;
    while (palavras >> p) cont++;
    cout << cont << " palavras\n";

    istringstream csv("a,b,,c");
    string campo;
    vector<string> campos;
    while (getline(csv, campo, ',')) campos.push_back(campo);
    cout << campos.size() << " campos, terceiro vazio: " << campos[2].empty() << "\n";
}
```

```text
Saída:
[ola mundo]
3 palavras
4 campos, terceiro vazio: 1
```

O `ignore()` depois de `in >> n` é essencial. A extração do número deixa a quebra de linha no buffer; sem descartá-la, o primeiro `getline` leria uma linha vazia. Essa é a armadilha número um ao misturar `>>` e `getline`.

## Velocidade

Por padrão, `cin` é sincronizado com o `stdio` do C, o que o torna lento para milhões de números. Duas linhas no começo do `main` resolvem:

```cpp
ios::sync_with_stdio(false);
cin.tie(nullptr);
```

A primeira desliga a sincronização (depois disso, não misture `cin` com `scanf` nem `cout` com `printf`). A segunda impede que cada leitura force o envio da saída pendente. Outra dica: use `"\n"` em vez de `endl`, que força um flush a cada linha e pode deixar a impressão de 10⁵ linhas várias vezes mais lenta.

## Armadilhas

- Misturar `>>` e `getline` sem `ignore()` produz linhas vazias inesperadas.
- Ler em `int` um valor acima de 2³¹: a leitura falha e o fluxo entra em estado de erro, parando as leituras seguintes. Leia em `long long` quando as restrições forem grandes.
- Laço `while (!cin.eof())` processa o último item duas vezes; prefira `while (cin >> x)`.
- Ler caracteres com `cin >> c` pula espaços; use `cin.get(c)` se espaços importam.
- `endl` em laços grandes é lento.

## Na entrevista

Pergunte o formato exato da entrada e se o número de casos vem antes. Escreva as duas linhas de velocidade por hábito, leia com `>>` sempre que possível e reserve `getline` para texto com espaços. Follow-ups comuns: "por que o `getline` leu uma linha vazia?" (o `\n` deixado pelo `>>`) e "o que faz `sync_with_stdio(false)`?" (desliga a sincronização com o stdio do C, acelerando o `cin`).
