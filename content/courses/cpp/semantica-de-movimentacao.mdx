Em Python, `b = a` faz as duas variáveis apontarem para o mesmo objeto e não copia nada. Em C++, `b = a` copia o objeto inteiro: se `a` é um `vector` com um milhão de elementos, são um milhão de cópias. Muitas vezes essa cópia é desperdício, porque o original vai morrer logo depois (um valor temporário retornado por uma função, por exemplo). A semântica de movimentação, introduzida no C++11, permite "roubar" o conteúdo de um objeto que não será mais usado, trocando uma cópia profunda por algumas atribuições de ponteiro.

## Cópia versus movimentação

Um `vector` por dentro guarda um ponteiro para um bloco no heap, o tamanho e a capacidade. Copiar aloca um bloco novo e duplica os elementos: custo O(n). Mover apenas copia os três campos para o destino e deixa a origem vazia: custo O(1). O mesmo vale para `string`, `map`, `unique_ptr` e quase todo contêiner.

Para pedir uma movimentação explícita use `std::move`. Apesar do nome, ela não move nada: apenas converte a expressão em um "rvalue" (um valor que pode ser pilhado), e quem faz o trabalho é o construtor ou o operador de atribuição de movimentação que receber esse rvalue.

```cpp
#include <iostream>
#include <string>
#include <utility>
#include <vector>
using namespace std;

int main() {
    vector<int> grande(1000, 7);
    vector<int> outro = move(grande);
    cout << outro.size() << " " << grande.empty() << "\n";

    vector<string> nomes;
    string s = "Ana";
    nomes.push_back(move(s));
    nomes.push_back("Bia");
    nomes.emplace_back("Caio");
    for (const string& n : nomes) cout << n << " ";
    cout << "\n";
}
```

```text
Saída:
1000 1
Ana Bia Caio 
```

Depois do `move`, o `vector` original ficou vazio, mas continua válido: você pode destruí-lo, atribuir um novo valor a ele ou chamar `clear()`. O padrão garante apenas isso para um objeto movido: está em estado válido, mas não especificado. Não leia o valor dele esperando algo. A linha final mostra `emplace_back`, que constrói o elemento diretamente no vetor a partir dos argumentos, sem criar um temporário primeiro.

## Seus próprios tipos

Se você cria uma classe que gerencia recurso, pode definir o construtor de movimentação `T(T&&)`. Ele recebe um rvalue por referência `&&` e deve deixar a origem num estado seguro. Marque-o `noexcept`: o `vector` só usa a movimentação ao crescer se ela não puder lançar.

```cpp
#include <iostream>
#include <string>
#include <utility>
using namespace std;

struct Buf {
    string nome;
    Buf(string n) : nome(n) { cout << "cria " << nome << "\n"; }
    Buf(const Buf& o) : nome(o.nome + "'") { cout << "copia\n"; }
    Buf(Buf&& o) noexcept : nome(move(o.nome)) { cout << "move\n"; }
};

int main() {
    Buf a("a");
    Buf b = a;
    Buf c = move(a);
    cout << b.nome << " " << c.nome << "\n";
}
```

```text
Saída:
cria a
copia
move
a' a
```

A cópia recebeu um nome diferente para provar que não é a mesma coisa. A movimentação transferiu o texto de `a` para `c`. Depois dessa linha, `a` não deve mais ser usado.

## Retorno por valor

Devolver um objeto local de uma função não exige `std::move`: o compilador já aplica a elisão de cópia (NRVO) ou a movimentação automaticamente. Escrever `return std::move(local);` atrapalha, pois pode impedir a elisão. Por isso `vector<int> f()` que devolve um vetor grande é seguro e barato.

## Armadilhas

- **Usar depois de mover**: ler uma variável movida é um bug de lógica clássico. Considere-a morta, a não ser para atribuir de novo.
- **`move` em objeto `const`**: vira cópia silenciosamente, porque não se pode pilhar algo constante.
- **Tipos triviais**: mover um `int` é só copiar; `std::move` em primitivos não ganha nada.
- **`return std::move(x)`**: quase sempre piora.
- **Falta de `noexcept`**: sem ela, o `vector` copia ao realocar, e você perde o ganho.
- **Regra dos cinco**: se você definir um destrutor, cópia ou movimentação, defina ou apague as demais. Com membros da STL, a regra do zero (não escrever nenhuma) vale.
