---
title: Overflow e comportamento indefinido
kind: lesson
---

Em Python um inteiro cresce sem limite: `2 ** 100` simplesmente funciona. Em JavaScript números grandes perdem precisão, mas o programa segue. Em C++ um `int` tem 32 bits, e passar do limite com tipos com sinal não é apenas "dar a volta": é comportamento indefinido (UB). Isso significa que o padrão não promete nada, e o compilador pode otimizar assumindo que o overflow nunca acontece. É uma das causas mais comuns de "passou nos exemplos, falhou nos testes escondidos".

## Os limites

| Tipo | Faixa típica |
| --- | --- |
| `int` | cerca de -2,1 bilhões a 2,1 bilhões (2³¹ - 1) |
| `long long` | cerca de ±9,2 × 10¹⁸ (2⁶³ - 1) |
| `unsigned int` | 0 a cerca de 4,3 bilhões |
| `size_t` | sem sinal, 64 bits na maioria das plataformas |

Regra de bolso: se o valor pode passar de 2 × 10⁹, use `long long`. Somas de até 10⁵ elementos de valor até 10⁹, produtos de dois `int` e contagens de pares (n² com n = 10⁵) estouram `int`.

## Por que UB é pior que um valor errado

Com tipos **sem sinal**, o overflow é definido: o resultado é calculado módulo 2ⁿ. Com tipos **com sinal**, não. O compilador pode, por exemplo, transformar `x + 1 > x` em `true` sempre, ou remover um teste de overflow escrito depois do fato. Por isso a verificação precisa vir **antes** da operação, ou ser feita em um tipo maior.

```cpp
#include <climits>
#include <iostream>
using namespace std;

int main() {
    int a = 2000000000, b = 2000000000;
    long long certo = (long long)a + b;
    cout << certo << "\n";

    long long produto = 1LL * a * 3;
    cout << produto << "\n";

    unsigned int u = 0;
    u = u - 1;
    cout << u << "\n";

    int x = INT_MAX;
    bool estoura = x > INT_MAX - 1;
    cout << "estouraria: " << estoura << "\n";
    cout << INT_MAX << " " << LLONG_MAX << "\n";
}
```

```text
Saída:
4000000000
6000000000
4294967295
estouraria: 1
2147483647 9223372036854775807
```

O erro clássico seria `long long s = a + b;`: a soma acontece em `int`, estoura, e só depois o resultado (já lixo) é convertido. A conversão precisa acontecer em um dos operandos, como em `(long long)a + b` ou `1LL * a * b`.

## Os casos de UB mais comuns em entrevista

Estes trechos **não** devem ser executados; servem só para reconhecer o padrão:

```cpp
int a = INT_MAX; a + 1;          // UB: overflow com sinal
int m = (lo + hi) / 2;           // pode estourar; use lo + (hi - lo) / 2
vector<int> v(3); v[3];          // UB: fora dos limites, sem exceção
int x; cout << x;                // UB: leitura de variável não inicializada
int* p = nullptr; *p;            // UB: desreferência de nulo
1 << 31;                         // UB em int antes do C++20
abs(INT_MIN);                    // UB: -INT_MIN não cabe em int
```

## Sem sinal também morde

`v.size()` devolve `size_t`, sem sinal. Se `v` está vazio, `v.size() - 1` não é -1, é um número enorme, e um laço `for (int i = 0; i < v.size() - 1; i++)` roda quase para sempre (e acessa fora dos limites). Comparar `int` negativo com `size_t` também converte o negativo para um número gigante.

```cpp
#include <iostream>
#include <vector>
using namespace std;

int main() {
    vector<int> v;
    cout << (v.size() - 1) << "\n";
    int n = (int)v.size();
    cout << n - 1 << "\n";
    int lo = 2000000000, hi = 2100000000;
    int meio = lo + (hi - lo) / 2;
    cout << meio << "\n";
    const long long MOD = 1000000007;
    long long r = 1;
    for (int i = 1; i <= 25; i++) r = r * i % MOD;
    cout << r << "\n";
}
```

```text
Saída:
18446744073709551615
-1
2050000000
440732388
```

A solução é converter o tamanho para `int` logo no começo. O cálculo do meio sem overflow e a aritmética modular (reduzir a cada passo, usando `long long` para o produto) são padrões que você deve escrever por reflexo.

## Ferramentas

Em casa, compile com `-fsanitize=undefined,address`: o programa avisa no momento em que um UB acontece. O GCC e o Clang também oferecem `__builtin_add_overflow` e `__builtin_mul_overflow` para testar estouro sem UB. Em C++20, `1 << 31` passou a ser definido, mas o overflow de soma com sinal continua UB.

## Na entrevista

Leia as restrições antes de escolher o tipo: valores até 10⁹ com somas ou produtos pedem `long long`. Diga em voz alta "uso `long long` aqui porque a soma pode passar de 2³¹". Ao fazer busca binária, escreva `lo + (hi - lo) / 2`. Follow-ups comuns: "o que é comportamento indefinido?" (o padrão não define o resultado, e o compilador pode assumir que não acontece) e "por que `v.size() - 1` é perigoso?" (é sem sinal e dá a volta quando o vetor está vazio).
