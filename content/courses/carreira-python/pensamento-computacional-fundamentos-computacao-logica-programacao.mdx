Quem começa a programar costuma travar antes de digitar a primeira linha: o enunciado está claro, a linguagem até parece simples, mas falta o caminho entre o problema e o código. Esse caminho tem nome, pensamento computacional, e é uma habilidade separada da sintaxe. É ela que o entrevistador observa quando pede para você resolver um exercício em voz alta: como você quebra o problema, que casos lembra de tratar, como confere se a solução funciona.

Este capítulo constrói essa base com um problema do domínio que acompanha a carreira inteira, a venda de ingressos para eventos. Os exemplos estão em Python bem simples, para que a atenção fique no raciocínio. A linguagem em si é assunto do próximo capítulo.

**Você vai aprender:**

- Aplicar os quatro pilares do pensamento computacional: decomposição, padrões, abstração e algoritmo
- Entender o que o computador faz ao executar um programa e por que cada dado tem um tipo
- Escrever lógica com variáveis, condicionais, laços e funções
- Conferir um algoritmo com teste de mesa antes de rodar
- Comparar dois algoritmos pelo número de passos que cada um executa

## O problema que vamos usar

Uma bilheteria vende ingressos para um show com capacidade de 500 pessoas. Um cliente pede uma quantidade de ingressos de um tipo (inteira ou meia). O sistema precisa responder duas perguntas: a venda pode acontecer? Se pode, quanto custa?

Parece uma conta só, mas esconde várias decisões: o que fazer se a quantidade pedida for zero ou negativa, se sobrarem menos ingressos que o pedido, se houver limite por compra, quanto vale a meia. Um programa não tolera lacunas desse tipo. O computador executa exatamente o que foi escrito, e o que não foi previsto vira erro ou, pior, vira uma venda errada sem erro nenhum.

## Os quatro pilares

**Decomposição** é quebrar o problema em partes que cabem na cabeça. A venda vira quatro subproblemas: validar a quantidade, verificar a disponibilidade, calcular o preço unitário e calcular o total. Cada parte pode ser resolvida e testada sozinha.

**Reconhecimento de padrões** é perceber o que se repete. Verificar disponibilidade de ingressos tem a mesma forma de verificar estoque de um produto ou vagas num voo: existe um limite, existe um total já ocupado e um pedido que não pode ultrapassar a diferença. Quem reconhece o padrão reaproveita a solução.

**Abstração** é ignorar o que não importa para a pergunta. Para decidir se a venda pode acontecer, a cor do ingresso, o nome do artista e o endereço do local são irrelevantes. Bastam três números: capacidade, vendidos e quantidade pedida. Escolher o que deixar de fora é metade do trabalho de modelagem.

**Algoritmo** é a sequência de passos, sem ambiguidade e com fim, que resolve o problema. Em português estruturado:

```text
1. Se a quantidade pedida for menor que 1, recuse a venda.
2. Calcule disponiveis = capacidade - vendidos.
3. Se a quantidade for maior que disponiveis, recuse a venda.
4. Se o tipo for meia, o preço unitário é metade do preço cheio.
5. total = preço unitário x quantidade.
6. Some a quantidade aos vendidos e informe o total.
```

Repare na ordem: as validações vêm antes do cálculo. Um algoritmo que calcula primeiro e valida depois pode alterar dados antes de descobrir que não devia.

## O que o computador faz com o seu programa

Um computador tem três peças que interessam aqui. O **processador** executa instruções muito simples (somar, comparar, copiar, saltar para outra instrução), bilhões por segundo. A **memória** (RAM) guarda os dados enquanto o programa roda e perde tudo quando ele termina. O **armazenamento** (disco) guarda o que precisa sobreviver. Por isso um cadastro que fica só em variáveis some ao fechar o programa, e por isso existem arquivos e bancos de dados.

Tudo na memória é número em base 2. Um **bit** vale 0 ou 1, e oito bits formam um **byte**, que representa 256 valores diferentes. Texto é uma tabela que associa números a caracteres (o Unicode, normalmente gravado em UTF-8), e uma imagem é uma grade de números de cor. O **tipo** de um dado diz ao programa como interpretar aqueles bits: o mesmo byte pode ser o número 65 ou a letra A.

Você não escreve instruções de processador. Escreve numa linguagem de alto nível, e outro programa faz a tradução. Em Python, o **interpretador** lê o seu arquivo, converte para uma forma intermediária (bytecode) e a executa. A consequência prática: muitos erros só aparecem quando a linha problemática é de fato executada, o que torna os testes ainda mais importantes.

## Variáveis e tipos

Uma variável é um nome que aponta para um valor guardado na memória. Em Python, a atribuição cria o nome:

```python
capacidade = 500          # int: número inteiro
vendidos = 480
preco = 120.0             # float: número com casas decimais
tipo = "meia"             # str: texto
venda_aberta = True       # bool: verdadeiro ou falso

disponiveis = capacidade - vendidos
print(disponiveis)        # 20
```

O sinal `=` não é igualdade matemática, é uma ordem: calcule o que está à direita e guarde no nome à esquerda. Por isso `vendidos = vendidos + 2` faz sentido (pegue o valor atual, some 2 e guarde de volta). Para comparar, o operador é `==`.

Bons nomes são parte da lógica. `disponiveis` conta o que o valor significa; `x` obriga quem lê a reconstruir o raciocínio. O tipo também carrega significado: quantidade de ingressos é inteiro, porque não existe meio ingresso vendido.

## Decisões: condicionais e operadores lógicos

O programa escolhe caminhos avaliando expressões que resultam em verdadeiro ou falso. Os operadores de comparação são `==`, `!=`, `<`, `<=`, `>` e `>=`. Os lógicos combinam condições:

| A | B | A and B | A or B | not A |
|---|---|---|---|---|
| True | True | True | True | False |
| True | False | False | True | False |
| False | True | False | True | True |
| False | False | False | False | True |

Em Python, o bloco que pertence a uma condição é definido pela indentação (quatro espaços):

```python
quantidade = 3
limite_por_compra = 6

if quantidade < 1:
    print("Quantidade inválida")
elif quantidade > limite_por_compra:
    print("Acima do limite por compra")
elif quantidade > disponiveis:
    print("Ingressos insuficientes")
else:
    print("Venda liberada")
```

As condições são testadas de cima para baixo, e só o primeiro bloco verdadeiro executa. A ordem importa: se a verificação de quantidade inválida viesse por último, um pedido de -2 ingressos passaria pelos outros testes e cairia em "Venda liberada".

Os casos de borda merecem atenção própria. Se restam 20 ingressos e o cliente pede 20, a venda deve acontecer, então a comparação certa é `quantidade > disponiveis` para recusar, e não `>=`. Trocar um operador pelo vizinho é o defeito mais comum em código de iniciante e de veterano.

## Repetição: laços

Quando a mesma operação vale para vários itens, você escreve uma vez e manda repetir. O `for` percorre uma coleção, um item por vez:

```python
pedidos = [2, 4, 1, 3]    # quantidades de quatro pedidos

total_vendido = 0
for quantidade in pedidos:
    total_vendido = total_vendido + quantidade

print(total_vendido)      # 10
```

A variável `total_vendido` é um **acumulador**: começa em zero antes do laço e cresce a cada volta. Esquecer de iniciá-la, ou iniciá-la dentro do laço, são erros clássicos.

O `while` repete enquanto uma condição for verdadeira, e serve quando você não sabe de antemão quantas voltas serão:

```python
fila = [2, 4, 30, 1]
disponiveis = 20
posicao = 0

while posicao < len(fila) and fila[posicao] <= disponiveis:
    disponiveis = disponiveis - fila[posicao]
    posicao = posicao + 1

print(posicao, disponiveis)   # 2 14
```

Todo `while` precisa de algo dentro do bloco que aproxime a condição do falso. Sem a linha que soma 1 em `posicao`, o laço nunca termina.

## Teste de mesa

Antes de rodar, execute o algoritmo no papel: uma coluna por variável, uma linha por passo. Para o `while` acima:

| Passo | posicao | fila[posicao] | disponiveis | Condição |
|---|---|---|---|---|
| início | 0 | 2 | 20 | verdadeira |
| 1ª volta | 1 | 4 | 18 | verdadeira |
| 2ª volta | 2 | 30 | 14 | falsa: 30 é maior que 14 |

O laço para na terceira pessoa, com dois pedidos atendidos e 14 ingressos restantes. O teste de mesa revela também uma decisão de negócio escondida: a quarta pessoa queria só 1 ingresso e não foi atendida, porque a fila parou. Se isso está certo ou errado depende da regra, mas agora a pergunta apareceu.

<Callout type="warning" title="O erro de um a mais ou a menos">
Listas em Python começam no índice 0, e uma lista de 4 itens vai do índice 0 ao 3. Usar `<=` no lugar de `<` ao comparar com `len(fila)` faz o programa tentar ler uma posição que não existe. Sempre que escrever um laço, teste mentalmente três casos: lista vazia, lista com um item e o último item.
</Callout>

## Funções: dando nome aos passos

Uma função empacota um trecho de lógica com um nome, entradas (parâmetros) e uma saída (retorno). É a decomposição virando código:

```python
def calcular_total(preco: float, quantidade: int, tipo: str) -> float:
    if tipo == "meia":
        preco = preco / 2
    return preco * quantidade


def pode_vender(capacidade: int, vendidos: int, quantidade: int) -> bool:
    if quantidade < 1:
        return False
    return quantidade <= capacidade - vendidos


if pode_vender(500, 480, 3):
    print(calcular_total(120.0, 3, "meia"))   # 180.0
else:
    print("Venda recusada")
```

As anotações depois dos dois-pontos e da seta (`float`, `int`, `bool`) são dicas de tipo: documentam o que a função espera e devolve. Cada função aqui responde a uma única pergunta, não lê o teclado e não imprime nada. Isso permite testá-las com valores escolhidos e reaproveitá-las num programa de terminal hoje e numa API amanhã.

<Callout type="tip" title="Função que calcula não imprime">
Separe quem decide de quem mostra. Uma função que devolve o resultado com `return` pode ser usada em qualquer contexto. Uma função que só chama `print` serve para um único cenário e não pode ser testada sem olhar a tela.
</Callout>

## Nem todo algoritmo custa igual

Dois algoritmos corretos podem ter custos muito diferentes. Para descobrir se um código de ingresso está numa lista de 1.000.000 de códigos, a **busca linear** olha um por um:

```python
def buscar_linear(codigos: list[str], procurado: str) -> bool:
    for codigo in codigos:
        if codigo == procurado:
            return True
    return False
```

No pior caso, são 1.000.000 de comparações. Se a lista estiver ordenada, a **busca binária** olha o item do meio, descarta a metade em que o código não pode estar e repete:

```python
def buscar_binaria(codigos: list[str], procurado: str) -> bool:
    inicio = 0
    fim = len(codigos) - 1
    while inicio <= fim:
        meio = (inicio + fim) // 2
        if codigos[meio] == procurado:
            return True
        if codigos[meio] < procurado:
            inicio = meio + 1
        else:
            fim = meio - 1
    return False
```

Como cada passo corta o problema pela metade, 1.000.000 de itens exigem no máximo 20 comparações. Essa forma de descrever o custo em função do tamanho da entrada (crescimento linear contra logarítmico) é a notação Big O, que você vai usar em toda entrevista de algoritmos.

## Como atacar um problema novo

1. **Reescreva o enunciado com as suas palavras** e liste entradas, saídas e restrições.
2. **Resolva um exemplo à mão**, com números pequenos. Se você não consegue fazer no papel, não vai conseguir programar.
3. **Liste os casos de borda**: vazio, zero, negativo, exatamente no limite, valor repetido.
4. **Escreva os passos em português** antes de escrever código.
5. **Traduza para código**, uma função por subproblema.
6. **Faça o teste de mesa** com o exemplo do passo 2 e com um caso de borda.
7. **Só então pense em melhorar**: dá para fazer com menos passos?

## Na entrevista

**O que é pensamento computacional?** É a forma de resolver problemas de modo que a solução possa ser executada por um computador: decompor em partes, reconhecer padrões, abstrair o que não importa e descrever um algoritmo. Não depende de linguagem, e é o que se avalia quando pedem para você pensar em voz alta.

**Qual a diferença entre algoritmo e programa?** O algoritmo é a sequência de passos, independente de linguagem. O programa é uma implementação desse algoritmo numa linguagem específica, com detalhes de sintaxe, tipos e entrada e saída.

**Quando usar `for` e quando usar `while`?** `for` quando você percorre uma coleção ou sabe o número de repetições. `while` quando a repetição depende de uma condição que muda durante a execução, como ler até o usuário digitar sair ou buscar até encontrar.

**Por que dividir o código em funções?** Para dar nome aos passos, evitar repetição, testar cada parte isoladamente e trocar uma implementação sem mexer no resto. Uma função deve fazer uma coisa só e ter entradas e saída explícitas.

**Por que a busca binária é mais rápida que a linear e qual o pré-requisito?** Ela descarta metade dos candidatos a cada comparação, então o número de passos cresce com o logaritmo do tamanho da lista, e não com o tamanho. O pré-requisito é a lista estar ordenada.

## Pratique

1. Escreva em português estruturado o algoritmo de uma compra com limite de 6 ingressos por pedido e taxa de serviço de 10% sobre o total. Liste pelo menos quatro casos de borda.
2. Implemente `calcular_total` com a taxa de serviço e uma função `validar_pedido` que devolve uma mensagem explicando por que a venda foi recusada (ou um texto vazio se foi aceita).
3. Dada uma lista de quantidades pedidas, escreva um laço que atenda todos os pedidos que couberem no estoque, pulando os que não cabem em vez de parar. Faça o teste de mesa com `[2, 4, 30, 1]` e 20 ingressos.
4. Escreva uma função que recebe a lista de quantidades vendidas por dia e devolve o dia de maior venda, sem usar a função `max`. Teste com lista vazia.
5. Conte, com uma variável contadora, quantas comparações a busca linear e a binária fazem para achar o último item de uma lista ordenada de 1.000 códigos.
