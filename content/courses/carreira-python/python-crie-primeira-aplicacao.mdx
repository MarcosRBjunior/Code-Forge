Saber lógica não basta para entregar um programa: é preciso instalar a linguagem, organizar arquivos, lidar com o que o usuário digita errado e deixar o projeto num estado em que outra pessoa consiga rodá-lo. Esse conjunto de hábitos, mais do que a sintaxe, separa um script solto de uma aplicação.

Aqui você monta a primeira versão do `ingressos`, o projeto que atravessa a carreira: um programa de terminal que cadastra e lista eventos. Ele é pequeno de propósito, mas já nasce com ambiente virtual, pacote, funções tipadas e tratamento de erro, a mesma estrutura que depois recebe classes, banco de dados e uma API.

**Você vai aprender:**

- Instalar o Python 3.13, criar um ambiente virtual e rodar código pelo terminal
- Usar os tipos básicos, strings formatadas, listas e dicionários
- Escrever funções com type hints e organizar o código em módulos e pacote
- Tratar entrada inválida com `try`/`except` sem derrubar o programa
- Montar uma aplicação de terminal com menu, cadastro e listagem

## Instalação e ambiente virtual

Baixe o Python 3.13 em python.org (no Windows, marque a opção de adicionar ao PATH; no Linux e no macOS, o gerenciador de pacotes também serve). Confira no terminal:

```bash
python --version      # Python 3.13.x (em alguns sistemas o comando é python3)
```

Cada projeto deve ter o próprio **ambiente virtual**: uma pasta com uma cópia isolada do interpretador e das bibliotecas instaladas. Sem isso, todos os projetos da máquina dividem as mesmas bibliotecas, e atualizar uma para o projeto A quebra o projeto B.

```bash
mkdir ingressos-app
cd ingressos-app
python -m venv .venv

# ative o ambiente (repita a cada novo terminal)
source .venv/bin/activate        # Linux e macOS
.venv\Scripts\Activate.ps1       # Windows PowerShell

python -m pip install --upgrade pip
```

Com o ambiente ativo, `python` e `pip` passam a ser os da pasta `.venv`. Essa pasta nunca vai para o Git: ela é recriada em qualquer máquina com os mesmos comandos. Existem ferramentas mais rápidas que fazem o mesmo trabalho, como o `uv`, mas `venv` e `pip` vêm com o Python e são o que você encontra em qualquer servidor.

Para experimentar, digite `python` sem argumentos e use o modo interativo (REPL): cada linha é executada na hora. Para sair, `exit()`.

## Tipos, operadores e strings

```python
nome = "Festival de Verão"     # str
capacidade = 500               # int
preco = 120.0                  # float
ativo = True                   # bool
local = None                   # ausência de valor

print(type(capacidade))        # <class 'int'>
print(7 // 2, 7 % 2, 7 / 2)    # 3 1 3.5  (divisão inteira, resto, divisão real)
print(2 ** 10)                 # 1024
```

Python tem tipagem dinâmica (o nome não tem tipo fixo, o valor tem) e forte (não mistura tipos calados: `"3" + 2` é erro). O que vem do teclado é sempre texto, então a conversão é explícita:

```python
texto = input("Capacidade: ")      # o usuário digita 500
capacidade = int(texto)            # "500" vira 500
```

Para montar texto, use **f-strings**. O que está entre chaves é avaliado, e depois dos dois-pontos vem o formato:

```python
preco = 120.0
quantidade = 3
print(f"Total: R$ {preco * quantidade:.2f}")      # Total: R$ 360.00
print(f"{nome.upper()} tem {len(nome)} letras")
print(nome.strip().lower().replace(" ", "-"))    # festival-de-verão
```

Strings são imutáveis: métodos como `strip`, `lower` e `replace` devolvem uma nova string e deixam a original intacta.

<Callout type="warning" title="Dinheiro não é float">
`0.1 + 0.2` resulta em `0.30000000000000004`, porque `float` guarda números em base 2. Para valores monetários de verdade, use `Decimal` (módulo `decimal`) criado a partir de texto, como `Decimal("120.00")`, ou guarde centavos em `int`. Nos primeiros exemplos o `float` aparece pela simplicidade; a partir do capítulo de persistência o preço passa a ser `Decimal`.
</Callout>

## Listas e dicionários

A **lista** guarda itens em ordem e pode crescer:

```python
locais = ["Arena Norte", "Teatro Central"]
locais.append("Praça da Estação")
print(locais[0], locais[-1])       # primeiro e último
print(len(locais))                 # 3
print("Teatro Central" in locais)  # True

for posicao, local in enumerate(locais, start=1):
    print(f"{posicao}. {local}")
```

O **dicionário** associa chaves a valores, ideal para representar um registro:

```python
evento = {
    "nome": "Festival de Verão",
    "local": "Arena Norte",
    "capacidade": 500,
}
print(evento["nome"])
evento["vendidos"] = 0                 # cria a chave
print(evento.get("preco", 0.0))        # get devolve o padrão se a chave não existe

for chave, valor in evento.items():
    print(f"{chave}: {valor}")
```

`evento["preco"]` com chave inexistente levanta `KeyError`; `evento.get("preco")` devolve `None`. Escolha conforme a ausência da chave ser um erro ou uma situação normal.

Duas construções aparecem em todo código Python. A **compreensão de lista** cria uma lista a partir de outra, e o **fatiamento** pega um trecho:

```python
capacidades = [500, 80, 1200, 300]
grandes = [c for c in capacidades if c >= 300]    # [500, 1200, 300]
primeiros = capacidades[:2]                       # [500, 80]
ordenadas = sorted(capacidades, reverse=True)     # [1200, 500, 300, 80]
```

Além desses dois, vale conhecer a `tuple` (sequência imutável, como `("Arena Norte", 500)`) e o `set` (coleção sem repetição, com teste de pertinência rápido).

## Funções com type hints

```python
from datetime import date


def descrever_evento(nome: str, data: date, capacidade: int = 100) -> str:
    return f"{nome} em {data:%d/%m/%Y} ({capacidade} lugares)"


print(descrever_evento("Sarau", date(2027, 3, 14)))
print(descrever_evento("Festival", date(2027, 1, 20), capacidade=500))
```

Os type hints não são verificados durante a execução: são documentação que o editor e ferramentas como o mypy usam para apontar erros antes de rodar. Use a sintaxe moderna, com os próprios tipos embutidos: `list[str]`, `dict[str, int]` e `str | None` para um valor opcional.

Parâmetros com valor padrão vêm depois dos obrigatórios, e chamar com o nome do argumento (`capacidade=500`) deixa a chamada legível.

<Callout type="warning" title="Nunca use lista ou dicionário como valor padrão">
O valor padrão é criado uma única vez, quando a função é definida. Em `def cadastrar(evento, lista=[])`, todas as chamadas dividem a mesma lista, e os itens de uma chamada aparecem na seguinte. O idioma correto é `lista: list | None = None` e, dentro da função, `if lista is None: lista = []`.
</Callout>

## Módulos e pacote

Cada arquivo `.py` é um **módulo**, e uma pasta com módulos é um **pacote**. Organize o projeto assim:

```text
ingressos-app/
├── .venv/
└── ingressos/
    ├── __init__.py      (vazio: marca a pasta como pacote)
    ├── __main__.py      (ponto de entrada: python -m ingressos)
    ├── eventos.py       (regras: cadastrar e listar)
    └── terminal.py      (conversa com o usuário)
```

A divisão segue uma regra que você vai repetir em toda a carreira: as regras do negócio não sabem de onde vêm os dados nem para onde vão. `eventos.py` não chama `input` nem `print`; `terminal.py` não decide o que é um evento válido.

## As regras: eventos.py

```python
# ingressos/eventos.py
from datetime import date, datetime

eventos: list[dict] = []


def converter_data(texto: str) -> date:
    return datetime.strptime(texto.strip(), "%d/%m/%Y").date()


def cadastrar_evento(nome: str, data: date, local: str, capacidade: int) -> dict:
    nome = nome.strip()
    if not nome:
        raise ValueError("o nome do evento é obrigatório")
    if capacidade <= 0:
        raise ValueError("a capacidade deve ser maior que zero")
    if data < date.today():
        raise ValueError("a data do evento não pode estar no passado")
    for existente in eventos:
        if existente["nome"].lower() == nome.lower() and existente["data"] == data:
            raise ValueError("já existe um evento com esse nome nessa data")

    evento = {
        "nome": nome,
        "data": data,
        "local": local.strip(),
        "capacidade": capacidade,
        "vendidos": 0,
    }
    eventos.append(evento)
    return evento


def listar_eventos() -> list[dict]:
    return sorted(eventos, key=lambda evento: evento["data"])


def quantidade_disponivel(evento: dict) -> int:
    return evento["capacidade"] - evento["vendidos"]
```

`raise ValueError(...)` interrompe a função e avisa quem chamou que os dados não servem. A função não imprime a mensagem nem devolve `None` em silêncio: quem chamou decide o que fazer. `strptime` converte texto em data segundo o formato e levanta `ValueError` se o texto não bater, o mesmo tipo de erro das validações.

O `key=lambda evento: evento["data"]` diz ao `sorted` qual valor usar na comparação. `lambda` é uma função pequena sem nome, útil para esse tipo de argumento.

## Tratamento de erros

Um erro em Python é uma **exceção**: um objeto que sobe pela pilha de chamadas até alguém tratá-lo. Se ninguém trata, o programa termina com um traceback. O `try`/`except` captura a exceção no ponto em que você sabe o que fazer com ela:

```python
def ler_inteiro(pergunta: str) -> int:
    while True:
        try:
            return int(input(pergunta))
        except ValueError:
            print("Digite um número inteiro.")
```

Três regras evitam a maior parte dos problemas:

- **Capture o tipo específico.** `except ValueError` trata o que você previu. Um `except:` sem tipo ou um `except Exception` genérico esconde erros de programação, como um nome digitado errado.
- **Trate onde há o que fazer.** A função de regra levanta; a camada que fala com o usuário captura e mostra a mensagem.
- **Não engula o erro.** Um `except` com `pass` faz o programa seguir com dados errados.

O bloco completo tem ainda `else` (roda se não houve exceção) e `finally` (roda sempre, com ou sem erro, útil para liberar recursos).

## A conversa com o usuário: terminal.py

```python
# ingressos/terminal.py
from ingressos import eventos


def ler_inteiro(pergunta: str) -> int:
    while True:
        try:
            return int(input(pergunta))
        except ValueError:
            print("Digite um número inteiro.")


def cadastrar() -> None:
    nome = input("Nome: ")
    texto_data = input("Data (dd/mm/aaaa): ")
    local = input("Local: ")
    capacidade = ler_inteiro("Capacidade: ")
    try:
        data = eventos.converter_data(texto_data)
        evento = eventos.cadastrar_evento(nome, data, local, capacidade)
    except ValueError as erro:
        print(f"Não foi possível cadastrar: {erro}")
    else:
        print(f"Evento cadastrado: {evento['nome']}")


def listar() -> None:
    lista = eventos.listar_eventos()
    if not lista:
        print("Nenhum evento cadastrado.")
        return
    for numero, evento in enumerate(lista, start=1):
        livres = eventos.quantidade_disponivel(evento)
        print(f"{numero}. {evento['data']:%d/%m/%Y}  {evento['nome']}  "
              f"({evento['local']}, {livres} lugares livres)")


def executar() -> None:
    opcoes = {"1": cadastrar, "2": listar}
    while True:
        print("\n1. Cadastrar evento\n2. Listar eventos\n0. Sair")
        escolha = input("Opção: ").strip()
        if escolha == "0":
            print("Até logo.")
            break
        acao = opcoes.get(escolha)
        if acao is None:
            print("Opção inválida.")
        else:
            acao()
```

O dicionário `opcoes` guarda as próprias funções como valores (sem parênteses, porque você quer a função, não o resultado dela). Acrescentar uma opção ao menu vira uma linha, em vez de mais um `elif`.

O ponto de entrada fica mínimo:

```python
# ingressos/__main__.py
from ingressos.terminal import executar

if __name__ == "__main__":
    executar()
```

```bash
python -m ingressos
```

`python -m ingressos` executa o `__main__.py` do pacote, com a pasta atual no caminho de importação, e por isso `from ingressos import eventos` funciona. A condição `if __name__ == "__main__"` vale verdadeiro só quando o arquivo é o programa principal, e evita que o menu dispare se alguém apenas importar o módulo.

## O que esta versão ainda não faz

Os eventos vivem numa lista em memória e somem ao fechar o programa. Um evento é um dicionário, e nada impede alguém de escrever `evento["capacidad"]` com erro de digitação. As duas limitações são o ponto de partida dos próximos capítulos: classes dão forma e comportamento aos dados, e arquivos e bancos de dados os fazem sobreviver.

## Na entrevista

**Para que serve um ambiente virtual?** Para isolar as dependências de cada projeto. Cada `.venv` tem seu próprio conjunto de bibliotecas e versões, o que evita conflito entre projetos e torna a instalação reproduzível em outra máquina.

**Qual a diferença entre lista, tupla e dicionário?** Lista é uma sequência ordenada e mutável; tupla é uma sequência ordenada e imutável, boa para agrupar valores fixos; dicionário mapeia chaves únicas a valores, com busca por chave em tempo constante em média.

**Python é tipado?** Sim: tipagem dinâmica (o tipo pertence ao valor, verificado em tempo de execução) e forte (não converte tipos implicitamente em operações como somar texto e número). Type hints são opcionais e verificados por ferramentas externas, não pelo interpretador.

**O que faz `if __name__ == "__main__"`?** Executa o bloco só quando o arquivo é rodado diretamente. Quando o módulo é importado, `__name__` é o nome do módulo e o bloco é ignorado, o que permite reutilizar as funções sem disparar o programa.

**Por que não usar `except:` sem tipo?** Porque ele captura tudo, inclusive erros de programação e a interrupção pelo teclado, e esconde a causa real. Capture a exceção específica que você sabe tratar e deixe as outras subirem.

## Pratique

1. Monte o projeto como descrito, com `.venv`, e rode `python -m ingressos`. Cadastre três eventos e confira a ordenação por data.
2. Acrescente a opção "Vender ingressos": o usuário escolhe o evento pelo número da listagem e informa a quantidade. Crie `vender(evento, quantidade)` em `eventos.py`, que levanta `ValueError` se a quantidade for inválida ou maior que a disponível.
3. Acrescente a opção "Buscar por nome", que lista os eventos cujo nome contém o texto digitado, ignorando maiúsculas e minúsculas. Use compreensão de lista.
4. Adicione um preço ao evento usando `Decimal` e mostre na listagem o faturamento (preço vezes vendidos) formatado com duas casas.
5. Teste `eventos.py` no REPL, sem passar pelo menu: importe o módulo, chame `cadastrar_evento` com dados inválidos e veja as exceções. Anote o que seria difícil testar se as regras estivessem misturadas com `input`.
