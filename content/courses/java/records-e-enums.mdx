Duas necessidades aparecem em todo problema de entrevista: agrupar alguns valores em um objeto pequeno e imutável (uma coordenada, um par nó-distância) e representar um conjunto fixo de opções (as quatro direções, os estados de uma máquina). Para a primeira Java 16 trouxe os `record`; para a segunda existe o `enum` desde o Java 5.

## Records: dados imutáveis sem boilerplate

Escrever uma classe `Ponto` à mão exigiria campos, construtor, getters, `equals`, `hashCode` e `toString`. Um record gera tudo isso a partir de uma linha.

```java
import java.util.*;

record Ponto(int x, int y) {
    Ponto {
        if (x < 0 || y < 0) throw new IllegalArgumentException("coordenada negativa");
    }

    int manhattan() { return x + y; }
}

public class Main {
    public static void main(String[] args) {
        Ponto p = new Ponto(1, 2);
        System.out.println(p);
        System.out.println(p.x() + " " + p.y());
        System.out.println(p.equals(new Ponto(1, 2)));
        System.out.println(p.manhattan());

        Set<Ponto> visitados = new HashSet<>();
        visitados.add(new Ponto(0, 0));
        visitados.add(new Ponto(0, 0));
        visitados.add(new Ponto(3, 1));
        System.out.println(visitados.size());
        System.out.println(visitados.contains(new Ponto(3, 1)));

        try {
            new Ponto(-1, 0);
        } catch (IllegalArgumentException e) {
            System.out.println(e.getMessage());
        }
    }
}
```

```text
Saída:
Ponto[x=1, y=2]
1 2
true
3
2
true
coordenada negativa
```

Os acessores têm o nome do componente (`p.x()`, sem `get`). O bloco sem parênteses é o construtor compacto, bom para validar. Como `equals` e `hashCode` comparam os componentes, um record funciona direto como chave de `HashMap` e elemento de `HashSet`. Isso resolve um problema comum de grade: em vez de codificar `x * largura + y` ou concatenar strings `"1,2"`, use um `Ponto`. Os campos são `final`, então não há setters; para "mudar" você cria outro record.

Um record pode ter métodos, métodos estáticos e implementar interfaces, mas não estender classes e não declara campos de instância extras. Se um componente for mutável (um array ou lista), o record continua apontando para o mesmo objeto, então a imutabilidade é rasa.

## Enums: um conjunto fechado de valores

Um enum define um tipo com instâncias fixas. Cada constante pode carregar campos e métodos, e o tipo vem com `values()`, `valueOf(String)`, `name()` e `ordinal()`.

```java
import java.util.*;

enum Direcao {
    CIMA(-1, 0), BAIXO(1, 0), ESQUERDA(0, -1), DIREITA(0, 1);

    final int dl, dc;

    Direcao(int dl, int dc) { this.dl = dl; this.dc = dc; }

    Direcao oposta() {
        switch (this) {
            case CIMA: return BAIXO;
            case BAIXO: return CIMA;
            case ESQUERDA: return DIREITA;
            default: return ESQUERDA;
        }
    }
}

public class Main {
    public static void main(String[] args) {
        int l = 2, c = 2;
        for (Direcao d : Direcao.values()) {
            System.out.println(d + " -> " + (l + d.dl) + "," + (c + d.dc));
        }
        System.out.println(Direcao.valueOf("CIMA").oposta());
        System.out.println(Direcao.DIREITA.ordinal());

        Map<Direcao, Integer> contagem = new EnumMap<>(Direcao.class);
        contagem.put(Direcao.DIREITA, 3);
        contagem.put(Direcao.CIMA, 1);
        System.out.println(contagem);
    }
}
```

```text
Saída:
CIMA -> 1,2
BAIXO -> 3,2
ESQUERDA -> 2,1
DIREITA -> 2,3
BAIXO
3
{CIMA=1, DIREITA=3}
```

Comparar enums com `==` é seguro, porque cada constante é um singleton. `EnumMap` e `EnumSet` são implementações compactas e rápidas, ordenadas pela ordem de declaração. O uso mais frequente em entrevista é o array de deltas de uma busca em grade, que também pode ser um simples `int[][]`; o enum é melhor quando o domínio pede nomes (estados, tipos de operação).

## Armadilhas

`valueOf` com um nome inexistente lança `IllegalArgumentException`. Usar `ordinal()` como identificador persistente é frágil, pois reordenar as constantes muda os números. Em `switch`, dentro do `case` você escreve só o nome da constante (`CIMA`), sem o prefixo do tipo.

<Callout type="tip" title="Record como chave">
Para memoizar estados com dois ou três inteiros, um record como chave do `HashMap` é mais legível que montar strings e tão correto quanto, já que `equals` e `hashCode` vêm prontos.
</Callout>

## Na entrevista

Cite records ao modelar pares e estados pequenos (`record Estado(int no, int custo)` numa fila de prioridade), e enums para tipos fechados como status de pedido. Follow-ups comuns: "por que um record é bom como chave de mapa?" (igualdade por valor e imutabilidade) e "em que um enum difere de constantes `static final int`?" (tipo seguro, com métodos e sem valores inválidos).
