Dizer "uso um `HashMap`" não basta numa entrevista: o entrevistador quer saber quanto custa cada chamada, porque é isso que define a complexidade final do seu algoritmo. Uma linha inocente como `list.remove(0)` dentro de um laço transforma uma solução de O(n) em O(n²). Este capítulo é a tabela de referência que você deve ter na cabeça para a biblioteca de Java.

## A tabela

| Estrutura | Operação | Custo |
|---|---|---|
| `ArrayList` | `get(i)`, `set(i, x)` | O(1) |
| `ArrayList` | `add(x)` no fim | O(1) amortizado |
| `ArrayList` | `add(0, x)`, `remove(0)`, `remove(i)` | O(n) |
| `ArrayList` | `contains`, `indexOf` | O(n) |
| `LinkedList` | `get(i)` | O(n) |
| `LinkedList` | `addFirst`, `removeFirst`, `addLast` | O(1) |
| `ArrayDeque` | `offer`, `poll`, `push`, `pop`, `peek` | O(1) |
| `HashMap` / `HashSet` | `put`, `get`, `containsKey`, `remove` | O(1) médio |
| `TreeMap` / `TreeSet` | `put`, `get`, `remove`, `floorKey`, `ceilingKey` | O(log n) |
| `PriorityQueue` | `offer`, `poll` | O(log n) |
| `PriorityQueue` | `peek` | O(1) |
| `PriorityQueue` | `remove(obj)`, `contains` | O(n) |
| `String` | `charAt`, `length` | O(1) |
| `String` | `substring`, concatenação, `equals` | O(tamanho) |
| `Arrays.sort`, `Collections.sort` | ordenação | O(n log n) |

Três observações. Primeiro, o "médio" do `HashMap` vale com um bom `hashCode`; desde o Java 8 baldes muito cheios viram árvores, limitando o pior caso a O(log n) por balde. Segundo, `ArrayList.add` no fim é amortizado porque, quando o array interno enche, ele é copiado para outro maior (cresce cerca de 50%), mas isso acontece raramente. Terceiro, `LinkedList` raramente vale a pena: a localidade de memória do array costuma vencer, e para filas e pilhas o `ArrayDeque` é melhor.

## Medindo na prática com contagem

Não vamos cronometrar, pois tempo varia; vamos contar operações, que é como você raciocina em complexidade. O programa abaixo conta quantas comparações um `contains` em lista faz contra uma consulta em conjunto, ao procurar duplicatas.

```java
import java.util.*;

public class Main {
    static int comparacoes = 0;

    static boolean contemLista(List<Integer> lista, int alvo) {
        for (int x : lista) {
            comparacoes++;
            if (x == alvo) return true;
        }
        return false;
    }

    public static void main(String[] args) {
        int[] entrada = {4, 8, 15, 16, 23, 42, 8};

        List<Integer> vistosLista = new ArrayList<>();
        boolean dupLista = false;
        for (int x : entrada) {
            if (contemLista(vistosLista, x)) { dupLista = true; break; }
            vistosLista.add(x);
        }
        System.out.println("lista: " + dupLista + " com " + comparacoes + " comparações");

        Set<Integer> vistos = new HashSet<>();
        boolean dupSet = false;
        for (int x : entrada) {
            if (!vistos.add(x)) { dupSet = true; break; }
        }
        System.out.println("set: " + dupSet + " com " + vistos.size() + " elementos guardados");
    }
}
```

```text
Saída:
lista: true com 17 comparações
set: true com 6 elementos guardados
```

Com a lista, o custo total é a soma 0+1+2+...: quadrático. Com `HashSet`, cada `add` custa O(1) médio e o retorno booleano já avisa a duplicata, sem uma busca à parte.

## Operações que surpreendem

```java
import java.util.*;

public class Main {
    public static void main(String[] args) {
        TreeMap<Integer, String> agenda = new TreeMap<>();
        agenda.put(10, "A");
        agenda.put(20, "B");
        agenda.put(30, "C");
        System.out.println(agenda.floorKey(25));
        System.out.println(agenda.ceilingKey(25));
        System.out.println(agenda.firstKey() + " " + agenda.lastKey());

        Deque<Integer> fila = new ArrayDeque<>();
        fila.offer(1);
        fila.offer(2);
        fila.offerFirst(0);
        System.out.println(fila.poll() + " " + fila.pollLast() + " " + fila);

        StringBuilder sb = new StringBuilder();
        for (int i = 0; i < 5; i++) sb.append(i);
        System.out.println(sb.reverse());
    }
}
```

```text
Saída:
20
30
10 30
0 2 [1]
43210
```

`TreeMap` responde "o maior menor ou igual a x" em O(log n), algo que `HashMap` não faz. `StringBuilder.append` é O(1) amortizado, ao contrário de `s += x` em laço, que copia a string a cada passo e dá O(n²).

## Armadilhas

`list.contains` e `list.indexOf` escondem um laço. `String.substring` copia (O(k)). `list.remove(i)` desloca todos os elementos à direita. `Collections.sort` numa `LinkedList` copia para array internamente. E no `HashMap`, uma chave com `hashCode` ruim (ou mutável após inserida) destrói o O(1).

<Callout type="tip" title="Dica de quadro branco">
Ao anunciar a complexidade, cite a estrutura: "O(n log n) por causa do `PriorityQueue`" mostra que você sabe de onde cada fator vem.
</Callout>
