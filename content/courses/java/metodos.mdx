Um método agrupa um trecho de código com nome, parâmetros tipados e tipo de retorno. Em Java não existem funções soltas: todo método pertence a uma classe. Para problemas de entrevista, o que você escreve na maior parte do tempo são métodos `static` dentro de `Solution` ou `Main`, chamados sem criar objeto.

## Assinatura e retorno

A assinatura declara tudo: modificador de acesso, `static` quando for o caso, tipo de retorno, nome e parâmetros. Quando o método não devolve nada, o tipo é `void`. Todo caminho de um método com retorno precisa terminar em `return` ou lançar uma exceção; o compilador verifica isso.

```java
static int maximo(int a, int b) {
    return a > b ? a : b;
}
```

## Sobrecarga e varargs

Java permite vários métodos com o mesmo nome desde que a lista de parâmetros seja diferente (sobrecarga). O compilador escolhe a versão pelos tipos dos argumentos, não pelo tipo de retorno. Já os argumentos variáveis (`int... nums`) chegam ao método como um array e aceitam zero ou mais valores.

```java
public class Main {
    static int soma(int a, int b) {
        return a + b;
    }

    static double soma(double a, double b) {
        return a + b;
    }

    static int soma(int... nums) {
        int total = 0;
        for (int n : nums) {
            total += n;
        }
        return total;
    }

    public static void main(String[] args) {
        System.out.println(soma(1, 2));
        System.out.println(soma(1.5, 2.5));
        System.out.println(soma(1, 2, 3));
        System.out.println(soma());
    }
}
```

```text
Saída:
3
4.0
6
0
```

Para `soma(1, 2)` o compilador prefere a versão com dois `int`, a correspondência mais específica. A versão varargs só é considerada quando nenhuma outra serve. Em Python você resolveria isso com argumentos padrão ou `*args`; Java não tem valores padrão de parâmetro, então a sobrecarga cumpre esse papel.

## Passagem por valor

Java sempre passa argumentos por valor. Para primitivos, o método recebe uma cópia. Para objetos e arrays, ele recebe uma cópia da referência: pode alterar o conteúdo do objeto apontado, mas reatribuir o parâmetro não afeta quem chamou.

```java
import java.util.Arrays;

public class Main {
    static void incrementa(int x) {
        x++;
    }

    static void zerar(int[] v) {
        v[0] = 0;
    }

    static void trocar(int[] v) {
        v = new int[]{9, 9};
    }

    static int fatorial(int n) {
        return n <= 1 ? 1 : n * fatorial(n - 1);
    }

    public static void main(String[] args) {
        int x = 5;
        incrementa(x);
        System.out.println(x);

        int[] v = {1, 2, 3};
        zerar(v);
        System.out.println(Arrays.toString(v));
        trocar(v);
        System.out.println(Arrays.toString(v));

        System.out.println(fatorial(5));
    }
}
```

```text
Saída:
5
[0, 2, 3]
[0, 2, 3]
120
```

`incrementa` mexe numa cópia, então `x` continua 5. `zerar` altera o array compartilhado e a mudança aparece fora. `trocar` só faz o parâmetro local apontar para outro array, sem efeito para o chamador. Por isso, em Java, o idioma para "devolver duas coisas" é retornar um array, um objeto ou um `record`, e não alterar parâmetros primitivos.

## Recursão

Java não otimiza chamadas recursivas finais, e cada chamada consome espaço na pilha. Uma recursão com profundidade de dezenas de milhares (por exemplo, percorrer uma lista de 100 mil nós) pode lançar `StackOverflowError`. Em entrevista, comente isso e ofereça a versão iterativa quando a entrada puder ser profunda.

## Métodos estáticos versus de instância

Um método `static` pertence à classe e não enxerga `this`. Um método de instância precisa de um objeto e acessa seus campos. Chamar um método de instância de dentro de `main` sem criar o objeto é um erro frequente: "non-static method cannot be referenced from a static context". Se a lógica não depende de estado, torne o método `static`.

## Na entrevista

Dê nomes que descrevem a intenção e extraia helpers pequenos (`ehValido`, `trocar`) em vez de blocos longos no `main`. Declare o método auxiliar recursivo como `private static`. Follow-ups: "Java passa por valor ou por referência?" (sempre por valor; no caso de objetos, o valor é a referência) e "qual a complexidade de espaço da recursão?" (a profundidade da pilha).
