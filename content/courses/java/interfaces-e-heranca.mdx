Quando um problema pede "vários tipos de coisa que respondem à mesma pergunta" (formas com área, contas com taxa, pagamentos de meios diferentes), você precisa de um contrato comum para tratá-los de forma uniforme. Java oferece dois mecanismos: interfaces e herança de classes. Entender a diferença é pergunta clássica de entrevista de design orientado a objetos.

## Interfaces: o contrato

Uma interface declara o que um tipo sabe fazer, sem dizer como. Uma classe pode implementar quantas interfaces quiser. Desde o Java 8, a interface também pode trazer métodos `default`, com corpo, que as implementações herdam e podem sobrescrever.

```java
import java.util.*;

interface Forma {
    int area();

    default String descricao() {
        return getClass().getSimpleName() + " com area " + area();
    }
}

class Retangulo implements Forma {
    private final int largura, altura;
    Retangulo(int largura, int altura) { this.largura = largura; this.altura = altura; }
    public int area() { return largura * altura; }
}

class Quadrado implements Forma {
    private final int lado;
    Quadrado(int lado) { this.lado = lado; }
    public int area() { return lado * lado; }
}

public class Main {
    public static void main(String[] args) {
        List<Forma> formas = List.of(new Retangulo(3, 4), new Quadrado(5));
        int total = 0;
        for (Forma f : formas) {
            System.out.println(f.descricao());
            total += f.area();
        }
        System.out.println("total = " + total);
    }
}
```

```text
Saída:
Retangulo com area 12
Quadrado com area 25
total = 37
```

Repare que métodos de interface são implicitamente `public`, por isso `area()` nas classes precisa ser declarado `public`. O laço trata tudo como `Forma`: isso é polimorfismo, a chamada resolve para a implementação do objeto real em tempo de execução.

## Herança e classes abstratas

Com `extends` uma classe reaproveita estado e comportamento de outra. Uma classe `abstract` não pode ser instanciada e pode misturar métodos concretos com métodos abstratos que as filhas são obrigadas a implementar. O construtor da mãe é chamado com `super(...)`, e `super.metodo()` chama a versão sobrescrita.

```java
abstract class Conta {
    protected int saldo;

    Conta(int saldo) { this.saldo = saldo; }

    abstract int taxa();

    int sacar(int valor) {
        saldo -= valor + taxa();
        return saldo;
    }
}

class Corrente extends Conta {
    Corrente(int saldo) { super(saldo); }
    int taxa() { return 2; }
}

class Poupanca extends Conta {
    Poupanca(int saldo) { super(saldo); }
    int taxa() { return 0; }

    @Override
    int sacar(int valor) {
        if (valor > saldo) return saldo;
        return super.sacar(valor);
    }
}

public class Main {
    public static void main(String[] args) {
        Conta[] contas = { new Corrente(100), new Poupanca(100) };
        for (Conta c : contas) {
            System.out.println(c.sacar(30));
        }
        Conta p = contas[1];
        System.out.println(p.sacar(500));
        System.out.println(p instanceof Poupanca);
        System.out.println(p instanceof Corrente);
    }
}
```

```text
Saída:
68
70
70
true
false
```

A anotação `@Override` faz o compilador conferir que você realmente sobrescreveu algo; se errar a assinatura, ele reclama em vez de criar um método novo silenciosamente.

## Interface ou classe abstrata?

| | Interface | Classe abstrata |
|---|---|---|
| Quantas por classe | várias | uma só |
| Estado (campos de instância) | não | sim |
| Construtor | não | sim |
| Quando usar | capacidade ("pode ser comparado") | base comum com código compartilhado |

A regra prática: comece pela interface e use classe abstrata quando existir estado ou código realmente compartilhado. Prefira também composição (um objeto que tem outro) a heranças profundas, que acoplam as classes e são difíceis de mudar.

## Armadilhas

Campos não são polimórficos: só métodos de instância são resolvidos pelo objeto real. Métodos `static` e `private` também não são sobrescritos. Se duas interfaces trazem o mesmo método `default`, a classe é obrigada a sobrescrevê-lo para resolver o conflito. E `final` em uma classe ou método impede herança e sobrescrita; `String` é `final`, por exemplo.

<Callout type="tip" title="Tipo da variável, tipo do objeto">
Escreva `List<Integer> xs = new ArrayList<>()` e não `ArrayList<Integer> xs`. Programar para a interface permite trocar a implementação em uma linha e é o que o entrevistador espera ver.
</Callout>
