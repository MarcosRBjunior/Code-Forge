Quem vem de Python e JavaScript tropeça sempre nos mesmos pontos de Java: igualdade de objetos, sobrecarga de `remove`, divisão inteira, listas imutáveis e modificação durante a iteração. Nenhum deles é difícil quando você conhece, mas todos produzem resposta errada sem erro de compilação, o pior tipo de bug em um quadro branco. Este capítulo reúne os mais frequentes.

## Igualdade: == contra equals

Para objetos, `==` compara a referência (se é o mesmo objeto) e `equals` compara o conteúdo. Para `String`, `Integer` e coleções, você quase sempre quer `equals`. Piora: `Integer` guarda em cache objetos de -128 a 127, então `==` entre dois `Integer` parece funcionar para valores pequenos e falha para grandes.

```java
import java.util.*;

public class Main {
    public static void main(String[] args) {
        Integer a = 127, b = 127;
        Integer c = 128, d = 128;
        System.out.println(a == b);
        System.out.println(c == d);
        System.out.println(c.equals(d));

        String s1 = "java";
        String s2 = new String("java");
        System.out.println(s1 == s2);
        System.out.println(s1.equals(s2));

        List<Integer> l1 = List.of(1, 2);
        List<Integer> l2 = new ArrayList<>(List.of(1, 2));
        System.out.println(l1.equals(l2));

        int[] x = {1, 2}, y = {1, 2};
        System.out.println(x.equals(y));
        System.out.println(Arrays.equals(x, y));
    }
}
```

```text
Saída:
true
false
true
false
true
true
false
true
```

Atenção a `x.equals(y)` em arrays: ele compara referência, então use `Arrays.equals`. E `System.out.println(x)` num array imprime algo como `[I@1b6d3586` (tipo e hash); para ver o conteúdo, use `Arrays.toString(x)` ou `Arrays.deepToString` para matrizes. O que importa guardar: em um `Map<String, Integer>`, comparar valores com `==` é bug latente.

## remove, listas fixas e iteração

`List<Integer>` tem duas sobrecargas: `remove(int indice)` e `remove(Object elemento)`. Com literal int, o Java escolhe o índice. Para remover o valor, passe `Integer.valueOf(x)` ou um cast. Listas de `List.of(...)` e `Arrays.asList(...)` não crescem; e remover de uma lista durante um `for-each` lança `ConcurrentModificationException`.

```java
import java.util.*;

public class Main {
    public static void main(String[] args) {
        List<Integer> lista = new ArrayList<>(List.of(10, 20, 30));
        lista.remove(1);
        System.out.println(lista);
        lista.remove(Integer.valueOf(10));
        System.out.println(lista);

        try {
            List.of(1, 2, 3).add(4);
        } catch (UnsupportedOperationException e) {
            System.out.println("List.of é imutável");
        }
        try {
            Arrays.asList(1, 2, 3).add(4);
        } catch (UnsupportedOperationException e) {
            System.out.println("Arrays.asList tem tamanho fixo");
        }

        List<Integer> nums = new ArrayList<>(List.of(1, 2, 3, 4));
        try {
            for (Integer n : nums) {
                if (n == 2) nums.remove(n);
            }
        } catch (ConcurrentModificationException e) {
            System.out.println("modificou durante o for-each");
        }
        nums.removeIf(n -> n % 2 == 0);
        System.out.println(nums);

        System.out.println(7 / 2);
        System.out.println(7 / 2.0);
        System.out.println('a' + 1);
        System.out.println((char) ('a' + 1));
        System.out.println("x" + 1 + 2);
        System.out.println(1 + 2 + "x");
    }
}
```

```text
Saída:
[10, 30]
[30]
List.of é imutável
Arrays.asList tem tamanho fixo
modificou durante o for-each
[1, 3]
3
3.5
98
b
x12
3x
```

Repare que o `nums.remove(n)` dentro do laço usa um `Integer`, então remove o objeto e não um índice. Depois de capturar a exceção, a lista já perdeu o 2 (o `remove` aconteceu antes da detecção), e `removeIf` remove os pares restantes. A forma correta de remover durante a iteração é `removeIf`, um `Iterator` com `it.remove()`, ou iterar de trás para frente por índice.

## Outras armadilhas frequentes

- **Divisão inteira:** `7 / 2` é 3. Para fração, torne um operando `double`.
- **char é número:** `'a' + 1` é 98. Converta de volta com `(char)`.
- **Strings são imutáveis:** `s.toUpperCase()` devolve nova string; você precisa atribuir. Para modificar caracteres, `toCharArray()` ou `StringBuilder`.
- **Arrays de arrays:** `int[][] g = new int[3][3]` já vem zerado; `Arrays.fill(g, 0)` não funciona do jeito que parece, preencha por linha.
- **Cópia rasa:** `int[] b = a;` aponta para o mesmo array; use `a.clone()` ou `Arrays.copyOf`.
- **Comparator com subtração:** `(a, b) -> a - b` estoura para valores extremos; use `Integer.compare(a, b)`.
- **HashMap com chave mutável:** alterar o objeto depois de inserido o perde no mapa.

<Callout type="tip" title="Antes de entregar">
Reserve um minuto para rodar mentalmente o caso vazio, o de um elemento e o dos extremos. A maioria dessas armadilhas aparece justamente aí.
</Callout>

## Na entrevista
