Até aqui você usou métodos estáticos e tipos prontos. Em algum momento da entrevista (um nó de lista ligada, um design de estacionamento, uma conta bancária) será preciso definir o seu próprio tipo. Uma classe agrupa dados (campos) e comportamento (métodos) e serve de molde; cada objeto criado com `new` é uma instância com os seus próprios valores.

## Campos, construtor e métodos

Por convenção, os campos são `private` e o acesso externo passa por métodos. Isso é encapsulamento: a classe controla como o estado muda e protege suas invariantes (por exemplo, um saldo nunca negativo). O construtor tem o nome da classe, não declara retorno e inicializa os campos. A palavra `this` é a referência ao objeto atual, usada para diferenciar campo e parâmetro de mesmo nome.

```java
class Conta {
    private final String titular;
    private long saldoCentavos;

    Conta(String titular, long saldoInicial) {
        this.titular = titular;
        this.saldoCentavos = saldoInicial;
    }

    void depositar(long valor) {
        if (valor <= 0) {
            throw new IllegalArgumentException("valor invalido");
        }
        saldoCentavos += valor;
    }

    boolean sacar(long valor) {
        if (valor > saldoCentavos) return false;
        saldoCentavos -= valor;
        return true;
    }

    long getSaldo() {
        return saldoCentavos;
    }

    @Override
    public String toString() {
        return titular + ": " + saldoCentavos;
    }
}

public class Main {
    public static void main(String[] args) {
        Conta c = new Conta("Ana", 1000);
        c.depositar(500);
        System.out.println(c.sacar(2000));
        System.out.println(c.sacar(300));
        System.out.println(c.getSaldo());
        System.out.println(c);
    }
}
```

```text
Saída:
false
true
1200
Ana: 1200
```

Algumas escolhas aqui são de design, não de sintaxe: o dinheiro está em centavos num `long` para evitar erros de ponto flutuante, o titular é `final` (atribuído uma só vez no construtor) e a validação fica no próprio método. `toString` sobrescrito (com `@Override`) é o que `println` usa para exibir o objeto; sem ele, você veria o nome da classe seguido de um código hexadecimal.

Se você não declara nenhum construtor, o compilador cria um sem argumentos. Assim que declara um, o padrão some. É possível ter vários construtores (sobrecarga) e chamar um a partir de outro com `this(...)`.

## Membros estáticos

Um campo ou método `static` pertence à classe, não a cada objeto. Serve para contadores globais, constantes e funções utilitárias. Dentro de um método estático não existe `this`.

## equals e hashCode

A implementação padrão de `equals` compara identidade, como `==`. Se dois objetos devem ser "iguais" por conteúdo (um ponto na grade, uma chave composta), sobrescreva `equals` e `hashCode` juntos. O contrato é: objetos iguais precisam ter o mesmo `hashCode`. Sem isso, `HashSet` e `HashMap` não os reconhecem como o mesmo elemento.

```java
import java.util.*;

class PontoSemEquals {
    final int x, y;

    PontoSemEquals(int x, int y) {
        this.x = x;
        this.y = y;
    }
}

class Ponto {
    final int x, y;
    static int criados = 0;

    Ponto(int x, int y) {
        this.x = x;
        this.y = y;
        criados++;
    }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof Ponto)) return false;
        Ponto p = (Ponto) o;
        return x == p.x && y == p.y;
    }

    @Override
    public int hashCode() {
        return Objects.hash(x, y);
    }

    @Override
    public String toString() {
        return "(" + x + "," + y + ")";
    }
}

public class Main {
    public static void main(String[] args) {
        Set<PontoSemEquals> a = new HashSet<>();
        a.add(new PontoSemEquals(1, 2));
        a.add(new PontoSemEquals(1, 2));
        System.out.println(a.size());

        Set<Ponto> b = new HashSet<>();
        b.add(new Ponto(1, 2));
        b.add(new Ponto(1, 2));
        System.out.println(b.size());
        System.out.println(b.contains(new Ponto(1, 2)));
        System.out.println(Ponto.criados);
        System.out.println(new Ponto(3, 4));
    }
}
```

```text
Saída:
2
1
true
3
(3,4)
```

Sem `equals` e `hashCode`, os dois pontos idênticos viram dois elementos do conjunto. Com eles, o conjunto reconhece a duplicata e o `contains` encontra um ponto equivalente criado depois. O contador `criados` é estático: ele conta as três instâncias de `Ponto` feitas até aquele momento (duas para inserir e uma para o `contains`). Se `hashCode` fosse deixado de fora, `contains` falharia na maior parte das vezes, pois buscaria no bucket errado.

Repare que `Ponto` e `Conta` ficam no mesmo arquivo que `Main` sem `public`: só uma classe pública por arquivo, e o nome do arquivo segue essa classe. Em entrevistas de uma só classe, é comum ver essas classes auxiliares como `static class` aninhadas dentro de `Solution`.

## Armadilhas

- Campos de objetos começam em `null`; chamar um método neles gera `NullPointerException`.
- Objetos mutáveis usados como chave de mapa quebram quando mudam; prefira campos `final`.
- Expor uma lista interna em um getter deixa quem chama alterá-la; devolva uma cópia ou `List.copyOf`.
- Esquecer `@Override` esconde erros de assinatura: `equals(Ponto p)` não sobrescreve `equals(Object o)`.

## Na entrevista

Em problemas de design, comece pelas responsabilidades: quais dados cada classe guarda e quais operações expõe. Mantenha os campos privados e nomeie os métodos pelo que fazem. Follow-ups: "qual a diferença entre `==` e `equals`?" e "por que sobrescrever `hashCode` ao sobrescrever `equals`?" (para que coleções baseadas em hash funcionem).
