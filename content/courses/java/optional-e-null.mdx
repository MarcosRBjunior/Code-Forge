Em Python existe `None`, em JavaScript `null` e `undefined`. Em Java, `null` é o valor padrão de qualquer referência não inicializada e a causa número um de `NullPointerException`. O tipo `Optional` (Java 8) é uma forma de dizer, na assinatura de um método, "este resultado pode não existir", obrigando quem chama a pensar nisso. Em entrevista, a questão é saber onde `null` aparece na biblioteca e como se proteger dele.

## De onde vem o null

Alguns exemplos que você encontra o tempo todo: `map.get(chave)` devolve `null` quando a chave não existe; campos de objeto e posições de array de referências começam `null`; `queue.poll()` e `queue.peek()` devolvem `null` em fila vazia, enquanto `remove()` e `element()` lançam exceção. Chamar um método em `null` lança `NullPointerException`.

```java
import java.util.*;

public class Main {
    static int somaTotal(Map<String, Integer> notas, String aluno) {
        Integer n = notas.get(aluno);
        return n;
    }

    public static void main(String[] args) {
        Map<String, Integer> notas = new HashMap<>();
        notas.put("ana", 9);

        System.out.println(notas.get("bia"));
        System.out.println(notas.getOrDefault("bia", 0));

        try {
            System.out.println(somaTotal(notas, "bia"));
        } catch (NullPointerException e) {
            System.out.println("NPE ao fazer unboxing de null");
        }

        String texto = null;
        System.out.println("abc".equals(texto));
        System.out.println(Objects.equals(texto, null));

        Queue<Integer> fila = new ArrayDeque<>();
        System.out.println(fila.poll());
        try {
            fila.remove();
        } catch (NoSuchElementException e) {
            System.out.println("remove lança exceção");
        }
    }
}
```

```text
Saída:
null
0
NPE ao fazer unboxing de null
false
true
null
remove lança exceção
```

O caso mais traiçoeiro é o `Integer n = ...get(...)` seguido de conversão para `int`: o unboxing de `null` lança NPE sem nenhum aviso visível. Por isso `getOrDefault` ou um teste de `containsKey` valem ouro. Outra regra útil: escreva `"literal".equals(variavel)` (ou `Objects.equals(a, b)`) em vez de `variavel.equals("literal")`, que explode se a variável for nula.

## Optional

`Optional<T>` é um contêiner que está vazio ou guarda um valor. Streams usam bastante: `findFirst`, `max` e `min` devolvem `Optional`. Você cria com `Optional.of(x)` (falha se `x` for null), `Optional.ofNullable(x)` e `Optional.empty()`.

```java
import java.util.*;

public class Main {
    static Optional<Integer> primeiroPar(List<Integer> xs) {
        for (int x : xs) {
            if (x % 2 == 0) return Optional.of(x);
        }
        return Optional.empty();
    }

    public static void main(String[] args) {
        Optional<Integer> a = primeiroPar(List.of(3, 5, 6, 8));
        Optional<Integer> b = primeiroPar(List.of(3, 5));

        System.out.println(a.isPresent() + " " + b.isPresent());
        System.out.println(a.get());
        System.out.println(b.orElse(-1));
        System.out.println(a.map(x -> x * 10).orElse(0));
        System.out.println(b.map(x -> x * 10).orElse(0));

        a.ifPresent(x -> System.out.println("achei " + x));
        System.out.println(Optional.ofNullable((String) null).isEmpty());

        List<Integer> vazia = List.of();
        System.out.println(vazia.stream().max(Integer::compare).orElse(-1));
    }
}
```

```text
Saída:
true false
6
-1
60
0
achei 6
true
-1
```

Prefira `orElse`, `orElseGet`, `map` e `ifPresent` a `isPresent()` seguido de `get()`, que repete o teste de `null` com mais código. Chamar `get()` num `Optional` vazio lança `NoSuchElementException`. `orElse(valor)` sempre avalia o argumento; `orElseGet(() -> ...)` só chama o fornecedor se for preciso, o que importa quando o valor padrão é caro de calcular.

## Quando não usar Optional

`Optional` serve como tipo de retorno. Evite em campos, parâmetros e coleções (`List<Optional<T>>` é cheiro de código), e jamais devolva `null` de um método que promete `Optional`. Há também custo: é um objeto extra alocado, então em laços quentes de algoritmos com milhões de iterações um `int` com valor sentinela (como `-1`) é a escolha natural. Para tipos primitivos existem `OptionalInt`, `OptionalDouble` e `OptionalLong`, que evitam boxing.

<Callout type="tip" title="Validação rápida">
Para falhar cedo com mensagem clara, use `Objects.requireNonNull(x, "x não pode ser nulo")`. Ela lança NPE na entrada do método, em vez de lá no fundo da pilha.
</Callout>

## Na entrevista

Trate explicitamente os casos de borda de nulo e vazio: lista nula, string vazia, árvore sem raiz. Ao devolver "nenhum resultado", combine com o entrevistador se é `null`, `-1`, lista vazia ou `Optional`. Follow-ups comuns: "como evitar NPE ao ler de um `HashMap`?" (`getOrDefault`, `containsKey`, `computeIfAbsent`) e "por que `Optional.of(null)` lança exceção?" (ele existe para valor presente; `ofNullable` é o que aceita null).
