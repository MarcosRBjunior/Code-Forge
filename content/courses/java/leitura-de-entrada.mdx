Em Python você escreve `input()` e em JavaScript lê `process.stdin`. Em Java existem várias formas, com tradeoffs de conforto e velocidade. Nas plataformas de entrevista com assinatura de método você nem precisa ler a entrada, mas em exercícios de competição, take-homes e alguns testes online o programa lê o `System.in` e escreve no `System.out`. Saber os dois jeitos e quando usar cada um poupa tempo e evita estouro de limite.

## Scanner: simples, porém lento

`Scanner` lê tokens separados por espaço com `nextInt()`, `nextLong()`, `next()` e linhas inteiras com `nextLine()`. É prático para entradas pequenas. Para ensaiar sem teclado, o exemplo constrói o `Scanner` a partir de uma `String`, e o código para `System.in` é idêntico, trocando só a fonte (`new Scanner(System.in)`).

```java
import java.util.*;

public class Main {
    public static void main(String[] args) {
        String entrada = "3\n10 20 30\nana silva\n";
        Scanner sc = new Scanner(entrada);

        int n = sc.nextInt();
        long soma = 0;
        for (int i = 0; i < n; i++) {
            soma += sc.nextLong();
        }
        sc.nextLine();
        String nome = sc.nextLine();

        System.out.println("n = " + n);
        System.out.println("soma = " + soma);
        System.out.println("nome = " + nome);
        System.out.println(sc.hasNextLine());
    }
}
```

```text
Saída:
n = 3
soma = 60
nome = ana silva
false
```

A armadilha clássica está no `sc.nextLine()` solitário: `nextInt()` e companhia param antes da quebra de linha, deixando-a no buffer. Sem esse `nextLine()` extra para consumi-la, o próximo `nextLine()` devolveria uma string vazia. Para ler até o fim, use `while (sc.hasNext())` ou `hasNextInt()`.

O problema do `Scanner` é o desempenho: ele usa expressões regulares por token e fica lento com centenas de milhares de números. Se o enunciado fala de 10 elevado a 5 ou mais valores, troque.

## BufferedReader: rápido

`BufferedReader` lê linhas inteiras com `readLine()` (que devolve `null` no fim da entrada) e você as divide. Com `StringTokenizer` ou `split(" ")` obtém os números. Ele lança `IOException`, então declare `throws IOException` em `main`.

```java
import java.io.*;
import java.util.*;

public class Main {
    public static void main(String[] args) throws IOException {
        String entrada = "5\n4 -1 7 0 2\n";
        BufferedReader br = new BufferedReader(new StringReader(entrada));

        int n = Integer.parseInt(br.readLine().trim());
        StringTokenizer st = new StringTokenizer(br.readLine());
        int[] v = new int[n];
        for (int i = 0; i < n; i++) {
            v[i] = Integer.parseInt(st.nextToken());
        }
        Arrays.sort(v);

        StringBuilder sb = new StringBuilder();
        for (int x : v) sb.append(x).append(' ');
        System.out.println(sb.toString().trim());
        System.out.println(br.readLine());
    }
}
```

```text
Saída:
-1 0 2 4 7
null
```

Para ler da entrada padrão de verdade, substitua o `StringReader` por `new InputStreamReader(System.in)`:

```java
BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
int n = Integer.parseInt(br.readLine().trim());
```

## Saída rápida

Chamar `System.out.println` centenas de milhares de vezes é lento, porque cada chamada pode gerar uma escrita. Acumule em um `StringBuilder` e imprima uma vez no final, como no exemplo anterior. Outra opção é um `PrintWriter` com buffer (`new PrintWriter(new BufferedWriter(new OutputStreamWriter(System.out)))`) e `flush()` ao terminar. Sem o `flush`, a saída pode ficar retida no buffer e nunca aparecer.

## Resumo de escolhas

| Situação | Ferramenta |
|---|---|
| Entrada pequena, conforto | `Scanner` |
| Muitos números (acima de uns 10 elevado a 5) | `BufferedReader` com `StringTokenizer` |
| Muitas linhas de saída | `StringBuilder` e um único `println` |
| Assinatura de método dada | nada, só use os parâmetros |

<Callout type="note" title="Formato da entrada">
Leia o formato com atenção: se o enunciado diz que a primeira linha traz `n` e a segunda traz `n` números, ler `n` tokens é mais robusto do que depender de quebras de linha, que variam entre plataformas.
</Callout>
