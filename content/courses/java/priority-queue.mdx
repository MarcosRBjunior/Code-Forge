Algumas perguntas se repetem em entrevista: "os K maiores", "mesclar K listas ordenadas", "o menor caminho (Dijkstra)", "agendar tarefas pelo prazo". Em todas, você precisa pegar sempre o menor (ou o maior) elemento de um conjunto que continua recebendo inserções. Ordenar de novo a cada passo custa caro; o heap resolve em O(log n) por operação. Em Java ele se chama `PriorityQueue`, equivalente ao módulo `heapq` do Python.

## Como funciona

A `PriorityQueue` é um min-heap binário guardado num array. A raiz é sempre o menor elemento segundo a ordem natural (ou um `Comparator` que você fornece). As operações:

| Operação | Custo |
|----------|-------|
| `add` / `offer` | O(log n) |
| `peek` (olhar o menor) | O(1) |
| `poll` (remover o menor) | O(log n) |
| `remove(Object)` / `contains` | O(n) |
| construir a partir de n elementos | O(n) |

Atenção ao que ela não é: o iterador e o `toString` mostram a ordem interna do array, que não é ordenada. Só `poll` entrega os elementos em ordem. Se você imprimir a fila para depurar e ver algo "fora de ordem", está tudo certo.

```java
import java.util.*;

public class Main {
    public static void main(String[] args) {
        PriorityQueue<Integer> pq = new PriorityQueue<>();
        pq.add(5);
        pq.add(1);
        pq.add(4);
        pq.add(2);
        System.out.println(pq.peek() + " " + pq.size());

        List<Integer> ordem = new ArrayList<>();
        while (!pq.isEmpty()) {
            ordem.add(pq.poll());
        }
        System.out.println(ordem);

        PriorityQueue<Integer> mx = new PriorityQueue<>(Collections.reverseOrder());
        mx.addAll(List.of(5, 1, 4, 2));
        List<Integer> desc = new ArrayList<>();
        while (!mx.isEmpty()) {
            desc.add(mx.poll());
        }
        System.out.println(desc);
    }
}
```

```text
Saída:
1 4
[1, 2, 4, 5]
[5, 4, 2, 1]
```

Para um max-heap, passe `Collections.reverseOrder()` ou um lambda `(a, b) -> b - a`. Cuidado com a subtração em valores grandes, que pode estourar `int`; `Integer.compare(b, a)` é mais seguro. Em Python você simularia o max-heap negando os valores; aqui basta o comparador.

## Elementos compostos

Quase sempre você guarda pares: um nó com a sua distância, uma tarefa com prioridade. Use `int[]` ou uma classe/record e informe o comparador na criação da fila.

```java
import java.util.*;

public class Main {
    static int kEsimoMaior(int[] nums, int k) {
        PriorityQueue<Integer> heap = new PriorityQueue<>();
        for (int n : nums) {
            heap.add(n);
            if (heap.size() > k) {
                heap.poll();
            }
        }
        return heap.peek();
    }

    public static void main(String[] args) {
        System.out.println(kEsimoMaior(new int[]{3, 2, 1, 5, 6, 4}, 2));

        PriorityQueue<int[]> tarefas = new PriorityQueue<>((a, b) -> Integer.compare(a[1], b[1]));
        tarefas.add(new int[]{1, 50});
        tarefas.add(new int[]{2, 10});
        tarefas.add(new int[]{3, 30});
        StringBuilder sb = new StringBuilder();
        while (!tarefas.isEmpty()) {
            sb.append(tarefas.poll()[0]).append(' ');
        }
        System.out.println(sb.toString().trim());
    }
}
```

```text
Saída:
5
2 3 1
```

O primeiro método é o padrão "heap de tamanho K": para achar o K-ésimo maior, mantenha um min-heap com no máximo K elementos. Cada elemento custa O(log k), então o total é O(n log k), melhor que ordenar tudo (O(n log n)) quando k é pequeno. No fim, a raiz é o K-ésimo maior. O segundo trecho ordena tarefas pelo segundo campo do par, devolvendo os ids na ordem 2, 3, 1.

## Armadilhas

- A fila não é estável: elementos com prioridade igual saem em ordem arbitrária. Se importar, inclua um contador de inserção como desempate.
- Não altere a prioridade de um elemento que já está na fila; o heap não reordena. Remova e reinsira, ou deixe duplicatas e ignore as obsoletas ao sair (técnica comum no Dijkstra).
- `PriorityQueue` não aceita `null`.
- `remove(obj)` é O(n); evite em laços grandes.
- Sem comparador, os elementos precisam ser `Comparable`; uma classe sua sem isso lança `ClassCastException` na primeira inserção.

## Na entrevista

Cite o heap sempre que o enunciado falar em "K maiores/menores", "mediana contínua" (dois heaps) ou "menor caminho". Informe a complexidade: n inserções custam O(n log n); heap de tamanho k, O(n log k). Follow-ups: "como obter os K elementos mais frequentes?" (contar com `HashMap` e manter um min-heap de tamanho K pelas frequências) e "quando um `TreeSet` seria melhor?" (quando precisa remover ou buscar elementos arbitrários).
