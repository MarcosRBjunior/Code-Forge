Em Python, inteiros crescem sem limite. Em JavaScript, números são doubles e perdem precisão acima de 2 elevado a 53. Em Java, `int` tem 32 bits e `long` tem 64, e quando uma conta passa do limite o resultado dá a volta sem avisar. Esse silêncio faz o overflow ser um dos erros mais comuns em entrevistas, principalmente em somas, produtos, pontos médios e módulos.

## Os limites

`int` vai de -2147483648 a 2147483647 (cerca de 2,1 bilhões). `long` vai até 9223372036854775807 (cerca de 9,2 quintilhões). As constantes `Integer.MAX_VALUE`, `Integer.MIN_VALUE`, `Long.MAX_VALUE` e `Long.MIN_VALUE` existem para você não decorar números. Ao passar de `MAX_VALUE`, o valor vira `MIN_VALUE`: a aritmética é em complemento de dois, módulo 2 elevado a 32.

```java
public class Main {
    public static void main(String[] args) {
        int max = Integer.MAX_VALUE;
        System.out.println(max + 1);

        int a = 100000, b = 100000;
        System.out.println(a * b);
        System.out.println((long) a * b);
        System.out.println((long) (a * b));

        System.out.println(Math.abs(Integer.MIN_VALUE));
        System.out.println(-Integer.MIN_VALUE == Integer.MIN_VALUE);

        System.out.println((int) 3_000_000_000L);
        System.out.println(Long.MAX_VALUE);

        try {
            Math.addExact(max, 1);
        } catch (ArithmeticException e) {
            System.out.println("addExact: " + e.getMessage());
        }
    }
}
```

```text
Saída:
-2147483648
1410065408
10000000000
1410065408
-2147483648
true
-1294967296
9223372036854775807

```

O ponto central está nas linhas 3 e 4: `(long) a * b` converte `a` antes de multiplicar e funciona; `(long) (a * b)` converte depois, quando o estrago já foi feito. Outra surpresa é `Math.abs(Integer.MIN_VALUE)`, que continua negativo, pois +2147483648 não cabe em `int`. Se você usa `abs` num hash ou índice, trate esse caso (ou use `& 0x7fffffff`, ou `Math.floorMod`).

Para detectar overflow em vez de ignorá-lo, use as variantes `Math.addExact`, `subtractExact`, `multiplyExact` e `toIntExact`, que lançam `ArithmeticException`. É útil em validação e mostra cuidado para o entrevistador.

## Onde o overflow aparece em entrevista

O caso clássico é o ponto médio da busca binária. `(lo + hi) / 2` estoura quando `lo + hi` passa de 2,1 bilhões; a forma segura é `lo + (hi - lo) / 2`. Outro caso é somar um array grande (use `long` para o acumulador), calcular fatorial ou Fibonacci (use `long`, e fique atento: 21! já estoura `long`), ou multiplicar para obter áreas e distâncias ao quadrado.

```java
public class Main {
    public static void main(String[] args) {
        int lo = 2_000_000_000, hi = 2_100_000_000;
        System.out.println((lo + hi) / 2);
        System.out.println(lo + (hi - lo) / 2);
        System.out.println((lo + hi) >>> 1);

        System.out.println(-7 % 3);
        System.out.println(Math.floorMod(-7, 3));

        long mod = 1_000_000_007L;
        long x = 123_456_789L, y = 987_654_321L;
        System.out.println(x * y % mod);

        int soma = 0;
        for (int i = 0; i < 3; i++) soma += Integer.MAX_VALUE;
        System.out.println(soma);

        char c = 'a';
        c += 2;
        System.out.println(c);
        System.out.println(c - 'a');
    }
}
```

```text
Saída:
-97483648
2050000000
2050000000
-1
2
259106859
2147483645
c
2
```

Veja que `(lo + hi) >>> 1` também resolve, pois o deslocamento sem sinal trata a soma estourada como número de 32 bits sem sinal. Mas `lo + (hi - lo) / 2` é a forma que todos reconhecem.

O resto da divisão em Java (`%`) segue o sinal do dividendo: `-7 % 3` é `-1`, ao contrário de Python, onde dá `2`. Para obter um módulo não negativo, use `Math.floorMod(a, m)` ou `((a % m) + m) % m`. Em problemas com módulo 1_000_000_007, os produtos de dois valores menores que o módulo cabem em `long`, mas precisam ser reduzidos antes da próxima multiplicação.

## Ponto flutuante

`double` tem 53 bits de mantissa e erros de arredondamento: `0.1 + 0.2` não é exatamente `0.3`. Nunca compare doubles com `==` quando o resultado vem de contas; use uma tolerância (`Math.abs(a - b) < 1e-9`). Divisão inteira por zero lança `ArithmeticException`, mas divisão de double por zero dá `Infinity` ou `NaN` sem lançar nada.

<Callout type="warning" title="Literais inteiros">
`long grande = 3_000_000_000;` não compila, pois o literal é `int`. Escreva `3_000_000_000L`. E `long x = 1 << 40` dá resultado errado porque o deslocamento ocorre em `int`; use `1L << 40`.
</Callout>

## Na entrevista

Ao ler as restrições do enunciado (por exemplo, "n até 10 elevado a 5, valores até 10 elevado a 9"), faça a conta do pior caso e decida `int` ou `long` antes de escrever. Dizer isso em voz alta vale pontos. Follow-ups comuns: "como evitar overflow no ponto médio?" e "o que `Math.abs(Integer.MIN_VALUE)` devolve?".
