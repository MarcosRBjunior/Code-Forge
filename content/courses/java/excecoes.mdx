Um erro em tempo de execução (divisão por zero, índice fora do array, texto que não é número) não deve derrubar o programa sem explicação nem ser ignorado. Exceções são o mecanismo de Java para sinalizar e tratar situações anormais separadas do fluxo normal. Python e JavaScript também têm `try/except` e `try/catch`; a diferença em Java é que existe uma hierarquia de tipos e a noção de exceção verificada.

## try, catch e finally

O código arriscado vai no `try`; cada `catch` trata um tipo; o `finally` roda sempre, houve erro ou não.

```java
public class Main {
    static int dividir(int a, int b) {
        return a / b;
    }

    public static void main(String[] args) {
        try {
            System.out.println(dividir(10, 2));
            System.out.println(dividir(1, 0));
            System.out.println("não chega aqui");
        } catch (ArithmeticException e) {
            System.out.println("erro: " + e.getMessage());
        } finally {
            System.out.println("finally roda sempre");
        }

        try {
            int n = Integer.parseInt("12x");
            System.out.println(n);
        } catch (NumberFormatException | NullPointerException e) {
            System.out.println(e.getClass().getSimpleName());
        }

        try {
            int[] v = new int[3];
            v[3] = 1;
        } catch (RuntimeException e) {
            System.out.println("capturada: " + e.getClass().getSimpleName());
        }
    }
}
```

```text
Saída:
5
erro: / by zero
finally roda sempre
NumberFormatException
capturada: ArrayIndexOutOfBoundsException
```

Os `catch` são testados em ordem, então o tipo mais específico vem primeiro; o compilador rejeita um `catch` inalcançável por já ter sido coberto por um tipo mais geral antes dele. Dá para tratar tipos diferentes juntos com `|`.

## Verificadas e não verificadas

Toda exceção descende de `Throwable`. As que estendem `Exception` mas não `RuntimeException` são verificadas (checked): o compilador obriga a tratar com `try/catch` ou declarar com `throws`. Exemplos: `IOException`, `InterruptedException`. As que estendem `RuntimeException` (`NullPointerException`, `IllegalArgumentException`, `IndexOutOfBoundsException`) são não verificadas e podem aparecer em qualquer lugar. `Error` (como `StackOverflowError` e `OutOfMemoryError`) indica problemas da JVM que você normalmente não captura.

Para sinalizar um erro seu, use `throw`. Para validar argumentos, `IllegalArgumentException` e `IllegalStateException` costumam ser a escolha certa. Se quiser um tipo próprio, estenda `RuntimeException` (ou `Exception`, se quiser obrigar o chamador a tratar).

## try-with-resources

Recursos que precisam ser fechados (arquivos, leitores) implementam `AutoCloseable`. Com `try (...)`, o `close()` é chamado automaticamente, mesmo em caso de exceção, na ordem inversa da abertura.

```java
public class Main {
    static class Recurso implements AutoCloseable {
        private final String nome;
        Recurso(String nome) { this.nome = nome; System.out.println("abre " + nome); }
        void usar(boolean falhar) {
            if (falhar) throw new IllegalStateException("falha em " + nome);
            System.out.println("usa " + nome);
        }
        @Override
        public void close() { System.out.println("fecha " + nome); }
    }

    static void validarIdade(int idade) {
        if (idade < 0) throw new IllegalArgumentException("idade negativa: " + idade);
    }

    public static void main(String[] args) {
        try (Recurso a = new Recurso("A"); Recurso b = new Recurso("B")) {
            a.usar(false);
            b.usar(true);
        } catch (IllegalStateException e) {
            System.out.println("tratada: " + e.getMessage());
        }

        try {
            validarIdade(-5);
        } catch (IllegalArgumentException e) {
            System.out.println(e.getMessage());
        }
    }
}
```

```text
Saída:
abre A
abre B
usa A
fecha B
fecha A
tratada: falha em B
idade negativa: -5
```

Repare que `B` é fechado antes de `A` e que o `catch` só roda depois dos fechamentos.

## Armadilhas

Capturar `Exception` ou `Throwable` por preguiça esconde bugs; capture o tipo mais específico possível. Um `catch` vazio engole o erro e é um péssimo sinal numa revisão. Um `return` dentro de `finally` sobrescreve qualquer retorno ou exceção do `try`, então evite. E exceções custam caro para criar (montam o stack trace): não use para controle de fluxo normal em laços quentes, prefira um `if`.

## Na entrevista

Você raramente precisa lançar exceções em algoritmos, mas deve tratar entradas inválidas quando o enunciado permitir: uma checagem `if (arr == null || arr.length == 0)` ou um `throw new IllegalArgumentException` mostra cuidado. Follow-ups comuns: "diferença entre checked e unchecked?" e "o que o `finally` garante e quando ele não roda?" (não roda se a JVM for encerrada, por exemplo com `System.exit`).
