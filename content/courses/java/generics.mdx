Em Python e JavaScript você coloca qualquer coisa em qualquer lista. Em Java a lista tem tipo, e o compilador recusa colocar um `String` onde se espera `Integer`. Generics são o mecanismo que permite escrever uma classe ou método uma vez e usá-lo com vários tipos sem perder essa checagem. Você os usa o tempo todo (`List<Integer>`, `Map<String, Integer>`) e precisa saber escrever os seus.

## O problema

Antes dos generics, coleções guardavam `Object` e você convertia na saída, descobrindo o erro só em execução. Com o parâmetro de tipo, o erro vira falha de compilação.

```java
import java.util.*;

class Caixa<T> {
    private T valor;

    Caixa(T valor) { this.valor = valor; }

    T get() { return valor; }

    void set(T novo) { valor = novo; }
}

public class Main {
    static <T extends Comparable<T>> T maior(List<T> itens) {
        T melhor = itens.get(0);
        for (T x : itens) {
            if (x.compareTo(melhor) > 0) melhor = x;
        }
        return melhor;
    }

    public static void main(String[] args) {
        Caixa<String> c = new Caixa<>("oi");
        System.out.println(c.get().length());
        Caixa<Integer> n = new Caixa<>(41);
        n.set(n.get() + 1);
        System.out.println(n.get());

        System.out.println(maior(List.of(3, 9, 4)));
        System.out.println(maior(List.of("kiwi", "uva", "abacate")));
    }
}
```

```text
Saída:
2
42
9
uva
```

`Caixa<T>` é uma classe genérica: `T` é um espaço reservado preenchido no uso. `maior` é um método genérico, com `<T extends Comparable<T>>` antes do tipo de retorno. O limite `extends Comparable<T>` diz que `T` precisa saber se comparar, o que libera o uso de `compareTo`. Sem o limite, o compilador não aceitaria a chamada.

## Curingas

Um erro comum é achar que `List<Integer>` é subtipo de `List<Number>`. Não é: se fosse, você poderia inserir um `Double` numa lista de inteiros através da referência. Para métodos que apenas leem, use o curinga `? extends`; para métodos que apenas escrevem, `? super`. A mnemônica é PECS: producer extends, consumer super.

```java
import java.util.*;

public class Main {
    static double soma(List<? extends Number> numeros) {
        double total = 0;
        for (Number n : numeros) total += n.doubleValue();
        return total;
    }

    static void preencher(List<? super Integer> destino) {
        destino.add(1);
        destino.add(2);
    }

    public static void main(String[] args) {
        List<Integer> inteiros = new ArrayList<>(List.of(1, 2, 3));
        List<Double> reais = List.of(1.5, 2.5);
        System.out.println(soma(inteiros));
        System.out.println(soma(reais));

        List<Number> mistos = new ArrayList<>();
        preencher(mistos);
        System.out.println(mistos);

        List<String> a = new ArrayList<>();
        List<Integer> b = new ArrayList<>();
        System.out.println(a.getClass() == b.getClass());
    }
}
```

```text
Saída:
6.0
4.0
[1, 2]
true
```

A última linha mostra o apagamento de tipos (type erasure): em tempo de execução, `List<String>` e `List<Integer>` são a mesma classe `ArrayList`. Os parâmetros de tipo existem só para o compilador.

## Consequências do apagamento

- Não dá para fazer `new T()` nem `new T[n]`; para criar um array genérico, use `(T[]) new Object[n]` com aviso de cast não verificado, ou use `List<T>`.
- Não dá para usar tipos primitivos como argumento: é `List<Integer>`, nunca `List<int>`. O custo é o boxing, tema do capítulo de armadilhas e de complexidade.
- `instanceof List<String>` não compila, pois a informação foi apagada.

Em problemas de entrevista você costuma escrever genéricos em situações como uma classe `Pair<A, B>`, uma pilha ou fila própria (`MinStack<T>`) ou um nó de lista ligada `Node<T>`. Nesses casos, a sintaxe do primeiro exemplo basta.

<Callout type="note" title="O operador diamante">
Escreva `new ArrayList<>()` e deixe o compilador inferir o tipo a partir da declaração. Repetir `<Integer>` dos dois lados só gasta tempo de quadro branco.
</Callout>

## Na entrevista

Se pedirem uma estrutura própria (LRU cache, fila de prioridade), declare-a genérica ou com tipos concretos conforme o enunciado, mas explique que usaria generics para reutilização. Follow-ups frequentes: "por que `List<Object>` não aceita um `List<String>`?" (invariância; use `List<?>` ou `? extends`) e "o que é type erasure?" (a JVM não conhece os argumentos de tipo, o que impede `new T()` e sobrecargas que só diferem por eles).
