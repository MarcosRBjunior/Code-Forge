Conhecer a biblioteca não basta: numa entrevista você é avaliado pela forma como conduz o problema. Um bom molde reduz o risco de travar e deixa o entrevistador acompanhar seu raciocínio. Este capítulo mostra a estrutura de código em Java e o roteiro de comunicação que funcionam para a maioria dos problemas de algoritmos.

## O roteiro

1. **Entenda e reformule.** Repita o problema com suas palavras e peça exemplos. Pergunte sobre tamanho das entradas, valores negativos, duplicatas, entrada vazia e se pode modificar a entrada.
2. **Exemplo à mão.** Rode um caso pequeno no papel. Isso revela padrões e já serve de teste depois.
3. **Força bruta primeiro.** Diga a solução óbvia e sua complexidade. Mesmo que não a implemente, ela mostra que você entendeu o problema.
4. **Otimize.** Procure o gargalo: uma busca repetida vira `HashMap`; ordenação ajuda com dois ponteiros; extremos repetidos pedem `PriorityQueue`.
5. **Combine antes de codar.** Descreva a estrutura escolhida e a complexidade final, e espere o aval.
6. **Código limpo.** Nomes claros, métodos pequenos, casos de borda no começo.
7. **Teste em voz alta.** Execute o código nos seus exemplos e em bordas (vazio, um elemento, extremos).

## O molde em Java

Em plataformas de entrevista você costuma receber uma classe `Solution` com um método. Mantenha a lógica nele, valide as bordas logo no início e use nomes descritivos. Se precisar de um programa completo, coloque os testes em `main`.

```java
import java.util.*;

class Solution {
    public int[] twoSum(int[] nums, int alvo) {
        if (nums == null || nums.length < 2) return new int[0];

        Map<Integer, Integer> indicePorValor = new HashMap<>();
        for (int i = 0; i < nums.length; i++) {
            int falta = alvo - nums[i];
            Integer j = indicePorValor.get(falta);
            if (j != null) return new int[] { j, i };
            indicePorValor.put(nums[i], i);
        }
        return new int[0];
    }
}

public class Main {
    public static void main(String[] args) {
        Solution s = new Solution();
        System.out.println(Arrays.toString(s.twoSum(new int[] {2, 7, 11, 15}, 9)));
        System.out.println(Arrays.toString(s.twoSum(new int[] {3, 2, 4}, 6)));
        System.out.println(Arrays.toString(s.twoSum(new int[] {1}, 2)));
        System.out.println(Arrays.toString(s.twoSum(new int[] {3, 3}, 6)));
    }
}
```

```text
Saída:
[0, 1]
[1, 2]
[]
[0, 1]
```

A solução faz uma passada, guardando valores já vistos: O(n) de tempo e O(n) de espaço, contra O(n²) da força bruta. Perceba os detalhes: a verificação de entrada no topo, o `Integer j` (e não `int`) para poder testar `null`, e o `put` depois da consulta, o que evita usar o mesmo elemento duas vezes (por isso o caso `{3, 3}` funciona). Ao final, testar `{1}` e `{3, 3}` mostra as bordas.

## Um segundo exemplo: busca em grade

Problemas em grade e grafos se repetem com o mesmo esqueleto: fila, conjunto de visitados, vetor de direções. Decorar esse esqueleto economiza minutos preciosos.

```java
import java.util.*;

class Solution {
    private static final int[][] DIRS = {{1, 0}, {-1, 0}, {0, 1}, {0, -1}};

    public int menorCaminho(int[][] grade) {
        int n = grade.length, m = grade[0].length;
        if (grade[0][0] == 1 || grade[n - 1][m - 1] == 1) return -1;

        boolean[][] visto = new boolean[n][m];
        Deque<int[]> fila = new ArrayDeque<>();
        fila.offer(new int[] {0, 0, 0});
        visto[0][0] = true;

        while (!fila.isEmpty()) {
            int[] atual = fila.poll();
            int l = atual[0], c = atual[1], passos = atual[2];
            if (l == n - 1 && c == m - 1) return passos;
            for (int[] d : DIRS) {
                int nl = l + d[0], nc = c + d[1];
                if (nl < 0 || nc < 0 || nl >= n || nc >= m) continue;
                if (visto[nl][nc] || grade[nl][nc] == 1) continue;
                visto[nl][nc] = true;
                fila.offer(new int[] {nl, nc, passos + 1});
            }
        }
        return -1;
    }
}

public class Main {
    public static void main(String[] args) {
        Solution s = new Solution();
        int[][] a = {{0, 0, 1}, {1, 0, 0}, {1, 1, 0}};
        int[][] b = {{0, 1}, {1, 0}};
        System.out.println(s.menorCaminho(a));
        System.out.println(s.menorCaminho(b));
        System.out.println(s.menorCaminho(new int[][] {{0}}));
    }
}
```

```text
Saída:
4
-1
0
```

A BFS (busca em largura) garante o menor número de passos em grafos sem peso. Marcar `visto` ao enfileirar, e não ao retirar, evita colocar o mesmo nó várias vezes. O custo é O(n vezes m) de tempo e de espaço.

## Armadilhas do processo

Começar a codar sem concordar sobre a abordagem é o erro número um. O segundo é ficar em silêncio: mesmo travado, narre o que está tentando, pois o entrevistador pode dar uma dica. O terceiro é descuidar de bordas e de nomes (`i`, `j` e `x` por toda parte). Por fim, evite otimizar prematuramente: uma solução correta em O(n log n) vale mais do que uma tentativa incompleta de O(n).

<Callout type="tip" title="Frase de transição">
Ao terminar de codar, diga "vou rodar o primeiro exemplo linha a linha" e faça isso apontando para o código. Muitos bugs aparecem aí, e você os corrige antes de o entrevistador notar.
</Callout>

## Na entrevista

Use o roteiro como checklist mental e fale a complexidade de tempo e espaço no fim. Follow-ups comuns: "dá para usar menos memória?", "e se a entrada não couber na memória?" e "como você testaria isso?". Responda com casos de borda concretos e, se fizer sentido, com uma variante da estrutura (ordenar e usar dois ponteiros troca memória por tempo de ordenação).
