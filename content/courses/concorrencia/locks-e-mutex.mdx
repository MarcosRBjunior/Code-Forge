Quando várias threads precisam mexer no mesmo estado, você precisa garantir que só uma delas esteja dentro do trecho perigoso por vez. O **mutex** (de *mutual exclusion*) é a ferramenta para isso: um objeto com dois estados, livre ou ocupado, e duas operações, adquirir e liberar. Quem tenta adquirir um mutex ocupado fica bloqueado até o dono liberar. Em Python ele se chama `threading.Lock`; em Java você tem `synchronized` e `ReentrantLock`; em Go, `sync.Mutex`; em C++, `std::mutex`.

## Como funciona

```text
         adquirir()                      liberar()
livre  ------------->  ocupado (dono: T1)  ------------->  livre
                          |
          T2 adquirir()   |  T2 fica bloqueada na fila de espera
                          v
                 T2 acorda quando T1 libera
```

Por baixo, um mutex costuma combinar uma instrução atômica do processador (para tentar trocar o estado de livre para ocupado) com uma chamada ao sistema operacional para colocar a thread para dormir quando a tentativa falha. Por isso adquirir um lock livre é barato, enquanto disputar um lock concorrido custa trocas de contexto.

Além da exclusão mútua, o lock também dá **visibilidade**: tudo que uma thread escreveu antes de liberar fica visível para a próxima que adquirir. Isso importa em Java, C++ e Go, onde sem sincronização o compilador e a CPU podem reordenar ou esconder escritas.

## Usando corretamente

A regra número um: libere sempre, mesmo se der exceção. Em Python, use `with`, que chama `release` na saída do bloco. Em Java, o padrão é `lock()` antes do `try` e `unlock()` no `finally`; em Go, `mu.Lock()` seguido de `defer mu.Unlock()`; em C++, `std::lock_guard` ou `std::scoped_lock` (RAII).

<CodeTabs>

```python
import threading

class Estoque:
    def __init__(self):
        self._itens = {}
        self._lock = threading.Lock()

    def adicionar(self, produto, qtd):
        with self._lock:
            self._itens[produto] = self._itens.get(produto, 0) + qtd

    def retirar(self, produto, qtd):
        with self._lock:
            atual = self._itens.get(produto, 0)
            if qtd > atual:
                raise ValueError(f"estoque insuficiente de {produto}")
            self._itens[produto] = atual - qtd

    def snapshot(self):
        with self._lock:
            return dict(sorted(self._itens.items()))

estoque = Estoque()

def repor(produto):
    for _ in range(1000):
        estoque.adicionar(produto, 2)

threads = [threading.Thread(target=repor, args=(p,)) for p in ["caneta", "lapis", "caneta"]]
for t in threads:
    t.start()
for t in threads:
    t.join()

try:
    estoque.retirar("lapis", 5000)
except ValueError as e:
    print("erro:", e)

estoque.retirar("caneta", 1000)  # o lock foi liberado mesmo após a exceção
print(estoque.snapshot())
```

```java
import java.util.*;
import java.util.concurrent.locks.ReentrantLock;

static class Estoque {
    private final Map<String, Integer> itens = new HashMap<>();
    private final ReentrantLock lock = new ReentrantLock();

    void adicionar(String produto, int qtd) {
        lock.lock();
        try {
            itens.put(produto, itens.getOrDefault(produto, 0) + qtd);
        } finally {
            lock.unlock();
        }
    }

    void retirar(String produto, int qtd) {
        lock.lock();
        try {
            int atual = itens.getOrDefault(produto, 0);
            if (qtd > atual) {
                throw new IllegalArgumentException("estoque insuficiente de " + produto);
            }
            itens.put(produto, atual - qtd);
        } finally {
            lock.unlock();   // roda também quando a exceção é lançada
        }
    }

    Map<String, Integer> snapshot() {
        lock.lock();
        try {
            return new TreeMap<>(itens);
        } finally {
            lock.unlock();
        }
    }
}

static final Estoque estoque = new Estoque();

static void repor(String produto) {
    for (int i = 0; i < 1000; i++) {
        estoque.adicionar(produto, 2);
    }
}

public static void main(String[] args) throws InterruptedException {
    List<Thread> threads = new ArrayList<>();
    for (String p : List.of("caneta", "lapis", "caneta")) {
        threads.add(new Thread(() -> repor(p)));
    }
    for (Thread t : threads) t.start();
    for (Thread t : threads) t.join();

    try {
        estoque.retirar("lapis", 5000);
    } catch (IllegalArgumentException e) {
        System.out.println("erro: " + e.getMessage());
    }

    estoque.retirar("caneta", 1000);  // o lock foi liberado mesmo após a exceção
    System.out.println(estoque.snapshot());
}
```

```cpp
#include <iostream>
#include <map>
#include <mutex>
#include <stdexcept>
#include <string>
#include <thread>
#include <vector>

class Estoque {
    std::map<std::string, int> itens;
    std::mutex trava;

public:
    void adicionar(const std::string& produto, int qtd) {
        std::lock_guard<std::mutex> guarda(trava);
        itens[produto] += qtd;
    }

    void retirar(const std::string& produto, int qtd) {
        std::lock_guard<std::mutex> guarda(trava);  // RAII: o destrutor libera, mesmo com exceção
        int atual = itens.count(produto) ? itens[produto] : 0;
        if (qtd > atual) {
            throw std::invalid_argument("estoque insuficiente de " + produto);
        }
        itens[produto] = atual - qtd;
    }

    std::map<std::string, int> snapshot() {
        std::lock_guard<std::mutex> guarda(trava);
        return itens;
    }
};

Estoque estoque;

void repor(const std::string& produto) {
    for (int i = 0; i < 1000; i++) {
        estoque.adicionar(produto, 2);
    }
}

int main() {
    std::vector<std::thread> threads;
    for (const std::string p : {"caneta", "lapis", "caneta"}) {
        threads.emplace_back(repor, p);
    }
    for (auto& t : threads) t.join();

    try {
        estoque.retirar("lapis", 5000);
    } catch (const std::invalid_argument& e) {
        std::cout << "erro: " << e.what() << std::endl;
    }

    estoque.retirar("caneta", 1000);  // o lock foi liberado mesmo após a exceção
    std::cout << "{";
    bool primeiro = true;
    for (const auto& [produto, qtd] : estoque.snapshot()) {
        std::cout << (primeiro ? "" : ", ") << produto << ": " << qtd;
        primeiro = false;
    }
    std::cout << "}" << std::endl;
}
```

```csharp
using System;
using System.Collections.Generic;
using System.Threading;

class Estoque
{
    private readonly Dictionary<string, int> _itens = new Dictionary<string, int>();
    private readonly object _lock = new object();

    private int Atual(string produto)
    {
        int atual;
        return _itens.TryGetValue(produto, out atual) ? atual : 0;
    }

    public void Adicionar(string produto, int qtd)
    {
        lock (_lock)
        {
            _itens[produto] = Atual(produto) + qtd;
        }
    }

    public void Retirar(string produto, int qtd)
    {
        lock (_lock)    // o lock é liberado na saída do bloco, mesmo com exceção
        {
            int atual = Atual(produto);
            if (qtd > atual)
            {
                throw new ArgumentException("estoque insuficiente de " + produto);
            }
            _itens[produto] = atual - qtd;
        }
    }

    public SortedDictionary<string, int> Snapshot()
    {
        lock (_lock)
        {
            return new SortedDictionary<string, int>(_itens);
        }
    }
}

static readonly Estoque estoque = new Estoque();

static void Repor(string produto)
{
    for (int i = 0; i < 1000; i++)
    {
        estoque.Adicionar(produto, 2);
    }
}

static void Main()
{
    var threads = new List<Thread>();
    foreach (string p in new[] { "caneta", "lapis", "caneta" })
    {
        threads.Add(new Thread(() => Repor(p)));
    }
    foreach (var t in threads) t.Start();
    foreach (var t in threads) t.Join();

    try
    {
        estoque.Retirar("lapis", 5000);
    }
    catch (ArgumentException e)
    {
        Console.WriteLine("erro: " + e.Message);
    }

    estoque.Retirar("caneta", 1000);  // o lock foi liberado mesmo após a exceção
    var pares = new List<string>();
    foreach (var par in estoque.Snapshot()) pares.Add(par.Key + ": " + par.Value);
    Console.WriteLine("{" + string.Join(", ", pares) + "}");
}
```

```go
import (
	"fmt"
	"sync"
)

type Estoque struct {
	itens map[string]int
	lock  sync.Mutex
}

func (e *Estoque) Adicionar(produto string, qtd int) {
	e.lock.Lock()
	defer e.lock.Unlock()
	e.itens[produto] += qtd
}

// Go não tem exceção: o erro volta como valor, e o defer libera o lock em qualquer saída
func (e *Estoque) Retirar(produto string, qtd int) error {
	e.lock.Lock()
	defer e.lock.Unlock()
	atual := e.itens[produto]
	if qtd > atual {
		return fmt.Errorf("estoque insuficiente de %s", produto)
	}
	e.itens[produto] = atual - qtd
	return nil
}

func (e *Estoque) Snapshot() map[string]int {
	e.lock.Lock()
	defer e.lock.Unlock()
	copia := make(map[string]int, len(e.itens))
	for produto, qtd := range e.itens {
		copia[produto] = qtd
	}
	return copia
}

func main() {
	estoque := &Estoque{itens: map[string]int{}}

	repor := func(produto string, wg *sync.WaitGroup) {
		defer wg.Done()
		for i := 0; i < 1000; i++ {
			estoque.Adicionar(produto, 2)
		}
	}

	var wg sync.WaitGroup
	for _, p := range []string{"caneta", "lapis", "caneta"} {
		wg.Add(1)
		go repor(p, &wg)
	}
	wg.Wait()

	if err := estoque.Retirar("lapis", 5000); err != nil {
		fmt.Println("erro:", err)
	}

	estoque.Retirar("caneta", 1000) // o lock foi liberado mesmo após o erro
	fmt.Println(estoque.Snapshot()) // fmt imprime o map em ordem de chave
}
```

</CodeTabs>

```text
Saída:
erro: estoque insuficiente de lapis
{'caneta': 3000, 'lapis': 2000}
```

Se o lock não fosse liberado no caminho da exceção, a chamada seguinte a `retirar` travaria para sempre. O `with` elimina essa classe de bug.

## Tentar sem bloquear

Às vezes você não quer esperar indefinidamente. Locks oferecem tentativa não bloqueante e espera com prazo: `tryLock()` em Java, `TryLock()` em Go, `try_lock()` em C++. Em Python:

<CodeTabs>

```python
import threading

lock = threading.Lock()
lock.acquire()  # simulando que alguém já está com o lock

print("tentativa sem bloquear:", lock.acquire(blocking=False))
print("tentativa com prazo de 0.1 s:", lock.acquire(timeout=0.1))

lock.release()
print("depois de liberar:", lock.acquire(blocking=False))
lock.release()
print("travado agora?", lock.locked())
```

```java
import java.util.concurrent.CountDownLatch;
import java.util.concurrent.TimeUnit;
import java.util.concurrent.locks.ReentrantLock;

public static void main(String[] args) throws InterruptedException {
    ReentrantLock lock = new ReentrantLock();
    CountDownLatch pegou = new CountDownLatch(1);
    CountDownLatch liberar = new CountDownLatch(1);

    // ReentrantLock é reentrante: se a própria main segurasse o lock, tryLock devolveria
    // true. Por isso o dono aqui é outra thread.
    Thread alguem = new Thread(() -> {
        lock.lock();
        try {
            pegou.countDown();
            liberar.await();
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        } finally {
            lock.unlock();
        }
    });
    alguem.start();
    pegou.await();

    System.out.println("tentativa sem bloquear: " + lock.tryLock());
    System.out.println("tentativa com prazo de 0.1 s: " + lock.tryLock(100, TimeUnit.MILLISECONDS));

    liberar.countDown();
    alguem.join();
    System.out.println("depois de liberar: " + lock.tryLock());
    lock.unlock();
    System.out.println("travado agora? " + lock.isLocked());
}
```

```cpp
#include <chrono>
#include <iostream>
#include <latch>
#include <mutex>
#include <thread>

int main() {
    std::timed_mutex lock;  // std::mutex tem try_lock, mas só timed_mutex aceita prazo
    std::latch pegou(1);
    std::latch liberar(1);

    // Chamar try_lock na thread que já é dona é comportamento indefinido em C++.
    // Por isso o dono aqui é outra thread.
    std::thread alguem([&] {
        lock.lock();
        pegou.count_down();
        liberar.wait();
        lock.unlock();
    });
    pegou.wait();

    std::cout << std::boolalpha;
    std::cout << "tentativa sem bloquear: " << lock.try_lock() << std::endl;
    std::cout << "tentativa com prazo de 0.1 s: " << lock.try_lock_for(std::chrono::milliseconds(100)) << std::endl;

    liberar.count_down();
    alguem.join();
    std::cout << "depois de liberar: " << lock.try_lock() << std::endl;
    lock.unlock();

    // não existe locked(): a única forma de consultar é tentar adquirir
    bool livre = lock.try_lock();
    if (livre) lock.unlock();
    std::cout << "travado agora? " << !livre << std::endl;
}
```

```csharp
using System;
using System.Threading;

static void Main()
{
    object trava = new object();
    var pegou = new ManualResetEventSlim(false);
    var liberar = new ManualResetEventSlim(false);

    // O Monitor é reentrante: se a própria Main segurasse o lock, TryEnter devolveria
    // true. Por isso o dono aqui é outra thread.
    Thread alguem = new Thread(() =>
    {
        lock (trava)
        {
            pegou.Set();
            liberar.Wait();
        }
    });
    alguem.Start();
    pegou.Wait();

    Console.WriteLine("tentativa sem bloquear: " + Monitor.TryEnter(trava));
    Console.WriteLine("tentativa com prazo de 0.1 s: " + Monitor.TryEnter(trava, 100));

    liberar.Set();
    alguem.Join();
    Console.WriteLine("depois de liberar: " + Monitor.TryEnter(trava));
    Monitor.Exit(trava);

    // Monitor não diz se outra thread está com o lock: a forma de consultar é tentar adquirir
    bool livre = Monitor.TryEnter(trava);
    if (livre) Monitor.Exit(trava);
    Console.WriteLine("travado agora? " + !livre);
}
```

```go
import (
	"fmt"
	"sync"
	"time"
)

// sync.Mutex só tem TryLock, sem prazo: a espera com prazo é um laço de tentativas
func tentarComPrazo(lock *sync.Mutex, prazo time.Duration) bool {
	limite := time.Now().Add(prazo)
	for time.Now().Before(limite) {
		if lock.TryLock() {
			return true
		}
		time.Sleep(time.Millisecond)
	}
	return false
}

func main() {
	var lock sync.Mutex
	lock.Lock() // simulando que alguém já está com o lock

	fmt.Println("tentativa sem bloquear:", lock.TryLock())
	fmt.Println("tentativa com prazo de 0.1 s:", tentarComPrazo(&lock, 100*time.Millisecond))

	lock.Unlock()
	fmt.Println("depois de liberar:", lock.TryLock())
	lock.Unlock()

	// não existe Locked(): a forma de consultar é tentar adquirir
	livre := lock.TryLock()
	if livre {
		lock.Unlock()
	}
	fmt.Println("travado agora?", !livre)
}
```

```text
Saída:
tentativa sem bloquear: False
tentativa com prazo de 0.1 s: False
depois de liberar: True
```

O prazo é útil para evitar deadlock (desistir, liberar o que tem e tentar de novo) e para dar resposta rápida ao usuário em vez de travar uma requisição.

## Granularidade e armadilhas

| Escolha | Vantagem | Custo |
| --- | --- | --- |
| Um lock global | Simples, difícil errar | Serializa tudo, vira gargalo |
| Lock por objeto ou por chave | Mais paralelismo | Mais locks para gerenciar, risco de deadlock |
| Lock striping (N locks por hash) | Bom meio-termo | Operações que tocam várias faixas ficam complexas |

- **Seção crítica longa demais.** Nada de I/O, rede ou chamadas a código desconhecido segurando um lock. Copie o que precisa, libere e só então faça o trabalho lento.
- **Esquecer de proteger a leitura.** Se a escrita usa lock e a leitura não, a leitura pode ver estado parcial.
- **Lock não reentrante.** Um `threading.Lock` adquirido duas vezes pela mesma thread trava ela mesma. Isso é assunto do próximo capítulo.
- **Vários locks em ordens diferentes** levam a deadlock. Defina uma ordem global de aquisição.

<Callout type="tip" title="Proteja invariantes, não variáveis">
Pense no lock como o guardião de uma regra (por exemplo, a soma de todas as contas é constante). Todo código que pode quebrar ou observar essa regra precisa estar sob o mesmo lock.
</Callout>

## Na entrevista

Ao usar um lock, diga explicitamente qual estado ele protege e qual invariante mantém. Mostre que a liberação é garantida (`with`, `finally`, `defer`, RAII) e mantenha a seção crítica curta. Follow-ups comuns: "qual a diferença entre mutex e semáforo binário?" (o mutex tem dono, só quem adquiriu libera; o semáforo não tem dono e serve para sinalização) e "como reduzir contenção?" (locks mais finos, striping, estruturas lock-free ou eliminar o compartilhamento).
