Uma família inteira de perguntas de entrevista tem o mesmo esqueleto: várias threads, cada uma responsável por imprimir um pedaço, e a saída precisa sair numa ordem exata. "Três threads chamam `primeiro`, `segundo` e `terceiro` em ordem aleatória; garanta que imprimam na ordem certa." "Duas threads alternam `ping` e `pong` n vezes." "Três threads imprimem 1, 2, 3, 1, 2, 3..." O entrevistador não quer saber se você decorou a resposta, e sim se escolhe a primitiva certa para expressar **quem pode rodar agora** e se evita espera ativa.

## O raciocínio

Toda solução responde a duas perguntas:

1. **Qual é o estado compartilhado** que diz de quem é a vez? Pode ser implícito (um sinal disparado) ou explícito (uma variável `vez`).
2. **Como uma thread espera** pela sua vez sem gastar CPU, e como avisa a próxima?

```text
 ordem fixa, uma vez só      alternância repetida        rodízio entre N threads
 T1 ─set(e1)─► T2            T_ping ─release(pong)─►     vez = 0, 1, 2, 0, 1...
 T2 ─set(e2)─► T3            T_pong ─release(ping)─►     cada thread espera
 Event / CountDownLatch      Semáforos em pingue-pongue  vez == meu_id (Condition)
```

| Cenário | Primitiva natural | Em Java | Em Go |
| --- | --- | --- | --- |
| Dependência única (A antes de B) | Evento / latch | `CountDownLatch(1)` | fechar um canal |
| Alternância entre 2 | Dois semáforos | `Semaphore` | dois canais sem buffer |
| Rodízio entre N | Lock + condição com `vez` | `ReentrantLock` + `Condition` | um canal por thread |

## Exemplo 1: ordem fixa com eventos

As threads são iniciadas na ordem inversa de propósito. Cada uma espera o evento da anterior antes de imprimir e então libera a seguinte. A saída é determinística porque a sincronização força a sequência, não a sorte do escalonador.

<CodeTabs>

```python
import threading

feito_1 = threading.Event()
feito_2 = threading.Event()

def primeiro():
    print("primeiro")
    feito_1.set()

def segundo():
    feito_1.wait()          # dorme até o primeiro terminar
    print("segundo")
    feito_2.set()

def terceiro():
    feito_2.wait()
    print("terceiro")

threads = [threading.Thread(target=f) for f in (terceiro, segundo, primeiro)]
for t in threads:
    t.start()
for t in threads:
    t.join()
```

```java
import java.util.*;
import java.util.concurrent.CountDownLatch;

static final CountDownLatch feito1 = new CountDownLatch(1);
static final CountDownLatch feito2 = new CountDownLatch(1);

static void primeiro() {
    System.out.println("primeiro");
    feito1.countDown();
}

static void segundo() {
    try {
        feito1.await();          // dorme até o primeiro terminar
        System.out.println("segundo");
        feito2.countDown();
    } catch (InterruptedException e) {
        Thread.currentThread().interrupt();
    }
}

static void terceiro() {
    try {
        feito2.await();
        System.out.println("terceiro");
    } catch (InterruptedException e) {
        Thread.currentThread().interrupt();
    }
}

public static void main(String[] args) throws InterruptedException {
    List<Thread> threads = List.of(new Thread(() -> terceiro()), new Thread(() -> segundo()), new Thread(() -> primeiro()));
    for (Thread t : threads) t.start();
    for (Thread t : threads) t.join();
}
```

```go
	"fmt"
	"sync"
)

	fmt.Println("primeiro")
	close(feito1)
}

	<-feito1 // dorme até o primeiro terminar

	close(feito2)
}

	<-feito2
	fmt.Println("terceiro")
}

	var wg sync.WaitGroup

		wg.Add(1)
		go func(f func()) {
			defer wg.Done()
			f()
		}(f)
	}
	wg.Wait()
}
```

## Exemplo 2: alternância com semáforos

Para alternar `ping` e `pong`, cada thread tem seu semáforo. O de `ping` começa com 1 (ele vai primeiro) e o de `pong` com 0. Cada thread adquire o seu, imprime e libera o da outra: é um bastão passado de mão em mão.

<CodeTabs>

```python
import threading

N = 3
vez_ping = threading.Semaphore(1)
vez_pong = threading.Semaphore(0)

def ping():
    for _ in range(N):
        vez_ping.acquire()
        print("ping")
        vez_pong.release()

def pong():
    for _ in range(N):
        vez_pong.acquire()
        print("pong")
        vez_ping.release()

a = threading.Thread(target=pong)
b = threading.Thread(target=ping)
a.start()
b.start()
a.join()
b.join()
```

```java
import java.util.concurrent.Semaphore;

static final int N = 3;
static final Semaphore vezPing = new Semaphore(1);
static final Semaphore vezPong = new Semaphore(0);

static void ping() {
    for (int i = 0; i < N; i++) {
        vezPing.acquireUninterruptibly();
        System.out.println("ping");
        vezPong.release();
    }
}

static void pong() {
    for (int i = 0; i < N; i++) {
        vezPong.acquireUninterruptibly();
        System.out.println("pong");
        vezPing.release();
    }
}

public static void main(String[] args) throws InterruptedException {
    Thread a = new Thread(() -> pong());
    Thread b = new Thread(() -> ping());
    a.start();
    b.start();
    a.join();
    b.join();
}
```

```go
import (
	"fmt"
	"sync"
)

const N = 3

// canal com capacidade 1 no papel do semáforo: enviar é release, receber é acquire.
// Sem o buffer, o último envio de pong ficaria preso, pois ninguém mais recebe.
var vezPing = make(chan struct{}, 1)
var vezPong = make(chan struct{}, 1)

func ping(wg *sync.WaitGroup) {
	defer wg.Done()
	for i := 0; i < N; i++ {
		<-vezPing
		fmt.Println("ping")
		vezPong <- struct{}{}
	}
}

func pong(wg *sync.WaitGroup) {
	defer wg.Done()
	for i := 0; i < N; i++ {
		<-vezPong
		fmt.Println("pong")
		vezPing <- struct{}{}
	}
}

func main() {
	vezPing <- struct{}{} // ping começa com a permissão; pong, sem nenhuma
	var wg sync.WaitGroup
	wg.Add(2)
	go pong(&wg)
	go ping(&wg)
	wg.Wait()
}
```

## Exemplo 3: rodízio entre N threads com Condition

Quando há mais de duas threads, uma variável `vez` protegida por uma `Condition` generaliza a ideia. Cada thread espera em laço até `vez` ser o seu índice, imprime, avança `vez` e acorda todas com `notify_all`, porque não há como acordar só a próxima numa condição compartilhada.

<CodeTabs>

```python
import threading

N_THREADS = 3
RODADAS = 2
cond = threading.Condition()
vez = 0

def trabalhador(meu_id):
    global vez
    for rodada in range(RODADAS):
        with cond:
            while vez != meu_id:        # sempre em laço: wakeups espúrios existem
                cond.wait()
            print(f"thread {meu_id + 1} (rodada {rodada + 1})")
            vez = (vez + 1) % N_THREADS
            cond.notify_all()

threads = [threading.Thread(target=trabalhador, args=(i,)) for i in reversed(range(N_THREADS))]
for t in threads:
    t.start()
for t in threads:
    t.join()
```

```java
import java.util.*;
import java.util.concurrent.locks.Condition;
import java.util.concurrent.locks.ReentrantLock;

static final int N_THREADS = 3;
static final int RODADAS = 2;
static final ReentrantLock trava = new ReentrantLock();
static final Condition cond = trava.newCondition();
static int vez = 0;

static void trabalhador(int meuId) {
    for (int rodada = 0; rodada < RODADAS; rodada++) {
        trava.lock();
        try {
            while (vez != meuId) {        // sempre em laço: wakeups espúrios existem
                cond.awaitUninterruptibly();
            }
            System.out.println("thread " + (meuId + 1) + " (rodada " + (rodada + 1) + ")");
            vez = (vez + 1) % N_THREADS;
            cond.signalAll();
        } finally {
            trava.unlock();
        }
    }
}

public static void main(String[] args) throws InterruptedException {
    List<Thread> threads = new ArrayList<>();
    for (int i = N_THREADS - 1; i >= 0; i--) {
        final int meuId = i;
        threads.add(new Thread(() -> trabalhador(meuId)));
    }
    for (Thread t : threads) t.start();
    for (Thread t : threads) t.join();
}
```

```csharp
using System;
using System.Collections.Generic;
using System.Threading;

const int N_THREADS = 3;
const int RODADAS = 2;
static readonly object cond = new object();
static int vez = 0;

static void Trabalhador(int meuId)

    {
        lock (cond)
        {
            while (vez != meuId)        // sempre em laço: PulseAll acorda todas, e só uma tem a vez

            Console.WriteLine("thread " + (meuId + 1) + " (rodada " + (rodada + 1) + ")");

            Monitor.PulseAll(cond);
        }
    }
}

static void Main()
{
    var threads = new List<Thread>();
    for (int i = N_THREADS - 1; i >= 0; i--)
    {
        int meuId = i;
        threads.Add(new Thread(() => Trabalhador(meuId)));
    }
    foreach (var t in threads) t.Start();
    foreach (var t in threads) t.Join();
}
```

```go
import (
	"fmt"
	"sync"
)

const N_THREADS = 3
const RODADAS = 2

var trava sync.Mutex
var cond = sync.NewCond(&trava)
var vez = 0

func trabalhador(meuId int, wg *sync.WaitGroup) {
	defer wg.Done()
	for rodada := 0; rodada < RODADAS; rodada++ {
		trava.Lock()
		for vez != meuId { // sempre em laço: Broadcast acorda todas, e só uma tem a vez
			cond.Wait()
		}
		fmt.Printf("thread %d (rodada %d)\n", meuId+1, rodada+1)
		vez = (vez + 1) % N_THREADS
		cond.Broadcast()
		trava.Unlock()
	}
}

func main() {
	var wg sync.WaitGroup
	for i := N_THREADS - 1; i >= 0; i-- {
		wg.Add(1)
		go trabalhador(i, &wg)
	}
	wg.Wait()
}
```

## Armadilhas

- **Espera ativa**: `while vez != meu_id: pass` funciona, mas queima CPU e, sem barreira de memória, pode nem enxergar a mudança em Java ou C++. Use primitivas que bloqueiam.
- **`if` em vez de `while`** em volta de `wait`: após acordar, a condição pode não valer mais (wakeup espúrio ou outra thread passou antes).
- **`notify` em vez de `notify_all`** numa condição compartilhada por N threads: você pode acordar a thread errada, que volta a dormir, e ninguém acorda a certa. Resultado: travamento.
- **`sleep` para ordenar**: dormir 100 ms "para dar tempo" não é sincronização; falha sob carga.
- **Estado inicial errado** dos semáforos causa deadlock imediato (os dois em 0) ou ordem errada (os dois em 1).

<Callout type="tip" title="Uma condição por thread">
Com `ReentrantLock` em Java você pode criar uma `Condition` por thread e chamar `signal` só na próxima, evitando acordar todas. Em Go, o equivalente é um canal por thread passando o bastão em anel.
</Callout>

## Na entrevista

Comece dizendo qual é o estado que define a vez e qual primitiva vai bloquear cada thread. Para dependência única, eventos ou latches; para alternância, semáforos; para rodízio, condição com variável `vez`. Escreva a versão com semáforos se for curta, e mencione por que evitou espera ativa e `sleep`. Follow-ups comuns: "e se forem N threads em vez de 2?" (generalize com `vez` e `notify_all`, ou um semáforo por thread em anel) e "como garantir que o programa termina?" (cada thread faz um número fixo de iterações e a última libera quem estiver esperando).
