title: Por que concorrência

Um programa sequencial faz uma coisa de cada vez: lê um arquivo, espera o disco responder, processa, chama uma API, espera a rede, processa de novo. Na maior parte desse tempo a CPU está parada, esperando. Concorrência é a técnica de estruturar o programa para que várias tarefas avancem no mesmo intervalo de tempo, aproveitando essas esperas e, quando há vários núcleos, executando trabalho de verdade em paralelo.

Em entrevista, esse tema aparece de duas formas: como pergunta conceitual ("por que usar threads aqui?") e como pano de fundo de problemas de design (um web crawler, um cache compartilhado, um rate limiter). Entender a motivação ajuda você a justificar cada decisão.

## Os dois motivos clássicos

**Esconder latência de I/O.** Uma requisição HTTP leva dezenas de milissegundos; um acesso a SSD, dezenas de microssegundos; uma instrução de CPU, menos de um nanossegundo. Enquanto uma tarefa espera a rede, outra pode usar o processador. Servidores web, crawlers e clientes de banco ganham muito com isso.

**Usar vários núcleos.** Uma máquina moderna tem 8, 16, 64 núcleos. Um programa de uma única thread usa só um. Para trabalho pesado de CPU (compressão, renderização, cálculo numérico), dividir o trabalho entre núcleos reduz o tempo total.

Há um terceiro motivo, menos lembrado: **responsividade**. Uma interface gráfica que faz um download na mesma thread que desenha a tela congela. Separar o trabalho lento mantém a interface viva.

```text
Sequencial (uma tarefa por vez, CPU ociosa durante a espera):
T1: [cpu][----espera rede----][cpu]
T2:                                [cpu][----espera rede----][cpu]

Concorrente (as esperas se sobrepõem):
T1: [cpu][----espera rede----][cpu]
T2:      [cpu][----espera rede----][cpu]
```

## Vendo o ganho em I/O

O programa abaixo simula quatro chamadas de rede com `time.sleep`. Rodando em threads, as esperas se sobrepõem e o tempo total fica perto do de uma chamada só, não da soma.

<CodeTabs>

```python
import threading
import time

def chamada_remota(i, resultados):
    time.sleep(0.2)  # simula espera de rede
    resultados[i] = f"resposta-{i}"

resultados = [None] * 4

inicio = time.perf_counter()
for i in range(4):
    chamada_remota(i, resultados)
sequencial = time.perf_counter() - inicio

resultados = [None] * 4
inicio = time.perf_counter()
threads = [threading.Thread(target=chamada_remota, args=(i, resultados)) for i in range(4)]
for t in threads:
    t.start()
for t in threads:
    t.join()
concorrente = time.perf_counter() - inicio

print(resultados)
print("sequencial levou pelo menos 0.8 s:", sequencial >= 0.8)
print("concorrente levou menos de 0.6 s:", concorrente < 0.6)
```

```java
import java.util.*;

static void chamadaRemota(int i, String[] resultados) {
    try {
        Thread.sleep(200);  // simula espera de rede
    } catch (InterruptedException e) {
        throw new RuntimeException(e);
    }
    resultados[i] = "resposta-" + i;
}

public static void main(String[] args) throws InterruptedException {
    String[] resultados = new String[4];

    long inicio = System.nanoTime();
    for (int i = 0; i < 4; i++) {
        chamadaRemota(i, resultados);
    }
    double sequencial = (System.nanoTime() - inicio) / 1e9;

    Arrays.fill(resultados, null);
    inicio = System.nanoTime();
    List<Thread> threads = new ArrayList<>();
    for (int i = 0; i < 4; i++) {
        int indice = i;
        threads.add(new Thread(() -> chamadaRemota(indice, resultados)));
    }
    for (Thread t : threads) t.start();
    for (Thread t : threads) t.join();
    double concorrente = (System.nanoTime() - inicio) / 1e9;

    System.out.println(Arrays.toString(resultados));
    System.out.println("sequencial levou pelo menos 0.8 s: " + (sequencial >= 0.8));
    System.out.println("concorrente levou menos de 0.6 s: " + (concorrente < 0.6));
}
```

```cpp
void chamada_remota(int i, std::vector<std::string>& resultados) {
```

```go
import (
	"fmt"
	"strconv"
	"sync"
	"time"

func chamadaRemota(i int, resultados []string) {

	}

	resultados = make([]string, 4)

	for i := 0; i < 4; i++ {

		go func(i int) {
			defer wg.Done()
			chamadaRemota(i, resultados)
		}(i)
	}
	wg.Wait()
	concorrente := time.Since(inicio).Seconds()

	fmt.Println(resultados)
	fmt.Println("sequencial levou pelo menos 0.8 s:", sequencial >= 0.8)
	fmt.Println("concorrente levou menos de 0.6 s:", concorrente < 0.6)
```

## Uma forma mais idiomática

Criar threads na mão é raro em código de produção. Normalmente você usa um pool, que reaproveita threads e devolve os resultados na ordem das entradas.

<CodeTabs>

```python
from concurrent.futures import ThreadPoolExecutor
import time

def buscar_preco(produto):
    time.sleep(0.1)  # simula consulta a um serviço externo
    precos = {"livro": 40, "caneta": 3, "mochila": 120}
    return produto, precos[produto]

produtos = ["livro", "caneta", "mochila"]
with ThreadPoolExecutor(max_workers=3) as pool:
    for produto, preco in pool.map(buscar_preco, produtos):
        print(f"{produto}: R$ {preco}")
```

```java
import java.util.*;
import java.util.concurrent.*;

static Map.Entry<String, Integer> buscarPreco(String produto) throws InterruptedException {
    Thread.sleep(100);  // simula consulta a um serviço externo
    Map<String, Integer> precos = Map.of("livro", 40, "caneta", 3, "mochila", 120);
    return Map.entry(produto, precos.get(produto));
}

public static void main(String[] args) throws Exception {
    List<String> produtos = List.of("livro", "caneta", "mochila");
    ExecutorService pool = Executors.newFixedThreadPool(3);
    List<Callable<Map.Entry<String, Integer>>> tarefas = new ArrayList<>();
    for (String produto : produtos) {
        tarefas.add(() -> buscarPreco(produto));
    }
    // invokeAll devolve os futuros na ordem das entradas
    for (Future<Map.Entry<String, Integer>> futuro : pool.invokeAll(tarefas)) {
        Map.Entry<String, Integer> item = futuro.get();
        System.out.println(item.getKey() + ": R$ " + item.getValue());
    }
    pool.shutdown();
}
```

```cpp
#include <chrono>
#include <future>
#include <iostream>
#include <map>
#include <string>
#include <thread>
#include <utility>
#include <vector>

std::pair<std::string, int> buscar_preco(const std::string& produto) {
    std::this_thread::sleep_for(std::chrono::milliseconds(100));  // simula consulta a um serviço externo
    const std::map<std::string, int> precos = {{"livro", 40}, {"caneta", 3}, {"mochila", 120}};
    return {produto, precos.at(produto)};
}

int main() {
    std::vector<std::string> produtos = {"livro", "caneta", "mochila"};
    // a biblioteca padrão não tem pool de threads; std::async com launch::async dispara uma thread por tarefa
    std::vector<std::future<std::pair<std::string, int>>> futuros;
    for (const auto& produto : produtos) {
        futuros.push_back(std::async(std::launch::async, buscar_preco, produto));
    }
    // percorrer os futuros na ordem de criação mantém a ordem das entradas
    for (auto& futuro : futuros) {
        auto [nome, preco] = futuro.get();
        std::cout << nome << ": R$ " << preco << std::endl;
    }
}
```

```csharp
using System;
using System.Collections.Generic;
using System.Threading;
using System.Threading.Tasks;

static KeyValuePair<string, int> BuscarPreco(string produto)
{
    Thread.Sleep(100);  // simula consulta a um serviço externo
    var precos = new Dictionary<string, int> { { "livro", 40 }, { "caneta", 3 }, { "mochila", 120 } };
    return new KeyValuePair<string, int>(produto, precos[produto]);
}

static void Main()
{
    string[] produtos = { "livro", "caneta", "mochila" };
    // Task.Run usa o pool de threads do runtime
    var tarefas = new List<Task<KeyValuePair<string, int>>>();
    foreach (string produto in produtos)
    {
        tarefas.Add(Task.Run(() => BuscarPreco(produto)));
    }
    // percorrer as tarefas na ordem de criação mantém a ordem das entradas
    foreach (var tarefa in tarefas)
    {
        var item = tarefa.Result;
        Console.WriteLine(item.Key + ": R$ " + item.Value);
    }
}
```

```go
import (
	"fmt"
	"sync"
	"time"
)

func buscarPreco(produto string) int {
	time.Sleep(100 * time.Millisecond) // simula consulta a um serviço externo
	precos := map[string]int{"livro": 40, "caneta": 3, "mochila": 120}
	return precos[produto]
}

func main() {
	produtos := []string{"livro", "caneta", "mochila"}
	// Go não tem pool na biblioteca padrão: goroutines são baratas e cada uma grava na sua posição
	precos := make([]int, len(produtos))
	var wg sync.WaitGroup
	for i, produto := range produtos {
		wg.Add(1)
		go func(i int, produto string) {
			defer wg.Done()
			precos[i] = buscarPreco(produto)
		}(i, produto)
	}
	wg.Wait()
	// lendo por índice depois do Wait, a saída fica na ordem das entradas
	for i, produto := range produtos {
		fmt.Printf("%s: R$ %d\n", produto, precos[i])
	}
}
```

## O custo

Concorrência não é de graça. Você troca simplicidade por desempenho e passa a lidar com:

- **Condições de corrida:** duas threads mexendo no mesmo dado sem coordenação produzem resultados errados e intermitentes.
- **Deadlocks:** threads esperando umas pelas outras para sempre.
- **Depuração difícil:** o bug aparece uma vez em mil execuções e some quando você adiciona um log.
- **Overhead:** criar threads, trocar de contexto e sincronizar custam tempo e memória. Para tarefas minúsculas, a versão sequencial pode ser mais rápida.

<Callout type="tip" title="Regra prática">
Pergunte primeiro onde o tempo é gasto. Se é esperando I/O, threads ou async ajudam. Se é CPU, você precisa de paralelismo real (processos, ou threads em linguagens sem GIL). Se é nenhum dos dois, concorrência só adiciona risco.
</Callout>

## Na entrevista

Quando o problema envolver muitas operações independentes de I/O (baixar páginas, consultar serviços), proponha concorrência e explique o motivo em uma frase: "as chamadas são limitadas por rede, então sobrepor as esperas reduz a latência total". Em seguida, diga como vai limitar o paralelismo (um pool de tamanho fixo) e como vai proteger estado compartilhado. Follow-ups comuns: "quantas threads você usaria?" (para I/O, mais que o número de núcleos; para CPU, perto do número de núcleos) e "o que muda se o trabalho for de CPU?".
