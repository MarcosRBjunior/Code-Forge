Cinco filósofos sentam em volta de uma mesa redonda. Entre cada par vizinho há um garfo, totalizando cinco. Para comer, cada um precisa dos dois garfos ao seu lado; depois de comer, devolve os dois e volta a pensar. O enunciado parece um passatempo, mas é um modelo compacto de qualquer sistema em que tarefas precisam de **vários recursos exclusivos ao mesmo tempo**: transferências que travam duas contas, jobs que reservam dois arquivos, transações que bloqueiam duas linhas. Por isso ele aparece tanto em entrevista: testa se você reconhece deadlock e sabe quebrá-lo.

## Onde a solução ingênua quebra

A ideia óbvia é "pegue o garfo da esquerda, depois o da direita". Se todos fizerem isso ao mesmo tempo, cada um segura um garfo e espera o vizinho soltar o outro, para sempre.

```text
        F0
    g4      g0          Fi pega g(i) (esquerda) e espera g(i+1) (direita)
  F4          F1        F0 tem g0, espera g1 (com F1)
    g3      g1          F1 tem g1, espera g2 (com F2)
     F3 g2 F2           ...
                        F4 tem g4, espera g0 (com F0)  -> ciclo
```

Estão presentes as quatro condições de Coffman: garfos são exclusivos, cada um **segura e espera**, ninguém tira o garfo de ninguém e há uma **espera circular**. Basta quebrar uma delas.

O programa abaixo força esse cenário de forma determinística: uma barreira garante que todos já pegaram o garfo da esquerda antes de tentar o da direita, e a tentativa usa timeout para o programa não travar de verdade.

<CodeTabs>

```python
import threading

N = 5
garfos = [threading.Lock() for _ in range(N)]
todos_com_esquerdo = threading.Barrier(N)
todos_tentaram = threading.Barrier(N)
conseguiu = [False] * N

def filosofo(i):
    esquerdo, direito = garfos[i], garfos[(i + 1) % N]
    with esquerdo:
        todos_com_esquerdo.wait()
        if direito.acquire(timeout=0.2):  # sem timeout, ficaria preso para sempre
            conseguiu[i] = True
            direito.release()
        todos_tentaram.wait()  # ninguém solta o esquerdo antes de todos tentarem

ts = [threading.Thread(target=filosofo, args=(i,)) for i in range(N)]
for t in ts:
    t.start()
for t in ts:
    t.join()

print("conseguiram os dois garfos:", sum(conseguiu))
print("deadlock: todos seguravam um garfo e esperavam o vizinho")
```

```java
import java.util.*;
import java.util.concurrent.BrokenBarrierException;
import java.util.concurrent.CyclicBarrier;
import java.util.concurrent.TimeUnit;
import java.util.concurrent.locks.ReentrantLock;

static final int N = 5;
static final ReentrantLock[] garfos = new ReentrantLock[N];
static final CyclicBarrier todosComEsquerdo = new CyclicBarrier(N);
static final CyclicBarrier todosTentaram = new CyclicBarrier(N);
static final boolean[] conseguiu = new boolean[N];

static void filosofo(int i) {
    ReentrantLock esquerdo = garfos[i], direito = garfos[(i + 1) % N];
    esquerdo.lock();
    try {
        todosComEsquerdo.await();
        if (direito.tryLock(200, TimeUnit.MILLISECONDS)) {  // sem timeout, ficaria preso para sempre
            conseguiu[i] = true;
            direito.unlock();
        }
        todosTentaram.await();  // ninguém solta o esquerdo antes de todos tentarem
    } catch (InterruptedException | BrokenBarrierException e) {
        Thread.currentThread().interrupt();
    } finally {
        esquerdo.unlock();
    }
}

public static void main(String[] args) throws InterruptedException {
    for (int i = 0; i < N; i++) garfos[i] = new ReentrantLock();
    List<Thread> ts = new ArrayList<>();
    for (int i = 0; i < N; i++) {
        final int id = i;
        ts.add(new Thread(() -> filosofo(id)));
    }
    for (Thread t : ts) t.start();
    for (Thread t : ts) t.join();

    int soma = 0;
    for (boolean c : conseguiu) if (c) soma++;
    System.out.println("conseguiram os dois garfos: " + soma);
    System.out.println("deadlock: todos seguravam um garfo e esperavam o vizinho");
}
```

```go
import (
	"fmt"
	"sync"
	"time"
)

const N = 5

// O sync.Mutex só tem TryLock imediato, sem prazo. Por isso cada garfo é um canal de
// capacidade 1: enviar é pegar o lock, receber é soltar, e o select dá o timeout.
var garfos [N]chan struct{}

// Go não tem barreira pronta. Um WaitGroup de uso único faz o papel: cada um dá Done e espera os demais.
var todosComEsquerdo, todosTentaram sync.WaitGroup
var conseguiu [N]bool

func filosofo(i int, wg *sync.WaitGroup) {
	defer wg.Done()
	esquerdo, direito := garfos[i], garfos[(i+1)%N]
	esquerdo <- struct{}{}
	defer func() { <-esquerdo }()
	todosComEsquerdo.Done()
	todosComEsquerdo.Wait()
	select {
	case direito <- struct{}{}:
		conseguiu[i] = true
		<-direito
	case <-time.After(200 * time.Millisecond): // sem timeout, ficaria preso para sempre
	}
	todosTentaram.Done() // ninguém solta o esquerdo antes de todos tentarem
	todosTentaram.Wait()
}

func main() {
	for i := range garfos {
		garfos[i] = make(chan struct{}, 1)
	}
	todosComEsquerdo.Add(N)
	todosTentaram.Add(N)
	var wg sync.WaitGroup
	for i := 0; i < N; i++ {
		wg.Add(1)
		go filosofo(i, &wg)
	}
	wg.Wait()

	soma := 0
	for _, c := range conseguiu {
		if c {
			soma++
		}
	}
	fmt.Println("conseguiram os dois garfos:", soma)
	fmt.Println("deadlock: todos seguravam um garfo e esperavam o vizinho")
}
```

## Três formas de resolver

**1. Ordem global dos recursos.** Numere os garfos e exija que todo mundo pegue primeiro o de menor número. O filósofo 4 precisa de g4 e g0, então pega g0 antes. Agora é impossível formar um ciclo, porque toda espera vai de um número menor para um maior. É a solução mais usada na prática: em Java ou Go, ordenar locks por id antes de adquiri-los é o mesmo truque.

**2. Garçom (limitar a concorrência).** Um semáforo com N menos 1 permissões deixa no máximo quatro filósofos tentarem comer ao mesmo tempo. Com cinco garfos e quatro pessoas, pelo princípio da casa dos pombos ao menos uma consegue os dois.

**3. Tentar e desistir.** Pegue o primeiro, tente o segundo com `acquire(timeout=...)` ou `tryLock`; se falhar, solte o primeiro e tente de novo depois. Isso quebra o "segurar e esperar", mas pode gerar **livelock** se todos desistirem e tentarem no mesmo ritmo, então use espera aleatória.

<CodeTabs>

```python
import threading

N = 5
REFEICOES = 3
garfos = [threading.Lock() for _ in range(N)]
garcom = threading.Semaphore(N - 1)
comeu = [0] * N

def filosofo_ordenado(i):
    a, b = i, (i + 1) % N
    primeiro, segundo = garfos[min(a, b)], garfos[max(a, b)]
    for _ in range(REFEICOES):
        with primeiro:
            with segundo:
                comeu[i] += 1

def filosofo_com_garcom(i):
    for _ in range(REFEICOES):
        with garcom:
            with garfos[i]:
                with garfos[(i + 1) % N]:
                    comeu[i] += 1

for estrategia in (filosofo_ordenado, filosofo_com_garcom):
    comeu = [0] * N
    ts = [threading.Thread(target=estrategia, args=(i,)) for i in range(N)]
    for t in ts:
        t.start()
    for t in ts:
        t.join()
    print(estrategia.__name__, "->", comeu)
```

```java
import java.util.*;
import java.util.concurrent.Semaphore;
import java.util.function.IntConsumer;

static final int N = 5;
static final int REFEICOES = 3;
static final Object[] garfos = new Object[N];
static final Semaphore garcom = new Semaphore(N - 1);
static int[] comeu = new int[N];

static void filosofoOrdenado(int i) {
    int a = i, b = (i + 1) % N;
    Object primeiro = garfos[Math.min(a, b)], segundo = garfos[Math.max(a, b)];
    for (int r = 0; r < REFEICOES; r++) {
        synchronized (primeiro) {
            synchronized (segundo) {
                comeu[i] += 1;
            }
        }
    }
}

static void filosofoComGarcom(int i) {
    for (int r = 0; r < REFEICOES; r++) {
        garcom.acquireUninterruptibly();
        try {
            synchronized (garfos[i]) {
                synchronized (garfos[(i + 1) % N]) {
                    comeu[i] += 1;
                }
            }
        } finally {
            garcom.release();
        }
    }
}

static void rodar(String nome, IntConsumer estrategia) throws InterruptedException {
    comeu = new int[N];
    List<Thread> ts = new ArrayList<>();
    for (int i = 0; i < N; i++) {
        final int id = i;
        ts.add(new Thread(() -> estrategia.accept(id)));
    }
    for (Thread t : ts) t.start();
    for (Thread t : ts) t.join();
    System.out.println(nome + " -> " + Arrays.toString(comeu));
}

public static void main(String[] args) throws InterruptedException {
    for (int i = 0; i < N; i++) garfos[i] = new Object();
    rodar("filosofo_ordenado", id -> filosofoOrdenado(id));
    rodar("filosofo_com_garcom", id -> filosofoComGarcom(id));
}
```

```go
import (
	"fmt"
	"sync"
)

const N = 5
const REFEICOES = 3

var garfos [N]sync.Mutex
var garcom = make(chan struct{}, N-1) // canal com N-1 lugares faz o papel do semáforo
var comeu [N]int

func filosofoOrdenado(i int) {
	a, b := i, (i+1)%N
	if a > b {
		a, b = b, a
	}
	primeiro, segundo := &garfos[a], &garfos[b]
	for r := 0; r < REFEICOES; r++ {
		primeiro.Lock()
		segundo.Lock()
		comeu[i] += 1
		segundo.Unlock()
		primeiro.Unlock()
	}
}

func filosofoComGarcom(i int) {
	for r := 0; r < REFEICOES; r++ {
		garcom <- struct{}{}
		garfos[i].Lock()
		garfos[(i+1)%N].Lock()
		comeu[i] += 1
		garfos[(i+1)%N].Unlock()
		garfos[i].Unlock()
		<-garcom
	}
}

func rodar(nome string, estrategia func(int)) {
	comeu = [N]int{}
	var wg sync.WaitGroup
	for i := 0; i < N; i++ {
		wg.Add(1)
		go func(id int) {
			defer wg.Done()
			estrategia(id)
		}(i)
	}
	wg.Wait()
	fmt.Println(nome, "->", comeu)
}

func main() {
	rodar("filosofo_ordenado", filosofoOrdenado)
	rodar("filosofo_com_garcom", filosofoComGarcom)
}
```

## Trade-offs

| Estratégia | Quebra qual condição | Custo |
| --- | --- | --- |
| Ordem global | Espera circular | Exige conhecer todos os recursos antes; pode ser injusta |
| Garçom | Espera circular (limita participantes) | Reduz paralelismo; o semáforo é um ponto central |
| Tentar e soltar | Segurar e esperar | Trabalho desperdiçado e risco de livelock |
| Árbitro único (um lock para a mesa) | Tudo | Correto, mas serializa: só um come por vez |

Evitar deadlock não garante justiça. Na solução por ordem, um filósofo pode perder repetidamente a disputa e passar fome (**starvation**). Se a pergunta exigir justiça, fale em filas de espera, locks justos (`ReentrantLock(true)` em Java) ou na solução de Chandy-Misra, em que garfos "sujos" são passados ao vizinho que pede.

## Na entrevista

Desenhe a mesa, mostre o ciclo e nomeie as condições de Coffman. Depois proponha a ordenação de recursos como solução principal, porque é simples e se generaliza para qualquer código com múltiplos locks. Mencione o garçom como alternativa e o timeout como último recurso. Follow-ups comuns: "sua solução evita starvation?" (não necessariamente; explique como torná-la justa) e "como isso aparece num sistema real?" (transferência bancária entre duas contas: sempre trave a conta de menor id primeiro).
