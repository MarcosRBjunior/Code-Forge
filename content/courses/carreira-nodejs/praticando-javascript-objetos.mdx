Um usuário tem nome, e-mail e data de cadastro. Um pedido tem cliente, itens e status. Guardar cada informação numa variável solta não escala: você precisa agrupar o que pertence à mesma coisa. Objetos fazem isso, e são também o formato do JSON, a língua que APIs, bancos como o MongoDB e arquivos de configuração usam para trocar dados. Dominar objetos é, na prática, dominar o formato de tudo o que entra e sai de um back-end.

**Você vai aprender:**

- Criar objetos, ler e alterar propriedades com ponto e colchetes
- Percorrer objetos com `Object.keys`, `Object.values` e `Object.entries`
- Desestruturação, spread e como copiar sem alterar o original
- Referência versus valor: por que alterar um objeto afeta "outro"
- Converter objetos para JSON e de volta

## Criando e acessando

Um objeto é um conjunto de pares **chave: valor** entre chaves.

```javascript
const usuario = {
  nome: "Ana Souza",
  email: "ana@exemplo.com",
  idade: 29,
  ativo: true,
  endereco: {
    cidade: "Recife",
    uf: "PE",
  },
  papeis: ["leitor", "editor"],
};

console.log(usuario.nome);            // Ana Souza
console.log(usuario.endereco.cidade); // Recife
console.log(usuario.papeis[1]);       // editor
console.log(usuario.telefone);        // undefined
```

Os valores podem ser de qualquer tipo, inclusive outros objetos e arrays. Ler uma propriedade que não existe devolve `undefined`, sem erro. O erro só aparece se você tentar ir um nível além de algo que não existe: `usuario.telefone.ddd` lança `TypeError`. Para isso existe o `?.` que você viu em condicionais: `usuario.telefone?.ddd`.

### Ponto ou colchetes

A notação de ponto é a mais comum. Use colchetes quando o nome da chave está numa variável ou tem caracteres especiais:

```javascript
const campo = "email";
console.log(usuario[campo]);   // ana@exemplo.com

const headers = { "content-type": "application/json" };
console.log(headers["content-type"]); // application/json
```

Colchetes são o que permite escrever código genérico, que funciona com qualquer campo: ordenar por um campo escolhido pelo cliente da API, validar uma lista de campos obrigatórios, e assim por diante.

## Alterando, adicionando e removendo

```javascript
const produto = { nome: "Caneca", preco: 35 };

produto.preco = 39.9;        // altera
produto.estoque = 12;        // adiciona
delete produto.estoque;      // remove

console.log(produto);        // { nome: 'Caneca', preco: 39.9 }
console.log("preco" in produto);       // true
console.log(Object.hasOwn(produto, "cor")); // false
```

Para saber se uma chave existe, use `Object.hasOwn(objeto, chave)` ou o operador `in`. Testar `if (produto.estoque)` falha quando o estoque é `0`, pela regra de falsy.

## Atalhos de escrita

Quando a variável tem o mesmo nome da chave, escreva só uma vez (shorthand). Chaves calculadas vão entre colchetes:

```javascript
const nome = "Bia";
const email = "bia@exemplo.com";

const novo = { nome, email };       // o mesmo que { nome: nome, email: email }
console.log(novo);

const campo = "cidade";
const filtro = { [campo]: "Natal" }; // { cidade: 'Natal' }
console.log(filtro);
```

Objetos também podem ter funções, chamadas de **métodos**:

```javascript
const carrinho = {
  itens: [
    { nome: "Livro", preco: 50, qtd: 2 },
    { nome: "Marcador", preco: 5, qtd: 3 },
  ],
  total() {
    return this.itens.reduce((s, i) => s + i.preco * i.qtd, 0);
  },
};

console.log(carrinho.total()); // 115
```

Dentro do método, `this` é o objeto antes do ponto na chamada (aqui, `carrinho`). É por isso que métodos são escritos com a sintaxe curta `total() {}`, e não como arrow function: a arrow não tem `this` próprio.

## Percorrendo objetos

Três funções transformam um objeto em array, e a partir daí você usa tudo o que aprendeu sobre arrays:

```javascript
const estoque = { caneca: 12, camiseta: 0, adesivo: 150 };

console.log(Object.keys(estoque));    // [ 'caneca', 'camiseta', 'adesivo' ]
console.log(Object.values(estoque));  // [ 12, 0, 150 ]
console.log(Object.entries(estoque));
// [ [ 'caneca', 12 ], [ 'camiseta', 0 ], [ 'adesivo', 150 ] ]

for (const [item, quantidade] of Object.entries(estoque)) {
  console.log(`${item}: ${quantidade}`);
}

const totalDeItens = Object.values(estoque).reduce((s, n) => s + n, 0);
console.log(totalDeItens); // 162
```

E `Object.fromEntries` faz o caminho de volta, de array de pares para objeto. Juntos, eles permitem "mapear" e "filtrar" objetos:

```javascript
const esgotados = Object.fromEntries(
  Object.entries(estoque).filter(([, qtd]) => qtd === 0)
);
console.log(esgotados); // { camiseta: 0 }

const precos = { caneca: 35, camiseta: 80 };
const comDesconto = Object.fromEntries(
  Object.entries(precos).map(([item, preco]) => [item, preco * 0.9])
);
console.log(comDesconto); // { caneca: 31.5, camiseta: 72 }
```

## Desestruturação

Extrai propriedades para variáveis, com renomeação e valor padrão:

```javascript
const pedido = {
  id: 501,
  cliente: { nome: "Carlos", email: "carlos@exemplo.com" },
  status: "pago",
};

const { id, status, cupom = "nenhum" } = pedido;
console.log(id, status, cupom); // 501 pago nenhum

const { cliente: { nome: nomeCliente } } = pedido;
console.log(nomeCliente); // Carlos

// separar um campo do resto
const usuarioDoBanco = { id: 1, nome: "Ana", senhaHash: "x9$k..." };
const { senhaHash, ...usuarioPublico } = usuarioDoBanco;
console.log(usuarioPublico); // { id: 1, nome: 'Ana' }
```

O último padrão é muito usado em APIs: tirar campos sensíveis antes de mandar o objeto na resposta. No Express, você vai escrever `const { nome, email } = req.body` em quase toda rota.

## Spread: combinando e copiando

O spread (`...`) espalha as propriedades de um objeto dentro de outro. Se a mesma chave aparece duas vezes, vale a última:

```javascript
const padrao = { porta: 3000, log: true, ambiente: "dev" };
const doUsuario = { porta: 8080 };

const config = { ...padrao, ...doUsuario };
console.log(config); // { porta: 8080, log: true, ambiente: 'dev' }

// atualizar sem alterar o original
const produto = { nome: "Caneca", preco: 35 };
const atualizado = { ...produto, preco: 39.9 };
console.log(produto.preco, atualizado.preco); // 35 39.9
```

Esse é exatamente o comportamento de um `PATCH` numa API: o objeto existente, sobrescrito apenas pelos campos enviados.

## Referência: o detalhe que mais gera bug

Números, strings e booleanos são copiados por **valor**. Objetos e arrays são guardados por **referência**: a variável aponta para o objeto, e atribuir a outra variável copia o apontamento, não o objeto.

```javascript
let a = 10;
let b = a;
b = 20;
console.log(a); // 10 (cópia independente)

const original = { nome: "Ana", tags: ["admin"] };
const mesmo = original;
mesmo.nome = "Bia";
console.log(original.nome); // Bia (é o mesmo objeto!)

console.log({ x: 1 } === { x: 1 }); // false: objetos diferentes
console.log(original === mesmo);    // true: mesma referência
```

O spread faz uma cópia **rasa**: o primeiro nível é novo, mas objetos e arrays internos continuam compartilhados.

```javascript
const copiaRasa = { ...original };
copiaRasa.nome = "Carla";
copiaRasa.tags.push("editor");

console.log(original.nome); // Bia (primeiro nível foi copiado)
console.log(original.tags); // [ 'admin', 'editor' ] (array interno compartilhado)

const copiaProfunda = structuredClone(original);
copiaProfunda.tags.push("financeiro");
console.log(original.tags); // [ 'admin', 'editor' ] (intacto)
```

`structuredClone` (disponível no Node 17+) copia todos os níveis. Use quando precisar de uma cópia realmente independente.

<Callout type="warning" title="Função que altera o objeto recebido">
Quando você passa um objeto para uma função, a função recebe a mesma referência. Se ela fizer `pedido.status = "cancelado"`, o objeto de quem chamou também muda. Em servidores, isso causa bugs difíceis: um objeto de configuração compartilhado entre requisições é alterado por uma delas e afeta todas as outras. Prefira devolver um novo objeto com spread em vez de alterar o recebido.
</Callout>

Comparar objetos com `===` compara referências, não conteúdo. Para saber se dois objetos têm os mesmos dados, compare campo a campo (ou, em testes, use `assert.deepEqual`).

## JSON: objetos em forma de texto

JSON (JavaScript Object Notation) é o formato de texto que representa objetos. Toda API REST que você vai construir recebe e devolve JSON.

```javascript
const livro = {
  titulo: "O Cortiço",
  autor: "Aluísio Azevedo",
  ano: 1890,
  disponivel: true,
  publicadoEm: new Date("1890-01-01"),
};

const texto = JSON.stringify(livro);
console.log(texto);
// {"titulo":"O Cortiço","autor":"Aluísio Azevedo","ano":1890,"disponivel":true,"publicadoEm":"1890-01-01T00:00:00.000Z"}

console.log(JSON.stringify(livro, null, 2)); // formatado com 2 espaços

const deVolta = JSON.parse(texto);
console.log(deVolta.titulo);            // O Cortiço
console.log(typeof deVolta.publicadoEm); // string (datas viram texto)
```

Regras do JSON que pegam desprevenido: chaves sempre entre aspas duplas, sem vírgula sobrando no fim, sem comentários. Funções e `undefined` são descartados no `stringify`, e datas viram string. `JSON.parse` lança `SyntaxError` se o texto for inválido, então trate o erro quando o texto vier de fora:

```javascript
function lerJsonSeguro(texto) {
  try {
    return JSON.parse(texto);
  } catch {
    return null;
  }
}

console.log(lerJsonSeguro('{"ok": true}')); // { ok: true }
console.log(lerJsonSeguro("{ok: true}"));   // null
```

## Juntando objetos e arrays

Na prática, você trabalha com arrays de objetos. Um padrão poderoso é transformar o array num objeto indexado pelo `id`, para buscar em tempo constante em vez de percorrer a lista toda:

```javascript
const usuarios = [
  { id: 10, nome: "Ana" },
  { id: 20, nome: "Bruno" },
];
const pedidos = [
  { id: 1, usuarioId: 20, total: 150 },
  { id: 2, usuarioId: 10, total: 80 },
  { id: 3, usuarioId: 20, total: 40 },
];

const usuarioPorId = Object.fromEntries(usuarios.map((u) => [u.id, u]));

const relatorio = pedidos.map((p) => ({
  pedido: p.id,
  cliente: usuarioPorId[p.usuarioId].nome,
  total: p.total,
}));
console.log(relatorio);
// [ { pedido: 1, cliente: 'Bruno', total: 150 }, ... ]
```

Isso é um "join" feito em memória, e é a mesma ideia que o banco usa quando você relaciona tabelas ou coleções.

## Na entrevista

- **Qual a diferença entre cópia rasa e profunda?** A rasa (spread, `Object.assign`) copia só o primeiro nível; objetos internos continuam compartilhados. A profunda (`structuredClone`) duplica todos os níveis.
- **Por que `{ a: 1 } === { a: 1 }` é `false`?** Objetos são comparados por referência; são dois objetos diferentes na memória, mesmo com o mesmo conteúdo.
- **O que `JSON.stringify` faz com funções, `undefined` e datas?** Descarta funções e `undefined` (em propriedades) e converte datas para string ISO; `JSON.parse` não as converte de volta.
- **Como verificar se uma propriedade existe?** `Object.hasOwn(obj, chave)` ou `chave in obj`. Testar o valor com `if` falha quando ele é falsy, como `0`.

## Pratique

Monte um pequeno "banco em memória" de livros em `livros.mjs`, com um array de objetos `{ id, titulo, autor, ano, tags }` e estas funções, todas sem alterar os objetos recebidos:

1. `criar(livros, dados)`: devolve um novo array com o livro adicionado e `id` gerado (maior id + 1).
2. `atualizar(livros, id, campos)`: devolve um novo array com o livro mesclado aos campos (como um `PATCH`); se o id não existir, lança `Error`.
3. `remover(livros, id)`: devolve um novo array sem o livro.
4. `contarPorAutor(livros)`: devolve um objeto `{ autor: quantidade }`.
5. `exportar(livros)` e `importar(texto)`: convertem de e para JSON.

Escreva testes com `node:test` que provem que o array original nunca muda. Esse módulo vira a primeira versão da API de livros do próximo nível.
