Nem todo dado cabe confortavelmente em tabelas. Um produto com atributos que variam por categoria, um perfil de usuário com preferências aninhadas, um evento de log com campos diferentes a cada versão do app: num banco relacional, isso vira dezenas de colunas opcionais ou várias tabelas com joins. Bancos NoSQL de documentos, como o MongoDB, guardam cada registro como um objeto parecido com JSON, no formato em que a aplicação já trabalha. Para quem escreve back-end em JavaScript, isso torna o MongoDB uma das escolhas mais comuns, e é por isso que ele aparece em tantas vagas de Node.js.

**Você vai aprender:**

- O que é NoSQL, os tipos principais e quando um banco de documentos faz sentido
- Como o MongoDB organiza dados em bancos, coleções e documentos BSON
- Fazer CRUD completo no `mongosh` com filtros, projeções e operadores de atualização
- Criar índices e conferir se uma consulta os usa
- Conectar uma API Node.js ao MongoDB com o driver oficial

## NoSQL em uma página

NoSQL é um guarda-chuva para bancos que não usam o modelo relacional de tabelas com joins. Não é "sem SQL" no sentido de pior ou melhor: são modelos diferentes, cada um otimizado para um tipo de acesso.

| Tipo | Como guarda | Exemplos | Bom para |
|---|---|---|---|
| Documentos | Objetos aninhados (JSON/BSON) | MongoDB, Couchbase | Entidades com estrutura variável, APIs |
| Chave-valor | Uma chave aponta para um valor | Redis, DynamoDB | Cache, sessões, contadores |
| Colunar largo | Linhas com colunas dinâmicas | Cassandra | Escrita massiva, séries temporais |
| Grafos | Nós e arestas | Neo4j | Relações complexas, recomendações |

O MongoDB troca algumas garantias do modelo relacional por flexibilidade: não há esquema obrigatório por padrão, e dados relacionados costumam ficar juntos no mesmo documento em vez de espalhados em tabelas. Em troca, você precisa pensar em como os dados serão lidos antes de decidir como guardá-los (assunto do próximo capítulo, sobre modelagem). Ele não é "melhor que SQL": dados muito relacionais, com muitas consultas cruzadas e regras de integridade fortes, ficam mais simples num PostgreSQL.

## Bancos, coleções e documentos

A hierarquia do MongoDB é: um servidor tem **bancos**, um banco tem **coleções** (o equivalente às tabelas) e uma coleção tem **documentos** (o equivalente às linhas). Um documento de livro:

```javascript
{
  _id: ObjectId("6735f1c2a1b2c3d4e5f60718"),
  titulo: "Dom Casmurro",
  autor: { nome: "Machado de Assis", nacionalidade: "brasileira" },
  categorias: ["romance", "clássico"],
  preco: Decimal128("39.90"),
  estoque: 12,
  publicadoEm: ISODate("1899-01-01T00:00:00Z"),
  avaliacoes: [
    { usuario: "ana", nota: 5 },
    { usuario: "bruno", nota: 4 }
  ]
}
```

Pontos importantes:

- Os documentos são guardados em **BSON**, um JSON binário com mais tipos: datas de verdade (`Date`), inteiros e decimais (`Decimal128`, para dinheiro), `ObjectId` e binário.
- Todo documento tem um `_id` único na coleção. Se você não informar, o driver gera um `ObjectId`: 12 bytes que incluem o horário de criação, por isso ids gerados depois tendem a ser maiores.
- Objetos aninhados e arrays são cidadãos de primeira classe: dá para filtrar, indexar e atualizar campos dentro deles.
- Cada documento pode ter no máximo 16 MB.

## Subindo o MongoDB e o mongosh

```bash
docker run --name mongo-livros -p 27017:27017 -d mongo:8
docker exec -it mongo-livros mongosh
```

O `mongosh` é o shell oficial, e ele é um ambiente JavaScript: você escreve objetos JS para filtros e pode usar variáveis e laços. Bancos e coleções são criados na primeira escrita, sem `CREATE`:

```javascript
use livraria            // muda para o banco (cria ao gravar)
show collections
db.livros.countDocuments()
```

## Create: inserindo documentos

```javascript
db.livros.insertOne({
  titulo: "Dom Casmurro",
  autor: { nome: "Machado de Assis" },
  categorias: ["romance", "clássico"],
  preco: 39.9,
  estoque: 12,
});

db.livros.insertMany([
  { titulo: "Memórias Póstumas de Brás Cubas", autor: { nome: "Machado de Assis" },
    categorias: ["romance", "clássico"], preco: 42.5, estoque: 8 },
  { titulo: "Sagarana", autor: { nome: "Guimarães Rosa" },
    categorias: ["contos"], preco: 54.9, estoque: 3 },
  { titulo: "Libertinagem", autor: { nome: "Manuel Bandeira" },
    categorias: ["poesia"], preco: 32, estoque: 0 },
  { titulo: "A Hora da Estrela", autor: { nome: "Clarice Lispector" },
    categorias: ["romance"], preco: 44.9, estoque: 7, paginas: 88 },
]);
```

Repare que só "A Hora da Estrela" tem `paginas`. Num banco de documentos isso é permitido: cada documento tem os campos que precisa. É uma vantagem e um risco, e a forma de controlar isso fica para o próximo capítulo.

## Read: consultando com find

`find` recebe um **filtro** (um objeto que descreve os documentos desejados) e, opcionalmente, uma **projeção** (quais campos devolver).

```javascript
// igualdade simples, inclusive em campo aninhado (com aspas e ponto)
db.livros.find({ "autor.nome": "Machado de Assis" });

// operadores de comparação começam com $
db.livros.find({ preco: { $gte: 35, $lte: 45 } });
db.livros.find({ estoque: { $gt: 0 }, categorias: "romance" });  // AND implícito

// OR explícito e "está em uma lista"
db.livros.find({ $or: [{ estoque: 0 }, { preco: { $gt: 50 } }] });
db.livros.find({ "autor.nome": { $in: ["Manuel Bandeira", "Guimarães Rosa"] } });

// campo existe? texto que começa com?
db.livros.find({ paginas: { $exists: true } });
db.livros.find({ titulo: { $regex: "^Mem" } });

// projeção: 1 inclui, 0 exclui; _id vem por padrão
db.livros.find({ estoque: { $gt: 0 } }, { titulo: 1, preco: 1, _id: 0 })
  .sort({ preco: -1 })
  .limit(2);
```

Os operadores mais usados são `$eq`, `$ne`, `$gt`, `$gte`, `$lt`, `$lte`, `$in`, `$nin`, `$exists`, `$regex`, `$and`, `$or` e `$not`. Um detalhe que surpreende: filtrar um array por um valor (`categorias: "romance"`) encontra documentos em que o array **contém** esse valor. Para vários valores ao mesmo tempo, use `$all`; para condições no mesmo elemento de um array de objetos, use `$elemMatch`:

```javascript
db.livros.find({ categorias: { $all: ["romance", "clássico"] } });
db.livros.find({ avaliacoes: { $elemMatch: { usuario: "ana", nota: { $gte: 4 } } } });
```

`findOne` devolve um único documento (ou `null`), e `.sort`, `.skip` e `.limit` fazem ordenação e paginação, como `ORDER BY`, `OFFSET` e `LIMIT` no SQL.

## Update: operadores de atualização

`updateOne` e `updateMany` recebem um filtro e um documento com **operadores de atualização**. Sem operador, você estaria substituindo o documento inteiro (isso é o `replaceOne`).

```javascript
// $set altera ou cria campos; $inc soma
db.livros.updateOne(
  { titulo: "Libertinagem" },
  { $set: { preco: 34.9 }, $inc: { estoque: 10 } }
);

// $push acrescenta a um array; $addToSet só se ainda não existir
db.livros.updateOne(
  { titulo: "Dom Casmurro" },
  { $push: { avaliacoes: { usuario: "carla", nota: 5 } }, $addToSet: { categorias: "realismo" } }
);

// updateMany afeta todos que casam; $unset remove um campo
db.livros.updateMany({ estoque: 0 }, { $set: { disponivel: false } });
db.livros.updateMany({}, { $unset: { paginas: "" } });

// upsert: atualiza se existir, insere se não
db.livros.updateOne(
  { titulo: "Iracema" },
  { $set: { autor: { nome: "José de Alencar" }, preco: 29.9 }, $setOnInsert: { estoque: 0 } },
  { upsert: true }
);
```

Cada atualização num único documento é atômica: duas requisições que fazem `$inc` no mesmo estoque nunca perdem uma à outra. Isso permite a baixa de estoque segura sem transação, colocando a condição no filtro:

```javascript
db.livros.updateOne(
  { titulo: "Sagarana", estoque: { $gte: 1 } },
  { $inc: { estoque: -1 } }
);
// { matchedCount: 0 } significa que não havia estoque
```

## Delete

```javascript
db.livros.deleteOne({ titulo: "Iracema" });
db.livros.deleteMany({ disponivel: false });
```

Como no SQL, `deleteMany({})` com filtro vazio apaga **tudo**. Confira com `find` (ou `countDocuments`) usando o mesmo filtro antes.

## Índices

Sem índice, todo `find` lê a coleção inteira (um `COLLSCAN`). Índices no MongoDB são árvores B, como no PostgreSQL, e podem ser simples, compostos, em campos aninhados ou em arrays (o índice "multikey" indexa cada elemento).

```javascript
db.livros.createIndex({ "autor.nome": 1 });
db.livros.createIndex({ categorias: 1, preco: -1 });     // composto
db.livros.createIndex({ titulo: 1 }, { unique: true });  // impede repetição

db.livros.find({ "autor.nome": "Machado de Assis" }).explain("executionStats");
```

No resultado do `explain`, procure `IXSCAN` (usou índice) em vez de `COLLSCAN`, e compare `totalDocsExamined` com `nReturned`: num índice bom, os dois números ficam próximos.

## Agregação: o primeiro pipeline

Para relatórios, o MongoDB usa o **aggregation pipeline**: uma lista de estágios, em que a saída de cada um é a entrada do próximo.

```javascript
db.livros.aggregate([
  { $match: { estoque: { $gt: 0 } } },                 // como WHERE
  { $unwind: "$categorias" },                           // um documento por categoria
  { $group: {                                           // como GROUP BY
      _id: "$categorias",
      livros: { $sum: 1 },
      precoMedio: { $avg: "$preco" },
  } },
  { $sort: { livros: -1 } },
]);
```

`$match`, `$group`, `$sort`, `$project` (escolhe e calcula campos), `$unwind` (abre arrays), `$limit` e `$lookup` (junta com outra coleção) cobrem a maioria dos relatórios.

## MongoDB no Node.js

Com o driver oficial (`npm install mongodb`), o código fica muito parecido com o que você escreveu no `mongosh`:

```javascript
// db.js
import { MongoClient } from "mongodb";

const client = new MongoClient(process.env.MONGO_URL ?? "mongodb://localhost:27017");
await client.connect();
export const db = client.db("livraria");
export const livros = db.collection("livros");
```

```javascript
// app.js
import express from "express";
import { ObjectId } from "mongodb";
import { livros } from "./db.js";

const app = express();
app.use(express.json());

app.get("/livros", async (req, res) => {
  const filtro = {};
  if (req.query.categoria) filtro.categorias = String(req.query.categoria);
  if (req.query.precoMax) filtro.preco = { $lte: Number(req.query.precoMax) };
  const lista = await livros.find(filtro).sort({ titulo: 1 }).limit(20).toArray();
  res.json(lista);
});

app.get("/livros/:id", async (req, res) => {
  if (!ObjectId.isValid(req.params.id)) return res.status(400).json({ erro: "id inválido" });
  const livro = await livros.findOne({ _id: new ObjectId(req.params.id) });
  livro ? res.json(livro) : res.status(404).json({ erro: "não encontrado" });
});

app.post("/livros", async (req, res) => {
  const { titulo, autor, preco, estoque = 0 } = req.body;
  const { insertedId } = await livros.insertOne({ titulo, autor, preco, estoque, criadoEm: new Date() });
  res.status(201).json({ _id: insertedId });
});

app.listen(3000);
```

O `MongoClient` mantém um pool de conexões: crie **um** cliente na inicialização e reutilize, nunca um por requisição. Muitos projetos usam o Mongoose por cima do driver para ter esquemas e validação; o próximo capítulo usa os dois.

<Callout type="warning" title="O _id em string não encontra nada">
O erro mais comum de quem começa com MongoDB no Node.js: buscar `findOne({ _id: req.params.id })` com o id em texto. O `_id` está gravado como `ObjectId`, e uma string nunca é igual a um `ObjectId`, então a consulta devolve `null` sem erro e a API responde 404 para um livro que existe. Converta com `new ObjectId(id)` (validando antes com `ObjectId.isValid`). O Mongoose faz essa conversão sozinho, por isso o problema aparece quando você troca para o driver puro.
</Callout>

Outra armadilha relacionada ao filtro vindo do usuário: nunca passe `req.body` ou `req.query` direto como filtro. Um corpo como `{ "senha": { "$ne": "" } }` vira um operador e casa com qualquer documento. Monte o filtro campo a campo e converta os valores para o tipo esperado (`String`, `Number`), como na rota acima.

## Na entrevista

**Quando escolher MongoDB em vez de um banco relacional?** Quando os dados são naturalmente documentos com estrutura variável, lidos quase sempre inteiros, com poucas consultas cruzando entidades. Se há muitas relações e regras de integridade, um relacional costuma ser mais simples.

**O que é um ObjectId?** O identificador padrão do `_id`: 12 bytes com um timestamp, um valor aleatório por processo e um contador, o que permite gerar ids únicos sem consultar o banco.

**Uma atualização no MongoDB é atômica?** Sim, no nível de um documento, incluindo subdocumentos e arrays. Para várias coleções ou documentos ao mesmo tempo, existem transações multi-documento (que exigem replica set).

**Como saber se uma consulta usa índice?** Com `explain("executionStats")`: `IXSCAN` indica uso de índice, `COLLSCAN` indica varredura completa.

## Pratique

Crie a API de livros com MongoDB e o driver oficial. Entregue:

1. Rotas `GET /livros` (filtros por categoria, autor e faixa de preço, com paginação), `GET /livros/:id`, `POST /livros`, `PATCH /livros/:id` (usando `$set` só com os campos enviados) e `DELETE /livros/:id`.
2. A rota `POST /livros/:id/avaliacoes` que usa `$push` e a `POST /livros/:id/vender` com baixa de estoque condicional, respondendo 409 sem estoque.
3. Índices para os filtros da listagem, com a saída do `explain` mostrando `IXSCAN` em um README.
4. Um `GET /relatorios/categorias` com o pipeline de agregação deste capítulo.
