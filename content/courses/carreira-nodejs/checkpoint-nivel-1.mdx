## Desafio prático

A biblioteca de um bairro quer sair da planilha. Você vai entregar a **API da biblioteca**: a API de livros do nível, na versão Express 5 com Sequelize, agora completa. O catálogo é público, leitores pedem empréstimos, bibliotecários cadastram livros, e tudo precisa rodar com um comando, ter testes e documentação. Use o projeto que você construiu nos capítulos de ORM, testes e autenticação como ponto de partida, ou recomece do zero se ele ficou pela metade.

### Requisitos

1. **Domínio e banco.** Modelos `Autor`, `Livro`, `Leitor` e `Emprestimo` com as associações do capítulo de Sequelize, criados por migrações (nada de `sync` fora dos testes) e um seeder com ao menos 20 livros de 5 autores.
2. **Catálogo.** `GET /livros` com filtro por título (busca parcial), autor e faixa de preço, paginação com `pagina` e `limite` (teto de 50) e ordenação escolhida pelo cliente a partir de uma lista fixa de campos.
3. **Erros previsíveis.** Um único middleware de erros. Toda falha sai no mesmo formato JSON, com o status certo: 400 para entrada inválida, 404 para recurso inexistente, 409 para regra de negócio violada e 500 sem stack trace para o resto.
4. **Validação na fronteira.** Corpos de `POST` e `PUT` validados com Zod num middleware genérico. Campos desconhecidos são descartados, o que impede mass assignment.
5. **Empréstimos.** `POST /emprestimos` numa transação que confere estoque, limita a 3 empréstimos ativos por leitor, baixa o estoque com `decrement` e cria o registro. `POST /emprestimos/:id/devolver` faz o caminho inverso.
6. **Autenticação e permissões.** Rotas `/auth/cadastro`, `/auth/login`, `/auth/renovar` e `/auth/logout`, com senha em scrypt ou Argon2, token de acesso curto e refresh token guardado como hash. Perfis `leitor`, `bibliotecario` e `admin` com permissões no formato `recurso:acao`. Leitor só vê os próprios empréstimos.
7. **Segurança básica.** `helmet`, CORS restrito a uma origem configurável, limite de tamanho de corpo e rate limit no login.
8. **Documentação.** `openapi.yaml` com todas as rotas, o esquema de autenticação Bearer e as respostas de erro, servido em `/docs` e em `/openapi.json`.
9. **Testes e qualidade.** Testes unitários das regras de empréstimo com dependências falsas e testes de integração com Supertest em SQLite em memória. ESLint com a regra que proíbe `process.env` fora de `src/config`, Husky com lint-staged e commitlint.
10. **Ambiente.** `Dockerfile` com cache de camadas e usuário `node`, `compose.yaml` para desenvolvimento, `.env.example` documentado e um README que leva alguém do `git clone` à API rodando em três comandos.

Um esqueleto para o service de empréstimo, que recebe as dependências pelo construtor e por isso pode ser testado sem banco:

```javascript
// src/services/EmprestimoService.js
export class EmprestimoService {
  constructor({ sequelize, modelos, notificador, limiteAtivos = 3 }) {
    this.sequelize = sequelize;
    this.modelos = modelos;
    this.notificador = notificador;
    this.limiteAtivos = limiteAtivos;
  }

  async emprestar({ livroId, leitorId, devolverAte }) {
    // 1. abrir a transação
    // 2. buscar o livro com lock e conferir estoque
    // 3. contar empréstimos ativos do leitor
    // 4. decrement no estoque e create do empréstimo, os dois com { transaction: t }
    // 5. notificar só depois do commit
  }
}
```

### Critérios de aceite

- `npm test` passa do zero, sem banco externo, e cobre pelo menos: 401 sem token, 403 com perfil errado, 409 ao emprestar sem estoque e leitor sem acesso ao empréstimo de outro.
- `npm run lint` termina sem erros, e um commit com `process.env.PORT` num controller é barrado pelo gancho.
- `docker compose up` sobe a API, e `curl -i localhost:3000/livros?limite=500` devolve 200 com `limite` igual a 50 nos metadados.
- `curl -i localhost:3000/livros/999999` devolve 404 no formato padrão de erro, e `curl -i -X POST localhost:3000/livros -H 'content-type: application/json' -d '{'` devolve 400.
- Duas requisições simultâneas pelo último exemplar terminam com um 201 e um 409, e o estoque fica em zero, nunca negativo.
- Remover a variável `JWT_SECRET` do `.env` faz a API sair ao iniciar com uma mensagem que cita a variável.
- A página `/docs` lista todas as rotas, e o botão **Try it out** funciona numa rota protegida depois de informar o token.

### Dicas

- Comece pelo banco e pelos testes de integração das rotas públicas. Com a base testada, autenticação e empréstimos entram sem medo de quebrar o catálogo. O capítulo de [testes](/learn/carreira-nodejs/nodejs-implementando-testes-api) mostra como separar `app` de `server`.
- A transação de empréstimo é o ponto mais fácil de errar: reveja a seção de transações em [Avançando no Sequelize](/learn/carreira-nodejs/orm-nodejs-avancando-funcionalidades-sequelize). No SQLite o `lock` é ignorado, então o teste de concorrência depende de a transação serializar a escrita.
- Para RBAC, copie a estrutura de `src/middlewares/acesso.js` do [capítulo de autenticação](/learn/carreira-nodejs/nodejs-criando-api-rest-autenticacao-perfis-usuarios) e escreva os testes de 401 e 403 antes das rotas.
- Escolha um formato de erro e não mude no meio. O Problem Details do [capítulo de validações](/learn/carreira-nodejs/typescript-desenvolvendo-validacoes-tratando-erros) é uma boa opção, mesmo em JavaScript.
- Não deixe o README para o fim. Escrever os três comandos de setup cedo revela variáveis de ambiente que só existem na sua máquina.
- Bônus para quem quer ir além: emita um evento `emprestimo:criado` com Socket.IO para uma sala `bibliotecarios`, autenticando no handshake como no [segundo capítulo de WebSockets](/learn/carreira-nodejs/websockets-implemente-autenticacao-avance-socketio), ou reescreva o módulo de livros em Nest.js.

## Revisão rápida

**Express 5 encaminha Promises rejeitadas.** Um `throw` dentro de um handler `async` chega ao middleware de erros sem `try`/`catch`. O middleware de erros precisa ter quatro parâmetros e ser registrado depois das rotas.

```javascript
// src/app.js
app.use("/livros", livrosRouter);
app.use(manipulador404);
app.use(manipuladorDeErros); // (erro, req, res, next)
```

Duas armadilhas de rotas no mesmo arquivo: `/livros/busca` precisa vir antes de `/livros/:id`, senão o Express trata `busca` como um id; e no Express 5 `req.query` não pode ser reatribuído, então guarde a query normalizada em outra propriedade.

**Paginação sem teto e sem ordem não é paginação.** Sem `Math.min` no limite, um cliente pede um milhão de registros. Sem ordenação por um campo único, o mesmo registro aparece em duas páginas. Os metadados saem de uma contagem feita em paralelo com a busca.

```javascript
// src/utils/paginacao.js
export function calcularPaginacao({ pagina, limite }, maximo = 50) {
  const p = Math.max(1, Number.parseInt(pagina, 10) || 1);
  const l = Math.min(maximo, Math.max(1, Number.parseInt(limite, 10) || 10));
  return { limite: l, offset: (p - 1) * l, pagina: p };
}
```

**Toda consulta da transação recebe `transaction`.** Uma consulta sem a opção roda em outra conexão do pool, fora da transação, e o rollback não a desfaz. Use `decrement` para que o banco calcule o novo estoque.

**N+1 aparece quando você percorre uma lista e busca a relação item por item.** Cem livros viram 101 consultas. A correção é carregar a relação na mesma consulta: `include` no Sequelize, `populate` no Mongoose, `relations` ou `leftJoinAndSelect` no TypeORM.

**Tipos do TypeScript não existem em tempo de execução.** O corpo da requisição é `unknown` até passar por um schema. Com Zod, o schema valida e o tipo sai dele:

```typescript
// src/livros/schemas.ts
import { z } from "zod";
export const CriarLivro = z.object({
  titulo: z.string().min(1),
  preco: z.coerce.number().nonnegative(),
  autorId: z.number().int().positive(),
});
export type CriarLivro = z.infer<typeof CriarLivro>;
```

**Um JWT comum é assinado, não cifrado.** O payload é Base64URL e qualquer um lê. Nada sigiloso vai nele, e a validação precisa fixar o algoritmo aceito. Para decidir acesso, nunca use `jwt.decode`, que não verifica nada. E quando a validação falha a resposta é 401 (o servidor não sabe quem você é); 403 fica para quem foi identificado mas não tem permissão.

```javascript
// src/seguranca/tokens.js
import jwt from "jsonwebtoken";
import { config } from "../config/env.js";

export function validarToken(token) {
  return jwt.verify(token, config.JWT_SECRET, { algorithms: ["HS256"] });
}
```

**Senha usa função lenta, com salt e comparação em tempo constante.** SHA-256 é rápido demais: com o banco vazado, o atacante testa bilhões de senhas por segundo. Use scrypt (nativo do Node) ou Argon2id, guarde no formato `algoritmo$salt$hash` e compare com `timingSafeEqual`. Para o refresh token, que já é aleatório, SHA-256 basta.

**Cache automático por URL vaza dados por usuário.** O `CacheInterceptor` do Nest usa a URL como chave. Em rotas como `GET /me/emprestimos`, a primeira resposta seria servida para todo mundo até o TTL expirar.

<Callout type="warning" title="Migração, não sincronização">
`sequelize.sync()` e `synchronize: true` no TypeORM servem para testes e protótipos. Em qualquer banco com dados que importam, o esquema muda por migração versionada, revisada no pull request e aplicada igual em todos os ambientes. Um `sync` com `alter` pode remover uma coluna com dados sem pedir confirmação.
</Callout>

## Na entrevista

**Como você organiza uma API Express?** Em camadas: rotas declaram caminhos e middlewares, controllers traduzem HTTP, services guardam a regra de negócio e models ou repositórios falam com o banco. O `app` fica separado do `listen` para os testes importarem sem abrir porta.

**Como você testa uma rota que grava no banco?** Com Supertest sobre o `app`, um banco isolado (SQLite em memória ou um container só para testes), estado limpo antes de cada teste e asserções tanto na resposta quanto no que ficou gravado.

**Quando usar transação?** Quando várias escritas precisam acontecer juntas ou nenhuma, e quando uma leitura decide uma escrita sob concorrência, como conferir e baixar estoque.

**Como revogar um JWT antes de expirar?** O token em si não é revogável. Usa-se token de acesso de vida curta, refresh token guardado no servidor como hash e apagado no logout, e, se preciso, uma lista de `jti` revogados no Redis.

**Qual a diferença entre OAuth 2.0 e OpenID Connect?** OAuth 2.0 é autorização delegada: dá a uma aplicação acesso a recursos em nome de alguém. OpenID Connect acrescenta identidade, com o `id_token` dizendo quem a pessoa é.

**O que é IDOR e como você evita?** É acessar o recurso de outra pessoa trocando o id na URL. Evita-se conferindo posse ou permissão em toda rota, de preferência filtrando a consulta pelo usuário autenticado.

**Por que validar variáveis de ambiente na inicialização?** Para falhar rápido e com mensagem clara, em vez de quebrar horas depois na primeira requisição que usa a variável.

**Qual a diferença entre inversão e injeção de dependência?** Inversão é o princípio: o código de alto nível depende de abstrações. Injeção é a técnica: as dependências chegam de fora, pelo construtor, montadas numa raiz de composição.
