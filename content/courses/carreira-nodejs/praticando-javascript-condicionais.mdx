Um programa que só executa linhas em sequência sempre faz a mesma coisa. Condicionais deixam o código escolher um caminho: aprovar ou reprovar, cobrar frete ou não, responder 200 ou 404. Em back-end, quase toda regra de negócio e toda validação de entrada é uma condicional, então vale treinar até escrever `if` sem pensar.

**Você vai aprender:**

- `if`, `else if` e `else`, e como ordenar as condições
- Valores truthy e falsy, e por que eles importam
- Operador ternário, `switch` e objetos como tabela de decisão
- Retorno antecipado (guard clause) para evitar `if` aninhado
- Os operadores `??` e `?.` para lidar com valores ausentes

## if e else

A estrutura básica executa um bloco só quando a condição é verdadeira:

```javascript
const idade = 17;

if (idade >= 18) {
  console.log("Pode tirar a carteira de motorista");
} else {
  console.log(`Faltam ${18 - idade} ano(s)`);
}
```

```text
Saída:
Faltam 1 ano(s)
```

A condição entre parênteses é qualquer expressão que resulte em verdadeiro ou falso. O bloco entre chaves é o que roda. Sempre use as chaves, mesmo com uma linha só: sem elas, a segunda linha que alguém adicionar depois fica fora do `if` sem ninguém perceber.

## Várias faixas com else if

Quando há mais de dois caminhos, encadeie com `else if`. O JavaScript testa de cima para baixo e para na **primeira** condição verdadeira.

```javascript
function conceito(nota) {
  if (nota >= 9) {
    return "A";
  } else if (nota >= 7) {
    return "B";
  } else if (nota >= 5) {
    return "C";
  } else {
    return "D";
  }
}

console.log(conceito(9.5)); // A
console.log(conceito(7));   // B
console.log(conceito(4.9)); // D
```

A ordem importa. Se você testar `nota >= 5` primeiro, a nota 9.5 cai nessa faixa e recebe "C". Regra: em faixas, comece pela condição mais restrita.

### Exercício guiado: IMC

Calcular o índice de massa corporal e classificar é o clássico para treinar faixas.

```javascript
function classificarImc(peso, altura) {
  const imc = peso / (altura * altura);
  let faixa;

  if (imc < 18.5) {
    faixa = "abaixo do peso";
  } else if (imc < 25) {
    faixa = "peso normal";
  } else if (imc < 30) {
    faixa = "sobrepeso";
  } else {
    faixa = "obesidade";
  }

  return `IMC ${imc.toFixed(1)}: ${faixa}`;
}

console.log(classificarImc(70, 1.75)); // IMC 22.9: peso normal
console.log(classificarImc(95, 1.70)); // IMC 32.9: obesidade
```

Repare que o segundo teste é só `imc < 25`. Não precisa escrever `imc >= 18.5 && imc < 25`, porque se o código chegou ali, a primeira condição já foi falsa.

## Combinando condições

Use `&&` quando todas precisam ser verdadeiras e `||` quando basta uma:

```javascript
function podeAlugarCarro(idade, temCnh, anosDeCnh) {
  return idade >= 21 && temCnh && anosDeCnh >= 2;
}

function temDesconto(ehEstudante, idade) {
  return ehEstudante || idade >= 60;
}

console.log(podeAlugarCarro(25, true, 3)); // true
console.log(podeAlugarCarro(25, true, 1)); // false
console.log(temDesconto(false, 65));       // true
```

Os dois operadores fazem **curto-circuito**: em `a && b`, se `a` for falso, `b` nem é avaliado. Isso é útil para evitar erros, como em `usuario && usuario.nome`, que não tenta ler `nome` de algo que não existe.

Um caso clássico de lógica é o ano bissexto: divisível por 4, exceto os divisíveis por 100, a menos que também sejam divisíveis por 400.

```javascript
function ehBissexto(ano) {
  return (ano % 4 === 0 && ano % 100 !== 0) || ano % 400 === 0;
}

console.log(ehBissexto(2024)); // true
console.log(ehBissexto(1900)); // false
console.log(ehBissexto(2000)); // true
```

## Truthy e falsy

O `if` não exige um booleano. Qualquer valor é convertido para verdadeiro ou falso. São **falsy** (viram falso) apenas estes:

| Valor falsy | Tipo |
|---|---|
| `false` | boolean |
| `0` e `-0` | number |
| `""` (string vazia) | string |
| `null` | null |
| `undefined` | undefined |
| `NaN` | number |

Todo o resto é **truthy**, inclusive `"0"`, `"false"`, `[]` (array vazio) e `{}` (objeto vazio).

```javascript
const nome = "";
if (!nome) {
  console.log("Nome é obrigatório");
}

const itens = [];
if (itens) {
  console.log("Isso aparece, porque array vazio é truthy");
}
if (itens.length === 0) {
  console.log("O jeito certo de testar array vazio");
}
```

<Callout type="warning" title="Zero também é falsy">
`if (!quantidade)` trata `0` como "não informado". Num carrinho, quantidade zero é um valor válido e diferente de ausente. Quando zero ou string vazia forem valores legítimos, compare explicitamente com `quantidade === undefined`, que não é a mesma coisa que `!quantidade`. O mesmo vale para `||`: `quantidade || 1` troca o zero por 1; use `quantidade ?? 1`.
</Callout>

## Valores ausentes: ?? e ?.

O operador `??` (nullish coalescing) devolve o lado direito só quando o esquerdo é `null` ou `undefined`. Diferente do `||`, ele respeita `0` e `""`.

```javascript
const config = { porta: 0, nome: "" };

console.log(config.porta || 3000); // 3000 (errado: 0 foi descartado)
console.log(config.porta ?? 3000); // 0
console.log(config.timeout ?? 5000); // 5000
```

O operador `?.` (optional chaining) para a leitura se encontrar `null` ou `undefined`, devolvendo `undefined` em vez de lançar erro:

```javascript
const pedido = { cliente: { nome: "Ana" } };
const outro = {};

console.log(pedido.cliente?.nome);  // Ana
console.log(outro.cliente?.nome);   // undefined
// console.log(outro.cliente.nome); // TypeError: Cannot read properties of undefined
```

Em back-end você vai usar os dois o tempo todo, porque dados que chegam em requisições podem vir incompletos.

## Operador ternário

Para escolher entre dois valores numa expressão curta, use `condicao ? seVerdadeiro : seFalso`:

```javascript
const estoque = 0;
const status = estoque > 0 ? "disponível" : "esgotado";
console.log(status); // esgotado

const itens = 3;
console.log(`${itens} ${itens === 1 ? "item" : "itens"}`); // 3 itens
```

O ternário é ótimo para atribuir um valor. Não aninhe vários ternários: a partir de dois níveis, um `if` ou uma função fica mais legível.

## switch

Quando você compara a mesma variável com vários valores exatos, `switch` organiza melhor:

```javascript
function diasNoMes(mes, ano) {
  switch (mes) {
    case 2:
      return ehBissexto(ano) ? 29 : 28;
    case 4:
    case 6:
    case 9:
    case 11:
      return 30;
    default:
      return 31;
  }
}

function ehBissexto(ano) {
  return (ano % 4 === 0 && ano % 100 !== 0) || ano % 400 === 0;
}

console.log(diasNoMes(2, 2024)); // 29
console.log(diasNoMes(9, 2025)); // 30
console.log(diasNoMes(1, 2025)); // 31
```

O `switch` compara com `===`. Cada `case` precisa terminar com `return` ou `break`, senão a execução "cai" no próximo caso. Isso é usado de propósito acima (4, 6, 9 e 11 compartilham o mesmo resultado), mas esquecer o `break` sem querer é um bug clássico.

## Objetos como tabela de decisão

Muitas vezes um `switch` só mapeia uma chave para um valor. Um objeto faz isso em menos linhas e é fácil de estender:

```javascript
const fretePorRegiao = {
  sudeste: 15,
  sul: 20,
  nordeste: 30,
  norte: 40,
  "centro-oeste": 25,
};

function calcularFrete(regiao, valorCompra) {
  if (valorCompra >= 200) return 0;
  const frete = fretePorRegiao[regiao];
  if (frete === undefined) {
    throw new Error(`Região desconhecida: ${regiao}`);
  }
  return frete;
}

console.log(calcularFrete("sul", 100));      // 20
console.log(calcularFrete("norte", 250));    // 0
```

Você vai ver esse padrão em APIs para mapear status, papéis de usuário e mensagens de erro.

## Retorno antecipado em vez de if aninhado

Condicionais aninhadas formam uma "pirâmide" difícil de ler:

```javascript
function sacarRuim(conta, valor) {
  if (conta) {
    if (conta.ativa) {
      if (valor > 0) {
        if (valor <= conta.saldo) {
          conta.saldo -= valor;
          return "ok";
        } else {
          return "saldo insuficiente";
        }
      } else {
        return "valor inválido";
      }
    } else {
      return "conta inativa";
    }
  }
  return "conta inexistente";
}
```

Inverta as condições e saia cedo (guard clauses). Cada erro é tratado no topo e o caminho feliz fica no fim, sem indentação:

```javascript
function sacar(conta, valor) {
  if (!conta) return "conta inexistente";
  if (!conta.ativa) return "conta inativa";
  if (valor <= 0) return "valor inválido";
  if (valor > conta.saldo) return "saldo insuficiente";

  conta.saldo -= valor;
  return "ok";
}

const conta = { ativa: true, saldo: 100 };
console.log(sacar(conta, 30));  // ok
console.log(sacar(conta, 500)); // saldo insuficiente
console.log(conta.saldo);       // 70
```

Esse formato é exatamente o de um handler de API: valida autenticação, valida o corpo da requisição, verifica se o recurso existe e só então executa a operação.

## Mais exercícios de lógica

Tente resolver antes de olhar a solução.

**1. Maior de três números sem usar `Math.max`.**

```javascript
function maiorDeTres(a, b, c) {
  if (a >= b && a >= c) return a;
  if (b >= c) return b;
  return c;
}
console.log(maiorDeTres(3, 9, 5)); // 9
```

**2. Tipo de triângulo**, dados três lados. Primeiro verifique se os lados formam um triângulo (cada lado menor que a soma dos outros dois).

```javascript
function tipoTriangulo(a, b, c) {
  if (a + b <= c || a + c <= b || b + c <= a) return "não é triângulo";
  if (a === b && b === c) return "equilátero";
  if (a === b || b === c || a === c) return "isósceles";
  return "escaleno";
}
console.log(tipoTriangulo(3, 3, 3)); // equilátero
console.log(tipoTriangulo(3, 4, 5)); // escaleno
console.log(tipoTriangulo(1, 2, 8)); // não é triângulo
```

**3. FizzBuzz para um número**: devolva "FizzBuzz" se divisível por 3 e 5, "Fizz" se por 3, "Buzz" se por 5, ou o próprio número. Note que o teste combinado vem primeiro, pela regra da condição mais restrita.

```javascript
function fizzBuzz(n) {
  if (n % 15 === 0) return "FizzBuzz";
  if (n % 3 === 0) return "Fizz";
  if (n % 5 === 0) return "Buzz";
  return String(n);
}
console.log(fizzBuzz(15), fizzBuzz(9), fizzBuzz(10), fizzBuzz(7));
// FizzBuzz Fizz Buzz 7
```

## Na entrevista

- **Quais valores são falsy em JavaScript?** `false`, `0`, `-0`, `""`, `null`, `undefined` e `NaN` (e `0n`, o BigInt zero). Todo o resto, inclusive `[]` e `{}`, é truthy.
- **Qual a diferença entre `||` e `??`?** `||` troca qualquer falsy pelo valor padrão; `??` troca apenas `null` e `undefined`. Use `??` para padrões quando `0` ou `""` são válidos.
- **Quando usar `switch` em vez de `if`?** Quando a mesma expressão é comparada com vários valores exatos. Para faixas (`nota >= 7`), use `if`. Para mapear chave em valor, um objeto costuma ser melhor que os dois.
- **O que é guard clause?** Tratar os casos inválidos no início da função com retorno antecipado, deixando o caminho principal sem aninhamento.
