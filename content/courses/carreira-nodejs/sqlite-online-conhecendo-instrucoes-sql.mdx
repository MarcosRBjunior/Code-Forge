Quase toda API guarda dados num banco relacional, e a língua desses bancos é o SQL. Mesmo que você vá usar um ORM no dia a dia, é o SQL que roda por baixo, e é ele que aparece no log quando algo dá errado. O SQLite é o jeito mais simples de aprender: o banco inteiro é um único arquivo, não há servidor para instalar, e dá para praticar direto no navegador. Este é o primeiro de três capítulos em sequência com o mesmo banco de exemplo, uma livraria online. Aqui você aprende as instruções básicas para criar tabelas e manipular dados.

**Você vai aprender:**

- O que é um banco relacional e onde o SQLite se encaixa num back-end
- Criar tabelas com tipos, chave primária, chave estrangeira e restrições
- Inserir, consultar, atualizar e apagar dados com `INSERT`, `SELECT`, `UPDATE` e `DELETE`
- Alterar e remover tabelas
- Executar as mesmas instruções a partir do Node.js

## Tabelas, linhas e colunas

Um banco de dados relacional organiza os dados em **tabelas**. Cada tabela representa um tipo de coisa (clientes, livros, pedidos), cada **coluna** é um atributo (nome, preço) e cada **linha** é um registro. As tabelas se relacionam por meio de identificadores: um pedido guarda o `id` do cliente que o fez, em vez de copiar o nome e o e-mail dele.

O SQL (Structured Query Language) é a linguagem para conversar com esse banco. Ela é declarativa: você descreve o resultado que quer ("os livros de poesia com preço abaixo de 50") e o banco decide como buscá-lo.

O SQLite é um banco relacional completo que roda dentro do seu programa, gravando tudo num arquivo. Ele está em todo celular, em navegadores e em milhões de aplicações. Num back-end Node.js, ele aparece em protótipos, em testes automatizados (um banco descartável por teste) e em aplicações pequenas. O SQL que você aprende aqui vale, com pequenas diferenças, para PostgreSQL e MySQL.

### Onde praticar

Você tem três opções, todas com o mesmo SQL:

- **No navegador:** editores como o SQLite Online rodam o SQLite na própria página. Cole os comandos e execute, sem instalar nada.
- **No terminal:** o programa `sqlite3` (`sqlite3 livraria.db` abre ou cria o arquivo).
- **No Node.js:** o módulo nativo `node:sqlite`, que você vai ver no fim do capítulo.

## Criando as tabelas

A instrução `CREATE TABLE` define o nome da tabela, as colunas, o tipo de cada uma e as regras que os dados devem seguir. Este é o banco da livraria que acompanha os três capítulos:

```sql
PRAGMA foreign_keys = ON;

CREATE TABLE clientes (
  id        INTEGER PRIMARY KEY,
  nome      TEXT NOT NULL,
  email     TEXT NOT NULL UNIQUE,
  cidade    TEXT,
  criado_em TEXT NOT NULL
);

CREATE TABLE livros (
  id        INTEGER PRIMARY KEY,
  titulo    TEXT NOT NULL,
  autor     TEXT NOT NULL,
  categoria TEXT NOT NULL,
  preco     REAL NOT NULL CHECK (preco >= 0),
  estoque   INTEGER NOT NULL DEFAULT 0
);

CREATE TABLE pedidos (
  id         INTEGER PRIMARY KEY,
  cliente_id INTEGER NOT NULL REFERENCES clientes (id),
  feito_em   TEXT NOT NULL,
  status     TEXT NOT NULL DEFAULT 'pago'
             CHECK (status IN ('pago', 'enviado', 'cancelado'))
);

CREATE TABLE itens_pedido (
  pedido_id      INTEGER NOT NULL REFERENCES pedidos (id),
  livro_id       INTEGER NOT NULL REFERENCES livros (id),
  quantidade     INTEGER NOT NULL CHECK (quantidade > 0),
  preco_unitario REAL NOT NULL,
  PRIMARY KEY (pedido_id, livro_id)
);
```

Vamos por partes.

**Tipos.** O SQLite tem poucos tipos de armazenamento: `INTEGER` (inteiros), `REAL` (números com casas decimais), `TEXT` (texto) e `BLOB` (bytes). Não existe tipo de data: o costume é guardar datas como texto no formato `AAAA-MM-DD`, que ordena corretamente e funciona com as funções de data do SQLite.

**Chave primária.** `PRIMARY KEY` identifica cada linha de forma única. No SQLite, uma coluna `INTEGER PRIMARY KEY` é especial: se você não informar o valor, o banco gera o próximo número automaticamente. Na tabela `itens_pedido`, a chave é composta por duas colunas: um mesmo livro não aparece duas vezes no mesmo pedido.

**Restrições.** São regras que o banco garante sempre:

- `NOT NULL`: a coluna é obrigatória.
- `UNIQUE`: o valor não pode se repetir (dois clientes com o mesmo e-mail).
- `CHECK (...)`: qualquer condição; aqui, preço não negativo e status entre três valores.
- `DEFAULT`: valor usado quando o `INSERT` não informa a coluna.
- `REFERENCES clientes (id)`: a chave estrangeira. O valor de `cliente_id` precisa existir em `clientes.id`.

**O `PRAGMA foreign_keys = ON`.** Por compatibilidade com versões antigas, o SQLite vem com a checagem de chaves estrangeiras **desligada**. Esse comando liga a checagem e precisa ser executado a cada nova conexão.

```sql
  (7, 'Libertinagem',                    'Manuel Bandeira',            'Poesia',  32.00,  4),

```

Textos vão entre aspas simples. `NULL` (sem aspas) significa "sem valor": a Elisa não informou a cidade. Repare que `itens_pedido` guarda o `preco_unitario` do momento da compra: se o preço do livro mudar amanhã, o pedido antigo continua com o valor que o cliente pagou.

Ao omitir uma coluna, o banco usa o `DEFAULT` ou o valor gerado:

```sql
INSERT INTO livros (titulo, autor, categoria, preco)
VALUES ('Vidas Secas', 'Graciliano Ramos', 'Romance', 38.00);
-- id gerado: 9, estoque: 0 (DEFAULT)
```

E as restrições recusam dados inválidos:

```sql
INSERT INTO pedidos (cliente_id, feito_em) VALUES (99, '2026-03-20');
-- Erro: FOREIGN KEY constraint failed  (não existe cliente 99)

INSERT INTO clientes (nome, email, criado_em) VALUES ('Outra Ana', 'ana@exemplo.com', '2026-03-20');
-- Erro: UNIQUE constraint failed: clientes.email
```

## Consultando com SELECT

O `SELECT` lê dados. A forma mais simples lista colunas de uma tabela, e o `WHERE` filtra as linhas:

```sql
SELECT * FROM livros;                       -- todas as colunas

SELECT titulo, preco FROM livros
WHERE categoria = 'Poesia';
```

```text
titulo        | preco
Libertinagem  | 32.0
Claro Enigma  | 48.0
```

```sql
SELECT id, titulo, preco FROM livros WHERE preco < 40;
SELECT titulo FROM livros WHERE estoque = 0;
SELECT nome FROM clientes WHERE cidade IS NULL;
```

O `*` é prático para explorar, mas em código de aplicação liste as colunas: a consulta fica mais clara, trafega menos dados e não quebra quando alguém adiciona uma coluna. O próximo capítulo aprofunda o `SELECT` (filtros combinados, ordenação, agrupamento).

## Atualizando e apagando

`UPDATE` altera colunas das linhas que passam no `WHERE`. `DELETE` remove linhas.

```sql
-- chegaram 10 exemplares de O Cortiço
UPDATE livros SET estoque = estoque + 10 WHERE id = 3;

-- reajuste de 5% em todos os livros de poesia
UPDATE livros SET preco = round(preco * 1.05, 2) WHERE categoria = 'Poesia';

-- remove o livro de teste
DELETE FROM livros WHERE id = 9;
```

`estoque = estoque + 10` usa o valor atual da própria linha. O `round(..., 2)` arredonda para duas casas.

<Callout type="warning" title="O WHERE esquecido">
`UPDATE` e `DELETE` sem `WHERE` afetam **todas** as linhas da tabela, e o banco não pede confirmação. `DELETE FROM livros;` apaga o catálogo inteiro. Crie o hábito: escreva primeiro um `SELECT` com o mesmo `WHERE`, confira as linhas que aparecem e só então troque o `SELECT` pelo `UPDATE` ou `DELETE`.
</Callout>

## Alterando e removendo tabelas

A estrutura também muda. O `ALTER TABLE` do SQLite é mais limitado que o de outros bancos, mas cobre o comum:

```sql
ALTER TABLE livros ADD COLUMN paginas INTEGER;
ALTER TABLE livros RENAME COLUMN paginas TO num_paginas;
ALTER TABLE livros DROP COLUMN num_paginas;
ALTER TABLE clientes RENAME TO compradores;
ALTER TABLE compradores RENAME TO clientes;

DROP TABLE IF EXISTS rascunho;   -- apaga a tabela e todos os dados
```

Mudanças mais profundas, como alterar o tipo de uma coluna, exigem no SQLite criar uma tabela nova, copiar os dados e trocar os nomes. Para explorar a estrutura, use `PRAGMA table_info(livros);` (lista as colunas) ou, no `sqlite3`, os comandos `.tables` e `.schema livros`.

## Tipagem flexível e tabelas STRICT

Uma particularidade do SQLite que pega quem vem de outros bancos: o tipo declarado da coluna é uma preferência, não uma obrigação.

```sql
INSERT INTO livros (titulo, autor, categoria, preco) VALUES ('Teste', 'X', 'Romance', 'caro');
SELECT titulo, preco, typeof(preco) FROM livros WHERE titulo = 'Teste';
-- Teste | caro | text
```

O texto `'caro'` foi aceito numa coluna `REAL` (e ainda passou no `CHECK (preco >= 0)`, porque no SQLite um texto é sempre considerado maior que um número). Para ter checagem rígida, crie a tabela com `STRICT` no fim:

```sql
CREATE TABLE livros_v2 (
  id INTEGER PRIMARY KEY,
  titulo TEXT NOT NULL,
  preco REAL NOT NULL CHECK (preco >= 0)
) STRICT;

INSERT INTO livros_v2 (titulo, preco) VALUES ('Teste', 'caro');
-- Erro: cannot store TEXT value in REAL column livros_v2.preco
```

Em projetos novos, prefira tabelas `STRICT`. E, num sistema real, valores em dinheiro ficam mais seguros como inteiros em centavos, já que `REAL` é ponto flutuante e pode acumular erros de arredondamento.

## As mesmas instruções no Node.js

O Node.js 22.13 ou mais novo traz o SQLite embutido no módulo `node:sqlite` (ainda marcado como experimental, então ele imprime um aviso). Crie `livraria.mjs`:

```javascript
import { DatabaseSync } from "node:sqlite";

const db = new DatabaseSync("livraria.db");
db.exec("PRAGMA foreign_keys = ON");

db.exec(`
  CREATE TABLE IF NOT EXISTS livros (
    id INTEGER PRIMARY KEY,
    titulo TEXT NOT NULL,
    autor TEXT NOT NULL,
    categoria TEXT NOT NULL,
    preco REAL NOT NULL CHECK (preco >= 0),
    estoque INTEGER NOT NULL DEFAULT 0
  ) STRICT
`);

const inserir = db.prepare(
  "INSERT INTO livros (titulo, autor, categoria, preco) VALUES (?, ?, ?, ?)"
);
const r = inserir.run("Vidas Secas", "Graciliano Ramos", "Romance", 38);
console.log("novo id:", r.lastInsertRowid, "linhas:", r.changes);

const porCategoria = db.prepare("SELECT id, titulo, preco FROM livros WHERE categoria = ?");
console.log(porCategoria.all("Romance"));

db.prepare("UPDATE livros SET estoque = estoque + ? WHERE id = ?").run(5, r.lastInsertRowid);
console.log(db.prepare("SELECT * FROM livros WHERE id = ?").get(r.lastInsertRowid));
```

```bash
node livraria.mjs
```

O `prepare` compila a instrução uma vez, e os `?` são substituídos pelos valores passados em `run`, `all` (todas as linhas) ou `get` (a primeira). Nunca monte o SQL concatenando valores vindos do usuário: com os `?`, o valor nunca é interpretado como comando, e isso previne SQL injection.

## Na entrevista

**O que é uma chave primária e uma chave estrangeira?** A primária identifica cada linha de forma única. A estrangeira é uma coluna que referencia a primária de outra tabela, garantindo que o relacionamento aponte para algo que existe.

**Qual a diferença entre `DELETE FROM t` e `DROP TABLE t`?** `DELETE` remove as linhas e mantém a tabela; `DROP` remove a tabela inteira, estrutura e dados.

**Por que o SQLite aceitou uma chave estrangeira inválida?** Porque a checagem vem desligada por padrão; é preciso executar `PRAGMA foreign_keys = ON` em cada conexão.

**Quando usar SQLite num back-end?** Em protótipos, testes automatizados, aplicações com um único servidor e pouca escrita concorrente, e em ferramentas locais. Com muitas escritas simultâneas ou vários servidores, prefira PostgreSQL ou MySQL.

## Pratique

Monte o banco da livraria do zero e entregue um arquivo `livraria.sql` que:

1. Cria as quatro tabelas como `STRICT` e insere os dados deste capítulo.
2. Adiciona uma tabela `avaliacoes` (cliente, livro, nota de 1 a 5, comentário opcional, data), com chaves estrangeiras e um `CHECK` para a nota, e insere 6 avaliações.
3. Mostra, com comentários, uma tentativa de inserir nota 7 e uma avaliação de cliente inexistente, com os erros obtidos.
4. Reajusta em 10% os livros com estoque zerado e depois apaga as avaliações com nota 1, sempre conferindo antes com um `SELECT`.

Depois, rode o mesmo arquivo pelo Node.js com `db.exec(fs.readFileSync("livraria.sql", "utf8"))`.
