Os algoritmos quadráticos do capítulo anterior servem para entender a ideia, mas não aguentam um milhão de registros. Para isso existem as técnicas de "dividir para conquistar", como merge sort e quick sort, que ordenam em O(n log n). E ordenar quase sempre tem um objetivo: buscar depois. Neste capítulo você implementa esses algoritmos em JavaScript e aplica cada um a problemas que aparecem num back-end Node.js, como juntar resultados de duas fontes, achar eventos num intervalo de tempo e escolher entre ordenar e indexar.

**Você vai aprender:**

- A operação de intercalação (merge) e como ela resolve problemas além de ordenar
- Implementar merge sort e quick sort e entender quando cada um degrada
- Busca binária correta, incluindo as variações de limite inferior e superior
- Buscar intervalos em dados ordenados, como logs por horário
- Decidir entre busca linear, busca binária e um índice com `Map`

## Intercalar duas listas ordenadas

Antes do merge sort, a operação que o sustenta. Dadas duas listas já ordenadas, produza uma terceira, também ordenada, olhando cada elemento uma única vez. A ideia é usar dois ponteiros e sempre pegar o menor da frente.

```javascript
function intercalar(a, b, comparar = (x, y) => x - y) {
  const resultado = [];
  let i = 0;
  let j = 0;
  while (i < a.length && j < b.length) {
    // <= mantém a estabilidade: em empate, quem estava em a vem antes
    if (comparar(a[i], b[j]) <= 0) resultado.push(a[i++]);
    else resultado.push(b[j++]);
  }
  while (i < a.length) resultado.push(a[i++]);
  while (j < b.length) resultado.push(b[j++]);
  return resultado;
}

console.log(intercalar([1, 4, 9], [2, 3, 10, 12]));
// [ 1, 2, 3, 4, 9, 10, 12 ]
```

O custo é O(n + m). Isso tem aplicação direta: imagine que a API de livros busca resultados em dois lugares, o catálogo próprio e o de um parceiro, e cada um já devolve a lista ordenada por data. Concatenar e chamar `sort` custaria O(k log k); intercalar custa O(k).

```javascript
const proprios = [{ titulo: "A", em: "2026-01-03" }, { titulo: "C", em: "2026-02-10" }];
const parceiro = [{ titulo: "B", em: "2026-01-20" }, { titulo: "D", em: "2026-03-01" }];

const todos = intercalar(proprios, parceiro, (x, y) => x.em.localeCompare(y.em));
console.log(todos.map((l) => l.titulo)); // [ 'A', 'B', 'C', 'D' ]
```

Datas em ISO 8601 (`AAAA-MM-DD`) têm uma propriedade útil: a ordem alfabética coincide com a cronológica, então comparar as strings basta.

## Merge sort

Com a intercalação pronta, o merge sort é quase uma frase: divida o array ao meio, ordene cada metade (recursivamente) e intercale as duas.

```javascript
function mergeSort(lista, comparar = (x, y) => x - y) {
  if (lista.length <= 1) return lista;
  const meio = Math.floor(lista.length / 2);
  const esquerda = mergeSort(lista.slice(0, meio), comparar);
  const direita = mergeSort(lista.slice(meio), comparar);
  return intercalar(esquerda, direita, comparar);
}

console.log(mergeSort([38, 27, 43, 3, 9, 82, 10]));
// [ 3, 9, 10, 27, 38, 43, 82 ]
```

Por que O(n log n)? O array é dividido ao meio até sobrar um elemento, o que dá log₂ n níveis. Em cada nível, as intercalações juntas tocam todos os n elementos. São n operações vezes log n níveis. E isso vale sempre: melhor, médio e pior caso. Ele é estável e o preço é memória extra O(n) para os arrays intermediários.

Essa garantia é o motivo pelo qual variações do merge sort (como o TimSort do V8) são a escolha de bibliotecas padrão, e o motivo pelo qual bancos de dados usam ordenação externa baseada em intercalação quando os dados não cabem na memória: ordenam pedaços, gravam em disco e intercalam os pedaços depois.

## Quick sort

O quick sort também divide, mas de outro jeito: escolhe um pivô, coloca os menores à esquerda e os maiores à direita (a partição) e repete em cada lado. Não há etapa de juntar, porque depois da partição o pivô já está na posição final.

```javascript
function quickSort(a, inicio = 0, fim = a.length - 1) {
  if (inicio >= fim) return a;
  const p = particionar(a, inicio, fim);
  quickSort(a, inicio, p - 1);
  quickSort(a, p + 1, fim);
  return a;
}

function particionar(a, inicio, fim) {
  // pivô aleatório evita o pior caso em dados já ordenados
  const sorteado = inicio + Math.floor(Math.random() * (fim - inicio + 1));
  [a[sorteado], a[fim]] = [a[fim], a[sorteado]];
  const pivo = a[fim];
  let i = inicio;
  for (let j = inicio; j < fim; j++) {
    if (a[j] < pivo) {
      [a[i], a[j]] = [a[j], a[i]];
      i++;
    }
  }
  [a[i], a[fim]] = [a[fim], a[i]];
  return i;
}

console.log(quickSort([38, 27, 43, 3, 9, 82, 10]));
```

No caso médio ele é O(n log n) e, na prática, costuma ser mais rápido que o merge sort porque ordena no lugar e acessa a memória de forma sequencial. O ponto fraco é o pior caso: se o pivô for sempre o menor ou o maior elemento, cada partição tira só um item e o custo vira O(n²). Com o pivô fixo no último elemento, isso acontece exatamente com um array **já ordenado**, que é a entrada mais comum do mundo real. O pivô aleatório torna esse cenário improvável.

| | Merge sort | Quick sort |
|---|---|---|
| Caso médio | O(n log n) | O(n log n) |
| Pior caso | O(n log n) | O(n²) |
| Memória extra | O(n) | O(log n) da recursão |
| Estável | Sim | Não |

## Busca binária

Num array desordenado, achar um valor exige olhar todos: O(n). Num array ordenado, dá para fazer muito melhor. Compare com o elemento do meio: se o alvo for menor, ele só pode estar na metade esquerda; se for maior, na direita. Cada passo descarta metade, então um milhão de elementos se resolve em no máximo 20 comparações.

```javascript
function buscaBinaria(a, alvo) {
  let baixo = 0;
  let alto = a.length - 1;
  while (baixo <= alto) {
    const meio = baixo + Math.floor((alto - baixo) / 2);
    if (a[meio] === alvo) return meio;
    if (a[meio] < alvo) baixo = meio + 1;
    else alto = meio - 1;
  }
  return -1;
}

const ids = [3, 8, 15, 21, 42, 57, 90];
console.log(buscaBinaria(ids, 42)); // 4
console.log(buscaBinaria(ids, 50)); // -1
```

Os detalhes que quebram a busca binária são sempre os limites: `<=` no `while` (para testar o último elemento restante) e `meio + 1` e `meio - 1` (para o intervalo sempre encolher). Esquecer qualquer um deles gera laço infinito ou um elemento nunca encontrado.

### Limite inferior: a versão que você mais vai usar

Em back-end, raramente a pergunta é "o valor existe?". É "a partir de onde?". A função de limite inferior devolve o índice do primeiro elemento maior ou igual ao alvo, ou o tamanho do array se nenhum for.

```javascript
function limiteInferior(a, alvo, chave = (x) => x) {
  let baixo = 0;
  let alto = a.length; // intervalo semiaberto [baixo, alto)
  while (baixo < alto) {
    const meio = (baixo + alto) >>> 1;
    if (chave(a[meio]) < alvo) baixo = meio + 1;
    else alto = meio;
  }
  return baixo;
}

console.log(limiteInferior([10, 20, 20, 30], 20)); // 1 (primeiro 20)
console.log(limiteInferior([10, 20, 20, 30], 25)); // 3
console.log(limiteInferior([10, 20, 20, 30], 99)); // 4
```

Com ela, várias perguntas viram uma linha: "o valor existe?" (o índice é válido e o elemento é igual), "quantas ocorrências?" (limite inferior de `x + 1` menos o de `x`, para inteiros) e "quais elementos estão entre A e B?", que é o exemplo a seguir.

## Buscando eventos num intervalo de tempo

Um serviço mantém em memória os últimos eventos de auditoria, em ordem de chegada (portanto, já ordenados por horário). O painel pede: "todos os eventos entre 10h e 10h15". Filtrar o array inteiro é O(n). Com duas buscas binárias, você acha o começo e o fim em O(log n) e recorta.

```javascript
const eventos = [
  { em: Date.parse("2026-11-12T09:58:00Z"), acao: "login" },
  { em: Date.parse("2026-11-12T10:02:00Z"), acao: "criou livro" },
  { em: Date.parse("2026-11-12T10:09:00Z"), acao: "editou livro" },
  { em: Date.parse("2026-11-12T10:15:00Z"), acao: "logout" },
  { em: Date.parse("2026-11-12T10:21:00Z"), acao: "login" },
];

function entre(lista, desde, ate) {
  const ini = limiteInferior(lista, desde, (e) => e.em);
  const fim = limiteInferior(lista, ate, (e) => e.em); // ate é exclusivo
  return lista.slice(ini, fim);
}

const r = entre(eventos, Date.parse("2026-11-12T10:00:00Z"), Date.parse("2026-11-12T10:15:00Z"));
console.log(r.map((e) => e.acao)); // [ 'criou livro', 'editou livro' ]
```

O intervalo semiaberto (inclui o início, exclui o fim) é a convenção mais segura: dois intervalos vizinhos, 10h às 10h15 e 10h15 às 10h30, não contam o mesmo evento duas vezes.

<Callout type="warning" title="Busca binária em dados que não estão ordenados">
A armadilha mais comum é aplicar busca binária num array que só parece ordenado: eventos que chegam fora de ordem pela rede, uma lista ordenada por nome e buscada por data, ou um array onde alguém fez `push` sem manter a ordem. A busca não dá erro; ela simplesmente devolve resposta errada. Garanta a ordem na inserção (insira na posição do `limiteInferior`) ou ordene antes, e deixe isso escrito num comentário ou num teste.
</Callout>

## Ordenar, buscar ou indexar?

Busca binária não é a única ferramenta. Para buscas por igualdade, um `Map` (tabela hash) responde em O(1) médio e não exige ordem:

```javascript
const livros = [
  { isbn: "978-85-359-0277-1", titulo: "Dom Casmurro" },
  { isbn: "978-85-08-13353-0", titulo: "Iracema" },
];

const porIsbn = new Map(livros.map((l) => [l.isbn, l]));
console.log(porIsbn.get("978-85-08-13353-0")?.titulo); // Iracema
```

A decisão costuma ser esta:

| Situação | Melhor escolha |
|---|---|
| Poucas buscas numa lista pequena | `find` / `filter` (busca linear) |
| Muitas buscas por igualdade | `Map` construído uma vez |
| Buscas por intervalo, mínimo, "a partir de" | Array ordenado + busca binária |
| Dados grandes ou persistidos | Índice no banco (B-tree), que faz o mesmo por você |

A última linha é a ponte com o banco de dados: um índice B-tree no PostgreSQL é, conceitualmente, uma estrutura ordenada com busca em O(log n), e é por isso que ele acelera tanto `WHERE id = 42` quanto `WHERE criado_em BETWEEN ...`. Os algoritmos deste capítulo são o modelo mental para entender por que uma consulta ficou lenta.

## Na entrevista

**Por que o quick sort é O(n²) no pior caso e como evitar?** Quando o pivô é sempre o extremo, cada partição remove só um elemento. Pivô aleatório (ou mediana de três) torna isso improvável.

**Quando preferir merge sort a quick sort?** Quando você precisa de estabilidade, de garantia O(n log n) no pior caso ou de ordenar dados que não cabem na memória (ordenação externa).

**Qual o pré-requisito da busca binária e qual a complexidade?** O array precisa estar ordenado pela chave buscada. A busca é O(log n).

**Como contar quantas vezes um valor aparece num array ordenado em O(log n)?** Duas buscas binárias: a posição do primeiro elemento maior ou igual a `x` e a do primeiro maior que `x`. A diferença é a contagem.

## Pratique

Construa um módulo `serie-temporal.js` que guarda leituras `{ em, valor }` em ordem e oferece:

1. `inserir(leitura)`: insere na posição correta com `limiteInferior` e `splice`, mesmo que a leitura chegue atrasada.
2. `entre(desde, ate)`: devolve as leituras do intervalo semiaberto em O(log n) mais o tamanho do resultado.
3. `mesclar(outraSerie)`: intercala com outra série em O(n + m).
4. Testes com `node --test` comparando cada função com uma versão ingênua (`filter` e `sort`) em mil leituras aleatórias.

Exponha `GET /leituras?desde=...&ate=...` numa rota Express usando o módulo.
