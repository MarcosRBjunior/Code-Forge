Um back-end existe para servir alguém, e quase sempre esse alguém é uma interface. Entender o mínimo de React deixa você desenhar APIs que o front-end consegue usar de verdade, depurar uma integração sozinho e mostrar no portfólio um projeto completo, do banco à tela. Este é o primeiro de três capítulos que constroem o mesmo projeto, a **Estante**: um app para pesquisar livros e marcar favoritos. Aqui você monta o front-end com dados locais; no próximo, cria a API com Express; no terceiro, liga os dois.

**Você vai aprender:**

- Criar um projeto React com Vite e entender a estrutura gerada
- Escrever componentes com JSX e passar dados por props
- Guardar estado com `useState` e reagir a eventos
- Renderizar listas com `map` e a prop `key`
- Organizar o projeto pensando na API que vai substituir os dados locais

## Por que React e por que Vite

React é uma biblioteca para construir interfaces a partir de **componentes**: funções que recebem dados e devolvem a descrição do que deve aparecer na tela. Quando os dados mudam, o React atualiza só o que mudou. Você não manipula o HTML diretamente; você descreve o resultado e o React cuida do resto.

Vite é a ferramenta que cria o projeto, roda o servidor de desenvolvimento com recarga instantânea e gera os arquivos finais para produção.

```bash
npm create vite@latest estante-web -- --template react
cd estante-web
npm install
npm run dev
```

Abra o endereço mostrado no terminal (normalmente `http://localhost:5173`). A estrutura que importa:

```text
estante-web/
  index.html        <- página única; o React é montado dentro de div#root
  src/
    main.jsx        <- ponto de entrada: cria a raiz do React
    App.jsx         <- componente principal
  package.json
  vite.config.js
```

```jsx
// src/main.jsx
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import App from "./App.jsx";
import "./index.css";

createRoot(document.getElementById("root")).render(
  <StrictMode>
    <App />
  </StrictMode>
);
```

`createRoot` liga o React a um elemento do HTML, e `render` desenha o componente `App` lá dentro. Apague o conteúdo de exemplo de `App.jsx` e `App.css`: você vai escrever o seu.

## JSX: HTML dentro do JavaScript

Um componente é uma função com nome em maiúscula que devolve JSX, uma sintaxe parecida com HTML que vira chamadas JavaScript.

```jsx
// src/App.jsx
export default function App() {
  const titulo = "Estante";
  const totalLivros = 3;

  return (
    <main className="app">
      <h1>{titulo}</h1>
      <p>Você tem {totalLivros} livros cadastrados.</p>
    </main>
  );
}
```

Regras do JSX que pegam quem vem do HTML:

| HTML | JSX | Por quê |
|---|---|---|
| `class="x"` | `className="x"` | `class` é palavra reservada no JavaScript |
| `for="campo"` | `htmlFor="campo"` | idem |
| `onclick="..."` | `onClick={funcao}` | eventos em camelCase, recebendo função |
| `<img>` | `<img />` | toda tag precisa ser fechada |
| vários elementos soltos | um elemento pai ou `<>...</>` | o componente devolve um valor só |

Dentro das chaves vai qualquer **expressão** JavaScript: variáveis, contas, chamadas de função, ternários. Comandos como `if` e `for` não cabem ali; para isso existem os padrões que você vai ver a seguir.

## Componentes e props

Divida a tela em peças com uma responsabilidade cada. Para a Estante:

```text
App
  Cabecalho
  Pesquisa
  ListaDeLivros
    CardLivro (um por livro)
  Favoritos
```

Componentes recebem dados por **props**, um objeto com os atributos passados no JSX. Desestruture direto nos parâmetros:

```jsx
// src/componentes/CardLivro.jsx
export default function CardLivro({ livro, favorito, aoAlternarFavorito }) {
  return (
    <article className="card">
      <img src={livro.capa} alt={`Capa de ${livro.titulo}`} />
      <h3>{livro.titulo}</h3>
      <p>
        {livro.autor}, {livro.ano}
      </p>
      <button type="button" onClick={() => aoAlternarFavorito(livro.id)}>
        {favorito ? "Remover dos favoritos" : "Favoritar"}
      </button>
    </article>
  );
}
```

Props são **somente leitura**: o componente nunca altera o que recebeu. Quando o card precisa avisar que algo aconteceu (o clique em favoritar), ele chama uma **função recebida por prop**. Os dados descem do pai para o filho por props; os eventos sobem do filho para o pai por callbacks. Esse fluxo de mão única é o coração do React.

## Listas com map e key

Para mostrar um card por livro, transforme o array de dados num array de elementos com `map`:

```jsx
// src/componentes/ListaDeLivros.jsx
import CardLivro from "./CardLivro.jsx";

export default function ListaDeLivros({ livros, idsFavoritos, aoAlternarFavorito }) {
  if (livros.length === 0) {
    return <p className="vazio">Nenhum livro encontrado.</p>;
  }

  return (
    <section className="grade">
      {livros.map((livro) => (
        <CardLivro
          key={livro.id}
          livro={livro}
          favorito={idsFavoritos.includes(livro.id)}
          aoAlternarFavorito={aoAlternarFavorito}
        />
      ))}
    </section>
  );
}
```

O retorno antecipado para lista vazia é o mesmo padrão de guard clause que você usa no back-end. E a prop `key` identifica cada item entre uma renderização e outra, para o React saber qual card mudou, qual entrou e qual saiu.

<Callout type="warning" title="Usar o índice como key">
`livros.map((livro, i) => <CardLivro key={i} ... />)` parece funcionar, mas quebra quando a lista é filtrada, ordenada ou tem itens removidos: o React passa a associar o estado de um card ao livro errado (um campo digitado, uma animação, um botão marcado). Use um identificador estável que vem dos dados, como o `id` que a API vai devolver. É mais um motivo para toda entidade da sua API ter um id.
</Callout>

## Estado com useState

Props vêm de fora. **Estado** é a memória do próprio componente: valores que mudam com a interação e que, ao mudar, fazem a tela atualizar. Você cria estado com o hook `useState`:

```jsx
import { useState } from "react";

function Contador() {
  const [cliques, setCliques] = useState(0);
  return <button onClick={() => setCliques(cliques + 1)}>Clicado {cliques} vezes</button>;
}
```

`useState(0)` devolve um par: o valor atual e a função que o substitui. Chamar `setCliques` agenda uma nova renderização com o novo valor. Mudar a variável diretamente (`cliques++`) não faz nada aparecer na tela.

## A pesquisa: input controlado

O campo de busca é um **input controlado**: o valor dele vive no estado, e cada tecla atualiza o estado.

```jsx
// src/componentes/Pesquisa.jsx
export default function Pesquisa({ termo, aoMudarTermo }) {
  return (
    <div className="pesquisa">
      <label htmlFor="busca">Pesquisar livro ou autor</label>
      <input
        id="busca"
        type="search"
        value={termo}
        onChange={(evento) => aoMudarTermo(evento.target.value)}
        placeholder="Ex.: Machado"
      />
    </div>
  );
}
```

O estado do termo fica no `App`, porque é ele que precisa do termo para filtrar a lista. Essa ideia tem nome: **elevar o estado** até o ancestral comum dos componentes que precisam dele.

## Juntando tudo no App

```jsx
// src/App.jsx
import { useState } from "react";
import { livros } from "./dados/livros.js";
import Pesquisa from "./componentes/Pesquisa.jsx";
import ListaDeLivros from "./componentes/ListaDeLivros.jsx";
import Favoritos from "./componentes/Favoritos.jsx";
import "./App.css";

function normalizar(texto) {
  return texto.normalize("NFD").replace(/[̀-ͯ]/g, "").toLowerCase();
}

export default function App() {
  const [termo, setTermo] = useState("");
  const [idsFavoritos, setIdsFavoritos] = useState([]);

  const filtrados = livros.filter((livro) => {
    const alvo = normalizar(`${livro.titulo} ${livro.autor}`);
    return alvo.includes(normalizar(termo.trim()));
  });

  const favoritos = livros.filter((livro) => idsFavoritos.includes(livro.id));

  function alternarFavorito(id) {
    setIdsFavoritos((atuais) =>
      atuais.includes(id) ? atuais.filter((x) => x !== id) : [...atuais, id]
    );
  }

  return (
    <main className="app">
      <h1>Estante</h1>
      <Pesquisa termo={termo} aoMudarTermo={setTermo} />
      <ListaDeLivros
        livros={filtrados}
        idsFavoritos={idsFavoritos}
        aoAlternarFavorito={alternarFavorito}
      />
      <Favoritos livros={favoritos} />
    </main>
  );
}
```

Três ideias importantes nesse código:

1. **Dado derivado não vira estado.** `filtrados` e `favoritos` são calculados a cada renderização a partir de `termo` e `idsFavoritos`. Guardar em `useState` criaria duas fontes de verdade que podem divergir.
2. **Atualização imutável.** `setIdsFavoritos` recebe um array **novo** (`filter` ou spread). Usar `push` no array atual alteraria o mesmo objeto, e o React, comparando referências, poderia não perceber a mudança. É a mesma disciplina de não alterar objetos recebidos que você treinou em JavaScript.
3. **Atualização com função.** `setIdsFavoritos((atuais) => ...)` recebe o valor mais recente do estado. Use essa forma sempre que o novo valor depender do anterior.

O componente `Favoritos` fica como exercício, e é praticamente um `ListaDeLivros` simplificado.

## Pensando como back-end desde já

O front-end que você acabou de escrever já define o **contrato** da API que vem no próximo capítulo:

| O front precisa | A API vai oferecer |
|---|---|
| Lista de livros com `id`, `titulo`, `autor`, `ano`, `capa` | `GET /livros` |
| Lista de favoritos | `GET /favoritos` |
| Favoritar | `POST /favoritos/:id` |
| Desfavoritar | `DELETE /favoritos/:id` |

Escrever esse contrato antes de codar a API evita o problema mais comum de projetos full stack: a API devolve `nome` e o front espera `titulo`, e alguém passa uma tarde descobrindo por que a tela está vazia.

Para fechar este capítulo, gere a versão de produção:

```bash
npm run build     # gera a pasta dist/ com HTML, JS e CSS otimizados
npm run preview   # serve o dist/ localmente para conferir
```

A pasta `dist/` é só arquivos estáticos: qualquer servidor web, CDN ou até o próprio Express pode servi-la.

## Na entrevista

- **Qual a diferença entre props e estado?** Props são dados recebidos do componente pai, somente leitura. Estado é a memória interna do componente, alterada com a função do `useState`, e cada alteração causa nova renderização.
- **Para que serve a prop `key` em listas?** Identifica cada item de forma estável entre renderizações, para o React reaproveitar e atualizar os elementos certos. Deve ser um id dos dados, não o índice.
- **Por que não alterar o estado diretamente?** O React detecta mudanças comparando referências. Alterar o array ou objeto existente não muda a referência, e a tela pode não atualizar; além disso, quebra a previsibilidade do fluxo de dados.
- **O que é elevar o estado?** Mover o estado para o ancestral comum mais próximo dos componentes que precisam dele, passando o valor e as funções de alteração por props.
