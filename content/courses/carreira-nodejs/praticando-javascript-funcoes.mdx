Quando o mesmo trecho de código aparece em três lugares, um bug corrigido em um deles continua vivo nos outros dois. Funções resolvem isso: você dá um nome a um bloco de lógica, escreve uma vez e chama quantas vezes quiser. Em Node.js, funções estão em todo lugar: cada rota de API é uma função, cada middleware é uma função, e boa parte das bibliotecas pede que você passe funções como argumento.

**Você vai aprender:**

- Declarar funções, receber parâmetros e devolver valores com `return`
- Arrow functions, parâmetros com valor padrão e rest parameters
- Escopo: onde cada variável existe
- Funções como valores: callbacks e funções de ordem superior
- Funções puras e como escrever funções fáceis de testar

## Declarando e chamando

Uma função tem nome, parâmetros (as entradas) e um corpo. `return` devolve o resultado para quem chamou.

```javascript
function calcularDesconto(preco, percentual) {
  const desconto = preco * (percentual / 100);
  return preco - desconto;
}

const final = calcularDesconto(200, 15);
console.log(final); // 170
console.log(calcularDesconto(80, 50)); // 40
```

Os nomes entre parênteses na declaração (`preco`, `percentual`) são **parâmetros**. Os valores passados na chamada (`200`, `15`) são **argumentos**. Quando a função é chamada, cada parâmetro recebe o argumento da mesma posição.

O `return` encerra a função na hora. Uma função sem `return` devolve `undefined`:

```javascript
function mostrarSaudacao(nome) {
  console.log(`Olá, ${nome}`);
}

const resultado = mostrarSaudacao("Ana"); // Olá, Ana
console.log(resultado);                    // undefined
```

Essa diferença é importante: **mostrar** um valor com `console.log` não é **devolver** o valor. Uma função que só imprime não pode ter o resultado reaproveitado em outra conta. Prefira funções que devolvem, e deixe o `console.log` para quem chama.

## Parâmetros: padrão, faltando e sobrando

Se você chamar a função com menos argumentos, os que faltam viram `undefined`. Para evitar isso, defina um **valor padrão**:

```javascript
function formatarPreco(valor, moeda = "BRL") {
  return valor.toLocaleString("pt-BR", { style: "currency", currency: moeda });
}

console.log(formatarPreco(1234.5));        // R$ 1.234,50
console.log(formatarPreco(99.9, "USD"));   // US$ 99,90
```

Para aceitar qualquer quantidade de argumentos, use **rest parameters** (três pontos antes do último parâmetro). Eles chegam como array:

```javascript
function somarTodos(...numeros) {
  let total = 0;
  for (const n of numeros) total += n;
  return total;
}

console.log(somarTodos(1, 2, 3));       // 6
console.log(somarTodos(10, 20, 30, 40)); // 100
console.log(somarTodos());               // 0
```

Quando uma função passa de três parâmetros, fica difícil lembrar a ordem. Receba um objeto e desestruture, assim a chamada fica autoexplicativa:

```javascript
function criarUsuario({ nome, email, papel = "leitor", ativo = true }) {
  return { nome, email, papel, ativo };
}

console.log(criarUsuario({ nome: "Ana", email: "ana@exemplo.com" }));
// { nome: 'Ana', email: 'ana@exemplo.com', papel: 'leitor', ativo: true }
console.log(criarUsuario({ email: "bia@exemplo.com", nome: "Bia", papel: "admin" }));
```

Esse é o formato que você vai ver em quase toda biblioteca Node.js: `mongoose.connect(url, { ... })`, `fetch(url, { method: "POST" })`.

## Arrow functions

Arrow functions são uma sintaxe mais curta, muito usada para funções pequenas e callbacks:

```javascript
const dobro = (n) => n * 2;
const somar = (a, b) => a + b;
const saudacao = () => "Bom dia";

const classificar = (idade) => {
  if (idade < 18) return "menor";
  return "maior";
};

console.log(dobro(21), somar(2, 3), saudacao(), classificar(30));
// 42 5 Bom dia maior
```

Com uma única expressão depois da seta, o `return` é implícito. Com chaves, você precisa escrever o `return`. Se a função devolve um objeto direto, envolva em parênteses, senão as chaves são lidas como bloco:

```javascript
const criarPonto = (x, y) => ({ x, y });
console.log(criarPonto(1, 2)); // { x: 1, y: 2 }
```

Quando usar qual? Use `function` para funções nomeadas de nível superior (as que formam o "vocabulário" do arquivo) e arrows para callbacks e funções curtas. A diferença técnica principal é que arrows não têm seu próprio `this`, o que só vai importar quando você estudar classes.

## Escopo: onde a variável existe

Uma variável declarada com `let` ou `const` só existe dentro do bloco (as chaves) onde foi criada. Variáveis de fora são visíveis dentro, mas o contrário não.

```javascript
const taxa = 0.1; // escopo do módulo: visível em todo o arquivo

function calcularImposto(valor) {
  const imposto = valor * taxa; // usa taxa de fora
  return imposto;
}

console.log(calcularImposto(500)); // 50
// console.log(imposto); // ReferenceError: imposto is not defined
```

Isso protege você: cada função tem as próprias variáveis, e duas funções podem usar o nome `total` sem uma estragar a outra. Evite modificar variáveis de fora dentro da função; receba o que precisa por parâmetro e devolva o resultado.

### Closures

Uma função "lembra" das variáveis do lugar onde foi criada, mesmo depois que aquele lugar terminou de executar. Isso se chama **closure**.

```javascript
function criarContador() {
  let contagem = 0;
  return () => {
    contagem++;
    return contagem;
  };
}

const proximoId = criarContador();
console.log(proximoId()); // 1
console.log(proximoId()); // 2

const outro = criarContador();
console.log(outro());     // 1 (contagem separada)
```

`contagem` não é acessível de fora, só pela função devolvida. Closures são a base de muitos padrões em Node: configurar um middleware com opções, criar um logger com prefixo, guardar um cache privado.

## Funções como valores

Em JavaScript, uma função é um valor como qualquer outro: pode ir para uma variável, ser passada como argumento ou ser devolvida por outra função. Uma função que recebe outra como argumento é chamada de **função de ordem superior**, e a função passada é um **callback**.

```javascript
function repetir(vezes, acao) {
  for (let i = 1; i <= vezes; i++) {
    acao(i);
  }
}

repetir(3, (n) => console.log(`Executando ${n}`));
```

```text
Saída:
Executando 1
Executando 2
Executando 3
```

Você já usa isso sem perceber. `setTimeout` recebe um callback, e os métodos de array do próximo capítulo também:

```javascript
setTimeout(() => console.log("Um segundo depois"), 1000);

const precos = [10, 25, 40];
const comImposto = precos.map((p) => p * 1.1);
console.log(comImposto); // [ 11, 27.500000000000004, 44 ]
```

(O `27.500000000000004` é efeito de como computadores guardam números decimais. Para dinheiro, trabalhe em centavos inteiros ou arredonde ao exibir.)

No Express, uma rota é exatamente uma função de ordem superior: você passa um callback que será chamado a cada requisição.

```javascript
// prévia do que vem no Nível 1
app.get("/saude", (req, res) => {
  res.json({ status: "ok" });
});
```

Uma função também pode devolver outra função, já configurada:

```javascript
function criarValidadorDeTamanho(minimo, maximo) {
  return (texto) => texto.length >= minimo && texto.length <= maximo;
}

const senhaValida = criarValidadorDeTamanho(8, 64);
const apelidoValido = criarValidadorDeTamanho(3, 20);

console.log(senhaValida("123"));        // false
console.log(apelidoValido("ana_dev"));  // true
```

<Callout type="warning" title="Passar a função ou chamar a função">
`setTimeout(avisar, 1000)` passa a função, que será chamada depois. `setTimeout(avisar(), 1000)` chama `avisar` agora e passa o **resultado** (normalmente `undefined`). Ao entregar um callback, escreva o nome sem parênteses ou uma arrow: `() => avisar("Ana")`.
</Callout>

## Funções puras e testáveis

Uma função **pura** devolve sempre o mesmo resultado para os mesmos argumentos e não altera nada fora dela (não mexe em variável global, não escreve em arquivo, não muda o objeto recebido).

```javascript
// impura: depende e altera estado externo
let saldoGlobal = 100;
function debitarImpuro(valor) {
  saldoGlobal -= valor;
}

// pura: recebe tudo e devolve o novo estado
function debitar(saldo, valor) {
  if (valor > saldo) throw new Error("Saldo insuficiente");
  return saldo - valor;
}

console.log(debitar(100, 30)); // 70
```

Funções puras são fáceis de testar: chame com uma entrada e compare a saída. O Node já traz um executor de testes embutido, e você pode testar a função acima assim:

```javascript
// debitar.test.mjs
import { test } from "node:test";
import assert from "node:assert/strict";

function debitar(saldo, valor) {
  if (valor > saldo) throw new Error("Saldo insuficiente");
  return saldo - valor;
}

test("debita quando há saldo", () => {
  assert.equal(debitar(100, 30), 70);
});

test("lança erro sem saldo", () => {
  assert.throws(() => debitar(10, 30), /Saldo insuficiente/);
});
```

```bash
node --test
```

Uma API real tem partes impuras (banco, rede, arquivos), mas a regra de negócio no meio pode ser pura. Separar as duas coisas é a habilidade que mais facilita a vida na hora de testar.

## Recursão

Uma função pode chamar a si mesma. Toda recursão precisa de um **caso base** que para as chamadas, e de um passo que se aproxima dele.

```javascript
function fatorial(n) {
  if (n <= 1) return 1;          // caso base
  return n * fatorial(n - 1);    // passo recursivo
}
console.log(fatorial(5)); // 120

function somaDigitos(n) {
  if (n < 10) return n;
  return (n % 10) + somaDigitos(Math.floor(n / 10));
}
console.log(somaDigitos(9875)); // 29
```

Sem caso base, a função chama a si mesma até estourar a pilha: `RangeError: Maximum call stack size exceeded`. Para problemas simples, um laço costuma ser mais eficiente; recursão brilha em estruturas aninhadas, como árvores e pastas dentro de pastas.

## Exercícios resolvidos

**Validar CPF só pelo formato** (11 dígitos, aceitando pontos e traço):

```javascript
const apenasDigitos = (texto) => texto.replace(/\D/g, "");

function cpfTemFormatoValido(cpf) {
  const digitos = apenasDigitos(cpf);
  if (digitos.length !== 11) return false;
  if (/^(\d)\1+$/.test(digitos)) return false; // todos iguais, como 111.111.111-11
  return true;
}

console.log(cpfTemFormatoValido("123.456.789-09")); // true
console.log(cpfTemFormatoValido("111.111.111-11")); // false
```

**Compor funções**: aplicar várias transformações em sequência.

```javascript
const aparar = (s) => s.trim();
const minusculas = (s) => s.toLowerCase();
const trocarEspacos = (s) => s.replace(/\s+/g, "-");

function compor(...funcoes) {
  return (valor) => {
    let resultado = valor;
    for (const f of funcoes) resultado = f(resultado);
    return resultado;
  };
}

const criarSlug = compor(aparar, minusculas, trocarEspacos);
console.log(criarSlug("  Minha Primeira API  ")); // minha-primeira-api
```

## Na entrevista

- **O que é uma closure?** Uma função junto com as variáveis do escopo onde foi criada, que ela continua acessando depois que esse escopo terminou. Usada para estado privado e funções configuradas.
- **Diferença entre arrow function e function?** Arrows têm sintaxe curta, retorno implícito com uma expressão e não têm `this` nem `arguments` próprios; não podem ser usadas com `new`.
- **O que é função de ordem superior?** Uma função que recebe ou devolve outra função, como `map`, `filter` ou um middleware do Express.
- **O que é uma função pura e por que importa?** Mesmo resultado para a mesma entrada, sem efeitos colaterais. É previsível, fácil de testar e de reutilizar.

## Pratique

Crie um arquivo `validacoes.mjs` com estas funções puras, cada uma devolvendo `true` ou `false`:

1. `emailValido(email)`: tem exatamente um `@`, algo antes dele e um ponto depois dele.
2. `senhaForte(senha)`: pelo menos 8 caracteres, uma letra maiúscula, uma minúscula e um dígito.
3. `validarCadastro(dados)`: recebe `{ nome, email, senha }` e devolve um **array de mensagens de erro** (vazio se tudo estiver certo), usando as funções anteriores.

Entregue também `validacoes.test.mjs` com pelo menos seis testes usando `node:test`, cobrindo casos válidos e inválidos. Essa função `validarCadastro` vai ser útil de verdade quando você escrever a rota de cadastro da sua API.
