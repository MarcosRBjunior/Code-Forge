Em entrevista, a pergunta "qual a complexidade da sua solução?" só tem resposta correta se você souber o custo de cada chamada da biblioteca. Uma linha inocente como `lista.Contains(x)` dentro de um laço transforma O(n) em O(n²), e `lista.RemoveAt(0)` faz o mesmo sem que isso apareça no código. Este capítulo é a tabela de consulta que você deve ter na cabeça para o .NET.

## Tabela de custos

| Estrutura e operação | Custo | Observação |
| --- | --- | --- |
| `T[]` acesso por índice | O(1) | tamanho fixo |
| `List<T>` acesso por índice | O(1) | array redimensionável |
| `List<T>.Add` | O(1) amortizado | dobra a capacidade quando enche |
| `List<T>.Insert(i)` e `RemoveAt(i)` | O(n) | desloca os elementos à direita |
| `List<T>.Contains` e `IndexOf` | O(n) | busca linear |
| `List<T>.Sort` | O(n log n) | introsort, instável |
| `List<T>.BinarySearch` | O(log n) | exige lista ordenada |
| `Dictionary` e `HashSet`: inserir, buscar, remover | O(1) médio | O(n) no pior caso, com muitas colisões |
| `SortedDictionary` e `SortedSet` | O(log n) | árvore rubro-negra, mantém ordem |
| `Stack<T>` e `Queue<T>` | O(1) | `Push`, `Pop`, `Enqueue`, `Dequeue`, `Peek` |
| `LinkedList<T>` inserir ou remover num nó conhecido | O(1) | acesso por posição é O(n) |
| `string` concatenar com `+` | O(n) | cria uma nova string |
| `StringBuilder.Append` | O(1) amortizado | `ToString` é O(n) |
| `string.Substring` | O(k) | copia os k caracteres |

Compare com Python: `list.append` e `list.pop()` são O(1), `list.pop(0)` é O(n); `dict` e `set` são O(1) médio. A tabela é praticamente a mesma, e o que muda são os nomes. Em JavaScript, `Array.shift` e `unshift` também são O(n).

## Contando passos: busca linear contra binária

Dá para visualizar a diferença sem cronômetro, contando quantas posições cada busca examina.

```csharp
using System;

class Program
{
    static int BuscaLinear(int[] a, int alvo, out int passos)
    {
        passos = 0;
        for (int i = 0; i < a.Length; i++)
        {
            passos++;
            if (a[i] == alvo) return i;
        }
        return -1;
    }

    static int BuscaBinaria(int[] a, int alvo, out int passos)
    {
        passos = 0;
        int lo = 0, hi = a.Length - 1;
        while (lo <= hi)
        {
            passos++;
            int mid = lo + (hi - lo) / 2;
            if (a[mid] == alvo) return mid;
            if (a[mid] < alvo) lo = mid + 1;
            else hi = mid - 1;
        }
        return -1;
    }

    static void Main()
    {
        int[] a = new int[1024];
        for (int i = 0; i < a.Length; i++) a[i] = i * 2;

        int p;
        Console.WriteLine(BuscaLinear(a, 2046, out p));
        Console.WriteLine(p);
        Console.WriteLine(BuscaBinaria(a, 2046, out p));
        Console.WriteLine(p);
    }
}
```

```text
Saída:
1023
1024
1023
11
```

Para mil elementos, 1024 passos contra 11. Quando o número dobra, a linear dobra e a binária ganha só mais um passo. O pré-requisito é a ordenação, que custa O(n log n) uma vez.

## Estruturas ordenadas e BinarySearch

`SortedSet` e `SortedDictionary` mantêm os elementos ordenados a cada inserção. Servem para consultas como menor, maior e intervalos. `BinarySearch` devolve a posição quando acha e, quando não acha, o complemento de bits (`~`) do ponto de inserção.

```csharp
using System;
using System.Collections.Generic;

class Program
{
    static void Main()
    {
        var sd = new SortedDictionary<int, string>();
        sd[5] = "cinco";
        sd[1] = "um";
        sd[3] = "tres";
        foreach (var kv in sd) Console.Write(kv.Key + " ");
        Console.WriteLine();

        var ss = new SortedSet<int> { 5, 1, 3, 9 };
        Console.WriteLine(ss.Min + " " + ss.Max);
        Console.WriteLine(ss.GetViewBetween(2, 6).Count);

        int[] v = { 1, 3, 5, 7 };
        Console.WriteLine(Array.BinarySearch(v, 5));
        int r = Array.BinarySearch(v, 4);
        Console.WriteLine(r);
        Console.WriteLine(~r);
    }
}
```

```text
Saída:
1 3 5
1 9
2
2
-3
2
```

Em `BinarySearch(v, 4)` o resultado negativo `-3` significa "não achei; inseriria na posição `~(-3)`", ou seja, 2. Esse truque é útil para achar o primeiro elemento maior ou igual a um valor.

## Armadilhas de complexidade escondida

- `list.Contains` ou `list.Remove(x)` dentro de um laço: use `HashSet` quando precisar de busca repetida.
- `s += c` num laço sobre uma string: O(n²) no total. Use `StringBuilder`.
- `list.RemoveAt(0)` ou `Insert(0, x)` em laço: use `Queue` ou um índice de cabeça.
- LINQ: `Count()` em um `IEnumerable` sem contagem conhecida percorre tudo, e `ElementAt` em sequências lazy também.
- `Dictionary` com chaves ruins (hash fraco) degrada para O(n); em geral, com tipos nativos isso não acontece.
- O custo de `ToList`, `ToArray` e `new List<T>(outra)` é O(n): copiar não é de graça.
- `SortedList` tem inserção O(n), apesar do nome parecido com `SortedDictionary`.

<Callout type="tip" title="Dica">
Fale o custo em voz alta ao escolher a estrutura: "preciso de busca repetida, então uso `HashSet`, que dá O(1) médio contra O(n) da lista". Essa frase vale mais pontos do que o código.
</Callout>
