Muitos algoritmos precisam de um pedaço de comportamento passado como argumento: um critério de ordenação, uma condição de filtro, uma ação a executar. Em Python e JavaScript você passa uma função. Em C# funções também podem ser valores, mas o tipo dessa função precisa ser declarado: isso é um delegate. As lambdas são a sintaxe curta para criar um.

## Delegates: o tipo de uma função

Um delegate descreve uma assinatura (parâmetros e retorno). Em vez de declarar o seu a cada vez, use os genéricos prontos da biblioteca:

- `Func<..., TResult>`: recebe zero ou mais parâmetros e devolve um valor. O último tipo é o do retorno, como em `Func<int, int, int>`.
- `Action<...>`: recebe parâmetros e não devolve nada.
- `Predicate<T>`: recebe T e devolve `bool`.
- `Comparison<T>`: recebe dois T e devolve um inteiro (negativo, zero ou positivo), usado em `Sort`.

Você ainda pode declarar o seu com `delegate int Operacao(int a, int b);`, útil quando o nome torna a intenção mais clara.

## Lambdas

A lambda tem a forma `(parametros) => expressao`. Com um parâmetro, os parênteses são opcionais; com corpo de várias linhas, use chaves e `return`. O compilador infere os tipos dos parâmetros pelo delegate de destino.

```csharp
using System;

delegate int Operacao(int a, int b);

class Program
{
    static void Main()
    {
        Func<int, int> dobro = x => x * 2;
        Console.WriteLine(dobro(21));

        Func<int, int, int> soma = (a, b) => a + b;
        Console.WriteLine(soma(3, 4));

        Action<string> diz = s => Console.WriteLine("ola " + s);
        diz("mundo");

        Predicate<int> par = n => n % 2 == 0;
        Console.WriteLine(par(4));

        Operacao op = (a, b) => a * b;
        Console.WriteLine(op(6, 7));

        Action multi = () => Console.WriteLine("um");
        multi += () => Console.WriteLine("dois");
        multi();
    }
}
```

```text
Saída:
42
7
ola mundo
True
42
um
dois
```

O último exemplo mostra um delegate multicast: com `+=` você encadeia métodos, e a chamada executa todos na ordem. É a base dos eventos em C#.

## Closures: capturando variáveis

Uma lambda pode usar variáveis do método onde nasceu. Ela não copia o valor: captura a própria variável, que continua viva enquanto a lambda existir. Isso é poderoso (um contador privado, por exemplo) e perigoso, como o laço `for` mostra.

```csharp
using System;
using System.Collections.Generic;

class Program
{
    static Func<int> Contador()
    {
        int c = 0;
        return () => ++c;
    }

    static void Main()
    {
        var acoes = new List<Action>();
        for (int i = 0; i < 3; i++)
            acoes.Add(() => Console.Write(i + " "));
        foreach (var a in acoes) a();
        Console.WriteLine();

        var corretas = new List<Action>();
        for (int i = 0; i < 3; i++)
        {
            int copia = i;
            corretas.Add(() => Console.Write(copia + " "));
        }
        foreach (var a in corretas) a();
        Console.WriteLine();

        var f = Contador();
        f();
        f();
        Console.WriteLine(f());

        var palavras = new List<string> { "ccc", "a", "bb" };
        palavras.Sort((x, y) => x.Length.CompareTo(y.Length));
        Console.WriteLine(string.Join(",", palavras));
    }
}
```

```text
Saída:
3 3 3
0 1 2
3
a,bb,ccc
```

No primeiro laço as três lambdas capturam a mesma variável `i`, que vale 3 quando elas rodam. A correção é declarar uma variável nova dentro do corpo (`copia`), que existe separadamente em cada iteração. Em um `foreach`, desde o C# 5 cada iteração já tem sua variável, então o problema aparece no `for`. Em JavaScript o equivalente é o clássico `var` dentro de laços; em Python, closures tardias em compreensões.

## Quando usar

- Critérios de ordenação, `Sort` e `OrderBy`, com chave ou comparação inline.
- Filtros e transformações com LINQ.
- Callbacks e `Dictionary<string, Func<...>>` para despachar operações sem `switch` longo.
- Funções locais (declaradas dentro de um método) quando a recursão ou a lógica auxiliar só interessa ali.

Armadilhas: lambdas que capturam variáveis podem manter objetos vivos mais tempo do que o esperado, e cada lambda com closure aloca um objeto, o que pesa em laços quentes. Um `static` antes da lambda (C# 9) proíbe capturas e evita esse custo.

<Callout type="note" title="Versão necessária">
Desde o C# 10 (.NET 6 ou superior), o compilador infere o tipo da lambda sozinho: `var dobro = (int x) => x * 2;` funciona sem declarar `Func<int, int>`, e lambdas aceitam parâmetros com valor padrão a partir do C# 12. Nas versões antigas o tipo do delegate é obrigatório.
</Callout>

## Na entrevista

Você usa lambdas o tempo todo: `list.Sort((a, b) => a[0].CompareTo(b[0]))` para ordenar intervalos, `OrderBy(p => p.Idade)` e `Where(...)`. Escreva o comparador com `CompareTo` em vez de subtrair (a diferença de dois inteiros pode estourar). Follow-ups comuns: "qual a diferença entre `Func` e `Action`?" e "o que é uma closure?". Se perguntarem do laço `for`, mostre a variável copiada.
