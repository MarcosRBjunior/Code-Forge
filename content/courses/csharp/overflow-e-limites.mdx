Em Python, inteiros crescem sem limite. Em JavaScript, todo número é um `double` de 64 bits, que perde precisão acima de 2 elevado a 53. Em C#, `int` tem 32 bits e `long` tem 64, e passar do limite não avisa nada: o valor simplesmente dá a volta. Esse é um dos bugs mais comuns em soluções de entrevista (somas de prefixo, produtos, ponto médio), e o entrevistador gosta de perguntar "e se os números forem grandes?".

## Os limites

| Tipo | Bits | Faixa aproximada |
| --- | --- | --- |
| `int` | 32 | de menos 2,1 bilhões a mais 2,1 bilhões |
| `long` | 64 | cerca de 9,2 vezes 10 elevado a 18 |
| `uint` | 32 | de 0 a 4,29 bilhões |
| `byte` | 8 | de 0 a 255 |
| `double` | 64 | cerca de 15 dígitos de precisão |
| `decimal` | 128 | 28 dígitos exatos, para dinheiro |

Os valores exatos estão em `int.MaxValue`, `int.MinValue`, `long.MaxValue`, etc. Use essas constantes em vez de números escritos à mão, por exemplo como valor inicial de um mínimo (`int.MaxValue`) ou como infinito em grafos.

## Wrap-around silencioso

Por padrão, a aritmética de inteiros não verifica estouro (contexto `unchecked`): o resultado fica módulo 2 elevado ao número de bits. Dentro de `checked(...)`, o mesmo estouro lança `OverflowException`.

```csharp
using System;

class Program
{
    static void Main()
    {
        int max = int.MaxValue;
        Console.WriteLine(max);

        int w = max + 1;
        Console.WriteLine(w);

        long l = (long)max + 1;
        Console.WriteLine(l);

        try
        {
            int c = checked(max + 1);
            Console.WriteLine(c);
        }
        catch (OverflowException)
        {
            Console.WriteLine("overflow detectado");
        }

        int min = int.MinValue;
        try
        {
            Console.WriteLine(Math.Abs(min));
        }
        catch (OverflowException)
        {
            Console.WriteLine("abs estoura");
        }

        Console.WriteLine(long.MaxValue);

        int big = 100000;
        Console.WriteLine(big * big);
        Console.WriteLine((long)big * big);
    }
}
```

```text
Saída:
2147483647
-2147483648
2147483648
overflow detectado
abs estoura
9223372036854775807
1410065408
10000000000
```

Duas lições: o cast para `long` precisa acontecer antes da operação (`(long)big * big`, e não `(long)(big * big)`, que converte um valor que já estourou); e `Math.Abs(int.MinValue)` lança exceção, porque `+2147483648` não cabe em `int`. Constantes conhecidas em tempo de compilação, como `int.MaxValue + 1` escrito direto, nem compilam; o erro só aparece em tempo de execução quando o valor vem de variável.

## Ponto médio, módulo e conversões

O padrão `(lo + hi) / 2` na busca binária estoura quando `lo` e `hi` são grandes. A forma segura é `lo + (hi - lo) / 2`. Outro ponto é o `%`: em C# o resto tem o sinal do dividendo, então `-7 % 5` vale -2, e não 3 como em Python. Para obter o módulo matemático, some o divisor antes do segundo `%`. Em contas modulares com módulos como 1_000_000_007, o produto de dois valores já estoura `int`, então faça a multiplicação em `long`.

```csharp
using System;

class Program
{
    static int Mod(int a, int m)
    {
        return ((a % m) + m) % m;
    }

    static void Main()
    {
        int lo = 1500000000, hi = 2000000000;
        int ruim = (lo + hi) / 2;
        int bom = lo + (hi - lo) / 2;
        Console.WriteLine(ruim);
        Console.WriteLine(bom);

        Console.WriteLine(-7 / 2);
        Console.WriteLine(-7 % 2);
        Console.WriteLine(Mod(-7, 5));

        long M = 1000000007;
        long a = 999999999, b = 999999999;
        Console.WriteLine((a * b) % M);

        Console.WriteLine(unchecked((int)3000000000L));
    }
}
```

```text
Saída:
-397483648
1750000000
-3
-1
3
64
-1294967296
```

Aqui `-7 / 2` dá -3 (a divisão trunca em direção a zero, e não para baixo como `//` do Python), e o cast de `long` para `int` descarta os bits altos. Se o enunciado fala em valores até 10 elevado a 9 e somas deles, planeje usar `long` desde o início.

## Armadilhas e boas práticas

- Somas de arrays de `int`: se o enunciado permite n grande e valores grandes, acumule em `long`. `nums.Sum()` do LINQ para `int` lança `OverflowException` em estouro (usa contexto checked); `Sum` de `long` não protege se o `long` estourar.
- Comparar `double` com `==` é arriscado; compare com tolerância.
- Divisão inteira por zero lança exceção, mas divisão de `double` por zero dá infinito.
- Evite `Math.Abs` em valores que possam ser `int.MinValue`; troque por um teste de sinal.
- Para números realmente grandes, `System.Numerics.BigInteger` existe, com custo maior.

<Callout type="warning" title="Atenção">
O estouro de `int` não gera erro algum por padrão. Sempre que o enunciado trouxer limites como 10 elevado a 5 ou mais, calcule o pior caso do seu acumulador e, se passar de 2 bilhões, use `long`.
</Callout>
