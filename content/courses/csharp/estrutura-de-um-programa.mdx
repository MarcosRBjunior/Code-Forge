Em entrevista você quase sempre recebe a assinatura de um método e preenche o corpo. Ainda assim, entender como um programa C# é montado evita erros de compilação bobos e ajuda quando o enunciado pede um programa completo, com entrada e saída.

## O menor programa

Todo código C# vive dentro de um tipo, normalmente uma `class`. A execução começa no método `Main`, escrito com M maiúsculo (diferente de Java e Python, C# diferencia maiúsculas de minúsculas).

```csharp
using System;

class Program
{
    static void Main()
    {
        Console.WriteLine("Olá, entrevista!");
    }
}
```

```text
Saída:
Olá, entrevista!
```

`using System;` importa o namespace onde mora `Console`. `static` permite chamar o método sem criar um objeto, e `void` indica que nada é devolvido. Se precisar dos argumentos da linha de comando, a assinatura vira `static void Main(string[] args)`. Também é válido devolver `int` (o código de saída do processo).

## Namespaces e using

O equivalente do `import` é o `using`. As coleções genéricas que você usa em todo problema estão em `System.Collections.Generic`, e o LINQ em `System.Linq`.

```csharp
using System;
using System.Collections.Generic;

class Program
{
    static void Main()
    {
        List<int> numeros = new List<int>();
        numeros.Add(10);
        numeros.Add(20);
        Console.WriteLine(numeros.Count);
        Console.WriteLine(string.Join(", ", numeros));
    }
}
```

```text
Saída:
2
10, 20
```

Note que `Console.WriteLine(numeros)` imprimiria apenas o nome do tipo, porque `List` não sobrescreve `ToString` para mostrar os elementos. Esse é um tropeço clássico de quem vem de Python, onde `print(lista)` mostra o conteúdo. Use `string.Join`.

## Imprimir resultados

Você vai usar `Console.WriteLine` (com quebra de linha) e `Console.Write` (sem quebra). Para montar texto, a forma mais legível é a interpolação com `$`:

```csharp
using System;

class Program
{
    static void Main()
    {
        int soma = 2 + 3;
        Console.WriteLine($"soma = {soma}");
        Console.Write("sem quebra");
        Console.WriteLine();
        Console.WriteLine("{0} e {1}", "a", "b");
    }
}
```

```text
Saída:
soma = 5
sem quebra
a e b
```

Um detalhe para decimais: ao virar texto, `double` usa a cultura do sistema. Em pt-BR, `2.5` sai como `2,5`; em outro ambiente, como `2.5`. Quando a saída precisa ser exata, formate com `CultureInfo.InvariantCulture`. Neste curso, os exemplos executáveis evitam decimais por esse motivo.

## Compilar e executar

O compilador (`csc`, ou o `dotnet build` nos projetos modernos) gera uma assembly (`.dll` ou `.exe`) com código intermediário, que o runtime compila para código nativo na execução. Um erro de sintaxe aparece na compilação, antes de qualquer saída.

## C# moderno: top-level statements

Desde o C# 9 você pode escrever o programa sem classe nem `Main`. O compilador cria o ponto de entrada para você.

```csharp
// Programa.cs (C# 9 ou superior)
using System;

Console.WriteLine("Olá!");
int x = 5;
Console.WriteLine(x * 2); // 10
```

<Callout type="note" title="Versão">
Top-level statements exigem C# 9 (.NET 5 ou superior). Em plataformas de entrevista, confirme a versão antes de usar; a forma com `class Program` funciona em qualquer uma.
</Callout>

## Na entrevista

Quando o enunciado dá uma classe `Solution` com um método a preencher, você não escreve `Main`: o avaliador chama o seu método. Se pedirem um programa completo, escreva `class Program` com `static void Main()` e lembre dos `using` no topo. Follow-ups comuns: "para que serve o `static`?" (chamar sem instância) e "o que acontece se eu esquecer o `using System.Collections.Generic`?" (erro de compilação: o tipo `List` não é encontrado).
