Uma fila de prioridade devolve sempre o elemento "mais urgente", não o mais antigo. É a estrutura por trás de Dijkstra, "os k maiores elementos", mesclagem de listas ordenadas e agendamento de tarefas. Internamente é um heap binário: inserir e remover o menor custam O(log n), e olhar o menor custa O(1).

## O que o C# oferece

O C# tem `PriorityQueue<TElement, TPriority>`, mas só a partir do .NET 6. Em frameworks antigos e em muitas plataformas de entrevista mais velhas ela não existe, e você precisa escrever o heap à mão ou usar `SortedSet`. Vale conhecer os dois caminhos.

## A forma moderna

Ela é um min-heap: `Dequeue` devolve o elemento de menor prioridade.

```csharp
// .NET 6 ou superior
using System;
using System.Collections.Generic;

var pq = new PriorityQueue<string, int>();
pq.Enqueue("baixa", 5);
pq.Enqueue("urgente", 1);
pq.Enqueue("media", 3);

Console.WriteLine(pq.Peek());      // urgente
Console.WriteLine(pq.Dequeue());   // urgente
Console.WriteLine(pq.Count);       // 2

// max-heap: inverta a comparação
var maxHeap = new PriorityQueue<int, int>(Comparer<int>.Create((a, b) => b.CompareTo(a)));
maxHeap.Enqueue(10, 10);
maxHeap.Enqueue(40, 40);
Console.WriteLine(maxHeap.Dequeue()); // 40
```

<Callout type="note" title="Versão">
`PriorityQueue` exige .NET 6 ou superior. O exemplo acima também usa top-level statements (C# 9). Ela não permite alterar a prioridade de um item existente; a técnica comum é inserir de novo e ignorar entradas antigas ao retirar.
</Callout>

Dois detalhes: o elemento e a prioridade são separados (o segundo parâmetro de `Enqueue` é a prioridade), e não há ordem definida entre prioridades iguais.

## Heap escrito à mão

Sem `PriorityQueue`, você implementa um min-heap sobre uma `List<int>`. Um nó `i` tem filhos em `2i+1` e `2i+2` e pai em `(i-1)/2`. Inserir coloca no fim e "sobe"; remover troca a raiz com o último e "desce".

```csharp
using System;
using System.Collections.Generic;

class MinHeap
{
    private List<int> d = new List<int>();

    public int Count { get { return d.Count; } }
    public int Peek() { return d[0]; }

    public void Push(int x)
    {
        d.Add(x);
        int i = d.Count - 1;
        while (i > 0)
        {
            int p = (i - 1) / 2;
            if (d[p] <= d[i]) break;
            int t = d[p]; d[p] = d[i]; d[i] = t;
            i = p;
        }
    }

    public int Pop()
    {
        int topo = d[0];
        int ultimo = d[d.Count - 1];
        d.RemoveAt(d.Count - 1);
        if (d.Count > 0)
        {
            d[0] = ultimo;
            int i = 0;
            while (true)
            {
                int e = 2 * i + 1, r = 2 * i + 2, menor = i;
                if (e < d.Count && d[e] < d[menor]) menor = e;
                if (r < d.Count && d[r] < d[menor]) menor = r;
                if (menor == i) break;
                int t = d[menor]; d[menor] = d[i]; d[i] = t;
                i = menor;
            }
        }
        return topo;
    }
}

class Program
{
    static void Main()
    {
        var h = new MinHeap();
        foreach (int x in new int[] { 9, 4, 7, 1, 8, 2 })
            h.Push(x);
        Console.WriteLine(h.Peek());
        var saida = new List<int>();
        while (h.Count > 0) saida.Add(h.Pop());
        Console.WriteLine(string.Join(" ", saida));
    }
}
```

```text
Saída:
1
1 2 4 7 8 9
```

Para um max-heap, basta inverter as comparações ou inserir os valores negados. Esta versão tem Push e Pop em O(log n).

## Alternativa: SortedSet

`SortedSet<T>` mantém os elementos ordenados (árvore balanceada) e dá `Min` e `Max` em O(log n), além de remoção arbitrária. O problema é que não aceita duplicados. A solução é guardar pares com um desempate, como o próprio índice.

```csharp
using System;
using System.Collections.Generic;

class Program
{
    static void Main()
    {
        // pares (distancia, id): o id desempata e mantém duplicados distintos
        var fila = new SortedSet<KeyValuePair<int, int>>(
            Comparer<KeyValuePair<int, int>>.Create((a, b) =>
            {
                int c = a.Key.CompareTo(b.Key);
                return c != 0 ? c : a.Value.CompareTo(b.Value);
            }));

        fila.Add(new KeyValuePair<int, int>(5, 0));
        fila.Add(new KeyValuePair<int, int>(2, 1));
        fila.Add(new KeyValuePair<int, int>(2, 2));
        fila.Add(new KeyValuePair<int, int>(9, 3));

        var menor = fila.Min;
        fila.Remove(menor);
        Console.WriteLine(menor.Key + " " + menor.Value);
        Console.WriteLine(fila.Min.Key + " " + fila.Min.Value);
        Console.WriteLine(fila.Count);
    }
}
```

```text
Saída:
2 1
2 2
3
```

Essa versão suporta "diminuir prioridade" removendo o par antigo e inserindo o novo, útil em Dijkstra.

## Padrão: os k maiores

Para os k maiores elementos de n, mantenha um min-heap de tamanho k: ao ver um valor maior que a raiz, troque. Custo O(n log k), melhor que ordenar tudo (O(n log n)) quando k é pequeno.

## Na entrevista

Diga "preciso sempre do menor/maior dinamicamente, então uso um heap". Confirme se a versão da linguagem tem `PriorityQueue`; se não, ofereça escrever o heap. Follow-ups comuns: "qual a complexidade de construir um heap com n itens?" (O(n) com heapify, O(n log n) com n inserções) e "como atualizar a prioridade?" (reinserir, ou usar `SortedSet`).
