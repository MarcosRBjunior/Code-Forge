Boa parte das soluções erradas em entrevista não tem falha de algoritmo: tem uma pegadinha da linguagem que o candidato não conhecia. C# é uma linguagem previsível, mas tem comportamentos que surpreendem quem vem de Python ou JavaScript. Este capítulo reúne os que mais custam pontos, com a correção de cada um.

## Alterar a coleção durante o foreach

Remover (ou adicionar) itens de uma `List` enquanto você a percorre com `foreach` invalida o enumerador, e a próxima iteração lança `InvalidOperationException`. A correção depende da intenção: `RemoveAll` com um predicado, um laço `for` de trás para frente, ou iterar sobre uma cópia.

```csharp
using System;
using System.Collections.Generic;

class Program
{
    static void Main()
    {
        var l = new List<int> { 1, 2, 3 };
        try
        {
            foreach (var x in l)
            {
                if (x == 2) l.Remove(x);
            }
        }
        catch (InvalidOperationException)
        {
            Console.WriteLine("colecao modificada");
        }

        l.RemoveAll(x => x == 2);
        Console.WriteLine(string.Join(",", l));

        Console.WriteLine('a' + 1);
        Console.WriteLine((char)('a' + 1));

        double d1 = 0.1, d2 = 0.2, d3 = 0.3;
        Console.WriteLine(d1 + d2 == d3);
        Console.WriteLine(Math.Abs(d1 + d2 - d3) < 1e-9);

        Console.WriteLine(5 / 2);
        Console.WriteLine((double)5 / 2 == 2.5);
    }
}
```

```text
Saída:
colecao modificada
1,3
98
b
False
True
2
True
```

Outras duas armadilhas aparecem aí. Somar um `int` a um `char` produz `int`: `'a' + 1` é 98, e para obter a letra seguinte é preciso o cast `(char)`. E a divisão entre dois `int` descarta a parte fracionária, então basta converter um dos lados para `double` (ou escrever `5 / 2.0`). Quanto aos decimais, `0.1 + 0.2` não é exatamente `0.3` em ponto flutuante, igual a Python e JavaScript; compare por tolerância, ou use `decimal` quando for dinheiro.

## Referências compartilhadas e igualdade

Duas pegadinhas relacionadas a referências são clássicas. A primeira: `Enumerable.Repeat(new List<int>(), 3)` não cria três listas, e sim uma lista repetida três vezes, porque o objeto é criado uma só vez. A segunda: o `==` de dois `object` compara referências, enquanto `Equals` compara conteúdo. Strings são um caso à parte, pois `==` já é sobrescrito para comparar texto.

```csharp
using System;
using System.Collections.Generic;
using System.Linq;

class Program
{
    static void Main()
    {
        var grade = Enumerable.Repeat(new List<int>(), 3).ToList();
        grade[0].Add(7);
        Console.WriteLine(grade[2].Count);

        var certa = new List<List<int>>();
        for (int i = 0; i < 3; i++) certa.Add(new List<int>());
        certa[0].Add(7);
        Console.WriteLine(certa[2].Count);

        object o1 = 1000, o2 = 1000;
        Console.WriteLine(o1 == o2);
        Console.WriteLine(o1.Equals(o2));

        string s = "abc";
        s.ToUpper();
        Console.WriteLine(s);
        s = s.ToUpper();
        Console.WriteLine(s);

        var d = new Dictionary<string, int>();
        try
        {
            int v = d["x"];
            Console.WriteLine(v);
        }
        catch (KeyNotFoundException)
        {
            Console.WriteLine("chave ausente");
        }
    }
}
```

```text
Saída:
1
0
False
True
abc
ABC
chave ausente
```

A grade feita com `Repeat` tem as três posições apontando para a mesma lista, então adicionar em `grade[0]` aparece em `grade[2]`. O mesmo acontece em Python com `[[]] * 3`. Para matrizes, crie cada linha em um laço (ou `Select(_ => new List<int>())`). Strings são imutáveis: métodos como `ToUpper`, `Trim` e `Replace` devolvem um novo valor, e ignorá-lo é um erro silencioso.

## Lista de outras pegadinhas

- Acessar uma chave inexistente do `Dictionary` com o indexador lança `KeyNotFoundException`. Use `TryGetValue` ou `ContainsKey`.
- `Substring(i, n)` recebe o comprimento, não o índice final, ao contrário de `slice` do JavaScript. Passar do fim lança `ArgumentOutOfRangeException`.
- `Array.Sort` e `List.Sort` não são estáveis; `OrderBy` do LINQ é. Se a ordem de empates importa, use LINQ ou um critério completo.
- `string.Split` devolve entradas vazias entre separadores repetidos, a menos que você passe `StringSplitOptions.RemoveEmptyEntries`.
- Comparar strings com `==` é correto em C#, mas `ReferenceEquals` não; e a ordenação padrão de strings depende da cultura, então use `string.CompareOrdinal` quando a ordem precisa ser previsível.
- Variáveis locais precisam ser atribuídas antes do uso (erro de compilação, ao contrário de Python), e arrays de tipos de referência começam cheios de `null`.
- Um `switch` exige `break` (ou `return`) em cada caso: não há fall-through automático.
- O operador `&&` e `||` faz curto-circuito; `&` e `|` avaliam os dois lados.

<Callout type="warning" title="Atenção">
Remover itens de uma lista dentro de um laço é o bug de entrevista mais frequente em C#. Diga em voz alta qual estratégia você escolhe: percorrer ao contrário com `for`, ou `RemoveAll`.
</Callout>

Depois de escrever o código, rode mentalmente um caso de borda: entrada vazia, um elemento, todos iguais, valores negativos. Isso pega a maioria dessas armadilhas.
