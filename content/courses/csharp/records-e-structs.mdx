Toda classe em C# é um tipo de referência: a variável guarda um endereço, e copiar a variável copia só o endereço. Isso é ótimo para objetos grandes, mas é um exagero para coisas pequenas como um ponto, um par de inteiros ou uma coordenada de grade. Para esses casos existem as structs (tipos de valor), e, mais recentemente, os records, que cuidam da igualdade e da cópia que você escreveria à mão.

## struct: tipo de valor

Uma struct é copiada por inteiro na atribuição e na passagem a métodos. Variáveis de struct guardam os dados diretamente (na pilha ou dentro do objeto que as contém), sem alocação separada. É o contrário do que acontece com classes, e o programa abaixo mostra a diferença.

```csharp
using System;

struct Ponto
{
    public int X, Y;
    public Ponto(int x, int y) { X = x; Y = y; }
}

class Caixa
{
    public int V;
}

class Program
{
    static void Mexe(Ponto p) { p.X = 500; }

    static void Main()
    {
        Ponto a = new Ponto(1, 2);
        Ponto b = a;
        b.X = 99;
        Console.WriteLine(a.X + " " + b.X);

        Caixa c1 = new Caixa { V = 1 };
        Caixa c2 = c1;
        c2.V = 99;
        Console.WriteLine(c1.V + " " + c2.V);

        Mexe(a);
        Console.WriteLine(a.X);

        var arr = new Ponto[2];
        arr[0].X = 5;
        Console.WriteLine(arr[0].X + " " + arr[1].X);
    }
}
```

```text
Saída:
1 99
99 99
1
5 0
```

A struct `b` é uma cópia independente de `a`; já `c1` e `c2` apontam para o mesmo objeto. `Mexe` recebeu uma cópia, então `a` ficou intacto. E o array de structs já nasce preenchido com valores zerados, sem alocar um objeto por posição. Python e JavaScript não têm equivalente direto: lá tudo composto é referência (tuplas e objetos), então o "copiar muda o original?" é uma pergunta nova para quem vem dessas linguagens.

## Structs como chaves e igualdade

Um uso muito comum em entrevistas é guardar coordenadas em `HashSet` ou como chave de `Dictionary`. A igualdade padrão de uma struct compara campo a campo, mas pode usar reflexão e é lenta. Para um código correto e rápido, implemente `IEquatable<T>`, `Equals(object)` e `GetHashCode`.

```csharp
using System;
using System.Collections.Generic;

struct Par : IEquatable<Par>
{
    public readonly int A, B;
    public Par(int a, int b) { A = a; B = b; }
    public bool Equals(Par o) { return A == o.A && B == o.B; }
    public override bool Equals(object o) { return o is Par && Equals((Par)o); }
    public override int GetHashCode() { return A * 31 + B; }
    public override string ToString() { return "(" + A + "," + B + ")"; }
}

class Program
{
    static void Main()
    {
        var set = new HashSet<Par>();
        set.Add(new Par(1, 2));
        set.Add(new Par(1, 2));
        set.Add(new Par(2, 1));
        Console.WriteLine(set.Count);
        Console.WriteLine(set.Contains(new Par(2, 1)));

        var d = new Dictionary<Par, string>();
        d[new Par(0, 0)] = "origem";
        Console.WriteLine(d[new Par(0, 0)]);
        Console.WriteLine(new Par(3, 4));
    }
}
```

```text
Saída:
2
True
origem
(3,4)
```

Repare que dois `Par(1, 2)` distintos contam como um só no conjunto: a igualdade é por valor. Com uma classe sem `Equals` próprio, seriam dois elementos, porque a igualdade padrão compara referências.

## record: igualdade e cópia prontas

Um record declara um tipo de dados com igualdade por valor, `ToString` legível e cópia com alteração, tudo gerado pelo compilador. A forma posicional é uma linha só:

```csharp
public record Pessoa(string Nome, int Idade);

var a = new Pessoa("Ana", 30);
var b = new Pessoa("Ana", 30);
Console.WriteLine(a == b);            // True: igualdade por valor
var c = a with { Idade = 31 };        // cópia alterando um campo
Console.WriteLine(c);                 // Pessoa { Nome = Ana, Idade = 31 }

public readonly record struct Celula(int Linha, int Coluna);  // struct imutável
```

<Callout type="note" title="Versão necessária">
Records exigem C# 9 (.NET 5 ou superior) e `record struct`, C# 10 (.NET 6 ou superior). O ambiente de execução dos exemplos completos acima usa um compilador antigo, por isso eles foram escritos com structs tradicionais. Em projetos atuais, prefira o record.
</Callout>

## Quando usar cada um

| Situação | Escolha |
| --- | --- |
| Valor pequeno e imutável (coordenada, par) | struct (ou record struct) |
| Objeto com identidade e comportamento | class |
| Dado imutável com igualdade por valor | record |
| Muitos elementos num array, sem alocação por item | struct |

Armadilhas: structs mutáveis são fontes de bug (você altera uma cópia sem perceber, como em `Mexe`), então prefira `readonly`. Structs grandes (acima de uns 16 bytes) custam caro para copiar a cada chamada. E evite o boxing: tratar uma struct como `object` ou interface empacota o valor na heap.

## Na entrevista

Coordenadas de grade, arestas de grafo e pares (distância, nó) são candidatos naturais a struct ou tupla. Se a chave de um `HashSet` for sua struct, lembre-se de `GetHashCode`. Follow-ups comuns: "qual a diferença entre struct e class?" e "o que é boxing?".
