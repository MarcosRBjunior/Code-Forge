Uma classe agrupa dados e comportamento. Em entrevistas de projeto de baixo nível (LLD) e até em problemas de estrutura de dados, como lista encadeada, árvore e cache, você descreve um tipo com campos, construtores e métodos. C# tem uma sintaxe própria e enxuta para isso, com propriedades no lugar dos getters e setters de Java.

## Campos, construtores e métodos

Um campo guarda estado; o construtor tem o nome da classe e inicializa o objeto; métodos de instância operam sobre esse estado. O modificador `private` esconde o membro fora da classe, `public` o expõe. Por padrão, membros de classe são `private`.

```csharp
using System;

class Contador
{
    private int valor;

    public Contador(int inicial)
    {
        valor = inicial;
    }

    public void Incrementar()
    {
        valor++;
    }

    public int Valor()
    {
        return valor;
    }
}

class Program
{
    static void Main()
    {
        Contador c = new Contador(10);
        c.Incrementar();
        c.Incrementar();
        Console.WriteLine(c.Valor());

        Contador d = c;       // mesma instância
        d.Incrementar();
        Console.WriteLine(c.Valor());
    }
}
```

```text
Saída:
12
13
```

Como classes são tipos de referência, `d = c` não copia o objeto: as duas variáveis apontam para o mesmo.

## Propriedades

Em vez de métodos `GetX` e `SetX`, C# usa propriedades: elas se lêem e escrevem como campos, mas podem ter lógica. A forma automática `public int X { get; set; }` cria o campo escondido para você. Você controla a escrita deixando o `set` privado.

```csharp
using System;

class ContaBancaria
{
    public string Titular { get; private set; }
    public decimal Saldo { get; private set; }

    public ContaBancaria(string titular)
    {
        Titular = titular;
        Saldo = 0;
    }

    public bool Sacar(decimal quantia)
    {
        if (quantia <= 0 || quantia > Saldo) return false;
        Saldo -= quantia;
        return true;
    }

    public void Depositar(decimal quantia)
    {
        if (quantia <= 0) throw new ArgumentException("quantia invalida");
        Saldo += quantia;
    }
}

class Program
{
    static void Main()
    {
        var conta = new ContaBancaria("Marta");
        conta.Depositar(100);
        Console.WriteLine(conta.Sacar(30));
        Console.WriteLine(conta.Sacar(500));
        Console.WriteLine(conta.Saldo);
        // conta.Saldo = 1;   // erro: o set é privado
    }
}
```

```text
Saída:
True
False
70
```

Esse é o encapsulamento: o estado só muda por métodos que protegem a regra de negócio (nenhum saldo negativo).

## Membros estáticos e this

Um membro `static` pertence à classe, e não a cada objeto. É útil para contadores globais e métodos utilitários. Dentro de um método de instância, `this` é o próprio objeto; ele resolve ambiguidade entre campo e parâmetro e permite encadear construtores com `: this(...)`.

```csharp
using System;

class No
{
    public int Valor;
    public No Proximo;

    public static int Criados = 0;

    public No(int valor)
    {
        Valor = valor;
        Proximo = null;
        Criados++;
    }

    public No(int valor, No proximo) : this(valor)
    {
        Proximo = proximo;
    }
}

class Program
{
    static int Tamanho(No cabeca)
    {
        int n = 0;
        for (No atual = cabeca; atual != null; atual = atual.Proximo) n++;
        return n;
    }

    static void Main()
    {
        No lista = new No(1, new No(2, new No(3)));
        Console.WriteLine(Tamanho(lista));
        Console.WriteLine(No.Criados);
        Console.WriteLine(lista.Proximo.Proximo.Valor);
    }
}
```

```text
Saída:
3
3
3
```

Esse molde de `No` com `Valor` e `Proximo` é o que você escreve em problemas de lista encadeada ou árvore. Campos públicos simples são aceitáveis em entrevista por brevidade; em código de produção, prefira propriedades.

## Sobrescrevendo ToString e Equals

Todo objeto herda de `object` os métodos `ToString`, `Equals` e `GetHashCode`. Sobrescreva `ToString` para depurar, e `Equals` com `GetHashCode` quando quiser comparar por valor ou usar o tipo como chave de dicionário.

```csharp
using System;

class Ponto
{
    public int X, Y;
    public Ponto(int x, int y) { X = x; Y = y; }

    public override string ToString() { return "(" + X + "," + Y + ")"; }

    public override bool Equals(object obj)
    {
        Ponto o = obj as Ponto;
        return o != null && o.X == X && o.Y == Y;
    }

    public override int GetHashCode() { return X * 31 + Y; }
}

class Program
{
    static void Main()
    {
        var a = new Ponto(1, 2);
        var b = new Ponto(1, 2);
        Console.WriteLine(a);
        Console.WriteLine(a == b);
        Console.WriteLine(a.Equals(b));
    }
}
```

```text
Saída:
(1,2)
False
True
```

O `==` continua comparando referências, a menos que você sobrecarregue o operador. Em C# moderno, `record` gera igualdade por valor automaticamente (veja o capítulo de records).

## Armadilhas

- Esquecer de inicializar campos de referência: eles começam em `null`, e acessar um membro lança `NullReferenceException`.
- Expor coleções internas diretamente, permitindo que qualquer um as modifique.
- Confundir copiar a referência com copiar o objeto.
