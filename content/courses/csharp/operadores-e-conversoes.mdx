Boa parte dos bugs de entrevista em C# não está no algoritmo, mas em uma divisão inteira, em uma conversão que perde dados ou em um overflow silencioso. Conhecer os operadores e as regras de conversão evita essas surpresas.

## Operadores aritméticos

Os usuais: `+ - * / %`. Há duas pegadinhas para quem vem de Python:

- A divisão entre dois inteiros é inteira e trunca em direção a zero: `7 / 2` vale `3` e `-7 / 2` vale `-3` (em Python, `-7 // 2` dá `-4`).
- O resto `%` tem o sinal do dividendo: `-7 % 3` vale `-1`, não `2`. Para um módulo sempre não negativo, use `((x % m) + m) % m`.

```csharp
using System;

class Program
{
    static void Main()
    {
        Console.WriteLine(7 / 2);
        Console.WriteLine(-7 / 2);
        Console.WriteLine(-7 % 3);
        Console.WriteLine(((-7 % 3) + 3) % 3);
        Console.WriteLine(7 / 2.0 > 3.4);
        int x = 5;
        x += 2;
        x++;
        Console.WriteLine(x);
        Console.WriteLine(x++ + ++x);
    }
}
```

```text
Saída:
3
-3
-1
2
True
8
18
```

A última linha: `x++` devolve 8 e depois vira 9; `++x` incrementa para 10 e devolve 10. Soma: 18. Evite esse tipo de expressão no código real.

## Comparação e lógicos

`==`, `!=`, `<`, `>`, `<=`, `>=` comparam valores. Os lógicos são `&&`, `||` e `!`, todos com curto-circuito: `a != null && a.Length > 0` não estoura se `a` for nulo. Os operadores `&` e `|` sobre `bool` não fazem curto-circuito. Para bits, use `& | ^ ~ << >>`.

Cuidado: `==` em `string` compara o conteúdo (o operador é sobrecarregado), mas em outras classes compara a referência, a menos que o tipo sobrescreva `Equals`.

## Conversão implícita e explícita

O compilador converte sozinho quando não há perda: de `int` para `long`, de `int` para `double`. Quando pode haver perda, exige um cast explícito.

```csharp
using System;

class Program
{
    static void Main()
    {
        int i = 10;
        long l = i;               // implícita
        double d = 3.99;
        int t = (int)d;           // explícita, trunca
        Console.WriteLine(t);

        char c = 'a';
        int cod = c;              // char vira int
        char prox = (char)(c + 1);
        Console.WriteLine(cod);
        Console.WriteLine(prox);

        int soma = 7;
        int cont = 2;
        double media = (double)soma / cont;
        Console.WriteLine(media == 3.5);

        string s = "123";
        int n = int.Parse(s) + 1;
        Console.WriteLine(n);
        int ok;
        Console.WriteLine(int.TryParse("abc", out ok));
    }
}
```

```text
Saída:
3
97
b
True
124
False
```

Pontos importantes: o cast para `int` trunca (não arredonda); use `Math.Round` se precisar arredondar. Em `(double)soma / cont`, o cast acontece antes da divisão, então ela é decimal; escrever `(double)(soma / cont)` faria a divisão inteira primeiro e perderia a fração. E `c + 1` é `int`, por isso o cast de volta para `char`.

## Parse e TryParse

`int.Parse` lança exceção se o texto for inválido. `int.TryParse` devolve `false` e não lança, e é a escolha certa para entrada não confiável. Em C# 7 você pode escrever `int.TryParse(s, out int n)` declarando a variável na hora.

## Overflow

Por padrão, a aritmética inteira não checada simplesmente dá a volta: `int.MaxValue + 1` vira `int.MinValue`. Um bloco `checked` faz o programa lançar `OverflowException`. Veja o capítulo dedicado a limites numéricos.

## Na entrevista

Sempre pergunte (ou confirme) as faixas de entrada para decidir entre `int` e `long`. Ao calcular média de dois índices, prefira `lo + (hi - lo) / 2` a `(lo + hi) / 2`. Follow-ups comuns: "o que `7 / 2` retorna?" e "como obter 3.5?" (promover um operando a `double`).
