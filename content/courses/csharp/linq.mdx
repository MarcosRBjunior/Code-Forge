Boa parte do código de entrevista é transformar coleções: filtrar, mapear, agrupar, somar, achar o maior. Em Python você usa compreensões de lista e `sorted`; em JavaScript, `filter`, `map` e `reduce`. Em C#, o equivalente é LINQ (Language Integrated Query): um conjunto de métodos de extensão em `System.Linq` que funcionam sobre qualquer `IEnumerable<T>`, ou seja, arrays, listas, conjuntos, dicionários e strings.

Para usar, basta o `using System.Linq;` no topo. Cada método devolve uma nova sequência, e você encadeia as chamadas.

## Os operadores essenciais

| Operador | Equivalente | Para que serve |
| --- | --- | --- |
| `Where(p)` | `filter` | mantém os itens que satisfazem p |
| `Select(f)` | `map` | transforma cada item |
| `OrderBy(k)` e `OrderByDescending(k)` | `sorted` com chave | ordena (estável) |
| `GroupBy(k)` | agrupar em dicionário | agrupa por chave |
| `Sum`, `Min`, `Max`, `Average`, `Count` | funções de agregação | reduz a um número |
| `Any(p)` e `All(p)` | `any` e `all` | existe algum, todos |
| `First`, `FirstOrDefault` | `next(...)` | primeiro item |
| `Take(n)` e `Skip(n)` | fatiar | primeiros n, pular n |
| `ToList`, `ToArray`, `ToDictionary` | materializar | força a execução |

```csharp
using System;
using System.Linq;

class Program
{
    static void Main()
    {
        int[] nums = { 5, 3, 8, 1, 9, 2 };

        var pares = nums.Where(n => n % 2 == 0).ToList();
        Console.WriteLine(string.Join(",", pares));

        var quad = nums.Select(n => n * n);
        Console.WriteLine(string.Join(",", quad));

        Console.WriteLine(nums.Sum());
        Console.WriteLine(nums.Max());
        Console.WriteLine(nums.OrderBy(n => n).First());
        Console.WriteLine(string.Join(",", nums.OrderByDescending(n => n).Take(3)));
        Console.WriteLine(nums.Any(n => n > 8));
        Console.WriteLine(nums.All(n => n > 1));
    }
}
```

```text
Saída:
8,2
25,9,64,1,81,4
28
9
1
9,8,5
True
False
```

A seta `=>` define uma lambda (função anônima); o próximo capítulo detalha isso. O mais importante agora é o encadeamento: `Where` entrega os itens filtrados a `Select`, que entrega a `OrderBy`, e assim por diante, sem variáveis intermediárias.

## Execução adiada

Esse é o ponto que mais derruba candidatos. `Where` e `Select` não rodam quando você os chama: eles montam uma consulta que só executa quando você itera o resultado (`foreach`, `ToList`, `Count()`, `Sum()` etc.). Se a coleção original mudar entre a definição e o uso, o resultado reflete a mudança. Chamar `ToList()` tira uma foto naquele momento.

```csharp
using System;
using System.Collections.Generic;
using System.Linq;

class Program
{
    static void Main()
    {
        var palavras = new List<string> { "banana", "abacate", "uva", "avela", "bolo", "kiwi" };

        foreach (var g in palavras.GroupBy(p => p[0]))
            Console.WriteLine(g.Key + ": " + string.Join(",", g));

        var lista = new List<int> { 1, 2, 3 };
        var maiores = lista.Where(n => n > 1);
        lista.Add(10);
        Console.WriteLine(maiores.Count());

        var foto = lista.Where(n => n > 1).ToList();
        lista.Add(20);
        Console.WriteLine(foto.Count);

        var tamanhos = palavras.ToDictionary(p => p, p => p.Length);
        Console.WriteLine(tamanhos["kiwi"]);
    }
}
```

```text
Saída:
b: banana,bolo
a: abacate,avela
u: uva
k: kiwi
3
3
4
```

`maiores` só foi avaliado na linha do `Count()`, depois do `Add(10)`, por isso contou 2, 3 e 10. Já `foto` guardou três itens e ignorou o `Add(20)` posterior. Observe também que `GroupBy` preserva a ordem da primeira aparição de cada chave.

## Custos e armadilhas

- LINQ é conveniente, mas cada etapa tem custo. `Count()` num `IEnumerable` percorre tudo (O(n)), embora para `List` e arrays seja otimizado; prefira a propriedade `Count` ou `Length` quando existir.
- Iterar a mesma consulta duas vezes executa a consulta duas vezes. Se ela é cara, materialize com `ToList()`.
- `First()` lança exceção em sequência vazia; `FirstOrDefault()` devolve o padrão do tipo (0, null).
- `OrderBy` custa O(n log n). Para achar só o maior, use `Max()` (O(n)), e não `OrderByDescending(...).First()`.
- Modificar a coleção dentro do `foreach` sobre ela lança `InvalidOperationException`.
- Em laços muito quentes ou com restrições de desempenho, um `for` simples pode ser mais rápido que a cadeia LINQ.

<Callout type="note" title="Versão necessária">
Alguns operadores são recentes. `MinBy`, `MaxBy`, `Chunk` e `DistinctBy` exigem .NET 6 ou superior, e `CountBy` e `Index` exigem .NET 9. Exemplo: `pessoas.MaxBy(p => p.Idade)` devolve a pessoa mais velha, e `nums.Chunk(3)` divide em blocos de 3. Nas versões antigas, use `OrderByDescending(...).First()` ou um laço.
</Callout>

## Na entrevista

Use LINQ para contagens, agrupamentos e verificações curtas ("existe duplicata?" vira `nums.Distinct().Count() != nums.Length`). Mas, se o problema pede uma complexidade específica, descreva o custo real: um `Contains` dentro de um `Where` sobre lista é O(n²). Muitos entrevistadores aceitam LINQ para o miolo, mas esperam o laço explícito quando o foco é o algoritmo. Follow-ups comuns: "o que é execução adiada?" e "qual a diferença entre `Select` e `SelectMany`?" (o segundo achata sequências de sequências).
