Saber a sintaxe não basta: em entrevista, o que você faz nos primeiros minutos e como organiza o código conta tanto quanto o algoritmo. Este capítulo mostra um molde que funciona para a maioria dos problemas de estruturas de dados, com C# em mente, e dois exemplos resolvidos de ponta a ponta.

## O roteiro

1. **Reformule e esclareça.** Repita o problema com suas palavras e pergunte pelos limites (tamanho da entrada, valores negativos, duplicatas, entrada vazia). Isso também define se `int` basta.
2. **Dê um exemplo e um caso de borda.** Escreva a entrada e a saída esperada à mão.
3. **Comece pela força bruta.** Diga a ideia mais simples e o custo dela. Mostra que você entendeu o problema e dá um ponto de partida.
4. **Otimize.** Pergunte "o que estou recalculando?". Quase sempre a resposta é um `Dictionary`, um `HashSet`, duas posições (ponteiros) ou uma ordenação.
5. **Codifique com calma.** Nomes claros, um método, funções auxiliares apenas se ajudarem.
6. **Teste com seus exemplos.** Percorra o código linha a linha com o caso de borda.
7. **Declare a complexidade** de tempo e de espaço.

## O formato do código

Plataformas costumam dar uma classe com a assinatura do método. Escreva o método estático ou de instância conforme o esqueleto, devolva o tipo pedido e deixe as validações de borda no começo (retorne cedo). Se precisar rodar localmente, um `Main` com alguns testes impressos basta.

## Exemplo 1: Two Sum com Dictionary

Dado um array e um alvo, ache os índices de dois elementos que somam o alvo. A força bruta testa todos os pares, O(n²). A otimização: ao visitar `x`, o que falta é `alvo - x`; se já vimos esse valor, acabou. Guardar o que foi visto num dicionário dá O(n).

```csharp
using System;
using System.Collections.Generic;

class Program
{
    static int[] TwoSum(int[] nums, int alvo)
    {
        var visto = new Dictionary<int, int>();
        for (int i = 0; i < nums.Length; i++)
        {
            int falta = alvo - nums[i];
            int j;
            if (visto.TryGetValue(falta, out j)) return new int[] { j, i };
            visto[nums[i]] = i;
        }
        return new int[0];
    }

    static void Imprime(int[] r)
    {
        Console.WriteLine(r.Length == 0 ? "sem resposta" : string.Join(" ", r));
    }

    static void Main()
    {
        Imprime(TwoSum(new int[] { 2, 7, 11, 15 }, 9));
        Imprime(TwoSum(new int[] { 3, 3 }, 6));
        Imprime(TwoSum(new int[] { 1, 2 }, 10));
        Imprime(TwoSum(new int[0], 5));
    }
}
```

```text
Saída:
0 1
0 1
sem resposta
sem resposta
```

Repare nos detalhes que o molde pede. A consulta ao dicionário acontece antes da inserção, para não emparelhar um elemento com ele mesmo (o caso `3, 3` funciona porque o primeiro 3 já foi guardado). A saída para "não achou" é um array vazio, decisão que você deve combinar com o entrevistador. O custo é O(n) em tempo e O(n) em espaço.

## Exemplo 2: janela deslizante

Maior substring sem caracteres repetidos. Força bruta: testar todas as substrings, O(n³) ou O(n²). Ideia melhor: manter uma janela `[ini, i]` sem repetidos e, quando o caractere atual já está dentro dela, empurrar o início para depois da última aparição. Guardar a última posição de cada caractere num dicionário torna cada passo O(1).

```csharp
using System;
using System.Collections.Generic;

class Program
{
    static int Maior(string s)
    {
        var ultimo = new Dictionary<char, int>();
        int ini = 0, melhor = 0;
        for (int i = 0; i < s.Length; i++)
        {
            int p;
            if (ultimo.TryGetValue(s[i], out p) && p >= ini) ini = p + 1;
            ultimo[s[i]] = i;
            melhor = Math.Max(melhor, i - ini + 1);
        }
        return melhor;
    }

    static void Main()
    {
        string[] casos = { "abcabcbb", "bbbbb", "", "pwwkew", "abba" };
        foreach (string c in casos)
            Console.WriteLine("'" + c + "' -> " + Maior(c));
    }
}
```

```text
Saída:
'abcabcbb' -> 3
'bbbbb' -> 1
'' -> 0
'pwwkew' -> 3
'abba' -> 2
```

O caso `abba` é o que derruba quem esquece a condição `p >= ini`: a letra `a` final está no dicionário, mas fora da janela atual, e não deve mover o início para trás. Testar essa borda mentalmente é exatamente o passo 6.

## Armadilhas do processo

- Codificar sem combinar os limites e, depois, descobrir que o `int` estoura.
- Pular a força bruta e travar na otimização.
- Escrever sem falar: o entrevistador avalia seu raciocínio, não só o resultado.
- Não testar o caso vazio e o de um elemento.
- Código com nomes de uma letra que você mesmo se perde ao revisar.

<Callout type="tip" title="Dica">
Diga o padrão em voz alta: "isso é uma janela deslizante", "isso pede um dicionário de frequências". Reconhecer o padrão é metade da entrevista, e a escolha da estrutura de dados costuma decidir a complexidade.
</Callout>

Reserve os últimos minutos para a análise final: tempo, espaço e possíveis melhorias ("se a entrada não coubesse na memória, eu leria em blocos"). Follow-ups comuns: "e se o array estiver ordenado?" (dois ponteiros, O(1) de espaço), "e se houver vários pares?" e "como você testaria isso?".
