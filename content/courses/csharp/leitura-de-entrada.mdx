Plataformas de entrevista com um método pronto (estilo LeetCode) entregam os dados como argumentos. Já em maratonas, testes online de empresas e plataformas de estilo Codeforces ou HackerRank, o programa recebe tudo pela entrada padrão (`stdin`) e precisa imprimir o resultado na saída padrão. Aqui o C# tem poucas armadilhas, mas elas custam um veredito de "erro" ou "tempo excedido" se você não as conhece.

## Console.ReadLine e Split

`Console.ReadLine()` lê uma linha e devolve `string`, ou `null` quando a entrada acabou (fim de arquivo). O padrão para uma linha de números é `Split` seguido de conversão. Para testar sem digitar, o programa abaixo redireciona a entrada para um texto fixo com `Console.SetIn`; num programa real, você simplesmente omite essa linha e o `Console.ReadLine` lê do teclado ou do arquivo redirecionado.

```csharp
using System;
using System.IO;
using System.Linq;

class Program
{
    static void Main()
    {
        Console.SetIn(new StringReader("3\n10 20 30\nabc def\n"));

        int n = int.Parse(Console.ReadLine());
        int[] v = Console.ReadLine().Split(' ').Select(s => int.Parse(s)).ToArray();
        long soma = 0;
        foreach (int x in v) soma += x;
        Console.WriteLine("n=" + n);
        Console.WriteLine("soma=" + soma);

        string[] palavras = Console.ReadLine().Split(' ');
        Console.WriteLine(palavras[1] + " " + palavras[0]);
        Console.WriteLine(Console.ReadLine() == null);
    }
}
```

```text
Saída:
n=3
soma=60
def abc
True
```

A última linha confirma o contrato: depois de consumir tudo, `ReadLine` devolve `null`. Se o código chamar `.Split` nesse `null`, vem uma `NullReferenceException`. Também vale lembrar que `Split(' ')` produz entradas vazias quando há espaços duplicados ou à direita; para entradas bagunçadas, use `Split(new char[] { ' ' }, StringSplitOptions.RemoveEmptyEntries)` ou `Trim()` antes. Em Python você usaria `input().split()`, que já descarta os vazios.

## Ler tudo de uma vez

Para entradas grandes, ler por tokens é mais simples e robusto do que linha a linha: leia o texto inteiro, divida por espaços e quebras de linha, e consuma os tokens em sequência. Para a saída, acumule num `StringBuilder` e imprima uma vez no final: chamar `Console.WriteLine` em um laço de 10 elevado a 5 iterações é bem mais lento, porque cada chamada descarrega a saída.

```csharp
using System;
using System.IO;
using System.Text;

class Program
{
    static void Main()
    {
        Console.SetIn(new StringReader("5 3\n1 2 3 4 5\n"));
        string tudo = Console.In.ReadToEnd();
        string[] tk = tudo.Split(new char[] { ' ', '\n', '\r' }, StringSplitOptions.RemoveEmptyEntries);

        int n = int.Parse(tk[0]);
        int k = int.Parse(tk[1]);
        long soma = 0;
        for (int i = 0; i < n; i++) soma += long.Parse(tk[2 + i]);

        var sb = new StringBuilder();
        sb.AppendLine("n=" + n + " k=" + k);
        sb.AppendLine("soma=" + soma);
        Console.Write(sb.ToString());

        Console.SetIn(new StringReader("a\nb\nc"));
        string linha;
        int cont = 0;
        while ((linha = Console.ReadLine()) != null) cont++;
        Console.WriteLine("linhas=" + cont);
    }
}
```

```text
Saída:
n=5 k=3
soma=15
linhas=3
```

O laço `while ((linha = Console.ReadLine()) != null)` é o idioma clássico para ler até o fim quando não se sabe quantas linhas existem. A atribuição dentro da condição devolve o valor atribuído, que é comparado com `null`.

## Escolhendo a ferramenta

| Situação | Abordagem |
| --- | --- |
| Poucas linhas | `Console.ReadLine` e `Split` |
| Até 10 elevado a 5 números | Ler tudo com `ReadToEnd` e dividir |
| Entrada enorme (acima de 10 elevado a 6) | `StreamReader` com buffer grande sobre `Console.OpenStandardInput()` |
| Saída com muitas linhas | `StringBuilder` e uma única escrita |
| Quantidade desconhecida de linhas | `while` até `ReadLine` devolver `null` |

Para entradas realmente grandes, a abordagem mais rápida é abrir um `StreamReader` com buffer grande e um `StreamWriter` com `AutoFlush` desligado, e só descarregar no final.

## Armadilhas

- A linha final pode ter `\r` (arquivos do Windows): `Trim()` resolve, e `ReadLine` já trata isso.
- `int.Parse` falha se houver espaço ou caractere inesperado; `Trim()` antes e `TryParse` quando a entrada não for confiável.
- Valores acima de 2 bilhões: use `long.Parse`, e não `int.Parse`.
- O separador decimal depende da cultura. Para ler números reais em plataformas de prova, use `double.Parse(s, System.Globalization.CultureInfo.InvariantCulture)`.
- Imprimir com `Console.Write` seguido de `\n` ou `WriteLine` muda só o terminador; confira o formato exato esperado, inclusive a linha final.

<Callout type="tip" title="Dica">
Defina seus utilitários de leitura no começo (um método `LerInts()` que devolve `int[]`) e reuse. Digitar o mesmo `Split` e `Select` dez vezes é fonte de erro e gasta tempo de prova.
</Callout>
