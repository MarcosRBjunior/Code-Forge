Tony Hoare chamou a referência nula de seu "erro de bilhão de dólares", e quem vem de Python (`None`) ou JavaScript (`null` e `undefined`) conhece o sintoma: `AttributeError` ou `TypeError` ao acessar algo que não existe. Em C# o equivalente é a `NullReferenceException`, provavelmente a exceção mais comum do ecossistema. O capítulo cobre duas ferramentas diferentes: valores anuláveis (`int?`) e os operadores que lidam com null de forma segura.

## Tipos de valor que aceitam null

Um `int` sempre tem valor; não existe "ausente". Para representar a ausência (um campo opcional, o resultado de uma busca que pode falhar), o sufixo `?` cria um `Nullable<T>`: `int?`, `double?`, `bool?`. Ele guarda o valor e um indicador de presença.

```csharp
using System;

class Program
{
    static void Main()
    {
        int? a = null;
        int? b = 5;
        Console.WriteLine(a.HasValue);
        Console.WriteLine(b.HasValue);
        Console.WriteLine(a ?? -1);
        Console.WriteLine(b.Value + 1);
        Console.WriteLine(a.GetValueOrDefault());
        Console.WriteLine("[" + a + "]");

        int? soma = a + b;
        Console.WriteLine(soma.HasValue);
        Console.WriteLine(a == null);
        Console.WriteLine(a < 1);
    }
}
```

```text
Saída:
False
True
-1
6
0
[]
False
True
False
```

Note três comportamentos. Aritmética com um operando nulo produz nulo (`a + b` não tem valor). Comparações com nulo como `a < 1` dão `false`, não erro. E ler `.Value` de um `int?` vazio lança `InvalidOperationException`, então teste `HasValue` ou use `??` antes.

## Operadores ?. e ??

O operador de navegação segura `?.` interrompe a cadeia quando encontra null e devolve null. O de coalescência `??` fornece um valor alternativo. Juntos eles eliminam a maior parte dos `if (x != null)`.

```csharp
using System;
using System.Collections.Generic;

class Pessoa
{
    public string Nome;
    public Pessoa Chefe;
}

class Program
{
    static void Main()
    {
        var ana = new Pessoa { Nome = "Ana" };
        var beto = new Pessoa { Nome = "Beto", Chefe = ana };

        Console.WriteLine(beto.Chefe.Nome);
        Console.WriteLine(ana.Chefe == null);

        string nomeChefe = ana.Chefe?.Nome;
        Console.WriteLine(nomeChefe == null);
        Console.WriteLine(ana.Chefe?.Nome ?? "sem chefe");
        Console.WriteLine(beto.Chefe?.Nome ?? "sem chefe");

        int? tamanho = ana.Nome?.Length;
        Console.WriteLine(tamanho);

        var d = new Dictionary<string, int> { { "a", 1 } };
        int v;
        if (d.TryGetValue("b", out v)) Console.WriteLine(v);
        else Console.WriteLine("ausente");
    }
}
```

```text
Saída:
Ana
True
True
sem chefe
Ana
3
ausente
```

Em `ana.Chefe?.Nome`, como `Chefe` é null, o `.Nome` nem é avaliado. Observe que o resultado de `?.` sobre um `int` vira `int?`, por isso `tamanho` precisou ser anulável. Para coleções, `TryGetValue` evita tanto a exceção `KeyNotFoundException` quanto uma dupla consulta com `ContainsKey`.

## Referências anuláveis no C# moderno

Desde o C# 8 existe o recurso de tipos de referência anuláveis. Com ele ligado, `string` significa "nunca nulo" e `string?` significa "pode ser nulo", e o compilador avisa quando você usa um valor que talvez seja nulo sem checar.

```csharp
#nullable enable
string nome = "Ana";           // não pode receber null sem aviso
string? talvez = BuscaNome(3); // pode ser null

int tamanho = talvez?.Length ?? 0;   // seguro
if (talvez is not null)              // C# 9
{
    Console.WriteLine(talvez.Length); // aqui o compilador sabe que não é null
}
string forte = talvez!;              // ! diz "confie em mim" (use com parcimônia)
cache ??= new List<int>();           // C# 8: atribui só se for null
```

<Callout type="note" title="Versão necessária">
Referências anuláveis (`string?`, `#nullable enable`) e o operador `??=` exigem C# 8 (.NET Core 3.0 ou superior); `is not null` exige C# 9. Em projetos novos o recurso já vem ligado. Nada disso muda o comportamento em tempo de execução: são avisos de compilação.
</Callout>

## Armadilhas

- `?.` não protege contra tudo: se `ana.Chefe` não for null mas `Nome` for, o resultado continua nulo e o próximo uso estoura.
- `==` entre `int?` com um lado nulo é `false`, mas `a != b` com ambos nulos é `false` também (nulos são iguais entre si).
- O operador `!` apenas silencia o aviso; se o valor for null, a exceção vem do mesmo jeito.
- Strings vazias e nulas são diferentes: use `string.IsNullOrEmpty(s)` ou `IsNullOrWhiteSpace` ao validar.

## Na entrevista

Em problemas de listas encadeadas e árvores, `node?.next` e `node == null` são o dia a dia: todo código seu precisa decidir o caso de nó nulo antes de acessar `.val`. Cite o caso base ("se a raiz for null, devolvo..."). Follow-ups comuns: "qual a diferença entre `int` e `int?`?" e "o que `a ?? b` faz?". Quem usa nullable reference types mostra familiaridade com o C# atual.
