Imagine escrever uma pilha de inteiros, depois uma de strings, depois uma de pontos. O corpo seria idêntico, só o tipo muda. Em Python e JavaScript você nem pensa nisso, porque a tipagem é dinâmica. Em C#, que é tipado estaticamente, os generics resolvem o problema: você escreve o código uma vez, com um parâmetro de tipo, e o compilador garante que cada uso é consistente.

## Antes dos generics

No C# 1.0 as coleções guardavam `object`. Você inseria um `int`, e na hora de ler precisava fazer cast. Isso tinha dois custos: boxing (empacotar o valor na heap) e erros de tipo só em tempo de execução. Hoje `List<int>` guarda inteiros diretamente, sem boxing e com verificação na compilação. Por isso você usa `List<T>`, `Dictionary<TKey, TValue>` e `HashSet<T>` o tempo todo, e raramente os tipos antigos como `ArrayList`.

## Classes e métodos genéricos

O parâmetro de tipo fica entre colchetes angulares, por convenção `T` (ou nomes como `TKey`). Pode estar numa classe ou só num método. Em muitas chamadas o compilador infere o tipo pelos argumentos, então você não precisa escrevê-lo.

```csharp
using System;
using System.Collections.Generic;

class Caixa<T>
{
    private T valor;
    public Caixa(T valor) { this.valor = valor; }
    public T Get() { return valor; }
    public override string ToString() { return "Caixa(" + valor + ")"; }
}

class Program
{
    static T Maior<T>(T a, T b) where T : IComparable<T>
    {
        return a.CompareTo(b) >= 0 ? a : b;
    }

    static void Main()
    {
        var c1 = new Caixa<int>(42);
        var c2 = new Caixa<string>("oi");
        Console.WriteLine(c1);
        Console.WriteLine(c2);
        Console.WriteLine(Maior(3, 9));
        Console.WriteLine(Maior("abc", "abd"));
        int x = c1.Get() + 1;
        Console.WriteLine(x);
    }
}
```

```text
Saída:
Caixa(42)
Caixa(oi)
9
abd
43
```

Repare que `c1.Get()` devolve `int` de verdade: sem cast e sem boxing. A chamada `Maior(3, 9)` não precisou de `Maior<int>`, pois o tipo foi inferido.

## Restrições com where

Dentro de um método genérico, `T` é desconhecido, então você só pode usar o que vale para `object`. Para usar `CompareTo`, por exemplo, é preciso prometer ao compilador que `T` implementa `IComparable<T>`. As restrições comuns são:

- `where T : class` ou `where T : struct`, para tipo de referência ou de valor;
- `where T : new()`, que exige um construtor sem parâmetros;
- `where T : SomeBase` ou `where T : ISomething`, para herdar de uma classe ou implementar uma interface.

Sem a restrição, `a.CompareTo(b)` não compilaria, e esse erro na compilação é exatamente o benefício.

## Pilha genérica, default e ref

O próximo exemplo mostra uma estrutura reutilizável, um método com `ref` e o valor `default(T)`, que é zero para numéricos, `false` para `bool` e `null` para referências.

```csharp
using System;
using System.Collections.Generic;

class Pilha<T>
{
    private readonly List<T> itens = new List<T>();
    public int Count { get { return itens.Count; } }
    public void Push(T item) { itens.Add(item); }
    public T Pop()
    {
        if (itens.Count == 0) throw new InvalidOperationException("pilha vazia");
        T topo = itens[itens.Count - 1];
        itens.RemoveAt(itens.Count - 1);
        return topo;
    }
}

class Program
{
    static void Trocar<T>(ref T a, ref T b)
    {
        T tmp = a;
        a = b;
        b = tmp;
    }

    static void Main()
    {
        var p = new Pilha<int>();
        p.Push(1); p.Push(2); p.Push(3);
        Console.WriteLine(p.Pop());
        Console.WriteLine(p.Count);

        string a = "x", b = "y";
        Trocar(ref a, ref b);
        Console.WriteLine(a + " " + b);

        Console.WriteLine(default(int));
        Console.WriteLine(default(bool));
        Console.WriteLine(default(string) == null);
    }
}
```

```text
Saída:
3
2
y x
0
False
True
```

## Armadilhas e trade-offs

Diferente de Java, os generics de C# são reificados: `List<int>` e `List<string>` são tipos diferentes em tempo de execução, e `typeof(T)` funciona dentro de um método genérico. Em contrapartida, não dá para escrever `new T()` sem a restrição `new()`, porque o compilador não sabe se `T` tem construtor sem parâmetros.

Outra confusão é a variância. `List<string>` não é um `List<object>`, mesmo que `string` seja um `object`, porque senão você poderia inserir um inteiro numa lista de strings. Já `IEnumerable<string>` pode ser usado como `IEnumerable<object>`, pois a interface é somente de leitura (covariância, marcada por `out T`). Raramente cai em entrevista, mas é uma pergunta clássica.

<Callout type="tip" title="Dica">
Tuplas de valor, como `(int, string)`, são generics prontos para devolver dois valores de um método. Elas existem a partir do C# 7 e dispensam criar uma classe só para retorno.
</Callout>

## Na entrevista

Você usa generics ao declarar `Dictionary<string, List<int>>` ou ao escrever uma estrutura própria (pilha, fila, LRU). Se pedirem para implementar uma estrutura, escreva `class MinhaFila<T>` em vez de fixar `int`: custa quase nada e mostra domínio da linguagem. Follow-ups comuns: "por que `List<T>` é melhor que `ArrayList`?" (sem boxing e com tipo verificado) e "para que serve `where T : IComparable<T>`?" (permitir comparar elementos dentro do código genérico).
