Antes de escrever a primeira linha de Java, você precisa de uma habilidade que nenhuma linguagem ensina sozinha: transformar um problema do mundo real em passos tão precisos que uma máquina consiga executá-los. É isso que se chama pensamento computacional. Todo dia, em back-end, alguém chega com um pedido vago ("o paciente não pode marcar duas consultas no mesmo horário") e o seu trabalho é quebrar isso em regras, dados e passos. Este capítulo é para quem nunca programou: você vai entender o que o computador faz de verdade e escrever os primeiros algoritmos, primeiro em pseudocódigo e depois em Java.

**Você vai aprender:**

- Os quatro pilares do pensamento computacional: decomposição, padrões, abstração e algoritmos
- Como um computador executa um programa (CPU, memória, disco e o papel da JVM)
- Variáveis, tipos, condições e repetição, em pseudocódigo e em Java
- Como testar um algoritmo de cabeça antes de rodar
- Por que existem algoritmos melhores e piores para o mesmo problema

## O problema que vamos usar

Ao longo desta carreira, o fio condutor é o sistema de uma clínica médica: pacientes, médicos e consultas. Começamos pequeno. A recepcionista hoje anota tudo num caderno e quer saber três coisas:

1. Quanto o paciente vai pagar pela consulta.
2. Se um horário pedido já está ocupado.
3. Qual o primeiro horário livre do dia.

Parece simples para uma pessoa. Para um computador, não existe "parece". Tudo precisa ser dito.

## Os quatro pilares

### Decomposição

Decompor é quebrar um problema grande em partes menores, que você resolve uma de cada vez. "Agendar consulta" vira:

- Identificar o paciente.
- Escolher o médico.
- Escolher um horário.
- Verificar se o horário está livre.
- Registrar a consulta.
- Calcular o valor.

Cada item é pequeno o bastante para você saber por onde começar. Quando um item ainda parece grande, decomponha de novo. Em código, essas partes vão virar métodos e classes.

### Reconhecimento de padrões

Depois de decompor, você nota repetições. Verificar se o horário das 9h está livre é igual a verificar o das 10h, só muda o valor. Calcular o preço da consulta de um cardiologista segue a mesma regra do dermatologista, só muda a tabela. Padrão encontrado significa que você escreve a lógica uma vez e a reaproveita.

### Abstração

Abstrair é ignorar o que não importa para o problema. Para agendar, o paciente é um nome, uma idade e talvez um convênio. A cor do cabelo e o time de futebol dele não entram. Um horário é só um número de hora (8, 9, 10...). Escolher os dados certos é metade do trabalho de programar: dados demais deixam o sistema confuso, dados de menos impedem que ele responda às perguntas.

### Algoritmos

Um algoritmo é uma sequência finita de passos, sem ambiguidade, que resolve um problema. Uma receita de bolo é quase um algoritmo, mas "asse até ficar dourado" é ambíguo para uma máquina. "Asse por 40 minutos a 180 graus" não é.

Três propriedades que todo algoritmo precisa ter:

| Propriedade | Significa |
|---|---|
| Finito | Termina depois de um número de passos |
| Preciso | Cada passo tem um só jeito de ser interpretado |
| Com entrada e saída | Recebe dados e produz um resultado |

## Como o computador funciona

Você não precisa saber eletrônica, mas precisa de um modelo mental correto.

- **CPU (processador):** executa instruções muito simples (somar, comparar, copiar um valor, pular para outra instrução) bilhões de vezes por segundo. Ela não "entende" nada: segue instruções.
- **Memória RAM:** onde ficam os dados e o programa enquanto ele roda. É rápida e apagada quando o programa termina ou o computador desliga. Cada variável do seu programa mora num pedaço dela.
- **Disco (SSD):** guarda arquivos de forma permanente. É bem mais lento que a RAM. Quando você salva uma consulta num arquivo ou banco de dados, ela vai parar no disco.
- **Entrada e saída:** teclado, tela, rede. Uma API web recebe dados pela rede e devolve pela rede.

Tudo, por dentro, é representado em binário (zeros e uns). O número 13 é `1101`. A letra "A" é o número 65. Uma imagem é uma grande lista de números de cor. Os tipos de dados de uma linguagem dizem como interpretar esses bits.

### De onde vem o programa que a CPU executa

A CPU só entende linguagem de máquina, que é ilegível para pessoas. Então escrevemos numa linguagem de alto nível e uma ferramenta traduz. Java faz isso em duas etapas:

1. O compilador `javac` transforma o seu `.java` em **bytecode** (arquivo `.class`).
2. A **JVM** (Java Virtual Machine) lê o bytecode e o traduz para a máquina onde está rodando, inclusive compilando os trechos mais usados para código nativo enquanto o programa roda (o compilador JIT).

É por isso que o mesmo `.class` roda em Windows, Linux e Mac: cada sistema tem a sua JVM. No servidor da clínica, a API em Java vai rodar numa JVM dentro de um container.

## Lógica com pseudocódigo

Pseudocódigo é escrever o algoritmo em português estruturado, sem se preocupar com a sintaxe de uma linguagem. Serve para pensar.

### Variáveis e tipos

Uma variável é um nome para um valor guardado na memória. O tipo diz que espécie de valor é.

```text
variavel nome: texto
variavel idade: inteiro
variavel valorBase: decimal
variavel temConvenio: logico

nome <- "Ana"
idade <- 67
valorBase <- 250.00
temConvenio <- falso
```

### Condição

Uma condição escolhe um caminho. Regra da clínica: paciente com 60 anos ou mais tem 20% de desconto; quem tem convênio paga só R$ 50 de coparticipação.

```text
algoritmo calcularValor
  entrada: idade (inteiro), temConvenio (logico), valorBase (decimal)
  se temConvenio entao
    retorne 50.00
  fimse
  se idade >= 60 entao
    retorne valorBase * 0.8
  fimse
  retorne valorBase
fimalgoritmo
```

Repare na ordem: a regra do convênio vem primeiro porque ela vence a outra. Ordem de condições é decisão de negócio, não detalhe.

### Repetição

Repetição executa um bloco várias vezes. Para descobrir o primeiro horário livre, olhamos hora por hora, das 8h às 17h:

```text
algoritmo primeiroHorarioLivre
  entrada: ocupados (lista de inteiros)
  para hora de 8 ate 17 faca
    se hora nao esta em ocupados entao
      retorne hora
    fimse
  fimpara
  retorne -1   // nenhum horário livre
fimalgoritmo
```

O `-1` é uma convenção para "não achei". Uma das lições deste algoritmo: sempre pense no caso em que a resposta não existe.

## Teste de mesa

Antes de rodar, simule o algoritmo à mão numa tabela. Isso se chama teste de mesa e pega a maioria dos erros de lógica. Com `ocupados = [8, 9, 11]`:

| Passo | hora | hora está em ocupados? | Ação |
|---|---|---|---|
| 1 | 8 | sim | continua |
| 2 | 9 | sim | continua |
| 3 | 10 | não | retorna 10 |

O resultado esperado é 10, e o teste confirma. Agora teste o caso extremo: todos os horários ocupados. O laço termina sem retornar nada dentro dele e cai no `retorne -1`. Ótimo.

<Callout type="warning" title="O erro de um a mais ou a menos">
O bug mais comum de quem começa é o limite do laço: "das 8 às 17" inclui ou não o 17? Se a última consulta começa às 17h, o laço precisa incluir 17. Em Java, `hora < 17` exclui e `hora <= 17` inclui. Sempre faça o teste de mesa com o primeiro e o último valor do intervalo.
</Callout>

## Do pseudocódigo para Java

Agora o mesmo raciocínio em Java 21. Não se preocupe em entender cada palavra ainda: o próximo capítulo explica a estrutura de um programa. Salve como `Clinica.java`:

```java
import java.util.List;

public class Clinica {

    static double calcularValor(int idade, boolean temConvenio, double valorBase) {
        if (temConvenio) {
            return 50.00;
        }
        if (idade >= 60) {
            return valorBase * 0.8;
        }
        return valorBase;
    }

    static int primeiroHorarioLivre(List<Integer> ocupados) {
        for (int hora = 8; hora <= 17; hora++) {
            if (!ocupados.contains(hora)) {
                return hora;
            }
        }
        return -1;
    }

    public static void main(String[] args) {
        System.out.println(calcularValor(67, false, 250.00)); // 200.0
        System.out.println(calcularValor(30, true, 250.00));  // 50.0
        System.out.println(primeiroHorarioLivre(List.of(8, 9, 11))); // 10
    }
}
```

Com o JDK 21 instalado, rode direto, sem compilar à parte:

```bash
java Clinica.java
```

Compare com o pseudocódigo: `se ... entao` virou `if (...) { }`, `para hora de 8 ate 17` virou `for (int hora = 8; hora <= 17; hora++)`, `retorne` virou `return`. Os tipos também aparecem: `int` para inteiro, `double` para decimal, `boolean` para lógico. A lógica é a mesma; a linguagem só exige mais precisão na escrita.

## Operadores lógicos e tabelas-verdade

Regras de negócio quase sempre combinam condições. Os três operadores básicos:

| Operador | Java | Verdadeiro quando |
|---|---|---|
| E | `&&` | os dois lados são verdadeiros |
| OU | `\|\|` | pelo menos um lado é verdadeiro |
| NÃO | `!` | o valor é falso |

Exemplo: o horário pode ser agendado se estiver livre **e** dentro do expediente.

```java
static boolean podeAgendar(int hora, List<Integer> ocupados) {
    boolean noExpediente = hora >= 8 && hora <= 17;
    boolean livre = !ocupados.contains(hora);
    return noExpediente && livre;
}
```

Dar nome a cada parte da condição (`noExpediente`, `livre`) é abstração aplicada: o `return` fica legível como uma frase.

## Nem todo algoritmo é igual

Imagine que a clínica cresceu e tem 2 mil horários por dia, guardados em ordem. Procurar um horário olhando um por um (busca linear) pode levar 2 mil comparações. Se a lista está ordenada, dá para olhar o meio, descartar a metade errada e repetir (busca binária): cerca de 11 comparações.

```java
static boolean existe(int[] horariosOrdenados, int alvo) {
    int inicio = 0;
    int fim = horariosOrdenados.length - 1;
    while (inicio <= fim) {
        int meio = (inicio + fim) / 2;
        if (horariosOrdenados[meio] == alvo) return true;
        if (horariosOrdenados[meio] < alvo) inicio = meio + 1;
        else fim = meio - 1;
    }
    return false;
}
```

Os dois resolvem o problema. O segundo escala. Medir o custo de um algoritmo em função do tamanho da entrada é o que se chama complexidade, e você vai encontrá-la em toda entrevista técnica. Por enquanto, guarde a ideia: o mesmo problema pode ter soluções com custos muito diferentes.

## Como atacar um problema novo

Um roteiro que funciona do primeiro exercício até a entrevista:

1. **Entenda a entrada e a saída.** O que chega? O que precisa sair? Escreva dois ou três exemplos concretos.
2. **Resolva à mão.** Se você não sabe resolver no papel, não vai saber programar.
3. **Escreva o pseudocódigo.** Decomponha em passos.
4. **Faça o teste de mesa**, incluindo casos extremos: lista vazia, zero, valor máximo.
5. **Traduza para a linguagem** e rode com os mesmos exemplos.

## Na entrevista

- **O que é um algoritmo?** Uma sequência finita e precisa de passos que transforma uma entrada numa saída. Ambiguidade ou laço infinito desqualificam.
- **Qual a diferença entre compilar e interpretar, no caso do Java?** O `javac` compila o código-fonte para bytecode; a JVM executa esse bytecode, interpretando e compilando para código nativo (JIT) os trechos mais usados. Por isso Java é portátil entre sistemas.
- **Qual a diferença entre memória RAM e disco para um programa?** A RAM é rápida e volátil, guarda as variáveis enquanto o programa roda. O disco é lento e persistente. Dado que precisa sobreviver a um reinício vai para disco ou banco de dados.
- **Como você aborda um problema que nunca viu?** Esclareço entrada e saída com exemplos, resolvo à mão, escrevo os passos, testo casos extremos e só então codifico.

## Pratique

Escreva, primeiro em pseudocódigo e depois em Java (um único arquivo `Agenda.java` rodado com `java Agenda.java`), um algoritmo que recebe a lista de horários ocupados de um médico e a duração da consulta em horas (1 ou 2) e devolve o primeiro horário em que cabem **horas consecutivas livres** dentro do expediente das 8h às 18h (a consulta precisa terminar até 18h). Devolva `-1` se não couber.

Entregue:

- O pseudocódigo.
- Um teste de mesa com `ocupados = [8, 10, 11]` e duração 2 (resposta esperada: 12).
- O código Java com pelo menos quatro chamadas no `main`, incluindo agenda vazia e agenda cheia.
