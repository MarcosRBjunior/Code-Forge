Abra o monitor de recursos e some a memória virtual de todos os processos: o total passa com folga da RAM instalada. Um processo Java pode reservar 10 GB de heap numa máquina de 8 GB e funcionar bem. Isso só é possível porque a **memória virtual** desacopla o que o processo acha que tem do que realmente está na RAM. Páginas são trazidas para a memória física **sob demanda**, quando são tocadas pela primeira vez, e podem ser devolvidas ao disco quando falta espaço. O mecanismo que liga essas duas pontas é o **page fault**.

## Paginação sob demanda

Quando um processo pede memória (`malloc` grande, `mmap`), o kernel só anota a região como válida. Nenhum quadro físico é alocado. No primeiro acesso, a entrada da tabela está marcada como não presente, a MMU gera uma exceção e o kernel resolve:

```text
 instrução acessa endereço virtual
        │
        ▼
 MMU: PTE não presente → exceção de page fault
        │
        ▼
 kernel: o endereço pertence a uma região válida?
   não → SIGSEGV (segmentation fault)
   sim → de onde vem o conteúdo?
          ├─ página nova (heap/pilha) → zera um quadro          [minor fault]
          ├─ arquivo já no page cache → só mapeia o quadro       [minor fault]
          └─ arquivo ou swap no disco → lê do disco, bloqueia    [major fault]
        │
        ▼
 atualiza a PTE (presente = 1), reexecuta a instrução
```

Um **minor fault** custa da ordem de microssegundos. Um **major fault** exige E/S de disco: dezenas de microssegundos num SSD, milissegundos num HD. É por isso que uma latência p99 ruim às vezes vem de páginas sendo lidas do disco, e não do seu código.

## O impacto de uma taxa de falhas

O tempo efetivo de acesso à memória depende brutalmente da fração de acessos que viram major fault:

## mmap: arquivos como memória

`mmap` usa o mesmo mecanismo para arquivos. Mapear um arquivo não lê nada; cada página é carregada no primeiro toque e, se modificada, escrita de volta mais tarde. O exemplo mapeia um arquivo de 1 MB e toca só algumas posições. O kernel só precisa trazer as páginas tocadas:

<CodeTabs>

```python
import mmap
import os
import tempfile

TAM_PAGINA = 4096
with tempfile.TemporaryDirectory() as pasta:
    caminho = os.path.join(pasta, "grande.bin")
    with open(caminho, "wb") as f:
        f.truncate(256 * TAM_PAGINA)      # arquivo de 1 MiB (esparso)

    with open(caminho, "r+b") as f:
        m = mmap.mmap(f.fileno(), 0)
        paginas_tocadas = set()
        for desloc in [0, 10, 4096 * 7 + 3, 4096 * 200, 4096 * 200 + 99]:
            m[desloc] = 65                # escreve 'A'
            paginas_tocadas.add(desloc // TAM_PAGINA)
        m.flush()
        print("tamanho mapeado:", len(m), "bytes")
        print("paginas tocadas:", sorted(paginas_tocadas))
        print(f"fracao que precisou ir para a RAM: {len(paginas_tocadas) / 256:.1%}")
        m.close()

    with open(caminho, "rb") as f:
        dados = f.read()
    print("bytes 'A' gravados no arquivo:", dados.count(b"A"))
```

import java.io.*;
import java.nio.MappedByteBuffer;
import java.nio.channels.FileChannel;
import java.nio.file.*;
import java.util.*;

static final int TAM_PAGINA = 4096;

public static void main(String[] args) throws IOException {
    Path pasta = Files.createTempDirectory("mmap");
    Path caminho = pasta.resolve("grande.bin");
    try (RandomAccessFile f = new RandomAccessFile(caminho.toFile(), "rw")) {
        f.setLength(256 * TAM_PAGINA); // arquivo de 1 MiB (esparso)
    }

    try (FileChannel f = FileChannel.open(caminho, StandardOpenOption.READ, StandardOpenOption.WRITE)) {
        MappedByteBuffer m = f.map(FileChannel.MapMode.READ_WRITE, 0, f.size());
        TreeSet<Integer> paginasTocadas = new TreeSet<>();
        for (int desloc : new int[] {0, 10, 4096 * 7 + 3, 4096 * 200, 4096 * 200 + 99}) {
            m.put(desloc, (byte) 65); // escreve 'A'
            paginasTocadas.add(desloc / TAM_PAGINA);
        }
        m.force();
        System.out.println("tamanho mapeado: " + m.capacity() + " bytes");
        System.out.println("paginas tocadas: " + paginasTocadas);
        System.out.println(String.format(Locale.US, "fracao que precisou ir para a RAM: %.1f%%", paginasTocadas.size() * 100.0 / 256));
    }

    byte[] dados = Files.readAllBytes(caminho);
    int quantos = 0;
    for (byte b : dados) {
        if (b == 'A') quantos++;
    }
    System.out.println("bytes 'A' gravados no arquivo: " + quantos);

    Files.delete(caminho);
    Files.delete(pasta);
}

import (
	"bytes"
	"fmt"
	"os"
	"path/filepath"
	"sort"
	"syscall"
	"unsafe"
)

const TAM_PAGINA = 4096

func main() {
	pasta, _ := os.MkdirTemp("", "mmap")
	defer os.RemoveAll(pasta)
	caminho := filepath.Join(pasta, "grande.bin")

	f, _ := os.Create(caminho)
	f.Truncate(256 * TAM_PAGINA) // arquivo de 1 MiB (esparso)
	f.Close()

	f, _ = os.OpenFile(caminho, os.O_RDWR, 0)
	info, _ := f.Stat()
	m, _ := syscall.Mmap(int(f.Fd()), 0, int(info.Size()), syscall.PROT_READ|syscall.PROT_WRITE, syscall.MAP_SHARED)
	paginasTocadas := map[int]bool{}
	for _, desloc := range []int{0, 10, 4096*7 + 3, 4096 * 200, 4096*200 + 99} {
		m[desloc] = 65 // escreve 'A'
		paginasTocadas[desloc/TAM_PAGINA] = true
	}
	// msync: o pacote syscall não tem um atalho, então a chamada é feita pelo número
	syscall.Syscall(syscall.SYS_MSYNC, uintptr(unsafe.Pointer(&m[0])), uintptr(len(m)), syscall.MS_SYNC)
	paginas := []int{}
	for p := range paginasTocadas {
		paginas = append(paginas, p)
	}
	sort.Ints(paginas)
	fmt.Println("tamanho mapeado:", len(m), "bytes")
	fmt.Println("paginas tocadas:", paginas)
	fmt.Printf("fracao que precisou ir para a RAM: %.1f%%\n", float64(len(paginas))*100/256)
	syscall.Munmap(m)
	f.Close()

	dados, _ := os.ReadFile(caminho)
	fmt.Println("bytes 'A' gravados no arquivo:", bytes.Count(dados, []byte("A")))
}

## Swap, overcommit e thrashing

Quando a RAM acaba, o kernel escolhe páginas para expulsar. Páginas de arquivo limpas são só descartadas (dá para ler de novo); páginas anônimas modificadas precisam ir para o **swap**. Se o conjunto de páginas que os processos usam ativamente, o **working set**, não cabe na RAM, o sistema entra em **thrashing**: passa mais tempo trocando páginas do que executando.

O Linux também faz **overcommit**: aceita reservas maiores que a memória disponível, apostando que nem tudo será tocado. Quando a aposta falha, o **OOM killer** escolhe um processo (normalmente o maior) e o mata.

| Situação | Sintoma | O que olhar |
| --- | --- | --- |
| Muitos major faults | Latência alta, CPU em iowait | `vmstat` colunas si/so, `sar -B` |
| Thrashing | Máquina quase parada, disco a 100% | Working set maior que a RAM |
| OOM kill | Processo some, exit 137 | `dmesg`, eventos do Kubernetes |

<Callout type="warning" title="Swap e serviços de baixa latência">
Para serviços sensíveis a latência, ir para o swap costuma ser pior que morrer: o processo fica vivo, mas cada requisição leva segundos. Por isso Kubernetes desativa swap por padrão e muitos times preferem limites de memória claros e reinício rápido. `vm.swappiness` controla quão cedo o kernel recorre ao swap.
</Callout>
