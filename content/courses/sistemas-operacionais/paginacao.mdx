Se cada processo usasse endereços físicos diretamente, dois programas compilados para o endereço 0x1000 colidiriam, um bug poderia sobrescrever a memória de outro processo e você precisaria de um bloco contíguo de RAM para cada programa. A **paginação** resolve tudo isso de uma vez: cada processo enxerga um espaço de **endereços virtuais** próprio, dividido em **páginas** de tamanho fixo, e o hardware traduz cada página para um **quadro** (frame) qualquer da memória física.

## A tradução

Com páginas de 4 KB (2¹² bytes), os 12 bits menos significativos de um endereço são o **deslocamento** dentro da página, e o resto é o **número da página virtual** (VPN). A tabela de páginas do processo diz em qual quadro físico está cada VPN.

```text
 endereço virtual 0x3A7C  (páginas de 4 KB)

 ┌─────────────── VPN ───────────────┬──── deslocamento ────┐
 │               0x3                 │        0xA7C         │
 └───────────────────────────────────┴──────────────────────┘
                  │
                  ▼  tabela de páginas: VPN 3 → quadro 0x51
 ┌────────────── quadro ─────────────┬──── deslocamento ────┐
 │              0x51                 │        0xA7C         │   = 0x51A7C físico
 └───────────────────────────────────┴──────────────────────┘
```

O deslocamento atravessa a tradução intacto; só o número da página muda. Cada entrada da tabela (PTE) também guarda bits de controle: **presente**, **escrita permitida**, **usuário/kernel**, **acessada** e **modificada (dirty)**, além de **NX** (não executável).

A função abaixo faz a tradução como a MMU faria, incluindo as verificações que geram falhas:

<CodeTabs>

```python
TAM_PAGINA = 4096

tabela = {
    0: {"quadro": 0x10, "presente": True, "escrita": False},   # codigo
    1: {"quadro": 0x2B, "presente": True, "escrita": True},    # dados
    3: {"quadro": 0x51, "presente": True, "escrita": True},    # heap
    7: {"quadro": None, "presente": False, "escrita": True},   # em swap
}

def traduzir(endereco, escrita=False):
    vpn, desloc = divmod(endereco, TAM_PAGINA)
    pte = tabela.get(vpn)
    if pte is None:
        return f"0x{endereco:05X} -> segfault (pagina {vpn} nao mapeada)"
    if not pte["presente"]:
        return f"0x{endereco:05X} -> page fault (pagina {vpn} fora da RAM)"
    if escrita and not pte["escrita"]:
        return f"0x{endereco:05X} -> violacao de protecao (escrita em pagina somente leitura)"
    fisico = pte["quadro"] * TAM_PAGINA + desloc
    return f"0x{endereco:05X} -> vpn={vpn} desloc=0x{desloc:03X} -> fisico 0x{fisico:05X}"

print(traduzir(0x3A7C))
print(traduzir(0x1004, escrita=True))
print(traduzir(0x0010, escrita=True))
print(traduzir(0x7123))
print(traduzir(0x5000))
```

Cada um desses casos é tratado de forma diferente pelo kernel: o page fault de uma página em swap é normal e transparente; o acesso a uma página não mapeada vira `SIGSEGV`; a escrita em página somente leitura pode ser copy-on-write legítimo ou um bug.

## O tamanho da tabela é um problema

Num espaço de 48 bits com páginas de 4 KB, existem 2³⁶ páginas virtuais. Uma tabela plana com entradas de 8 bytes ocuparia 512 GB por processo. A solução é a **tabela de páginas multinível**: o VPN é dividido em pedaços, cada um indexando uma tabela de um nível, e níveis inteiros que não são usados simplesmente não existem. O x86-64 usa 4 níveis de 9 bits (e 5 níveis em máquinas recentes).

<CodeTabs>

```python
BITS_DESLOC = 12
BITS_NIVEL = 9
NIVEIS = 4

def indices(endereco):
    vpn = endereco >> BITS_DESLOC
    partes = []
    for _ in range(NIVEIS):
        partes.append(vpn & ((1 << BITS_NIVEL) - 1))
        vpn >>= BITS_NIVEL
    return list(reversed(partes)), endereco & 0xFFF

for end in [0x0000_7F12_3456_7ABC, 0x0000_0000_0040_1000]:
    idx, desloc = indices(end)
    print(f"0x{end:016X} -> PML4={idx[0]} PDPT={idx[1]} PD={idx[2]} PT={idx[3]} desloc=0x{desloc:03X}")

plana = (2 ** (48 - BITS_DESLOC)) * 8
um_processo_pequeno = 4 * 4096   # um caminho de 4 tabelas de 4 KB
print(f"tabela plana: {plana / 2**30:.0f} GiB; multinivel minima: {um_processo_pequeno // 1024} KiB")
```

```go
		fmt.Printf("0x%016X -> PML4=%d PDPT=%d PD=%d PT=%d desloc=0x%03X\n", end, idx[0], idx[1], idx[2], idx[3], desloc)
	}

	plana := uint64(1<<(48-BITS_DESLOC)) * 8
	umProcessoPequeno := 4 * 4096 // um caminho de 4 tabelas de 4 KB
	fmt.Printf("tabela plana: %.0f GiB; multinivel minima: %d KiB\n", float64(plana)/(1<<30), umProcessoPequeno/1024)
}
```

O preço da economia é tempo: sem cache, cada acesso à memória vira cinco (quatro níveis de tabela mais o dado). É por isso que existe a TLB, tema do próximo capítulo.

## Trade-offs do tamanho de página

| Página | Vantagem | Desvantagem |
| --- | --- | --- |
| 4 KB (padrão) | Pouca fragmentação interna, granularidade fina | Tabelas maiores, mais falhas de TLB |
| 2 MB / 1 GB (huge pages) | Muito menos entradas na TLB | Desperdício interno, alocação mais difícil |

Bancos de dados e JVMs com heaps grandes costumam ganhar com huge pages. Já o recurso **Transparent Huge Pages** do Linux, que promove páginas automaticamente, causa picos de latência em alguns workloads (Redis e MongoDB recomendam desativá-lo).

<Callout type="note" title="Paginação também é proteção">
Como cada processo tem sua tabela, ele simplesmente não tem como nomear a memória de outro processo. Bibliotecas compartilhadas e o copy-on-write funcionam apontando entradas de tabelas diferentes para o mesmo quadro físico.
</Callout>
