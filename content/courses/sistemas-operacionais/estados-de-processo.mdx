Numa máquina com 8 núcleos e 400 processos, no máximo 8 estão de fato executando. Os outros estão esperando alguma coisa: a vez na CPU, um disco, um pacote de rede, um lock. O kernel organiza essa espera atribuindo a cada processo um **estado** e mantendo filas por estado. Saber ler esses estados é o que permite interpretar o `top`, a load average e um processo "travado" em produção.

## O modelo de cinco estados

```text
             admitido                 escalonado
   ┌──────┐ ─────────► ┌────────┐ ───────────────► ┌────────────┐  exit   ┌───────────┐
   │ novo │            │ pronto │                  │ executando │ ──────► │ terminado │
   └──────┘            └────────┘ ◄─────────────── └────────────┘         └───────────┘
                           ▲        preempção (timer)      │
                           │                               │ espera E/S, lock, sleep
                           │       evento concluído        ▼
                           └──────────────────────── ┌────────────┐
                                                     │ bloqueado  │
                                                     └────────────┘
```

- **Novo:** o PCB está sendo criado.
- **Pronto:** pode rodar, só falta CPU. Fica na fila do escalonador.
- **Executando:** está num núcleo agora.
- **Bloqueado (ou esperando):** não adianta dar CPU, ele está esperando um evento.
- **Terminado:** acabou, mas o PCB ainda existe até o pai recolher o código de saída.

Repare nas setas que **não existem**. Um processo bloqueado nunca vai direto para executando: quando o disco responde, ele volta para pronto e espera sua vez. E um processo pronto não fica bloqueado sem antes executar, porque é a própria execução que pede a E/S.

Muitos livros acrescentam dois estados **suspensos**: pronto-suspenso e bloqueado-suspenso, para processos cuja memória foi inteiramente levada ao disco. No Linux moderno isso praticamente não aparece como estado separado, porque a memória é devolvida página a página, mas a ideia ajuda a entender por que um processo que ficou muito tempo parado demora a responder quando volta: as páginas dele precisam ser trazidas de novo.

```python
TRANSICOES = {
    ("novo", "admitir"): "pronto",
    ("pronto", "escalonar"): "executando",
    ("executando", "preempcao"): "pronto",
    ("executando", "esperar_io"): "bloqueado",
```

## Filas e contagem por estado

Na prática, o kernel não percorre todos os processos para achar quem está pronto: ele mantém uma fila de prontos (no Linux, uma árvore por núcleo) e filas de espera por evento. A próxima simulação avança um relógio com dois processos e uma única CPU, registrando quanto tempo cada um passou em cada estado.

<CodeTabs>

```python
from collections import Counter

# (nome, rajadas): rajadas alternam CPU e E/S
procs = {"A": ["cpu", "cpu", "io", "io", "io", "cpu"],
         "B": ["cpu", "io", "cpu", "cpu"]}
pos = {n: 0 for n in procs}
tempo = {n: Counter() for n in procs}

for t in range(10):
    cpu_livre = True
    for nome in sorted(procs):
        rajadas = procs[nome]
        if pos[nome] >= len(rajadas):
            tempo[nome]["terminado"] += 1
            continue
        tipo = rajadas[pos[nome]]
        if tipo == "io":
            tempo[nome]["bloqueado"] += 1
            pos[nome] += 1
        elif cpu_livre:
            tempo[nome]["executando"] += 1
            pos[nome] += 1
            cpu_livre = False
        else:
            tempo[nome]["pronto"] += 1

for nome in sorted(tempo):
    print(nome, dict(sorted(tempo[nome].items())))
```

```java
import java.util.*;

public static void main(String[] args) {
    // (nome, rajadas): rajadas alternam CPU e E/S
    Map<String, List<String>> procs = new TreeMap<>();
    procs.put("A", List.of("cpu", "cpu", "io", "io", "io", "cpu"));
    procs.put("B", List.of("cpu", "io", "cpu", "cpu"));
    Map<String, Integer> pos = new HashMap<>();
    Map<String, TreeMap<String, Integer>> tempo = new TreeMap<>(); // contador: estado -> quantos instantes
    for (String n : procs.keySet()) {
        pos.put(n, 0);
        tempo.put(n, new TreeMap<>());
    }

    for (int t = 0; t < 10; t++) {
        boolean cpuLivre = true;
        for (String nome : procs.keySet()) { // TreeMap: ordem alfabética
            List<String> rajadas = procs.get(nome);
            if (pos.get(nome) >= rajadas.size()) {
                tempo.get(nome).merge("terminado", 1, Integer::sum);
                continue;
            }
            String tipo = rajadas.get(pos.get(nome));
            if (tipo.equals("io")) {
                tempo.get(nome).merge("bloqueado", 1, Integer::sum);
                pos.put(nome, pos.get(nome) + 1);
            } else if (cpuLivre) {
                tempo.get(nome).merge("executando", 1, Integer::sum);
                pos.put(nome, pos.get(nome) + 1);
                cpuLivre = false;
            } else {
                tempo.get(nome).merge("pronto", 1, Integer::sum);
            }
        }
    }

    for (String nome : tempo.keySet()) {
        System.out.println(nome + " " + tempo.get(nome));
    }
}
```

```go
import (
	"fmt"
	"sort"
	"strings"
)

func main() {
	// (nome, rajadas): rajadas alternam CPU e E/S
	procs := map[string][]string{"A": {"cpu", "cpu", "io", "io", "io", "cpu"},
		"B": {"cpu", "io", "cpu", "cpu"}}
	nomes := []string{}
	pos := map[string]int{}
	tempo := map[string]map[string]int{} // contador: estado -> quantos instantes
	for n := range procs {
		nomes = append(nomes, n)
		pos[n] = 0
		tempo[n] = map[string]int{}
	}
	sort.Strings(nomes)

	for t := 0; t < 10; t++ {
		cpuLivre := true
		for _, nome := range nomes {
			rajadas := procs[nome]
			if pos[nome] >= len(rajadas) {
				tempo[nome]["terminado"]++
				continue
			}
			tipo := rajadas[pos[nome]]
			if tipo == "io" {
				tempo[nome]["bloqueado"]++
				pos[nome]++
			} else if cpuLivre {
				tempo[nome]["executando"]++
				pos[nome]++
				cpuLivre = false
			} else {
				tempo[nome]["pronto"]++
			}
		}
	}

	for _, nome := range nomes {
		estados := []string{}
		for e := range tempo[nome] {
			estados = append(estados, e)
		}
		sort.Strings(estados)
		itens := []string{}
		for _, e := range estados {
			itens = append(itens, fmt.Sprintf("'%s': %d", e, tempo[nome][e]))
		}
		fmt.Printf("%s {%s}\n", nome, strings.Join(itens, ", "))
	}
}
```

## Como isso aparece no Linux

| Letra no `ps` | Estado | Interpretação |
| --- | --- | --- |
| R | Running/runnable | Executando ou pronto na fila |
| S | Sleeping interrompível | Esperando evento, aceita sinais |
| D | Sleeping não interrompível | Esperando E/S de disco ou NFS, ignora até `kill -9` |
| T | Stopped | Pausado por sinal (Ctrl+Z) ou debugger |
| Z | Zombie | Terminou e o pai não chamou `wait` |

<Callout type="tip" title="Load average não é uso de CPU">
No Linux, a load average conta processos em R **e** em D. Uma máquina com CPU ociosa e load 40 geralmente tem processos presos em E/S lenta, como um disco saturado ou um NFS travado. Olhe `vmstat 1` (colunas r e b) antes de concluir que falta CPU.
</Callout>

```bash
ps -eo pid,stat,wchan:20,cmd | awk '$2 ~ /D/'   # quem está preso em E/S
vmstat 1                                         # r = prontos, b = bloqueados
```
