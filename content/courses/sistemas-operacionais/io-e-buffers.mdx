Você escreve um arquivo de 1 GB e o `write` retorna em meio segundo, mais rápido do que o disco conseguiria gravar. Depois, a máquina cai e metade dos dados some. Ou então você lê o mesmo arquivo duas vezes e a segunda leitura é cem vezes mais rápida. Esses comportamentos vêm de camadas de **buffer** e **cache** entre o seu código e o disco. Elas são a razão de E/S ser rápida no caso comum, e a razão de dados se perderem quando você não entende onde eles realmente estão.

## As camadas

```text
 seu código           f.write("linha\n")
      │
 buffer da linguagem   (BufferedWriter do Python, stdio do C, BufferedOutputStream)
      │  flush → syscall write()
 page cache do kernel  (páginas "sujas" em RAM)
      │  writeback em segundo plano ou fsync()
 cache do dispositivo  (RAM do controlador / SSD)
      │  FUA / flush de cache
 mídia persistente
```

Cada camada pode guardar dados que você acha que "já escreveu". Só depois do `fsync` (que pede ao kernel para gravar e ao dispositivo para descarregar o próprio cache) os dados sobrevivem a uma queda de energia.

## Buffer em espaço de usuário

A primeira camada existe para economizar syscalls. Escrever 10.000 linhas de 16 bytes com um `write` para cada uma faz 10.000 travessias para o kernel; com um buffer de 8 KB, menos de 30. O programa abaixo conta as chamadas de escrita que chegam a um "dispositivo" falso, com e sem buffer:

<CodeTabs>

```python
import io

class DispositivoContador(io.RawIOBase):
    def __init__(self):
        self.chamadas = 0
        self.bytes = 0

    def writable(self):
        return True

    def write(self, dados):
        self.chamadas += 1
        self.bytes += len(dados)
        return len(dados)

linhas = [f"evento {i:05d} ok\n".encode() for i in range(10_000)]

cru = DispositivoContador()
for linha in linhas:
    cru.write(linha)

disp = DispositivoContador()
com_buffer = io.BufferedWriter(disp, buffer_size=8192)
for linha in linhas:
    com_buffer.write(linha)
com_buffer.flush()

print(f"sem buffer: {cru.chamadas:>6} chamadas, {cru.bytes} bytes")
print(f"com buffer: {disp.chamadas:>6} chamadas, {disp.bytes} bytes")
```

```javascript
// o Node não traz um BufferedWriter genérico: o buffer de 8 KiB é escrito à mão
class BufferedWriter {
  constructor(destino, tamanho = 8192) {
    this.destino = destino;
    this.buf = Buffer.alloc(tamanho);
    this.usado = 0;
  }

  write(dados) {
    if (this.usado + dados.length > this.buf.length) this.flush();
    if (dados.length >= this.buf.length) return this.destino.write(dados);
    dados.copy(this.buf, this.usado);
    this.usado += dados.length;
    return dados.length;
  }

  flush() {
    if (this.usado > 0) {
      this.destino.write(this.buf.subarray(0, this.usado));
      this.usado = 0;
    }
  }
}
```

```typescript
  private usado = 0;

    this.buf = new Uint8Array(tamanho);
```

```cpp
struct DispositivoContador {
    long chamadas = 0;
    long bytes = 0;
};

ssize_t escrever(void* cookie, const char* dados, size_t tamanho) {
    auto* d = static_cast<DispositivoContador*>(cookie);
    d->chamadas++;
    d->bytes += tamanho;
    return tamanho;
}

int main() {
    vector<string> linhas;
    char texto[32];
    for (int i = 0; i < 10'000; i++) {
        snprintf(texto, sizeof texto, "evento %05d ok\n", i);
        linhas.push_back(texto);
    }

    DispositivoContador cru;
    for (const string& linha : linhas) {
        escrever(&cru, linha.data(), linha.size());
    }

    // o buffer é o do próprio FILE* da biblioteca C; fopencookie (glibc) liga o FILE* ao dispositivo falso
    DispositivoContador disp;
    cookie_io_functions_t funcoes = {nullptr, escrever, nullptr, nullptr};
    FILE* comBuffer = fopencookie(&disp, "w", funcoes);
    static char buffer[8192];
    setvbuf(comBuffer, buffer, _IOFBF, sizeof buffer);
    for (const string& linha : linhas) {
        fwrite(linha.data(), 1, linha.size(), comBuffer);
    }
    fflush(comBuffer);

    printf("sem buffer: %6ld chamadas, %ld bytes\n", cru.chamadas, cru.bytes);
    printf("com buffer: %6ld chamadas, %ld bytes\n", disp.chamadas, disp.bytes);
    fclose(comBuffer);
}
```

## Page cache

O kernel usa toda a RAM que sobra como **page cache**: cópias de páginas de arquivos. Leituras que acertam o cache não tocam o disco; escritas vão para o cache, a página é marcada como suja e um processo do kernel a grava depois (por padrão, dados sujos ficam até cerca de 30 segundos). É por isso que o `free` mostra pouca memória "livre" num servidor saudável: ela está em `buff/cache` e é devolvida assim que alguém precisar.

A simulação modela um page cache LRU de 4 páginas e mostra o efeito de ler o mesmo arquivo duas vezes, e o de uma varredura grande no meio:

<CodeTabs>

```python
from collections import OrderedDict

class PageCache:
    def __init__(self, capacidade):
        self.paginas = OrderedDict()
        self.capacidade = capacidade
        self.hits = self.misses = 0

    def ler(self, arquivo, pagina):
        chave = (arquivo, pagina)
        if chave in self.paginas:
            self.paginas.move_to_end(chave)
            self.hits += 1
        else:
            self.misses += 1
            if len(self.paginas) >= self.capacidade:
                self.paginas.popitem(last=False)
            self.paginas[chave] = True

    def rodada(self, nome, leituras):
        h0, m0 = self.hits, self.misses
        for arq, pag in leituras:
            self.ler(arq, pag)
        print(f"{nome:<28} hits={self.hits - h0:>2} misses={self.misses - m0:>2}")

cache = PageCache(capacidade=4)
config = [("config", p) for p in range(3)]
cache.rodada("1a leitura de config", config)
cache.rodada("2a leitura de config", config)
cache.rodada("varredura de backup (10 pag)", [("backup", p) for p in range(10)])
cache.rodada("3a leitura de config", config)
```

```javascript
class PageCache {
  constructor(capacidade) {
    this.paginas = new Map(); // o Map guarda a ordem de inserção: o primeiro é o menos recente
    this.capacidade = capacidade;
    this.hits = this.misses = 0;

    const chave = `${arquivo}:${pagina}`;

      this.paginas.delete(chave); // move para o fim (mais recente)
```

```java
import java.util.*;

class Leitura {
    final String arquivo;
    final int pagina;

    Leitura(String arquivo, int pagina) {
        this.arquivo = arquivo;
        this.pagina = pagina;
    }
}

class PageCache {
    // o LinkedHashMap guarda a ordem de inserção: o primeiro é o menos recente
    private final LinkedHashMap<String, Boolean> paginas = new LinkedHashMap<>();
    private final int capacidade;
    int hits = 0, misses = 0;

    PageCache(int capacidade) {
        this.capacidade = capacidade;
    }

    void ler(String arquivo, int pagina) {
        String chave = arquivo + ":" + pagina;
        if (paginas.containsKey(chave)) {
            paginas.remove(chave); // move para o fim (mais recente)
            paginas.put(chave, true);
            hits++;
        } else {
            misses++;
            if (paginas.size() >= capacidade) {
                paginas.remove(paginas.keySet().iterator().next());
            }
            paginas.put(chave, true);
        }
    }

    void rodada(String nome, List<Leitura> leituras) {
        int h0 = hits, m0 = misses;
        for (Leitura l : leituras) {
            ler(l.arquivo, l.pagina);
        }
        System.out.println(String.format("%-28s hits=%2d misses=%2d", nome, hits - h0, misses - m0));
    }
}
```

```cpp
#include <cstdio>
#include <list>
#include <map>
#include <string>
#include <utility>
#include <vector>
using namespace std;

using Chave = pair<string, int>;

class PageCache {
    // lista na ordem de uso (frente = menos recente) + mapa para achar o nó: o mesmo que o OrderedDict faz
    list<Chave> ordem;
    map<Chave, list<Chave>::iterator> paginas;
    size_t capacidade;

public:
    int hits = 0, misses = 0;

    PageCache(size_t capacidade) : capacidade(capacidade) {}

    void ler(const string& arquivo, int pagina) {
        Chave chave{arquivo, pagina};
        auto it = paginas.find(chave);
        if (it != paginas.end()) {
            ordem.splice(ordem.end(), ordem, it->second); // move para o fim (mais recente)
            hits++;
        } else {
            misses++;
            if (paginas.size() >= capacidade) {
                paginas.erase(ordem.front());
                ordem.pop_front();
            }
            ordem.push_back(chave);
            paginas[chave] = prev(ordem.end());
        }
    }

    void rodada(const string& nome, const vector<Chave>& leituras) {
        int h0 = hits, m0 = misses;
        for (const auto& [arq, pag] : leituras) {
            ler(arq, pag);
        }
        printf("%-28s hits=%2d misses=%2d\n", nome.c_str(), hits - h0, misses - m0);
    }
};

vector<Chave> paginasDe(const string& arquivo, int n) {
    vector<Chave> lista;
    for (int p = 0; p < n; p++) {
        lista.push_back({arquivo, p});

    return lista;
}
```

```csharp
using System;
using System.Collections.Generic;

class Leitura
{
    public readonly string Arquivo;
    public readonly int Pagina;

    public Leitura(string arquivo, int pagina)
    {
        Arquivo = arquivo;
        Pagina = pagina;
    }
}

class PageCache
{
    // lista na ordem de uso (frente = menos recente) + dicionário para achar o nó: o mesmo que o OrderedDict faz
    private readonly LinkedList<string> ordem = new LinkedList<string>();
    private readonly Dictionary<string, LinkedListNode<string>> paginas = new Dictionary<string, LinkedListNode<string>>();
    private readonly int capacidade;
    public int Hits = 0, Misses = 0;

    public PageCache(int capacidade)
    {
        this.capacidade = capacidade;
    }

    public void Ler(string arquivo, int pagina)
    {
        string chave = arquivo + ":" + pagina;
        LinkedListNode<string> no;
        if (paginas.TryGetValue(chave, out no))
        {
            ordem.Remove(no); // move para o fim (mais recente)
            ordem.AddLast(no);
            Hits++;
        }
        else
        {
            Misses++;
            if (paginas.Count >= capacidade)
            {
                paginas.Remove(ordem.First.Value);
                ordem.RemoveFirst();
            }
            paginas[chave] = ordem.AddLast(chave);
        }
    }

    public void Rodada(string nome, List<Leitura> leituras)
    {
        int h0 = Hits, m0 = Misses;
        foreach (var l in leituras)
        {
            Ler(l.Arquivo, l.Pagina);
        }
        Console.WriteLine(string.Format("{0,-28} hits={1,2} misses={2,2}", nome, Hits - h0, Misses - m0));
    }
}

static List<Leitura> PaginasDe(string arquivo, int n)
{
    var lista = new List<Leitura>();
    for (int p = 0; p < n; p++)
    {
        lista.Add(new Leitura(arquivo, p));
    }
    return lista;
}

static void Main()
{
    var cache = new PageCache(4);
    var config = PaginasDe("config", 3);
    cache.Rodada("1a leitura de config", config);
    cache.Rodada("2a leitura de config", config);
    cache.Rodada("varredura de backup (10 pag)", PaginasDe("backup", 10));
    cache.Rodada("3a leitura de config", config);
}
```

```go
}

type PageCache struct {
	// lista na ordem de uso (frente = menos recente) + mapa para achar o nó: o mesmo que o OrderedDict faz
	ordem        *list.List
	paginas      map[Chave]*list.Element
	capacidade   int
	hits, misses int
}

func NovoPageCache(capacidade int) *PageCache {
	return &PageCache{ordem: list.New(), paginas: map[Chave]*list.Element{}, capacidade: capacidade}
}

func (c *PageCache) ler(arquivo string, pagina int) {
	chave := Chave{arquivo, pagina}
	if el, ok := c.paginas[chave]; ok {
		c.ordem.MoveToBack(el) // move para o fim (mais recente)
		c.hits++
	} else {
		c.misses++
		if len(c.paginas) >= c.capacidade {
			velho := c.ordem.Front()
			delete(c.paginas, velho.Value.(Chave))
			c.ordem.Remove(velho)
		}
		c.paginas[chave] = c.ordem.PushBack(chave)
	}
}

func (c *PageCache) rodada(nome string, leituras []Chave) {
	h0, m0 := c.hits, c.misses
	for _, l := range leituras {
		c.ler(l.arquivo, l.pagina)
	}
	fmt.Printf("%-28s hits=%2d misses=%2d\n", nome, c.hits-h0, c.misses-m0)
}

func paginasDe(arquivo string, n int) []Chave {
	lista := []Chave{}
	for p := 0; p < n; p++ {
		lista = append(lista, Chave{arquivo, p})
	}
	return lista
}

func main() {
	cache := NovoPageCache(4)
	config := paginasDe("config", 3)
	cache.rodada("1a leitura de config", config)
	cache.rodada("2a leitura de config", config)
	cache.rodada("varredura de backup (10 pag)", paginasDe("backup", 10))
	cache.rodada("3a leitura de config", config)
}
```

</CodeTabs>

```text
Saída:

2a leitura de config         hits= 3 misses= 0
varredura de backup (10 pag) hits= 0 misses=10
3a leitura de config         hits= 0 misses= 3
```

A segunda leitura sai inteira do cache. Mas a varredura do backup, lida uma única vez, expulsou as páginas quentes de `config`, e a terceira leitura volta ao disco. Por isso ferramentas de backup usam `posix_fadvise` com `DONTNEED` ou `O_DIRECT` para não poluir o cache.

## Garantindo durabilidade

| Chamada | O que garante |
| --- | --- |
| `write` | Os dados estão no page cache; outros processos já os veem |
| `fflush` / `flush()` | Saíram do buffer da linguagem para o kernel |
| `fsync(fd)` | Dados e metadados do arquivo estão no disco |
| `fdatasync(fd)` | Só os dados (e metadados essenciais), um pouco mais barato |
| `fsync` do diretório | A entrada criada ou renomeada também persistiu |
| `O_DIRECT` | Ignora o page cache; a aplicação gerencia o próprio cache |

Bancos de dados fazem `fsync` do write-ahead log a cada commit (ou em grupos de commits, o **group commit**) e é por isso que a latência de commit está ligada à latência de `fsync` do disco. Muitos bancos (PostgreSQL é exceção notável) usam `O_DIRECT` para os dados, porque o próprio buffer pool já faz o papel de cache e não querem cópias duplicadas.

<Callout type="warning" title="O incidente do fsyncgate">
Em 2018 descobriu-se que, no Linux, se um `fsync` falhar por erro de disco, as páginas sujas podem ser descartadas e um segundo `fsync` retorna sucesso. O PostgreSQL passou a tratar falha de `fsync` como erro fatal e reiniciar a partir do WAL. Lição: erro de `fsync` não é algo para simplesmente tentar de novo.
</Callout>

## Modelos de E/S

- **Bloqueante:** a thread dorme até a operação terminar. Simples; escala com muitas threads.
- **Não bloqueante + multiplexação** (`select`, `poll`, `epoll`, `kqueue`): uma thread acompanha milhares de sockets e só age nos que estão prontos. É a base de Nginx, Node.js e Netty.
- **Assíncrona de verdade** (`io_uring`, IOCP no Windows): você envia pedidos numa fila compartilhada com o kernel e colhe os resultados depois, com poucas syscalls.

```bash
free -h                     # coluna buff/cache
vmtouch arquivo.db          # quanto do arquivo está no page cache
echo 3 > /proc/sys/vm/drop_caches   # esvazia o cache (só para testes!)
```
