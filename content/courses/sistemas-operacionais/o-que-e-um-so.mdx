Seu programa em Python chama `open("dados.csv")` e recebe um arquivo. Ele não sabe se o disco é um SSD NVMe, um volume de rede ou um pendrive, nem se outros cem processos estão disputando a mesma CPU. Quem esconde tudo isso é o **sistema operacional**: a camada de software que gerencia o hardware e oferece aos programas uma interface estável e segura para usá-lo.

## Dois papéis ao mesmo tempo

Vale a pena pensar no SO de dois jeitos complementares:

- **Máquina estendida (abstração):** em vez de setores, interrupções e registradores de controlador, você recebe arquivos, processos, sockets e memória virtual. São abstrações limpas sobre um hardware feio.
- **Gerente de recursos:** CPU, memória, disco e rede são finitos e compartilhados. O SO decide quem usa o quê, por quanto tempo, e impede que um programa atrapalhe o outro.

O compartilhamento acontece de duas formas. **No tempo**, um recurso é usado por um de cada vez, em fatias: é assim com a CPU. **No espaço**, o recurso é dividido em pedaços simultâneos: é assim com a memória e o disco.

```text
  aplicativos   →  navegador   banco de dados   seu serviço
  ------------------------------------------------------------
  bibliotecas   →  libc, runtime do Python, JVM
  ------------------------------------------------------------
  kernel        →  escalonador | memória virtual | VFS | rede | drivers
  ------------------------------------------------------------
  hardware      →  CPU   RAM   disco   placa de rede   timer
```

## Multiplexação no tempo, na prática

Com um só núcleo, dois processos parecem rodar juntos porque o SO alterna entre eles muitas vezes por segundo. A simulação abaixo dá fatias de 3 unidades de tempo a cada processo até todos terminarem:

<CodeTabs>

```python
processos = {"editor": 5, "compilador": 7, "player": 4}
fatia = 3
relogio = 0
linha_do_tempo = []

fila = list(processos)
restante = dict(processos)
while fila:
    nome = fila.pop(0)
    uso = min(fatia, restante[nome])
    linha_do_tempo.append(f"{relogio:>2}-{relogio + uso:>2} {nome}")
    relogio += uso
    restante[nome] -= uso
    if restante[nome] > 0:
        fila.append(nome)

for trecho in linha_do_tempo:
    print(trecho)
print("tempo total:", relogio)
```

```java
import java.util.*;

public static void main(String[] args) {
    Map<String, Integer> processos = new LinkedHashMap<>();
    processos.put("editor", 5);
    processos.put("compilador", 7);
    processos.put("player", 4);
    int fatia = 3;
    int relogio = 0;
    List<String> linhaDoTempo = new ArrayList<>();

    Deque<String> fila = new ArrayDeque<>(processos.keySet());
    Map<String, Integer> restante = new HashMap<>(processos);
    while (!fila.isEmpty()) {
        String nome = fila.pollFirst();
        int uso = Math.min(fatia, restante.get(nome));
        linhaDoTempo.add(String.format("%2d-%2d %s", relogio, relogio + uso, nome));
        relogio += uso;
        restante.put(nome, restante.get(nome) - uso);
        if (restante.get(nome) > 0) {
            fila.addLast(nome);
        }
    }

    for (String trecho : linhaDoTempo) {
        System.out.println(trecho);
    }
    System.out.println("tempo total: " + relogio);
}
```

```cpp
#include <algorithm>
#include <cstdio>
#include <deque>
#include <map>
#include <string>
#include <utility>
#include <vector>
using namespace std;

int main() {
    vector<pair<string, int>> processos = {{"editor", 5}, {"compilador", 7}, {"player", 4}};
    int fatia = 3;
    int relogio = 0;
    vector<string> linhaDoTempo;

    deque<string> fila;
    map<string, int> restante;
    for (const auto& [nome, rajada] : processos) {
        fila.push_back(nome);
        restante[nome] = rajada;
    }
    while (!fila.empty()) {
        string nome = fila.front();
        fila.pop_front();
        int uso = min(fatia, restante[nome]);
        char trecho[64];
        snprintf(trecho, sizeof trecho, "%2d-%2d %s", relogio, relogio + uso, nome.c_str());
        linhaDoTempo.push_back(trecho);
        relogio += uso;
        restante[nome] -= uso;
        if (restante[nome] > 0) {
            fila.push_back(nome);
        }
    }

    for (const string& trecho : linhaDoTempo) {
        printf("%s\n", trecho.c_str());
    }
    printf("tempo total: %d\n", relogio);
}
```

```csharp
using System;
using System.Collections.Generic;

static void Main()
{
    var processos = new List<KeyValuePair<string, int>> {
        new KeyValuePair<string, int>("editor", 5),
        new KeyValuePair<string, int>("compilador", 7),
        new KeyValuePair<string, int>("player", 4),
    };
    int fatia = 3;
    int relogio = 0;
    var linhaDoTempo = new List<string>();

    var fila = new Queue<string>();
    var restante = new Dictionary<string, int>();
    foreach (var p in processos)
    {
        fila.Enqueue(p.Key);
        restante[p.Key] = p.Value;
    }
    while (fila.Count > 0)
    {
        string nome = fila.Dequeue();
        int uso = Math.Min(fatia, restante[nome]);
        linhaDoTempo.Add(string.Format("{0,2}-{1,2} {2}", relogio, relogio + uso, nome));
        relogio += uso;
        restante[nome] -= uso;
        if (restante[nome] > 0)
        {
            fila.Enqueue(nome);
        }
    }

    foreach (var trecho in linhaDoTempo)
    {
        Console.WriteLine(trecho);
    }
    Console.WriteLine("tempo total: " + relogio);
}
```

```go
import "fmt"

func main() {
	nomes := []string{"editor", "compilador", "player"}
	processos := map[string]int{"editor": 5, "compilador": 7, "player": 4}
	fatia := 3
	relogio := 0
	linhaDoTempo := []string{}

	fila := append([]string{}, nomes...) // o map do Go não guarda ordem: a fila parte da lista
	restante := map[string]int{}
	for nome, rajada := range processos {
		restante[nome] = rajada
	}
	for len(fila) > 0 {
		nome := fila[0]
		fila = fila[1:]
		uso := restante[nome]
		if fatia < uso {
			uso = fatia
		}
		linhaDoTempo = append(linhaDoTempo, fmt.Sprintf("%2d-%2d %s", relogio, relogio+uso, nome))
		relogio += uso
		restante[nome] -= uso
		if restante[nome] > 0 {
			fila = append(fila, nome)
		}
	}

	for _, trecho := range linhaDoTempo {
		fmt.Println(trecho)
	}
	fmt.Println("tempo total:", relogio)
}
```

## A mesma interface para qualquer dispositivo

A outra metade do trabalho é a abstração. O programa abaixo usa as chamadas de baixo nível do módulo `os`, que mapeiam quase um para um para chamadas de sistema: abrir, escrever, posicionar, ler e fechar. O código não muda se o arquivo estiver num SSD, num HD ou num disco em memória.

<CodeTabs>

```python
import os
import tempfile

with tempfile.TemporaryDirectory() as pasta:
    caminho = os.path.join(pasta, "log.txt")
    fd = os.open(caminho, os.O_CREAT | os.O_RDWR)
    escritos = os.write(fd, b"pedido 42 aprovado")
    os.lseek(fd, 0, os.SEEK_SET)
    lido = os.read(fd, 100)
    os.close(fd)
    print("bytes escritos:", escritos)
    print("conteudo:", lido.decode())
    print("tamanho segundo o SO:", os.stat(caminho).st_size)
```

```javascript
const fs = require("fs");
const os = require("os");
const path = require("path");

const pasta = fs.mkdtempSync(path.join(os.tmpdir(), "so-"));
try {
  const caminho = path.join(pasta, "log.txt");
  const fd = fs.openSync(caminho, fs.constants.O_CREAT | fs.constants.O_RDWR);
  const escritos = fs.writeSync(fd, Buffer.from("pedido 42 aprovado"));
  // o Node não expõe lseek: a posição 0 vai direto na leitura (equivale a voltar ao início e ler)
  const buf = Buffer.alloc(100);
  const n = fs.readSync(fd, buf, 0, 100, 0);
  const lido = buf.subarray(0, n);
  fs.closeSync(fd);
  console.log("bytes escritos:", escritos);
  console.log("conteudo:", lido.toString());
  console.log("tamanho segundo o SO:", fs.statSync(caminho).size);
  fs.unlinkSync(caminho);
} finally {
  fs.rmdirSync(pasta);
}
```

```java
import java.io.*;
import java.nio.ByteBuffer;
import java.nio.channels.FileChannel;
import java.nio.file.*;

public static void main(String[] args) throws IOException {
    Path pasta = Files.createTempDirectory("so");
    Path caminho = pasta.resolve("log.txt");
    // FileChannel é a camada do Java mais próxima do descritor: write/position/read
    FileChannel fd = FileChannel.open(caminho, StandardOpenOption.CREATE, StandardOpenOption.READ, StandardOpenOption.WRITE);
    int escritos = fd.write(ByteBuffer.wrap("pedido 42 aprovado".getBytes()));
    fd.position(0); // lseek(fd, 0, SEEK_SET)
    ByteBuffer buf = ByteBuffer.allocate(100);
    int n = fd.read(buf);
    String lido = new String(buf.array(), 0, n);
    fd.close();
    System.out.println("bytes escritos: " + escritos);
    System.out.println("conteudo: " + lido);
    System.out.println("tamanho segundo o SO: " + Files.size(caminho));
    Files.delete(caminho);
    Files.delete(pasta);
}
```

O número `fd` é um **descritor de arquivo**: um índice numa tabela que o kernel mantém para o processo. O programa nunca toca no disco; ele pede ao kernel, que fala com o driver.

## Kernel, SO e o resto

Em conversa técnica, "SO" às vezes significa só o **kernel** (o código que roda em modo privilegiado) e às vezes o pacote todo, com shell, bibliotecas e utilitários. Linux, a rigor, é um kernel; Ubuntu é uma distribuição que o empacota. Saber essa diferença ajuda a entender containers mais adiante: todos os containers de uma máquina compartilham o mesmo kernel, mas cada um pode ter o próprio "resto".

| Componente | Responsabilidade | Exemplo de problema real |
| --- | --- | --- |
| Escalonador | Decide quem usa a CPU | Latência alta com CPU saturada |
| Gerência de memória | Memória virtual, paginação | OOM killer matando seu serviço |
| Sistema de arquivos | Arquivos, diretórios, cache | `fsync` lento derrubando throughput |
| Pilha de rede | TCP/IP, sockets | Esgotar portas efêmeras |
| Drivers | Falar com cada dispositivo | Driver de disco com bug travando E/S |

<Callout type="tip" title="Por que um engenheiro de aplicação precisa disso">
Quase todo problema de desempenho estranho, como pausas, picos de latência ou memória que "some", é o SO fazendo exatamente o que foi projetado para fazer. Conhecer o mecanismo transforma mistério em diagnóstico.
</Callout>

## Trade-offs de projeto

Um SO equilibra objetivos que brigam entre si: **vazão** (fazer muito trabalho) contra **latência** (responder rápido), **isolamento** (proteger processos uns dos outros) contra **desempenho** (cada fronteira de proteção custa ciclos), e **generalidade** contra **especialização**. Bancos de dados, por exemplo, muitas vezes contornam o cache de arquivos do SO porque sabem melhor o que manter em memória.
