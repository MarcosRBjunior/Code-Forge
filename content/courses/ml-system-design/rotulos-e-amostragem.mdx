Um modelo supervisionado é tão bom quanto os rótulos que recebe. Em entrevistas, a pergunta "de onde vêm os rótulos?" separa quem já pôs modelo em produção de quem só treinou em datasets prontos. Em sistemas reais, rótulos são caros, atrasados, ruidosos ou enviesados pelo próprio sistema, e quase sempre extremamente desbalanceados: 1 clique em 50 impressões, 1 fraude em 1.000 transações.

## De onde vêm os rótulos

| Fonte | Exemplo | Vantagem | Problema |
| --- | --- | --- | --- |
| Feedback implícito | Clique, tempo assistido, compra | Abundante e de graça | Ruidoso; clique não é satisfação |
| Feedback explícito | Curtida, nota, "não tenho interesse" | Sinal claro | Raro e enviesado para quem avalia |
| Anotação humana | Moderadores rotulando posts | Alta qualidade | Caro, lento, precisa de guia e concordância entre anotadores |
| Resultado de negócio | Estorno, inadimplência | É o que importa | Chega semanas ou meses depois |
| Heurística | Regras que rotulam automaticamente | Escala | Ensina o modelo a imitar a regra |

Três cuidados aparecem sempre:

- **Atraso**: se o estorno de uma fraude leva até 60 dias, os exemplos dos últimos 60 dias ainda parecem legítimos. Ou você espera a janela fechar, ou usa um rótulo provisório e corrige depois.
- **Definição**: "o usuário gostou do vídeo" precisa virar regra objetiva, como "assistiu mais de 50% ou curtiu". Escreva a regra e meça quanto ela concorda com satisfação declarada numa amostra.
- **Viés de exposição**: você só observa reação a itens que o sistema mostrou. Itens nunca exibidos não têm rótulo negativo, apenas ausência de dado. Reservar uma pequena fração de tráfego para exploração ajuda.

## Amostragem para lidar com o desbalanceamento

Com bilhões de impressões e poucos cliques, treinar com tudo é caro e a maior parte dos negativos é redundante. A técnica padrão é **subamostrar negativos**: manter todos os positivos e só uma fração `w` dos negativos. O treino fica mais rápido e equilibrado, mas o modelo passa a prever probabilidades infladas, porque viu positivos em proporção maior que a real. Se a probabilidade importa (anúncios, decisões com custo), você precisa **recalibrar**:

```text
p_real = q / (q + (1 - q) / w)
```

em que `q` é a probabilidade prevista pelo modelo treinado na amostra.

<CodeTabs>

```python
import random

random.seed(42)
n = 200_000
ctr_real = 0.02
dados = [1 if random.random() < ctr_real else 0 for _ in range(n)]

w = 0.1
amostra = [y for y in dados if y == 1 or random.random() < w]
positivos = sum(amostra)
q = positivos / len(amostra)

def recalibrar(q, w):
    return q / (q + (1 - q) / w)

print(f"exemplos: completo={n} amostra={len(amostra)}")
print(f"taxa de positivos real   = {sum(dados) / n:.4f}")
print(f"taxa vista na amostra (q) = {q:.4f}")
print(f"taxa recalibrada          = {recalibrar(q, w):.4f}")

pesos = [1.0 if y == 1 else 1 / w for y in amostra]
ponderada = sum(p for p, y in zip(pesos, amostra) if y == 1) / sum(pesos)
print(f"alternativa com pesos 1/w = {ponderada:.4f}")
```

```javascript
// gerador com semente (mulberry32): o Math.random do JS não aceita semente
function mulberry32(semente) {
  return () => {
    semente = (semente + 0x6d2b79f5) | 0;
    let z = Math.imul(semente ^ (semente >>> 15), 1 | semente);
    z = (z + Math.imul(z ^ (z >>> 7), 61 | z)) ^ z;
    return ((z ^ (z >>> 14)) >>> 0) / 4294967296;
  };
}

const rng = mulberry32(42);
const n = 200_000;
const ctrReal = 0.02;
const dados = Array.from({ length: n }, () => (rng() < ctrReal ? 1 : 0));

const w = 0.1;
const amostra = dados.filter((y) => y === 1 || rng() < w);
const positivos = amostra.reduce((a, b) => a + b, 0);

  return q / (q + (1 - q) / w);
}
```

```java
import java.util.*;

static double recalibrar(double q, double w) {
    return q / (q + (1 - q) / w);
}

public static void main(String[] args) {
    Random rng = new Random(42);
    int n = 200000;
    double ctrReal = 0.02;
    int[] dados = new int[n];
    for (int i = 0; i < n; i++) dados[i] = rng.nextDouble() < ctrReal ? 1 : 0;

    double w = 0.1;
    List<Integer> amostra = new ArrayList<>();
    for (int y : dados) {
        if (y == 1 || rng.nextDouble() < w) amostra.add(y);
    }
    int positivos = 0;
    for (int y : amostra) positivos += y;
    double q = (double) positivos / amostra.size();
    int totalPositivos = 0;
    for (int y : dados) totalPositivos += y;

    System.out.println("exemplos: completo=" + n + " amostra=" + amostra.size());
    System.out.println(String.format(Locale.US, "taxa de positivos real   = %.4f", (double) totalPositivos / n));
    System.out.println(String.format(Locale.US, "taxa vista na amostra (q) = %.4f", q));
    System.out.println(String.format(Locale.US, "taxa recalibrada          = %.4f", recalibrar(q, w)));

    double somaPos = 0, somaPesos = 0;
    for (int y : amostra) {
        double p = y == 1 ? 1.0 : 1 / w;
        if (y == 1) somaPos += p;
        somaPesos += p;
    }
    double ponderada = somaPos / somaPesos;
    System.out.println(String.format(Locale.US, "alternativa com pesos 1/w = %.4f", ponderada));
```

```go

import (
	"fmt"
	"math/rand"
)

func recalibrar(q, w float64) float64 {
	return q / (q + (1-q)/w)
}

func main() {
	rng := rand.New(rand.NewSource(42))
	n := 200000
	ctrReal := 0.02
	dados := make([]int, n)
	for i := range dados {
		if rng.Float64() < ctrReal {
			dados[i] = 1
		}
	}

	w := 0.1
	var amostra []int
	for _, y := range dados {
		if y == 1 || rng.Float64() < w {
			amostra = append(amostra, y)
		}
	}
	positivos := 0
	for _, y := range amostra {
		positivos += y
	}
	q := float64(positivos) / float64(len(amostra))
	totalPositivos := 0
	for _, y := range dados {
		totalPositivos += y
	}

	fmt.Printf("exemplos: completo=%d amostra=%d\n", n, len(amostra))
	fmt.Printf("taxa de positivos real   = %.4f\n", float64(totalPositivos)/float64(n))
	fmt.Printf("taxa vista na amostra (q) = %.4f\n", q)
	fmt.Printf("taxa recalibrada          = %.4f\n", recalibrar(q, w))

	somaPos, somaPesos := 0.0, 0.0
	for _, y := range amostra {
		p := 1 / w
		if y == 1 {
			p = 1.0
			somaPos += p
		}
		somaPesos += p
	}
	ponderada := somaPos / somaPesos
	fmt.Printf("alternativa com pesos 1/w = %.4f\n", ponderada)
}
```

## Outras estratégias de amostragem

- **Amostragem negativa em recomendação**: com feedback implícito só há positivos (o usuário assistiu). Os negativos são sorteados entre itens não interagidos, de forma uniforme ou proporcional à popularidade, para que o modelo não aprenda apenas "item popular é bom". Negativos difíceis (itens parecidos que o usuário viu e ignorou) ensinam mais.
- **Amostragem estratificada** para avaliação: garanta exemplos suficientes de segmentos pequenos (países, usuários novos) para medir cada um.
- **Aprendizado ativo**: em vez de rotular aleatoriamente, mande para anotação humana os exemplos em que o modelo está mais incerto. O mesmo orçamento rende mais.
- **Sobreamostragem de positivos** (repetir ou gerar sintéticos): útil em datasets pequenos, mas cuidado com overfitting aos poucos positivos.

<Callout type="warning" title="Nunca subamostre o conjunto de teste">
Subamostragem é para treino. Avalie no conjunto com a distribuição real, senão precisão e métricas de calibração ficam otimistas e não refletem o que você verá em produção.
</Callout>

## Na entrevista

Ao chegar em dados, diga explicitamente: qual é o rótulo, como ele é definido, quanto demora e que vieses carrega. Mencione o desbalanceamento com a ordem de grandeza e a estratégia de amostragem com a recalibração. Follow-ups comuns: "e se o rótulo leva 90 dias?" (rótulos proxy mais cedo, janela de maturação, treino com correção posterior), "como conseguir rótulos para um produto novo?" (heurística, anotação, feedback explícito no começo) e "como você garantiria a qualidade dos anotadores?" (guia, exemplos de ouro, concordância entre anotadores).
