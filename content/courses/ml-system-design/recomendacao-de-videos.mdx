"Projete o sistema de recomendação da página inicial de uma plataforma de vídeos" é talvez a pergunta mais comum de ML system design. Ela exercita tudo: definição de objetivo, rótulos implícitos, recuperação em escala, ranqueamento com muitos sinais e avaliação online. Vamos percorrer como uma entrevista de 45 minutos.

## Esclarecer o objetivo e a métrica

Comece perguntando o que o negócio quer. "Mais cliques" é uma resposta perigosa: otimizar só clique premia miniaturas apelativas e vídeos que o usuário abandona em 5 segundos. Uma proposta mais saudável:

- **Métrica de negócio (online)**: tempo assistido por usuário por dia e retenção de 7 dias.
- **Métrica de guarda**: taxa de "não tenho interesse", denúncias, diversidade de criadores.
- **Escala hipotética**: centenas de milhões de usuários ativos, um catálogo da ordem de 1 bilhão de vídeos, latência de p99 abaixo de 200 ms para montar a página.

Pergunte também se há restrições: conteúdo infantil, regiões, vídeos recém-publicados que precisam de exposição.

## Dados e rótulos

Quase não há rótulo explícito. Você constrói rótulos a partir de eventos de log:

| Evento | Rótulo derivado |
| --- | --- |
| Impressão sem clique | negativo fraco |
| Clique e assistiu menos de 10% | negativo ou neutro |
| Assistiu mais de 50% | positivo |
| Curtiu, compartilhou, se inscreveu | positivo forte |
| "Não recomendar este canal" | negativo forte |

Dois cuidados: **viés de posição** (itens no topo recebem mais clique só por estarem no topo) e **viés de exposição** (o modelo só vê feedback do que ele mesmo mostrou). Registre a posição como feature no treino e fixe-a num valor neutro no servimento; reserve uma fatia pequena de tráfego com exploração aleatória.

## Features

- **Usuário**: histórico recente de vídeos assistidos (como sequência de IDs), idioma, país, tipo de dispositivo, hora do dia.
- **Vídeo**: embedding de título e miniatura, duração, idade do vídeo, canal, taxa histórica de conclusão.
- **Cruzadas**: quantas vezes o usuário assistiu esse canal, similaridade entre o embedding do vídeo e a média dos últimos 20 assistidos.

## Modelo: base e evolução

Mostre que você sabe começar simples:

1. **Base**: vídeos populares por país e idioma. Serve de fallback e de piso de comparação.
2. **Recuperação**: um modelo two-tower que gera embeddings de usuário e de vídeo; busca de vizinhos aproximados (ANN) traz de 500 a 1.000 candidatos. Some fontes extras: inscrições, vídeos em alta, continuação de séries.
3. **Ranqueamento**: um modelo mais pesado (árvores com gradient boosting no início, depois uma rede multitarefa) que prevê P(clique), tempo esperado assistido e P(curtida). A pontuação final é uma combinação ponderada dessas cabeças.
4. **Re-ranqueamento**: regras de diversidade (no máximo 2 vídeos do mesmo canal no topo), remoção de já assistidos, políticas de conteúdo.

O programa abaixo simula a cascata com embeddings de brinquedo: a recuperação usa só produto interno e o ranqueador adiciona um sinal de qualidade que a recuperação não vê.

```python
import random

random.seed(7)
DIM, N = 4, 2000

def vetor():
    return [random.gauss(0, 1) for _ in range(DIM)]

def dot(a, b):
    return sum(x * y for x, y in zip(a, b))

videos = [{"id": i, "emb": vetor(), "qualidade": random.random()} for i in range(N)]
usuario = vetor()

def relevancia_real(v):
    return dot(usuario, v["emb"]) + 3 * v["qualidade"]

ideal = sorted(videos, key=relevancia_real, reverse=True)[:10]
ideal_ids = {v["id"] for v in ideal}

candidatos = sorted(videos, key=lambda v: dot(usuario, v["emb"]), reverse=True)[:200]
so_recuperacao = candidatos[:10]
ranqueados = sorted(candidatos, key=relevancia_real, reverse=True)[:10]

def acertos(lista):
    return len(ideal_ids & {v["id"] for v in lista})

print(f"catalogo: {N}, candidatos apos recuperacao: {len(candidatos)}")
print(f"recall dos candidatos sobre o top-10 ideal: {acertos(candidatos)}/10")
print(f"top-10 so com recuperacao: {acertos(so_recuperacao)}/10 acertos")
print(f"top-10 apos ranqueamento: {acertos(ranqueados)}/10 acertos")
```

// gerador com semente (mulberry32): o Math.random do JS não aceita semente
function mulberry32(semente) {
  return () => {
    semente = (semente + 0x6d2b79f5) | 0;
    let z = Math.imul(semente ^ (semente >>> 15), 1 | semente);
    z = (z + Math.imul(z ^ (z >>> 7), 61 | z)) ^ z;
    return ((z ^ (z >>> 14)) >>> 0) / 4294967296;
  };
}

const rng = mulberry32(7);

// equivalente ao random.gauss(mu, sigma) do Python (Box-Muller)
function gauss(mu, sigma) {
  const u1 = 1 - rng();
  const u2 = rng();
  return mu + sigma * Math.sqrt(-2 * Math.log(u1)) * Math.cos(2 * Math.PI * u2);
}

const DIM = 4, N = 2000;

function vetor() {
  return Array.from({ length: DIM }, () => gauss(0, 1));
}

function dot(a, b) {
  return a.reduce((soma, x, i) => soma + x * b[i], 0);
}

const videos = [];
for (let i = 0; i < N; i++) {
  const emb = vetor();
  videos.push({ id: i, emb, qualidade: rng() });
}
const usuario = vetor();

function relevanciaReal(v) {
  return dot(usuario, v.emb) + 3 * v.qualidade;
}

const ideal = [...videos].sort((a, b) => relevanciaReal(b) - relevanciaReal(a)).slice(0, 10);
const idealIds = new Set(ideal.map((v) => v.id));

const candidatos = [...videos].sort((a, b) => dot(usuario, b.emb) - dot(usuario, a.emb)).slice(0, 200);
const soRecuperacao = candidatos.slice(0, 10);
const ranqueados = [...candidatos].sort((a, b) => relevanciaReal(b) - relevanciaReal(a)).slice(0, 10);

function acertos(lista) {
  return new Set(lista.map((v) => v.id).filter((id) => idealIds.has(id))).size;
}

console.log(`catalogo: ${N}, candidatos apos recuperacao: ${candidatos.length}`);
console.log(`recall dos candidatos sobre o top-10 ideal: ${acertos(candidatos)}/10`);
console.log(`top-10 so com recuperacao: ${acertos(soRecuperacao)}/10 acertos`);
console.log(`top-10 apos ranqueamento: ${acertos(ranqueados)}/10 acertos`);

import java.util.*;
import java.util.stream.*;

static final int DIM = 4, N = 2000;
static Random rng = new Random(7);

static double[] vetor() {
    double[] v = new double[DIM];
    for (int d = 0; d < DIM; d++) v[d] = rng.nextGaussian();
    return v;
}

static double dot(double[] a, double[] b) {
    double soma = 0.0;
    for (int i = 0; i < a.length; i++) soma += a[i] * b[i];
    return soma;
}

static double[][] emb = new double[N][];
static double[] qualidade = new double[N];
static double[] usuario;

static double relevanciaReal(int v) {
    return dot(usuario, emb[v]) + 3 * qualidade[v];
}

static Set<Integer> idealIds;

static int acertos(List<Integer> lista) {
    Set<Integer> ids = new HashSet<>(lista);
    ids.retainAll(idealIds);
    return ids.size();
}

public static void main(String[] args) {
    // cada video e o seu indice: id i, embedding emb[i], qualidade[i]
    for (int i = 0; i < N; i++) {
        emb[i] = vetor();
        qualidade[i] = rng.nextDouble();
    }
    usuario = vetor();

    List<Integer> todos = IntStream.range(0, N).boxed().collect(Collectors.toList());
    List<Integer> ideal = todos.stream()
        .sorted(Comparator.comparingDouble((Integer v) -> relevanciaReal(v)).reversed())
        .limit(10).collect(Collectors.toList());
    idealIds = new HashSet<>(ideal);

    List<Integer> candidatos = todos.stream()
        .sorted(Comparator.comparingDouble((Integer v) -> dot(usuario, emb[v])).reversed())
        .limit(200).collect(Collectors.toList());
    List<Integer> soRecuperacao = candidatos.subList(0, 10);
    List<Integer> ranqueados = candidatos.stream()
        .sorted(Comparator.comparingDouble((Integer v) -> relevanciaReal(v)).reversed())
        .limit(10).collect(Collectors.toList());

    System.out.println("catalogo: " + N + ", candidatos apos recuperacao: " + candidatos.size());
    System.out.println("recall dos candidatos sobre o top-10 ideal: " + acertos(candidatos) + "/10");
    System.out.println("top-10 so com recuperacao: " + acertos(soRecuperacao) + "/10 acertos");
    System.out.println("top-10 apos ranqueamento: " + acertos(ranqueados) + "/10 acertos");
}

#include <algorithm>
#include <cstdio>
#include <random>
#include <set>
#include <vector>
using namespace std;

const int DIM = 4, N = 2000;
mt19937 rng(7);
normal_distribution<double> normal(0.0, 1.0);
uniform_real_distribution<double> uniforme(0.0, 1.0);

struct Video {
    int id;
    vector<double> emb;
    double qualidade;
};

vector<double> vetor() {
    vector<double> v(DIM);
    for (int d = 0; d < DIM; d++) v[d] = normal(rng);
    return v;
}

double dot(const vector<double>& a, const vector<double>& b) {
    double soma = 0.0;
    for (size_t i = 0; i < a.size(); i++) soma += a[i] * b[i];
    return soma;
}

vector<double> usuario;
set<int> idealIds;

double relevanciaReal(const Video& v) {
    return dot(usuario, v.emb) + 3 * v.qualidade;
}

vector<Video> topPor(vector<Video> lista, size_t k, bool porRelevancia) {
    stable_sort(lista.begin(), lista.end(), [&](const Video& a, const Video& b) {
        if (porRelevancia) return relevanciaReal(a) > relevanciaReal(b);
        return dot(usuario, a.emb) > dot(usuario, b.emb);
    });
    if (lista.size() > k) lista.resize(k);
    return lista;
}

int acertos(const vector<Video>& lista) {
    set<int> ids;
    for (const Video& v : lista) {
        if (idealIds.count(v.id)) ids.insert(v.id);
    }
    return (int)ids.size();
}

int main() {
    vector<Video> videos;
    for (int i = 0; i < N; i++) {
        vector<double> emb = vetor();
        videos.push_back({i, emb, uniforme(rng)});
    }
    usuario = vetor();

    vector<Video> ideal = topPor(videos, 10, true);
    for (const Video& v : ideal) idealIds.insert(v.id);

    vector<Video> candidatos = topPor(videos, 200, false);
    vector<Video> soRecuperacao(candidatos.begin(), candidatos.begin() + 10);
    vector<Video> ranqueados = topPor(candidatos, 10, true);

    printf("catalogo: %d, candidatos apos recuperacao: %zu\n", N, candidatos.size());
    printf("recall dos candidatos sobre o top-10 ideal: %d/10\n", acertos(candidatos));
    printf("top-10 so com recuperacao: %d/10 acertos\n", acertos(soRecuperacao));
    printf("top-10 apos ranqueamento: %d/10 acertos\n", acertos(ranqueados));
}

using System;
using System.Collections.Generic;
using System.Linq;

class Video {
    public int Id;
    public double[] Emb;
    public double Qualidade;
}

const int DIM = 4, N = 2000;
static Random rng = new Random(7);

// equivalente ao random.gauss(mu, sigma) do Python (Box-Muller)
static double Gauss(double mu, double sigma) {
    double u1 = 1.0 - rng.NextDouble();
    double u2 = rng.NextDouble();
    return mu + sigma * Math.Sqrt(-2.0 * Math.Log(u1)) * Math.Cos(2.0 * Math.PI * u2);
}

static double[] Vetor() {
    var v = new double[DIM];
    for (int d = 0; d < DIM; d++) v[d] = Gauss(0, 1);
    return v;
}

static double Dot(double[] a, double[] b) {
    double soma = 0.0;
    for (int i = 0; i < a.Length; i++) soma += a[i] * b[i];
    return soma;
}

static double[] usuario;
static HashSet<int> idealIds;

static double RelevanciaReal(Video v) {
    return Dot(usuario, v.Emb) + 3 * v.Qualidade;
}

static int Acertos(List<Video> lista) {
    return lista.Select(v => v.Id).Where(id => idealIds.Contains(id)).Distinct().Count();
}

static void Main() {
    var videos = new List<Video>();
    for (int i = 0; i < N; i++) {
        double[] emb = Vetor();
        videos.Add(new Video { Id = i, Emb = emb, Qualidade = rng.NextDouble() });
    }
    usuario = Vetor();

    var ideal = videos.OrderByDescending(RelevanciaReal).Take(10).ToList();
    idealIds = new HashSet<int>(ideal.Select(v => v.Id));

    var candidatos = videos.OrderByDescending(v => Dot(usuario, v.Emb)).Take(200).ToList();
    var soRecuperacao = candidatos.Take(10).ToList();
    var ranqueados = candidatos.OrderByDescending(RelevanciaReal).Take(10).ToList();

    Console.WriteLine($"catalogo: {N}, candidatos apos recuperacao: {candidatos.Count}");
    Console.WriteLine($"recall dos candidatos sobre o top-10 ideal: {Acertos(candidatos)}/10");
    Console.WriteLine($"top-10 so com recuperacao: {Acertos(soRecuperacao)}/10 acertos");
    Console.WriteLine($"top-10 apos ranqueamento: {Acertos(ranqueados)}/10 acertos");
}

import (
	"fmt"
	"math/rand"
	"sort"
)

const DIM, N = 4, 2000

var rng = rand.New(rand.NewSource(7))

type Video struct {
	id        int
	emb       []float64
	qualidade float64
}

func vetor() []float64 {
	v := make([]float64, DIM)
	for d := range v {
		v[d] = rng.NormFloat64()
	}
	return v
}

func dot(a, b []float64) float64 {
	soma := 0.0
	for i := range a {
		soma += a[i] * b[i]
	}
	return soma
}

var usuario []float64
var idealIds = map[int]bool{}

func relevanciaReal(v Video) float64 {
	return dot(usuario, v.emb) + 3*v.qualidade
}

func topPor(lista []Video, k int, chave func(Video) float64) []Video {
	copia := append([]Video{}, lista...)
	sort.SliceStable(copia, func(a, b int) bool { return chave(copia[a]) > chave(copia[b]) })
	if len(copia) > k {
		copia = copia[:k]
	}
	return copia
}

func acertos(lista []Video) int {
	ids := map[int]bool{}
	for _, v := range lista {
		if idealIds[v.id] {
			ids[v.id] = true
		}
	}
	return len(ids)
}

func main() {
	var videos []Video
	for i := 0; i < N; i++ {
		emb := vetor()
		videos = append(videos, Video{i, emb, rng.Float64()})
	}
	usuario = vetor()

	ideal := topPor(videos, 10, relevanciaReal)
	for _, v := range ideal {
		idealIds[v.id] = true
	}

	candidatos := topPor(videos, 200, func(v Video) float64 { return dot(usuario, v.emb) })
	soRecuperacao := candidatos[:10]
	ranqueados := topPor(candidatos, 10, relevanciaReal)

	fmt.Printf("catalogo: %d, candidatos apos recuperacao: %d\n", N, len(candidatos))
	fmt.Printf("recall dos candidatos sobre o top-10 ideal: %d/10\n", acertos(candidatos))
	fmt.Printf("top-10 so com recuperacao: %d/10 acertos\n", acertos(soRecuperacao))
	fmt.Printf("top-10 apos ranqueamento: %d/10 acertos\n", acertos(ranqueados))
}

Quem acerta a ordem final é o ranqueador, que pode ser caro porque roda sobre 200 itens, não sobre o catálogo inteiro.

## Arquitetura de treino e servimento

```text
             OFFLINE (diário / horário)                    ONLINE (por requisição)
 +-----------+    +-------------+    +-----------+     +-----------+
 | logs de   |--->| geração de  |--->| treino    |     | app abre  |
 | eventos   |    | rótulos e   |    | two-tower |     | a home    |
 | (Kafka)   |    | features    |    | e ranker  |     +-----+-----+
 +-----+-----+    +------+------+    +-----+-----+           |
       |                 |                 |           +-----v------+   embeddings
       |          +------v------+    +-----v-----+     | recuperação|<--- de vídeo
       +--------->| feature     |    | registro  |     | ANN + fontes|   (índice ANN)
                  | store       |    | de modelos|     +-----+------+
                  | (on/offline)|    +-----+-----+           | ~1.000
                  +------+------+          |           +-----v------+
                         |                 +---------->| ranker     |
                         +---------------------------->| multitarefa|
                                                       +-----+------+
                                                             | ~50
                                                       +-----v------+
                                                       | re-ranking |-> página
                                                       +------------+
```

Embeddings de vídeo são recalculados em lote e publicados num índice ANN; o embedding do usuário é calculado na hora, porque depende do que ele acabou de assistir. A feature store garante que treino e servimento usem a mesma definição de cada feature.

## Avaliação

- **Offline**: recall@k da recuperação; NDCG e AUC por cabeça do ranqueador, sempre com divisão temporal (treine até o dia D, avalie em D+1).
- **Online**: teste A/B com tempo assistido por usuário como métrica principal e as métricas de guarda. Rode por pelo menos uma ou duas semanas para cobrir efeito de novidade e ciclos semanais.

## Monitoramento

Acompanhe distribuição das pontuações, fração de vídeos novos recomendados, latência por estágio, taxa de fallback para populares e drift de features como duração média dos vídeos assistidos. Um embedding velho no índice ANN é uma falha silenciosa: o sistema responde, só que pior.

<Callout type="tip" title="Diga o que você otimiza e o que você protege">
Entrevistadores gostam quando você nomeia uma métrica principal e duas de guarda. Isso mostra que você entende que maximizar engajamento sem freios degrada a experiência no longo prazo.
</Callout>

## Trade-offs

| Decisão | Opção A | Opção B |
| --- | --- | --- |
| Objetivo | Clique: rótulo abundante, incentiva clickbait | Tempo assistido: mais alinhado, favorece vídeos longos |
| Frescor do modelo | Treino diário: simples | Atualização contínua: capta tendências, mais risco |
| Candidatos | Poucos: ranker barato | Muitos: mais recall, mais latência |

Normalize o tempo assistido pela duração (ou use a fração assistida) para não favorecer só vídeos longos.

## Follow-ups comuns

- **Vídeo recém-publicado sem histórico?** Use embeddings de conteúdo (título, miniatura, áudio) e reserve exposição exploratória.
- **Usuário novo?** Populares por região, perguntas de interesse no onboarding e aprendizado rápido com as primeiras sessões.
- **Como evitar bolha de filtro?** Cota de exploração e regras de diversidade no re-ranqueamento.
- **E se o ranker cair?** Degrade para a ordem da recuperação ou para populares em cache.
