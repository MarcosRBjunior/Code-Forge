Imagine um catálogo com 50 milhões de vídeos e um ranqueador que olha centenas de features cruzadas entre usuário e item. Mesmo a 0,1 ms por item, pontuar o catálogo inteiro custaria mais de uma hora por requisição. O orçamento é de cerca de 100 ms. A saída, usada por praticamente todo sistema de recomendação, busca e anúncios em escala, é dividir o trabalho em **funil**: etapas baratas reduzem muito o conjunto, e etapas caras olham poucos itens com cuidado.

## As fases

```text
 catalogo (milhoes)
       |
 [1] RECUPERACAO  -- varias fontes baratas, alto recall
       |              (embeddings + ANN, co-ocorrencia, populares, seguidos)
   ~ milhares
       |
 [2] PRE-RANQUEAMENTO (opcional) -- modelo leve
       |
   ~ centenas
       |
 [3] RANQUEAMENTO -- modelo pesado, muitas features cruzadas
       |
   ~ dezenas
       |
 [4] RE-RANQUEAMENTO -- regras de negocio, diversidade, frescor
       |
   pagina final
```

Cada etapa tem um objetivo diferente:

- **Recuperação (candidate generation):** maximizar **recall**. O que ela não trouxer, nenhuma etapa posterior recupera. Usa modelos que permitem busca sublinear, como embeddings com busca aproximada de vizinhos (ANN), além de heurísticas: itens populares na região, itens de criadores seguidos, itens parecidos com o último assistido. Várias fontes rodam em paralelo e são mescladas.
- **Ranqueamento:** maximizar **precisão no topo**. Com poucas centenas de candidatos, dá para usar features caras (histórico do usuário com aquele criador, contexto da sessão, interações cruzadas) e modelos grandes, prevendo clique, tempo de exibição, curtida.
- **Re-ranqueamento:** ajustar a lista para objetivos que o modelo não otimiza sozinho: não mostrar cinco itens do mesmo autor seguidos, remover já vistos, aplicar políticas e impulsionar conteúdo novo.

## O funil na prática

O programa monta um catálogo de brinquedo com 20 mil itens. O "modelo pesado" é o score verdadeiro. A recuperação usa só uma aproximação barata (as primeiras 4 ou 10 das 16 dimensões do embedding) e passa K candidatos para o ranqueador. Medimos quantos dos 10 melhores de verdade chegam ao topo final e quantas avaliações caras foram feitas.

```python
import random

random.seed(5)
DIM, N = 16, 20_000

def vetor():
    return [random.gauss(0, 1) for _ in range(DIM)]

itens = [vetor() for _ in range(N)]
usuario = vetor()

def score_caro(item):  # ranqueador: usa todas as dimensoes
    return sum(u * x for u, x in zip(usuario, item))

def recuperacao(dims):  # aproximacao barata: so as primeiras dimensoes
    return sorted(range(N), key=lambda i: sum(u * x for u, x in zip(usuario[:dims], itens[i][:dims])), reverse=True)

ideal = set(sorted(range(N), key=lambda i: score_caro(itens[i]), reverse=True)[:10])
fraca, melhor = recuperacao(4), recuperacao(10)

print("K candidatos | avaliacoes caras | recall@10 (4 dims) | recall@10 (10 dims)")
for k in (100, 1000, 5000, N):
    linha = []
    for ordem in (fraca, melhor):
        top = sorted(ordem[:k], key=lambda i: score_caro(itens[i]), reverse=True)[:10]
        linha.append(len(ideal & set(top)) / 10)
    print(f"{k:12d} | {k:16d} | {linha[0]:18.1f} | {linha[1]:19.1f}")
```

// gerador com semente (mulberry32): Math.random não aceita semente
function mulberry32(semente) {
  return () => {
    semente = (semente + 0x6d2b79f5) | 0;
    let t = Math.imul(semente ^ (semente >>> 15), 1 | semente);
    t = (t + Math.imul(t ^ (t >>> 7), 61 | t)) ^ t;
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
}

const gauss = (mu, sigma) => mu + sigma * Math.sqrt(-2 * Math.log(1 - random())) * Math.cos(2 * Math.PI * random());

    vector<int> ids(N);

    stable_sort(ids.begin(), ids.end(), [&](int i, int j) { return baratos[i] > baratos[j]; });
    return ids;
}

int main() {
    for (int i = 0; i < N; i++) itens.push_back(vetor());
    usuario = vetor();
    for (auto& item : itens) caros.push_back(scoreCaro(item));

    auto porCusto = [&](int i, int j) { return caros[i] > caros[j]; };
    vector<int> ordemIdeal = indices();
    stable_sort(ordemIdeal.begin(), ordemIdeal.end(), porCusto);
    set<int> ideal(ordemIdeal.begin(), ordemIdeal.begin() + 10);
    vector<int> fraca = recuperacao(4), melhor = recuperacao(10);

using System;
using System.Collections.Generic;
using System.Globalization;
using System.Linq;

const int DIM = 16, N = 20000;
static Random random = new Random(5);
static double[][] itens = new double[N][];
static double[] usuario;
static double[] caros = new double[N];

// random.gauss do Python, pelo método de Box-Muller
static double Gauss(double mu, double sigma)
{
    return mu + sigma * Math.Sqrt(-2 * Math.Log(1 - random.NextDouble())) * Math.Cos(2 * Math.PI * random.NextDouble());
}

static double[] Vetor()
{
    var v = new double[DIM];
    for (int d = 0; d < DIM; d++) v[d] = Gauss(0, 1);
    return v;
}

// produto escalar nas primeiras `dims` dimensões
static double Produto(double[] a, double[] b, int dims)
{
    double s = 0;
    for (int d = 0; d < dims; d++) s += a[d] * b[d];
    return s;
}

static double ScoreCaro(double[] item) // ranqueador: usa todas as dimensoes
{
    return Produto(usuario, item, DIM);
}

static List<int> Recuperacao(int dims) // aproximacao barata: so as primeiras dimensoes
{
    double[] baratos = itens.Select(item => Produto(usuario, item, dims)).ToArray();
    // OrderByDescending é estável, como o sorted do Python
    return Enumerable.Range(0, N).OrderByDescending(i => baratos[i]).ToList();
}

static void Main()
{
    for (int i = 0; i < N; i++) itens[i] = Vetor();
    usuario = Vetor();
    for (int i = 0; i < N; i++) caros[i] = ScoreCaro(itens[i]);

    var ideal = new HashSet<int>(Enumerable.Range(0, N).OrderByDescending(i => caros[i]).Take(10));
    List<int> fraca = Recuperacao(4), melhor = Recuperacao(10);

    Console.WriteLine("K candidatos | avaliacoes caras | recall@10 (4 dims) | recall@10 (10 dims)");

    {
        var linha = new List<double>();
        foreach (var ordem in new[] { fraca, melhor })

            var top = ordem.Take(k).OrderByDescending(i => caros[i]).Take(10);

// os números sorteados vêm do gerador desta linguagem; a saída difere da mostrada no texto, mas a lógica e as conclusões são as mesmas
import (
	"fmt"
	"math/rand"
	"sort"
)

const DIM, N = 16, 20000

var rng = rand.New(rand.NewSource(5))
var itens [][]float64
var usuario []float64
var caros []float64

func vetor() []float64 {
	v := make([]float64, DIM)
	for d := range v {
		v[d] = rng.NormFloat64()
	}
	return v
}

// produto escalar nas primeiras `dims` dimensões
func produto(a, b []float64, dims int) float64 {
	s := 0.0
	for d := 0; d < dims; d++ {
		s += a[d] * b[d]
	}
	return s
}

func scoreCaro(item []float64) float64 { // ranqueador: usa todas as dimensoes
	return produto(usuario, item, DIM)
}

// índices ordenados pela chave, do maior para o menor (estável, como o sorted do Python)
func ordenarPor(ids []int, chave []float64) []int {
	sort.SliceStable(ids, func(a, b int) bool { return chave[ids[a]] > chave[ids[b]] })
	return ids
}

func indices() []int {
	ids := make([]int, N)
	for i := range ids {
		ids[i] = i
	}
	return ids
}

func recuperacao(dims int) []int { // aproximacao barata: so as primeiras dimensoes
	baratos := make([]float64, N)
	for i, item := range itens {
		baratos[i] = produto(usuario, item, dims)
	}
	return ordenarPor(indices(), baratos)
}

func main() {
	for i := 0; i < N; i++ {
		itens = append(itens, vetor())
	}
	usuario = vetor()
	for _, item := range itens {
		caros = append(caros, scoreCaro(item))
	}

	ideal := map[int]bool{}
	for _, i := range ordenarPor(indices(), caros)[:10] {
		ideal[i] = true
	}
	fraca, melhor := recuperacao(4), recuperacao(10)

	fmt.Println("K candidatos | avaliacoes caras | recall@10 (4 dims) | recall@10 (10 dims)")
	for _, k := range []int{100, 1000, 5000, N} {
		var linha []float64
		for _, ordem := range [][]int{fraca, melhor} {
			top := ordenarPor(append([]int{}, ordem[:k]...), caros)[:10]
			acertos := 0
			for _, i := range top {
				if ideal[i] {
					acertos++
				}
			}
			linha = append(linha, float64(acertos)/10)
		}
		fmt.Printf("%12d | %16d | %18.1f | %19.1f\n", k, k, linha[0], linha[1])
	}
}

Com a recuperação fraca, 100 candidatos não trazem nenhum dos 10 melhores, e só com 5 mil avaliações caras o funil chega a 80%. A recuperação melhor alcança 60% com 100 candidatos e 100% com 5 mil. Aumentar K melhora o recall, mas multiplica o custo do ranqueador. Os dois controles que você tem são: **melhorar a recuperação** (embeddings treinados para isso, várias fontes complementares) e **escolher K** pelo orçamento de latência do ranqueador.

## Trade-offs

| Decisão | Mais de um lado | Mais do outro |
| --- | --- | --- |
| Número de candidatos | Mais recall | Mais latência e custo no ranqueador |
| Número de fontes de recuperação | Diversidade e cobertura | Complexidade e deduplicação |
| Pré-ranqueador | Permite K maior na recuperação | Mais um modelo para treinar e manter |
| Features no ranqueamento | Mais precisão | Mais buscas no feature store |

Um problema sutil: o ranqueador é treinado com dados de itens que **já passaram pela recuperação** e foram exibidos. Se você trocar a recuperação, o ranqueador vê candidatos de uma distribuição diferente da que conheceu. Por isso mudanças em uma fase devem ser testadas com o funil inteiro, e o treino do ranqueador costuma incluir negativos amostrados além dos itens exibidos.

<Callout type="tip" title="Meça cada fase separadamente">
Registre o recall da recuperação (quantos itens que o usuário acabou consumindo estavam entre os candidatos) e a qualidade do ranqueamento (NDCG nos candidatos). Assim você sabe qual fase está limitando o sistema.
</Callout>

Depois aprofunde: quais fontes de recuperação, qual modelo de ranqueamento, quais regras no re-ranqueamento. Follow-ups comuns: como escolher o número de candidatos, como deduplicar fontes, como garantir diversidade e como avaliar a recuperação isoladamente.
