Um serviço web quebrado costuma avisar: erros 500, latência alta, alertas. Um modelo de ML quebrado frequentemente continua respondendo 200 com scores perfeitamente plausíveis, só que errados. A degradação é silenciosa, e por isso monitorar ML exige olhar além da saúde do serviço: você precisa vigiar **os dados que entram, as previsões que saem e, quando chegam, os rótulos**.

## Tipos de mudança

- **Data drift (covariate shift):** a distribuição das features muda. Exemplo: o app lança em outro país e a idade média dos usuários cai.
- **Concept drift:** a relação entre features e rótulo muda. Os mesmos sinais que indicavam fraude deixam de indicar, porque os fraudadores se adaptaram.
- **Prediction drift:** a distribuição dos scores muda. É barato de medir e funciona como alarme precoce para os dois tipos acima.
- **Label drift:** a taxa base do rótulo muda (a fração de fraudes dobra numa Black Friday).
- **Bugs de pipeline:** a causa mais comum na prática. Uma feature passa a vir nula, uma unidade muda de reais para centavos, um join para de casar.

## O que monitorar, em camadas

| Camada | Sinais | Latência do sinal |
| --- | --- | --- |
| Serviço | QPS, latência, erros, timeouts | Segundos |
| Dados de entrada | Taxa de nulos, faixa de valores, categorias novas, drift por feature | Minutos |
| Previsões | Média e distribuição do score, fração por classe | Minutos |
| Qualidade | Precision, recall, calibração com rótulos reais | Horas a semanas |
| Negócio | Receita, CTR, perdas com fraude | Dias |

Quanto mais acima, mais rápido o sinal chega e menos ele diz sobre qualidade. Quando os rótulos demoram (fraude, churn), as camadas de dados e previsões são tudo o que você tem por semanas.

## Medindo drift com PSI

Uma métrica popular para comparar a distribuição de uma feature em produção com a de referência (o treino) é o **Population Stability Index**. Você divide os valores em faixas definidas pelos quantis da referência e soma, para cada faixa, `(atual - ref) * ln(atual / ref)`. Uma regra de bolso comum: abaixo de 0,1 é estável, entre 0,1 e 0,25 merece atenção, acima de 0,25 é mudança relevante.

```python
import math
import random

random.seed(11)

def psi(ref, atual, faixas=10):
    ordenados = sorted(ref)
    cortes = [ordenados[int(len(ordenados) * i / faixas)] for i in range(1, faixas)]
    def proporcoes(valores):
        contagem = [0] * faixas
        for v in valores:
            contagem[sum(v > c for c in cortes)] += 1
        return [max(c / len(valores), 1e-4) for c in contagem]
    r, a = proporcoes(ref), proporcoes(atual)
    return sum((x - y) * math.log(x / y) for x, y in zip(a, r))

referencia = [random.gauss(100, 20) for _ in range(5000)]  # valor do pedido no treino
cenarios = {
    "mesma distribuicao": [random.gauss(100, 20) for _ in range(5000)],
    "media +5": [random.gauss(105, 20) for _ in range(5000)],
    "media +20": [random.gauss(120, 20) for _ in range(5000)],
    "bug: valores em centavos (10%)": [random.gauss(100, 20) * (100 if random.random() < 0.1 else 1) for _ in range(5000)],
}
lo, hi = min(referencia), max(referencia)
for nome, atual in cenarios.items():
    valor = psi(referencia, atual)
    nivel = "estavel" if valor < 0.1 else "atencao" if valor < 0.25 else "ALERTA"
    fora = sum(not lo <= v <= hi for v in atual) / len(atual)
    print(f"{nome:32s} PSI={valor:.3f} {nivel:8s} fora da faixa={fora:.1%}")
```

```javascript
function mulberry32(semente) {
  return () => {
    semente = (semente + 0x6d2b79f5) | 0;
    let t = Math.imul(semente ^ (semente >>> 15), 1 | semente);
    t = (t + Math.imul(t ^ (t >>> 7), 61 | t)) ^ t;
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;

  const ordenados = [...ref].sort((a, b) => a - b);

    const contagem = new Array(faixas).fill(0);
```

```java
static double gauss(double mu, double sigma) {
    return mu + sigma * random.nextGaussian();

static double[] proporcoes(double[] valores, double[] cortes, int faixas) {
    int[] contagem = new int[faixas];
    for (double v : valores) {
        int faixa = 0;
        for (double c : cortes) if (v > c) faixa++;
        contagem[faixa]++;
    }
    double[] p = new double[faixas];
    for (int i = 0; i < faixas; i++) p[i] = Math.max((double) contagem[i] / valores.length, 1e-4);
    return p;
}

static double psi(double[] ref, double[] atual, int faixas) {
    double[] ordenados = ref.clone();
```

```csharp
    var contagem = new int[faixas];
    foreach (double v in valores) contagem[cortes.Count(c => v > c)]++;
```

```go
import (
	"fmt"
	"math"
	"math/rand"
	"sort"
)

var rng = rand.New(rand.NewSource(11))

func gauss(mu, sigma float64) float64 {
	return mu + sigma*rng.NormFloat64()
}

func psi(ref, atual []float64, faixas int) float64 {
	ordenados := append([]float64{}, ref...)
	sort.Float64s(ordenados)
	var cortes []float64
	for i := 1; i < faixas; i++ {
		cortes = append(cortes, ordenados[len(ordenados)*i/faixas])
	}
	proporcoes := func(valores []float64) []float64 {
		contagem := make([]int, faixas)
		for _, v := range valores {
			faixa := 0
			for _, c := range cortes {
				if v > c {
					faixa++
				}
			}
			contagem[faixa]++
		}
		p := make([]float64, faixas)
		for i, c := range contagem {
			p[i] = math.Max(float64(c)/float64(len(valores)), 1e-4)
		}
		return p
	}
	r, a := proporcoes(ref), proporcoes(atual)
	soma := 0.0
	for i := range a {
		soma += (a[i] - r[i]) * math.Log(a[i]/r[i])
	}
	return soma
}

func amostra(gerar func() float64) []float64 {
	v := make([]float64, 5000)
	for i := range v {
		v[i] = gerar()
	}
	return v
}

func main() {
	referencia := amostra(func() float64 { return gauss(100, 20) }) // valor do pedido no treino
	nomes := []string{"mesma distribuicao", "media +5", "media +20", "bug: valores em centavos (10%)"}
	cenarios := map[string][]float64{
		nomes[0]: amostra(func() float64 { return gauss(100, 20) }),
	}
	cenarios[nomes[1]] = amostra(func() float64 { return gauss(105, 20) })
	cenarios[nomes[2]] = amostra(func() float64 { return gauss(120, 20) })
	cenarios[nomes[3]] = amostra(func() float64 {
		g := gauss(100, 20)
		if rng.Float64() < 0.1 {
			return g * 100
		}
		return g
	})
	lo, hi := referencia[0], referencia[0]
	for _, v := range referencia {
		lo, hi = math.Min(lo, v), math.Max(hi, v)
	}
	for _, nome := range nomes {
		atual := cenarios[nome]
		valor := psi(referencia, atual, 10)

		fmt.Printf("%-32s PSI=%.3f %-8s fora da faixa=%.1f%%\n", nome, valor, nivel, fora*100)
	}
}
```


O deslocamento grande da média dispara o alerta, e o pequeno fica abaixo do limiar, como esperado. Mas repare no bug de unidade: 10% das linhas multiplicadas por 100 passam como "estável". Como a última faixa é aberta, um valor de 10.000 conta igual a um de 140, e o PSI só vê a faixa do topo ficar um pouco mais cheia. A verificação simples de "fora da faixa vista no treino" pega o bug na hora. Por isso, monitoramento de dados combina métricas de distribuição com validações de esquema e de limites (nulos, mínimo, máximo, categorias desconhecidas).

## Armadilhas

- **Alertas demais:** com centenas de features, alguma vai "driftar" todo dia. Priorize as features mais importantes para o modelo e alerte sobre o score, que resume tudo.
- **Drift não é necessariamente problema:** se a distribuição muda mas a precisão se mantém, retreinar pode ser desperdício. Drift é motivo para investigar, não gatilho cego.
- **Amostra pequena:** PSI com poucas centenas de pontos é ruidoso. Agregue por janela de tempo suficiente.
- **Sazonalidade:** compare segunda com segunda, não segunda com domingo, ou o alarme vai tocar toda semana.

## Do alerta à ação

Um bom sistema define antes o que acontece quando o alerta dispara: verificar se é bug de dados (o caso mais comum), retreinar com dados recentes, reverter para a versão anterior ou acionar um fallback por regras. O retreino pode ser agendado (todo dia) ou disparado por drift; o agendado é mais previsível e mais simples de operar.

<Callout type="tip" title="Rótulos atrasados pedem proxies">
Se o rótulo de fraude chega em 60 dias, use sinais precoces como proxy: disputas abertas, revisões manuais, taxa de bloqueio. Eles não substituem o rótulo, mas encurtam o tempo até você perceber um problema.
</Callout>
