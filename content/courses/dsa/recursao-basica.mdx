Uma função **recursiva** resolve um problema chamando a si mesma para uma versão menor do mesmo problema. Árvores, backtracking, divisão e conquista e programação dinâmica top-down são todos construídos sobre essa ideia, então vale dominá-la antes de seguir.

## As três perguntas

Toda recursão bem escrita responde a três perguntas:

1. **Caso base:** qual é a menor entrada, cuja resposta eu sei sem recursão?
2. **Redução:** como transformo a entrada atual numa entrada estritamente menor?
3. **Combinação:** sabendo a resposta do problema menor, como monto a resposta do atual?

O truque mental é o **salto de fé**: ao escrever a função, assuma que a chamada recursiva já funciona para entradas menores. Você não precisa rastrear a pilha inteira; só precisa garantir que o caso atual está certo se o menor estiver.

```python
def soma_digitos(n):
    if n < 10:                          # caso base
        return n
    return n % 10 + soma_digitos(n // 10)  # redução + combinação

print(soma_digitos(9045))  # 18
```

## A pilha de chamadas

Cada chamada ainda não terminada ocupa um **frame** na pilha de chamadas, com suas variáveis locais. Por isso a recursão tem um custo de espaço que não aparece no código: a **profundidade máxima** da recursão. Para `soma_digitos(n)` a profundidade é o número de dígitos, O(log n). Para percorrer uma lista ligada recursivamente, é O(n).

```text
soma_digitos(9045)
  -> 5 + soma_digitos(904)
         -> 4 + soma_digitos(90)
                -> 0 + soma_digitos(9)
                       -> 9         (caso base, começa a voltar)
```

<Callout type="warning" title="Limite de recursão do Python">
O CPython interrompe a execução por volta de 1000 chamadas aninhadas (`RecursionError`). Para entradas com profundidade da ordem de 10⁵, converta para iteração com uma pilha explícita ou aumente o limite com `sys.setrecursionlimit`, sabendo que isso pode estourar a pilha real do processo.
</Callout>

## Recursão com mais de uma chamada

Quando a função faz duas ou mais chamadas, o número total de chamadas pode explodir. O exemplo clássico é gerar todas as strings binárias de tamanho n:

```python
def binarias(n):
    if n == 0:
        return [""]
    menores = binarias(n - 1)
    return ["0" + s for s in menores] + ["1" + s for s in menores]

print(binarias(3))
# ['000', '001', '010', '011', '100', '101', '110', '111']
```

Aqui é inevitável: a saída tem 2ⁿ strings de tamanho n, então nenhum algoritmo faz melhor que O(n·2ⁿ). Já em Fibonacci ingênuo, as duas chamadas recalculam os mesmos valores, e a solução é memorização (programação dinâmica).

## Recursão com acumulador

Às vezes é mais natural carregar o resultado parcial como parâmetro em vez de combiná-lo na volta. Esse estilo é a base do backtracking:

```python
def caminhos(arvore, no, atual, saida):
    atual.append(no)
    filhos = arvore.get(no, [])
    if not filhos:
        saida.append("->".join(atual))
    for f in filhos:
        caminhos(arvore, f, atual, saida)
    atual.pop()   # desfaz a escolha antes de voltar

arv = {"a": ["b", "c"], "b": ["d"]}
res = []
caminhos(arv, "a", [], res)
print(res)  # ['a->b->d', 'a->c']
```

O `atual.pop()` no final é o passo de "desfazer", que permite reutilizar a mesma lista em todos os ramos sem copiá-la.

## Como analisar a complexidade

Uma regra prática: **tempo ≈ número de chamadas × trabalho por chamada**, e **espaço ≈ profundidade máxima × espaço por frame** (mais o que for alocado). Para `binarias`, há cerca de n níveis, mas o trabalho do último nível já é O(n·2ⁿ) por causa das concatenações.

## Quando reconhecer

- A estrutura é naturalmente recursiva: árvores, expressões aninhadas, diretórios.
- O enunciado pede **todas** as combinações, permutações ou caminhos.
- O problema se divide em metades independentes (merge sort, busca em árvore).
- A definição matemática já é recursiva (fatorial, potência, Fibonacci).

## Na entrevista

Diga o caso base em voz alta antes de escrever qualquer coisa: é onde mais nascem bugs (recursão infinita, índice fora do array). Mencione a profundidade da pilha ao falar de espaço, porque muitos candidatos esquecem. Um follow-up comum é "e se a entrada for enorme?"; a resposta é converter para iteração com pilha explícita ou, se houver repetição de subproblemas, memorizar.
