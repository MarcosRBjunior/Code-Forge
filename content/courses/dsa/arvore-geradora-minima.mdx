Uma operadora quer ligar cinco cidades com fibra ótica. Cada par de cidades tem um custo de instalação, e basta que todas fiquem conectadas, direta ou indiretamente. Qual o menor custo total? A resposta é uma **árvore geradora mínima** (AGM, ou *MST*, de *minimum spanning tree*): um subconjunto de arestas que conecta todos os vértices, sem ciclos, com a menor soma de pesos possível.

## Propriedades úteis

- Um grafo conexo com V vértices tem AGM com exatamente **V − 1 arestas**.
- **Propriedade do corte:** se você divide os vértices em dois grupos, a aresta mais barata que cruza a divisão pertence a alguma AGM. Os dois algoritmos clássicos são aplicações gulosas dessa ideia.
- Se o grafo for desconexo, não existe árvore geradora; o máximo é uma **floresta** geradora mínima.

## Kruskal: arestas em ordem de custo

Ordene todas as arestas pelo peso e percorra da mais barata para a mais cara. Aceite a aresta se ela liga dois componentes diferentes; descarte se fecharia um ciclo. Quem responde "estão no mesmo componente?" é o Union-Find.

```python
def kruskal(n, arestas):
    pai = list(range(n))
    def find(x):
        while pai[x] != x:
            pai[x] = pai[pai[x]]
            x = pai[x]
        return x

    custo, usadas = 0, []
    for w, u, v in sorted(arestas):
        ru, rv = find(u), find(v)
        if ru != rv:
            pai[ru] = rv
            custo += w
            usadas.append((u, v, w))
            if len(usadas) == n - 1:
                break
    return custo if len(usadas) == n - 1 else None, usadas

arestas = [(4, 0, 1), (1, 0, 2), (3, 1, 2), (2, 1, 3), (5, 2, 3), (7, 3, 4)]
print(kruskal(5, arestas))  # (13, [(0, 2, 1), (1, 3, 2), (1, 2, 3), (3, 4, 7)])
```

**Complexidade:** O(E log E) para ordenar as arestas, que domina o custo do Union-Find. Espaço O(V) além da lista de arestas.

## Prim: crescendo a partir de um vértice

Comece com um vértice qualquer. Repetidamente, adicione a aresta mais barata que liga a árvore atual a um vértice de fora. Um min-heap mantém as candidatas, de forma parecida com Dijkstra; a diferença é que a prioridade é o peso da aresta, não a distância acumulada.

```python
import heapq

def prim(n, arestas):
    g = [[] for _ in range(n)]
    for w, u, v in arestas:
        g[u].append((w, v))
        g[v].append((w, u))
    na_arvore = [False] * n
    heap = [(0, 0)]                  # (peso da aresta, vértice)
    custo = adicionados = 0
    while heap and adicionados < n:
        w, u = heapq.heappop(heap)
        if na_arvore[u]:
            continue
        na_arvore[u] = True
        custo += w
        adicionados += 1
        for peso, v in g[u]:
            if not na_arvore[v]:
                heapq.heappush(heap, (peso, v))
    return custo if adicionados == n else None

arestas = [(4, 0, 1), (1, 0, 2), (3, 1, 2), (2, 1, 3), (5, 2, 3), (7, 3, 4)]
print(prim(5, arestas))  # 13
```

**Complexidade:** O(E log V) de tempo com heap binário e O(V + E) de espaço.

## Kruskal ou Prim?

| Critério | Kruskal | Prim |
| --- | --- | --- |
| Entrada natural | Lista de arestas | Lista de adjacência |
| Melhor em | Grafos esparsos | Grafos densos (com matriz, O(V²) sem heap) |
| Estrutura auxiliar | Union-Find | Min-heap |
| Código em entrevista | Geralmente mais curto | Parecido com Dijkstra |

<Callout type="note" title="Grafo implícito completo">
Em problemas como "conectar todos os pontos do plano com custo igual à distância de Manhattan", toda dupla de pontos é uma aresta: E é cerca de V²/2. Aqui Prim com um vetor de menor custo, sem heap, roda em O(V²) e evita gerar e ordenar todas as arestas.
</Callout>

## Quando reconhecer

- "Conectar todos" (cidades, computadores, pontos) com **custo total mínimo**.
- Não importa a distância entre dois pontos específicos, só a soma de todas as conexões. Se importasse, seria caminho mínimo.
- Variações: custo mínimo para fornecer água a casas (crie um vértice virtual ligado a cada casa com o custo de um poço), ou identificar arestas críticas da AGM.
