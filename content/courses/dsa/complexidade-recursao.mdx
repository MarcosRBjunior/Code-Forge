Num laço, você multiplica o número de iterações pelo custo de cada uma. Na recursão, o algoritmo chama a si mesmo, então o custo depende de **quantas chamadas acontecem** e de **quanto trabalho cada uma faz fora das chamadas recursivas**. A ferramenta para pensar nisso é a **árvore de recursão**.

## A árvore de recursão

Desenhe cada chamada como um nó e as chamadas que ela faz como filhos. O tempo total é a soma do trabalho local de todos os nós.

```text
fib(4)
├── fib(3)
│   ├── fib(2)
│   │   ├── fib(1)
│   │   └── fib(0)
│   └── fib(1)
└── fib(2)
    ├── fib(1)
    └── fib(0)
```

Três perguntas resolvem a maioria dos casos:

1. **Quantos filhos** cada chamada gera (o fator de ramificação, b)?
2. **Qual a profundidade** da árvore (d)?
3. **Quanto trabalho local** cada nó faz?

Se cada nó faz O(1) e todos têm b filhos, há cerca de b elevado a d nós, e o tempo é O(b^d). O espaço é a **profundidade** da árvore, porque só um caminho da raiz até a folha fica na pilha ao mesmo tempo.

## Quatro formas que aparecem sempre

```python
def contar_regressivo(n):          # 1 filho, profundidade n
    if n == 0:
        return 0
    return 1 + contar_regressivo(n - 1)            # T(n) = T(n-1) + O(1) -> O(n)

def busca_bin(nums, alvo, lo, hi): # 1 filho, metade do tamanho
    if lo > hi:
        return -1
    meio = (lo + hi) // 2
    if nums[meio] == alvo:
        return meio
    if nums[meio] < alvo:
        return busca_bin(nums, alvo, meio + 1, hi)
    return busca_bin(nums, alvo, lo, meio - 1)     # T(n) = T(n/2) + O(1) -> O(log n)

def fib(n):                        # 2 filhos, profundidade n
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)                 # O(2^n) tempo, O(n) espaço

def subconjuntos(nums, i=0, atual=None, saida=None):
    if atual is None:
        atual, saida = [], []
    if i == len(nums):
        saida.append(atual[:])     # cópia custa O(n)
        return saida
    atual.append(nums[i])
    subconjuntos(nums, i + 1, atual, saida)        # inclui
    atual.pop()
    subconjuntos(nums, i + 1, atual, saida)        # exclui
    return saida                                   # O(n · 2^n)

print(contar_regressivo(5), busca_bin([1, 3, 5, 7], 7, 0, 3), fib(10))  # 5 3 55
print(len(subconjuntos([1, 2, 3])))                                      # 8
```

| Recorrência | Exemplo | Tempo |
| --- | --- | --- |
| T(n) = T(n−1) + O(1) | soma recursiva | O(n) |
| T(n) = T(n/2) + O(1) | busca binária | O(log n) |
| T(n) = 2T(n/2) + O(n) | merge sort | O(n log n) |
| T(n) = 2T(n−1) + O(1) | subconjuntos, Fibonacci ingênuo | O(2^n) |
| T(n) = n · T(n−1) | permutações | O(n!) |

## Dividir e conquistar sem decorar o Teorema Mestre

Para T(n) = 2T(n/2) + O(n), olhe nível por nível. No nível 0 há um problema de tamanho n; no nível 1, dois de tamanho n/2; no nível k, 2^k de tamanho n/2^k. **Cada nível soma O(n)** de trabalho, e há log n níveis. Total: O(n log n).

Esse "trabalho por nível vezes número de níveis" resolve a maioria dos casos sem fórmulas. O Teorema Mestre generaliza a ideia, mas em entrevista explicar a árvore é mais convincente que recitar o teorema.

<Callout type="tip" title="Memoização muda a conta">
Com memória, cada **estado distinto** é calculado uma vez. A complexidade vira número de estados vezes trabalho por estado. Fibonacci memoizado tem n estados com O(1) cada: O(n).
</Callout>

## Quando reconhecer

Use essa análise sempre que sua solução tiver recursão: backtracking (ramificação grande, profundidade pequena), dividir e conquistar (ramificação 2, tamanho cai pela metade) ou DFS em árvores e grafos (cada nó visitado uma vez, então O(n) independentemente da forma).

## Na entrevista

Diga a recorrência em voz alta e justifique: "cada chamada faz duas chamadas com n − 1, então a árvore tem cerca de 2^n nós". Lembre de separar tempo e espaço: o espaço da recursão é a profundidade, não o número total de nós. E inclua o custo de copiar o resultado em cada folha, um detalhe que muitos esquecem no backtracking.
