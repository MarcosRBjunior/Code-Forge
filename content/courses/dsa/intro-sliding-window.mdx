Imagine que você precisa da maior soma de 3 dias seguidos numa lista de vendas diárias. A ideia ingênua é, para cada posição inicial, somar os 3 valores de novo. Com uma janela de tamanho k e n elementos, isso custa O(n·k), e quase todo o trabalho é repetido: duas janelas vizinhas compartilham k-1 elementos. A **janela deslizante** (sliding window) elimina essa repetição. Ela mantém um trecho contíguo do array ou da string e o ajusta de forma incremental: entra um elemento de um lado, sai outro do outro, e o resultado anterior é reaproveitado.

## Janela fixa

Na **janela fixa**, o tamanho `k` é dado. Você calcula a primeira janela inteira uma vez e, a cada passo, soma o elemento que entra e subtrai o que sai. Cada deslize custa O(1), então o total cai para O(n).

```python
def maior_soma_k(nums, k):
    soma = sum(nums[:k])
    melhor = soma
    for i in range(k, len(nums)):
        soma += nums[i] - nums[i - k]   # entra nums[i], sai nums[i - k]
        melhor = max(melhor, soma)
    return melhor

print(maior_soma_k([2, 1, 5, 1, 3, 2], 3))  # 9
```

## Janela variável

Quando o tamanho não é dado e a pergunta é algo como "a maior substring sem caracteres repetidos" ou "o menor subarray com soma pelo menos S", a janela varia. O ponteiro da direita **expande** a janela a cada passo, e o da esquerda **contrai** sempre que ela deixa de ser válida. O molde geral é este:

```python
esq = 0
for dir in range(len(s)):
    adicionar(s[dir])
    while janela_invalida():
        remover(s[esq])
        esq += 1
    atualizar_resposta(esq, dir)
```

Um exemplo completo: a maior substring sem repetições. A janela é válida enquanto todos os caracteres são distintos, e um dicionário de contagem diz quando ela deixa de ser.

```python
def maior_sem_repeticao(s):
    contagem = {}
    esq = 0
    melhor = 0
    for dir, c in enumerate(s):
        contagem[c] = contagem.get(c, 0) + 1
        while contagem[c] > 1:            # janela invalida: c repetido
            contagem[s[esq]] -= 1
            esq += 1
        melhor = max(melhor, dir - esq + 1)
    return melhor

print(maior_sem_repeticao("abcabcbb"))  # 3
```

<Callout type="note" title="Sinais no enunciado">
"Subarray contíguo", "substring", "maior ou menor janela que satisfaz uma condição". Se a pergunta fala de subsequências não contíguas, a janela deslizante não se aplica.
</Callout>

## Por que é O(n)

Há um `while` dentro de um `for`, e isso parece quadrático. Não é: o ponteiro `esq` só anda para frente e nunca passa de `dir`. Cada elemento entra na janela uma vez e sai no máximo uma vez, então o total de operações é cerca de 2n. O espaço extra costuma ser O(1) para somas e O(k) ou O(alfabeto) quando você guarda contagens.

## Armadilhas e trade-offs

- **Números negativos:** em "menor subarray com soma pelo menos S", a contração só é segura se somar mais elementos nunca diminui a soma. Com negativos a janela perde essa monotonicidade e a técnica falha; nesse caso pense em prefix sums com um mapa ou em deque monotônico.
- **Atualizar a resposta no lugar errado:** em janelas de maior tamanho, atualize depois de restaurar a validade; em janelas de menor tamanho, atualize dentro do `while`, enquanto ela ainda é válida.
- **Erros de um:** o tamanho da janela é `dir - esq + 1`. Teste com entrada vazia e com k maior que o array.
- **Estado auxiliar:** a janela precisa responder "sou válida?" em O(1). Se você recalcula isso varrendo a janela, perde o ganho. Mantenha contadores, somas ou um conjunto atualizados a cada entrada e saída.
