Comparar duas strings de tamanho m custa O(m). Comparar dois **números** custa O(1). O Rabin-Karp transforma cada janela do texto num número (um hash) e só compara caracteres quando os números batem. O truque que torna isso eficiente é o **rolling hash**: o hash da próxima janela sai do hash da anterior em O(1), sem reler os m caracteres.

## O hash polinomial

Trate a string como um número escrito numa base B (por exemplo, 256), reduzido por um primo grande M:

```text
hash("abc") = (a·B² + b·B¹ + c·B⁰) mod M
```

Para deslizar a janela de `"abc"` para `"bcd"`:

1. Remova a contribuição do caractere que sai: subtraia `a·B²`.
2. Desloque o resto uma casa: multiplique por B.
3. Some o caractere que entra: some `d`.

O valor `B^(m-1) mod M` é calculado uma vez no início, então cada passo custa O(1).

## Implementação

```python
def rabin_karp(texto, padrao):
    m, n = len(padrao), len(texto)
    if m == 0:
        return [0]
    if m > n:
        return []
    BASE, MOD = 256, 1_000_000_007
    potencia = pow(BASE, m - 1, MOD)        # peso do caractere que sai
    hp = hj = 0
    for i in range(m):
        hp = (hp * BASE + ord(padrao[i])) % MOD
        hj = (hj * BASE + ord(texto[i])) % MOD
    ocorrencias = []
    for i in range(n - m + 1):
        if hp == hj and texto[i:i + m] == padrao:   # confirma: evita falso positivo
            ocorrencias.append(i)
        if i + m < n:
            hj = (hj - ord(texto[i]) * potencia) % MOD   # remove o da esquerda
            hj = (hj * BASE + ord(texto[i + m])) % MOD   # adiciona o da direita
    return ocorrencias

print(rabin_karp("abracadabra", "abra"))   # [0, 7]
print(rabin_karp("aaaaa", "aa"))           # [0, 1, 2, 3]
```

**Complexidade:** O(n + m) no caso esperado, porque colisões são raras com um primo grande. No pior caso, com muitas colisões, cada uma exige a verificação em O(m), e o total vai a O(n·m). Espaço O(1) extra.

<Callout type="warning" title="Colisões existem">
Dois textos diferentes podem ter o mesmo hash. Sempre confirme comparando os caracteres, ou use dois hashes independentes (bases e módulos diferentes) quando a verificação for cara. Em Python, o `%` de número negativo já devolve valor positivo; em Java e JavaScript, some M antes do módulo.
</Callout>

## Hash de qualquer substring em O(1)

Calculando os hashes de todos os prefixos e as potências da base, o hash de `s[i:i+t]` sai de uma conta só, parecida com soma de prefixos. Isso permite comparar substrings arbitrárias em O(1) e combina muito bem com busca binária. Exemplo: a maior substring que aparece pelo menos duas vezes. Se existe uma repetida de tamanho t, existe uma de tamanho t-1, então dá para buscar t binariamente.

```python
def maior_repetida(s):
    MOD, BASE = (1 << 61) - 1, 131
    n = len(s)
    pref = [0] * (n + 1)
    pot = [1] * (n + 1)
    for i, c in enumerate(s):
        pref[i + 1] = (pref[i] * BASE + ord(c)) % MOD
        pot[i + 1] = pot[i] * BASE % MOD

    def hash_de(i, tam):                    # hash de s[i:i+tam] em O(1)
        return (pref[i + tam] - pref[i] * pot[tam]) % MOD

    def acha(tam):
        vistos = {}
        for i in range(n - tam + 1):
            h = hash_de(i, tam)
            if h in vistos and s[vistos[h]:vistos[h] + tam] == s[i:i + tam]:
                return i
            vistos.setdefault(h, i)
        return -1

    lo, hi, melhor = 1, n - 1, ""
    while lo <= hi:
        meio = (lo + hi) // 2
        i = acha(meio)
        if i != -1:
            melhor, lo = s[i:i + meio], meio + 1
        else:
            hi = meio - 1
    return melhor

print(maior_repetida("banana"))            # ana
```

Cada chamada de `acha` é O(n) esperado, e a busca binária faz O(log n) chamadas, totalizando O(n log n).

## KMP ou Rabin-Karp?

| Situação | Melhor escolha |
| --- | --- |
| Um padrão, garantia de pior caso | KMP |
| Vários padrões do mesmo tamanho | Rabin-Karp (guarde os hashes num set) |
| Comparar substrings de tamanhos variados | Rolling hash com prefixos |
| Padrão em 2D ou detectar janelas repetidas | Rolling hash |
