Um array guarda elementos em **posições contíguas de memória**. Essa única propriedade explica quase tudo sobre o seu desempenho: o que é barato, o que é caro e por que ele aparece em praticamente toda solução de entrevista.

## Acesso por índice em O(1)

Como os elementos ficam lado a lado e têm o mesmo tamanho, o endereço do elemento `i` é calculado com uma conta simples: endereço inicial mais `i` vezes o tamanho de cada elemento. Não importa se o array tem dez ou dez milhões de posições, ler `arr[i]` custa o mesmo.

O preço dessa organização aparece quando você precisa **mudar a forma** do array. Inserir no meio exige empurrar todos os elementos seguintes uma posição para a direita; remover exige puxá-los de volta.

| Operação | Custo | Por quê |
| --- | --- | --- |
| Ler ou escrever `arr[i]` | O(1) | Endereço calculado direto |
| Adicionar no fim | O(1) amortizado | Ocasionalmente realoca |
| Remover do fim | O(1) | Nada precisa ser deslocado |
| Inserir ou remover no início ou no meio | O(n) | Desloca os elementos seguintes |
| Buscar um valor sem ordenação | O(n) | Precisa olhar um por um |

## Arrays dinâmicos e amortização

A `list` do Python, o `ArrayList` do Java e o array do JavaScript são **arrays dinâmicos**. Por baixo existe um array de tamanho fixo com folga. Quando a folga acaba, a estrutura aloca um bloco maior (em geral cerca do dobro) e copia tudo para lá.

Essa cópia custa O(n), mas acontece raramente. Se a capacidade dobra a cada realocação, a soma de todas as cópias feitas durante n inserções fica em torno de 2n. Dividindo pelo número de inserções, cada `append` custa **O(1) amortizado**: algumas inserções são caras, mas a média por operação é constante.

```python
nums = []
for i in range(5):
    nums.append(i * 10)   # O(1) amortizado

nums.insert(0, -1)        # O(n): desloca todos para a direita
ultimo = nums.pop()       # O(1): remove do fim
primeiro = nums.pop(0)    # O(n): desloca todos para a esquerda
print(nums, ultimo, primeiro)
```

<Callout type="warning" title="Cuidado com pop(0) em laço">
Remover do início dentro de um laço transforma um algoritmo linear em quadrático sem que o código pareça complicado. Se você precisa tirar elementos da frente com frequência, use `collections.deque`, que faz isso em O(1).
</Callout>

## Padrões de iteração

A maior parte dos problemas com arrays usa uma destas formas de percorrer:

```python
nums = [4, 8, 15, 16, 23, 42]

# índice e valor ao mesmo tempo
for i, x in enumerate(nums):
    pass

# pares de vizinhos
for a, b in zip(nums, nums[1:]):
    pass

# de trás para frente
for i in range(len(nums) - 1, -1, -1):
    pass

# acumulando um resultado em uma passada
maior = nums[0]
for x in nums[1:]:
    maior = max(maior, x)
print(maior)
```

Percorrer de trás para frente é útil quando você modifica o array enquanto anda por ele: os índices que ainda vão ser visitados não mudam.

## Na entrevista

Antes de codar, pergunte se o array pode estar vazio, se tem números negativos e se pode ser modificado in-place. Essas três respostas mudam a solução com frequência. Ao analisar a complexidade, lembre que fatias como `nums[1:]` criam uma cópia e custam O(k) de tempo e de espaço: diga isso em voz alta, porque o entrevistador costuma notar.
