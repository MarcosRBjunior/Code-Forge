**Backtracking** é uma busca exaustiva organizada: você constrói uma solução passo a passo e, assim que percebe que um caminho não leva a nada, volta atrás e tenta outra opção. É a técnica para problemas que pedem **todas** as combinações, permutações ou configurações válidas.

## O molde: escolher, explorar, desfazer

Quase todo backtracking tem a mesma forma:

```python
def backtrack(estado, escolhas, resultado):
    if estado_completo(estado):
        resultado.append(list(estado))   # copia!
        return
    for escolha in escolhas_validas(estado, escolhas):
        estado.append(escolha)            # escolher
        backtrack(estado, escolhas, resultado)  # explorar
        estado.pop()                      # desfazer
```

O passo de **desfazer** é o que diferencia backtracking de recursão comum: o mesmo `estado` é reaproveitado por todos os ramos, então cada ramo precisa deixá-lo como encontrou.

Vale imaginar a execução como uma árvore de decisões. A raiz é o estado vazio, cada nível corresponde a uma decisão e cada folha é uma solução completa ou um beco sem saída. A recursão desce por um ramo, registra o que encontrou e sobe para tentar o ramo vizinho. Pensar assim ajuda a responder duas perguntas antes de escrever código: quais são as escolhas possíveis em cada nível e quando um caminho termina.

<Callout type="warning" title="Copie ao guardar">
Guardar `estado` diretamente coloca a mesma lista várias vezes no resultado, e ela termina vazia depois dos `pop`. Sempre guarde uma cópia com `list(estado)` ou `estado[:]`.
</Callout>

## Subconjuntos e permutações

Gerar todos os subconjuntos: em cada passo, decida a partir de qual índice ainda pode escolher, para não repetir combinações.

```python
def subconjuntos(nums):
    resultado = []
    atual = []
    def bt(inicio):
        resultado.append(list(atual))
        for i in range(inicio, len(nums)):
            atual.append(nums[i])
            bt(i + 1)
            atual.pop()
    bt(0)
    return resultado

print(subconjuntos([1, 2, 3]))
# [[], [1], [1, 2], [1, 2, 3], [1, 3], [2], [2, 3], [3]]
```

Permutações usam todos os elementos, então o controle é "quais já foram usados":

```python
def permutacoes(nums):
    resultado, atual = [], []
    usado = [False] * len(nums)
    def bt():
        if len(atual) == len(nums):
            resultado.append(list(atual))
            return
        for i, x in enumerate(nums):
            if usado[i]:
                continue
            usado[i] = True
            atual.append(x)
            bt()
            atual.pop()
            usado[i] = False
    bt()
    return resultado

print(len(permutacoes([1, 2, 3])))  # 6
```

## Poda

A força do backtracking está em **cortar ramos cedo**. Se a soma parcial já passou do alvo, se uma rainha já está sob ataque, se a palavra montada não é prefixo de nenhuma palavra válida, não adianta continuar descendo. Ordenar a entrada antes costuma permitir podas melhores, como interromper o laço inteiro quando o próximo número já é grande demais.

| Problema | O que define um ramo inválido |
| --- | --- |
| Soma de combinação | Soma parcial maior que o alvo |
| N rainhas | Coluna ou diagonal já ocupada |
| Busca de palavra na grade | Célula já visitada ou letra errada |

## Na entrevista

Diga logo que a complexidade é exponencial por natureza (2ⁿ subconjuntos, n! permutações) e que o objetivo é podar o máximo possível. Desenhe a árvore de decisões para uma entrada pequena antes de codar: ela mostra quais são as escolhas em cada nível e onde a poda entra.
