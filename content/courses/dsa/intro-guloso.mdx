Um algoritmo **guloso** constrói a resposta tomando, a cada passo, a decisão que parece melhor naquele momento, sem nunca voltar atrás. Quando funciona, é a solução mais simples e rápida possível. O problema é que nem sempre funciona, e a parte difícil é saber quando confiar nele.

## Quando reconhecer

Sinais no enunciado:

- Pede um **máximo** ou **mínimo** de algo (menos moedas, mais tarefas, menor custo).
- Os itens podem ser **ordenados** por algum critério natural: término, prazo, razão valor por peso.
- Uma escolha local não restringe muito as escolhas futuras.
- As restrições de n são grandes (10⁵ ou mais), o que descarta DP quadrática.

Se a escolha de agora pode estragar opções futuras de forma imprevisível, desconfie: provavelmente é DP.

## Exemplo: máximo de reuniões numa sala

Dadas reuniões com início e fim, quantas cabem na mesma sala sem sobreposição? Considere três critérios gulosos:

| Critério | Funciona? | Contraexemplo |
| --- | --- | --- |
| Menor duração primeiro | Não | Uma reunião curta que cruza duas longas compatíveis entre si |
| Começa mais cedo primeiro | Não | Uma reunião longa que começa cedo e bloqueia várias |
| **Termina mais cedo primeiro** | Sim | Não existe |

A intuição: escolher a que termina mais cedo deixa a sala livre o máximo de tempo possível para as próximas.

```python
def max_reunioes(reunioes):
    reunioes = sorted(reunioes, key=lambda r: r[1])  # por horário de fim
    total, livre_a_partir = 0, float("-inf")
    for inicio, fim in reunioes:
        if inicio >= livre_a_partir:
            total += 1
            livre_a_partir = fim
    return total

print(max_reunioes([(1, 4), (3, 5), (0, 6), (5, 7), (8, 9), (5, 9)]))  # 3
print(max_reunioes([]))                                                 # 0
```

**Complexidade:** O(n log n) de tempo por causa da ordenação, e O(n) de espaço para a cópia ordenada (O(1) extra se ordenar in-place).

## Como justificar que o guloso está certo

A técnica mais usada é o **argumento de troca**. Pegue qualquer solução ótima. Se a primeira escolha dela difere da escolha gulosa, troque-a pela gulosa e mostre que a solução continua válida e não piora. Repetindo isso passo a passo, a solução ótima vira a gulosa, então a gulosa também é ótima.

No exemplo das reuniões: a reunião gulosa termina antes ou junto da primeira reunião da solução ótima, então trocá-las não causa conflito com as seguintes.

## Quando o guloso falha

O caso clássico é o troco com moedas arbitrárias. Com moedas 1, 3 e 4 e valor 6, pegar sempre a maior moeda dá 4 + 1 + 1 (três moedas), mas 3 + 3 usa só duas.

```python
def troco_guloso(moedas, valor):
    usadas = 0
    for m in sorted(moedas, reverse=True):
        usadas += valor // m
        valor %= m
    return usadas if valor == 0 else -1

print(troco_guloso([1, 3, 4], 6))   # 3, mas o ótimo é 2
print(troco_guloso([1, 5, 10, 25], 30))  # 2: funciona para o sistema americano
```

O guloso funciona para sistemas de moedas "canônicos", como o real e o dólar, mas não em geral. Quando falha, a saída é programação dinâmica.

<Callout type="tip" title="Teste com contraexemplos pequenos">
Antes de codar um guloso, gaste um minuto tentando quebrá-lo com três ou quatro itens. Se você não encontrar contraexemplo e conseguir esboçar um argumento de troca, siga em frente.
</Callout>

## Padrões gulosos frequentes

- **Ordenar por fim:** seleção de intervalos, menor número de flechas para estourar balões.
- **Alcance máximo:** no jogo de saltos, manter o índice mais distante alcançável até agora.
- **Heap de prioridade:** sempre processar o item mais urgente ou mais barato, como em Dijkstra e Prim.
- **Dois ponteiros após ordenar:** formar pares (o mais pesado com o mais leve) em problemas de barcos ou times.

## Na entrevista

Diga o critério guloso e, logo em seguida, por que acredita nele: "ordenando pelo fim, cada escolha deixa o máximo de tempo livre; se a solução ótima começasse com outra reunião, eu poderia trocá-la por essa sem conflito". Follow-ups comuns: "e se cada reunião tivesse um peso?" (aí vira DP com busca binária) e "e se houvesse várias salas?" (heap com os horários de término).
