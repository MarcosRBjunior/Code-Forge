Algumas operações às vezes custam caro, mas quase sempre custam pouco. **Análise amortizada** mede o custo médio por operação ao longo de uma **sequência** delas, no pior caso dessa sequência. Não é média estatística nem depende de sorte: é uma garantia sobre o total.

## O exemplo clássico: lista dinâmica

Um `list` do Python (ou `ArrayList` em Java) guarda os elementos num bloco contíguo com alguma folga. Enquanto há espaço, `append` custa O(1). Quando o bloco enche, a lista aloca um bloco maior e copia tudo, o que custa O(n).

Parece que `append` é O(n) no pior caso, e de fato uma chamada isolada pode ser. Mas olhe a sequência inteira com a capacidade dobrando a cada estouro:

```text
capacidade:  1   2   4   8   16 ...
cópias:      1 + 2 + 4 + 8 + ... + n/2  <  n
```

Depois de n inserções, o total de cópias é menor que n. Somando os n passos baratos, o custo total é menor que 2n, ou seja, O(n) para n operações e **O(1) amortizado** por operação.

```python
class ListaDinamica:
    def __init__(self):
        self.cap = 1
        self.tam = 0
        self.dados = [None]
        self.copias = 0

    def append(self, x):
        if self.tam == self.cap:          # cheio: dobra e copia
            novo = [None] * (self.cap * 2)
            for i in range(self.tam):
                novo[i] = self.dados[i]
                self.copias += 1
            self.dados, self.cap = novo, self.cap * 2
        self.dados[self.tam] = x
        self.tam += 1

lista = ListaDinamica()
n = 1000
for i in range(n):
    lista.append(i)
print(lista.copias)            # 1023
print(lista.copias <= 2 * n)   # True: total linear
```

Repare que o número exato de cópias é 1 + 2 + 4 + ... + 512 = 1023, um pouco acima de n = 1000, mas sempre limitado por 2n. O que importa é a ordem de grandeza.

<Callout type="note" title="Por que dobrar, e não somar 10">
Se a capacidade crescesse em passos fixos (mais 10 a cada estouro), haveria n/10 cópias com tamanho crescente, totalizando O(n²). O crescimento **geométrico** é o que garante O(1) amortizado.
</Callout>

## Os três métodos

| Método | Ideia |
| --- | --- |
| Agregado | Some o custo total de n operações e divida por n. Foi o que fizemos acima. |
| Contábil (banqueiro) | Cobre um pouco a mais das operações baratas e guarde o "crédito" para pagar as caras. |
| Potencial | Defina uma função de energia da estrutura; o custo amortizado é o custo real mais a variação de energia. |

Em entrevista, o método agregado resolve quase tudo: conte quantas vezes cada elemento pode ser tocado no total.

## O mesmo raciocínio em padrões de entrevista

**Pilha monotônica:** cada elemento entra na pilha uma vez e sai no máximo uma vez. Mesmo com um `while` dentro do `for`, o total é O(n).

<CodeTabs>

```python
def proximo_maior(nums):
    resp = [-1] * len(nums)
    pilha = []                      # índices esperando um maior
    for i, x in enumerate(nums):
        while pilha and nums[pilha[-1]] < x:
            resp[pilha.pop()] = x   # cada índice sai uma única vez
        pilha.append(i)
    return resp

print(proximo_maior([2, 1, 5, 3, 4]))  # [5, 5, -1, 4, -1]
```

```go
import "fmt"

func proximoMaior(nums []int) []int {
	resp := make([]int, len(nums))
	for i := range resp {
		resp[i] = -1
	}
	pilha := []int{} // índices esperando um maior
	for i, x := range nums {
		for len(pilha) > 0 && nums[pilha[len(pilha)-1]] < x {
			resp[pilha[len(pilha)-1]] = x // cada índice sai uma única vez
			pilha = pilha[:len(pilha)-1]
		}
		pilha = append(pilha, i)
	}
	return resp
}

func main() {
	fmt.Println(proximoMaior([]int{2, 1, 5, 3, 4})) // [5 5 -1 4 -1]
}
```

**Janela deslizante:** o ponteiro da esquerda só avança, então anda no máximo n posições no total. **Fila com duas pilhas:** cada elemento é transferido de uma pilha para a outra uma única vez, então `dequeue` é O(1) amortizado.

## Quando reconhecer

Desconfie de análise amortizada quando você vê um laço interno que **não reinicia**: um ponteiro que só avança, uma pilha da qual cada item só sai uma vez, uma estrutura que cresce geometricamente. Nesses casos, contar "por elemento" é mais preciso do que multiplicar laços.

## Na entrevista

Se o entrevistador perguntar por que seu `while` dentro do `for` não é O(n²), responda contando movimentos: "cada índice entra e sai da pilha no máximo uma vez, então são no máximo 2n operações". E diferencie: "esse `append` é O(1) amortizado, mas uma chamada individual pode ser O(n)". Isso importa em sistemas de baixa latência, em que um pico isolado pode ser inaceitável.
