Dado um array ordenado, encontre dois números que somam um alvo. A solução óbvia testa todos os pares com dois laços aninhados e custa O(n²). A técnica de **dois ponteiros** percorre a estrutura com dois índices ao mesmo tempo e, a cada passo, descarta de uma vez uma série de possibilidades que comprovadamente não levam à resposta. O resultado costuma ser O(n) de tempo e O(1) de espaço extra.

## Quando usar

Procure por estes sinais no enunciado:

- O array está **ordenado**, ou ordená-lo não atrapalha.
- Você precisa encontrar um **par** ou uma **subsequência** com alguma propriedade.
- A solução deve ser **in-place**, com O(1) de espaço extra.

## As duas variações

**Ponteiros opostos:** um começa no início e outro no fim, e eles se aproximam. É o caso clássico de encontrar um par com soma alvo em um array ordenado. Se a soma é pequena demais, o menor valor não serve com ninguém restante, então ele é descartado. Se é grande demais, o maior é que não serve.

```python
def par_com_soma(nums, alvo):
    esq, dir = 0, len(nums) - 1
    while esq < dir:
        soma = nums[esq] + nums[dir]
        if soma == alvo:
            return [esq, dir]
        if soma < alvo:
            esq += 1   # precisamos de uma soma maior
        else:
            dir -= 1   # precisamos de uma soma menor
    return []

print(par_com_soma([1, 3, 4, 6, 8, 11], 10))  # [2, 3]
```

**Leitura e escrita:** os dois ponteiros andam na mesma direção. Um lê cada elemento e o outro marca onde escrever o próximo elemento válido. É a base de problemas como remover duplicados ou mover zeros, sempre in-place.

```python
def remover_duplicados(nums):
    if not nums:
        return 0
    escrita = 1
    for leitura in range(1, len(nums)):
        if nums[leitura] != nums[escrita - 1]:
            nums[escrita] = nums[leitura]
            escrita += 1
    return escrita   # tamanho do prefixo sem repetidos

dados = [1, 1, 2, 2, 3]
n = remover_duplicados(dados)
print(dados[:n])  # [1, 2, 3]
```

<Callout type="tip" title="Por que funciona">
Em cada passo, um ponteiro avança e descarta uma possibilidade que comprovadamente não leva à resposta. Como cada ponteiro anda no máximo n posições, o total é O(n).
</Callout>

## Um padrão a mais: palíndromo

Verificar se uma string é palíndromo também é um caso de ponteiros opostos: compare os extremos e vá para dentro, parando quando eles se cruzam. A mesma ideia resolve "reverter um array in-place", trocando os elementos das pontas a cada passo.

## Armadilhas e trade-offs

- **Ordenar custa O(n log n):** se o array não está ordenado e você precisa dos índices originais, ordenar destrói a informação. Nesse caso uma tabela hash (O(n) de tempo e espaço) costuma ser melhor.
- **Condição de parada:** use `esq < dir` quando o par precisa de dois elementos distintos e `esq <= dir` quando um elemento pode ser usado sozinho. Esse detalhe causa muitos bugs.
- **Duplicados em problemas de três números:** em 3Sum, depois de fixar um valor você aplica ponteiros opostos no resto, e precisa pular valores repetidos para não devolver trios duplicados.
- **Provar a correção:** a técnica só é válida se você consegue justificar por que o ponteiro descartado não leva à resposta. Sem argumento de monotonicidade, ela vira chute.

## Na entrevista

Comece mencionando a força bruta em O(n²) e diga qual propriedade (ordenação, simetria) permite descartar candidatos. Declare O(n) de tempo e O(1) de espaço, somando o custo de ordenar quando houver. Follow-ups frequentes: "e se o array não estiver ordenado?" (ordene ou use hash), "e se for preciso devolver todos os pares?" (pule duplicados e continue após cada acerto) e "e se forem três ou quatro números?" (fixe um ou dois e use ponteiros no resto).
