**Merge sort** é o exemplo didático de **dividir e conquistar**: corte a lista ao meio, ordene cada metade recursivamente e junte as duas metades ordenadas numa só. A parte inteligente está toda na junção.

## A junção (merge)

Se as duas metades já estão ordenadas, o menor elemento de todos é o menor entre os primeiros de cada metade. Dois ponteiros resolvem a junção em tempo linear:

```python
def merge(a, b):
    i = j = 0
    saida = []
    while i < len(a) and j < len(b):
        if a[i] <= b[j]:          # <= mantém o sort estável
            saida.append(a[i])
            i += 1
        else:
            saida.append(b[j])
            j += 1
    saida.extend(a[i:])           # sobra de uma das metades
    saida.extend(b[j:])
    return saida

print(merge([1, 4, 7], [2, 3, 8, 9]))  # [1, 2, 3, 4, 7, 8, 9]
```

## O algoritmo completo

```python
def merge_sort(nums):
    if len(nums) <= 1:
        return nums
    meio = len(nums) // 2
    esq = merge_sort(nums[:meio])
    dir = merge_sort(nums[meio:])
    return merge(esq, dir)

def merge(a, b):
    i = j = 0
    saida = []
    while i < len(a) and j < len(b):
        if a[i] <= b[j]:
            saida.append(a[i]); i += 1
        else:
            saida.append(b[j]); j += 1
    return saida + a[i:] + b[j:]

print(merge_sort([38, 27, 43, 3, 9, 82, 10]))
# [3, 9, 10, 27, 38, 43, 82]
```

## Complexidade

- **Tempo:** a árvore de recursão tem log n níveis e cada nível faz O(n) de trabalho total nas junções. Resultado: **O(n log n) no melhor, médio e pior caso**. Não há entrada ruim.
- **Espaço:** O(n) para as listas auxiliares da junção, mais O(log n) de pilha. Esta versão com fatias aloca mais memória temporária; uma versão com índices e um buffer único fica em O(n) estrito.
- **Estável:** sim, desde que a comparação use `<=` e prefira a metade da esquerda em empates.

| Prós | Contras |
| --- | --- |
| Pior caso garantido O(n log n) | Precisa de O(n) de memória extra |
| Estável | Mais lento que quick sort na prática em arrays, por mexer mais na memória |
| Ótimo para listas ligadas e dados em disco | Recursão adiciona overhead em entradas pequenas |

<Callout type="tip" title="Listas ligadas">
Em lista ligada, a junção só reaponta ponteiros, sem memória extra. Por isso merge sort é a escolha padrão para ordenar listas ligadas em O(n log n).
</Callout>

## A junção como ferramenta

Mesmo quando você não precisa ordenar do zero, a ideia de **mesclar sequências ordenadas** aparece sozinha:

- Juntar duas listas (ou listas ligadas) já ordenadas.
- Juntar k listas ordenadas: junte em pares, rodada a rodada, em O(N log k), ou use um heap.
- **Contar inversões** (pares i menor que j com `nums[i] > nums[j]`): durante a junção, quando um elemento da direita sai antes, ele forma inversão com todos os que restam na esquerda.

```python
def contar_inversoes(nums):
    if len(nums) <= 1:
        return nums, 0
    meio = len(nums) // 2
    esq, ie = contar_inversoes(nums[:meio])
    dir, id_ = contar_inversoes(nums[meio:])
    saida, i, j, inv = [], 0, 0, ie + id_
    while i < len(esq) and j < len(dir):
        if esq[i] <= dir[j]:
            saida.append(esq[i]); i += 1
        else:
            saida.append(dir[j]); j += 1
            inv += len(esq) - i      # todos os restantes da esquerda são maiores
    return saida + esq[i:] + dir[j:], inv

print(contar_inversoes([2, 4, 1, 3, 5])[1])  # 3
```

## Quando reconhecer

Pense em merge sort quando o enunciado pede ordenação com pior caso garantido ou estabilidade, quando os dados são uma lista ligada, quando já existem sequências ordenadas para combinar, ou quando aparece "contar pares fora de ordem" em O(n log n).
