Alguns problemas não pedem uma função, e sim uma **classe**: "implemente um cache LRU", "projete uma pilha que devolve o mínimo em O(1)", "crie um contador de acessos nos últimos 5 minutos". São os problemas de **design de estruturas de dados**. O desafio não é um algoritmo novo, mas **combinar** estruturas que você já conhece para que cada operação atinja a complexidade pedida.

## O roteiro

1. **Liste as operações e a complexidade exigida de cada uma.** Escreva isso antes de tudo. É a especificação.
2. **Para cada operação, pergunte qual estrutura a faz no custo pedido.** Busca por chave em O(1): hash map. Ordem de inserção ou de uso: lista ligada ou deque. Mínimo/máximo: heap ou pilha auxiliar. Ordem com busca: árvore balanceada.
3. **Se nenhuma estrutura sozinha atende tudo, combine duas** e mantenha-as sincronizadas: toda operação que altera uma altera a outra.
4. **Defina os invariantes** (o que é sempre verdade sobre o estado) e verifique cada método contra eles.

## Exemplo: pilha com mínimo em O(1)

Operações: `empilhar`, `desempilhar`, `topo`, `minimo`, todas O(1). Uma pilha comum faz as três primeiras; o mínimo exigiria varrer tudo. A solução é guardar, junto de cada elemento, o mínimo **até aquele ponto**:

```python
class PilhaMin:
    def __init__(self):
        self.dados = []  # pares (valor, minimo_ate_aqui)

    def empilhar(self, x):
        menor = min(x, self.dados[-1][1]) if self.dados else x
        self.dados.append((x, menor))

    def desempilhar(self):
        return self.dados.pop()[0]

    def topo(self):
        return self.dados[-1][0]

    def minimo(self):
        return self.dados[-1][1]

p = PilhaMin()
for v in [5, 3, 7, 2]:
    p.empilhar(v)
print(p.minimo())  # 2
p.desempilhar()
print(p.minimo())  # 3
```

Invariante: o segundo campo do topo é sempre o mínimo de toda a pilha. Como desempilhar remove o par inteiro, o mínimo anterior "reaparece" sozinho. Espaço O(n).

## Exemplo: cache LRU

Operações: `get(chave)` e `put(chave, valor)` em O(1), descartando o item **menos recentemente usado** quando a capacidade estoura. Precisamos de busca por chave (hash map) e de ordem de uso com remoção e movimentação em O(1) (lista duplamente ligada). Em Python, `OrderedDict` já é essa combinação pronta:

```python
from collections import OrderedDict

class CacheLRU:
    def __init__(self, capacidade):
        self.cap = capacidade
        self.itens = OrderedDict()

    def get(self, chave):
        if chave not in self.itens:
            return -1
        self.itens.move_to_end(chave)      # passa a ser o mais recente
        return self.itens[chave]

    def put(self, chave, valor):
        if chave in self.itens:
            self.itens.move_to_end(chave)
        self.itens[chave] = valor
        if len(self.itens) > self.cap:
            self.itens.popitem(last=False)  # remove o mais antigo

c = CacheLRU(2)
c.put("a", 1); c.put("b", 2)
c.get("a")          # "a" vira o mais recente
c.put("c", 3)       # estoura: remove "b"
print(c.get("b"), c.get("a"), c.get("c"))  # -1 1 3
```

<Callout type="warning" title="Pergunte se pode usar a biblioteca">
Muitos entrevistadores aceitam `OrderedDict` primeiro, mas depois pedem a versão com hash map apontando para nós de uma lista duplamente ligada, com nós sentinela na cabeça e na cauda. Saiba explicar por que a lista precisa ser **dupla**: remover um nó do meio em O(1) exige acesso ao anterior.
</Callout>

## Combinações recorrentes

| Requisito | Combinação típica |
| --- | --- |
| Busca O(1) + ordem de uso | hash map + lista duplamente ligada |
| Inserir, remover e sortear aleatório em O(1) | lista + hash map de valor para índice (troca com o último ao remover) |
| Mínimo/máximo em O(1) com pilha | pilha de pares ou pilha auxiliar |
| Mediana de um fluxo | dois heaps (max-heap da metade baixa, min-heap da alta) |
| Eventos numa janela de tempo | deque, descartando da frente o que expirou |

## Quando reconhecer

O enunciado descreve uma **classe** com vários métodos e dá a complexidade de cada um, ou diz "projete", "implemente uma estrutura que suporte...". A pista mais forte é uma exigência de O(1) para operações que nenhuma estrutura isolada oferece juntas.

## Na entrevista

Escreva a tabela operação → complexidade exigida antes de codificar e mostre qual estrutura cobre cada linha. Fale dos invariantes. Depois implemente método a método, testando um cenário curto ao final, como no exemplo do cache. Follow-ups frequentes: segurança com múltiplas threads, capacidade zero e chaves repetidas.
