Você recebe um fluxo de dados (linhas de um log de terabytes, eventos chegando pela rede, os nós de uma lista ligada) e precisa escolher **k itens uniformemente ao acaso**. O problema: você não sabe quantos itens existem até o fluxo acabar, e não cabe guardar todos na memória. A **amostragem de reservatório** resolve isso numa única passada, com O(k) de memória.

## O algoritmo

1. Coloque os k primeiros itens no reservatório.
2. Para o item de índice `i` (começando em 0), quando `i >= k`, sorteie um inteiro `j` entre 0 e `i`, inclusive.
3. Se `j < k`, o novo item substitui a posição `j` do reservatório. Caso contrário, é descartado.

Ao final, o reservatório é uma amostra uniforme: cada item do fluxo tem a mesma probabilidade k/n de estar nele, qualquer que seja n.

## Por que funciona

Considere o caso k = 1, que é o mais pedido. O i-ésimo item (contando de 1) entra com probabilidade 1/i. Para ele estar na resposta final, precisa entrar e depois **não** ser trocado por nenhum dos seguintes:

```text
P(item i fica) = 1/i · (i/(i+1)) · ((i+1)/(i+2)) · ... · ((n-1)/n)
               = 1/n
```

Os termos se cancelam em cadeia e sobra 1/n para todo i. Para k geral, a conta é a mesma: o item entra com probabilidade k/i, e cada item seguinte o expulsa com probabilidade (k/(t)) · (1/k) = 1/t, o que dá k/n no final.

## Implementação

```python
import random

def reservatorio(fluxo, k, rng=random):
    amostra = []
    for i, item in enumerate(fluxo):
        if i < k:
            amostra.append(item)            # enche o reservatório
        else:
            j = rng.randint(0, i)           # 0..i, inclusive
            if j < k:
                amostra[j] = item           # entra com probabilidade k/(i+1)
    return amostra

rng = random.Random(42)
print(len(reservatorio(range(1_000_000), 5, rng)))   # 5

# Verificação empírica: cada número de 0 a 9 deve aparecer ~30% das vezes (k/n = 3/10)
contagem = [0] * 10
for _ in range(20_000):
    for x in reservatorio(range(10), 3, rng):
        contagem[x] += 1
print([round(c / 20_000, 2) for c in contagem])
```

Note que `reservatorio` aceita qualquer iterável, inclusive um `range` de um milhão de itens que nunca é materializado. Só k itens ficam na memória.

**Complexidade:** O(n) de tempo (uma passada, um sorteio por item) e O(k) de espaço.

## Exemplo: nó aleatório de lista ligada

Um problema clássico pede um nó aleatório de uma lista ligada com chances iguais, sem saber o tamanho e sem usar memória extra. É o reservatório com k = 1: ao visitar o i-ésimo nó, troque a escolha com probabilidade 1/i.

```python
class ListaAleatoria:
    def __init__(self, valores, rng=random):
        self.valores, self.rng = valores, rng

    def sortear(self):
        escolhido = None
        for i, v in enumerate(self.valores, start=1):
            if self.rng.randint(1, i) == 1:     # troca com probabilidade 1/i
                escolhido = v
        return escolhido

print(ListaAleatoria([1, 2, 3], rng).sortear() in (1, 2, 3))   # True
```

O mesmo raciocínio resolve "devolva um índice aleatório em que `nums[i] == alvo`": percorra o array e aplique o reservatório só sobre os índices que batem.

## Armadilhas

- **Intervalo do sorteio:** `randint(0, i)` em Python inclui as duas pontas. Em outras linguagens, `random() * (i + 1)` com piso. Errar por um quebra a uniformidade.
- **Saber n de antemão:** se o tamanho é conhecido e os dados cabem na memória, `random.sample` ou um embaralhamento parcial de Fisher-Yates é mais simples. O reservatório brilha quando n é desconhecido ou gigante.
- **Ordem da amostra:** o reservatório não preserva a ordem do fluxo. Se ela importar, guarde o índice junto e ordene ao final.

<Callout type="note" title="Distribuído">
Com o fluxo dividido entre várias máquinas, uma variante atribui a cada item uma chave aleatória e mantém os k de menor chave num heap. Juntar resultados parciais vira pegar os k menores de todos, o que escala bem.
</Callout>
