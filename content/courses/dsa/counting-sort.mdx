Nenhum algoritmo que só compara elementos consegue ordenar em menos de O(n log n) no pior caso. **Counting sort** e **bucket sort** fogem desse limite usando informação extra sobre os valores: eles são inteiros num intervalo pequeno, ou estão bem espalhados num intervalo conhecido.

## Counting sort

Se os valores estão entre 0 e k, crie um array de contagens com k + 1 posições, conte quantas vezes cada valor aparece e reescreva a saída na ordem dos índices.

```python
def counting_sort(nums, k):
    contagem = [0] * (k + 1)
    for x in nums:
        contagem[x] += 1
    saida = []
    for valor, vezes in enumerate(contagem):
        saida.extend([valor] * vezes)
    return saida

print(counting_sort([4, 1, 3, 4, 0, 2, 1], 4))  # [0, 1, 1, 2, 3, 4, 4]
```

**Tempo O(n + k), espaço O(k).** Vale a pena quando k é da ordem de n ou menor. Se os valores vão até 10^9, o array de contagem é inviável.

### Versão estável, para ordenar registros

Quando você ordena objetos por uma chave inteira (e não números soltos), precisa preservar a ordem dos empatados. A técnica: transforme as contagens em **somas de prefixo**, que dizem onde cada valor termina na saída, e percorra a entrada de trás para frente.

```python
def counting_sort_estavel(itens, chave, k):
    contagem = [0] * (k + 1)
    for it in itens:
        contagem[chave(it)] += 1
    for v in range(1, k + 1):
        contagem[v] += contagem[v - 1]   # posição final (exclusiva) de cada valor
    saida = [None] * len(itens)
    for it in reversed(itens):
        contagem[chave(it)] -= 1
        saida[contagem[chave(it)]] = it
    return saida

alunos = [("lia", 2), ("rui", 1), ("eva", 2), ("max", 0)]
print(counting_sort_estavel(alunos, lambda a: a[1], 2))
# [('max', 0), ('rui', 1), ('lia', 2), ('eva', 2)]
```

Essa versão estável é a base do **radix sort**, que ordena números grandes dígito a dígito, do menos significativo para o mais significativo, em O(d · (n + b)), com d dígitos na base b.

## Bucket sort

Se os valores estão espalhados de forma razoavelmente uniforme num intervalo, divida o intervalo em n baldes, jogue cada valor no seu balde, ordene cada balde (que terá poucos elementos) e concatene.

```python
def bucket_sort(nums):
    if not nums:
        return []
    lo, hi = min(nums), max(nums)
    n = len(nums)
    largura = (hi - lo) / n or 1
    baldes = [[] for _ in range(n)]
    for x in nums:
        i = min(int((x - lo) / largura), n - 1)
        baldes[i].append(x)
    saida = []
    for b in baldes:
        saida.extend(sorted(b))
    return saida

print(bucket_sort([0.42, 0.32, 0.23, 0.52, 0.25, 0.47, 0.51]))
# [0.23, 0.25, 0.32, 0.42, 0.47, 0.51, 0.52]
```

**Tempo médio O(n)** com distribuição uniforme; **pior caso O(n log n)** ou pior, se todos caírem no mesmo balde. Espaço O(n).

## Baldes por frequência: o uso mais comum em entrevista

Em entrevistas, a ideia de baldes aparece mais como truque do que como sort completo. Exemplo: os k elementos mais frequentes. A frequência de qualquer elemento está entre 1 e n, então dá para usar a frequência como índice do balde:

```python
from collections import Counter

def top_k_frequentes(nums, k):
    freq = Counter(nums)
    baldes = [[] for _ in range(len(nums) + 1)]
    for valor, f in freq.items():
        baldes[f].append(valor)
    resp = []
    for f in range(len(baldes) - 1, 0, -1):
        for valor in baldes[f]:
            resp.append(valor)
            if len(resp) == k:
                return resp
    return resp

print(top_k_frequentes([5, 5, 5, 2, 2, 9], 2))  # [5, 2]
```

O(n) de tempo e espaço, melhor que o heap (O(n log k)) e que ordenar as frequências (O(n log n)).

<Callout type="tip" title="Alfabeto fixo é um array de contagem">
Contar letras de a até z com uma lista de 26 posições é counting sort disfarçado. Comparar anagramas assim custa O(n) em vez de O(n log n) ordenando as strings.
</Callout>

## Quando reconhecer

Sinais no enunciado: valores inteiros com **limite pequeno** ("notas de 0 a 100", "idades", "letras minúsculas"), **frequências** que você quer agrupar, ou pedido explícito de tempo linear para ordenar. Se os valores não têm limite conhecido ou são arbitrários, volte aos sorts por comparação.

## Na entrevista

Quando o entrevistador pergunta "dá para fazer melhor que O(n log n)?", verifique o intervalo dos valores. Responda com a condição: "se os valores estão entre 0 e k, counting sort faz em O(n + k); isso só compensa se k não for muito maior que n". Esse cuidado em declarar a hipótese conta muito.
