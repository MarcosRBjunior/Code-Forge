Procurar um padrão de tamanho m num texto de tamanho n do jeito ingênuo é simples: tente casar o padrão em cada posição e, ao encontrar uma diferença, avance uma casa e recomece. No pior caso, como buscar `aaab` em `aaaaaaaa...`, você compara quase o padrão inteiro em cada posição, e o custo chega a O(n·m). O algoritmo **KMP** (Knuth-Morris-Pratt) garante **O(n + m)**, porque nunca volta atrás no texto.

## A ideia

Quando uma comparação falha depois de casar `k` caracteres, você já sabe exatamente quais eram esses `k` caracteres: são o começo do padrão. O KMP usa essa informação para decidir quanto do padrão ainda está casado, sem reler o texto.

O pré-processamento calcula, para cada posição `i` do padrão, o tamanho do maior **prefixo próprio** de `padrao[0..i]` que também é **sufixo** dele. Esse vetor se chama **LPS** (*longest proper prefix which is also suffix*), ou função de falha.

```text
padrão:  A  B  A  B  C  A  B  A  B
índice:  0  1  2  3  4  5  6  7  8
lps:     0  0  1  2  0  1  2  3  4

lps[3] = 2 porque "ABAB" começa e termina com "AB".
lps[8] = 4 porque "ABABCABAB" começa e termina com "ABAB".
```

Durante a busca, se você casou `k` caracteres e o próximo falha, em vez de recomeçar do zero você faz `k = lps[k-1]`: o sufixo do trecho casado que também é prefixo do padrão continua valendo. Repete até casar ou chegar a zero.

## Implementação

```python
def tabela_lps(padrao):
    lps = [0] * len(padrao)
    k = 0                                   # tamanho do prefixo-sufixo atual
    for i in range(1, len(padrao)):
        while k > 0 and padrao[i] != padrao[k]:
            k = lps[k - 1]                  # recua para a próxima borda menor
        if padrao[i] == padrao[k]:
            k += 1
        lps[i] = k
    return lps

def kmp_busca(texto, padrao):
    if not padrao:
        return [0]
    lps = tabela_lps(padrao)
    ocorrencias = []
    k = 0                                   # quantos chars do padrão casaram
    for i, c in enumerate(texto):
        while k > 0 and c != padrao[k]:
            k = lps[k - 1]
        if c == padrao[k]:
            k += 1
        if k == len(padrao):
            ocorrencias.append(i - k + 1)
            k = lps[k - 1]                  # continua buscando sobreposições
    return ocorrencias

print(tabela_lps("ABABCABAB"))             # [0, 0, 1, 2, 0, 1, 2, 3, 4]
print(kmp_busca("ABABDABABCABABCABAB", "ABABCABAB"))  # [5, 10]
print(kmp_busca("aaaaa", "aa"))            # [0, 1, 2, 3]
```

function tabelaLps(padrao) {
  const lps = new Array(padrao.length).fill(0);
  let k = 0;                                   // tamanho do prefixo-sufixo atual

func tabelaLps(padrao string) []int {

Note que `tabela_lps` é a própria busca do padrão contra ele mesmo. Entender uma função é entender a outra.

## Por que é linear

O índice `i` do texto só avança. O `k` sobe no máximo 1 por iteração, e cada passo do `while` faz `k` diminuir. Como `k` nunca fica negativo, o total de recuos ao longo da busca é no máximo o total de avanços, ou seja, n. Somando o pré-processamento, o custo é **O(n + m) de tempo e O(m) de espaço**.

## Usos além da busca

O vetor LPS sozinho resolve vários problemas de entrevista:

- **Padrão repetido:** uma string `s` de tamanho n é formada por repetições de um bloco se `lps[n-1] > 0` e `n % (n - lps[n-1]) == 0`.
- **Menor palíndromo adicionando à esquerda:** calcule o LPS de `s + "#" + reverso(s)`. O último valor diz o maior prefixo de `s` que já é palíndromo.
- **Maior prefixo que também é sufixo:** é diretamente `lps[n-1]`.

<Callout type="tip" title="Separador na concatenação">
Ao montar `padrao + "#" + texto` para reaproveitar só a função LPS, use um separador que não aparece em nenhuma das strings. Sem ele, um casamento pode atravessar a fronteira e gerar um falso resultado.
</Callout>

## Na entrevista

Em Python, `texto.find(padrao)` costuma ser aceito para uma única busca simples, e vale perguntar se o entrevistador quer a implementação. Quando ele quer, ou quando o problema pede O(n + m) garantido, escreva o KMP. Explique o LPS com um exemplo pequeno antes de codar, porque o `while` de recuo é onde a maioria erra. Follow-ups comuns: "qual o pior caso do ingênuo?" (O(n·m)) e "como achar todas as ocorrências, inclusive sobrepostas?" (o `k = lps[k-1]` depois do casamento completo). Se o problema envolve muitos padrões ou comparar substrings de tamanhos variados, Rabin-Karp costuma ser mais flexível.
