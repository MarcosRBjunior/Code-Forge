**Quick sort** também divide e conquista, mas faz o trabalho pesado **antes** da recursão: escolhe um **pivô**, reorganiza o array para que os menores fiquem à esquerda e os maiores à direita, e então ordena cada lado. Não há junção: quando os dois lados estão ordenados, o array inteiro está.

## Particionamento de Lomuto

O particionamento é o coração do algoritmo. A versão de Lomuto usa um ponteiro `i` que marca a fronteira da região "menor que o pivô":

<CodeTabs>

```python
import random

def particionar(nums, lo, hi):
    k = random.randint(lo, hi)            # pivô aleatório
    nums[k], nums[hi] = nums[hi], nums[k] # leva o pivô para o fim
    pivo = nums[hi]
    i = lo                                # próxima posição da região "menores"
    for j in range(lo, hi):
        if nums[j] < pivo:
            nums[i], nums[j] = nums[j], nums[i]
            i += 1
    nums[i], nums[hi] = nums[hi], nums[i] # pivô na posição final
    return i

def quick_sort(nums, lo=0, hi=None):
    if hi is None:
        hi = len(nums) - 1
    if lo < hi:
        p = particionar(nums, lo, hi)
        quick_sort(nums, lo, p - 1)
        quick_sort(nums, p + 1, hi)
    return nums

print(quick_sort([9, 4, 7, 3, 10, 5, 3]))  # [3, 3, 4, 5, 7, 9, 10]
```

Depois de `particionar`, o pivô está exatamente onde ficará no array ordenado. Essa propriedade é o que permite o **quickselect**, mais abaixo.

## Complexidade

- **Melhor e médio caso:** se o pivô divide o array em partes razoavelmente equilibradas, há cerca de log n níveis com O(n) de trabalho cada: **O(n log n)**.
- **Pior caso:** se o pivô é sempre o menor ou o maior elemento, um lado fica vazio e o outro com n − 1 elementos. São n níveis: **O(n²)**. Acontece, por exemplo, com pivô fixo no último elemento e entrada já ordenada.
- **Espaço:** in-place, com O(log n) de pilha no caso médio e O(n) no pior.
- **Estável:** não. As trocas longas embaralham elementos iguais.

<Callout type="warning" title="Escolha do pivô">
Pivô aleatório torna o pior caso extremamente improvável para qualquer entrada, inclusive as já ordenadas. Outra defesa comum é a mediana de três (primeiro, meio, último). Mencione isso sempre que apresentar quick sort.
</Callout>

## Muitos valores repetidos

Com muitos elementos iguais ao pivô, Lomuto joga todos para um lado e a recursão desequilibra. A **partição em três vias** (menores, iguais, maiores), a mesma ideia do problema da bandeira holandesa, resolve:

<CodeTabs>

```python
def tres_vias(nums, pivo):
    lt, i, gt = 0, 0, len(nums) - 1
    while i <= gt:
        if nums[i] < pivo:
            nums[lt], nums[i] = nums[i], nums[lt]
            lt += 1; i += 1
        elif nums[i] > pivo:
            nums[i], nums[gt] = nums[gt], nums[i]
            gt -= 1                       # não avança i: o trocado ainda não foi visto
        else:
            i += 1
    return nums

print(tres_vias([2, 0, 2, 1, 1, 0], 1))   # [0, 0, 1, 1, 2, 2]
```

## Quickselect: o k-ésimo sem ordenar tudo

Para achar o k-ésimo menor, particione e recorra **só** para o lado que contém a posição k. O trabalho cai pela metade a cada passo no caso médio: n + n/2 + n/4 + ... = **O(n)** em média, O(n²) no pior caso.

<CodeTabs>

```python
import random

def quickselect(nums, k):                 # k-ésimo menor, com k começando em 0
    lo, hi = 0, len(nums) - 1
    while True:
        r = random.randint(lo, hi)
        nums[r], nums[hi] = nums[hi], nums[r]
        pivo, i = nums[hi], lo
        for j in range(lo, hi):
            if nums[j] < pivo:
                nums[i], nums[j] = nums[j], nums[i]
                i += 1
        nums[i], nums[hi] = nums[hi], nums[i]
        if i == k:
            return nums[i]
        if i < k:
            lo = i + 1
        else:
            hi = i - 1

dados = [7, 2, 9, 4, 1, 8]
print(quickselect(dados[:], 2))                 # 4 (terceiro menor)
print(quickselect(dados[:], len(dados) - 1))    # 9 (maior)
```

      return nums[i];
    }

      lo = i + 1;
    } else {
      hi = i - 1;
    }
  }
}

			}
		}
		nums[i], nums[hi] = nums[hi], nums[i]
		if i == k {
			return nums[i]
		}
		if i < k {
			lo = i + 1
		} else {
			hi = i - 1
		}
	}
}

func main() {
	dados := []int{7, 2, 9, 4, 1, 8}
	fmt.Println(quickselect(append([]int(nil), dados...), 2))             // 4 (terceiro menor)
	fmt.Println(quickselect(append([]int(nil), dados...), len(dados)-1)) // 9 (maior)
}

## Quick sort ou merge sort?

| Critério | Quick sort | Merge sort |
| --- | --- | --- |
| Tempo médio | O(n log n), constantes baixas | O(n log n) |
| Pior caso | O(n²) | O(n log n) |
| Memória extra | O(log n) | O(n) |
| Estável | Não | Sim |

## Quando reconhecer

Use a ideia de particionamento quando o enunciado pede "k-ésimo maior/menor", "os k mais próximos" sem exigir ordem entre eles, "separar em grupos" (pares e ímpares, cores 0, 1 e 2) ou ordenação in-place com pouca memória.

## Na entrevista

Para "k-ésimo maior", ofereça as opções: ordenar (O(n log n)), heap de tamanho k (O(n log k)) e quickselect (O(n) médio). Explique a troca: quickselect é mais rápido em média, mas modifica o array e tem pior caso quadrático; o heap é previsível e funciona em streaming.
