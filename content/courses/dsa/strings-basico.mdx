Strings aparecem em quase toda entrevista: validar palíndromos, comparar anagramas, comprimir texto, achar substrings. A boa notícia é que uma string é, na prática, um **array de caracteres**. Quase tudo que você sabe de arrays vale aqui, com uma diferença importante: em Python (e em Java e JavaScript) strings são **imutáveis**.

## Imutabilidade e o custo escondido

Como a string não pode ser alterada, toda "modificação" cria uma cópia nova. Isso esconde um custo quadrático em código que parece inocente:

```python
def juntar_lento(palavras):
    resultado = ""
    for p in palavras:
        resultado += p + " "   # cada += pode copiar tudo que já existe
    return resultado.strip()

def juntar_rapido(palavras):
    return " ".join(palavras)    # uma única passada: O(n) no tamanho total

print(juntar_rapido(["ola", "mundo"]))  # ola mundo
```

O CPython às vezes otimiza o `+=`, mas você não deve contar com isso. A regra é: **acumule pedaços numa lista e junte no final com `join`**. Para editar caractere por caractere, converta para lista com `list(s)`, altere e volte com `"".join(...)`.

## As ferramentas que mais aparecem

| Necessidade | Ferramenta | Custo |
| --- | --- | --- |
| Contar frequência de letras | `collections.Counter(s)` ou array de 26 posições | O(n) |
| Testar se é letra/dígito | `c.isalnum()`, `c.isalpha()`, `c.isdigit()` | O(1) |
| Código numérico do caractere | `ord(c) - ord('a')` | O(1) |
| Inverter | `s[::-1]` | O(n) |
| Fatiar | `s[i:j]` | O(j − i), cria cópia |
| Procurar substring | `s.find(t)` ou `t in s` | O(n·m) no pior caso |

O detalhe do fatiamento importa: `s[i:j]` copia os caracteres. Dentro de um laço, fatiar a cada passo pode transformar um O(n) em O(n²). Quando possível, trabalhe com **índices** em vez de criar substrings.

## Exemplo: anagramas com contagem fixa

Duas strings são anagramas se têm exatamente as mesmas letras com as mesmas frequências. Com o alfabeto restrito a minúsculas, um array de 26 inteiros resolve sem ordenar:

```python
def sao_anagramas(a, b):
    if len(a) != len(b):
        return False
    contagem = [0] * 26
    for ca, cb in zip(a, b):
        contagem[ord(ca) - ord('a')] += 1
        contagem[ord(cb) - ord('a')] -= 1
    return all(x == 0 for x in contagem)

print(sao_anagramas("roma", "amor"))   # True
print(sao_anagramas("roma", "ramos"))  # False
```

Tempo O(n), espaço O(1), porque o array tem tamanho fixo (26), independente da entrada. Ordenar as duas strings também funciona, mas custa O(n log n).

## Exemplo: palíndromo ignorando pontuação

Dois ponteiros, um em cada ponta, pulando o que não é letra nem dígito:

```python
def eh_palindromo(s):
    i, j = 0, len(s) - 1
    while i < j:
        if not s[i].isalnum():
            i += 1
        elif not s[j].isalnum():
            j -= 1
        else:
            if s[i].lower() != s[j].lower():
                return False
            i += 1
            j -= 1
    return True

print(eh_palindromo("Socorram-me, subi no onibus em Marrocos"))  # True
```

Tempo O(n), espaço O(1): nenhuma string nova foi criada, diferente da versão que filtra e inverte (O(n) de espaço).

## Quando reconhecer

- O enunciado fala em **anagrama, permutação, frequência**: pense em contagem (hash map ou array de 26).
- Fala em **palíndromo** ou comparar extremos: dois ponteiros.
- Fala em **maior/menor substring com alguma condição**: provavelmente janela deslizante.
- Pede para **construir** uma string grande: lista de pedaços e `join`.

<Callout type="warning" title="Pergunte sobre o alfabeto">
Antes de escolher o array de 26 posições, confirme com o entrevistador: só minúsculas? Pode ter Unicode, espaços, maiúsculas? Se o alfabeto for aberto, use um dicionário.
</Callout>

## Na entrevista

Deixe claro que você conhece a imutabilidade e o custo de `+=` e de fatiar em laço. Diga explicitamente qual é o alfabeto que você está assumindo e por que o espaço é O(1) quando ele é fixo. Um follow-up comum é "e se a entrada for um fluxo enorme que não cabe na memória?"; aí a contagem incremental continua funcionando, enquanto ordenar deixa de ser viável.
