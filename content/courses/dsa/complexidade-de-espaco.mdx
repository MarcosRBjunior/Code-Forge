Complexidade de tempo mede quantos passos o algoritmo dá. **Complexidade de espaço** mede quanta memória **extra** ele precisa à medida que a entrada cresce. Em entrevistas, as duas aparecem juntas: quase todo follow-up do tipo "dá para melhorar?" é na verdade uma troca entre uma e outra.

## O que conta e o que não conta

A convenção mais comum em entrevistas é contar o **espaço auxiliar**: tudo o que você aloca além da própria entrada.

- **Conta:** listas, dicionários e conjuntos novos, cópias de strings, fatias (`nums[1:]` cria uma lista nova) e a **pilha de chamadas** da recursão.
- **Não conta (em geral):** a entrada recebida e a saída que o problema exige devolver. Se o enunciado pede uma lista com n resultados, essa lista não entra no cálculo, mas vale dizer isso em voz alta.
- **Variáveis escalares:** contadores, índices e somas ocupam O(1), não importa quantas sejam, desde que a quantidade não dependa de n.

## Exemplos lado a lado

```python
def tem_duplicado_conjunto(nums):
    vistos = set()               # até n elementos: O(n) de espaço
    for x in nums:
        if x in vistos:
            return True
        vistos.add(x)
    return False

def tem_duplicado_ordenando(nums):
    nums.sort()                  # in-place: O(1) extra (fora o sort interno)
    for i in range(1, len(nums)):
        if nums[i] == nums[i - 1]:
            return True
    return False

print(tem_duplicado_conjunto([3, 1, 4, 1]))    # True
print(tem_duplicado_ordenando([3, 1, 4, 5]))   # False
```

| Versão | Tempo | Espaço extra |
| --- | --- | --- |
| Conjunto | O(n) | O(n) |
| Ordenação in-place | O(n log n) | O(1) a O(n), depende do sort |

A segunda versão troca tempo por memória, mas **modifica a entrada**. Pergunte ao entrevistador se isso é permitido antes de escolher.

## A pilha de chamadas é memória

Cada chamada recursiva ainda não terminada guarda seus parâmetros e variáveis locais. A profundidade máxima da recursão vira espaço:

<CodeTabs>

```python
def soma_recursiva(nums, i=0):
    if i == len(nums):
        return 0
    return nums[i] + soma_recursiva(nums, i + 1)   # profundidade n: O(n)

def soma_iterativa(nums):
    total = 0                                      # O(1)
    for x in nums:
        total += x
    return total

print(soma_recursiva([1, 2, 3, 4]), soma_iterativa([1, 2, 3, 4]))  # 10 10
```

Uma DFS em árvore usa O(h), em que h é a altura: O(log n) numa árvore balanceada e O(n) numa árvore degenerada (uma "lista" disfarçada). Busca binária recursiva usa O(log n) de pilha; a iterativa usa O(1).

<Callout type="warning" title="Fatias escondem cópias">
Em Python, `s[1:]` e `nums[:mid]` criam objetos novos. Uma recursão que passa fatias a cada nível pode gastar O(n²) de memória total ao longo da execução, ou O(n log n) no caso do merge sort. Passe índices em vez de fatias quando o espaço importar.
</Callout>

## Técnicas para economizar espaço

1. **Reaproveitar a entrada:** escrever o resultado no próprio array (dois ponteiros de leitura e escrita).
2. **Guardar só o necessário em DP:** se `dp[i]` depende apenas de `dp[i - 1]` e `dp[i - 2]`, duas variáveis bastam.
3. **Iterar em vez de recorrer:** troca pilha implícita por um laço.
4. **Marcar no lugar:** usar o sinal do número ou um valor sentinela para marcar "visitado" em vez de um conjunto separado, quando a entrada permite.

## Quando o padrão aparece no enunciado

Frases como "use memória constante", "O(1) de espaço extra", "in-place" ou "sem alocar outro array" indicam que a solução com hash set não serve. Pense em ordenação, dois ponteiros, manipulação de bits ou reutilização da entrada.

## Na entrevista

Sempre declare as duas complexidades ao final: "tempo O(n), espaço O(n) por causa do dicionário". Se usou recursão, mencione a pilha sem esperar a pergunta. Um follow-up clássico é "e se a memória for limitada?"; responda apresentando a troca: "posso ordenar in-place e ficar com O(1) extra, pagando O(n log n) de tempo".
