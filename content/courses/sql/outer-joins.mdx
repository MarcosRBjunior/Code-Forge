"Liste todos os clientes e quanto cada um gastou, incluindo quem nunca comprou." Com `INNER JOIN`, quem nunca comprou some. As junções externas existem para isso: preservar linhas de um lado mesmo quando não há correspondência do outro. É também o terreno da armadilha mais clássica de SQL em entrevista, o filtro no lugar errado.

## Como funciona

- `LEFT JOIN` mantém todas as linhas da tabela da esquerda. Quando não há par, as colunas da direita vêm como `NULL`.
- `RIGHT JOIN` é o espelho: mantém todas as da direita. Na prática, quase todo mundo reescreve como `LEFT JOIN` trocando a ordem das tabelas, porque é mais fácil de ler.
- `FULL JOIN` (ou `FULL OUTER JOIN`) mantém as linhas dos dois lados, completando com `NULL` o lado que faltar.

```sql
CREATE TABLE clientes (
  id   integer PRIMARY KEY,
  nome text NOT NULL
);

CREATE TABLE pedidos (
  id         integer PRIMARY KEY,
  cliente_id integer,
  valor      numeric(10, 2) NOT NULL,
  status     text NOT NULL
);

INSERT INTO clientes VALUES
  (1, 'Ana'), (2, 'Bruno'), (3, 'Carla'), (4, 'Diego');

INSERT INTO pedidos VALUES
  (10, 1, 120.00, 'pago'),
  (11, 1, 80.00, 'cancelado'),
  (12, 2, 300.00, 'pago'),
  (13, 3, 45.00, 'cancelado'),
  (14, NULL, 99.00, 'pago');

SELECT c.nome, p.id AS pedido, p.valor
FROM clientes c
LEFT JOIN pedidos p ON p.cliente_id = c.id
ORDER BY c.id, p.id;
```

```text
Saída:
nome | pedido | valor
Ana | 10 | 120.00
Ana | 11 | 80.00
Bruno | 12 | 300.00
Carla | 13 | 45.00
Diego | NULL | NULL
```

Diego aparece com `NULL` nas colunas do pedido. O pedido 14, sem cliente (um pedido de visitante, por exemplo), não aparece porque está do lado direito.

## Anti-join: quem não tem par

Um uso muito cobrado do `LEFT JOIN` é encontrar linhas **sem** correspondência. Faça a junção e filtre onde a chave do lado direito ficou nula:

```sql
SELECT c.nome
FROM clientes c
LEFT JOIN pedidos p ON p.cliente_id = c.id
WHERE p.id IS NULL
ORDER BY c.nome;
```

```text
Saída:
nome
Diego
```

Teste sempre uma coluna que **não pode** ser nula numa linha real da direita, como a chave primária. Se você testar uma coluna que aceita `NULL`, vai confundir "não teve par" com "teve par, mas o valor era nulo". A alternativa com `NOT EXISTS` aparece no capítulo de subconsultas e costuma gerar o mesmo plano.

## A armadilha do WHERE

Agora a pergunta: "todos os clientes com o total de pedidos **pagos**". A tentação é escrever:

```sql
SELECT c.nome, coalesce(sum(p.valor), 0) AS total_pago
FROM clientes c
LEFT JOIN pedidos p ON p.cliente_id = c.id
WHERE p.status = 'pago'
GROUP BY c.nome
ORDER BY c.nome;
```

```text
Saída:
nome | total_pago
Ana | 120.00
Bruno | 300.00
```

Carla e Diego sumiram. O `WHERE` roda **depois** da junção: para Diego, `p.status` é `NULL`, e `NULL = 'pago'` não é verdadeiro, então a linha cai. Na prática o `LEFT JOIN` virou um `INNER JOIN`. A correção é mover o filtro da tabela da direita para o `ON`, onde ele decide apenas quais pedidos casam, sem eliminar clientes:

```sql
SELECT c.nome, coalesce(sum(p.valor), 0) AS total_pago
FROM clientes c
LEFT JOIN pedidos p ON p.cliente_id = c.id AND p.status = 'pago'
GROUP BY c.nome
ORDER BY c.nome;
```

```text
Saída:
nome | total_pago
Ana | 120.00
Bruno | 300.00
Carla | 0
Diego | 0
```

<Callout type="warning" title="Regra prática">
Filtro sobre a tabela preservada (a da esquerda num LEFT JOIN) vai no WHERE. Filtro sobre a tabela opcional vai no ON. Fora isso, você transforma a junção externa numa interna sem perceber.
</Callout>

## FULL JOIN

O `FULL JOIN` aparece em reconciliações: comparar duas fontes e mostrar o que existe só em uma, só na outra ou nas duas.

```sql
SELECT c.nome, p.id AS pedido
FROM clientes c
FULL JOIN pedidos p ON p.cliente_id = c.id
WHERE c.id IS NULL OR p.id IS NULL
ORDER BY pedido, c.nome;
```

```text
Saída:
nome | pedido
NULL | 14
Diego | NULL
```

O resultado mostra Diego (cliente sem pedido) e o pedido 14 (pedido sem cliente).

O **MySQL não tem `FULL JOIN`**. Lá você emula com a união de um `LEFT JOIN` e de um anti-join no sentido oposto:

```text
SELECT c.nome, p.id FROM clientes c LEFT JOIN pedidos p ON p.cliente_id = c.id
UNION ALL
SELECT c.nome, p.id FROM clientes c RIGHT JOIN pedidos p ON p.cliente_id = c.id
WHERE c.id IS NULL;
```

## Armadilhas

- **`count(*)` com LEFT JOIN.** Para Diego, `count(*)` devolve 1 (a linha com nulos existe). Use `count(p.id)`, que ignora nulos e devolve 0.
- **Encadear LEFT com INNER.** `A LEFT JOIN B ... JOIN C ON C.x = B.y` descarta as linhas de A sem B, porque a junção interna com C exige `B.y` não nulo. Mantenha `LEFT JOIN` em toda a cadeia opcional.
- **`sum` sem `coalesce`.** A soma de nenhum valor é `NULL`, não zero.

## Na entrevista

Antes de escrever, pergunte: "devo incluir clientes sem pedidos?". A resposta decide entre `INNER` e `LEFT`. Depois, olhe cada filtro e decida se ele vai no `ON` ou no `WHERE`. Follow-ups comuns: "reescreva usando `NOT EXISTS`" e "como fazer um FULL JOIN no MySQL?" (LEFT JOIN unido a um RIGHT JOIN filtrado, como acima).
