Qual tipo escolher no Postgres?" options={["float8, ponto flutuante de precisão dupla","numeric(10,2), decimal exato com duas casas","integer, guardando o preço em reais inteiros","text, guardando o preço como texto formatado"]} answer={1} explanation="numeric é exato. <Quiz question="Uma consulta usa WHERE total_com_imposto > 100, em que total_com_imposto é um apelido definido no SELECT. O que acontece?" options={["Funciona normalmente, pois o WHERE enxerga os apelidos do SELECT","Dá erro, pois o WHERE é avaliado antes do SELECT e não vê o apelido","Funciona só se o apelido também aparecer em um ORDER BY da consulta","O apelido é ignorado e a consulta devolve todas as linhas da tabela inteira"]} answer={1} explanation="Na ordem lógica, FROM e WHERE vêm antes do SELECT. Repita a expressão ou use uma subconsulta/CTE." />
<Quiz question="WHERE cargo = 'Pleno' AND depto = 'Dados' OR depto = 'Vendas' devolve o quê?" options={["Só pessoas de nível Pleno, tanto do depto Dados quanto do depto Vendas","Plenos de Dados mais qualquer pessoa de Vendas, de qualquer cargo","Nenhuma linha, porque as duas condições se contradizem entre si","Apenas plenos de Vendas, pois o OR descarta a condição de Dados"]} answer={1} explanation="AND tem precedência sobre OR. Use parênteses ou depto IN ('Dados', 'Vendas')." />
<Quiz question="Uma API pagina com LIMIT 20 OFFSET 200000 e ficou lenta. Qual a melhor correção?" options={["Aumentar o LIMIT, para o banco buscar mais linhas de cada vez no disco rígido","Paginar por chave: WHERE (criado_em, id) menor que o último visto, com índice","Remover o ORDER BY para o banco não precisar ordenar as linhas antes de paginar","Trocar para SELECT DISTINCT para eliminar linhas repetidas antes do OFFSET"]} answer={1} explanation="OFFSET obriga o banco a ler e descartar todas as linhas anteriores. A paginação por chave salta direto pelo índice." />
<Quiz question="No Postgres, ORDER BY nota DESC LIMIT 3 retorna alunos sem nota no topo. Por quê?" options={["É um bug conhecido do Postgres, que deveria colocar os nulos por último","NULL é tratado como maior que qualquer valor, então vem antes em DESC","O LIMIT ignora o ORDER BY e devolve as primeiras linhas lidas da tabela toda","A coluna nota precisa de índice para o ORDER BY tratar os nulos direito"]} answer={1} explanation="Use ORDER BY nota DESC NULLS LAST. No MySQL, NULL é o menor valor e o comportamento é o inverso." />
<Quiz question="SELECT * FROM t WHERE id NOT IN (SELECT ref FROM u) devolveu zero linhas, mas você sabe que há ids sem referência. Causa mais provável?" options={["Falta índice em ref", "u.ref contém NULL", "t está vazia", "NOT IN não funciona em subconsultas"]} answer={1} explanation="Com um NULL na lista, todo NOT IN fica desconhecido. Use NOT EXISTS ou filtre ref IS NOT NULL." />
<Quiz question="Você declara FOREIGN KEY em pedidos.cliente_id no Postgres e deleções de clientes ficaram lentas. O que falta?" options={["Uma chave primária em pedidos, para o banco localizar as linhas","Um índice em pedidos.cliente_id, para a checagem não varrer a tabela","A opção ON DELETE CASCADE, que acelera a verificação das linhas filhas","Uma restrição CHECK em cliente_id, para o banco pular as linhas inválidas"]} answer={1} explanation="A cada deleção, o banco procura pedidos que referenciam o cliente. Sem índice na coluna, isso vira uma varredura completa." />
<Quiz question="Uma coluna tem CHECK (quantidade > 0) e aceita NULL. Qual INSERT é aceito?" options={["quantidade = 0, pois zero não é um valor negativo","quantidade = -1, pois o CHECK só compara valores positivos","quantidade = NULL, pois NULL > 0 é desconhecido e não falso","Nenhum valor passa, pois qualquer INSERT é checado contra a regra"]} answer={2} explanation="O CHECK só rejeita resultados falsos; NULL > 0 é desconhecido e passa. Adicione NOT NULL se o valor for obrigatório." />
