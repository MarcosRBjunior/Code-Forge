<Quiz question="Uma transferência debita a conta A, o servidor cai antes de creditar a conta B e, ao reiniciar, o débito sumiu. Qual propriedade ACID garantiu isso?" options={["Consistência", "Atomicidade", "Isolamento", "Durabilidade"]} answer={1} explanation="Atomicidade: ou todas as instruções da transação são aplicadas, ou nenhuma. <Quiz question="Num relatório, a mesma consulta de soma rodada duas vezes dentro de uma transação devolve valores diferentes porque outra sessão confirmou um UPDATE no meio. Qual é a anomalia e o nível mínimo que a evita?" options={["Leitura suja; READ COMMITTED", "Leitura não repetível; REPEATABLE READ", "Deadlock; SERIALIZABLE", "Escrita perdida; READ UNCOMMITTED"]} answer={1} explanation="Ler de novo e ver dado alterado e confirmado por outra transação é leitura não repetível. REPEATABLE READ usa o mesmo snapshot durante toda a transação." />
<Quiz question="Qual é o nível de isolamento padrão no Postgres e no MySQL com InnoDB, respectivamente?" options={["SERIALIZABLE e READ COMMITTED", "READ COMMITTED e REPEATABLE READ", "REPEATABLE READ e READ COMMITTED", "READ UNCOMMITTED nos dois"]} answer={1} explanation="O Postgres usa READ COMMITTED por padrão; o InnoDB usa REPEATABLE READ." />
<Quiz question="Dois pedidos tentam reservar a última vaga de um curso ao mesmo tempo. Qual abordagem evita a venda dupla com uma única instrução?" options={["SELECT vagas e depois UPDATE no código da aplicação", "UPDATE cursos SET vagas = vagas - 1 WHERE id = 9 AND vagas > 0, conferindo as linhas afetadas", "Criar um índice em vagas", "Usar READ UNCOMMITTED"]} answer={1} explanation="O UPDATE condicional é atômico: a segunda transação espera o lock da linha, reavalia vagas > 0 e não altera nada." />
<Quiz question="Sua aplicação recebe 'deadlock detected' de vez em quando em transferências entre contas. O que resolve a causa?" options={["Aumentar o deadlock_timeout", "Atualizar as contas sempre na mesma ordem (por exemplo, id crescente) e prever retry", "Remover a chave primária", "Trocar para Index Only Scan"]} answer={1} explanation="Deadlock é espera circular. Ordem fixa de travamento elimina o ciclo; retry cobre os casos residuais." />
<Quiz question="Existe índice em (status, criado_em). Qual consulta NÃO aproveita bem o índice?" options={["WHERE status = 'pago'", "WHERE status = 'pago' AND criado_em > '2024-01-01'", "WHERE criado_em > '2024-01-01'", "WHERE status = 'pago' ORDER BY criado_em"]} answer={2} explanation="Pela regra do prefixo à esquerda, filtrar só pela segunda coluna não permite descer na B-tree de forma direcionada." />
<Quiz question="O EXPLAIN de uma consulta que filtra uma tabela de 10 linhas mostra Seq Scan mesmo com índice na coluna.
