Algumas perguntas de SQL voltam tanto em entrevistas que viraram um repertório: o segundo maior salário, os registros duplicados, quem ganha mais que o próprio gestor, os clientes que nunca compraram. Elas parecem simples, mas cada uma esconde uma borda (empate, `NULL`, ausência de resultado) que o entrevistador usa para separar quem decorou de quem entende. Este capítulo resolve cada uma e mostra onde está a pegadinha.

## O esquema

```sql
CREATE TABLE departamentos (
  id   integer PRIMARY KEY,
  nome text NOT NULL
);

CREATE TABLE funcionarios (
  id       integer PRIMARY KEY,
  nome     text NOT NULL,
  email    text NOT NULL,
  salario  integer NOT NULL,
  depto_id integer REFERENCES departamentos (id),
  gestor_id integer REFERENCES funcionarios (id)
);

CREATE TABLE vendas (
  id             integer PRIMARY KEY,
  funcionario_id integer NOT NULL REFERENCES funcionarios (id),
  valor          integer NOT NULL
);

INSERT INTO departamentos VALUES (1, 'Engenharia'), (2, 'Vendas'), (3, 'Jurídico');

INSERT INTO funcionarios VALUES
  (1, 'Helena',  'helena@ex.com', 30000, 1, NULL),
  (2, 'Igor',    'igor@ex.com',   18000, 1, 1),
  (3, 'Júlia',   'julia@ex.com',  32000, 1, 1),
  (4, 'Kleber',  'kleber@ex.com', 18000, 1, 1),
  (5, 'Lara',    'lara@ex.com',   15000, 2, NULL),
  (6, 'Marcos',  'marcos@ex.com',   16000, 2, 5),
  (7, 'Nina',    'igor@ex.com',   12000, 2, 5);

INSERT INTO vendas VALUES (1, 5, 900), (2, 6, 400), (3, 6, 650), (4, 5, 120);

SELECT count(*) AS funcionarios FROM funcionarios;
```

```text
Saída:
funcionarios
7
```

## 1. O segundo maior salário

A primeira ideia, `ORDER BY salario DESC LIMIT 1 OFFSET 1`, falha com empates: se dois funcionários dividirem o maior salário, você devolve o maior de novo. Ela também devolve zero linhas quando não existe segundo salário, e muitos enunciados pedem `NULL` nesse caso. A versão robusta compara com o máximo:

```sql
SELECT max(salario) AS segundo_maior
FROM funcionarios
WHERE salario < (SELECT max(salario) FROM funcionarios);
```

```text
Saída:
segundo_maior
30000
```

Como uma agregação sem `GROUP BY` sempre devolve uma linha, a resposta é `NULL` quando não há segundo valor. Para o **N-ésimo** maior, generalize com `DENSE_RANK`, que trata empates como uma posição só:

```sql
SELECT DISTINCT salario AS terceiro_maior
FROM (
  SELECT salario, DENSE_RANK() OVER (ORDER BY salario DESC) AS pos
  FROM funcionarios
) t
WHERE pos = 3;
```

```text
Saída:
terceiro_maior
18000
```

## 2. Valores duplicados

Encontrar e-mails repetidos é um `GROUP BY` com `HAVING`:

```sql
SELECT email, count(*) AS vezes
FROM funcionarios
GROUP BY email
HAVING count(*) > 1
ORDER BY email;
```

```text
Saída:
email | vezes
igor@ex.com | 2
```

O follow-up quase certo é "agora apague as duplicatas mantendo a de menor id". No Postgres, uma forma clara é usar `ROW_NUMBER` ou uma autojunção no `DELETE ... USING`. Para não estragar os exemplos seguintes, faça dentro de uma transação desfeita:

```sql
BEGIN;
DELETE FROM funcionarios f
USING funcionarios outro
WHERE f.email = outro.email AND f.id > outro.id;
SELECT id, email FROM funcionarios WHERE email = 'igor@ex.com';
ROLLBACK;
```

```text
Saída:
id | email
2 | igor@ex.com
```

No MySQL, a sintaxe é diferente: `DELETE f FROM funcionarios f JOIN funcionarios o ON ...`. Mostre isso como texto se for perguntado:

```text
DELETE f FROM funcionarios f
JOIN funcionarios o ON f.email = o.email AND f.id > o.id;
```

## 3. Quem ganha mais que o gestor

É um self join: a mesma tabela aparece duas vezes, uma no papel de funcionário e outra no de gestor.

```sql
SELECT f.nome AS funcionario, f.salario, g.nome AS gestor, g.salario AS salario_gestor
FROM funcionarios f
JOIN funcionarios g ON g.id = f.gestor_id
WHERE f.salario > g.salario
ORDER BY f.nome;
```

```text
Saída:
funcionario | salario | gestor | salario_gestor
Júlia | 32000 | Helena | 30000
Marcos | 16000 | Lara | 15000
```

O `INNER JOIN` descarta quem não tem gestor, o que aqui é exatamente o desejado.

## 4. Quem nunca vendeu

O anti-join clássico. Prefira `NOT EXISTS` ou `LEFT JOIN ... IS NULL`; evite `NOT IN` com subconsulta, porque um único `NULL` na lista faz a condição nunca ser verdadeira.

```sql
SELECT f.nome
FROM funcionarios f
WHERE f.depto_id = 2
  AND NOT EXISTS (SELECT 1 FROM vendas v WHERE v.funcionario_id = f.id)
ORDER BY f.nome;
```

```text
Saída:
nome
Nina
```

## 5. O maior salário de cada departamento

Mostre o funcionário, não só o valor. Comparar com o máximo do grupo mantém os empates:

```sql
SELECT d.nome AS depto, f.nome, f.salario
FROM funcionarios f
JOIN departamentos d ON d.id = f.depto_id
WHERE f.salario = (
  SELECT max(f2.salario) FROM funcionarios f2 WHERE f2.depto_id = f.depto_id
)
ORDER BY d.nome;
```

```text
Saída:
depto | nome | salario
Engenharia | Júlia | 32000
Vendas | Marcos | 16000
```

O Jurídico não aparece porque não tem funcionários. Se o enunciado pedir todos os departamentos, comece por `departamentos` com `LEFT JOIN`. O capítulo de Top N por grupo generaliza esse padrão.

<Callout type="warning" title="Empates e conjuntos vazios">
Antes de responder, pergunte: "se houver empate, devolvo todos?" e "se não houver resultado, devolvo NULL ou nada?". Essas duas perguntas resolvem metade das pegadinhas deste capítulo.
</Callout>

## Na entrevista

Escreva primeiro a versão mais simples que funciona, depois teste mentalmente com empate, `NULL` e tabela vazia, e ajuste. Diga em voz alta por que escolheu `NOT EXISTS` em vez de `NOT IN`, ou `DENSE_RANK` em vez de `OFFSET`. Follow-ups comuns: "e o N-ésimo maior, com N como parâmetro?" e "como apagar as duplicatas mantendo uma?".
