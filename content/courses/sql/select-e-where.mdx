`SELECT` com `WHERE` é a base de toda consulta, e é justamente por ser básico que erros aqui custam caro na entrevista: um filtro com `OR` sem parênteses ou uma comparação de texto com o caso errado devolve um resultado plausível e errado. Neste capítulo você vai ver como o banco avalia uma consulta simples e os filtros que mais aparecem.

## Ordem lógica de execução

Você escreve `SELECT ... FROM ... WHERE ...`, mas o banco processa as cláusulas em outra ordem lógica:

```text
FROM / JOIN  ->  WHERE  ->  GROUP BY  ->  HAVING  ->  SELECT  ->  DISTINCT  ->  ORDER BY  ->  LIMIT
```

Duas consequências práticas: o `WHERE` filtra linhas antes de qualquer agregação, e um apelido criado no `SELECT` não existe ainda no `WHERE`. Ele só fica visível a partir do `ORDER BY`.

Vamos usar uma tabela de funcionários:

```sql
CREATE TABLE funcionarios (
  id           integer PRIMARY KEY,
  nome         text NOT NULL,
  departamento text NOT NULL,
  cargo        text NOT NULL,
  salario      numeric(10, 2) NOT NULL,
  admitido_em  date NOT NULL
);

INSERT INTO funcionarios VALUES
  (1, 'Ana Souza', 'Engenharia', 'Sênior', 18000, '2019-04-10'),
  (2, 'Bruno Lima', 'Engenharia', 'Pleno', 11000, '2021-08-02'),
  (3, 'Carla Dias', 'Dados', 'Sênior', 17500, '2020-01-15'),
  (4, 'Diego Melo', 'Vendas', 'Júnior', 4500, '2023-02-20'),
  (5, 'Elisa Rocha', 'Dados', 'Pleno', 12000, '2022-06-01'),
  (6, 'Fábio Nunes', 'Vendas', 'Pleno', 7000, '2020-11-30'),
  (7, 'Gabi Torres', 'Engenharia', 'Júnior', 6500, '2024-01-08'),
  (8, 'Hugo Alves', 'RH', 'Pleno', 8000, '2018-09-12');

SELECT nome, cargo, salario
FROM funcionarios
WHERE departamento = 'Engenharia'
ORDER BY salario DESC;
```

```text
Saída:
nome | cargo | salario
Ana Souza | Sênior | 18000.00
Bruno Lima | Pleno | 11000.00
Gabi Torres | Júnior | 6500.00
```

## Projeção: escolha as colunas

Liste as colunas que você precisa em vez de `SELECT *`. Em produção, `*` traz dados desnecessários pela rede, quebra quando alguém adiciona uma coluna e impede que o banco responda só com um índice. Você também pode calcular expressões e dar apelidos com `AS`:

```sql
SELECT nome,
       salario * 12 AS salario_anual,
       upper(departamento) AS depto
FROM funcionarios
WHERE salario * 12 > 150000
ORDER BY salario_anual DESC;
```

```text
Saída:
nome | salario_anual | depto
Ana Souza | 216000.00 | ENGENHARIA
Carla Dias | 210000.00 | DADOS
```

Observe que o `WHERE` repete `salario * 12` em vez de usar `salario_anual`. Escrever `WHERE salario_anual > 150000` dá erro de coluna inexistente, pela ordem lógica vista acima. O `ORDER BY`, que roda depois do `SELECT`, aceita o apelido.

## Filtros comuns

- **Comparação**: `=`, `<>` (ou `!=`), `<`, `<=`, `>`, `>=`.
- **Intervalo**: `BETWEEN a AND b` inclui as duas pontas.
- **Lista**: `IN ('a', 'b')`.
- **Padrão de texto**: `LIKE 'Ana%'`, em que `%` casa qualquer sequência e `_` casa um caractere.
- **Combinação**: `AND`, `OR`, `NOT`. O `AND` tem precedência maior que o `OR`.

A precedência é a armadilha clássica. Suponha que você quer os plenos de Dados ou de Vendas:

```sql
SELECT nome, departamento, cargo
FROM funcionarios
WHERE cargo = 'Pleno'
  AND (departamento = 'Dados' OR departamento = 'Vendas')
ORDER BY nome;
```

```text
Saída:
nome | departamento | cargo
Elisa Rocha | Dados | Pleno
Fábio Nunes | Vendas | Pleno
```

Sem os parênteses, a condição vira `(cargo = 'Pleno' AND departamento = 'Dados') OR departamento = 'Vendas'` e Diego, que é júnior de Vendas, apareceria no resultado. Escrever `departamento IN ('Dados', 'Vendas')` evita o problema e é mais legível.

Para datas, prefira intervalos semiabertos. Eles funcionam igual para `date` e `timestamp` e não deixam escapar nada do último dia:

```sql
SELECT nome, admitido_em
FROM funcionarios
WHERE admitido_em >= '2020-01-01'
  AND admitido_em < '2022-01-01'
ORDER BY admitido_em;
```

```text
Saída:
nome | admitido_em
Carla Dias | 2020-01-15
Fábio Nunes | 2020-11-30
Bruno Lima | 2021-08-02
```

## Texto e maiúsculas

No Postgres, `=` e `LIKE` diferenciam maiúsculas de minúsculas; para ignorar o caso, use `ILIKE` ou compare `lower(coluna)`. No MySQL, o resultado depende da collation da coluna, e as collations padrão (como `utf8mb4_0900_ai_ci`) já ignoram maiúsculas e acentos. A mesma consulta pode, portanto, devolver resultados diferentes nos dois bancos.

```sql
SELECT nome
FROM funcionarios
WHERE nome ILIKE '%souza%' OR nome LIKE 'g%'
ORDER BY nome;
```

```text
Saída:
nome
Ana Souza
```

`LIKE 'g%'` não encontrou Gabi porque o nome começa com G maiúsculo.

## Armadilhas

- **Apelido no `WHERE`**: não funciona; repita a expressão ou use uma subconsulta.
- **`OR` sem parênteses**: confira a precedência sempre que misturar `AND` e `OR`.
- **Função sobre a coluna filtrada**: `WHERE lower(nome) = 'ana souza'` ou `WHERE extract(year FROM admitido_em) = 2020` impede o uso de um índice comum na coluna. Prefira reescrever como intervalo.
- **`LIKE '%texto'`**: um curinga no começo também não usa índice B-tree.

<Callout type="tip" title="Diga a granularidade do resultado">
Antes de escrever, diga o que é uma linha da resposta: "uma linha por funcionário de Engenharia". Isso ajuda o entrevistador a acompanhar e evita colunas sobrando.
</Callout>

## Na entrevista

Leia o enunciado, escreva primeiro o `FROM` e o `WHERE` (de onde vêm as linhas e quais ficam) e só depois o `SELECT`. Confirme se a comparação de texto deve ignorar caso e se as datas incluem o último dia. Follow-ups comuns: "por que não usar `SELECT *`?" e "essa consulta usaria um índice em `admitido_em`?" (sim, com o intervalo; não, com `extract` sobre a coluna).
