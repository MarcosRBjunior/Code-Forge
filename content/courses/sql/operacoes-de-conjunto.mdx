Junções combinam tabelas **lado a lado**, acrescentando colunas. As operações de conjunto combinam resultados **um embaixo do outro**, tratando cada consulta como um conjunto de linhas. Elas respondem perguntas como "quem comprou no app **ou** no site", "quem comprou nos **dois**" e "quem se cadastrou **mas não** comprou".

## As regras do jogo

Para combinar duas consultas com `UNION`, `INTERSECT` ou `EXCEPT`:

- as duas precisam ter o **mesmo número de colunas**;
- as colunas correspondentes precisam ter **tipos compatíveis**;
- os **nomes** das colunas do resultado vêm da primeira consulta;
- `ORDER BY` e `LIMIT` aparecem uma vez só, no final, e valem para o resultado combinado.

Por padrão, as três operações removem duplicatas, como conjuntos matemáticos. A versão com `ALL` mantém as repetições.

```sql
CREATE TABLE compras_app (cliente text NOT NULL, dia date NOT NULL);
CREATE TABLE compras_site (cliente text NOT NULL, dia date NOT NULL);
CREATE TABLE cadastros (cliente text PRIMARY KEY);

INSERT INTO compras_app VALUES
  ('ana', '2024-05-01'), ('bruno', '2024-05-02'),
  ('ana', '2024-05-03'), ('carla', '2024-05-03');
INSERT INTO compras_site VALUES
  ('bruno', '2024-05-01'), ('diego', '2024-05-02'),
  ('carla', '2024-05-04'), ('carla', '2024-05-05');
INSERT INTO cadastros VALUES
  ('ana'), ('bruno'), ('carla'), ('diego'), ('elisa'), ('fabio');

SELECT cliente FROM compras_app
UNION
SELECT cliente FROM compras_site
ORDER BY cliente;
```

```text
Saída:
cliente
ana
bruno
carla
diego
```

## UNION vs UNION ALL

`UNION` precisa eliminar duplicatas, o que exige ordenar ou montar uma tabela hash com o resultado inteiro. `UNION ALL` só concatena. Se você sabe que não há duplicatas, ou se quer mantê-las, use `UNION ALL`: é mais barato e, em entrevista, mostra que você pensou nisso.

Um uso típico de `UNION ALL` é empilhar eventos de fontes diferentes com uma coluna que identifica a origem e depois agregar:

```sql
SELECT canal, count(*) AS compras
FROM (
  SELECT 'app' AS canal, cliente FROM compras_app
  UNION ALL
  SELECT 'site', cliente FROM compras_site
) t
GROUP BY canal
ORDER BY canal;
```

```text
Saída:
canal | compras
app | 4
site | 4
```

Se você tivesse usado `UNION` em vez de `UNION ALL`, as duas compras de Ana no app (e as duas de Carla no site) virariam uma só e a contagem sairia 3 e 3. Esse é um bug silencioso clássico.

## INTERSECT: nos dois

`INTERSECT` devolve as linhas que aparecem nas duas consultas. Quem comprou pelos dois canais:

```sql
SELECT cliente FROM compras_app
INTERSECT
SELECT cliente FROM compras_site
ORDER BY cliente;
```

```text
Saída:
cliente
bruno
carla
```

## EXCEPT: em um, mas não no outro

`EXCEPT` devolve as linhas da primeira consulta que **não** aparecem na segunda. A ordem importa: `A EXCEPT B` é diferente de `B EXCEPT A`. Clientes cadastrados que nunca compraram em canal nenhum:

```sql
SELECT cliente FROM cadastros
EXCEPT
SELECT cliente FROM compras_app
EXCEPT
SELECT cliente FROM compras_site
ORDER BY cliente;
```

```text
Saída:
cliente
elisa
fabio
```

As operações são avaliadas da esquerda para a direita, exceto `INTERSECT`, que tem precedência maior que `UNION` e `EXCEPT`. Na dúvida, use parênteses.

### Comparação com NULL

As operações de conjunto tratam dois `NULL` como iguais ao eliminar duplicatas, diferentemente do `=` de um join, em que `NULL = NULL` não é verdadeiro. Por isso `EXCEPT` é um jeito seguro de comparar duas tabelas inteiras, coluna por coluna, mesmo com nulos.

## Postgres e MySQL

O Postgres suporta tudo há muito tempo. O MySQL só ganhou `INTERSECT` e `EXCEPT` na versão 8.0.31; antes disso você escrevia com `IN`, `EXISTS` ou `LEFT JOIN ... IS NULL`. O Oracle chama `EXCEPT` de `MINUS`. Se o entrevistador disser "estamos em MySQL 5.7", tenha a versão com `NOT EXISTS` pronta:

```text
SELECT c.cliente
FROM cadastros c
WHERE NOT EXISTS (SELECT 1 FROM compras_app a WHERE a.cliente = c.cliente)
  AND NOT EXISTS (SELECT 1 FROM compras_site s WHERE s.cliente = c.cliente);
```

<Callout type="tip" title="Validar uma reescrita">
Para provar que duas consultas devolvem o mesmo resultado, rode `(A EXCEPT B)` e `(B EXCEPT A)`. Se as duas vierem vazias, os conjuntos são iguais (use `EXCEPT ALL` para comparar também a quantidade de repetições).
</Callout>

## Armadilhas

- **Colunas em ordem diferente.** As colunas casam por posição, não por nome. `SELECT nome, cidade` unido a `SELECT cidade, nome` não dá erro (os tipos batem) e produz lixo.
- **`ORDER BY` no meio.** Ordenar a primeira consulta isoladamente exige parênteses e não garante a ordem final.
- **`UNION` onde bastava `UNION ALL`.** Custo extra de deduplicação e, pior, perda de linhas legítimas.

## Na entrevista

Diga explicitamente se quer ou não manter duplicatas e escolha `UNION` ou `UNION ALL` por isso. Follow-ups comuns: "qual a diferença de custo entre UNION e UNION ALL?" (deduplicação exige ordenação ou hash) e "reescreva o EXCEPT sem EXCEPT" (`NOT EXISTS` ou anti-join com `LEFT JOIN`).
