Sua aplicação sabe o IP de destino, mas a placa de rede só sabe entregar quadros para endereços MAC. Alguém precisa traduzir "quero falar com 192.168.1.1" em "mande o quadro para a4:bb:6d:11:22:33". Em IPv4 esse papel é do **ARP** (Address Resolution Protocol). Ele é pequeno, antigo e confia em todo mundo, o que o torna fonte de latência na primeira conexão e de ataques clássicos em redes locais.

## Primeiro: quem é o destino do quadro?

Antes de resolver qualquer coisa, o host decide se o destino está na mesma sub-rede. Se estiver, ele resolve o MAC do próprio destino. Se não estiver, resolve o MAC do **gateway padrão** e entrega o pacote a ele, ainda com o IP de destino final. Você nunca faz ARP para um IP da internet.

## Como funciona a troca

```text
 Host A 192.168.1.10                        Host B 192.168.1.42
   |                                                  |
   |-- broadcast ff:ff:ff:ff:ff:ff ------------------>|  (todos recebem)
   |   "quem tem 192.168.1.42? responda a .10"        |
   |                                                  |
   |<-------------------------- unicast para A -------|
   |   "192.168.1.42 está em 08:00:27:aa:bb:cc"       |
   |                                                  |
   [A guarda no cache e envia o pacote IP]
```

A requisição vai em broadcast porque A ainda não sabe a quem mandar. A resposta vai direto para A. Os dois lados aproveitam: B também anota o MAC de A, já que provavelmente vai responder em seguida.

O resultado fica num **cache ARP** com validade curta (de segundos a poucos minutos, dependendo do sistema). Enquanto a resolução não volta, o kernel segura o pacote numa fila pequena; se ninguém responde, os pacotes são descartados e você vê "host unreachable".

## O pacote ARP por dentro

O ARP viaja direto sobre Ethernet (EtherType `0x0806`), sem IP. São 28 bytes com campos fixos, fáceis de montar com `struct`:

<CodeTabs>

```python
import struct, socket

def arp_request(mac_orig, ip_orig, ip_alvo):
    return struct.pack(
        "!HHBBH6s4s6s4s",
        1,           # hardware: Ethernet
        0x0800,      # protocolo: IPv4
        6, 4,        # tamanhos: MAC 6, IP 4
        1,           # operação: 1 = request, 2 = reply
        bytes.fromhex(mac_orig.replace(":", "")),
        socket.inet_aton(ip_orig),
        b"\x00" * 6, # MAC alvo desconhecido
        socket.inet_aton(ip_alvo),
    )

pkt = arp_request("3c:22:fb:9a:10:7e", "192.168.1.10", "192.168.1.42")
print(len(pkt), "bytes")
print(pkt.hex(" "))
hw, proto, hl, pl, op, sha, spa, tha, tpa = struct.unpack("!HHBBH6s4s6s4s", pkt)
print("op", op, "quem tem", socket.inet_ntoa(tpa), "? diga a", socket.inet_ntoa(spa))
```

import java.nio.ByteBuffer;

// IP em texto -> 4 bytes (como socket.inet_aton)
static byte[] inetAton(String ip) {
    String[] partes = ip.split("\\.");
    byte[] b = new byte[4];
    for (int i = 0; i < 4; i++) b[i] = (byte) Integer.parseInt(partes[i]);
    return b;
}

static String inetNtoa(byte[] b) {
    return (b[0] & 0xFF) + "." + (b[1] & 0xFF) + "." + (b[2] & 0xFF) + "." + (b[3] & 0xFF);
}

static byte[] arpRequest(String macOrig, String ipOrig, String ipAlvo) {
    ByteBuffer buf = ByteBuffer.allocate(28); // big-endian por padrão (ordem de rede)
    buf.putShort((short) 1);         // hardware: Ethernet
    buf.putShort((short) 0x0800);    // protocolo: IPv4
    buf.put((byte) 6).put((byte) 4); // tamanhos: MAC 6, IP 4
    buf.putShort((short) 1);         // operação: 1 = request, 2 = reply
    for (String h : macOrig.split(":")) buf.put((byte) Integer.parseInt(h, 16));
    buf.put(inetAton(ipOrig));
    buf.put(new byte[6]);            // MAC alvo desconhecido
    buf.put(inetAton(ipAlvo));
    return buf.array();
}

public static void main(String[] args) {
    byte[] pkt = arpRequest("3c:22:fb:9a:10:7e", "192.168.1.10", "192.168.1.42");
    System.out.println(pkt.length + " bytes");
    StringBuilder hex = new StringBuilder();
    for (byte b : pkt) hex.append(hex.length() > 0 ? " " : "").append(String.format("%02x", b & 0xFF));
    System.out.println(hex);
    ByteBuffer leitor = ByteBuffer.wrap(pkt);
    int op = leitor.getShort(6) & 0xFFFF;
    byte[] spa = new byte[4], tpa = new byte[4];
    leitor.position(14);
    leitor.get(spa);
    leitor.position(24);
    leitor.get(tpa);
    System.out.println("op " + op + " quem tem " + inetNtoa(tpa) + " ? diga a " + inetNtoa(spa));
}

    return to_string(b[0]) + "." + to_string(b[1]) + "." + to_string(b[2]) + "." + to_string(b[3]);
}

// grava 16 bits em big-endian (ordem de rede)
void put16(vector<uint8_t>& v, uint16_t x) {
    v.push_back(x >> 8);
    v.push_back(x & 0xFF);
}

vector<uint8_t> arpRequest(const string& macOrig, const string& ipOrig, const string& ipAlvo) {
    vector<uint8_t> pkt;
    put16(pkt, 1);       // hardware: Ethernet
    put16(pkt, 0x0800);  // protocolo: IPv4
    pkt.push_back(6);    // tamanho do MAC
    pkt.push_back(4);    // tamanho do IP
    put16(pkt, 1);       // operação: 1 = request, 2 = reply
    for (size_t i = 0; i < macOrig.size(); i += 3) pkt.push_back((uint8_t)stoi(macOrig.substr(i, 2), nullptr, 16));
    for (auto b : inetAton(ipOrig)) pkt.push_back(b);
    pkt.insert(pkt.end(), 6, 0);  // MAC alvo desconhecido
    for (auto b : inetAton(ipAlvo)) pkt.push_back(b);
    return pkt;
}

func arpRequest(macOrig, ipOrig, ipAlvo string) []byte {
	pkt := make([]byte, 28)
	binary.BigEndian.PutUint16(pkt[0:], 1)      // hardware: Ethernet
	binary.BigEndian.PutUint16(pkt[2:], 0x0800) // protocolo: IPv4

## Simulando o cache

O cache é o que evita um broadcast por pacote. A simulação abaixo usa um relógio fictício para mostrar acerto, expiração e nova consulta.

<CodeTabs>

```python
class CacheArp:
    def __init__(self, ttl):
        self.ttl, self.entradas = ttl, {}

    def resolver(self, ip, agora, rede):
        e = self.entradas.get(ip)
        if e and agora - e[1] < self.ttl:
            return f"t={agora}: {ip} -> {e[0]} (cache)"
        mac = rede[ip]  # simula a resposta ao broadcast
        self.entradas[ip] = (mac, agora)
        return f"t={agora}: {ip} -> {mac} (broadcast ARP)"

rede = {"192.168.1.1": "a4:bb:6d:11:22:33"}
c = CacheArp(ttl=60)
for t in [0, 5, 59, 61]:
    print(c.resolver("192.168.1.1", t, rede))
```

import java.util.*;

class CacheArp {
    final int ttl;
    final Map<String, String> macs = new HashMap<>();       // ip -> mac
    final Map<String, Integer> instantes = new HashMap<>(); // ip -> quando aprendeu

    CacheArp(int ttl) { this.ttl = ttl; }

    String resolver(String ip, int agora, Map<String, String> rede) {
        Integer quando = instantes.get(ip);
        if (quando != null && agora - quando < ttl) {
            return "t=" + agora + ": " + ip + " -> " + macs.get(ip) + " (cache)";
        }

## Armadilhas e segurança

- **ARP spoofing:** qualquer máquina pode mandar respostas não solicitadas dizendo "o gateway sou eu". Os outros atualizam o cache e passam a enviar o tráfego para o atacante (man-in-the-middle). Defesas: inspeção dinâmica de ARP no switch, entradas estáticas para o gateway e, acima de tudo, criptografia fim a fim (TLS), que torna a interceptação inútil.
- **Gratuitous ARP:** um host anuncia o próprio IP sem ninguém perguntar. É usado para detectar IP duplicado e, em failover, para um IP virtual "mudar de máquina" (keepalived, VRRP): os vizinhos atualizam o cache na hora.
- **Cache velho:** após trocar um servidor mantendo o IP, clientes podem continuar mandando quadros para o MAC antigo até a entrada expirar. Daí o gratuitous ARP em migrações.
- **IPv6 não usa ARP:** usa o Neighbor Discovery, com mensagens ICMPv6 enviadas a grupos multicast em vez de broadcast.

## Na entrevista

ARP aparece quase sempre dentro de "o que acontece quando você digita uma URL": diga que o host compara o destino com a própria máscara, resolve o MAC do gateway via ARP (ou usa o cache) e só então envia o primeiro quadro. Se a conversa for de segurança, cite ARP spoofing e por que TLS protege mesmo numa rede local comprometida. Follow-ups: "por que a requisição é broadcast e a resposta unicast?" e "como um IP flutuante troca de máquina no failover?" (gratuitous ARP).
