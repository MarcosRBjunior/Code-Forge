Se duas réplicas aceitam escrita ao mesmo tempo (offline, em regiões diferentes, durante uma partição), elas divergem. Normalmente alguém precisa resolver o conflito com last-write-wins, que perde dados, ou com código manual. Os **CRDTs** (Conflict-free Replicated Data Types) são estruturas de dados projetadas de modo que réplicas possam receber atualizações em qualquer ordem, duplicadas e atrasadas, e mesmo assim **convergir automaticamente** para o mesmo estado, sem coordenação.

## A ideia matemática

Para convergir, a operação de mesclar estados precisa ser:

- **Comutativa:** mesclar A com B dá o mesmo que B com A.
- **Associativa:** a ordem de agrupamento não importa.
- **Idempotente:** mesclar o mesmo estado duas vezes não muda nada.

Estados que formam um semirreticulado com essa função de junção (merge) convergem. É o que sustenta a *consistência eventual forte*: quem recebeu o mesmo conjunto de atualizações tem o mesmo estado.

## Dois estilos

- **Baseados em estado (CvRDT):** as réplicas trocam o estado inteiro (ou deltas) e aplicam merge.
- **Baseados em operações (CmRDT):** trocam operações, que precisam ser comutativas e entregues sem perda (muitas vezes com entrega causal).

## Exemplos clássicos

**G-Counter (contador que só cresce):** cada réplica tem sua posição em um vetor; incrementa apenas a sua. O valor é a soma, o merge é o máximo posição a posição.

```python
class GCounter:
    def __init__(self, id_no):
        self.id = id_no
        self.v = {}

    def incrementar(self, n=1):
        self.v[self.id] = self.v.get(self.id, 0) + n

    def valor(self):
        return sum(self.v.values())

    def merge(self, outro):
        for no, c in outro.v.items():
            self.v[no] = max(self.v.get(no, 0), c)
```

```javascript
class GCounter {
```

```java
import java.util.*;

class GCounter {
    private final String id;
    private final Map<String, Integer> v = new HashMap<>();

    GCounter(String idNo) {
        this.id = idNo;
    }

    void incrementar(int n) {
        v.merge(id, n, Integer::sum);
    }

    int valor() {
        int soma = 0;
        for (int c : v.values()) soma += c;
        return soma;
    }

    void merge(GCounter outro) {
        for (Map.Entry<String, Integer> e : outro.v.entrySet()) {
            v.merge(e.getKey(), e.getValue(), Math::max);
        }
    }
}
```

```csharp
using System;
using System.Collections.Generic;
using System.Linq;

class GCounter
{
    private readonly string id;
    private readonly Dictionary<string, int> v = new Dictionary<string, int>();

    public GCounter(string idNo)
    {
        id = idNo;
    }

    public void Incrementar(int n = 1)
    {
        int atual;
        v.TryGetValue(id, out atual);
        v[id] = atual + n;
    }

    public int Valor()
    {
        return v.Values.Sum();
    }

    public void Merge(GCounter outro)
    {
        foreach (var par in outro.v)
        {
            int atual;
            v.TryGetValue(par.Key, out atual);
            v[par.Key] = Math.Max(atual, par.Value);
        }
    }
}
```

```go
type GCounter struct {
	id string
	v  map[string]int
}

func novoGCounter(idNo string) *GCounter {
	return &GCounter{id: idNo, v: map[string]int{}}
}

func (g *GCounter) incrementar(n int) {
	g.v[g.id] += n
}

func (g *GCounter) valor() int {
	soma := 0
	for _, c := range g.v {
		soma += c
	}
	return soma
}

func (g *GCounter) merge(outro *GCounter) {
	for no, c := range outro.v {
		if c > g.v[no] {
			g.v[no] = c
		}
	}
}
```

**PN-Counter:** dois G-Counters, um para incrementos e outro para decrementos.

**G-Set e OR-Set:** conjunto só de adições, e conjunto que permite remover (cada adição ganha uma etiqueta única; a remoção apaga as etiquetas vistas, e uma adição concorrente sobrevive).

**LWW-Register:** guarda o valor com o maior timestamp. Simples, mas descarta o perdedor.

**Sequências (RGA, Logoot, Yjs, Automerge):** usadas em editores colaborativos; cada caractere tem um identificador único e ordenável.

## Onde são usados

Redis Enterprise (Active-Active), Riak, Azure Cosmos DB em multi-região, contadores de likes, carrinhos de compra e editores como Figma e aplicativos baseados em Yjs ou Automerge.

## Trade-offs

| Vantagem | Custo |
| --- | --- |
| Escrita local, sem coordenação, funciona offline | Estruturas especiais, não se adapta a qualquer dado |
| Convergência garantida | Metadados crescem (tombstones, etiquetas, vetores) |
| Latência baixa multi-região | Semântica nem sempre é a intuitiva (remover versus adicionar concorrente) |
| Sem conflitos para o usuário | Não impõe invariantes globais, como saldo nunca negativo |

<Callout type="warning" title="CRDT não garante invariantes globais">
Dois dispositivos podem decrementar o mesmo estoque localmente e juntos passar de zero. Regras que exigem coordenação, como "não vender além do estoque", precisam de consenso ou de reserva de cotas.
</Callout>
