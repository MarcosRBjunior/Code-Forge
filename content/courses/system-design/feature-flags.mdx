Você terminou metade de uma funcionalidade grande. Se não fizer merge, o branch diverge do `main` por semanas; se fizer, o código incompleto vai para produção. **Feature flags** (ou feature toggles) resolvem esse dilema: o código novo entra em produção desligado, protegido por um `if`, e é ligado depois, para quem você quiser, sem novo deploy.

## A ideia básica

<CodeTabs>

```python
if flags.ativa("novo-checkout", usuario):
    return checkout_v2(carrinho)
return checkout_v1(carrinho)
```

A decisão de qual caminho seguir sai do código e vai para uma configuração que pode mudar em tempo de execução. Com isso você separa **deploy** (o código está lá) de **release** (o usuário vê).

## Tipos de flag

Nem toda flag é igual, e tratá-las da mesma forma gera bagunça:

| Tipo | Para quê | Vida útil | Quem controla |
| --- | --- | --- | --- |
| Release | Esconder funcionalidade incompleta, lançar gradualmente | Dias a semanas | Engenharia |
| Experimento | Teste A/B, comparar variantes | Semanas | Produto, dados |
| Operacional (kill switch) | Desligar algo caro ou instável sob pressão | Longa | Operação |
| Permissão | Liberar recurso para plano pago, beta testers | Permanente | Produto |

Flags de release devem morrer logo depois do lançamento completo. Flags operacionais podem durar anos, por exemplo para desligar recomendações personalizadas quando o banco está sob carga e servir uma lista estática.

## Como avaliar uma flag

Uma regra de flag combina segmentação e porcentagem:

```json
{
  "chave": "novo-checkout",
  "ativa": true,
  "regras": [
    {"se": {"atributo": "email", "termina_com": "@empresa.com"}, "valor": true},
    {"se": {"atributo": "pais", "igual": "BR"}, "porcentagem": 10}
  ],
  "padrao": false
}
```

A porcentagem precisa ser **estável**: o mesmo usuário deve cair sempre no mesmo grupo, senão a experiência muda a cada página. Faça isso com hash determinístico:

<CodeTabs>

```python
import hashlib

def no_rollout(chave_flag: str, user_id: str, porcentagem: int) -> bool:
    h = hashlib.sha256(f"{chave_flag}:{user_id}".encode()).hexdigest()
    balde = int(h[:8], 16) % 100
    return balde < porcentagem
```

    static const uint32_t K[64] = {

        0xa2bfe8a1, 0xa81a664b, 0xc24b8b70, 0xc76c51a3, 0xd192e819, 0xd6990624, 0xf40e3585, 0x106aa070,
        0x19a4c116, 0x1e376c08, 0x2748774c, 0x34b0bcb5, 0x391c0cb3, 0x4ed8aa4a, 0x5b9cca4f, 0x682e6ff3,
        0x748f82ee, 0x78a5636f, 0x84c87814, 0x8cc70208, 0x90befffa, 0xa4506ceb, 0xbef9a3f7, 0xc67178f2};
    uint32_t h[8] = {0x6a09e667, 0xbb67ae85, 0x3c6ef372, 0xa54ff53a, 0x510e527f, 0x9b05688c, 0x1f83d9ab, 0x5be0cd19};
    string m = msg;
    uint64_t bits = (uint64_t)msg.size() * 8;
    m += (char)0x80;
    while (m.size() % 64 != 56) m += (char)0;
    for (int i = 7; i >= 0; i--) m += (char)(bits >> (i * 8));
    auto rotr = [](uint32_t x, int n) { return (x >> n) | (x << (32 - n)); };
    for (size_t off = 0; off < m.size(); off += 64) {
        uint32_t w[64];
        for (int i = 0; i < 16; i++) {
            w[i] = ((uint32_t)(uint8_t)m[off + 4 * i] << 24) | ((uint32_t)(uint8_t)m[off + 4 * i + 1] << 16) |
                   ((uint32_t)(uint8_t)m[off + 4 * i + 2] << 8) | (uint32_t)(uint8_t)m[off + 4 * i + 3];
        }
        for (int i = 16; i < 64; i++) {
            uint32_t s0 = rotr(w[i - 15], 7) ^ rotr(w[i - 15], 18) ^ (w[i - 15] >> 3);
            uint32_t s1 = rotr(w[i - 2], 17) ^ rotr(w[i - 2], 19) ^ (w[i - 2] >> 10);
            w[i] = w[i - 16] + s0 + w[i - 7] + s1;
        }
        uint32_t a = h[0], b = h[1], c = h[2], d = h[3], e = h[4], f = h[5], g = h[6], hh = h[7];
        for (int i = 0; i < 64; i++) {
            uint32_t t1 = hh + (rotr(e, 6) ^ rotr(e, 11) ^ rotr(e, 25)) + ((e & f) ^ (~e & g)) + K[i] + w[i];
            uint32_t t2 = (rotr(a, 2) ^ rotr(a, 13) ^ rotr(a, 22)) + ((a & b) ^ (a & c) ^ (b & c));
            hh = g; g = f; f = e; e = d + t1; d = c; c = b; b = a; a = t1 + t2;
        }
        h[0] += a; h[1] += b; h[2] += c; h[3] += d; h[4] += e; h[5] += f; h[6] += g; h[7] += hh;
    }
    string out;
    for (int i = 0; i < 8; i++) for (int j = 3; j >= 0; j--) out += (char)(h[i] >> (j * 8));
    return out;
}

    for (unsigned char c : bytes) { r += d[c >> 4]; r += d[c & 15]; }

func noRollout(chaveFlag, userID string, porcentagem int) bool {
	soma := sha256.Sum256([]byte(chaveFlag + ":" + userID))

}

Incluir a chave da flag no hash evita que os mesmos 10% de usuários sejam sempre as cobaias de todas as flags. E aumentar a porcentagem de 10 para 20 mantém os 10% iniciais dentro, porque o balde de cada usuário não muda.

## Arquitetura de um serviço de flags

```text
[console de flags] -> [serviço de flags + banco] --stream/poll--> [SDK no serviço A]
                                                              --> [SDK no serviço B]
```

- O SDK mantém as regras **em memória** e avalia localmente. Consultar um serviço remoto a cada `if` adicionaria latência e um ponto de falha em todo caminho crítico.
- Atualizações chegam por streaming (SSE) ou polling a cada poucos segundos.
- **Valor padrão seguro:** se o SDK não conseguir carregar as regras, cada flag cai no valor definido no código, normalmente o comportamento antigo.
- **Auditoria:** quem mudou o quê e quando. Muitos incidentes são uma flag alterada por engano, e o histórico encurta a investigação.

Em apps móveis e frontends, a avaliação costuma ocorrer no servidor, que devolve só os resultados, para não expor regras internas nem nomes de funcionalidades não lançadas.

## Armadilhas

- **Dívida de flags:** centenas de flags velhas, ninguém sabe quais ainda importam, e o código vira um labirinto de `if`. Defina dono e data de expiração ao criar cada flag, e remova o código morto depois do lançamento.
- **Combinações não testadas:** com 10 flags, existem 1.024 combinações. Teste as combinações relevantes, principalmente "tudo novo ligado" e "tudo desligado".
- **Flags que mudam schema ou contratos:** a flag desligada não desfaz uma migração que já rodou. Flags controlam comportamento, não estrutura de dados.
- **Flag reaproveitada:** reutilizar uma chave antiga com outro significado já causou incidentes sérios na indústria, quando servidores com código antigo interpretaram a flag reativada da forma antiga.

<Callout type="tip" title="Kill switch é ferramenta de confiabilidade">
Coloque flags operacionais em dependências não essenciais: recomendações, busca sugerida, enriquecimento de dados. Quando um desses componentes degrada, desligar a flag preserva o fluxo principal em segundos, sem deploy.
</Callout>

## Na entrevista

Feature flags aparecem quando o entrevistador pergunta sobre lançamentos seguros ou degradação controlada. Mostre a separação entre deploy e release, a avaliação local no SDK com valor padrão seguro e o rollout por hash estável. Follow-ups: como evitar latência na avaliação, o que acontece se o serviço de flags cair e como limpar flags antigas.
