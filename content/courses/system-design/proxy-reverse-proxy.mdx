---
title: Proxy e proxy reverso
kind: lesson
---

Um **proxy** é um intermediário: recebe uma requisição, decide o que fazer com ela e a repassa a outro destino. A diferença entre os dois tipos está em **quem ele representa**. O proxy direto (forward proxy) age em nome dos clientes; o proxy reverso age em nome dos servidores.

## Proxy direto (forward proxy)

Fica do lado do cliente. Os clientes são configurados para mandar suas requisições a ele, e ele sai para a internet em nome deles. O servidor de destino vê o IP do proxy, não o do cliente.

```text
[cliente A] \
[cliente B] -- [forward proxy] ---- internet ---- [site externo]
[cliente C] /
```

Usos típicos:

- **Controle de saída** em empresas: bloquear categorias de sites, registrar acessos.
- **Cache compartilhado** de conteúdo externo para economizar banda.
- **Anonimato** ou contornar restrições geográficas.
- **Egress controlado** em infraestrutura: servidores numa rede privada só falam com APIs externas através de um proxy que aplica allowlist de destinos.

## Proxy reverso

Fica do lado do servidor. Os clientes acham que estão falando com o servidor final; na verdade falam com o proxy, que escolhe para qual backend encaminhar. Os backends ficam escondidos na rede interna.

```text
                                 /-- [app 1]
[clientes] -- internet -- [proxy reverso] --- [app 2]
                                 \-- [serviço de imagens]
```

Usos típicos:

- **Balanceamento de carga** entre várias instâncias.
- **Terminação de TLS:** o proxy cuida dos certificados e da criptografia, liberando os backends.
- **Roteamento por caminho ou host:** `/api` vai para um serviço, `/static` para outro.
- **Cache** de respostas e servir arquivos estáticos.
- **Compressão** das respostas.
- **Segurança:** esconder a topologia interna, aplicar WAF, limitar taxa, absorver conexões lentas (o proxy segura clientes lentos e libera o backend rapidamente).
- **Autenticação centralizada** antes de chegar aos serviços.

Exemplos: Nginx, HAProxy, Envoy, Traefik e balanceadores gerenciados de nuvem. Um **API gateway** é essencialmente um proxy reverso especializado em APIs, com autenticação, quotas e transformação de requisições.

## Configuração de exemplo

Um Nginx que termina TLS e distribui entre duas instâncias:

```text
upstream app {
    server 10.0.1.11:8080;
    server 10.0.1.12:8080;
}

server {
    listen 443 ssl;
    server_name loja.com;
    ssl_certificate     /etc/ssl/loja.crt;
    ssl_certificate_key /etc/ssl/loja.key;

    location /static/ {
        root /var/www;
        expires 7d;
    }

    location / {
        proxy_pass http://app;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
    }
}
```

Repare nos cabeçalhos `X-Forwarded-For` e `X-Forwarded-Proto`: como o backend recebe a conexão do proxy, ele perderia o IP real do cliente e o fato de a requisição original ser HTTPS. O proxy repassa essas informações em cabeçalhos (o padrão mais novo é o cabeçalho `Forwarded`).

## Comparação

| Aspecto | Proxy direto | Proxy reverso |
| --- | --- | --- |
| Representa | clientes | servidores |
| Quem configura | rede ou cliente | dono do serviço |
| O que esconde | identidade dos clientes | topologia dos servidores |
| Usos | filtragem, cache de saída, egress | balanceamento, TLS, cache, roteamento |

## Trade-offs e armadilhas

- **Mais um salto:** cada proxy adiciona um pouco de latência e um componente para operar.
- **Ponto único de falha:** um proxy reverso sozinho na frente de tudo derruba o sistema se cair. Rode várias instâncias.
- **Confiança em cabeçalhos:** só confie em `X-Forwarded-For` vindo do seu próprio proxy. Se o backend aceitar o cabeçalho de qualquer origem, um cliente pode forjar o IP.
- **Timeouts encadeados:** o timeout do proxy precisa ser coerente com o do backend, senão o cliente recebe 504 enquanto o backend ainda trabalha.

<Callout type="tip" title="Na entrevista">
Quase todo desenho tem um proxy reverso, mesmo que você o chame de load balancer ou API gateway. Diga quais responsabilidades ele assume (TLS, roteamento, rate limiting, cache) para que os serviços fiquem simples. Follow-up comum: "qual a diferença entre load balancer, proxy reverso e API gateway?" (o load balancer é um caso de proxy reverso focado em distribuir carga; o gateway adiciona funções de gestão de API).
</Callout>
