Imagine a tela inicial de um app de streaming: dados do usuário, lista "continuar assistindo" com progresso, recomendações com capa e nota. Com REST, ou você faz várias chamadas sequenciais (lento em rede móvel), ou cria um endpoint específico para essa tela (que vira manutenção a cada mudança de layout). E cada endpoint devolve campos que a tela nem usa. O **GraphQL**, criado no Facebook e aberto em 2015, inverte a responsabilidade: o **cliente** descreve o formato exato dos dados de que precisa, e o servidor monta a resposta.

## Como funciona

O servidor publica um **schema** tipado que descreve tipos e relacionamentos. Há três tipos de operação:

- **Query:** leitura.
- **Mutation:** escrita.
- **Subscription:** fluxo de eventos em tempo real, normalmente sobre WebSocket.

```text
type Usuario {
  id: ID!
  nome: String!
  assistindo: [Progresso!]!
}

type Progresso {
  titulo: Titulo!
  percentual: Int!
}

type Titulo {
  id: ID!
  nome: String!
  capaUrl: String
}

type Query {
  usuario(id: ID!): Usuario
}
```

O cliente envia, em geral via `POST /graphql`, uma consulta com exatamente os campos desejados:

```text
query TelaInicial {
  usuario(id: "42") {
    nome
    assistindo {
      percentual
      titulo { nome capaUrl }
    }
  }
}
```

A resposta espelha a forma da consulta, dentro de um objeto `data`. Erros vêm num array `errors` ao lado, e a resposta pode ser parcial: alguns campos resolvidos, outros com erro, ainda com status HTTP 200.

## Resolvers e o problema N+1

Cada campo do schema tem um **resolver**, uma função que sabe buscar aquele dado. O servidor percorre a consulta chamando resolvers. Isso é flexível, mas esconde uma armadilha: se `usuario.assistindo` devolve 20 itens e o resolver de `titulo` faz uma consulta por item, você tem 1 + 20 consultas ao banco.

A solução padrão é o **DataLoader**: dentro de uma requisição, ele acumula as chaves pedidas no mesmo ciclo e faz uma única busca em lote.

```python
class TituloLoader:
    def __init__(self, repo):
        self.repo = repo
        self.pendentes = []

    def carregar(self, titulo_id):
        self.pendentes.append(titulo_id)

    def despachar(self):
        ids = list(set(self.pendentes))
        self.pendentes = []
        linhas = self.repo.buscar_por_ids(ids)  # um único SELECT ... WHERE id IN (...)
        return {t.id: t for t in linhas}
```

```java
import java.util.*;

class Titulo {
    int id;
    String nome;
    Titulo(int id, String nome) { this.id = id; this.nome = nome; }
}

interface Repo {
    List<Titulo> buscarPorIds(List<Integer> ids);
}

class TituloLoader {
    private final Repo repo;
    private List<Integer> pendentes = new ArrayList<>();

    TituloLoader(Repo repo) {
        this.repo = repo;
    }

    void carregar(int tituloId) {
        pendentes.add(tituloId);
    }

    Map<Integer, Titulo> despachar() {
        List<Integer> ids = new ArrayList<>(new LinkedHashSet<>(pendentes));
        pendentes = new ArrayList<>();
        List<Titulo> linhas = repo.buscarPorIds(ids); // um único SELECT ... WHERE id IN (...)
        Map<Integer, Titulo> mapa = new HashMap<>();
        for (Titulo t : linhas) mapa.put(t.id, t);
        return mapa;
    }
}

public static void main(String[] args) {
    // peça de apoio do exemplo: um repositório que conta as consultas
    int[] consultas = {0};
    Repo repo = ids -> {
        consultas[0]++;
        List<Titulo> r = new ArrayList<>();
        for (int id : ids) r.add(new Titulo(id, "titulo-" + id));
        return r;
    };
    TituloLoader loader = new TituloLoader(repo);
    for (int id : new int[]{1, 2, 1, 3, 2}) loader.carregar(id);
    Map<Integer, Titulo> resultado = loader.despachar();
    System.out.println(resultado.size() + " " + consultas[0]);
}
```

```cpp
#include <functional>
#include <iostream>
#include <map>
#include <set>
#include <string>
#include <vector>
using namespace std;

struct Titulo {
    int id;
    string nome;
};

class TituloLoader {
public:
    using Repo = function<vector<Titulo>(const vector<int>&)>;

    explicit TituloLoader(Repo repo) : repo(repo) {}

    void carregar(int tituloId) {
        pendentes.push_back(tituloId);
    }

    map<int, Titulo> despachar() {
        set<int> unicos(pendentes.begin(), pendentes.end());
        vector<int> ids(unicos.begin(), unicos.end());
        pendentes.clear();
        vector<Titulo> linhas = repo(ids); // um único SELECT ... WHERE id IN (...)
        map<int, Titulo> mapa;
        for (const auto& t : linhas) mapa[t.id] = t;
        return mapa;
    }

private:
    Repo repo;
    vector<int> pendentes;
};

int main() {
    // peça de apoio do exemplo: um repositório que conta as consultas
    int consultas = 0;
    TituloLoader loader([&](const vector<int>& ids) {
        consultas++;
        vector<Titulo> r;
        for (int id : ids) r.push_back({id, "titulo-" + to_string(id)});
        return r;
    });
    for (int id : {1, 2, 1, 3, 2}) loader.carregar(id);
    auto resultado = loader.despachar();
    cout << resultado.size() << " " << consultas << endl;
}
```

```csharp
using System;
using System.Collections.Generic;
using System.Linq;

class Titulo
{
    public int Id;
    public string Nome;
}

class TituloLoader
{
    private readonly Func<List<int>, List<Titulo>> repo;
    private List<int> pendentes = new List<int>();

    public TituloLoader(Func<List<int>, List<Titulo>> repo)
    {
        this.repo = repo;
    }

    public void Carregar(int tituloId)
    {
        pendentes.Add(tituloId);
    }

    public Dictionary<int, Titulo> Despachar()
    {
        var ids = pendentes.Distinct().ToList();
        pendentes = new List<int>();
        var linhas = repo(ids); // um único SELECT ... WHERE id IN (...)
        return linhas.ToDictionary(t => t.Id, t => t);
    }
}

static void Main()
{
    // peça de apoio do exemplo: um repositório que conta as consultas
    int consultas = 0;
    var loader = new TituloLoader(ids =>
    {
        consultas++;
        return ids.Select(id => new Titulo { Id = id, Nome = "titulo-" + id }).ToList();
    });
    foreach (var id in new[] { 1, 2, 1, 3, 2 }) loader.Carregar(id);
    var resultado = loader.Despachar();
    Console.WriteLine(resultado.Count + " " + consultas);
}
```

```go
package main

import "fmt"

type Titulo struct {
	id   int
	nome string
}

type Repo interface {
	buscarPorIDs(ids []int) []Titulo
}

type TituloLoader struct {
	repo      Repo
	pendentes []int
}

func (l *TituloLoader) carregar(tituloID int) {
	l.pendentes = append(l.pendentes, tituloID)
}

func (l *TituloLoader) despachar() map[int]Titulo {
	vistos := map[int]bool{}
	ids := []int{}
	for _, id := range l.pendentes {
		if !vistos[id] {
			vistos[id] = true
			ids = append(ids, id)
		}
	}
	l.pendentes = nil
	linhas := l.repo.buscarPorIDs(ids) // um único SELECT ... WHERE id IN (...)
	mapa := map[int]Titulo{}
	for _, t := range linhas {
		mapa[t.id] = t
	}
	return mapa
}

// peça de apoio do exemplo: um repositório que conta as consultas
type RepoFalso struct{ consultas int }

func (r *RepoFalso) buscarPorIDs(ids []int) []Titulo {
	r.consultas++
	out := []Titulo{}
	for _, id := range ids {
		out = append(out, Titulo{id, fmt.Sprintf("titulo-%d", id)})
	}
	return out
}

func main() {
	repo := &RepoFalso{}
	loader := &TituloLoader{repo: repo}
	for _, id := range []int{1, 2, 1, 3, 2} {
		loader.carregar(id)
	}
	resultado := loader.despachar()
	fmt.Println(len(resultado), repo.consultas)
}
```

## Vantagens

- **Sem over-fetching nem under-fetching:** uma requisição, só os campos necessários.
- **Schema como contrato:** tipado, introspectável, gera documentação e código de cliente.
- **Evolução sem versões:** adiciona-se campos livremente e marca-se antigos com `@deprecated`, acompanhando quem ainda os usa.
- **Agregação:** um servidor GraphQL pode unificar vários microsserviços (padrão comum de BFF ou federação).

## Desvantagens e cuidados

| Problema | Por quê | Mitigação |
| --- | --- | --- |
| Cache HTTP difícil | Tudo vai em POST para uma URL | Persisted queries via GET, cache por campo no cliente |
| Consultas abusivas | Aninhamento profundo explode o custo | Limite de profundidade, análise de custo, timeout |
| N+1 no backend | Resolvers por campo | DataLoader e batching |
| Rate limiting | Uma requisição pode valer 1 ou 10 mil operações | Limitar por custo calculado, não por chamada |
| Monitoramento | Tudo retorna 200 | Métricas por operação e por resolver |

<Callout type="tip" title="Persisted queries">
Em apps próprios, registre as consultas permitidas no build e envie só um hash. O servidor recusa consultas desconhecidas, o que fecha a porta para abuso e permite usar GET com cache em CDN.
</Callout>

## Quando usar

GraphQL vale a pena quando há **muitos clientes diferentes** (web, iOS, Android, TV) consumindo os mesmos dados com necessidades distintas, telas ricas que combinam várias entidades, e times de frontend que evoluem rápido. Para APIs públicas simples, CRUD direto ou comunicação entre serviços de backend, REST ou gRPC costumam ser mais simples e baratos de operar.

## Na entrevista

Se o problema tiver um feed ou tela agregadora com vários tipos de cliente, GraphQL é uma boa proposta para a camada de borda. Mostre que conhece os custos: N+1 e DataLoader, limitação por complexidade de consulta e a perda do cache HTTP nativo. Follow-ups comuns: como fazer rate limiting em GraphQL, como lidar com erros parciais e como fazer subscriptions escalarem.
