Log é o diário do sistema: cada linha registra que algo aconteceu, quando e em que contexto. Parece trivial, mas logs mal projetados são uma fonte clássica de dor: ruído que esconde o erro real, dados sensíveis vazando, discos cheios e custos astronômicos. O objetivo é registrar o suficiente para reconstruir o que houve, sem afogar o time.

## Níveis de log

| Nível | Uso | Exemplo |
| --- | --- | --- |
| DEBUG | Detalhe para desenvolvedores, normalmente desligado em produção | Valor de uma variável intermediária |
| INFO | Marcos normais do negócio | Pedido 123 criado |
| WARN | Algo inesperado, mas recuperável | Retry na chamada ao gateway de pagamento |
| ERROR | Operação falhou | Falha ao gravar pedido |
| FATAL | O processo não consegue continuar | Sem acesso ao banco na inicialização |

O nível deve ser configurável em tempo de execução, para você ligar DEBUG num serviço durante uma investigação sem fazer deploy.

## Logs estruturados

Texto livre é fácil de escrever e difícil de consultar. Prefira JSON, com campos nomeados:

```json
{
  "ts": "2026-10-30T14:03:22.114Z",
  "nivel": "ERROR",
  "servico": "checkout",
  "trace_id": "9f3a1c",
  "pedido_id": 4821,
  "msg": "falha ao autorizar pagamento",
  "erro": "timeout",
  "duracao_ms": 3000
}
```

Agora é possível filtrar por `servico`, somar por `erro` ou seguir um `trace_id` entre serviços. Em Python:

<CodeTabs>

```python
import json, logging, sys

class JsonFormatter(logging.Formatter):
    def format(self, r):
        base = {"nivel": r.levelname, "msg": r.getMessage()}
        base.update(getattr(r, "ctx", {}))
        return json.dumps(base, ensure_ascii=False)

log = logging.getLogger("checkout")
h = logging.StreamHandler(sys.stdout)
h.setFormatter(JsonFormatter())
log.addHandler(h)
log.setLevel(logging.INFO)

log.info("pedido criado", extra={"ctx": {"pedido_id": 4821}})
```

```java
import java.util.*;

// formatador JSON: cada linha de log vira um objeto com campos pesquisáveis
static String formatar(String nivel, String msg, Map<String, Object> ctx) {
    Map<String, Object> base = new LinkedHashMap<>();
    base.put("nivel", nivel);
    base.put("msg", msg);
    base.putAll(ctx);
    StringBuilder sb = new StringBuilder("{");
    boolean primeiro = true;
    for (Map.Entry<String, Object> e : base.entrySet()) {
        if (!primeiro) sb.append(", ");
        primeiro = false;
        sb.append("\"").append(e.getKey()).append("\": ");
        if (e.getValue() instanceof Number) sb.append(e.getValue());
        else sb.append("\"").append(e.getValue()).append("\"");
    }
    return sb.append("}").toString();
}

static void info(String msg, Map<String, Object> ctx) {
    System.out.println(formatar("INFO", msg, ctx));
}

public static void main(String[] args) {
    Map<String, Object> ctx = new LinkedHashMap<>();
    ctx.put("pedido_id", 4821);
    info("pedido criado", ctx);
}
```

```cpp
#include <iostream>
#include <string>
#include <utility>
#include <vector>
using namespace std;

// formatador JSON: cada linha de log vira um objeto com campos pesquisáveis
// (campos numéricos entram sem aspas)
using Campo = pair<string, string>;

string formatar(const string& nivel, const string& msg, const vector<Campo>& ctx, const vector<string>& numericos) {
    string saida = "{\"nivel\": \"" + nivel + "\", \"msg\": \"" + msg + "\"";
    for (const auto& [chave, valor] : ctx) {
        bool numero = false;
        for (const auto& n : numericos) if (n == chave) numero = true;
        saida += ", \"" + chave + "\": " + (numero ? valor : "\"" + valor + "\"");
    }
    return saida + "}";
}

void info(const string& msg, const vector<Campo>& ctx, const vector<string>& numericos = {}) {
    cout << formatar("INFO", msg, ctx, numericos) << endl;
}

int main() {
    info("pedido criado", {{"pedido_id", "4821"}}, {"pedido_id"});
}
```

```csharp
using System;
using System.Collections.Generic;
using System.Text;

// formatador JSON: cada linha de log vira um objeto com campos pesquisáveis
static string Formatar(string nivel, string msg, Dictionary<string, object> ctx)
{
    var campos = new List<KeyValuePair<string, object>>();
    campos.Add(new KeyValuePair<string, object>("nivel", nivel));
    campos.Add(new KeyValuePair<string, object>("msg", msg));
    foreach (var kv in ctx) campos.Add(kv);

    var sb = new StringBuilder("{");
    for (int i = 0; i < campos.Count; i++)
    {
        if (i > 0) sb.Append(", ");
        sb.Append("\"" + campos[i].Key + "\": ");
        if (campos[i].Value is int) sb.Append(campos[i].Value);
        else sb.Append("\"" + campos[i].Value + "\"");
    }
    return sb.Append("}").ToString();
}

static void Info(string msg, Dictionary<string, object> ctx)
{
    Console.WriteLine(Formatar("INFO", msg, ctx));
}

static void Main()
{
    Info("pedido criado", new Dictionary<string, object> { { "pedido_id", 4821 } });
}
```

## Boas práticas

- **Escreva em stdout** em ambientes de contêiner e deixe a plataforma coletar. A aplicação não deve gerenciar rotação de arquivos.
- **Inclua contexto de correlação:** trace_id, id do pedido e id do usuário (quando permitido).
- **Uma mensagem estável e campos variáveis.** Em vez de interpolar o id na frase, use um campo, para agrupar eventos iguais.
- **Nunca registre segredos ou dados pessoais:** senhas, tokens, números de cartão, CPF. Mascare ou omita. Isso também é exigência da LGPD.
- **Não logue no caminho quente sem critério:** milhares de linhas por segundo custam CPU e I/O. Use amostragem para eventos repetitivos.
- **Registre o erro uma vez**, no ponto em que é tratado, com o stack trace. Logar e relançar em todas as camadas duplica o ruído.

## Armadilhas comuns

- Logar objetos inteiros por preguiça, vazando campos sensíveis.
- Usar ERROR para tudo, o que mata a confiança nos alertas.
- Depender de logs para contar eventos de negócio. Para isso, métricas são mais baratas e confiáveis.
- Logs síncronos que bloqueiam a requisição quando o disco ou a rede estão lentos. Prefira bufferização assíncrona.

<Callout type="warning" title="Logs viram dados regulados">
Um log com e-mail ou CPF é um repositório de dados pessoais, sujeito a retenção, acesso restrito e pedidos de exclusão. Defina o que pode ser registrado antes de o sistema ir ao ar.
</Callout>

## Na entrevista

Diga que usa logs estruturados, com níveis e trace_id, enviados para um agregador central (próximo capítulo). Follow-ups: "como correlaciona logs entre serviços?" (propagar um id de requisição em cabeçalho) e "como evita vazar dados sensíveis?" (filtros de mascaramento e revisão de campos).
