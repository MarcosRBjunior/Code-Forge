Navios são divididos em compartimentos estanques, as anteparas (bulkheads, em inglês). Se o casco é furado, só um compartimento alaga e o navio continua flutuando. Em software, a ideia é a mesma: **isolar recursos em compartimentos** para que a falha ou a sobrecarga de uma parte não afunde o sistema inteiro.

## O problema

Seu serviço de checkout usa um único pool de 200 threads para atender requisições e chamar três dependências: estoque, pagamentos e cupons. O serviço de cupons fica lento. Cada requisição que precisa de cupom segura uma thread por 30 segundos. Em pouco tempo, as 200 threads estão todas esperando cupons, e o checkout não consegue mais processar **nada**, nem as compras sem cupom. Uma dependência secundária derrubou a função principal.

Repare que um circuit breaker ajuda, mas só depois de detectar a falha. O bulkhead limita o estrago **desde o primeiro segundo**.

## Como aplicar

```text
Sem bulkhead                          Com bulkhead

+---------------------------+         +---------+ +---------+ +---------+
| pool único: 200 threads   |         | estoque | | pagam.  | | cupons  |
| (cupons lento consome     |         | 80      | | 80      | | 20      |
|  todas)                   |         | threads | | threads | | threads |
+---------------------------+         +---------+ +---------+ +---------+
                                       cupons lento esgota só os 20 dele
```

O isolamento pode acontecer em vários níveis:

- **Pools de threads separados** por dependência. Cada chamada externa roda no pool dela; se o pool encher, a chamada é rejeitada na hora.
- **Semáforos:** em vez de threads dedicadas, um contador limita quantas chamadas simultâneas podem estar em andamento para aquela dependência. Mais leve, ideal para código assíncrono.
- **Pools de conexões separados:** um pool de conexões ao banco para leituras de relatório e outro para transações, assim um relatório pesado não esgota as conexões do checkout.
- **Instâncias separadas por tipo de cliente:** um cluster para tráfego de clientes pagantes e outro para o tráfego gratuito ou para jobs em lote.
- **Isolamento por inquilino ou célula:** arquitetura celular, em que cada célula atende um subconjunto de clientes com infraestrutura própria. Um bug acionado por um cliente afeta só a célula dele.

```python
import asyncio

class Bulkhead:
    def __init__(self, max_concorrentes):
        self.sem = asyncio.Semaphore(max_concorrentes)

    async def executar(self, coro_func, *args):
        if self.sem.locked():
            raise RuntimeError("bulkhead cheio, rejeitando")
        async with self.sem:
            return await coro_func(*args)

bulkhead_cupons = Bulkhead(max_concorrentes=20)
bulkhead_pagamentos = Bulkhead(max_concorrentes=80)
```

class Bulkhead {
  constructor(maxConcorrentes) {
    this.livres = maxConcorrentes;
  }

  async executar(funcao, ...args) {
    if (this.livres === 0) {
      throw new Error("bulkhead cheio, rejeitando");
    }
    this.livres -= 1;
    try {
      return await funcao(...args);
    } finally {
      this.livres += 1;
    }
  }
}

const bulkheadCupons = new Bulkhead(20);
const bulkheadPagamentos = new Bulkhead(80);

```java
import java.util.concurrent.Callable;
import java.util.concurrent.Semaphore;

class Bulkhead {
    private final Semaphore sem;

    Bulkhead(int maxConcorrentes) {
        this.sem = new Semaphore(maxConcorrentes);
    }

    <T> T executar(Callable<T> funcao) throws Exception {
        if (!sem.tryAcquire()) { // não espera: rejeita na hora
            throw new IllegalStateException("bulkhead cheio, rejeitando");
        }
        try {
            return funcao.call();
        } finally {
            sem.release();
        }
    }
}

static final Bulkhead bulkheadCupons = new Bulkhead(20);
static final Bulkhead bulkheadPagamentos = new Bulkhead(80);
```

#include <atomic>
#include <functional>
#include <stdexcept>
using namespace std;

class Bulkhead {
    atomic<int> livres;

public:
    Bulkhead(int maxConcorrentes) : livres(maxConcorrentes) {}

    template <typename T>
    T executar(function<T()> funcao) {
        if (livres.fetch_sub(1) <= 0) { // não espera: rejeita na hora
            livres.fetch_add(1);
            throw runtime_error("bulkhead cheio, rejeitando");
        }
        struct Libera {
            atomic<int>& livres;
            ~Libera() { livres.fetch_add(1); }
        } libera{livres};
        return funcao();
    }
};

Bulkhead bulkheadCupons(20);
Bulkhead bulkheadPagamentos(80);

using System;
using System.Threading;

class Bulkhead
{
    private readonly SemaphoreSlim sem;

    public Bulkhead(int maxConcorrentes)
    {
        sem = new SemaphoreSlim(maxConcorrentes);
    }

    public T Executar<T>(Func<T> funcao)
    {
        if (!sem.Wait(0)) // não espera: rejeita na hora
        {
            throw new InvalidOperationException("bulkhead cheio, rejeitando");
        }
        try
        {
            return funcao();
        }
        finally
        {
            sem.Release();
        }
    }
}

static readonly Bulkhead bulkheadPagamentos = new Bulkhead(80);

```go
import "errors"

type Bulkhead struct {
	vagas chan struct{}
}

func NovoBulkhead(maxConcorrentes int) *Bulkhead {
	return &Bulkhead{vagas: make(chan struct{}, maxConcorrentes)}
}

func (b *Bulkhead) executar(funcao func() error) error {
	select {
	case b.vagas <- struct{}{}: // pegou uma vaga
		defer func() { <-b.vagas }()
		return funcao()
	default: // não espera: rejeita na hora
		return errors.New("bulkhead cheio, rejeitando")
	}
}

var bulkheadCupons = NovoBulkhead(20)
var bulkheadPagamentos = NovoBulkhead(80)
```

Quando os 20 slots de cupons estão ocupados, a chamada seguinte falha imediatamente, e o checkout pode seguir sem aplicar o cupom, ou pedir que o usuário tente de novo. Os slots de pagamentos continuam livres.

## Dimensionamento

Uma referência útil é a lei de Little: concorrência necessária ≈ taxa de chegada × latência. Se a dependência recebe 100 req/s com latência normal de 100 ms, você precisa de cerca de 10 chamadas simultâneas. Dê uma folga (por exemplo, 2 a 3 vezes) e pronto. Se a latência explodir para 30 s, a concorrência necessária iria a 3 mil, e o bulkhead corta isso em 20 ou 30, que é exatamente o objetivo.

## Trade-offs

| Vantagem | Custo |
| --- | --- |
| Falhas ficam contidas | Recursos ociosos em compartimentos pouco usados |
| Funções críticas protegidas | Mais parâmetros para calibrar |
| Comportamento previsível sob carga | Rejeições quando o compartimento enche |

<Callout type="warning" title="Compartimentos pequenos demais">
Um bulkhead subdimensionado rejeita tráfego legítimo em horário de pico, causando falhas que não existiriam sem ele. Monitore a taxa de rejeição de cada compartimento e ajuste com dados reais.
</Callout>

## Na entrevista

Ao falar de resiliência, apresente bulkhead junto com timeout e circuit breaker: o timeout limita quanto tempo você espera, o bulkhead limita quantos recursos você arrisca, e o breaker decide quando parar de tentar. Mencione também isolamento em nível de infraestrutura, como clusters separados para tráfego crítico e não crítico. Follow-ups comuns: "como dimensionar os pools?", "o que fazer quando o compartimento enche?", "o que é arquitetura celular?".
