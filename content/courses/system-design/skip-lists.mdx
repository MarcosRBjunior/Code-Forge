Uma lista encadeada ordenada tem busca em tempo linear: para achar um elemento, você caminha nó a nó. Uma árvore balanceada resolve em log n, mas manter o balanceamento (rotações) é complexo, especialmente com concorrência. A **skip list** consegue busca, inserção e remoção em **O(log n) esperado** usando apenas listas encadeadas e uma moeda.

## A estrutura

Imagine várias camadas de listas ordenadas empilhadas. A camada 0 contém todos os elementos. Cada camada acima contém, em média, metade dos elementos da camada abaixo, funcionando como "pistas expressas":

```text
nível 3:  1 ---------------------------------> 50
nível 2:  1 --------> 17 ------------------> 50
nível 1:  1 ----> 9 -> 17 ----> 33 -------> 50
nível 0:  1 -> 5 -> 9 -> 17 -> 25 -> 33 -> 42 -> 50
```

## Busca

Comece no nível mais alto, no primeiro nó. Avance para a direita enquanto o próximo valor for menor que o procurado; quando não puder, desça um nível. Repita até o nível 0. Para achar 33: do nível 3 pule para o nível 2 (17), depois nível 1 (33). Poucos passos em vez de percorrer tudo.

## Inserção

1. Faça a busca registrando em cada nível o último nó visitado antes do ponto de inserção.
2. Sorteie a altura do novo nó: comece em 1 e, enquanto uma moeda der cara (probabilidade p, geralmente 1/2 ou 1/4), aumente a altura.
3. Ligue o nó nas listas dos níveis até a altura sorteada.

```python
import random

def altura_aleatoria(max_nivel=16, p=0.5):
    h = 1
    while random.random() < p and h < max_nivel:
        h += 1
    return h
```

Como a altura é sorteada, não há rotações nem rebalanceamento. A estrutura é balanceada **em probabilidade**, e a chance de ela degenerar de forma relevante é desprezível.

## Por que é popular

- **Simplicidade:** bem menos código que uma árvore rubro-negra ou AVL.
- **Concorrência:** inserir exige alterar poucos ponteiros locais, o que facilita versões lock-free ou com locks finos. Por isso a Java tem `ConcurrentSkipListMap`.
- **Varredura por intervalo:** como a camada 0 é uma lista ordenada, ler um intervalo é caminhar para frente, útil para consultas de faixa.
- **Em memória:** funciona bem para índices e tabelas em RAM.

## Onde aparece

- **Redis Sorted Sets (ZSET):** implementados com skip list mais tabela hash, permitem ranking e consultas por faixa de score em O(log n).
- **MemTable de LSM trees:** LevelDB e RocksDB usam skip list para a tabela em memória que recebe as escritas.
- **Bancos em memória e caches** que precisam de ordenação com concorrência.

## Trade-offs

| Aspecto | Skip list | Árvore balanceada |
| --- | --- | --- |
| Complexidade esperada | O(log n) | O(log n) garantido |
| Implementação | Simples | Rotações complexas |
| Concorrência | Mais fácil | Mais difícil |
| Memória | Ponteiros extras (cerca de 1 a 2 por nó em média) | Dois ponteiros por nó |
| Localidade de cache | Ruim (ponteiros espalhados) | Ruim, melhor em B-trees |
| Em disco | Inadequada | B-trees são a escolha |

<Callout type="note" title="Esperado, não garantido">
O desempenho é probabilístico: em casos muito raros pode ficar pior que log n. Na prática, com muitos elementos, a variação é pequena.
</Callout>
