O geohash divide o mapa numa grade de tamanho fixo: cada célula de 6 caracteres tem o mesmo tamanho no centro de uma metrópole e no meio do oceano. Se um bairro tem 20 mil restaurantes e uma cidade do interior tem 30, uma grade única fica ou grossa demais para o bairro ou fina demais para o interior. A **quadtree** resolve isso com uma divisão **adaptativa**: só subdivide onde há muitos pontos.

## Como funciona

Uma quadtree é uma árvore em que cada nó representa um retângulo do espaço.

- Um nó folha guarda até `capacidade` pontos (por exemplo, 100).
- Quando uma folha passa desse limite, ela se divide em **quatro filhos** iguais: noroeste, nordeste, sudoeste e sudeste. Os pontos são redistribuídos entre eles.
- Regiões vazias continuam como folhas grandes; regiões densas viram árvores profundas.

```text
+---------------+---------------+
|               |       |   |   |
|               |       +---+---+
|   poucos      |       |   |   |
|   pontos      +-------+---+---+
|               |       |       |
|               |       |       |
+---------------+---------------+
|               |               |
|   (vazio)     |   poucos      |
|               |   pontos      |
+---------------+---------------+
o quadrante nordeste, mais denso, foi subdividido duas vezes
```

## Implementação

```python
class Retangulo:
    def __init__(self, x, y, larg, alt):
        self.x, self.y, self.larg, self.alt = x, y, larg, alt

    def contem(self, px, py):
        return self.x <= px < self.x + self.larg and self.y <= py < self.y + self.alt

    def intersecta(self, outro):
        return not (outro.x >= self.x + self.larg or outro.x + outro.larg <= self.x or
                    outro.y >= self.y + self.alt or outro.y + outro.alt <= self.y)


class QuadTree:
    def __init__(self, limite, capacidade=4):
        self.limite = limite
        self.capacidade = capacidade
        self.pontos = []
        self.filhos = None

    def inserir(self, px, py):
        if not self.limite.contem(px, py):
            return False
        if self.filhos is None:
            if len(self.pontos) < self.capacidade:
                self.pontos.append((px, py))
                return True
            self._dividir()
        return any(f.inserir(px, py) for f in self.filhos)

    def _dividir(self):
        x, y = self.limite.x, self.limite.y
        m_l, m_a = self.limite.larg / 2, self.limite.alt / 2
        self.filhos = [QuadTree(Retangulo(x + dx, y + dy, m_l, m_a), self.capacidade)
                       for dx in (0, m_l) for dy in (0, m_a)]
        for p in self.pontos:
            any(f.inserir(*p) for f in self.filhos)
        self.pontos = []

    def buscar(self, area, achados=None):
        achados = [] if achados is None else achados
        if not self.limite.intersecta(area):
            return achados          # poda: subárvore inteira descartada
        achados.extend(p for p in self.pontos if area.contem(*p))
        for f in self.filhos or []:
            f.buscar(area, achados)
        return achados


import random
random.seed(7)
arvore = QuadTree(Retangulo(0, 0, 100, 100))
for _ in range(500):
    arvore.inserir(random.uniform(0, 100), random.uniform(0, 100))
print(len(arvore.buscar(Retangulo(40, 40, 10, 10))), "pontos na janela")
```

A busca por janela é eficiente porque descarta subárvores inteiras cujo retângulo não toca a área procurada. Para "os K mais próximos", explora-se primeiro o nó que contém o ponto e depois os vizinhos, em ordem de distância, até ter K candidatos e nenhum nó restante poder conter algo mais perto.

## Custos

| Operação | Custo típico |
| --- | --- |
| Inserção | Proporcional à profundidade, O(log n) em dados bem espalhados |
| Busca por janela | Profundidade mais o número de nós visitados na região |
| Pior caso | Pontos muito aglomerados criam árvores profundas; limite a profundidade máxima |

## Quadtrees em sistemas reais

Num serviço de "lugares próximos", os lugares mudam pouco. Uma estratégia comum:

- Construir a quadtree **em memória** a partir do banco ao iniciar o servidor. Com centenas de milhões de lugares, isso cabe em algumas dezenas de GB e leva minutos.
- Ter várias réplicas do serviço de busca, cada uma com a árvore completa, atrás de um load balancer.
- Aplicar inserções novas em lote (por exemplo, à noite) ou reconstruir a árvore periodicamente, em vez de manter escrita concorrente.

Para pontos que se movem o tempo todo, como motoristas, atualizar a árvore a cada poucos segundos gera muito rebalanceamento. Nesse caso, uma grade fixa (geohash ou H3) em memória costuma ser mais simples.

## Quadtree versus geohash

| Critério | Geohash | Quadtree |
| --- | --- | --- |
| Granularidade | Fixa por precisão | Adapta-se à densidade |
| Onde vive | Em qualquer índice de string no banco | Normalmente em memória |
| Atualizações frequentes | Baratas | Podem causar divisões e fusões |
| Busca de K vizinhos | Consultar células e expandir | Natural na árvore |
