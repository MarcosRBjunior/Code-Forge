O **relógio de Lamport**, proposto por Leslie Lamport em 1978, é a forma mais simples de dar uma ordem consistente com a causalidade aos eventos de um sistema distribuído: cada processo mantém **um único contador inteiro**, que sobe a cada evento e é corrigido ao receber mensagens.

## As regras

Cada processo guarda um contador `L`, iniciado em 0.

1. **Evento local:** `L = L + 1`.
2. **Envio de mensagem:** `L = L + 1` e a mensagem carrega o valor `L` como timestamp.
3. **Recebimento:** `L = max(L, timestamp_da_mensagem) + 1`.

A regra 3 é a chave: ao receber, o processo "pula" para além do remetente, garantindo que o recebimento tenha timestamp maior que o envio.

## Exemplo passo a passo

```text
         P1                      P2                      P3
   a (L=1)
   envia m1 (L=2) ------------> recebe m1 (L=3)
                                 b (L=4)
                                 envia m2 (L=5) ------> recebe m2 (L=6)
   c (L=3)                                                d (L=7)
```

P1 fez `c` (L=3) sem relação causal com `b` (L=4): ambos os valores existem, mas isso não significa que `c` precedeu `b`. É a limitação central, abordada abaixo.

## Implementação

```python
class RelogioLamport:
    def __init__(self):
        self.tempo = 0

    def evento_local(self):
        self.tempo += 1
        return self.tempo

    def enviar(self):
        self.tempo += 1
        return self.tempo            # vai junto com a mensagem

    def receber(self, ts_mensagem):
        self.tempo = max(self.tempo, ts_mensagem) + 1
        return self.tempo

p1, p2 = RelogioLamport(), RelogioLamport()
ts = p1.enviar()          # 1
print(p2.receber(ts))     # 2
```

## A garantia e o limite

A garantia é a **condição de relógio**: se `a` aconteceu antes de `b`, então `L(a) < L(b)`.

A volta **não vale**: `L(a) < L(b)` não implica que `a` causou `b`; podem ser concorrentes. Por isso o relógio de Lamport serve para obter uma ordem **compatível com a causalidade**, mas não para detectar concorrência (para isso, use vetores de versão).

## Ordem total

Para obter uma ordem total de eventos (todos concordam sobre quem vem primeiro), desempate eventos com o mesmo contador pelo identificador do processo: ordene pelo par `(L, id_do_processo)`. Essa ordem é arbitrária entre eventos concorrentes, mas igual para todos.

## Para que serve na prática

- **Exclusão mútua distribuída:** o algoritmo original de Lamport usa essa ordem total para decidir quem entra na seção crítica.
- **Replicação por máquina de estados:** todas as réplicas aplicam os comandos na mesma ordem.
- **Ordenação de logs** e mensagens em sistemas que precisam de uma sequência consistente.
- **IDs ordenáveis:** muitos sistemas combinam contador lógico com tempo físico (relógios híbridos).

## Comparação rápida

| Critério | Relógio físico | Lamport | Vetor |
| --- | --- | --- | --- |
| Depende de sincronização | Sim | Não | Não |
| Respeita causalidade | Não garante | Sim | Sim |
| Detecta concorrência | Não | Não | Sim |
| Espaço por timestamp | Pequeno | Pequeno | Cresce com N |

<Callout type="tip" title="Dica de memória">
Lamport ordena de forma consistente com a causalidade, mas não prova causalidade. Se você precisa saber se dois eventos são independentes, precisa de vetores.
</Callout>
