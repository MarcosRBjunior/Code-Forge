Como achar páginas quase duplicadas entre bilhões, documentos semelhantes para um mecanismo de busca, usuários com gostos parecidos ou plágio? Comparar todos os pares é quadrático e impraticável. O **MinHash** cria uma assinatura curta de cada conjunto, de modo que a **similaridade de Jaccard** entre dois conjuntos possa ser estimada comparando apenas as assinaturas.

## Similaridade de Jaccard

Para dois conjuntos A e B:

```text
J(A, B) = |A interseção B| / |A união B|
```

Vale 1 para conjuntos idênticos e 0 para disjuntos. Para texto, cada documento vira o conjunto de seus **shingles** (sequências de k palavras ou caracteres consecutivos). Documentos quase iguais compartilham a maior parte dos shingles.

## A ideia do MinHash

Aplique uma função de hash h a todos os elementos de um conjunto e guarde o **menor** valor de hash, `minhash(A) = min(h(x) para x em A)`. Propriedade chave:

```text
Probabilidade[ minhash(A) == minhash(B) ] = J(A, B)
```

Intuição: o elemento com o menor hash na união A ∪ B é uniformemente aleatório. A e B terão o mesmo mínimo exatamente quando esse elemento estiver na interseção, o que acontece com probabilidade J.

Uma única comparação é um sorteio 0 ou 1. Para estimar J, use **k funções de hash diferentes**, construindo uma assinatura de k valores mínimos. A fração de posições iguais entre duas assinaturas estima J, com erro de aproximadamente 1/sqrt(k).

```python
import hashlib

def assinatura(conjunto, k=128):
    sig = []
    for i in range(k):
        sig.append(min(
            int(hashlib.md5(f"{i}:{x}".encode()).hexdigest(), 16)
            for x in conjunto
        ))
    return sig

def jaccard_estimado(s1, s2):
    return sum(a == b for a, b in zip(s1, s2)) / len(s1)
```

Com k = 128, o erro típico é cerca de 9%; com k = 1.024, cerca de 3%. Cada documento, por maior que seja, vira 128 inteiros.

## LSH: evitando comparar todos os pares

Mesmo com assinaturas, comparar todos os pares é caro. O **Locality-Sensitive Hashing** em bandas resolve:

1. Divida a assinatura de k posições em b bandas de r posições cada.
2. Para cada banda, faça o hash das r posições para um bucket.
3. Dois documentos são **candidatos** se caírem no mesmo bucket em pelo menos uma banda.

A probabilidade de virarem candidatos é `1 - (1 - J^r)^b`, uma curva em S. Ajustando b e r, você escolhe o limiar: pares muito similares quase sempre colidem, e pares diferentes quase nunca. Depois, só os candidatos são conferidos com precisão.

## Aplicações

- **Deduplicação de documentos e páginas** em buscadores e crawlers (AltaVista foi pioneiro).
- **Sistemas de recomendação:** usuários ou itens com muitos vizinhos em comum.
- **Detecção de plágio e spam** em escala.
- **Agrupamento de notícias** quase iguais.
- **Genômica:** comparação de sequências (Mash).

## Armadilhas

- **Escolha de shingles:** pequenos demais geram falsa similaridade; grandes demais, falsa diferença.
- **Mede conjuntos, não ordem ou semântica.** Textos reordenados ou parafraseados têm Jaccard baixo; para semântica, use embeddings.
- **Variantes** como b-bit MinHash e one-permutation hashing reduzem o custo de calcular k hashes por elemento.
- É estimativa: valide candidatos importantes com a comparação exata.

<Callout type="tip" title="Comparação com SimHash">
SimHash estima similaridade de cosseno com uma assinatura de poucos bits e é comum para deduplicação web. MinHash é a escolha para Jaccard de conjuntos.
</Callout>
