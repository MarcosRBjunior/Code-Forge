Você quer saber quantas vezes cada item apareceu em um fluxo gigantesco: os hashtags mais frequentes, os IPs que mais fazem requisições, as músicas mais tocadas. Um dicionário com um contador por item pode ocupar gigabytes quando há bilhões de chaves distintas. O **count-min sketch** estima frequências com memória pequena e fixa, aceitando um pequeno erro.

## Como funciona

A estrutura é uma matriz de contadores com d linhas e w colunas, e uma função de hash diferente por linha.

- **Incrementar x:** para cada linha i, some 1 em `matriz[i][hash_i(x) % w]`.
- **Estimar x:** devolva o **mínimo** entre `matriz[i][hash_i(x) % w]` de todas as linhas.

```python
import hashlib

class CountMin:
    def __init__(self, w=1000, d=5):
        self.w, self.d = w, d
        self.t = [[0] * w for _ in range(d)]

    def _col(self, i, item):
        h = hashlib.sha256(f"{i}:{item}".encode()).hexdigest()
        return int(h, 16) % self.w

    def adicionar(self, item, n=1):
        for i in range(self.d):
            self.t[i][self._col(i, item)] += n

    def estimar(self, item):
        return min(self.t[i][self._col(i, item)] for i in range(self.d))
```

```javascript
const { createHash } = require("crypto");

const sha256Hex = (s) => createHash("sha256").update(s).digest("hex");
// int(hex, 16) % m, sem perder precisão
const modHex = (hex, m) => Number(BigInt("0x" + hex) % BigInt(m));

class CountMin {
  constructor(w = 1000, d = 5) {
    this.w = w;
    this.d = d;
    this.t = Array.from({ length: d }, () => new Array(w).fill(0));
  }

  _col(i, item) {
    return modHex(sha256Hex(`${i}:${item}`), this.w);
  }

  adicionar(item, n = 1) {
    for (let i = 0; i < this.d; i++) {
      this.t[i][this._col(i, item)] += n;
    }
  }

  estimar(item) {
    let menor = Infinity;
    for (let i = 0; i < this.d; i++) menor = Math.min(menor, this.t[i][this._col(i, item)]);
    return menor;
  }
}
```

```cpp
    unsigned long long r = 0;
    for (char c : h) r = (r * 16 + (c <= '9' ? c - '0' : c - 'a' + 10)) % m;

}
```

```csharp
static string Sha256Hex(string s)

    using (var sha = SHA256.Create())
    {

static int ModHex(string hex, int m)
{
    long r = 0;
    foreach (char c in hex) r = (r * 16 + Convert.ToInt32(c.ToString(), 16)) % m;

}
```

```go
func sha256Hex(s string) string {
	h := sha256.Sum256([]byte(s))
	return hex.EncodeToString(h[:])
}

// int(hex, 16) % m
func modHex(h string, m int) int {
	n := new(big.Int)
	n.SetString(h, 16)
	return int(n.Mod(n, big.NewInt(int64(m))).Int64())
}

	w, d int
	t    [][]int

func NovoCountMin(w, d int) *CountMin {
	t := make([][]int, d)
	for i := range t {
		t[i] = make([]int, w)
	}
	return &CountMin{w: w, d: d, t: t}
}

	return modHex(sha256Hex(fmt.Sprintf("%d:%s", i, item)), c.w)
}

	for i := 0; i < c.d; i++ {
		c.t[i][c.col(i, item)] += n
	}
}

func (c *CountMin) estimar(item string) int {
	menor := c.t[0][c.col(0, item)]
	for i := 1; i < c.d; i++ {
		if v := c.t[i][c.col(i, item)]; v < menor {
			menor = v
		}
	}
	return menor
}
```

## Por que o mínimo

Colisões só **somam** contagens de outros itens ao contador, nunca subtraem. Cada contador é, portanto, maior ou igual à contagem real. O mínimo entre linhas é a melhor estimativa, a que sofreu menos colisão. O resultado é sempre **superestimado ou exato, nunca subestimado**.

## Garantias e dimensionamento

Escolhendo `w = ceil(e / epsilon)` e `d = ceil(ln(1 / delta))`, com N sendo o total de eventos, a estimativa excede a real em no máximo `epsilon * N` com probabilidade de pelo menos `1 - delta`. Exemplo: epsilon de 0,1% e delta de 1% dão cerca de 2.718 colunas e 5 linhas: aproximadamente 14 mil contadores, independentemente do número de itens distintos.

## Aplicações

- **Heavy hitters / Top-K:** combine o sketch com um heap pequeno: a cada evento, estime a contagem e mantenha no heap os K maiores. É a base de "tendências" e de detecção de abuso.
- **Limitação de taxa aproximada** por cliente em escala enorme.
- **Estimativa de frequência em bancos e roteadores:** otimizadores de consulta e monitoramento de rede.
- **Detecção de DDoS:** IPs com contagem anormal.
- Pode ser **mesclado**: somar as matrizes de nós diferentes dá o sketch da união, o que é ótimo para agregação distribuída.

## Limitações

- Só superestima. Itens raros ficam distorcidos quando o erro (`epsilon * N`) é maior que a própria contagem. A estrutura é útil para itens **frequentes**.
- Não lista os itens; para o Top-K é preciso manter candidatos à parte.
- Não suporta remoção sem perder as garantias (a menos que seja um conservative update ou um modelo com deltas negativos controlados).
- O erro cresce com N: com fluxos ilimitados use janelas de tempo ou decaimento.

<Callout type="tip" title="Conservative update">
Atualizar apenas os contadores que estão no valor mínimo reduz bastante a superestimativa, sem custo relevante.
</Callout>
