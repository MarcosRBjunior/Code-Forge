Como um sistema descobre que um nó morreu? Ninguém avisa: máquinas simplesmente param. A técnica mais comum é o **heartbeat** (batimento cardíaco): cada nó envia, periodicamente, uma mensagem curta dizendo "estou vivo". Quando as mensagens deixam de chegar por tempo suficiente, o nó é **suspeito** de ter falhado, e o sistema reage: remove-o do balanceamento, elege novo líder ou re-replica dados.

## Mecanismo básico

```text
Nó A --"vivo"--> Monitor    (t = 0 s)
Nó A --"vivo"--> Monitor    (t = 1 s)
Nó A --"vivo"--> Monitor    (t = 2 s)
Nó A   ...nada...           (t = 3 s, 4 s, 5 s)
Monitor: passaram 3 intervalos sem batimento -> A é considerado falho
```

Dois parâmetros definem o comportamento:

- **Intervalo:** de quanto em quanto tempo se envia (por exemplo, 1 s).
- **Timeout:** quanto tempo sem batimento antes de declarar falha (por exemplo, 3 a 10 s).

```python
import time

class Monitor:
    def __init__(self, timeout):
        self.ultimo = {}
        self.timeout = timeout

    def batimento(self, no):
        self.ultimo[no] = time.time()

    def suspeitos(self):
        agora = time.time()
        return [n for n, t in self.ultimo.items() if agora - t > self.timeout]
```

```java
import java.util.*;

class Monitor {
    private final Map<String, Double> ultimo = new HashMap<>();
    private final double timeout;   // em segundos

    Monitor(double timeout) {
        this.timeout = timeout;
    }

    void batimento(String no) {
        ultimo.put(no, System.currentTimeMillis() / 1000.0);
    }

    List<String> suspeitos() {
        double agora = System.currentTimeMillis() / 1000.0;
        List<String> saida = new ArrayList<>();
        for (Map.Entry<String, Double> e : ultimo.entrySet()) {
            if (agora - e.getValue() > timeout) saida.add(e.getKey());
        }
        return saida;
    }
}
```

```cpp
#include <chrono>
#include <map>
#include <string>
#include <vector>
using namespace std;

class Monitor {
    map<string, double> ultimo;
    double timeout;   // em segundos

    static double agora() {
        return chrono::duration<double>(chrono::system_clock::now().time_since_epoch()).count();
    }

public:
    Monitor(double timeout) : timeout(timeout) {}

    void batimento(const string& no) {
        ultimo[no] = agora();
    }

    vector<string> suspeitos() const {
        double t0 = agora();
        vector<string> saida;
        for (const auto& [no, t] : ultimo) {
            if (t0 - t > timeout) saida.push_back(no);
        }
        return saida;
    }
};
```

```csharp
using System;
using System.Collections.Generic;
using System.Linq;

class Monitor
{
    private readonly Dictionary<string, double> ultimo = new Dictionary<string, double>();
    private readonly double timeout;   // em segundos

    public Monitor(double timeout)
    {
        this.timeout = timeout;
    }

    private static double Agora()
    {
        return DateTimeOffset.UtcNow.ToUnixTimeMilliseconds() / 1000.0;
    }

    public void Batimento(string no)
    {
        ultimo[no] = Agora();
    }

    public List<string> Suspeitos()
    {
        double agora = Agora();
        return ultimo.Where(p => agora - p.Value > timeout).Select(p => p.Key).ToList();
    }
}
```

```go
import "time"

type Monitor struct {
	ultimo  map[string]time.Time
	timeout time.Duration
}

func novoMonitor(timeout time.Duration) *Monitor {
	return &Monitor{ultimo: map[string]time.Time{}, timeout: timeout}
}

func (m *Monitor) batimento(no string) {
	m.ultimo[no] = time.Now()
}

func (m *Monitor) suspeitos() []string {
	saida := []string{}
	for no, t := range m.ultimo {
		if time.Since(t) > m.timeout {
			saida = append(saida, no)
		}
	}
	return saida
}
```

## O trade-off do timeout

| Timeout | Detecção | Risco |
| --- | --- | --- |
| Curto | Rápida | Falsos positivos: nó lento ou rede congestionada é dado como morto, causando failovers desnecessários |
| Longo | Lenta | Cliente sofre mais tempo com nó realmente morto |

Não existe valor perfeito. Num sistema assíncrono, é **impossível** distinguir um nó lento de um nó morto; o detector só pode suspeitar. Por isso falsos positivos precisam ser seguros: o sistema deve tolerar que um nó "morto" continue funcionando (fencing, quórum).

## Variações

- **Push versus pull:** no push, o nó envia o batimento; no pull, o monitor pergunta ("health check"). Load balancers usam pull com endpoints como `/health`.
- **Níveis de saúde:** *liveness* (o processo está vivo?) versus *readiness* (está pronto para receber tráfego?). Um serviço que carrega cache ainda está vivo, mas não pronto.
- **Gossip:** cada nó troca informações de vivacidade com alguns vizinhos aleatórios, e a suspeita se espalha pela rede. Escala bem e não depende de monitor central (Cassandra, Consul).
- **Detector de falha phi accrual:** em vez de sim ou não, calcula uma probabilidade de falha com base no histórico de atrasos, adaptando-se à rede (usado em Cassandra e Akka).
- **Leases:** o batimento renova uma concessão; sem renovação, ela expira sozinha.

## Armadilhas

- **Heartbeat que só mede o processo:** o nó responde ao ping, mas está com disco travado ou sem acesso ao banco. Faça checagens que exercitem dependências críticas, com cuidado para não derrubar tudo se uma dependência opcional cair.
- **Tempestade de batimentos:** milhares de nós enviando ao mesmo monitor sobrecarregam. Use hierarquia ou gossip.
- **Falha do monitor:** o próprio monitor precisa de redundância.
- **Pausas longas de GC:** parecem queda de nó. Ajuste timeouts acima das pausas esperadas.
- **Sincronização de picos:** nós reiniciados juntos enviam batimentos no mesmo instante; adicione jitter.

<Callout type="note" title="Suspeita, não certeza">
Um heartbeat perdido é só uma evidência. Decisões irreversíveis (promover um novo líder, apagar dados) devem combinar o detector com quórum ou fencing.
</Callout>

## Na entrevista

Cite heartbeats ao explicar como detectar falha em clusters, eleição de líder (o líder envia batimentos aos seguidores; sem eles, os seguidores iniciam eleição, como no Raft) e health checks de load balancers. Follow-ups: "como escolher o timeout?" (equilibrando falsos positivos e tempo de detecção) e "e se o nó está vivo mas isolado?" (partição: quórum e fencing).
