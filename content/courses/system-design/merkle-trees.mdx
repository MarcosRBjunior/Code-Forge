Duas réplicas de um banco devem ter os mesmos dados, mas após falhas podem ter divergido em algumas linhas. Como descobrir **quais** registros diferem sem enviar todos os dados pela rede nem comparar bilhões de linhas uma a uma? A **Merkle tree** (árvore de hashes) resolve com muito pouco tráfego: compara-se um hash da raiz e, só se diferir, desce-se até as folhas que mudaram.

## Estrutura

- Cada **folha** contém o hash de um bloco de dados (um intervalo de chaves, um arquivo, uma transação).
- Cada **nó interno** contém o hash da concatenação dos hashes dos filhos.
- A **raiz** resume todo o conjunto: se um bit de qualquer dado mudar, o hash da raiz muda.

```text
             H(H12 + H34)         <- raiz
            /            \
        H12=H(h1+h2)   H34=H(h3+h4)
        /     \         /     \
       h1     h2       h3     h4  <- hashes dos blocos
```

```python
import hashlib

def h(b: bytes) -> bytes:
    return hashlib.sha256(b).digest()

def raiz(blocos):
    nivel = [h(b) for b in blocos]
    while len(nivel) > 1:
        if len(nivel) % 2:
            nivel.append(nivel[-1])          # duplica o último se for ímpar
        nivel = [h(nivel[i] + nivel[i + 1]) for i in range(0, len(nivel), 2)]
    return nivel[0]
```

## Anti-entropy: sincronizando réplicas

1. Cada réplica constrói uma Merkle tree sobre seus intervalos de chaves.
2. Trocam as raízes. Se forem iguais, os dados são idênticos: fim, com um único hash trafegado.
3. Se diferirem, comparam os filhos e descem **apenas pelos ramos cujos hashes diferem**.
4. Ao chegar nas folhas divergentes, sincronizam só esses intervalos.

O custo cresce com log n para localizar uma diferença, em vez de n. Cassandra e DynamoDB (e o Riak) usam isso nos processos de reparo (*anti-entropy repair*).

## Prova de inclusão

Para provar que um bloco pertence ao conjunto sem enviar tudo, basta enviar o bloco mais os **hashes irmãos ao longo do caminho até a raiz**: cerca de log n hashes. O verificador recalcula a raiz e compara com a raiz confiável.

```text
Provar h3 em 4 blocos: enviar h3, h4 e H12.
Verificador: H34 = H(h3 + h4); raiz = H(H12 + H34) e compara.
```

Isso é a base de:

- **Git:** objetos de árvore e commits formam uma estrutura de hashes que detecta qualquer alteração.
- **Bitcoin e Ethereum:** cada bloco tem a raiz Merkle de suas transações; clientes leves verificam uma transação com poucos hashes (SPV).
- **Certificate Transparency:** logs públicos de certificados com provas de inclusão e consistência.
- **Sistemas de arquivos e distribuição de dados:** ZFS, IPFS, BitTorrent v2 e Dynamo para verificação de integridade.

## Trade-offs

- **Custo de manutenção:** cada escrita invalida os hashes do caminho até a raiz (log n atualizações). Em bancos com muitas escritas, a árvore é reconstruída periodicamente ou por intervalos.
- **Granularidade:** folhas grandes reduzem a árvore, mas obrigam a sincronizar blocos maiores quando há diferença.
- **Dados em memória ou disco:** árvore muito grande precisa de armazenamento dedicado.
- **Escolha do hash:** SHA-256 ou similar para segurança; para detecção de divergência interna basta algo mais barato.

<Callout type="note" title="Detecta divergência, não corrige sozinha">
A Merkle tree diz onde as réplicas diferem. Quem decide qual versão vale é outra regra: timestamp, vetor de versões ou líder.
</Callout>
