**Serverless** não significa ausência de servidores, e sim que você não os gerencia. Você entrega o código (uma função ou um contêiner) e o provedor cuida de provisionar máquinas, escalar conforme a demanda, aplicar patches e cobrar apenas pelo que foi executado. Exemplos: AWS Lambda, Google Cloud Functions, Azure Functions, Cloudflare Workers, além de serviços gerenciados como DynamoDB e S3.

## Como funciona

```text
Evento (HTTP, fila, upload, agenda)
        |
        v
 Plataforma: cria ou reutiliza uma instância isolada
        |
        v
 Sua função executa (poucos ms a minutos) e retorna
        |
        v
 Instância fica ociosa e eventualmente é descartada
```

Cada invocação é disparada por um **evento**. A plataforma escala de zero a milhares de execuções paralelas sem configuração, e volta a zero quando não há tráfego, sem custo.

import java.util.*;

static Map<String, Object> handler(Map<String, String> event, Object context) {
    // recebe o evento, faz o trabalho e devolve a resposta
    String nome = event.getOrDefault("nome", "mundo");
    Map<String, Object> resposta = new LinkedHashMap<>();
    resposta.put("statusCode", 200);
    resposta.put("body", "Olá, " + nome);
    return resposta;
}

public static void main(String[] args) {
    Map<String, String> evento = new HashMap<>();
    evento.put("nome", "Ana");
    System.out.println(handler(evento, null));
    System.out.println(handler(new HashMap<>(), null));
}

```cpp
#include <iostream>
#include <map>
#include <string>
using namespace std;

struct RespostaHttp {
    int statusCode;
    string body;
};

RespostaHttp handler(const map<string, string>& event) {
    // recebe o evento, faz o trabalho e devolve a resposta
    auto it = event.find("nome");
    string nome = it != event.end() ? it->second : "mundo";
    return {200, "Olá, " + nome};
}

int main() {
    for (const auto& ev : {map<string, string>{{"nome", "Ana"}}, map<string, string>{}}) {
        RespostaHttp r = handler(ev);
        cout << r.statusCode << " " << r.body << endl;
    }
}
```

```csharp
using System;
using System.Collections.Generic;

class RespostaHttp
{
    public int StatusCode;
    public string Body;
}

static RespostaHttp Handler(Dictionary<string, string> evento)
{
    // recebe o evento, faz o trabalho e devolve a resposta
    string nome;
    if (!evento.TryGetValue("nome", out nome))
    {
        nome = "mundo";
    }
    return new RespostaHttp { StatusCode = 200, Body = "Olá, " + nome };
}

static void Main()
{
    var r1 = Handler(new Dictionary<string, string> { { "nome", "Ana" } });
    var r2 = Handler(new Dictionary<string, string>());
    Console.WriteLine(r1.StatusCode + " " + r1.Body);
    Console.WriteLine(r2.StatusCode + " " + r2.Body);
}
```

## Vantagens

- **Escala automática** e granular, inclusive para picos imprevisíveis.
- **Pagamento por uso:** ótimo para cargas esporádicas ou muito variáveis.
- **Menos operação:** sem patches de SO, sem capacidade para planejar.
- **Integração por eventos:** conecta facilmente filas, buckets, agendadores e APIs.

## Limitações

- **Cold start:** a primeira execução após ociosidade precisa iniciar o ambiente, adicionando de dezenas de milissegundos a segundos. Runtimes leves, instâncias provisionadas e menos dependências ajudam.
- **Sem estado local:** a instância pode sumir a qualquer momento. Estado vai para banco, cache ou object storage.
- **Limites de execução:** tempo máximo, memória, tamanho de pacote e concorrência.
- **Custo em carga constante:** para tráfego alto e estável, servidores ou contêineres dedicados podem sair mais baratos.
- **Dependência do provedor** (vendor lock-in) e dificuldade de testar localmente.
- **Conexões com banco:** milhares de execuções simultâneas esgotam o pool de conexões. Use proxy de conexões ou bancos que falam HTTP.

## Quando escolher

| Cenário | Serverless? |
| --- | --- |
| Processar miniaturas ao chegar uma imagem | Sim |
| Webhook recebido algumas vezes por hora | Sim |
| Backend com tráfego alto, constante e previsível | Talvez não: compare custos |
| Tarefa que roda por horas | Não: prefira contêineres ou batch |
| Latência ultrabaixa e consistente | Cuidado com cold start |

<Callout type="tip" title="Idempotência é obrigatória">
Plataformas serverless geralmente garantem entrega "pelo menos uma vez": a mesma função pode ser invocada mais de uma vez para o mesmo evento. Escreva funções idempotentes.
</Callout>

## Padrões comuns

- **API serverless:** API gateway + funções + banco gerenciado.
- **Pipeline de eventos:** upload no bucket dispara função, que publica numa fila, que dispara outra função.
- **Tarefas agendadas:** limpeza, relatórios e sincronizações periódicas.

## Na entrevista

Cite serverless para componentes assíncronos, esporádicos ou com picos (processamento de mídia, notificações, ETL leve), explicando como trata cold start, estado e idempotência. Follow-ups: "como controlar custos?" (limites de concorrência, monitorar invocações), "como evitar sobrecarregar o banco?" (limitar concorrência, usar proxy ou fila no meio) e "quando não usar?" (carga constante alta, tarefas longas, latência rígida).
