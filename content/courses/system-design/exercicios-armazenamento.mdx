Revise os tipos de armazenamento: block, sistemas de arquivos distribuídos, object storage e erasure coding.

<QuizSet>
<Quiz question="Você vai hospedar um PostgreSQL em VMs na nuvem. Que tipo de armazenamento é o mais indicado?" options={["Object storage", "Block storage em SSD provisionado", "Um bucket com URLs pré-assinadas", "Um sistema de arquivos distribuído do tipo HDFS"]} answer={1} explanation="Bancos transacionais precisam de baixa latência e acesso a posições arbitrárias, o que o block storage entrega." />
<Quiz question="Um app permite upload de vídeos de até 4 GB. Qual desenho é mais adequado?" options={["O backend recebe o vídeo inteiro e o grava numa coluna de tabela do banco relacional","Upload direto ao object storage por URL pré-assinada, com a referência guardada no banco","Um volume de bloco compartilhado entre todos os servidores, montado em cada instância","Enviar o vídeo em partes por uma fila de mensagens e remontar o arquivo inteiro dentro do banco de dados"]} answer={1} explanation="Mídia grande vai para object storage, com upload direto do cliente, e o banco guarda apenas metadados e a chave." />
<Quiz question="No HDFS, o que o servidor de metadados faz?" options={["Armazena todos os blocos de dados dos arquivos e os entrega aos clientes que os pedem","Guarda a árvore de diretórios e o mapa de localização dos blocos nos nós de dados","Calcula as paridades de erasure coding e as grava junto de cada bloco nos nós","Serve diretamente os dados ao cliente, atuando como proxy de leitura e de escrita"]} answer={1} explanation="Ele mapeia arquivos para blocos e nós; os dados trafegam entre cliente e nós de dados." />
<Quiz question="Qual é o overhead de espaço de um esquema de erasure coding 10+4?" options={["10%", "40%", "100%", "200%"]} answer={1} explanation="O overhead é (k+m)/k = 14/10 = 1,4x, ou seja, 40% de espaço extra." />
<Quiz question="Um volume de bloco está cheio de snapshots esquecidos e o banco ficou lento, mesmo com 30% de espaço livre. Qual métrica você verifica primeiro?" options={["Tamanho do bucket de objetos, para ver se o volume ultrapassou a cota de armazenamento contratada","IOPS e latência do volume, comparados com o limite de desempenho provisionado para ele","Número de objetos armazenados, para checar se há excesso de arquivos pequenos no volume","Fator de replicação do HDFS, para checar se os blocos estão bem distribuídos pelo cluster"]} answer={1} explanation="Volumes limitam IOPS e throughput independentemente do espaço livre, então o gargalo pode ser o desempenho provisionado." />
<Quiz question="Por que espalhar os fragmentos de erasure coding por racks e zonas diferentes?" options={["Para reduzir o uso de CPU nos nós, já que cada rack calcula somente a sua própria paridade","Para que uma falha de rack ou zona não destrua mais fragmentos do que o código tolera","Para eliminar a necessidade de paridade, já que cada zona guarda uma cópia completa","Para acelerar escritas pequenas, que passam a ser gravadas em paralelo em vários racks"]} answer={1} explanation="Falhas correlacionadas num domínio de falha só são toleradas se os fragmentos estiverem em domínios distintos." />
<Quiz question="Qual afirmação sobre durabilidade e disponibilidade no object storage é correta?" options={["São sinônimos, pois ambas medem a probabilidade de acessar o objeto a qualquer momento","Dados podem estar duráveis mesmo com o serviço temporariamente indisponível para leitura","Durabilidade alta garante disponibilidade de 100%, pois um dado preservado está sempre acessível","A disponibilidade é garantida pela versão do objeto, e não pela infraestrutura do serviço"]} answer={1} explanation="Durabilidade é a chance de não perder dados; disponibilidade é a chance de acessá-los naquele momento. São métricas diferentes." />
