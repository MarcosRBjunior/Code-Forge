Dados se corrompem. Um bit vira no cabo de rede, um setor do disco degrada, uma placa de memória falha, um bug grava metade de um arquivo. Na maior parte das vezes, ninguém percebe até que alguém tente ler o dado e algo estranho aconteça. Um **checksum** é um valor pequeno calculado a partir dos dados que permite verificar, depois, se eles continuam iguais.

## Como funciona

1. Quem envia ou grava calcula `c = f(dados)` e guarda ou transmite `c` junto com os dados.
2. Quem recebe ou lê recalcula `f(dados)` e compara com `c`.
3. Se os valores diferem, os dados foram alterados. Se coincidem, eles provavelmente estão intactos.

O "provavelmente" vem do fato de que o checksum é menor que os dados: existem infinitas entradas para cada valor possível. Um bom algoritmo torna improvável que corrupções comuns produzam o mesmo valor.

## Famílias de algoritmos

| Algoritmo | Tamanho | Velocidade | Detecta | Uso típico |
| --- | --- | --- | --- | --- |
| Soma simples / checksum da internet | 16 bits | muito rápida | erros simples; falha com bytes trocados de lugar | cabeçalhos IPv4, TCP, UDP |
| CRC32 / CRC32C | 32 bits | muito rápida (instrução de hardware) | rajadas de erros de bits com alta probabilidade | Ethernet, ZIP, PNG, armazenamento, Kafka |
| xxHash, MurmurHash | 32 a 128 bits | extremamente rápida | corrupção acidental | verificação interna, deduplicação não adversária |
| SHA-256 | 256 bits | mais lenta | corrupção acidental **e** alteração intencional | downloads, Git, blockchain, assinaturas |
| MD5, SHA-1 | 128 / 160 bits | rápida | corrupção acidental | legado; quebrados contra ataques |

A divisão principal é entre **checksums não criptográficos** (rápidos, ótimos contra acidentes, inúteis contra um atacante que pode recalcular o valor) e **hashes criptográficos** (mais caros, mas é inviável produzir de propósito dois conteúdos com o mesmo hash). Para garantir também que o dado veio de quem você acha, é preciso um HMAC ou uma assinatura digital, porque um atacante que altera os dados pode simplesmente recalcular um hash sem chave.

```python
import hashlib
import zlib

def crc32(dados: bytes) -> int:
    return zlib.crc32(dados) & 0xFFFFFFFF

def sha256(dados: bytes) -> str:
    return hashlib.sha256(dados).hexdigest()

original = b"pedido=981;valor=150.00"
corrompido = b"pedido=981;valor=950.00"

print(crc32(original) == crc32(corrompido))    # False
print(sha256(original) == sha256(corrompido))  # False
```

```javascript
const { createHash } = require("crypto");

// CRC-32 (polinômio 0xEDB88320), bit a bit
function crc32(dados) {
  let crc = 0xffffffff;
  for (const byte of dados) {
    crc ^= byte;
    for (let i = 0; i < 8; i++) crc = (crc >>> 1) ^ (0xedb88320 & -(crc & 1));
  }
  return ~crc >>> 0;
}

const sha256 = (dados) => createHash("sha256").update(dados).digest("hex");

const original = new TextEncoder().encode("pedido=981;valor=150.00");
const corrompido = new TextEncoder().encode("pedido=981;valor=950.00");

console.log(crc32(original) === crc32(corrompido));    // false
console.log(sha256(original) === sha256(corrompido));  // false
```

```java
import java.math.BigInteger;
import java.nio.charset.StandardCharsets;
import java.security.MessageDigest;
import java.util.zip.CRC32;

static long crc32(byte[] dados) {
    CRC32 c = new CRC32();
    c.update(dados);
    return c.getValue() & 0xFFFFFFFFL;
}

static String sha256(byte[] dados) {
    try {
        return String.format("%064x", new BigInteger(1, MessageDigest.getInstance("SHA-256").digest(dados)));
    } catch (Exception e) {
        throw new IllegalStateException(e);
    }
}

public static void main(String[] args) {
    byte[] original = "pedido=981;valor=150.00".getBytes(StandardCharsets.UTF_8);
    byte[] corrompido = "pedido=981;valor=950.00".getBytes(StandardCharsets.UTF_8);

    System.out.println(crc32(original) == crc32(corrompido));                 // false
    System.out.println(sha256(original).equals(sha256(corrompido)));          // false
}
```

```csharp
using System;
using System.Linq;
using System.Security.Cryptography;
using System.Text;

// CRC-32 (polinômio 0xEDB88320), bit a bit
static uint Crc32(byte[] dados)
{
    uint crc = 0xFFFFFFFF;
    foreach (byte b in dados)
    {
        crc ^= b;
        for (int i = 0; i < 8; i++) crc = (crc >> 1) ^ (0xEDB88320 & (0 - (crc & 1)));
    }
    return ~crc;
}

static string Sha256(byte[] dados)
{
    using (var sha = SHA256.Create())
    {
        return string.Concat(sha.ComputeHash(dados).Select(b => b.ToString("x2")));
    }
}

static void Main()
{
    byte[] original = Encoding.UTF8.GetBytes("pedido=981;valor=150.00");
    byte[] corrompido = Encoding.UTF8.GetBytes("pedido=981;valor=950.00");

    Console.WriteLine((Crc32(original) == Crc32(corrompido)).ToString().ToLower());       // false
    Console.WriteLine((Sha256(original) == Sha256(corrompido)).ToString().ToLower());     // false
}
```

```go
func sha256Hex(dados []byte) string {
	h := sha256.Sum256(dados)
```

## Onde aparecem em sistemas distribuídos

- **Rede:** Ethernet usa CRC em cada quadro; TCP e UDP têm um checksum de 16 bits. São proteções fracas, e corrupções raras passam por elas, por isso TLS e protocolos de aplicação adicionam verificação própria.
- **Armazenamento:** sistemas de arquivos como ZFS e Btrfs guardam checksums de cada bloco e detectam corrupção silenciosa. Sistemas distribuídos como HDFS verificam blocos ao ler e, se houver divergência, leem de outra réplica e reparam a cópia ruim.
- **Bancos de dados:** páginas com checksum detectam corrupção no disco antes que ela se espalhe.
- **Object storage:** clientes enviam o hash do conteúdo no upload (por exemplo, cabeçalhos de MD5 ou CRC32C), e o serviço rejeita o objeto se não bater.
- **Mensageria e logs:** cada registro no log do Kafka carrega CRC.
- **Sincronização:** Merkle trees combinam hashes hierarquicamente para descobrir rapidamente quais blocos diferem entre duas réplicas.
- **Distribuição de artefatos:** downloads publicam o SHA-256 para que você verifique o arquivo recebido.

<Callout type="warning" title="Detectar não é corrigir">
Checksum só diz que algo está errado. Para recuperar o dado você precisa de redundância: outra réplica, paridade, erasure coding ou um código corretor de erros (como ECC na memória). Projete o caminho de reparo junto com a verificação.
</Callout>

## Na entrevista

Mencione checksums ao falar de durabilidade e integridade: "cada bloco é gravado com CRC32C; na leitura, se o checksum falhar, buscamos de outra réplica e disparamos reparo". Em uploads, cite verificação ponta a ponta. Follow-ups comuns: "CRC ou SHA-256?" (CRC para corrupção acidental, rápido; SHA-256 quando há risco de adulteração ou para endereçar conteúdo), "como achar quais dados divergem entre réplicas sem transferir tudo?" (Merkle trees).
