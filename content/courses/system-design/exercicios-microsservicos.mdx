<Quiz question="O app mobile faz 7 chamadas para montar a tela inicial e baixa campos que não usa, enquanto o site precisa de muito mais dados na mesma tela. Qual padrão ataca isso diretamente?" options={["Circuit breaker, que interrompe as chamadas a um serviço dependente enquanto ele falha","Backend for frontend (BFF), com uma camada de agregação própria para cada tipo de cliente","Bulkhead, que isola pools de recursos para que a falha de uma dependência não se espalhe","Strangler fig, que substitui aos poucos as funcionalidades de um sistema legado por novas"]} answer={1} explanation="Um BFF por experiência de cliente agrega as chamadas internas em paralelo e devolve só o que aquela interface precisa." />
<Quiz question="O serviço de frete ficou lento e o checkout, que usa um pool único de threads para todas as dependências, parou de responder até para compras com retirada na loja. Qual padrão teria contido o problema desde o início?" options={["Bulkhead, isolando um pool de threads ou semáforo para cada dependência externa chamada","API gateway, centralizando autenticação, limite de taxa e roteamento das requisições para os serviços","Sidecar de logs, coletando e enviando os registros de cada serviço para um sistema central","Strangler fig, desviando o tráfego do checkout gradualmente para uma implementação nova"]} answer={0} explanation="Com compartimentos separados, a lentidão do frete esgota só os recursos reservados a ele; o resto do checkout continua funcionando." />

<Quiz question="Qual destas responsabilidades é adequada para um API gateway?" options={["Calcular o desconto de um pedido com base nas regras comerciais da campanha vigente na loja online","Validar JWT, aplicar rate limiting e rotear as requisições por caminho para cada serviço","Manter o estado de sessão do carrinho de compras de cada cliente entre as requisições","Executar transações no banco de dados de pedidos garantindo a consistência dos itens"]} answer={1} explanation="O gateway concentra preocupações transversais de borda. Regras de domínio e estado devem ficar nos serviços." />
<Quiz question="Você precisa migrar um monólito crítico para microsserviços sem parar a operação. Qual a abordagem recomendada?" options={["Reescrever tudo do zero em microsserviços e trocar o sistema inteiro num fim de semana","Strangler fig: fachada na frente e extração incremental, desviando tráfego rota por rota","Congelar o monólito por dois anos enquanto uma equipe separada constrói toda a versão nova","Duplicar o monólito em vários servidores e dividir o tráfego entre as cópias idênticas do sistema"]} answer={1} explanation="O strangler fig dilui o risco, entrega valor continuamente e permite rollback por funcionalidade." />
<Quiz question="Sua empresa tem 300 serviços em quatro linguagens e a segurança exige mTLS em todo tráfego interno com políticas de quem pode chamar quem. Qual solução se encaixa melhor?" options={["Uma biblioteca de TLS para cada linguagem, mantida e atualizada separadamente por cada time dono","Um service mesh com identidade por serviço, mTLS automático e políticas de autorização entre eles","Um único API gateway na borda da rede, responsável por validar o mTLS de todas as chamadas internas","Regras de firewall por IP entre os serviços, ajustadas a cada mudança de endereço dos pods"]} answer={1} explanation="O mesh entrega mTLS e autorização uniformes via proxies, sem alterar o código, independente da linguagem." />
