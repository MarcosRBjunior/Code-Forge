Redes falham de um jeito traiçoeiro: às vezes a requisição chega, o servidor processa, e é a **resposta** que se perde. O cliente vê um timeout e não tem como saber se a operação aconteceu. A reação natural é tentar de novo. Se a operação for "cobrar R$ 300 no cartão", tentar de novo pode cobrar duas vezes. **Idempotência** é a propriedade que torna a retentativa segura: executar a mesma operação uma ou várias vezes produz o mesmo efeito no sistema.

## Definição precisa

Uma operação é idempotente se `f(f(x)) = f(x)`. Em APIs, isso significa que o **estado do servidor** depois de N requisições idênticas é igual ao estado depois de uma. A **resposta** pode variar: apagar um recurso pode devolver 204 na primeira vez e 404 na segunda, e a operação continua idempotente, porque o efeito (o recurso não existe) é o mesmo.

Não confunda com **segurança** (safe): uma operação segura não altera estado nenhum. Toda operação segura é idempotente, mas o contrário não vale.

## Métodos HTTP

| Método | Seguro | Idempotente | Observação |
| --- | --- | --- | --- |
| GET, HEAD, OPTIONS | Sim | Sim | Só leitura |
| PUT | Não | Sim | Substitui o recurso pelo conteúdo enviado |
| DELETE | Não | Sim | Apagar duas vezes deixa o recurso apagado |
| POST | Não | Não | Cada chamada pode criar algo novo |
| PATCH | Não | Depende | `definir saldo = 10` é idempotente; `somar 10 ao saldo` não é |

A especificação define a **intenção** de cada método. Cabe à sua implementação respeitá-la: um `PUT` que incrementa um contador viola o contrato.

## Tornando o POST idempotente: chaves de idempotência

O padrão mais usado (popularizado por gateways de pagamento) é o cliente gerar um identificador único por **intenção de operação** e enviá-lo num cabeçalho, como `Idempotency-Key`. O servidor guarda o resultado associado à chave e, se receber a mesma chave de novo, devolve o resultado salvo sem reexecutar.

```text
POST /v1/pagamentos
Idempotency-Key: 5f1c9a2e-7b44-4c1e-9d3a-0e2f6a8b1c77
Content-Type: application/json

{"pedido_id": 991, "valor": 300.00}
```

```java
import java.util.*;

// peças de apoio do exemplo: tabela de chaves, gateway e o hash do corpo
class Resposta {
    int codigo;
    String texto;
    Resposta(int codigo, String texto) { this.codigo = codigo; this.texto = texto; }
    public String toString() { return codigo + " " + texto; }
}

class Registro {
    boolean novo;
    String status;
    int hashCorpo;
    Resposta resposta;
}

static Map<String, Registro> registros = new HashMap<>();

static Registro inserirSeAusente(String chave, String status, int hashCorpo) {
    Registro r = registros.get(chave);
    if (r != null) {
        Registro copia = new Registro();
        copia.novo = false;
        copia.status = r.status;
        copia.hashCorpo = r.hashCorpo;
        copia.resposta = r.resposta;
        return copia;
    }
    r = new Registro();
    r.status = status;
    r.hashCorpo = hashCorpo;
    registros.put(chave, r);
    Registro novo = new Registro();
    novo.novo = true;
    novo.status = status;
    novo.hashCorpo = hashCorpo;
    return novo;
}

static void concluir(String chave, Resposta resposta, int expiraEmHoras) {
    Registro r = registros.get(chave);
    r.status = "concluido";
    r.resposta = resposta;
}

static Resposta cobrar(String corpo) { return new Resposta(200, "cobrado: " + corpo); }

static Resposta criarPagamento(String chave, String corpo) {
    // Insere a chave atomicamente; falha se já existir
    Registro registro = inserirSeAusente(chave, "processando", corpo.hashCode());
    if (!registro.novo) {
        if (registro.hashCorpo != corpo.hashCode()) {
            return new Resposta(422, "chave reutilizada com outro corpo");
        }
        if (registro.status.equals("processando")) {
            return new Resposta(409, "requisição em andamento, tente depois");
        }
        return registro.resposta;
    }

    Resposta resposta = cobrar(corpo);
    concluir(chave, resposta, 24);
    return resposta;
}

public static void main(String[] args) {
    System.out.println(criarPagamento("k1", "R$10"));
    System.out.println(criarPagamento("k1", "R$10")); // repetição: devolve a resposta salva
    System.out.println(criarPagamento("k1", "R$99")); // mesma chave, corpo diferente
}
```

```cpp
struct Resposta {
    int codigo;

    bool novo = false;
    string status;
    size_t hashCorpo = 0;
    Resposta resposta{0, ""};

map<string, Registro> registros;

Registro inserirSeAusente(const string& chave, const string& status, size_t hashCorpo) {
    auto it = registros.find(chave);
    if (it != registros.end()) {
        Registro copia = it->second;
        copia.novo = false;
        return copia;
    }
    Registro r;
    r.status = status;
    r.hashCorpo = hashCorpo;
    registros[chave] = r;
    r.novo = true;
    return r;
}

    registros[chave].status = "concluido";

}

    if (!registro.novo) {
        if (registro.hashCorpo != h) {

        }
        if (registro.status == "processando") {
            return {409, "requisição em andamento, tente depois"};
        }
        return registro.resposta;

    concluir(chave, resposta, 24);
    return resposta;
```

```go
package main

import (
	"fmt"
	"hash/fnv"
)

// peças de apoio do exemplo: tabela de chaves, gateway e o hash do corpo
type Resposta struct {
	codigo int
	texto  string
}

type Registro struct {
	novo      bool
	status    string
	hashCorpo uint32
	resposta  Resposta
}

var registros = map[string]*Registro{}

func hashDe(corpo string) uint32 {
	h := fnv.New32a()
	h.Write([]byte(corpo))
	return h.Sum32()
}

func inserirSeAusente(chave, status string, hashCorpo uint32) Registro {
	if r, ok := registros[chave]; ok {
		copia := *r
		copia.novo = false
		return copia
	}
	registros[chave] = &Registro{status: status, hashCorpo: hashCorpo}
	return Registro{novo: true, status: status, hashCorpo: hashCorpo}
}

func concluir(chave string, resposta Resposta, expiraEmHoras int) {
	registros[chave].status = "concluido"
	registros[chave].resposta = resposta
}

func cobrar(corpo string) Resposta { return Resposta{200, "cobrado: " + corpo} }

func criarPagamento(chave, corpo string) Resposta {
	// Insere a chave atomicamente; falha se já existir
	registro := inserirSeAusente(chave, "processando", hashDe(corpo))
	if !registro.novo {
		if registro.hashCorpo != hashDe(corpo) {
			return Resposta{422, "chave reutilizada com outro corpo"}
		}
		if registro.status == "processando" {
			return Resposta{409, "requisição em andamento, tente depois"}
		}
		return registro.resposta
	}

	resposta := cobrar(corpo)
	concluir(chave, resposta, 24)
	return resposta
}

func main() {
	fmt.Println(criarPagamento("k1", "R$10"))
	fmt.Println(criarPagamento("k1", "R$10")) // repetição: devolve a resposta salva
	fmt.Println(criarPagamento("k1", "R$99")) // mesma chave, corpo diferente
}
```

Detalhes que fazem diferença:

- **Inserção atômica:** use uma restrição `UNIQUE` ou `SET NX` no Redis. Checar e depois inserir abre janela para duas requisições simultâneas passarem.
- **Validar o corpo:** a mesma chave com payload diferente indica bug no cliente; rejeite.
- **Estado "em andamento":** evita que uma retentativa rápida dispare um segundo processamento enquanto o primeiro ainda roda.
- **Expiração:** as chaves não precisam viver para sempre; 24 horas a alguns dias cobre as retentativas realistas.
- **Mesma transação:** se possível, grave o efeito (o pagamento) e o registro da chave na mesma transação do banco.

## Outras técnicas

- **Identificador natural:** se cada pedido gera no máximo um pagamento, uma restrição única em `pedido_id` já impede duplicatas.
- **Upsert:** `INSERT ... ON CONFLICT DO UPDATE` transforma criação em operação idempotente.
- **Escritas condicionais:** com `ETag` e `If-Match`, a atualização só ocorre se o recurso estiver na versão esperada.
- **Deduplicação no consumidor:** em mensageria, o consumidor registra os IDs de mensagens já processadas, pois brokers costumam entregar ao menos uma vez.

<Callout type="warning" title="Retentativa sem idempotência é bug">
Clientes HTTP, SDKs, load balancers e service meshes fazem retry automático. Se o endpoint não é idempotente, alguma camada vai duplicar operações em produção, cedo ou tarde.
</Callout>

## Trade-offs

Guardar chaves custa armazenamento e uma escrita extra por requisição. A chave precisa ser gerada pelo **cliente** e reutilizada em cada retentativa da mesma intenção; se o cliente gerar uma chave nova a cada tentativa, o mecanismo não protege nada. E a idempotência local não resolve efeitos externos: se seu serviço chama outro sistema, ele também precisa ser idempotente ou receber a chave repassada.

## Na entrevista

Sempre que aparecer pagamento, reserva, envio de mensagem ou qualquer escrita com retry, cite idempotência espontaneamente. Explique a chave enviada pelo cliente, o armazenamento com restrição única e o TTL. Follow-ups prováveis: o que acontece com duas requisições simultâneas com a mesma chave, onde guardar as chaves e como isso se relaciona com entrega "pelo menos uma vez" em filas.
