Condicionais e laços são o esqueleto de qualquer solução. A sintaxe é a mesma do JavaScript; o que o TypeScript acrescenta é que o compilador acompanha o fluxo e refina os tipos dentro de cada ramo, o que também ajuda a descobrir ramos esquecidos.

## if, else e o operador ternário

Use `if` para decisões com efeito e o ternário para escolher um valor. Prefira retornos antecipados (guard clauses) a `else` aninhado: o código fica plano e os casos de borda saem logo do caminho.

```typescript
function classificar(n: number): string {
  if (n < 0) return "negativo";
  if (n === 0) return "zero";
  return n % 2 === 0 ? "par" : "ímpar";
}

console.log(classificar(-3), classificar(0), classificar(7), classificar(10));
```

```text
Saída:
negativo zero ímpar par
```

## Laços: for, while e for...of

Para índices use o `for` clássico. Para percorrer valores, `for...of` é mais limpo. Já `for...in` percorre as chaves (como texto) de um objeto e, em arrays, entrega índices em formato de string; evite em arrays.

```typescript
const nums: number[] = [5, 3, 8];

for (let i = 0; i < nums.length; i++) {
  console.log("indice", i, "valor", nums[i]);
}

let soma = 0;
for (const n of nums) soma += n;
console.log("soma", soma);

let k = 10;
while (k > 1) k = Math.floor(k / 2);
console.log("k", k);

for (const i in nums) console.log(typeof i);
```

```text
Saída:
indice 0 valor 5
indice 1 valor 3
indice 2 valor 8
soma 16
k 1
string
string
string
```

O último laço mostra por que `for...in` engana: `i` é `string`, não `number`. Para ter índice e valor juntos, use `nums.forEach((valor, i) => ...)` ou um `for` clássico.

## break, continue e rótulos

`break` sai do laço e `continue` pula para a próxima volta. Para sair de laços aninhados existem rótulos, mas em geral uma função auxiliar com `return` é mais legível.

```typescript
function achaPar(m: number[][]): [number, number] | null {
  for (let i = 0; i < m.length; i++) {
    for (let j = 0; j < m[i].length; j++) {
      if (m[i][j] % 2 === 0) return [i, j];
    }
  }
  return null;
}

const r = achaPar([[1, 3], [5, 6]]);
console.log(r === null ? "nenhum" : r.join(","));
```

```text
Saída:
1,1
```

## switch e exaustividade

O `switch` compara com `===` e precisa de `break`, senão cai no próximo caso (fallthrough). Combinado com uniões de literais, ele permite uma checagem de exaustividade: se você esquece um caso, o compilador acusa o erro.

```typescript
type Dia = "seg" | "sab" | "dom";

function tipoDeDia(d: Dia): string {
  switch (d) {
    case "seg":
      return "util";
    case "sab":
    case "dom":
      return "fim de semana";
    default: {
      const nunca: never = d;
      return nunca;
    }
  }
}

console.log(tipoDeDia("seg"), tipoDeDia("dom"));
```

```text
Saída:
util fim de semana
```

Se alguém adicionar `"ter"` à união sem tratar o caso, a linha `const nunca: never = d` deixa de compilar e aponta o ponto exato do esquecimento. É um truque barato que impressiona.

## Armadilhas

- Um laço `for` com `let` cria uma variável nova por volta, o que evita o bug clássico de closures com `var`.
- Alterar o array enquanto você o percorre (por exemplo com `splice`) pula elementos; itere de trás para frente ou monte um novo array.
- `forEach` ignora `break` e `return` do laço: o `return` só sai da função de callback. Se precisa interromper, use `for...of`.

## Na entrevista

Prefira condições simples e retornos antecipados, e nomeie as variáveis de índice quando houver mais de um laço. Perguntas comuns: "como sair de dois laços aninhados?" (função com `return` ou rótulo) e "por que `forEach` não aceita `break`?" (é uma chamada de função com callback, não uma estrutura de controle).
