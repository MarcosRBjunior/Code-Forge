Você escreve uma solução com um único laço e diz "é O(n)". O entrevistador aponta para um `shift()` dentro do laço e pergunta: "tem certeza?". Métodos da biblioteca padrão escondem custo. Saber o que cada um faz por baixo é o que separa uma análise de complexidade correta de uma chutada, e o TypeScript não muda nada aqui: em execução é tudo JavaScript.

## Arrays

Um array de JavaScript é, na prática, um vetor dinâmico contíguo. Mexer no fim é barato; mexer no começo ou no meio desloca todos os elementos seguintes.

| Operação | Custo | Observação |
| --- | --- | --- |
| `a[i]`, `a[i] = x`, `a.length` | O(1) | acesso direto |
| `push`, `pop` | O(1) amortizado | o array cresce em blocos |
| `shift`, `unshift` | O(n) | desloca todos os elementos |
| `splice(i, k)` | O(n) | desloca o que vem depois de `i` |
| `indexOf`, `includes`, `find` | O(n) | busca linear |
| `slice`, `concat`, `[...a]` | O(k) | copia k elementos |
| `sort` | O(n log n) | e ordena como texto por padrão |
| `reverse`, `map`, `filter`, `join` | O(n) | percorrem tudo |

O caso mais traiçoeiro é a fila. Em Python você usaria `deque`; em JavaScript não existe um equivalente nativo, e `shift()` é O(n). Numa BFS com milhões de nós, isso transforma O(n) em O(n²). A saída barata é manter um índice de cabeça e nunca remover do começo:

```typescript
function bfsDistancias(adj: number[][], origem: number): number[] {
  const dist: number[] = new Array(adj.length).fill(-1);
  const fila: number[] = [origem];
  let cabeca = 0; // em vez de fila.shift(), que é O(n)
  dist[origem] = 0;
  while (cabeca < fila.length) {
    const u = fila[cabeca++];
    for (const v of adj[u]) {
      if (dist[v] === -1) {
        dist[v] = dist[u] + 1;
        fila.push(v);
      }
    }
  }
  return dist;
}

const grafo = [[1, 2], [3], [3], [4], []];
console.log(bfsDistancias(grafo, 0).join(" "));
```

```text
Saída:
0 1 1 2 3
```

## Map, Set e objetos

`Map` e `Set` são tabelas hash: `get`, `set`, `has` e `delete` custam O(1) em média. Objetos comuns usados como dicionário também, mas convertem toda chave para string. Por isso, quando a chave é um número ou par de números, `Map` evita conversões e surpresas. Iterar, por outro lado, é O(n), assim como `Array.from(mapa.keys())`.

Um erro clássico é usar `includes` dentro de um laço para checar se algo "já foi visto". Isso é O(n) por consulta e leva a solução a O(n²). Troque por um `Set`:

```typescript
function temDuplicadoLento(nums: number[]): boolean {
  const vistos: number[] = [];
  for (const n of nums) {
    if (vistos.includes(n)) return true; // O(n) por consulta
    vistos.push(n);
  }
  return false;
}

function temDuplicado(nums: number[]): boolean {
  const vistos = new Set<number>();
  for (const n of nums) {
    if (vistos.has(n)) return true; // O(1) em média
    vistos.add(n);
  }
  return false;
}

console.log(temDuplicadoLento([3, 1, 4, 1]), temDuplicado([3, 1, 4, 1]));
console.log(temDuplicado([1, 2, 3]));
```

```text
Saída:
true true
false
```

## Strings

Strings são imutáveis. Cada concatenação cria uma nova string, e `slice` e `substring` copiam o trecho, custando O(k). Motores modernos otimizam `s += x` em laços com estruturas internas, então na prática isso costuma ser rápido, mas a forma segura e fácil de justificar é acumular pedaços num array e fazer um `join` no fim, O(n) no total.

Outros custos: `split` e `indexOf` são O(n); comparar duas strings com `===` é O(n) no pior caso; `s[i]` e `s.length` são O(1).

## Heap e ordenação

Não há fila de prioridade nativa. Se o problema pede "os k menores" ou Dijkstra, você precisa escrever um heap binário (O(log n) por inserção e remoção) ou justificar uma alternativa, como ordenar uma vez em O(n log n). Ordenar dentro de um laço, a cada inserção, é O(n² log n) e quase sempre está errado.

<Callout type="warning" title="O sort ordena como texto">
`[10, 9, 1].sort()` devolve `[1, 10, 9]`. Para números passe sempre um comparador: `a.sort((x, y) => x - y)`. O custo continua O(n log n).
</Callout>

## Na entrevista

Ao terminar a solução, percorra o código linha por linha e diga o custo de cada chamada da biblioteca dentro dos laços. Citar espontaneamente "não uso `shift` porque é linear; uso um índice de cabeça" mostra maturidade. Se for usar `sort`, inclua o O(n log n) na análise final.

Follow-ups comuns: "qual o custo do `push` e por que se diz amortizado?" (de vez em quando o array realoca e copia tudo, mas na média por operação o custo é constante) e "o seu `Map` pode degradar?" (em teoria, com muitas colisões, mas na prática assume-se O(1) médio).
