Entrevistas usam classes em dois contextos: problemas de design de estrutura (LRU cache, MinStack, Trie) e perguntas de orientação a objetos. As classes do JavaScript ganham no TypeScript tipos nos campos, modificadores de acesso e a palavra-chave `implements`, que deixam o contrato explícito.

## Campos, construtor e métodos

Todo campo precisa ser declarado com tipo. O construtor inicializa e os métodos operam sobre `this`. O exemplo abaixo é o clássico MinStack, uma pilha que devolve o mínimo em O(1).

```typescript
class MinStack {
  private dados: number[] = [];
  private minimos: number[] = [];

  push(x: number): void {
    this.dados.push(x);
    const m = this.minimos.length === 0 ? x : Math.min(x, this.minimos[this.minimos.length - 1]);
    this.minimos.push(m);
  }

  pop(): void {
    this.dados.pop();
    this.minimos.pop();
  }

  top(): number { return this.dados[this.dados.length - 1]; }
  getMin(): number { return this.minimos[this.minimos.length - 1]; }
}

const s = new MinStack();
s.push(5); s.push(2); s.push(7);
console.log(s.top(), s.getMin());
s.pop(); s.pop();
console.log(s.top(), s.getMin());
```

```text
Saída:
7 2
5 5
```

## Modificadores de acesso e parameter properties

- `public` (padrão): acessível de fora.
- `private`: só dentro da classe.
- `protected`: na classe e nas subclasses.
- `readonly`: atribuído uma vez, no construtor ou na declaração.

Escrever um modificador no parâmetro do construtor cria e atribui o campo de uma vez (parameter property), o que economiza linhas em entrevista.

```typescript
class Conta {
  private saldo = 0;
  constructor(readonly titular: string, private limite: number) {}

  depositar(v: number): void { this.saldo += v; }

  sacar(v: number): boolean {
    if (v > this.saldo + this.limite) return false;
    this.saldo -= v;
    return true;
  }

  extrato(): string { return this.titular + ": " + this.saldo; }
}

const c = new Conta("Ana", 100);
c.depositar(50);
console.log(c.sacar(120), c.extrato());
console.log(c.sacar(100), c.extrato());
// c.saldo = 1000;  // erro: saldo é private
```

```text
Saída:
true Ana: -70
false Ana: -70
```

Atenção: `private` do TypeScript é só checagem de compilação. Em execução o campo existe normalmente. Para privacidade real, o JavaScript tem campos com `#`, que exigem um alvo de compilação ES2015 ou mais recente.

## Herança, classes abstratas e implements

`extends` herda implementação; `abstract` declara métodos que as subclasses são obrigadas a implementar; `implements` só verifica se a classe cumpre uma interface, sem herdar nada.

```typescript
interface Forma {
  area(): number;
  nome(): string;
}

abstract class Base implements Forma {
  abstract area(): number;
  nome(): string { return "forma"; }
  descrever(): string { return this.nome() + " com area " + this.area().toFixed(2); }
}

class Quadrado extends Base {
  constructor(private lado: number) { super(); }
  area(): number { return this.lado * this.lado; }
  nome(): string { return "quadrado"; }
}

class Circulo extends Base {
  constructor(private raio: number) { super(); }
  area(): number { return Math.PI * this.raio * this.raio; }
}

const formas: Forma[] = [new Quadrado(3), new Circulo(1)];
for (const f of formas) console.log((f as Base).descrever());
```

```text
Saída:
quadrado com area 9.00
forma com area 3.14
```

Nas subclasses, `super()` precisa ser chamado antes de usar `this`. O polimorfismo funciona como em qualquer linguagem orientada a objetos: `descrever` chama a `area` da subclasse real.

## Membros estáticos e o problema do this

Membros `static` pertencem à classe, não às instâncias, e são bons para contadores e fábricas. O cuidado clássico é o `this` perdido: passar `obj.metodo` como callback desliga o método do objeto. Use uma arrow function (`() => obj.metodo()`) ou declare o método como propriedade arrow.

## Armadilhas

- Esquecer de inicializar campos no modo estrito gera erro; inicialize na declaração ou no construtor.
- Classes também são tipos estruturais: um objeto literal com os mesmos membros públicos é aceito onde a classe é esperada, desde que ela não tenha membros `private`.
- Herança profunda complica; em design de entrevista, prefira composição.

## Na entrevista

Em problemas de design (LRU, Trie, MinStack), escreva a classe com campos `private`, construtor curto e métodos com tipos explícitos, e diga a complexidade de cada método. Follow-ups comuns: "o `private` do TypeScript protege em execução?" (não, só o `#` protege) e "quando usar classe abstrata em vez de interface?" (quando há implementação compartilhada).
