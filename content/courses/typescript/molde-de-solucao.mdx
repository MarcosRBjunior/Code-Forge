Numa entrevista de código, o avaliador olha duas coisas ao mesmo tempo: se a resposta está certa e como você chegou nela. Um código organizado, com tipos claros e testes rápidos, deixa as duas visíveis. Ter um molde pronto na cabeça evita perder minutos decidindo como começar, e o TypeScript ajuda porque a assinatura tipada já documenta o contrato.

## O roteiro

1. **Entenda e confirme.** Repita o problema, pergunte limites (tamanho da entrada, valores negativos, duplicados, entrada vazia) e escreva dois exemplos, incluindo uma borda.
2. **Fale a ideia antes do código.** Comece pela força bruta e sua complexidade, depois proponha a melhoria. Espere o entrevistador concordar.
3. **Escreva a assinatura tipada.** `function maisFrequentes(nums: number[], k: number): number[]` responde metade das dúvidas sobre o formato.
4. **Implemente com funções pequenas.** Um auxiliar com nome bom vale mais que um comentário.
5. **Teste com os exemplos**, rastreando à mão ou rodando, e verifique as bordas.
6. **Dê a complexidade final** de tempo e espaço, incluindo o custo das chamadas da biblioteca.

## O molde em código

Um arquivo de solução tem três partes: tipos auxiliares (se houver), a função principal e um bloco de testes que compara o obtido com o esperado.

```typescript
// Dado um array e um alvo, devolva os índices de dois números que somam o alvo.
// Ideia: um Map de valor para índice; para cada x, procure alvo - x. O(n) tempo e espaço.
function doisSomam(nums: number[], alvo: number): [number, number] | null {
  const indicePorValor = new Map<number, number>();
  for (let i = 0; i < nums.length; i++) {
    const falta = alvo - nums[i];
    const j = indicePorValor.get(falta);
    if (j !== undefined) {
      return [j, i];
    }
    indicePorValor.set(nums[i], i);
  }
  return null;
}

function testar(nome: string, obtido: unknown, esperado: unknown): void {
  const ok = JSON.stringify(obtido) === JSON.stringify(esperado);
  console.log((ok ? "ok    " : "FALHOU") + " " + nome + " -> " + JSON.stringify(obtido));
}

testar("exemplo", doisSomam([2, 7, 11, 15], 9), [0, 1]);
testar("repetido", doisSomam([3, 3], 6), [0, 1]);
testar("sem resposta", doisSomam([1, 2], 10), null);
testar("vazio", doisSomam([], 0), null);
```

```text
Saída:
ok     exemplo -> [0,1]
ok     repetido -> [0,1]
ok     sem resposta -> null
ok     vazio -> null
```

Detalhes que contam pontos: o tipo de retorno `[number, number] | null` deixa explícito o caso "não existe"; a comparação `j !== undefined` evita a armadilha do índice `0` ser falsy; o comentário de duas linhas no topo registra a ideia e a complexidade.

## Estruturas próprias

Se a solução precisa de uma estrutura que a linguagem não tem (heap, union-find, trie), escreva-a como uma classe pequena antes da função principal, com só os métodos necessários. O entrevistador quer ver que você sabe montá-la, não uma biblioteca completa.

```typescript
class UniaoBusca {
  private pai: number[];

  constructor(n: number) {
    this.pai = Array.from({ length: n }, (_, i) => i);
  }

  achar(x: number): number {
    while (this.pai[x] !== x) {
      this.pai[x] = this.pai[this.pai[x]]; // compressão de caminho
      x = this.pai[x];
    }
    return x;
  }

  unir(a: number, b: number): boolean {
    const ra = this.achar(a);
    const rb = this.achar(b);
    if (ra === rb) return false;
    this.pai[ra] = rb;
    return true;
  }
}

function componentes(n: number, arestas: [number, number][]): number {
  const ub = new UniaoBusca(n);
  let total = n;
  for (const [a, b] of arestas) {
    if (ub.unir(a, b)) total--;
  }
  return total;
}

console.log(componentes(5, [[0, 1], [1, 2], [3, 4]]));
console.log(componentes(4, []));
console.log(componentes(3, [[0, 1], [1, 2], [2, 0]]));
```

```text
Saída:
2
4
1
```

## Armadilhas de organização

- Escrever tudo dentro de uma função de 60 linhas. Extraia auxiliares assim que um bloco tiver um nome natural.
- Tipar tudo com `any` para "ganhar tempo". Você perde a ajuda do compilador justo quando mais precisa dela.
- Variáveis globais mutáveis compartilhadas entre testes, que fazem o segundo teste herdar o estado do primeiro.
- Otimizar antes de ter uma versão correta. Uma força bruta funcionando é um ponto de partida; uma solução ótima pela metade não é.

<Callout type="tip" title="Narração">
Fale enquanto digita: "agora trato o caso vazio", "este laço mantém a invariante de que tudo à esquerda de i já foi visto". Se você travar, o entrevistador consegue ajudar porque sabe onde você está.
</Callout>

## Na entrevista

Combine o roteiro com o tempo disponível: em 45 minutos, cerca de 5 para entender, 5 para a ideia, 20 para codificar e o restante para testar e discutir. Se o tempo apertar, diga o que faltaria testar.

Follow-ups comuns: "e se a entrada não couber na memória?" e "como você testaria isso em produção?" (testes unitários com casos de borda, testes de propriedade comparando com a força bruta em entradas aleatórias pequenas).
