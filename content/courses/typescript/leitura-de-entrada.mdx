Em plataformas como o LeetCode você só preenche uma função. Mas testes online de algumas empresas, maratonas e juízes como Codeforces e HackerRank pedem um programa completo que lê da entrada padrão e escreve na saída padrão. Em Python você faria `input()` ou `sys.stdin.read()`. Em TypeScript, rodando em Node, não há um `input()` síncrono pronto, e saber o padrão de leitura economiza minutos preciosos.

## Ler tudo de uma vez

O jeito mais simples e rápido é ler a entrada inteira como texto e depois quebrá-la. Em Node, `readFileSync(0, "utf8")` lê o descritor 0, que é a entrada padrão. Como os exemplos aqui não importam tipos de módulos do Node, declaramos `require` para o compilador aceitar a chamada.

```typescript
declare const require: any;

function lerEntrada(): string {
  try {
    return require("fs").readFileSync(0, "utf8");
  } catch (e) {
    return "";
  }
}

// usa um exemplo fixo quando a entrada vier vazia, útil para testar localmente
const texto = lerEntrada().trim() || "3\n10 20 30";
const tokens = texto.split(/\s+/);
let pos = 0;
const proximo = (): string => tokens[pos++];

const n = Number(proximo());
let soma = 0;
for (let i = 0; i < n; i++) {
  soma += Number(proximo());
}
console.log("n =", n, "soma =", soma);
```

```text
Saída:
n = 3 soma = 60
```

Quebrar por `/\s+/` (qualquer sequência de espaços e quebras de linha) e consumir os tokens com um ponteiro torna o código indiferente ao layout: tanto faz se os números vêm na mesma linha ou em linhas separadas. O `trim()` antes evita um token vazio no começo ou no fim. Sem ele, um arquivo terminado em quebra de linha produz uma string vazia, e `Number("")` vale `0`, um erro silencioso.

## Ler por linhas

Quando a estrutura da linha importa (texto com espaços, uma grade de caracteres), divida por linhas. Lembre do `\r` de arquivos gerados no Windows.

```typescript
function parseGrade(entrada: string): { linhas: number; colunas: number; grade: string[][] } {
  const linhas = entrada.trim().split(/\r?\n/);
  const [l, c] = linhas[0].split(" ").map(Number);
  const grade = linhas.slice(1, 1 + l).map((linha) => linha.split(""));
  return { linhas: l, colunas: c, grade };
}

const exemplo = "3 4\r\n#..#\r\n....\r\n.##.\r\n";
const { linhas, colunas, grade } = parseGrade(exemplo);

let paredes = 0;
for (const linha of grade) {
  for (const celula of linha) {
    if (celula === "#") paredes++;
  }
}
console.log(linhas, colunas, paredes);
console.log(grade[2].join(""));
```

```text
Saída:
3 4 4
.##.
```

Separar o parsing numa função que recebe uma string (em vez de ler a entrada lá dentro) tem uma vantagem extra: você testa com exemplos fixos no próprio código, sem precisar de arquivos.

## Escrever a saída

`console.log` adiciona uma quebra de linha e é lento quando chamado centenas de milhares de vezes. Acumule as linhas num array e imprima uma vez no fim com `join("\n")`. Isso costuma ser a diferença entre passar e estourar o tempo em problemas com muitas consultas.

```typescript
// lento com 1e5 consultas:
// for (const q of consultas) console.log(responder(q));

// rápido:
// const saida: string[] = [];
// for (const q of consultas) saida.push(String(responder(q)));
// console.log(saida.join("\n"));
```

## E o readline?

O módulo `readline` lê linha a linha por eventos. Ele é útil para entradas interativas ou gigantes, mas exige lidar com callbacks ou `for await`, o que complica um problema simples. Para juízes online, ler tudo de uma vez é o padrão mais seguro, e o limite de memória raramente é problema para a entrada.

<Callout type="warning" title="Números grandes na entrada">
`Number("12345678901234567890")` perde precisão em silêncio. Se a entrada pode passar de 2 elevado a 53, leia o token como string e converta com `BigInt(token)`.
</Callout>

## Na entrevista

Se o formato for "programa completo", escreva primeiro o leitor de tokens (quatro linhas que você deve saber de cor) e só depois a lógica, numa função separada que recebe valores já convertidos. Confirme com o entrevistador o formato exato: há uma linha com a quantidade de casos? Os números vêm separados por espaço ou por linha?

Follow-ups comuns: "por que sua solução estoura o tempo com 1e5 linhas de saída?" (muitas chamadas a `console.log`) e "como você leria uma entrada de vários gigabytes?" (em fluxo, com `readline` ou lendo blocos do stream).
