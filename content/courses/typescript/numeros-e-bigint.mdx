Em Python, `int` cresce sem limite e a divisão inteira é `//`. Em JavaScript e TypeScript, quase tudo é `number`: um ponto flutuante de 64 bits (IEEE 754). Não existe tipo inteiro separado, e isso tem consequências diretas em problemas de entrevista: somas grandes perdem precisão, divisão não trunca e respostas "módulo 1e9+7" podem sair erradas sem nenhum aviso.

## O que um number consegue representar

Um `number` guarda inteiros exatos até 2 elevado a 53 menos 1, o valor de `Number.MAX_SAFE_INTEGER` (cerca de 9 quatrilhões). Acima disso, inteiros vizinhos passam a ter a mesma representação. Frações decimais como 0,1 não têm representação binária exata.

```typescript
console.log(0.1 + 0.2);
console.log(0.1 + 0.2 === 0.3);
console.log(Math.abs(0.1 + 0.2 - 0.3) < 1e-9);

const limite = Number.MAX_SAFE_INTEGER;
console.log(limite);
console.log(limite + 1 === limite + 2);
console.log(Number.isSafeInteger(limite + 1));

console.log(7 / 2, Math.floor(7 / 2), Math.trunc(-7 / 2), Math.floor(-7 / 2));
console.log(-7 % 3, ((-7 % 3) + 3) % 3);
```

```text
Saída:
0.30000000000000004
false
true
9007199254740991
true
false
3.5 3 -3 -4
-1 2
```

Leia linha a linha:

- Compare decimais com uma tolerância (`1e-9`), nunca com `===`.
- Passado o limite seguro, `limite + 1` e `limite + 2` dão o mesmo número.
- `/` sempre devolve fração. Para divisão inteira use `Math.floor` (arredonda para baixo, igual ao `//` do Python) ou `Math.trunc` (corta em direção a zero, como em Java e C). Com negativos eles diferem.
- `%` mantém o sinal do dividendo: `-7 % 3` é `-1`, não `2` como em Python. Para um resto sempre positivo, some o módulo e aplique `%` de novo.

Operadores de bits (`|`, `&`, `>>`, `<<`) convertem para inteiro de 32 bits com sinal. O truque `x | 0` para truncar funciona só até cerca de 2,1 bilhões, então prefira `Math.trunc`.

## Módulo 1e9+7 e multiplicação

Muitos problemas pedem a resposta módulo 1.000.000.007. Somar dois valores já reduzidos é seguro, pois o resultado fica abaixo de 2,1 bilhões. Multiplicar não é: o produto de dois números próximos de 1e9 chega a 1e18, bem acima do limite seguro, e os últimos dígitos se perdem antes do `%`.

## BigInt

`bigint` é um tipo primitivo separado, com inteiros de precisão arbitrária. Você cria um com o sufixo `n` (`10n`) ou com a função `BigInt(...)`. Os operadores aritméticos funcionam, a divisão trunca e não há como misturar com `number` sem conversão explícita: `BigInt(1) + 1` não compila.

```typescript
const MOD = 1000000007;

function mulModErrado(a: number, b: number): number {
  return (a * b) % MOD;
}

function mulMod(a: number, b: number): number {
  return Number((BigInt(a) * BigInt(b)) % BigInt(MOD));
}

const a = 999999999;
const b = 999999998;
console.log(mulModErrado(a, b));
console.log(mulMod(a, b));

let fatorial = BigInt(1);
for (let i = 1; i <= 25; i++) {
  fatorial = fatorial * BigInt(i);
}
console.log(fatorial.toString());
console.log(String(BigInt(7) / BigInt(2)), typeof fatorial);
```

```text
Saída:
70
72
15511210043330985984000000
3 bigint
```

A versão com `number` devolveu 70; a correta é 72. Nenhum erro foi lançado: o produto, perto de 1e18, já tinha perdido os últimos dígitos antes do `%`. É o pior tipo de bug, porque passa em exemplos pequenos e falha nos testes escondidos. A regra: se um valor intermediário pode passar de `Number.MAX_SAFE_INTEGER`, use `BigInt` nesse trecho (ou uma multiplicação modular que divide um dos fatores em partes menores). O fatorial de 25 também mostra o ganho: são 26 dígitos exatos, impossíveis com `number`.

Na saída, `String(...)` e `toString()` evitam o sufixo `n` que o `console.log` do Node mostra ao imprimir um `bigint` diretamente.

<Callout type="warning" title="Custo do BigInt">
Operações com `bigint` são bem mais lentas que com `number`. Use só onde o valor realmente pode estourar, como a multiplicação modular, e converta de volta com `Number(...)` assim que o valor couber.
</Callout>

## Na entrevista

Antes de codificar, estime o maior valor intermediário. Se a soma de n até 1e5 elementos de até 1e9 cabe (1e14 é menor que 9e15), diga isso. Se há multiplicação de dois valores grandes ou fatoriais, avise que vai usar `BigInt`. Para divisão inteira, diga se quer `floor` ou `trunc`.

Follow-ups comuns: "por que `0.1 + 0.2` não dá `0.3`?" (representação binária de ponto flutuante) e "como você checaria overflow?" (comparando com `Number.MAX_SAFE_INTEGER` ou com `Number.isSafeInteger`).
