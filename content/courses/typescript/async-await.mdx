Cadeias de `then` resolvem a escada de callbacks, mas ainda deixam o código fragmentado: variáveis intermediárias precisam ser passadas de elo em elo e laços com passos assíncronos ficam desajeitados. `async` e `await` são uma sintaxe sobre Promises que permite escrever código assíncrono com a cara de código sequencial.

## Como funciona

Uma função marcada com `async` sempre devolve uma Promise. No TypeScript, o tipo de retorno é anotado como `Promise<T>`, mesmo que o corpo faça `return` de um `T` simples. Dentro dela, `await expressao` pausa a função até a Promise terminar e entrega o valor resolvido. Se a Promise rejeitar, o `await` lança o erro, que você captura com `try` e `catch` comuns.

```typescript
function buscarUsuario(id: number): Promise<{ id: number; nome: string }> {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (id <= 0) {
        reject(new Error("id inválido: " + id));
      } else {
        resolve({ id, nome: "usuario" + id });
      }
    }, 10);
  });
}

async function saudar(id: number): Promise<string> {
  try {
    const u = await buscarUsuario(id);
    return "olá, " + u.nome;
  } catch (e) {
    return e instanceof Error ? "falhou: " + e.message : "falhou";
  }
}

async function main(): Promise<void> {
  console.log(await saudar(7));
  console.log(await saudar(0));
}

main();
```

```text
Saída:
olá, usuario7
falhou: id inválido: 0
```

O `await` só pausa a função `async` em que está, não o programa inteiro. Enquanto ela espera, o event loop atende outras tarefas. Por isso `main()` é chamada sem `await` no fim: em scripts compilados para alvos antigos não há `await` no nível superior, e o padrão é envolver tudo numa função `main`.

## Sequencial versus paralelo

O erro mais comum com `await` é serializar sem querer operações independentes. Cada `await` em linha espera a anterior terminar. Se as operações não dependem umas das outras, dispare todas primeiro e depois espere juntas com `Promise.all`.

```typescript
function tarefa(nome: string, ms: number): Promise<string> {
  return new Promise((resolve) => setTimeout(() => resolve(nome), ms));
}

async function sequencial(): Promise<number> {
  const inicio = Date.now();
  await tarefa("a", 50);
  await tarefa("b", 50);
  await tarefa("c", 50);
  return Date.now() - inicio;
}

async function paralelo(): Promise<number> {
  const inicio = Date.now();
  await Promise.all([tarefa("a", 50), tarefa("b", 50), tarefa("c", 50)]);
  return Date.now() - inicio;
}

async function main(): Promise<void> {
  const s = await sequencial();
  const p = await paralelo();
  console.log("sequencial levou 150 ms ou mais:", s >= 145);
  console.log("paralelo levou menos de 120 ms:", p < 120);
}

main();
```

```text
Saída:
sequencial levou 150 ms ou mais: true
paralelo levou menos de 120 ms: true
```

A versão sequencial soma os tempos; a paralela leva o tempo da mais lenta.

## Laços com await

Dentro de um `for` comum, `await` funciona como esperado e processa um item por vez. Já `forEach` com callback `async` não espera nada: ele dispara as funções e segue em frente. Se a ordem importa, use `for`; se não importa e você quer velocidade, use `map` seguido de `Promise.all`.

```typescript
// processa em ordem, um de cada vez
// for (const id of ids) { await salvar(id); }

// dispara tudo e espera o conjunto
// await Promise.all(ids.map((id) => salvar(id)));

// ERRADO: forEach não espera os callbacks async
// ids.forEach(async (id) => { await salvar(id); });
```

## Armadilhas

- Esquecer o `await` faz a variável receber a Promise, não o valor. O TypeScript ajuda aqui: tentar ler `.nome` de uma `Promise<Usuario>` não compila.
- Um `try` sem `await` não captura a rejeição. `try { return buscar(); }` deixa o erro escapar; `try { return await buscar(); }` o captura.
- Toda função que usa `await` precisa ser `async`, e isso "contamina" quem a chama.

<Callout type="warning" title="Promise flutuante">
Chamar uma função `async` sem `await` e sem `catch` gera uma Promise "flutuante": se ela rejeitar, ninguém trata o erro. Linters costumam ter uma regra só para isso.
</Callout>

## Na entrevista

Em perguntas de Node ou front-end, escreva com `async` e `await` por padrão: fica mais legível e o entrevistador acompanha o raciocínio. Mostre que você sabe quando paralelizar ("essas três chamadas são independentes, então uso `Promise.all`") e onde colocar o `try`.

Follow-ups comuns: "o `await` bloqueia a thread?" (não, só suspende a função) e "como limitar a 3 requisições simultâneas?" (um pool de workers que puxam da mesma fila de tarefas, cada um com um laço `while` e `await`).
