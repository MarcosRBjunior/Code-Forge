Em entrevista, a assinatura da função é a metade do problema: ela diz o que entra, o que sai e quais casos existem. O TypeScript torna essa assinatura verificável, e o resto da linguagem (arrow functions, closures, recursão) é o JavaScript que você já conhece.

## Parâmetros e retorno tipados

Anote cada parâmetro e o retorno. O retorno pode ser inferido, mas escrevê-lo evita que um `return` esquecido mude o tipo sem você perceber. Funções que não devolvem nada usam `void`.

```typescript
function media(nums: number[]): number {
  if (nums.length === 0) return 0;
  let soma = 0;
  for (const n of nums) soma += n;
  return soma / nums.length;
}

function registrar(msg: string): void {
  console.log("[log] " + msg);
}

registrar("media = " + media([2, 4, 9]));
```

```text
Saída:
[log] media = 5
```

## Parâmetros opcionais, padrão e rest

Um parâmetro com `?` é opcional e chega como `undefined` se omitido. Um valor padrão dispensa o `?`. O parâmetro rest recolhe o restante dos argumentos num array. Parâmetros opcionais precisam vir depois dos obrigatórios.

```typescript
function potencia(base: number, expoente: number = 2): number {
  return Math.pow(base, expoente);
}

function somaTudo(...valores: number[]): number {
  return valores.reduce((acc, v) => acc + v, 0);
}

function saudar(nome: string, titulo?: string): string {
  return titulo ? titulo + " " + nome : nome;
}

console.log(potencia(3), potencia(2, 5));
console.log(somaTudo(1, 2, 3, 4));
console.log(saudar("Lima"), saudar("Lima", "Dra."));
```

```text
Saída:
9 32
10
Lima Dra. Lima
```

## Arrow functions e tipos de função

As arrow functions são curtas e herdam o `this` do contexto. Para tipar uma função passada como argumento, descreva a assinatura: `(x: number) => boolean`. Isso permite funções de ordem superior bem tipadas.

```typescript
type Predicado = (x: number) => boolean;

function filtrar(nums: number[], ok: Predicado): number[] {
  const saida: number[] = [];
  for (const n of nums) if (ok(n)) saida.push(n);
  return saida;
}

const ehPar: Predicado = (x) => x % 2 === 0;
console.log(filtrar([1, 2, 3, 4, 5, 6], ehPar).join(","));
console.log(filtrar([10, 20, 30], (x) => x > 15).join(","));
```

```text
Saída:
2,4,6
20,30
```

Repare que em `const ehPar: Predicado = (x) => ...` o parâmetro `x` não precisa de anotação: o tipo vem do contexto.

## Recursão e closures

Recursão é central em árvores, backtracking e programação dinâmica. O JavaScript não faz otimização de chamada em cauda de forma confiável, então uma recursão muito profunda (dezenas de milhares de níveis) estoura a pilha com `RangeError`. Closures permitem guardar estado, como um cache de memoização.

```typescript
function criaFibonacci(): (n: number) => number {
  const memo: { [n: number]: number } = {};
  function fib(n: number): number {
    if (n < 2) return n;
    if (memo[n] !== undefined) return memo[n];
    memo[n] = fib(n - 1) + fib(n - 2);
    return memo[n];
  }
  return fib;
}

const fib = criaFibonacci();
console.log(fib(10), fib(50));
```

```text
Saída:
55 12586269025
```

O cache vive na closure: cada chamada de `criaFibonacci` produz um `memo` independente. Sem ele, `fib(50)` levaria um tempo exponencial.

## Sobrecarga e this

TypeScript permite declarar várias assinaturas para uma função (sobrecarga), mas uma união como `string | number` costuma ser mais simples. Quanto ao `this`, funções comuns recebem o valor conforme a chamada; arrow functions usam o do escopo onde foram escritas. Em entrevista, prefira arrow functions dentro de métodos para não perder o `this`.
