Os operadores do TypeScript são os do JavaScript, e é aí que mora o perigo: o JavaScript converte tipos em silêncio para fazer a conta "dar certo". O compilador barra parte desses casos, mas não todos, então vale conhecer as regras que continuam valendo.

## Aritmética e a divisão que não é inteira

Como só existe `number`, a divisão `7 / 2` devolve `3.5`, não `3`. Para obter a divisão inteira use `Math.floor`, `Math.trunc` ou `Math.floor(a / b)`. A diferença aparece com negativos: `Math.floor(-7 / 2)` é `-4`, enquanto `Math.trunc(-7 / 2)` é `-3`. O operador `%` devolve o resto com o sinal do dividendo, então `-7 % 3` é `-1`. Para obter um módulo sempre não negativo, como em índices circulares, use `((a % n) + n) % n`.

```typescript
console.log(7 / 2);
console.log(Math.floor(7 / 2), Math.floor(-7 / 2), Math.trunc(-7 / 2));
console.log(-7 % 3, ((-7 % 3) + 3) % 3);
console.log(2 ** 10);
console.log(0.1 + 0.2);
console.log(0.1 + 0.2 === 0.3, Math.abs(0.1 + 0.2 - 0.3) < 1e-9);
```

```text
Saída:
3.5
3 -4 -3
-1 2
1024
0.30000000000000004
false true
```

O último par mostra a armadilha dos números de ponto flutuante: nunca compare decimais com `===`; compare a diferença com uma tolerância.

## Igualdade: sempre ===

`==` converte os dois lados antes de comparar, e `===` compara tipo e valor. Use sempre `===` e `!==`. O compilador ajuda: ele reclama quando você compara tipos sem sobreposição, como `number` com `string`.

```typescript
const a: unknown = 5;
const b: unknown = "5";
console.log(a == b, a === b);
console.log(null == undefined, null === undefined);
console.log(NaN === NaN, Number.isNaN(NaN));
```

```text
Saída:
true false
true false
false true
```

`NaN` não é igual nem a si mesmo; para testá-lo use `Number.isNaN`.

## Conversões explícitas

Converter texto em número é rotina em entrevista, e há três caminhos com comportamentos diferentes.

```typescript
console.log(Number("42"), Number(""), Number("4x"));
console.log(parseInt("42px", 10), parseInt("x42", 10));
console.log(parseFloat("3.14abc"));
console.log(String(123) + 1, 123 + "1", Number("3") * 2);
console.log(Boolean(""), Boolean("0"), Boolean(0), !!"texto");
```

```text
Saída:
42 0 NaN
42 NaN
3.14
1231 1231 6
false true false true
```

`Number` é rigoroso e devolve `NaN` se sobrar lixo, mas converte texto vazio em `0`. `parseInt` lê o prefixo numérico e ignora o resto; passe sempre a base. Note que `123 + "1"` concatena em vez de somar: o `+` com um texto de um lado sempre vira concatenação. O compilador aceita, então converta com `Number` antes de somar.

## Valores falsy

São falsy: `false`, `0`, `""`, `null`, `undefined`, `NaN` (e `0n`). Todo o resto é truthy, inclusive `"0"`, `[]` e `{}`. Cuidado com `if (valor)` quando `0` ou texto vazio forem entradas legítimas.

## Operadores úteis do dia a dia

- `??` devolve o lado direito só se o esquerdo for `null` ou `undefined`; `||` troca por qualquer falsy, inclusive `0`.
- `?.` interrompe a cadeia e devolve `undefined` se o meio for nulo.
- `&&=`, `||=` e `??=` atribuem condicionalmente, bons para contadores.
- Operadores de bits (`&`, `|`, `^`, `<<`, `>>`) convertem para inteiros de 32 bits com sinal.

```typescript
const config: { porta?: number } = { porta: 0 };
console.log(config.porta || 8080, config.porta ?? 8080);
const vazio: { a?: { b: number } } = {};
console.log(vazio.a?.b);
console.log(1 << 31, 2 ** 31 | 0, 5 & 3, 5 ^ 3);
```

```text
Saída:
8080 0
undefined
-2147483648 -2147483648 1 6
```

## Na entrevista

Cite que você usa `===`, que sabe que a divisão é de ponto flutuante e que o estouro de 32 bits nos operadores de bits é uma pegadinha. Follow-ups comuns: "por que `0.1 + 0.2 !== 0.3`?" (representação binária de 64 bits, erro de arredondamento) e "qual a diferença entre `||` e `??`?" (o segundo só reage a null e undefined).
