JavaScript decide o tipo de cada valor só na hora de executar, e isso gera bugs clássicos como somar um número com um texto. O TypeScript resolve isso dando nome aos tipos e verificando o uso antes de o programa rodar, sem exigir que você escreva anotação em tudo.

## Os tipos básicos

Os tipos primitivos são `number`, `string`, `boolean`, `bigint`, `symbol`, `null` e `undefined`. Existe um único `number` para inteiros e decimais (ponto flutuante de 64 bits), então não há `int` nem `long`. Para listas há `number[]` ou, de forma equivalente, `Array<number>`; para pares de tamanho fixo existem as tuplas.

```typescript
const idade: number = 30;
const nome: string = "Ana";
const ativo: boolean = true;
const notas: number[] = [7.5, 8, 9.5];
const par: [string, number] = ["x", 10];

console.log(idade, nome, ativo);
console.log(notas.length, par[0], par[1]);
```

```text
Saída:
30 Ana true
3 x 10
```

## Inferência: nem tudo precisa de anotação

Se você inicializa a variável, o compilador deduz o tipo. Anotar `const x: number = 5` é redundante; basta `const x = 5`. Escreva a anotação onde o compilador não consegue deduzir: parâmetros de função, retornos que você quer fixar e variáveis declaradas vazias.

```typescript
let contador = 0;
contador = contador + 1;
// contador = "um";  // erro: string não é atribuível a number

const lista: number[] = [];
lista.push(10);
let resultado: string | undefined;
resultado = "pronto";

console.log(contador, lista.length, resultado);
```

```text
Saída:
1 1 pronto
```

Sem a anotação `number[]`, uma lista vazia seria inferida de forma muito frouxa, então anote listas e mapas vazios.

## const, let e var

Use `const` por padrão e `let` quando o valor mudar. Evite `var`, que tem escopo de função e sofre hoisting, fonte de bugs em laços com closures. Note que `const` impede reatribuir a variável, não mutar o conteúdo: um array `const` aceita `push`.

## any, unknown e never

- `any` desliga a verificação. Usá-lo é admitir derrota; em entrevista, evite.
- `unknown` é o "não sei ainda": você só pode usar o valor depois de verificar seu tipo.
- `never` é o tipo de algo que nunca acontece, como uma função que sempre lança erro.

```typescript
function descrever(valor: unknown): string {
  if (typeof valor === "number") return "número " + valor.toFixed(1);
  if (typeof valor === "string") return "texto " + valor.toUpperCase();
  return "outro";
}

console.log(descrever(3));
console.log(descrever("oi"));
console.log(descrever(null));
```

```text
Saída:
número 3.0
texto OI
outro
```

Dentro dos `if`, o compilador estreita `valor` de `unknown` para `number` ou `string`. Esse mecanismo, chamado narrowing, é um dos pilares do TypeScript e aparece em detalhe mais adiante.

## null, undefined e o modo estrito

Sem o modo `strict`, `null` e `undefined` entram em qualquer tipo, e o erro "cannot read property of undefined" volta. Com `strict` ligado, você precisa declarar `string | null` e tratar o caso vazio. Muitas plataformas de entrevista usam o modo padrão, mais permissivo, então escreva como se o modo estrito estivesse ligado: é mais seguro e mostra rigor.

Literais também são tipos. `"asc" | "desc"` aceita só esses dois textos, o que substitui enums simples e pega erros de digitação.

```typescript
type Direcao = "asc" | "desc";

function ordenar(nums: number[], dir: Direcao): number[] {
  const copia = nums.slice();
  copia.sort((a, b) => (dir === "asc" ? a - b : b - a));
  return copia;
}

console.log(ordenar([3, 1, 2], "asc").join(","));
console.log(ordenar([3, 1, 2], "desc").join(","));
```

```text
Saída:
1,2,3
3,2,1
```
