Em entrevista de TypeScript você quase sempre recebe a assinatura de uma função e preenche o corpo. Ainda assim, entender como um arquivo `.ts` vira um programa que roda evita surpresas, principalmente a mais comum: o código que "funciona" no navegador mas nem compila no avaliador.

## TypeScript é JavaScript com tipos

TypeScript é um superconjunto de JavaScript: todo JavaScript válido continua válido, e você acrescenta anotações de tipo. O compilador `tsc` verifica os tipos e depois apaga as anotações, gerando JavaScript puro. Em tempo de execução não existe nenhum tipo: quem roda é o Node (ou o navegador) com o JavaScript gerado.

```text
arquivo.ts  --tsc-->  arquivo.js  --node-->  saída
 (checa tipos)       (sem tipos)
```

Isso tem uma consequência importante: um erro de tipo é um erro de compilação, não de execução. Se o `tsc` reclama, o programa nem chega a imprimir nada. E o contrário também vale: os tipos não protegem você de dados errados que chegam de fora, porque depois da compilação eles já não existem.

## O menor programa

Não existe `main` obrigatório. O arquivo é executado de cima para baixo, e `console.log` imprime.

```typescript
function saudacao(nome: string): string {
  return "Olá, " + nome + "!";
}

console.log(saudacao("entrevista"));
```

```text
Saída:
Olá, entrevista!
```

A anotação `nome: string` diz o que a função aceita, e `: string` depois dos parênteses diz o que ela devolve. Chamar `saudacao(42)` seria um erro de compilação.

## Imprimir resultados

`console.log` aceita vários argumentos e os separa por espaço. Template strings, delimitadas por crases, deixam a saída mais legível do que concatenar com `+`.

```typescript
const soma: number = 2 + 3;
console.log("soma =", soma);
console.log(`dobro = ${soma * 2}`);
console.log([1, 2, 3]);
console.log(JSON.stringify({ a: 1, b: [2, 3] }));
```

```text
Saída:
soma = 5
dobro = 10
[ 1, 2, 3 ]
{"a":1,"b":[2,3]}
```

Repare que o Node formata arrays com espaços dentro dos colchetes. Quando precisar de uma saída exata, como em um desafio que compara texto, prefira `join` ou `JSON.stringify`, que você controla por completo.

## Módulos, scripts e a biblioteca

Um arquivo com `import` ou `export` no topo é tratado como módulo; sem eles, é um script global. A diferença aparece quando dois arquivos declaram o mesmo nome no escopo global: o compilador acusa duplicidade. Em plataformas de entrevista isso raramente importa, mas explica por que às vezes você vê `export {}` solto no fim de um exemplo.

Os tipos e funções da biblioteca padrão dependem da versão de JavaScript que o compilador considera. Em configurações antigas, métodos como `includes` ou classes como `Map` podem não existir para o verificador de tipos, mesmo funcionando no Node. Quando isso acontecer, o ajuste é indicar a biblioteca desejada, por exemplo com a diretiva abaixo no topo do arquivo.

```typescript

const nums: number[] = [4, 8, 15];
const tem = nums.includes(8);
const m = new Map<string, number>();
m.set("a", 1);
console.log(tem, m.get("a"));
```

```text
Saída:
true 1
```

## Funções de entrada

O formato típico de uma plataforma é uma função ou uma classe com um método. Você não escreve o código que chama sua função; escreva apenas a assinatura correta, com tipos de parâmetro e retorno.

```typescript
function somaPares(nums: number[]): number {
  let total = 0;
  for (const n of nums) {
    if (n % 2 === 0) total += n;
  }
  return total;
}

console.log(somaPares([1, 2, 3, 4, 5, 6]));
```

```text
Saída:
12
```

## Na entrevista

Anote sempre os tipos dos parâmetros e do retorno: isso documenta sua intenção e o entrevistador percebe que você pensa nos casos de borda (lista vazia, número negativo). Não gaste tempo configurando o compilador; use o que a plataforma oferece. Perguntas de follow-up comuns: "o que o TypeScript faz em tempo de execução?" (nada, os tipos são apagados) e "por que um valor tipado ainda pode quebrar?" (dados externos não são verificados pelo compilador).
