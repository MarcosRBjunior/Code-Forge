Em JavaScript um objeto é só um saco de propriedades, e o erro de digitar `usuario.nmoe` aparece apenas em execução. O TypeScript permite descrever a forma de um objeto uma vez e conferir cada uso. Há duas ferramentas para isso, `interface` e `type`, e entrevistadores gostam de perguntar a diferença.

## Descrevendo a forma de um objeto

Uma `interface` lista as propriedades e seus tipos. Propriedades com `?` são opcionais e `readonly` impede reatribuição depois da criação.

```typescript
interface Usuario {
  readonly id: number;
  nome: string;
  email?: string;
}

function rotulo(u: Usuario): string {
  return u.nome + " #" + u.id + (u.email ? " <" + u.email + ">" : "");
}

const ana: Usuario = { id: 1, nome: "Ana" };
const bruno: Usuario = { id: 2, nome: "Bruno", email: "b@x.com" };
// ana.id = 5;         // erro: id é readonly
// const c: Usuario = { id: 3 };  // erro: falta nome

console.log(rotulo(ana));
console.log(rotulo(bruno));
```

```text
Saída:
Ana #1
Bruno #2 <b@x.com>
```

## Tipagem estrutural

O TypeScript compara tipos pela forma, não pelo nome. Qualquer objeto com as propriedades exigidas serve, mesmo que nunca tenha "declarado" implementar a interface. Isso é chamado de tipagem estrutural, diferente de Java ou C#, onde a herança precisa ser explícita.

```typescript
interface Ponto { x: number; y: number; }

function distancia(a: Ponto, b: Ponto): number {
  return Math.sqrt((a.x - b.x) ** 2 + (a.y - b.y) ** 2);
}

const p3 = { x: 3, y: 4, z: 9 };
console.log(distancia({ x: 0, y: 0 }, p3));
// distancia({ x: 0, y: 0 }, { x: 3, y: 4, z: 9 });  // erro: literal com propriedade extra
```

```text
Saída:
5
```

Há uma exceção que confunde: um objeto literal escrito direto no argumento passa pela checagem de propriedades em excesso. A variável `p3` é aceita, mas o mesmo literal inline seria rejeitado, porque provavelmente é um erro de digitação.

## type: aliases para qualquer tipo

`type` dá nome a qualquer tipo, não só a objetos: uniões, tuplas, funções, literais. Para descrever objetos, `type` e `interface` são quase intercambiáveis.

```typescript
type Id = number | string;
type Par = [number, number];
type Comparador = (a: number, b: number) => number;
type Forma =
  | { tipo: "circulo"; raio: number }
  | { tipo: "retangulo"; l: number; a: number };

function area(f: Forma): number {
  return f.tipo === "circulo" ? 3 * f.raio * f.raio : f.l * f.a;
}

const ids: Id[] = [1, "abc"];
const par: Par = [2, 5];
const cmp: Comparador = (a, b) => a - b;

console.log(ids.length, par[0] + par[1], [3, 1, 2].sort(cmp).join(","));
console.log(area({ tipo: "circulo", raio: 2 }), area({ tipo: "retangulo", l: 3, a: 4 }));
```

```text
Saída:
2 7 1,2,3
12 12
```

## Estendendo e combinando

Interfaces se estendem com `extends`; types se combinam com interseção `&`. Interfaces também se fundem: declarar duas vezes a mesma interface junta as propriedades (declaration merging), o que é útil para estender tipos de bibliotecas.

```typescript
interface Animal { nome: string; }
interface Cachorro extends Animal { raca: string; }

type ComIdade = { idade: number };
type CachorroComIdade = Cachorro & ComIdade;

const rex: CachorroComIdade = { nome: "Rex", raca: "vira-lata", idade: 4 };
console.log(rex.nome, rex.raca, rex.idade);
```

```text
Saída:
Rex vira-lata 4
```

## Assinaturas de índice e Record

Para objetos usados como dicionário, use uma assinatura de índice (`{ [chave: string]: number }`) ou `Record<string, number>`. Lembre que, no modo padrão, ler uma chave inexistente é tipado como `number` mas devolve `undefined`. Para dicionários dinâmicos em algoritmos, `Map` continua sendo melhor.

## Quando usar cada um

| Situação | Escolha |
| --- | --- |
| Forma de objeto ou contrato de classe | `interface` |
| União, tupla, tipo de função | `type` |
| Precisa de declaration merging | `interface` |
| Combinar tipos com `&` ou tipos mapeados | `type` |

Na dúvida, siga o padrão do projeto. Muitos times usam `interface` para objetos e `type` para o resto.

## Na entrevista

Defina os tipos de entrada logo no início (um `interface Intervalo` ou `type Aresta = [number, number]`): isso torna a solução legível e mostra organização. Follow-ups comuns: "qual a diferença entre `interface` e `type`?" (type aceita uniões e tuplas; interface aceita merging e `extends`) e "o que é tipagem estrutural?" (compatibilidade pela forma, não pelo nome).
