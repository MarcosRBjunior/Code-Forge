Em JavaScript, uma variável pode guardar números, strings, `null` ou um objeto, e o código se vira para descobrir o que recebeu. O TypeScript formaliza isso com tipos união: `string | number` diz que o valor é de um tipo ou do outro. O problema é que, dentro da função, você só pode usar o que vale para os dois. Para usar algo específico, você precisa provar ao compilador qual caso é o atual. Essa prova se chama narrowing (estreitamento).

## Tipos união e o estreitamento básico

Os operadores que você já conhece em JavaScript servem de prova: `typeof`, `instanceof`, `in`, comparação com `null` e checagem de verdade.

```typescript
function descrever(valor: string | number | null): string {
  if (valor === null) {
    return "nulo";
  }
  if (typeof valor === "string") {
    return "texto de tamanho " + valor.length;
  }
  return "número dobrado: " + valor * 2;
}

console.log(descrever("abc"));
console.log(descrever(21));
console.log(descrever(null));
```

```text
Saída:
texto de tamanho 3
número dobrado: 42
nulo
```

Dentro do primeiro `if` o tipo é `null`; no segundo, `string`; depois deles, o que sobrou é `number`. O compilador acompanha o fluxo do código e reduz a união a cada ramo. Se você tentasse `valor.length` fora do bloco do `typeof`, receberia um erro.

## Uniões discriminadas

O padrão mais útil para entrevistas é a união discriminada: cada variante carrega um campo literal em comum (a "tag") que diz qual é ela. Ao testar a tag, o TypeScript sabe quais outros campos existem.

```typescript
type Forma =
  | { tipo: "circulo"; raio: number }
  | { tipo: "retangulo"; largura: number; altura: number }
  | { tipo: "quadrado"; lado: number };

function area(f: Forma): number {
  switch (f.tipo) {
    case "circulo":
      return Math.round(3.14159 * f.raio * f.raio);
    case "retangulo":
      return f.largura * f.altura;
    case "quadrado":
      return f.lado * f.lado;
  }
}

const formas: Forma[] = [
  { tipo: "circulo", raio: 2 },
  { tipo: "retangulo", largura: 3, altura: 4 },
  { tipo: "quadrado", lado: 5 },
];

for (const f of formas) {
  console.log(f.tipo, area(f));
}
```

```text
Saída:
circulo 13
retangulo 12
quadrado 25
```

Em cada `case`, `f` já é a variante certa: `f.raio` só compila no caso do círculo. É o modelo ideal para representar nós de árvore (folha ou interno), resultados (sucesso ou erro) e comandos de um interpretador.

## Checagem de exaustividade com never

E se alguém adicionar uma variante nova e esquecer de tratá-la? O tipo `never` (o tipo "impossível") resolve: no `default`, atribua o valor a uma variável `never`. Se ainda restar alguma variante, a atribuição não compila.

```typescript
type Estado = "pendente" | "ok" | "falha";

function rotulo(e: Estado): string {
  switch (e) {
    case "pendente":
      return "aguardando";
    case "ok":
      return "concluído";
    case "falha":
      return "com erro";
    default: {
      const impossivel: never = e;
      return impossivel;
    }
  }
}

console.log(rotulo("ok"), rotulo("falha"));
```

```text
Saída:
concluído com erro
```

Se você acrescentar `"cancelado"` ao tipo `Estado` sem criar o `case`, o compilador aponta o erro exatamente no `default`.

## Type guards personalizados

Quando a prova não cabe num `typeof`, escreva uma função com retorno `valor is Tipo`. O compilador confia nela, então ela precisa estar correta.

```typescript
interface Gato { miar(): void }
interface Cachorro { latir(): void }

function ehGato(a: Gato | Cachorro): a is Gato {
  return "miar" in a;
}
```

<Callout type="warning" title="Cuidado com a checagem de verdade">
`if (valor)` descarta também `0`, `""` e `NaN`. Se `0` é um valor legítimo, compare explicitamente com `null` ou `undefined` (`valor == null` cobre os dois).
</Callout>

## Na entrevista

Uniões discriminadas deixam o código limpo quando o problema tem "tipos de coisa": tokens de uma calculadora, operações de um editor, nós de uma árvore sintática. Mostrar a tag e o `switch` exaustivo costuma impressionar mais do que uma cadeia de `if` com `as`. Evite o operador `as` para forçar tipos, pois ele desliga a verificação.

Follow-ups comuns: "o que o compilador faz com `never`?" e "qual a diferença entre `in` e `instanceof`?" (`in` testa a presença de uma propriedade; `instanceof` testa a cadeia de protótipos de uma classe).
