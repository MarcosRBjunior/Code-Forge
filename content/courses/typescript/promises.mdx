Ler um arquivo, chamar uma API ou esperar um timer são operações que terminam "mais tarde". JavaScript roda numa única thread, então não pode ficar parado esperando. Antes das Promises, o resultado chegava por callbacks aninhados, e o código virava uma escada difícil de ler e de tratar erros. Uma Promise é um objeto que representa um valor que ainda vai existir, e o TypeScript tipa esse valor: `Promise<number>` promete um número.

## Estados e criação

Uma Promise começa pendente e termina uma única vez, ou resolvida (com um valor) ou rejeitada (com um motivo). Depois disso o estado não muda mais. Você cria uma passando ao construtor uma função que recebe `resolve` e `reject`.

```typescript
function esperar(ms: number, valor: number): Promise<number> {
  return new Promise<number>((resolve) => {
    setTimeout(() => resolve(valor), ms);
  });
}

function falharSeNegativo(n: number): Promise<number> {
  return new Promise<number>((resolve, reject) => {
    if (n < 0) {
      reject(new Error("negativo: " + n));
    } else {
      resolve(n * 10);
    }
  });
}

esperar(20, 5).then((v) => console.log("resolveu com", v));
falharSeNegativo(-1).catch((e: Error) => console.log("rejeitou:", e.message));
console.log("isso aparece primeiro");
```

```text
Saída:
isso aparece primeiro
rejeitou: negativo: -1
resolveu com 5
```

O `console.log` final aparece antes porque `then` e `catch` só registram o que fazer depois; o código síncrono continua. A rejeição chega antes do timer porque a Promise já nasceu rejeitada, enquanto a outra espera 20 ms.

## Encadeamento com then

`then` devolve uma nova Promise com o que o callback retornar. Se o callback devolver outra Promise, a cadeia espera por ela. Assim os passos ficam numa sequência plana, e um único `catch` no fim captura erro de qualquer etapa.

```typescript
function dobrar(n: number): Promise<number> {
  return Promise.resolve(n * 2);
}

Promise.resolve(3)
  .then((n) => n + 1)
  .then((n) => dobrar(n))
  .then((n) => {
    console.log("valor:", n);
    if (n > 5) {
      throw new Error("passou de 5");
    }
    return n;
  })
  .then(() => console.log("não executa"))
  .catch((e: Error) => console.log("erro:", e.message))
  .finally(() => console.log("fim"));
```

```text
Saída:
valor: 8
erro: passou de 5
fim
```

O TypeScript infere o tipo em cada elo: depois de `dobrar`, o próximo `then` recebe `number`, e não `Promise<number>`, porque Promises aninhadas são "achatadas" automaticamente.

## Combinadores

Para várias operações independentes, use os métodos estáticos:

| Método | Resolve quando | Rejeita quando |
| --- | --- | --- |
| `Promise.all` | todas resolvem (array na mesma ordem) | a primeira rejeita |
| `Promise.allSettled` | todas terminam, com sucesso ou não | nunca |
| `Promise.race` | a primeira termina | a primeira termina com erro |

```typescript
function atraso<T>(ms: number, valor: T): Promise<T> {
  return new Promise<T>((resolve) => setTimeout(() => resolve(valor), ms));
}

Promise.all([atraso(30, "a"), atraso(10, "b"), atraso(20, "c")]).then((r) =>
  console.log("all:", r.join(","))
);

Promise.race([atraso(30, "lento"), atraso(5, "rápido")]).then((r) =>
  console.log("race:", r)
);

// o mesmo efeito de allSettled: cada Promise vira uma que nunca rejeita
const tentativas: Promise<number>[] = [Promise.resolve(1), Promise.reject(new Error("x"))];
Promise.all(
  tentativas.map((p) => p.then(() => "fulfilled", () => "rejected"))
).then((r) => console.log("allSettled:", r.join(",")));
```

```text
Saída:
allSettled: fulfilled,rejected
race: rápido
all: a,b,c
```

O último bloco simula `allSettled` com `then` de dois argumentos, o que funciona mesmo em ambientes antigos que não têm o método (ele é do ES2020) e é exatamente o que pedem quando dizem "implemente o allSettled". Repare também que `Promise.all` mantém a ordem dos argumentos, não a ordem de conclusão. As três esperas rodam em paralelo, então o total é cerca de 30 ms, e não 60 ms.

## Armadilhas

- Esquecer o `return` dentro de um `then` quebra a cadeia: o próximo passo recebe `undefined` e não espera a operação.
- Uma rejeição sem `catch` vira "unhandled rejection", e o Node pode encerrar o processo.
- O executor do construtor roda imediatamente, de forma síncrona. Só os callbacks de `then` são adiados.

<Callout type="tip" title="Promise já resolvida">
`Promise.resolve(x)` e `Promise.reject(erro)` criam Promises prontas. São úteis em testes e para devolver um valor de cache numa função que normalmente seria assíncrona.
</Callout>

## Na entrevista

Promises aparecem em perguntas de front-end e Node: "implemente um `Promise.all`", "limite a concorrência a N requisições", "faça um retry com espera". Saber que `all` falha rápido e que `allSettled` não falha resolve metade dessas perguntas. Ao implementar `all`, guarde os resultados por índice e conte quantas terminaram, em vez de usar `push`.

Follow-ups comuns: "qual a diferença entre `all` e `allSettled`?" e "as Promises do `all` rodam em sequência ou em paralelo?" (elas já estão rodando quando você as passa; o `all` só espera).
