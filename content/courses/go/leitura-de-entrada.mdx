Em plataformas de programação competitiva e em alguns testes online, o programa lê a entrada padrão (stdin) e escreve na saída padrão (stdout). Em Python você usa `input()`; em Go existem mais opções, e escolher a errada deixa a solução lenta ou limita o tamanho da linha.

## fmt.Scan para entradas pequenas

`fmt.Scan(&a, &b)` lê valores separados por espaço ou quebra de linha e converte para o tipo da variável. É simples, mas lento: serve para até algumas dezenas de milhares de números.

```go
package main

import (
	"fmt"
	"strings"
)

func main() {
	entrada := strings.NewReader("3 4\nola 7\n")

	var a, b int
	fmt.Fscan(entrada, &a, &b)
	fmt.Println(a + b)

	var nome string
	var n int
	fmt.Fscan(entrada, &nome, &n)
	fmt.Println(nome, n*2)
}
```

```text
Saída:
7
ola 14
```

Aqui usamos `fmt.Fscan` sobre um leitor de texto fixo, que se comporta como `fmt.Scan` mas lê de qualquer fonte. Assim o exemplo roda sem teclado; num problema real troque por `os.Stdin`.

## bufio para entradas grandes

Para muitos dados, envolva `os.Stdin` num `bufio.Reader` e use `fmt.Fscan` nele, ou use `bufio.Scanner` para ler linha a linha ou palavra a palavra. O Scanner tem um limite de 64 KB por linha, que pode ser ampliado com `scanner.Buffer`. Para saída volumosa, use `bufio.Writer` e dê `Flush` no fim, senão nada aparece.

```go
package main

import (
	"bufio"
	"fmt"
	"strconv"
	"strings"
)

func main() {
	texto := "5\n10 20 30 40 50\nfim da entrada\n"
	sc := bufio.NewScanner(strings.NewReader(texto))
	sc.Buffer(make([]byte, 1024*1024), 1024*1024)

	sc.Scan()
	n, _ := strconv.Atoi(sc.Text())

	sc.Scan()
	campos := strings.Fields(sc.Text())
	soma := 0
	for _, c := range campos[:n] {
		v, _ := strconv.Atoi(c)
		soma += v
	}

	sc.Scan()
	resto := sc.Text()

	out := bufio.NewWriter(nowrite{})
	defer out.Flush()
	fmt.Println(n, soma, resto)
	fmt.Fprintln(out, "nada visível")
}

type nowrite struct{}

func (nowrite) Write(p []byte) (int, error) { return len(p), nil }
```

```text
Saída:
5 150 fim da entrada
```

O `bufio.Writer` aqui escreve num destino que descarta tudo apenas para demonstrar o padrão; num problema real, escreva `bufio.NewWriter(os.Stdout)` e chame `defer out.Flush()` logo após criar. `strings.Fields` divide por qualquer espaço em branco e ignora vazios, ao contrário de `strings.Split`.

## Receita para stdin real

Para leitura rápida de números, o padrão mais usado é criar `reader := bufio.NewReader(os.Stdin)` e chamar `fmt.Fscan(reader, &x)` em um laço. Para linhas com espaços no meio, use `reader.ReadString('\n')` e remova a quebra com `strings.TrimSpace`. Se o formato for "primeiro o número de casos, depois os casos", leia `t` e repita `t` vezes.

## Armadilhas

O `Scanner` com o limite padrão falha silenciosamente em linhas longas: `Scan` devolve `false` e o erro fica em `sc.Err()`. Misturar `fmt.Scan` direto com `bufio.Reader` sobre o mesmo `os.Stdin` perde dados, pois o buffer consome mais do que o pedido; escolha uma só forma. `Fscan` ignora quebras de linha, o que atrapalha formatos baseados em linhas. E esquecer o `Flush` do `bufio.Writer` faz a saída sumir.

## Na entrevista

A maioria das entrevistas dá a função pronta e não pede leitura de entrada. Quando pedirem, use `bufio` com `Fscan` e `Flush`, e diga por que: `fmt.Scan` puro é lento. Follow-ups: "como lê uma linha inteira com espaços?" e "como lidar com entrada de milhões de números?" (leitor com buffer, saída com buffer, evitar `Sprintf` em laço).
