O mapa de Go é a tabela hash que você usa para contar frequências, detectar duplicatas, indexar por chave e resolver quase todo problema do tipo "já vi esse valor?". Ele equivale ao `dict` de Python e ao `Map` de JavaScript, com algumas regras que valem conhecer: o valor zero para chaves ausentes, a leitura com dois retornos e a ordem de iteração propositalmente aleatória.

## Criando e usando

O tipo é `map[K]V`. A chave precisa ser comparável (números, strings, booleanos, ponteiros, arrays e structs de campos comparáveis); slices, mapas e funções não servem. Crie com literal ou com `make`.

```go
package main

import (
	"fmt"
	"maps"
	"slices"
)

type Ponto struct{ X, Y int }

func main() {
	contagem := map[string]int{}
	for _, r := range "banana" {
		contagem[string(r)]++
	}
	fmt.Println(contagem, len(contagem))

	v, ok := contagem["z"]
	fmt.Println(v, ok)

	delete(contagem, "b")
	_, existe := contagem["b"]
	fmt.Println(existe)

	chaves := slices.Sorted(maps.Keys(contagem))
	fmt.Println(chaves)

	visto := map[Ponto]bool{}
	visto[Ponto{1, 2}] = true
	fmt.Println(visto[Ponto{1, 2}], visto[Ponto{2, 1}])
}
```

```text
Saída:
map[a:3 b:1 n:2] 3
0 false
false
[a n]
true false
```

Ler uma chave ausente devolve o valor zero do tipo, sem erro. Por isso `contagem[k]++` funciona mesmo na primeira vez: parte de zero. Quando precisa distinguir "ausente" de "presente com valor zero", use a forma de dois retornos: `v, ok := m[k]`. O `delete` não faz nada se a chave não existe. `fmt.Println` imprime mapas com as chaves ordenadas, o que torna a saída previsível para depuração, mas não vale para `range`.

## A ordem do range é aleatória

Iterar um mapa com `for k, v := range m` percorre as entradas em ordem não especificada, e Go de propósito a varia de uma execução para outra. Nunca construa lógica que dependa dessa ordem. Se precisar de ordem, extraia as chaves, ordene e itere sobre elas. Desde Go 1.23, `maps.Keys` devolve um iterador e `slices.Sorted` consome e ordena, como no programa acima.

## Mapa de slices e Two Sum

Agrupar valores por chave é um padrão frequente: `grupos[k] = append(grupos[k], v)` funciona sem inicializar a lista, porque um slice `nil` aceita `append`. O problema Two Sum mostra o outro uso clássico, procurar o complemento enquanto percorre:

```go
package main

import "fmt"

func doisSomam(nums []int, alvo int) []int {
	idx := map[int]int{}
	for i, n := range nums {
		if j, ok := idx[alvo-n]; ok {
			return []int{j, i}
		}
		idx[n] = i
	}
	return nil
}

func main() {
	fmt.Println(doisSomam([]int{2, 7, 11, 15}, 9))

	grupos := map[int][]string{}
	for _, p := range []string{"um", "dois", "tres", "seis"} {
		grupos[len(p)] = append(grupos[len(p)], p)
	}
	fmt.Println(grupos)
}
```

```text
Saída:
[0 1]
map[2:[um] 4:[dois tres seis]]
```

Aqui o mapa troca memória por tempo: em vez de duas buscas aninhadas, que custam O(n ao quadrado), uma passada com consulta O(1) em média resolve em O(n). No segundo bloco, a chave é o comprimento da palavra, então `um` fica sozinho na chave 2 e as outras três palavras dividem a chave 4, na ordem em que foram inseridas.

## Armadilhas

Um mapa `nil` pode ser lido (devolve zeros), mas escrever nele causa pânico. Sempre inicialize com `make` ou um literal antes de gravar. Mapas não são seguros para uso concorrente: duas goroutines escrevendo ao mesmo tempo é erro fatal, e o capítulo sobre `sync` mostra como proteger. Além disso, `m[k].campo = x` não compila quando o valor é uma struct; leia a struct, altere e grave de volta, ou guarde ponteiros.

<Callout type="tip" title="Complexidade">
Leitura, escrita e `delete` são O(1) em média, mas O(n) no pior caso teórico. Iterar custa O(n) sobre as entradas. O mapa cresce sozinho; se souber o tamanho aproximado, `make(map[string]int, n)` evita rehash.
</Callout>

## Na entrevista

Diga sempre qual a chave e qual o valor. Para contagem, use `map[string]int` ou `[26]int` quando o alfabeto é fixo. Ao precisar de saída determinística, ordene as chaves. Follow-ups comuns: "o que acontece ao ler uma chave inexistente?" (valor zero, sem erro), "a ordem do range é estável?" (não, é aleatória) e "como usar um slice como chave?" (não dá; converta para string ou para um array de tamanho fixo).
