Python e JavaScript passam referências a objetos por baixo dos panos e escondem isso de você. Go passa tudo por valor, mas oferece ponteiros explícitos para quando você quer que a função altere o original ou evite copiar uma struct grande.

## O básico: & e *

`&x` dá o endereço de `x` e `*p` acessa o valor apontado. Um ponteiro não inicializado vale `nil`, e desreferenciar nil causa pânico. Diferente de C, não há aritmética de ponteiros.

```go
package main

import "fmt"

func dobrarCopia(n int) {
	n *= 2
}

func dobrar(n *int) {
	*n *= 2
}

func main() {
	x := 10
	dobrarCopia(x)
	fmt.Println(x)
	dobrar(&x)
	fmt.Println(x)

	p := &x
	*p = 99
	fmt.Println(x, *p == x)

	var q *int
	fmt.Println(q == nil)
}
```

```text
Saída:
10
20
99 true
true
```

## Ponteiros e structs

Para structs, o Go desreferencia sozinho: `p.campo` funciona tanto com valor quanto com ponteiro. Métodos com receptor ponteiro podem alterar a struct; com receptor valor, trabalham numa cópia. Estruturas ligadas, como listas encadeadas e árvores, usam ponteiros para os nós, e `nil` marca o fim.

```go
package main

import "fmt"

type No struct {
	Val  int
	Prox *No
}

func inserirInicio(cabeca *No, v int) *No {
	return &No{Val: v, Prox: cabeca}
}

func (n *No) Soma() int {
	total := 0
	for atual := n; atual != nil; atual = atual.Prox {
		total += atual.Val
	}
	return total
}

func main() {
	var lista *No
	for i := 1; i <= 4; i++ {
		lista = inserirInicio(lista, i)
	}
	var vals []int
	for n := lista; n != nil; n = n.Prox {
		vals = append(vals, n.Val)
	}
	fmt.Println(vals)
	fmt.Println(lista.Soma())
}
```

```text
Saída:
[4 3 2 1]
10
```

## new, literais e escape

`&No{Val: 1}` cria uma struct e devolve o endereço; `new(int)` devolve um ponteiro para um zero. Em Go é legal devolver o endereço de uma variável local: o compilador percebe que ela "escapa" e a aloca no heap, com coleta de lixo cuidando do resto. Você não precisa pensar em `malloc` nem em `free`.

## Armadilhas

Slices, mapas e canais já se comportam como referências: um slice é um pequeno cabeçalho com ponteiro, tamanho e capacidade. Passar um `[]int` para uma função permite alterar os elementos, mas não o tamanho que o chamador enxerga, a menos que você devolva o slice novo ou passe `*[]int`. Para mapas, passar o valor basta.

Outra armadilha clássica: no laço `for _, item := range itens`, `item` é uma cópia. Alterar `item.Campo` não muda o slice; use o índice, `itens[i].Campo`. E guardar `&item` em Go anterior à 1.22 apontava sempre para a mesma variável; na 1.22 em diante cada iteração tem a sua, mas não vale confiar nisso em código antigo.

Por fim, ponteiro para ponteiro, ou ponteiro para interface, quase sempre indica que algo está errado.

## Na entrevista

Use ponteiros em nós de lista e árvore, em receptores que modificam estado e em structs grandes. Sempre teste `nil` antes de desreferenciar: o caso de lista ou árvore vazia é o que mais reprova. Follow-ups comuns: "qual a diferença entre receptor valor e ponteiro?" e "Go passa por valor ou por referência?" (sempre por valor; o valor pode ser um ponteiro ou um cabeçalho de slice).
