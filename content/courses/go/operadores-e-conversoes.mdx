Os operadores de Go são os mesmos de C, com poucas exceções, mas o comportamento nas fronteiras (divisão inteira, resto de negativos, truncamento em conversões) é exatamente o tipo de detalhe que derruba soluções em casos de borda. Aqui você vê o que muda em relação a Python e JavaScript.

## Aritmética e divisão inteira

Em Go, dividir dois inteiros dá um inteiro, truncado em direção a zero. Em Python, `//` arredonda para baixo (então `-7 // 2` dá `-4`); em Go, `-7 / 2` dá `-3`. O resto acompanha o sinal do dividendo: `-7 % 3` dá `-1`, e não `2` como em Python. Quando precisar de resto não negativo para índices circulares, some o divisor antes: `((x % n) + n) % n`.

```go
package main

import "fmt"

func main() {
	fmt.Println(7/2, -7/2, 7%3, -7%3)
	fmt.Println(float64(7)/2, 7/2.0)

	i := 10
	i++
	i *= 2
	fmt.Println(i)

	fmt.Println(6&3, 6|3, 6^3, 1<<4, 6&^3)
	fmt.Println(!true, 3 > 2 && 2 > 5, 3 > 2 || 2 > 5)
}
```

```text
Saída:
3 -3 1 -1
3.5 3.5
22
2 7 5 16 4
false false true
```

Alguns pontos do programa. `i++` é uma instrução, não uma expressão: você não escreve `x = i++`, e também não existe `++i`. Os operadores de bit são `&` (e), `|` (ou), `^` (ou exclusivo; unário, é a negação de bits), `<<` e `>>` (deslocamentos) e `&^` (bit clear, zera os bits marcados). Os booleanos usam `&&`, `||` e `!`, com curto-circuito. A expressão `7/2.0` mistura uma constante sem tipo com um decimal e resulta em `3.5`, mas `float64(7)/2` precisa da conversão explícita porque `7` literal em variável seria `int`.

## Conversões são explícitas

Go não converte tipos numéricos sozinho. Para usar um `int` onde se espera `float64`, escreva `float64(n)`. A sintaxe é `Tipo(valor)`, como uma chamada de função. Converter decimal para inteiro trunca: `int(f)` com `f` valendo `3.9` dá `3` (com uma constante literal o compilador recusa). Converter para um tipo menor descarta bits altos, sem erro nem aviso.

```go
package main

import (
	"fmt"
	"strconv"
)

func main() {
	n, err := strconv.Atoi("123")
	fmt.Println(n+1, err)

	_, err = strconv.Atoi("x1")
	fmt.Println(err)

	fmt.Println(strconv.Itoa(45) + "!")
	fmt.Println(string(rune(65)))

	big := int64(1)<<40 + 5
	fmt.Println(int32(big))

	var u uint8 = 250
	u += 10
	fmt.Println(u)
	f := 3.9
	fmt.Println(int(f))
}
```

```text
Saída:
124 <nil>
strconv.Atoi: parsing "x1": invalid syntax
45!
A
5
4
3
```

Atenção a `string(65)`: converter um inteiro diretamente em `string` produz o caractere Unicode daquele código, não o texto `"65"`. Por isso o programa usa `string(rune(65))` para deixar a intenção clara, e `strconv.Itoa` quando você quer os dígitos. O `go vet` até reclama de `string(int)`. Para o caminho inverso, `strconv.Atoi` devolve o número e um erro; trate o erro, mesmo que seja com `_` em um teste rápido.

## Overflow é silencioso

Inteiros em Go dão a volta ao estourar, como em C para tipos sem sinal. No programa acima, `uint8` valendo 250 mais 10 resulta em 4 (260 menos 256). Para tipos com sinal, passar de `math.MaxInt64` vira um valor negativo grande. Não há exceção. Em entrevista, isso significa que você deve raciocinar sobre limites antes de escolher o tipo; o capítulo sobre overflow na última seção do curso aprofunda isso.

## Comparações e tipos diferentes

Operadores de comparação só funcionam entre valores do mesmo tipo. Comparar `int` com `int64` ou `byte` com `rune` exige conversão. Já strings comparam com `==`, `<` e companhia, lexicograficamente por bytes, o que facilita checar ordem alfabética sem nenhuma função auxiliar. Structs e arrays também são comparáveis com `==` quando seus campos são comparáveis; slices e mapas não são (só comparam com `nil`).

<Callout type="tip" title="Truques de bits que caem sempre">
`n&(n-1)` remove o bit 1 mais baixo, `n&1` testa se é ímpar, `1<<k` cria uma máscara e `n&(-n)` isola o bit mais baixo. Vale ter na ponta dos dedos para problemas de subconjuntos e de contagem de bits.
</Callout>

## Na entrevista

Quando fizer média ou razão, converta antes de dividir: `float64(a)/float64(b)`. Para a média de dois índices em busca binária, prefira `mid := lo + (hi-lo)/2`, que evita estouro. Follow-ups típicos: "qual o resultado de `-7 % 3` em Go?" (`-1`) e "o que acontece ao somar 1 em `math.MaxInt64`?" (volta para o menor valor negativo, sem erro).
