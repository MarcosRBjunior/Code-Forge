Go é simples, mas tem um punhado de comportamentos que surpreendem quem vem de Python ou JavaScript. Entrevistadores sabem disso e gostam de ver se você cai neles. Este capítulo reúne as armadilhas que mais derrubam soluções corretas no papel.

## Slices que compartilham memória

Fatiar não copia: o novo slice aponta para o mesmo array. Alterar um altera o outro, e `append` pode ou não escrever no array original, dependendo da capacidade. Isso é a fonte número um de bugs em backtracking, em que você guarda o caminho atual numa lista de resultados.

```go
package main

import "fmt"

func main() {
	a := []int{1, 2, 3, 4}
	b := a[:2]
	b = append(b, 99)
	fmt.Println(a, b)

	c := make([]int, len(a))
	copy(c, a)
	c[0] = -1
	fmt.Println(a, c)

	var todos [][]int
	atual := []int{}
	for i := 1; i <= 3; i++ {
		atual = append(atual, i)
		copia := make([]int, len(atual))
		copy(copia, atual)
		todos = append(todos, copia)
	}
	fmt.Println(todos)
}
```

```text
Saída:
[1 2 99 4] [1 2 99]
[1 2 99 4] [-1 2 99 4]
[[1] [1 2] [1 2 3]]
```

Sem a cópia no último trecho, os resultados poderiam acabar apontando para o mesmo array e todos exibiriam o mesmo conteúdo no fim. Ao guardar um estado de backtracking, sempre copie.

## Mapas: ordem aleatória, nil e struct como valor

Iterar um mapa com `range` dá uma ordem diferente a cada execução; se a resposta precisa ser determinística, extraia as chaves e ordene. Ler de um mapa nil funciona (devolve o valor zero), mas escrever causa pânico: crie com `make`. E não dá para alterar um campo de uma struct guardada num mapa (`m[k].campo = 1` não compila); leia, altere e grave de volta, ou guarde ponteiros.

```go
package main

import (
	"fmt"
	"slices"
)

type Item struct{ Qtd int }

func main() {
	var m map[string]int
	fmt.Println(m["x"], len(m))

	contagem := map[string]int{"b": 2, "a": 1, "c": 3}
	chaves := make([]string, 0, len(contagem))
	for k := range contagem {
		chaves = append(chaves, k)
	}
	slices.Sort(chaves)
	fmt.Println(chaves)

	itens := map[string]Item{"x": {1}}
	it := itens["x"]
	it.Qtd++
	itens["x"] = it
	fmt.Println(itens)
}
```

```text
Saída:
0 0
[a b c]
map[x:{2}]
```

## Strings e runes

`len("olá")` conta bytes, não caracteres: é 4, não 3. Indexar `s[i]` dá um byte. Para tratar caracteres Unicode, converta para `[]rune` ou use `for _, r := range s`. Em problemas só com letras ASCII, bytes bastam. Strings são imutáveis, então para trocar um caractere converta para `[]byte` ou `[]rune`.

## Outras pegadinhas

O `range` sobre slice copia o elemento. Variáveis declaradas com `:=` num bloco interno sombreiam as externas: um `err := ...` dentro de um `if` não altera o `err` de fora. `defer` em laço só roda no fim da função. Um laço `for` sem condição é infinito, e o único jeito de sair é `break` ou `return`. A comparação de slices com `==` não compila, e o `switch` não precisa de `break`, mas também não cai para o caso seguinte a não ser que você use `fallthrough`.

Dividir inteiros trunca: `7/2` é 3. Para obter decimal, converta antes: `float64(a) / float64(b)`. Não há conversão implícita entre `int` e `int64`, nem entre `int` e `float64`.

## Na entrevista

Verbalize os pontos de risco antes que o entrevistador os aponte: "vou copiar o slice antes de guardar o caminho", "mapa tem ordem aleatória, então vou ordenar as chaves". Isso mostra domínio. Follow-ups comuns: "o que `append` faz quando a capacidade acaba?" (aloca novo array, geralmente com o dobro, e copia) e "por que `len` de uma string com acento surpreende?" (conta bytes em UTF-8).
