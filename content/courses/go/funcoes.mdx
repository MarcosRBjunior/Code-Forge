Funções em Go são simples e ao mesmo tempo mais flexíveis do que parecem: podem devolver vários valores, aceitar quantidade variável de argumentos, ser guardadas em variáveis e capturar o ambiente onde nasceram. Quase toda solução de entrevista é uma ou duas funções pequenas, então vale dominar a sintaxe.

## Assinatura e múltiplos retornos

O tipo vem depois do nome do parâmetro, e o tipo de retorno vem depois da lista de parâmetros. Parâmetros consecutivos do mesmo tipo podem dividir a declaração: `func soma(a, b int) int`. Uma função pode devolver mais de um valor, e é assim que Go reporta erros, sem exceções: o último retorno costuma ser um `error`.

```go
package main

import (
	"errors"
	"fmt"
)

func divmod(a, b int) (q, r int) {
	q = a / b
	r = a % b
	return
}

func soma(nums ...int) int {
	total := 0
	for _, n := range nums {
		total += n
	}
	return total
}

func divide(a, b int) (int, error) {
	if b == 0 {
		return 0, errors.New("divisão por zero")
	}
	return a / b, nil
}

func main() {
	q, r := divmod(17, 5)
	fmt.Println(q, r)

	fmt.Println(soma(1, 2, 3))
	xs := []int{4, 5}
	fmt.Println(soma(xs...))

	if _, err := divide(1, 0); err != nil {
		fmt.Println("erro:", err)
	}
	v, _ := divide(9, 3)
	fmt.Println(v)
}
```

```text
Saída:
3 2
6
9
erro: divisão por zero
3
```

Três recursos aparecem aqui. Os retornos nomeados `(q, r int)` já criam as variáveis, e um `return` sem argumentos devolve o que elas valem; use com moderação, só em funções curtas. O parâmetro variádico `nums ...int` chega à função como um slice, e para passar um slice existente você escreve `xs...`. E o identificador em branco `_` descarta um valor que você não quer, já que variável não usada é erro.

## Funções são valores

Você pode atribuir uma função a uma variável, passá-la como argumento e devolvê-la. Uma função anônima que usa variáveis de fora é uma closure: ela guarda uma referência a essas variáveis, não uma cópia.

```go
package main

import "fmt"

func aplica(xs []int, f func(int) int) []int {
	out := make([]int, 0, len(xs))
	for _, x := range xs {
		out = append(out, f(x))
	}
	return out
}

func novoContador() func() int {
	c := 0
	return func() int {
		c++
		return c
	}
}

func main() {
	fmt.Println(aplica([]int{1, 2, 3}, func(x int) int { return x * x }))

	prox := novoContador()
	fmt.Println(prox(), prox(), prox())

	memo := map[int]int{}
	var fib func(n int) int
	fib = func(n int) int {
		if n < 2 {
			return n
		}
		if v, ok := memo[n]; ok {
			return v
		}
		memo[n] = fib(n-1) + fib(n-2)
		return memo[n]
	}
	fmt.Println(fib(30))
}
```

```text
Saída:
[1 4 9]
1 2 3
832040
```

Para fazer recursão com uma função anônima, declare a variável antes (`var fib func(n int) int`) e só então atribua a closure; sem isso, o nome ainda não existe dentro do corpo. Esse é o padrão de DFS e de memoização em entrevistas: uma closure interna que enxerga o mapa, o grafo ou o contador do escopo externo, sem precisar passá-los como parâmetro a cada chamada.

## Passagem por valor

Tudo em Go é passado por valor: o argumento é copiado. Para inteiros, strings e structs isso significa que a função não altera o original. Mas slices, mapas e canais carregam internamente uma referência aos dados, então modificar elementos de um slice ou chaves de um mapa dentro da função é visível para quem chamou. Já reatribuir a variável (`s = append(s, 1)`) só muda a cópia local. O capítulo sobre ponteiros e o de slices por dentro mostram os detalhes.

<Callout type="note" title="Funções de primeira classe e init">
Além de `main`, existe a função especial `init()`, executada antes de `main` em cada pacote. Em entrevista você quase nunca precisa dela; prefira inicializar dentro de `main`.
</Callout>

## Na entrevista

Dê nomes curtos e específicos e mantenha cada função com uma responsabilidade. Para backtracking e DFS, uma closure interna evita carregar muitos parâmetros. Se o enunciado fornece a assinatura, não a mude. Em funções que podem falhar, devolva `(valor, error)` em vez de usar `panic`.

Follow-ups comuns: "como Go trata erros sem exceções?" (retornos múltiplos e `error`), "o que é uma closure e o que ela captura?" (variáveis do escopo externo, por referência) e "o que `xs...` faz?" (expande um slice em argumentos variádicos).
