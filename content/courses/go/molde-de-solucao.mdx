Saber a sintaxe não basta: em entrevista você precisa entregar código correto, legível e explicado em 30 a 45 minutos. Ter um molde mental reduz erros e libera atenção para o algoritmo.

## O roteiro

Primeiro, entenda o problema: repita com suas palavras, peça os limites da entrada e liste casos de borda (vazio, um elemento, repetidos, negativos). Depois, proponha a abordagem mais simples, diga sua complexidade e só então otimize. Escreva o código, teste à mão com um exemplo e confirme a complexidade final. Em Go a rotina de código também ajuda a organizar.

## Esqueleto de função

Em plataformas de entrevista você normalmente preenche uma função com assinatura fixa. Trate as bordas primeiro, prepare estruturas com `make` e deixe o laço principal limpo. O exemplo clássico "dois números que somam o alvo" mostra o molde com mapa.

```go
package main

import "fmt"

func doisSoma(nums []int, alvo int) []int {
	if len(nums) < 2 {
		return nil
	}
	visto := make(map[int]int, len(nums))
	for i, n := range nums {
		if j, ok := visto[alvo-n]; ok {
			return []int{j, i}
		}
		visto[n] = i
	}
	return nil
}

func main() {
	fmt.Println(doisSoma([]int{2, 7, 11, 15}, 9))
	fmt.Println(doisSoma([]int{3, 3}, 6))
	fmt.Println(doisSoma([]int{1}, 2) == nil)
}
```

```text
Saída:
[0 1]
[0 1]
true
```

Repare nos idiomas que valem ouro: o "comma ok" para consultar o mapa, `make` com capacidade para evitar realocações e `nil` como resultado vazio (um slice nil se comporta como vazio em `len`, `range` e `append`).

## Moldes por tipo de problema

Para dois ponteiros, declare `esq, dir := 0, len(s)-1` e um laço `for esq < dir`. Para janela deslizante, mantenha `esq` e avance `dir` num `for dir := range s`. Para busca em largura, use um slice como fila e um mapa ou slice de booleanos como visitados. Para busca em profundidade e backtracking, escreva uma função recursiva interna: em Go, uma closure atribuída a uma variável `var dfs func(int)` permite recursão e acesso ao estado externo.

```go
package main

import "fmt"

func subconjuntos(nums []int) [][]int {
	var res [][]int
	var atual []int
	var dfs func(inicio int)
	dfs = func(inicio int) {
		copia := append([]int(nil), atual...)
		res = append(res, copia)
		for i := inicio; i < len(nums); i++ {
			atual = append(atual, nums[i])
			dfs(i + 1)
			atual = atual[:len(atual)-1]
		}
	}
	dfs(0)
	return res
}

func main() {
	for _, s := range subconjuntos([]int{1, 2, 3}) {
		fmt.Println(s)
	}
}
```

```text
Saída:
[]
[1]
[1 2]
[1 2 3]
[1 3]
[2]
[2 3]
[3]
```

A cópia com `append([]int(nil), atual...)` é o idioma curto para clonar um slice (também há `slices.Clone`). O retrocesso (`atual[:len(atual)-1]`) desfaz a escolha antes da próxima.

## Trade-offs de estilo

Prefira nomes curtos em escopos pequenos (`i`, `n`, `res`) e nomes descritivos para estruturas importantes. Funções auxiliares pequenas valem mais que um corpo gigante. Evite pacotes ou abstrações extras: structs e interfaces só se o problema for de design. Retorne cedo para reduzir aninhamento. E prefira `min`, `max`, `slices` e `maps` da biblioteca em vez de reescrevê-los, o que poupa tempo e erros.

## Na entrevista

Narre o que faz enquanto escreve, e teste com um exemplo pequeno e uma borda. Se travar, volte à força bruta e melhore. Follow-ups: "qual a complexidade de tempo e espaço?" (inclua a pilha de recursão no espaço) e "como mudaria para entradas enormes?" (streaming, paralelismo, estruturas mais eficientes). Se for pedido um programa completo, lembre de `package main`, dos imports usados e de `func main`.
