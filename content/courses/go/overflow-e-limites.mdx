Python tem inteiros de precisão arbitrária e JavaScript promove tudo a ponto flutuante. Em Go os inteiros têm largura fixa, e passar do limite não gera erro: o valor simplesmente dá a volta. Em problemas de entrevista com somas grandes, produtos ou módulos, isso muda a resposta sem aviso.

## Tamanhos e limites

`int` e `uint` têm 64 bits em máquinas de 64 bits (e 32 em plataformas de 32 bits). Os tipos de tamanho fixo são `int8`, `int16`, `int32`, `int64` e os sem sinal correspondentes. O pacote `math` traz as constantes: `math.MaxInt32`, `math.MinInt32`, `math.MaxInt64`, `math.MinInt64` e também `math.MaxInt` e `math.MinInt`, que seguem o tamanho de `int`.

```go
package main

import (
	"fmt"
	"math"
)

func main() {
	fmt.Println(math.MaxInt32, math.MinInt32)
	fmt.Println(math.MaxInt64)

	var a int32 = math.MaxInt32
	a++
	fmt.Println(a)

	var b uint8 = 250
	b += 10
	fmt.Println(b)

	var u uint = 0
	u--
	fmt.Println(u == math.MaxUint64)
}
```

```text
Saída:
2147483647 -2147483648
9223372036854775807
-2147483648
4
true
```

O overflow é silencioso: `int32` passa de máximo para mínimo, `uint8` volta ao início, e `uint` abaixo de zero vira o maior valor. Subtrair de um `uint` é um bug clássico, por exemplo `len(s) - 1` quando você guardou o tamanho como sem sinal.

## Usando int com segurança

O padrão `int` de 64 bits aguenta somas de até cerca de 9 vezes 10 elevado a 18. Isso basta para a maioria dos problemas, mas o produto de dois valores de até 10 elevado a 10 já estoura. Quando o enunciado fala em módulo 10 elevado a 9 mais 7, reduza a cada multiplicação.

```go
package main

import "fmt"

const MOD = 1_000_000_007

func potencia(base, exp int) int {
	resultado := 1
	base %= MOD
	for exp > 0 {
		if exp&1 == 1 {
			resultado = resultado * base % MOD
		}
		base = base * base % MOD
		exp >>= 1
	}
	return resultado
}

func somaSegura(a, b int) (int, bool) {
	if b > 0 && a > 1<<62 {
		return 0, false
	}
	return a + b, true
}

func main() {
	fmt.Println(potencia(2, 10))
	fmt.Println(potencia(2, 100))
	fmt.Println(somaSegura(1, 2))
	_, ok := somaSegura(1<<62+1, 1<<62)
	fmt.Println(ok)
}
```

```text
Saída:
1024
976371285
3 true
false
```

Como cada fator fica abaixo de 10 elevado a 9 mais 7, o produto cabe em 64 bits (cerca de 10 elevado a 18). Reduzir só no final não funcionaria.

## Divisão, resto e ponto flutuante

A divisão inteira trunca em direção a zero, e o resto leva o sinal do dividendo: `-7 / 2` dá `-3` e `-7 % 2` dá `-1`. Para obter um módulo não negativo, use `((x % m) + m) % m`. Dividir inteiro por zero causa pânico, enquanto dividir `float64` por zero gera infinito. Compare floats com tolerância, nunca com `==`.

Para pontos de partida em mínimo e máximo, a forma moderna é `math.MaxInt` como "infinito" em busca de mínimo. Cuidado ao somar a ele: `math.MaxInt + 1` vira o menor inteiro. Prefira `math.MaxInt / 2` quando precisar somar custos sobre um valor infinito.

## Armadilhas

Converter entre tamanhos trunca sem avisar: `int32(valor)` com valor grande descarta bits altos. A média `(lo + hi) / 2` na busca binária pode estourar em índices enormes; escreva `lo + (hi-lo)/2`. Valor absoluto de `math.MinInt64` continua negativo, pois não há positivo correspondente. E `math.Abs` só aceita `float64`; para inteiros escreva você mesmo.

## Na entrevista

Pergunte os limites da entrada logo no começo: eles definem o tipo e a complexidade aceitável. Diga "vou usar int de 64 bits, que cobre até 9 vezes 10 elevado a 18". Follow-ups: "e se a soma passar de 64 bits?" (usar `math/big` ou reduzir por módulo) e "como detectar overflow antes que aconteça?" (comparar com `math.MaxInt - b` antes de somar).
