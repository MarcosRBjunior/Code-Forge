A estrutura de dados que você mais vai usar em Go é o slice. Ele faz o papel da lista de Python e do array de JavaScript, mas com regras próprias: tem tipo de elemento fixo, cresce com `append` e compartilha memória quando você o fatia. Antes de chegar nele, vale conhecer o array, porque o slice é construído sobre ele.

## Arrays têm tamanho fixo e são valores

Um array declara seu tamanho no tipo: `[3]int` e `[4]int` são tipos diferentes. Atribuir um array a outra variável copia todos os elementos, e passar um array a uma função também copia. É por isso que arrays aparecem pouco em código de entrevista, exceto para tabelas pequenas de tamanho conhecido, como `[26]int` para contar letras.

```go
package main

import "fmt"

func main() {
	a := [3]int{1, 2, 3}
	b := a
	b[0] = 99
	fmt.Println(a, b)

	s := []int{1, 2, 3}
	s = append(s, 4, 5)
	fmt.Println(s, len(s))

	t := s[1:3]
	fmt.Println(t, len(t))

	z := make([]int, 3)
	fmt.Println(z)

	var vazio []int
	fmt.Println(vazio == nil, len(vazio))
	vazio = append(vazio, 7)
	fmt.Println(vazio)
}
```

```text
Saída:
[1 2 3] [99 2 3]
[1 2 3 4 5] 5
[2 3] 2
[0 0 0]
true 0
[7]
```

O array `b` é uma cópia independente de `a`. Já o slice `s` é uma janela sobre um array subjacente: `[]int{1, 2, 3}` (sem tamanho entre os colchetes) cria um slice. `make([]int, 3)` cria um slice de tamanho 3 preenchido com zeros. E um slice `nil` já é válido: tem tamanho zero e aceita `append` normalmente, então você raramente precisa inicializá-lo.

## Fatiando

A expressão `s[i:j]` pega do índice `i` (inclusive) ao `j` (exclusivo), igual a Python. Os dois limites são opcionais: `s[:k]` pega os primeiros `k` elementos, `s[k:]` pula os `k` primeiros. Diferente de Python, índices negativos não existem, e passar um índice fora do intervalo gera um pânico em tempo de execução, não um erro silencioso. Strings também podem ser fatiadas, mas por bytes.

## Matrizes e utilitários do pacote slices

Uma grade é um slice de slices, e cada linha precisa ser criada. Pela versão 1.21, o pacote `slices` traz as operações que antes você escrevia à mão:

```go
package main

import (
	"fmt"
	"slices"
)

func main() {
	grid := make([][]int, 3)
	for i := range grid {
		grid[i] = make([]int, 3)
	}
	grid[1][2] = 5
	fmt.Println(grid)

	s := []int{10, 20, 30, 40}
	s = slices.Delete(s, 1, 2)
	fmt.Println(s)
	fmt.Println(slices.Contains(s, 30), slices.Index(s, 40))
	slices.Reverse(s)
	fmt.Println(s, slices.Max(s))

	c := slices.Clone(s)
	c[0] = 0
	fmt.Println(s, c)
}
```

```text
Saída:
[[0 0 0] [0 0 5] [0 0 0]]
[10 30 40]
true 2
[40 30 10] 40
[40 30 10] [0 30 10]
```

`slices.Delete(s, 1, 2)` remove o intervalo de índices 1 a 2 (exclusivo) e devolve o slice resultante; reatribua sempre. `slices.Clone` cria uma cópia independente, o que será essencial quando o assunto for compartilhamento de memória. Existem ainda `slices.Insert`, `slices.Equal`, `slices.Min` e `slices.IndexFunc`. O equivalente manual de remoção é `s = append(s[:i], s[i+1:]...)`, que você ainda verá bastante.

## Custos

| Operação | Custo |
|---|---|
| Acessar `s[i]` | O(1) |
| `append` ao final | O(1) amortizado |
| Inserir ou remover no meio | O(n) |
| Remover do início com `s[1:]` | O(1), mas mantém a memória |
| `slices.Contains` / `Index` | O(n) |

O `append` é amortizado porque, ao esgotar a capacidade, Go aloca um array maior e copia tudo. Na maioria das vezes o custo é constante; ocasionalmente é linear.

<Callout type="warning" title="Slices não são comparáveis">
Não dá para usar `==` entre dois slices (só contra `nil`), e slices não servem como chave de mapa. Use `slices.Equal` para comparar o conteúdo, ou converta para string ou array quando precisar de uma chave.
</Callout>

## Na entrevista

Declare a saída como `var res []int` e use `append`; para tamanho conhecido, `make([]int, n)` evita realocações. Prefira `slices.Sort`, `slices.Contains` e `slices.Reverse` ao reescrever o que a biblioteca já oferece. Follow-ups típicos: "qual a diferença entre array e slice?" (tamanho no tipo e semântica de valor versus janela sobre memória compartilhada) e "como copiar um slice sem compartilhar memória?" (`slices.Clone` ou `copy` para um slice recém-criado).
