Antes dos generics, escrever uma função `Max` para `int` e outra para `float64` era rotina, ou você recorria a `any` e perdia a segurança de tipos. Em Python isso nunca foi problema por causa da tipagem dinâmica. Em Go, desde a versão 1.18, você parametriza funções e tipos por tipo.

## Funções genéricas

Os parâmetros de tipo ficam entre colchetes, antes dos parâmetros normais. Cada um tem uma restrição que diz quais operações são permitidas. `any` aceita tudo; `comparable` permite `==` e serve como chave de mapa; `cmp.Ordered` (do pacote `cmp`) permite `<` e `>`.

```go
package main

import (
	"cmp"
	"fmt"
)

func Maior[T cmp.Ordered](a, b T) T {
	if a > b {
		return a
	}
	return b
}

func Filtrar[T any](xs []T, pred func(T) bool) []T {
	var saida []T
	for _, x := range xs {
		if pred(x) {
			saida = append(saida, x)
		}
	}
	return saida
}

func Contar[T comparable](xs []T) map[T]int {
	m := make(map[T]int)
	for _, x := range xs {
		m[x]++
	}
	return m
}

func main() {
	fmt.Println(Maior(3, 7), Maior("ab", "aa"), Maior(2.5, 1.5))
	pares := Filtrar([]int{1, 2, 3, 4, 5, 6}, func(n int) bool { return n%2 == 0 })
	fmt.Println(pares)
	fmt.Println(Contar([]string{"a", "b", "a"}))
}
```

```text
Saída:
7 ab 2.5
[2 4 6]
map[a:2 b:1]
```

O compilador infere `T` a partir dos argumentos, então raramente você escreve `Maior[int](...)`.

## Tipos genéricos

Structs também aceitam parâmetros de tipo. O exemplo clássico de entrevista é uma pilha que serve para qualquer tipo. Os métodos repetem o parâmetro no receptor, mas não podem declarar parâmetros de tipo novos.

```go
package main

import "fmt"

type Pilha[T any] struct {
	itens []T
}

func (p *Pilha[T]) Push(x T) {
	p.itens = append(p.itens, x)
}

func (p *Pilha[T]) Pop() (T, bool) {
	var zero T
	if len(p.itens) == 0 {
		return zero, false
	}
	x := p.itens[len(p.itens)-1]
	p.itens = p.itens[:len(p.itens)-1]
	return x, true
}

func (p *Pilha[T]) Len() int { return len(p.itens) }

func main() {
	var p Pilha[string]
	p.Push("a")
	p.Push("b")
	x, ok := p.Pop()
	fmt.Println(x, ok, p.Len())
	p.Pop()
	_, ok = p.Pop()
	fmt.Println(ok)
}
```

```text
Saída:
b true 1
false
```

Note o `var zero T`: é assim que você devolve "nada" num tipo genérico, já que não existe `nil` para todo `T`.

## Restrições personalizadas

Você pode declarar uma restrição como interface com uma união de tipos, como `type Numero interface { ~int | ~int64 | ~float64 }`. O til inclui tipos definidos pelo usuário cujo tipo base seja aquele. Use isso para somar ou comparar números num código genérico.

## Armadilhas e trade-offs

Generics não fazem tudo: não há métodos genéricos com parâmetros de tipo próprios, nem especialização. Se a lógica depende de comportamento, uma interface costuma ser mais clara que um parâmetro de tipo. A regra prática é: use generics para estruturas de dados e algoritmos que operam sobre elementos sem se importar com o que são; use interfaces quando o comportamento varia.

Sem restrição adequada, o compilador recusa operações: `a + b` com `T any` não compila. E lembre que a biblioteca padrão já traz `slices` e `maps` genéricos, além de `min` e `max` embutidos, então não reescreva o que existe.

## Na entrevista

Generics aparecem principalmente em estruturas reutilizáveis: pilha, fila, cache LRU, conjunto. Um `Set[T comparable]` baseado em `map[T]struct{}` é um clássico. Follow-ups: "qual a diferença entre `any` e `comparable`?" (o segundo permite `==` e uso como chave) e "por que não usar `any` em vez de generics?" (perde checagem de tipos e exige type assertion).
