Ordenar é uma das primeiras coisas que você faz em um problema: intervalos, pares, anagramas, sweep line. Go oferece dois pacotes, o clássico `sort` e o mais novo `slices`. Os dois usam um algoritmo O(n log n) no pior caso, mas o `slices` é mais curto de digitar e funciona com generics, então é o caminho padrão desde a versão 1.21.

## O caminho curto

Para tipos básicos ordenáveis (números e strings), `slices.Sort` ordena no lugar. Para uma ordem personalizada, use `slices.SortFunc` com uma função de comparação que devolve um inteiro negativo, zero ou positivo, como o `cmp` de outras linguagens. O pacote `cmp` traz `cmp.Compare` para tipos básicos e `cmp.Or`, que devolve o primeiro valor diferente de zero, ótimo para desempates.

```go
package main

import (
	"cmp"
	"fmt"
	"slices"
	"strings"
)

type Pessoa struct {
	Nome  string
	Idade int
}

func main() {
	nums := []int{5, 2, 9, 1}
	slices.Sort(nums)
	fmt.Println(nums)

	ps := []Pessoa{{"Ana", 30}, {"Bia", 25}, {"Caio", 30}}
	slices.SortFunc(ps, func(a, b Pessoa) int {
		return cmp.Or(
			cmp.Compare(b.Idade, a.Idade),
			strings.Compare(a.Nome, b.Nome),
		)
	})
	fmt.Println(ps)

	palavras := []string{"banana", "fig", "apple"}
	slices.SortFunc(palavras, func(a, b string) int {
		return cmp.Compare(len(a), len(b))
	})
	fmt.Println(palavras)
}
```

```text
Saída:
[1 2 5 9]
[{Ana 30} {Caio 30} {Bia 25}]
[fig apple banana]
```

A comparação das pessoas ordena por idade decrescente (note `b.Idade` antes de `a.Idade`) e, em caso de empate, por nome crescente. Trocar a ordem dos argumentos de `cmp.Compare` inverte o sentido. A função precisa ser consistente: se retornar sempre valores aleatórios ou violar a transitividade, o resultado é indefinido.

## O pacote sort

Você ainda verá `sort` em muito código, e é o que muitos conhecem de cor. `sort.Ints` e `sort.Strings` ordenam slices básicos, e `sort.Slice` recebe uma função `less(i, j int) bool` que olha para os índices, não para os valores. Para ordem decrescente, `sort.Sort(sort.Reverse(sort.IntSlice(a)))` funciona, mas é bem verboso. `sort.SliceStable` mantém a ordem relativa de elementos iguais.

```go
package main

import (
	"fmt"
	"slices"
	"sort"
)

func main() {
	iv := [][]int{{3, 5}, {1, 2}, {2, 4}}
	sort.Slice(iv, func(i, j int) bool { return iv[i][0] < iv[j][0] })
	fmt.Println(iv)

	a := []int{1, 2, 5, 9}
	pos, achou := slices.BinarySearch(a, 5)
	fmt.Println(pos, achou)
	pos, achou = slices.BinarySearch(a, 6)
	fmt.Println(pos, achou)
	fmt.Println(sort.SearchInts(a, 2))

	d := []int{4, 1, 3}
	sort.Sort(sort.Reverse(sort.IntSlice(d)))
	fmt.Println(d)
}
```

```text
Saída:
[[1 2] [2 4] [3 5]]
2 true
3 false
1
[4 3 1]
```

Os intervalos aparecem ordenados pelo começo, o primeiro passo de "mesclar intervalos". A busca binária só vale em slices já ordenados. `slices.BinarySearch` devolve a posição e um booleano; quando o valor não existe, a posição é onde ele deveria ser inserido (aqui, 3 para o 6). `sort.SearchInts` devolve só essa posição.

## Estabilidade e custo

| Função | Estável? | Custo |
|---|---|---|
| `slices.Sort`, `sort.Ints` | não importa (valores iguais são indistinguíveis) | O(n log n) |
| `slices.SortFunc`, `sort.Slice` | não | O(n log n) |
| `slices.SortStableFunc`, `sort.SliceStable` | sim | O(n log n) |
| `slices.BinarySearch` | só em slice ordenado | O(log n) |

Se a ordem de elementos "iguais" pelo critério importa para o resultado, use a versão estável ou inclua um desempate no comparador. É um follow-up recorrente.

<Callout type="warning" title="Ordenar modifica o slice">
Tanto `slices.Sort` quanto `sort.Slice` alteram o argumento no lugar. Se precisa da ordem original depois, faça `slices.Clone` antes. Quem chamou sua função verá o slice mudado.
</Callout>

## Na entrevista

Prefira `slices.Sort` e `slices.SortFunc`, mas saiba ler `sort.Slice`, que está em quase todas as soluções públicas. Diga o custo (O(n log n)) e mencione que isso domina a complexidade final de problemas como intervalos e duas somas com dois ponteiros. Para ordenar índices por valor, crie `idx := make([]int, n)`, preencha e ordene `idx` com um comparador que consulta o valor original. Follow-ups comuns: "o sort é estável?" (não, use a variante estável) e "como ordenar por dois critérios?" (comparador com desempate, como `cmp.Or`).
