Go é estaticamente tipada, mas a sintaxe esconde boa parte do trabalho: você raramente escreve o tipo, porque o compilador o infere. O que você precisa saber de cabeça é quais tipos existem, qual é o valor padrão de cada um e a diferença entre `var`, `:=` e `const`.

## Declarando variáveis

Existem duas formas. `var nome tipo` declara com valor zero (e pode aparecer fora de funções). `nome := valor` declara e infere o tipo, mas só funciona dentro de funções.

```go
package main

import "fmt"

func main() {
	var a int
	var s string
	var b bool
	var f float64
	fmt.Printf("%d %q %t %v\n", a, s, b, f)

	x := 10
	y, z := 3.5, "go"
	fmt.Println(x, y, z)

	const Max = 100
	dobro := Max * 2
	fmt.Println(dobro)

	x, w := 20, 1
	fmt.Println(x, w)
}
```

```text
Saída:
0 "" false 0
10 3.5 go
200
20 1
```

Tudo em Go nasce com um valor zero útil: `0` para números, `""` para strings, `false` para booleanos, `nil` para ponteiros, slices, mapas, canais e funções. Isso elimina a categoria de bugs de variável não inicializada, e é por isso que `var contagem [26]int` já serve como tabela de frequência pronta.

O `:=` exige que ao menos uma variável do lado esquerdo seja nova. Na última parte do programa, `x` já existia e é apenas reatribuída, enquanto `w` é criada. Uma armadilha clássica é o sombreamento: dentro de um bloco `if` ou `for`, usar `:=` com um nome já existente cria uma variável nova que esconde a de fora.

## Tipos básicos

| Categoria | Tipos | Observação |
|---|---|---|
| Inteiros com sinal | `int`, `int8`, `int16`, `int32`, `int64` | `int` tem 64 bits em máquinas de 64 bits |
| Inteiros sem sinal | `uint`, `uint8`, `uint16`, `uint32`, `uint64` | cuidado com subtração |
| Ponto flutuante | `float32`, `float64` | prefira `float64` |
| Texto | `string`, `byte`, `rune` | `byte` é `uint8`, `rune` é `int32` |
| Lógico | `bool` | não converte de número |

Não existe conversão implícita entre tipos numéricos: somar um `int` e um `int64` é erro de compilação. Isso parece chato, mas evita surpresas de overflow silencioso.

## byte, rune e constantes com iota

Um `byte` guarda um valor de 0 a 255, e um `rune` guarda um ponto de código Unicode. Aspas simples criam esses valores; aspas duplas criam strings. Para enumerações, Go usa `const` com `iota`, um contador que começa em zero a cada bloco.

```go
package main

import "fmt"

const (
	Domingo = iota
	Segunda
	Terca
)

func main() {
	var b byte = 'a'
	var r rune = 'é'
	fmt.Println(b, r, string(r))
	fmt.Println(Domingo, Segunda, Terca)

	a, c := 1, 2
	a, c = c, a
	fmt.Println(a, c)
}
```

```text
Saída:
97 233 é
0 1 2
2 1
```

Note a troca `a, c = c, a`: a atribuição múltipla avalia o lado direito inteiro antes de gravar, então não precisa de variável temporária. Esse idioma aparece o tempo todo em ordenação e em manipulação de ponteiros de lista ligada.

## Constantes sem tipo

Constantes numéricas literais em Go têm precisão arbitrária e só ganham tipo quando usadas. `const Max = 100` pode ser usada como `int` ou como `float64` sem conversão. Já uma variável tem tipo fixo desde a declaração. Se uma constante não cabe no tipo de destino (por exemplo, `var u uint8 = 300`), o erro é de compilação.

<Callout type="warning" title="Cuidado com int e tamanhos">
O tamanho de `int` depende da plataforma. Em entrevistas ele costuma ter 64 bits, mas se o enunciado fala em valores até 10 elevado a 18, confirme o tipo. Para somas que podem estourar 32 bits, declare `int64` explicitamente e converta nas fronteiras.
</Callout>

## Na entrevista

Use `:=` por padrão e `var` quando quiser o valor zero ou declarar fora de função. Para contadores, `var freq [26]int` é mais rápido e mais curto que um mapa quando o alfabeto é fixo. Declare variáveis perto de onde são usadas, o que ajuda o entrevistador a acompanhar.

Follow-ups comuns: "qual é o valor zero de um slice?" (`nil`, e ele já funciona com `len` e `append`) e "por que `int` e `int64` não se misturam?" (Go não faz conversões implícitas; você converte com `int64(x)`).
