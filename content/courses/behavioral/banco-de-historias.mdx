title: Montando seu banco de histórias

Com as lembranças garimpadas, o próximo passo é transformá-las num **banco de histórias**: um conjunto pequeno de casos bem preparados, mapeados para as competências que as entrevistas cobram. Na hora da pergunta, você não procura na memória; você consulta um índice mental.

## A matriz história × competência

Monte uma tabela com as histórias nas linhas e as competências nas colunas. Marque onde cada história serve bem.

| História | Conflito | Fracasso | Liderança | Ambiguidade | Colaboração | Impacto técnico |
| --- | --- | --- | --- | --- | --- | --- |
| Migração do monólito de pagamentos | | | X | X | X | X |
| Incidente do cache expirado | | X | | | | X |
| Discordância sobre GraphQL | X | | | | X | |
| Onboarding de dois estagiários | | | X | | X | |
| Job de relatório de 6 h | | | | | | X |

O objetivo é que **toda coluna** tenha pelo menos duas histórias. Assim, se você já usou uma na rodada anterior, tem outra para a mesma competência.

## Ficha de cada história

Para cada linha da matriz, escreva uma ficha curta:

```text
Título: Migração do monólito de pagamentos
Quando: 2024, 5 meses, time de 6 pessoas
S: Monólito Rails com deploy semanal travando o roadmap.
T: Fui escolhido para liderar a extração do módulo de pagamentos.
A: - Mapeei dependências com análise de chamadas em produção
   - Propus strangler pattern em vez de reescrita total
   - Negociei com o time de fraude uma API provisória
   - Montei rollout por porcentagem de tráfego
R: Deploy diário do serviço novo, 0 incidentes na virada,
   lead time caiu de 7 para 1 dia.
Aprendizado: Alinhar times dependentes antes de escrever código.
Números: 6 pessoas, 5 meses, 7 → 1 dia, 30% → 100% tráfego
```

Escreva em tópicos, não em prosa. Você vai **contar** a história, não ler.

## Equilíbrio do banco

Garanta variedade em três eixos:

- **Tom**: histórias de sucesso e histórias de erro ou fracasso.
- **Tempo**: a maioria dos últimos dois ou três anos, para refletir seu nível atual.
- **Tipo**: técnicas, interpessoais e de processo.

Se seu banco só tem vitórias técnicas, você vai travar em "conte de um conflito". Se só tem histórias de cinco anos atrás, vai parecer que não evoluiu.

<Callout type="note" title="Adapte o ângulo, não os fatos">
A mesma história de migração pode enfatizar liderança (como você alinhou o time) ou impacto técnico (como resolveu a consistência de dados). Mude o foco das ações, nunca os fatos.
</Callout>

## Ensaio

Conte cada história em voz alta pelo menos três vezes, gravando-se. Verifique: o contexto passou de 30 segundos? Há "eu" suficiente? O resultado tem número? Ajuste a ficha e repita. Na semana da entrevista, revise o banco relendo só os títulos e números.
