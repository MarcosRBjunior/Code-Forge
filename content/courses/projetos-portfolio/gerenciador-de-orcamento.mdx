**Em uma frase:** um app para registrar receitas e despesas por categoria, ver o saldo do mês e um gráfico de para onde o dinheiro foi.

**Nível:** iniciante · **Tempo:** 1 semana · **Pré-requisito:** saber fazer um CRUD simples com banco

## O que você vai construir

Uma tela de lançamentos (data, descrição, categoria, valor, entrada ou saída), um resumo do mês com total de receitas, total de despesas e saldo, e um gráfico de pizza ou barras com as despesas por categoria. Dá para trocar de mês e ver o histórico.

Parece o CRUD mais simples do mundo, e é por isso que ele é bom: o desafio está nos detalhes que separam um app amador de um confiável. O principal deles é como guardar dinheiro.

## MVP

- [ ] Cadastrar, editar e excluir lançamentos com categoria
- [ ] Valores guardados em centavos inteiros
- [ ] Resumo do mês: receitas, despesas e saldo
- [ ] Filtro por mês
- [ ] Gráfico de despesas por categoria
- [ ] Deploy gratuito e README com print do resumo

## Fora do escopo

Integração com banco ou importação de extrato, várias moedas, orçamentos compartilhados entre pessoas e metas. Se quiser login, use algo pronto ou deixe para depois de fazer o projeto de autenticação.

## Etapas

1. **Decida o formato do dinheiro antes de tudo.** Ponto flutuante não representa bem frações decimais: em JavaScript, `0.1 + 0.2` dá `0.30000000000000004`. Somando centenas de lançamentos, o saldo sai errado por um centavo. Guarde valores como inteiros em centavos (`1990` para R$ 19,90) e só formate na tela.
2. **Modele as tabelas.** Uma tabela de categorias e uma de lançamentos, com `amount_cents` inteiro, um tipo (`income` ou `expense`) e a data. Use restrições do banco: valor maior que zero, tipo só com os dois valores aceitos.
3. **Formulário com conversão cuidadosa.** A pessoa digita "19,90"; o servidor converte para `1990` sem passar por `float`. Valide no servidor também, porque o cliente pode mandar qualquer coisa.
4. **Resumo calculado no banco.** Use `SUM` com `GROUP BY` filtrando pelo mês. O banco soma inteiros sem erro e você evita trazer milhares de linhas para somar no JavaScript.
5. **Gráfico.** Pegue o resultado agrupado por categoria e passe para a biblioteca de gráficos. Um gráfico simples e legível vale mais que um bonito e confuso.
6. **Deploy e README.** No README, explique em duas linhas por que os valores estão em centavos. É exatamente o tipo de decisão que um entrevistador gosta de ver.

A conversão e a formatação ficam assim:

```typescript
function toCents(input: string): number {
  const clean = input.trim().replace(/\./g, "").replace(",", ".");
  if (!/^\d+(\.\d{1,2})?$/.test(clean)) throw new Error("Valor inválido");
  const [reais, cents = ""] = clean.split(".");
  return Number(reais) * 100 + Number(cents.padEnd(2, "0"));
}

const brl = new Intl.NumberFormat("pt-BR", { style: "currency", currency: "BRL" });
brl.format(1990 / 100); // "R$ 19,90"
```

<Callout type="tip" title="Datas também enganam">
Guarde a data do lançamento como `DATE` (sem hora). Se você usar data e hora em UTC, uma despesa feita às 22h do dia 31 pode cair no mês seguinte para quem está no Brasil.
</Callout>

## Extras para se destacar

- Lançamentos recorrentes (aluguel, assinatura) gerados todo mês.
- Exportar o mês em CSV.
- Comparação com o mês anterior por categoria, mostrando onde o gasto subiu.
- Testes automatizados da função de conversão, incluindo entradas inválidas.

## O que este projeto mostra no portfólio

"Eu sei que dinheiro não se guarda em float, sei agregar dados no banco e transformar números em algo que a pessoa entende de relance."
