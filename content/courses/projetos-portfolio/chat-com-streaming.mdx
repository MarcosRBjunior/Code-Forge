**Em uma frase:** uma interface de chat em que a resposta do modelo aparece token por token, enquanto é gerada.

**Nível:** iniciante em IA · **Tempo:** 3 a 5 dias · **Pré-requisito:** nenhum (é o primeiro da trilha de IA)

## O que você vai construir

Um app web com caixa de mensagem, histórico na tela e respostas que chegam aos poucos, como nos assistentes que você já usa. Parece simples, mas obriga você a resolver três problemas reais de produto: esconder a chave da API no servidor, repassar um fluxo de dados (streaming) do provedor até o navegador e montar uma UI que se atualiza sem travar.

Este projeto é a base dos próximos quatro. A UI e a rota de API que você criar aqui vão ser reaproveitadas no RAG, na memória, nas imagens e no agente.

## MVP

- [ ] Campo de mensagem e histórico da conversa na tela
- [ ] Chamada ao modelo com streaming (Server-Sent Events ou stream HTTP)
- [ ] Texto aparecendo em tempo real, sem esperar a resposta inteira
- [ ] Mensagens do usuário e do assistente com visual diferente
- [ ] README com um GIF de uns 10 segundos mostrando o streaming

## Stack sugerida

| Camada | Opção principal | Alternativa |
|---|---|---|
| Front-end | Next.js | React + Vite |
| Back-end | Route handler do Next.js | FastAPI |
| Modelo | Qualquer provedor com streaming | Modelo local com Ollama |

A regra que não muda: **a chave da API fica só no servidor**. O navegador chama a sua rota, e a sua rota chama o provedor.

## Fora do escopo

Login, troca de modelo na tela, RAG, memória entre sessões e ferramentas. Tudo isso vem nos projetos seguintes; colocar agora só atrasa o primeiro deploy.

## Etapas

1. **Rota de API sem streaming.** Faça a rota receber o histórico e devolver a resposta completa. Confirme que funciona com `curl` antes de mexer na UI.
2. **Liga o streaming no servidor.** Peça a resposta em modo stream ao provedor e repasse os pedaços para o cliente à medida que chegam.
3. **Consome o stream no navegador.** Leia o corpo da resposta com `fetch` e um leitor de stream, acrescentando cada pedaço à última mensagem do assistente.
4. **Estados da UI.** Desabilite o envio enquanto a resposta chega, mostre um indicador de "gerando" e trate erro de rede com uma mensagem amigável.
5. **README e GIF.** Explique em um parágrafo o que o projeto faz e por que o streaming importa (a pessoa vê a resposta começar em menos de um segundo).

O núcleo do passo 3 cabe em poucas linhas:

```typescript
const res = await fetch("/api/chat", { method: "POST", body: JSON.stringify({ messages }) });
const reader = res.body!.getReader();
const decoder = new TextDecoder();
while (true) {
  const { done, value } = await reader.read();
  if (done) break;
  appendToLastMessage(decoder.decode(value, { stream: true }));
}
```

<Callout type="warning" title="Nunca no repositório">
Coloque a chave num `.env.local` fora do Git e publique só um `.env.example` com o nome da variável. Chave vazada em repositório público é revogada ou usada por terceiros em minutos.
</Callout>

## Extras para se destacar

- Botão de parar a geração no meio (cancelando o `fetch` com `AbortController`).
- Renderização de Markdown e blocos de código na resposta.
- Medir e mostrar o tempo até o primeiro token.
