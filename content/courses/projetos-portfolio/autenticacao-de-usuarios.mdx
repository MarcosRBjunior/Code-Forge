**Em uma frase:** cadastro, login, sessão, logout e redefinição de senha por e-mail, feitos do jeito certo e com proteção contra ataques de força bruta.

**Nível:** iniciante (com cuidado redobrado) · **Tempo:** 1 a 2 semanas · **Pré-requisito:** um CRUD com banco e noções de HTTP (cookies, status)

## O que você vai construir

Um app mínimo com páginas de cadastro, login, "esqueci minha senha" e uma área restrita que só aparece para quem está logado. O conteúdo da área restrita não importa; o que importa é tudo o que acontece em volta dela.

Em produção, você provavelmente vai usar uma biblioteca ou serviço pronto, e deve. Fazer uma vez à mão serve para entender o que essas ferramentas fazem por você e para conseguir explicar cada decisão numa entrevista. Por isso o foco aqui não é ter muitas funcionalidades, é fazer as poucas que existem sem nenhuma falha clássica.

## MVP

- [ ] Cadastro com senha guardada como hash argon2id ou bcrypt
- [ ] Login que cria uma sessão no banco e um cookie seguro
- [ ] Logout que invalida a sessão no servidor
- [ ] Redefinição de senha com link de uso único que expira
- [ ] Rate limit em login e em "esqueci minha senha"
- [ ] Deploy gratuito e README explicando cada decisão de segurança

## Stack sugerida

| Camada | Opção principal | Alternativa |
|---|---|---|
| Aplicação | Next.js | Express, FastAPI ou Django |
| Banco | Postgres | SQLite |
| Hash de senha | `argon2` (argon2id) | `bcrypt` |
| E-mail | Provedor transacional com plano gratuito | Mailpit ou similar em desenvolvimento |

Segredos (URL do banco, chave do provedor de e-mail) ficam em variáveis de ambiente. O repositório tem só um `.env.example` com os nomes.

## Fora do escopo

Login social (OAuth), autenticação em dois fatores, papéis e permissões, JWT. Sessão no banco é mais simples de revogar e suficiente aqui.

## Etapas

1. **Cadastro.** Valide e-mail e tamanho mínimo de senha no servidor. Normalize o e-mail (minúsculas, sem espaços) e crie um índice único nele. Gere o hash com argon2id; a biblioteca cuida do salt e o embute no próprio hash.
2. **Login e sessão.** Compare a senha com a função de verificação da biblioteca. Se der certo, gere um token aleatório longo, guarde no banco só o hash dele, com data de expiração, e envie o token num cookie.
3. **Cookie seguro.** Use `HttpOnly` (JavaScript não lê), `Secure` (só HTTPS), `SameSite=Lax` (reduz CSRF) e `Path=/`. Em toda requisição protegida, procure a sessão no banco e confira a validade.
4. **Mensagens que não vazam informação.** Login falho diz sempre "e-mail ou senha incorretos". O "esqueci minha senha" responde sempre "se o e-mail existir, enviamos um link". Assim ninguém descobre quem tem conta. Para o tempo de resposta também não denunciar, verifique a senha contra um hash falso quando o e-mail não existir.
5. **Redefinição de senha.** Gere um token aleatório, guarde o hash dele com validade curta (uns 30 minutos) e envie o link por e-mail. Ao usar, troque a senha, apague o token e encerre todas as sessões abertas daquele usuário.
6. **Rate limit.** Limite tentativas por IP e por e-mail, por exemplo 5 por minuto. Uma tabela no banco com contadores por janela de tempo resolve no começo.
7. **README.** Liste cada decisão e o ataque que ela evita. Essa lista é o portfólio.

O núcleo do login fica assim:

```typescript
const user = await db.findUserByEmail(email.trim().toLowerCase());
// DUMMY_HASH: hash argon2 de uma senha qualquer, gerado uma vez na inicialização
const ok = await argon2.verify(user?.passwordHash ?? DUMMY_HASH, password);
if (!user || !ok) return error401("E-mail ou senha incorretos");

const token = crypto.randomBytes(32).toString("base64url");
await db.createSession(user.id, sha256(token), addDays(new Date(), 30));
setCookie("session", token, { httpOnly: true, secure: true, sameSite: "lax", path: "/" });
```

<Callout type="warning" title="Erros que reprovam o projeto">
Senha em texto puro ou com MD5/SHA-256 simples, token de sessão gerado com `Math.random`, sessão guardada em `localStorage` e link de redefinição que nunca expira. Qualquer um desses aparece numa revisão de código em segundos.
</Callout>

## Extras para se destacar

- Confirmação de e-mail no cadastro, com o mesmo mecanismo de token do reset.
- Página "dispositivos conectados" para encerrar sessões específicas.
- Rehash automático quando você aumentar o custo do argon2.
- Testes automatizados do fluxo inteiro, incluindo token expirado e tentativa acima do limite.

## O que este projeto mostra no portfólio

"Eu entendo autenticação por dentro: hash de senha, sessão revogável, cookie seguro, rate limit e por que a mensagem de erro não pode dizer se o e-mail existe."
