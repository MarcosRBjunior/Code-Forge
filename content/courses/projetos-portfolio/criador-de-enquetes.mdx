**Em uma frase:** um app para criar uma enquete, compartilhar o link, receber votos e ver o resultado mudando ao vivo.

**Nível:** iniciante · **Tempo:** 1 semana · **Pré-requisito:** um CRUD com banco

## O que você vai construir

Uma tela para criar a enquete (pergunta e de duas a dez opções), que gera um link curto para compartilhar. Quem abre o link vota e, logo depois, vê as barras de resultado se mexendo sozinhas à medida que outras pessoas votam. Quem criou pode encerrar a enquete.

O ponto mais interessante do projeto não é técnico, é de produto: como evitar que alguém vote cem vezes sem obrigar todo mundo a criar conta? Não existe resposta perfeita, e saber explicar os limites de cada abordagem é exatamente o que você vai mostrar.

## MVP

- [ ] Criar enquete com pergunta e opções
- [ ] Link compartilhável com identificador aleatório
- [ ] Votar e ver o resultado em barras com percentual
- [ ] Resultado atualizando ao vivo, sem recarregar a página
- [ ] Uma estratégia contra voto duplicado, explicada no README
- [ ] Deploy gratuito e README com GIF de dois navegadores votando

## Stack sugerida

| Camada | Opção principal | Alternativa |
|---|---|---|
| Aplicação | Next.js | Express + React |
| Banco | Postgres | SQLite |
| Tempo real | Server-Sent Events | Polling a cada poucos segundos |
| Deploy | Render ou Fly.io (conexão longa) | Vercel com polling |

## Fora do escopo

Várias perguntas por enquete, opções com imagem, voto ranqueado, painel com histórico de enquetes e exportação. Uma pergunta, uma escolha.

## Etapas

1. **Modelo e link.** Tabelas de enquetes, opções e votos. Use um identificador aleatório e curto no link (como `/p/k3x9qz`), não o `id` sequencial; senão qualquer um percorre todas as enquetes trocando o número.
2. **Votar.** O servidor confere se a opção pertence à enquete e se ela está aberta. Nunca aceite a contagem vinda do cliente; ele só diz qual opção escolheu.
3. **Resultado.** Uma consulta com `COUNT` agrupado por opção. Calcule o percentual no servidor ou no cliente, mas trate o caso de zero votos para não dividir por zero.
4. **Ao vivo.** Comece com polling: a página pede o resultado a cada 3 segundos. Funciona em qualquer hospedagem. Depois troque por Server-Sent Events, em que o servidor empurra o novo placar a cada voto. O polling continua útil como plano B.
5. **Voto duplicado.** Escolha uma abordagem, implemente e documente as limitações (veja a tabela abaixo).
6. **Deploy e README.** Grave o GIF com duas janelas lado a lado, uma votando e a outra atualizando.

As abordagens contra voto duplicado, e onde cada uma falha:

| Abordagem | Como funciona | Limite |
|---|---|---|
| Cookie ou `localStorage` | Marca no navegador que já votou | Aba anônima ou limpar dados e vota de novo |
| IP | Um voto por IP por enquete | Uma casa ou empresa inteira divide o mesmo IP; com celular e Wi-Fi a mesma pessoa tem dois |
| Conta | Um voto por usuário logado, com chave única no banco | O mais confiável, mas cria atrito e reduz votos |

Na prática, combine: cookie para o caso comum, limite por IP mais folgado para conter abuso em massa, e conta obrigatória como opção de quem cria a enquete quando o resultado importa.

<Callout type="note" title="Não existe enquete anônima à prova de fraude">
Sem identificar a pessoa, você só consegue tornar a fraude mais trabalhosa, nunca impossível. Dizer isso com clareza no README mostra mais maturidade do que fingir que o problema está resolvido.
</Callout>

## Extras para se destacar

- Data de encerramento automática.
- Opção de esconder o resultado até a pessoa votar, para não influenciar.
- QR code do link para usar em aula ou apresentação.
- Captcha leve só quando o mesmo IP vota muito em pouco tempo.
