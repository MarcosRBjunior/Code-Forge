**Em uma frase:** o usuário anexa uma imagem à mensagem e o modelo responde sobre o que vê nela.

**Nível:** intermediário em IA · **Tempo:** 2 a 3 dias · **Pré-requisito:** [Projeto 3: memória de conversas](/learn/projetos-portfolio/memoria-de-conversas)

## O que você vai construir

Um botão de clipe ao lado da caixa de mensagem. O usuário escolhe uma foto (um print de erro, um gráfico, um cardápio), escreve uma pergunta e envia as duas coisas juntas. O modelo, que precisa ter suporte a visão, responde considerando a imagem, e a miniatura fica no histórico da conversa.

É o projeto mais curto da trilha porque quase tudo já existe. O que muda no código: a mensagem deixa de ser uma string e vira uma lista de partes (texto e imagem), tanto na rota de API quanto na tabela `messages` do Projeto 3. Como a conversa é persistida, a imagem também precisa ser: ao retomar a sessão amanhã, a miniatura tem que aparecer e o modelo tem que poder voltar a ela numa pergunta de acompanhamento.

## MVP

- [ ] Botão de anexar que aceita jpg e png
- [ ] Imagem e texto enviados na mesma mensagem
- [ ] Modelo com visão respondendo sobre a imagem, com streaming
- [ ] Miniatura da imagem no histórico, inclusive ao reabrir a conversa
- [ ] Funciona dentro de uma sessão com memória (Projeto 3)

## Stack sugerida

| Camada | Opção principal | Alternativa |
|---|---|---|
| UI, sessões e banco | Os mesmos dos Projetos 1 a 3 | — |
| Formato da mensagem | Array de conteúdo com partes de texto e de imagem | — |
| Armazenamento | Object storage (S3, Azure Blob, Supabase Storage) | Base64 no banco, só no MVP |
| Modelo | Qualquer provedor com entrada de imagem | Modelo local com visão via Ollama |

Base64 no banco funciona para começar, mas incha a tabela e cada imagem de alguns megabytes vira um texto ainda maior. Com object storage, o banco guarda só a chave do arquivo e o servidor gera um link temporário quando precisa.

## Fora do escopo

Várias imagens por mensagem, um pipeline de OCR separado e geração de imagens. O objetivo aqui é entrada multimodal; gerar imagem é outro produto.

## Etapas

1. **Escolher o arquivo no front.** Use um `input` de arquivo com filtro de tipo e mostre a pré-visualização antes do envio, com um botão para remover.
2. **Validar no servidor.** Confira o tipo real do arquivo (não só a extensão) e o tamanho máximo antes de gravar qualquer coisa. Redimensione imagens muito grandes: o modelo raramente precisa de mais que alguns megapixels, e imagem maior custa mais tokens.
3. **Guardar a imagem.** Grave no storage e salve na mensagem só a referência. Adapte a coluna `content` para aceitar a lista de partes (um campo JSON resolve).
4. **Montar a chamada.** Converta a mensagem para o formato de conteúdo multimodal do provedor. As mensagens antigas da sessão também entram, então decida se imagens de turnos anteriores vão de novo ou se só o texto delas basta.
5. **Miniatura no histórico.** Ao carregar a sessão, gere os links das imagens e exiba a miniatura ao lado da mensagem do usuário.

Na maioria dos SDKs, a mensagem fica parecida com isto:

```typescript
const userMessage = {
  role: "user",
  content: [
    { type: "text", text: "O que está errado neste gráfico?" },
    { type: "image", image: imageUrl },
  ],
};
```

<Callout type="warning" title="Nunca confie no navegador">
O filtro do `input` de arquivo é só conveniência. Quem chama a sua API direto pode mandar qualquer coisa, de qualquer tamanho. Valide tipo e tamanho no servidor e, se o app for público, limite quantas imagens cada usuário pode enviar por hora: chamadas com imagem custam bem mais que as de texto.
</Callout>

## Extras para se destacar

- Colar imagem direto da área de transferência e arrastar e soltar.
- Mostrar o custo estimado de cada mensagem com imagem.
- Permitir que o RAG do Projeto 2 receba a imagem de uma página escaneada.
- Abrir a imagem em tamanho real ao clicar na miniatura.
