**Em uma frase:** um jogo de peças que caem num tabuleiro, com rotação, linhas que somem, pontuação e níveis, rodando no navegador com Canvas.

**Nível:** avançado · **Tempo:** 2 a 3 semanas · **Pré-requisito:** JavaScript ou TypeScript com segurança e noção de matrizes

## O que você vai construir

Um jogo completo e jogável: peças de quatro blocos descem, você move para os lados, gira, acelera a queda, completa linhas e vê a velocidade aumentar com o nível. Parece um projeto "de diversão", mas é um dos melhores para mostrar engenharia: há estado, tempo, regras com muitos casos de borda e uma separação clara entre lógica e renderização.

Dê ao jogo um nome, um logo e um visual próprios. O gênero de blocos que caem é livre, mas a marca, a música e a arte de jogos comerciais não são: crie suas cores e sons, ou use recursos com licença que permita o uso.

## MVP

- [ ] Tabuleiro de 10 por 20 com as sete peças clássicas e sorteio justo (saco de 7)
- [ ] Movimento lateral, queda suave, queda instantânea e rotação com verificação de colisão
- [ ] Linhas completas removidas, pontuação e aumento de nível a cada 10 linhas
- [ ] Prévia da próxima peça, pausa e tela de fim de jogo
- [ ] Lógica do jogo em módulo puro, coberta por testes unitários
- [ ] Deploy público e README com GIF de uma partida

## Fora do escopo

Multiplayer, ranking on-line, peça guardada (hold), animações elaboradas e versão mobile com gestos. Ranking global, se vier depois, exige validar a partida no servidor; um placar que o cliente envia pronto é fácil de fraudar.

## Etapas

1. **Modele o estado.** O tabuleiro é uma matriz de 20 linhas por 10 colunas, em que 0 é vazio e outro número indica a cor. A peça ativa é uma pequena matriz mais a posição. Todo o estado do jogo cabe num objeto simples.
2. **Escreva a lógica como funções puras.** `collides(board, piece)`, `rotate(piece)`, `lockPiece(board, piece)` e `clearLines(board)` recebem estado e devolvem estado novo, sem tocar no Canvas. É isso que torna o jogo testável.
3. **Rotação com ajuste.** Girar uma matriz no sentido horário é transpor e inverter cada linha. Se a peça girada colide com a parede, tente deslocá-la uma ou duas colunas antes de desistir; sem esse ajuste, girar perto da borda parece um bug.
4. **Game loop com tempo fixo.** Use `requestAnimationFrame` para desenhar, mas faça a peça descer com base no tempo acumulado, não no número de quadros. Assim o jogo tem a mesma velocidade num monitor de 60 Hz e num de 144 Hz.

```typescript
let acc = 0, last = performance.now();
function frame(now: number) {
  acc += now - last; last = now;
  while (acc >= dropInterval(state.level)) { state = tick(state); acc -= dropInterval(state.level); }
  render(ctx, state);
  if (!state.over) requestAnimationFrame(frame);
}
```

5. **Linhas, pontos e níveis.** Ao travar uma peça, remova as linhas cheias, some os pontos (mais pontos para várias linhas de uma vez) e reduza o intervalo de queda conforme o nível sobe.
6. **Entrada e estados.** Trate teclado num só lugar e organize o jogo como máquina de estados: jogando, pausado, fim de jogo. Isso evita bugs como peças se movendo durante a pausa.
7. **Testes.** Cubra colisão nas bordas, rotação perto da parede, remoção de duas linhas não adjacentes e fim de jogo quando a peça nova já nasce colidindo.

## Extras para se destacar

- Peça fantasma mostrando onde a peça vai cair.
- Recorde salvo no `localStorage` e controles configuráveis.
- Replays determinísticos: com sorteio por semente e a lista de comandos, a partida se reproduz igual.
- Suporte a toque no celular.

## O que este projeto mostra no portfólio

"Eu separo regra de negócio de interface: toda a lógica do jogo é pura e testada, e o loop roda na mesma velocidade em qualquer tela."
