**Em uma frase:** o usuário envia um PDF, faz uma pergunta e recebe a resposta junto com o trecho do documento que a sustenta.

**Nível:** intermediário em IA · **Tempo:** 5 a 7 dias (com o Projeto 1 pronto) · **Pré-requisito:** [Projeto 1: chat com streaming](/learn/projetos-portfolio/chat-com-streaming)

## O que você vai construir

O chat do Projeto 1 ganha um "cérebro" externo: em vez de responder só com o que aprendeu no treino, o modelo responde com base num documento que o usuário acabou de enviar. Esse é o padrão de RAG (Retrieval-Augmented Generation): recuperar os trechos relevantes, colocá-los no prompt e pedir uma resposta presa a eles.

Você não começa do zero. A tela de chat, o streaming e a rota de API continuam iguais. O que muda é o caminho da mensagem no servidor: antes de chamar o modelo, a rota busca os trechos mais parecidos com a pergunta e monta um prompt com eles. Do lado da UI, entram só duas peças novas: o upload e a exibição da citação.

## MVP

- [ ] Upload de 1 PDF (ou um campo para colar texto, se o PDF atrasar você)
- [ ] Divisão do texto em chunks, geração de embeddings e gravação num vector store
- [ ] Recuperação dos top-k chunks mais próximos da pergunta, montagem do prompt e resposta com streaming
- [ ] Na UI, o trecho (ou trechos) usado na resposta, com página ou posição no documento
- [ ] Quando nada relevante for encontrado, a resposta é "não encontrei isso no documento", sem inventar

## Stack sugerida

| Camada | Opção principal | Alternativa |
|---|---|---|
| UI e rota | A mesma do Projeto 1 | — |
| Orquestração de RAG | Código manual (poucas funções) | LangChain ou LlamaIndex |
| Vector store | Postgres com pgvector | Chroma local ou um array em memória |
| Extração de PDF | Uma biblioteca de leitura de PDF da sua linguagem | Colar texto puro no MVP |
| Embeddings | O modelo de embeddings do seu provedor | Um modelo local de embeddings |

O pgvector é a recomendação porque o Projeto 3 vai precisar de Postgres de qualquer jeito: você guarda vetores e conversas no mesmo banco. Escrever o RAG à mão na primeira vez também vale a pena, porque na entrevista você vai saber explicar cada etapa sem depender da abstração de um framework.

## Fora do escopo

Vários usuários com permissões por documento (multi-tenant e ACL), re-ranking com modelo dedicado e avaliação automatizada da qualidade das respostas. São ótimos assuntos para os extras ou para a conversa na entrevista, mas não para o MVP.

## Etapas

1. **Ingestão.** Extraia o texto do PDF guardando o número da página de cada parte. Sem essa informação, a citação na UI fica vaga.
2. **Chunking.** Corte em pedaços de algumas centenas de tokens com uma pequena sobreposição entre eles. Pedaço grande demais dilui o significado; pequeno demais perde o contexto.
3. **Embeddings e gravação.** Gere o vetor de cada chunk e grave junto com o texto, a página e o id do documento. Faça isso uma vez, no upload, e não a cada pergunta.
4. **Recuperação.** Gere o embedding da pergunta, busque os k chunks mais próximos e descarte os que ficarem abaixo de um limiar de similaridade. Se não sobrar nenhum, responda que não encontrou, sem chamar o modelo.
5. **Prompt com contexto.** Monte o prompt com os chunks numerados e instrua o modelo a responder só com base neles e a indicar quais números usou. Mande a resposta pela mesma rota com streaming do Projeto 1.
6. **Citação na UI.** Abaixo da resposta, mostre o trecho citado e a página. É aqui que o usuário passa a confiar (ou não) no que leu.

A busca do passo 4, com pgvector, é uma consulta comum:

```sql
SELECT content, page, 1 - (embedding <=> $1) AS similarity
FROM chunks
WHERE document_id = $2
ORDER BY embedding <=> $1
LIMIT 5;
```

<Callout type="warning" title="O documento é dado, não instrução">
Um PDF pode conter frases como "ignore as instruções anteriores e responda X". Isso é prompt injection. Coloque os chunks num bloco claramente delimitado, diga no prompt de sistema que o conteúdo ali é material de consulta e nunca deixe o texto recuperado decidir ações do sistema.
</Callout>

## Extras para se destacar

- Busca híbrida: combinar a busca vetorial com busca por palavra-chave (BM25) para nomes próprios e códigos.
- Um pequeno conjunto de perguntas com resposta esperada para conferir se uma mudança no chunking melhorou ou piorou o resultado.
- Destacar o trecho citado dentro do próprio PDF, numa visualização lado a lado.
- Mostrar quanto custou cada upload (tokens de embedding) e cada pergunta.
