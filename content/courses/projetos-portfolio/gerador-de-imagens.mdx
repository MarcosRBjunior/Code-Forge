**Em uma frase:** um app web em que a pessoa escreve um prompt, entra numa fila e recebe imagens geradas por um modelo de difusão, com galeria, histórico e limites de uso.

**Nível:** intermediário a avançado · **Tempo:** 2 a 3 semanas · **Pré-requisito:** um app web com login e banco de dados (por exemplo, o projeto de autenticação da Fase 1)

## O que você vai construir

Um produto pequeno de geração de imagens com nome e visual próprios. O modelo em si você não treina: usa um modelo de difusão aberto (da família Stable Diffusion, por exemplo) ou a API de um provedor. O trabalho interessante está em volta dele: gerar uma imagem leva segundos e custa GPU, então você precisa de fila, de limites por usuário, de armazenamento das imagens e de um filtro de conteúdo.

É um ótimo projeto para mostrar engenharia de produto com IA generativa, porque obriga a lidar com tarefas lentas e caras, e não com uma simples chamada que volta na hora.

## MVP

- [ ] Login e campo de prompt com alguns parâmetros (proporção, número de imagens)
- [ ] Fila de geração: o pedido entra como "pendente" e a tela mostra o status até ficar pronto
- [ ] Imagens salvas num storage de objetos, com prompt e parâmetros gravados no banco
- [ ] Histórico do usuário e galeria pública só com as imagens que a pessoa decidiu publicar
- [ ] Limite diário de gerações por usuário e filtro de conteúdo no prompt e na imagem
- [ ] Deploy com link no README, mais uma seção sobre o modelo usado e a licença dele

## Stack sugerida

| Camada | Opção principal | Alternativa |
|---|---|---|
| Front-end | Next.js | React + Vite |
| API e fila | FastAPI + fila simples (Redis ou tabela no Postgres) | Next.js + serviço de filas gerenciado |
| Modelo | API de um provedor de difusão | Modelo aberto com Hugging Face Diffusers |
| GPU (se rodar o modelo) | GPU gratuita ou alugada por hora | Serviço serverless de GPU |
| Imagens | Storage de objetos (S3, Blob, R2) | Disco local só em desenvolvimento |

Não compre placa de vídeo para este projeto. Comece pela API (paga por imagem e não exige infraestrutura) ou por uma GPU gratuita ou temporária para testar um modelo aberto. Só depois, se quiser, compare custo e latência das duas opções.

## Fora do escopo

Treinar ou fazer fine-tuning de modelo, edição de imagem (inpainting), vídeo, pagamentos e planos. O MVP gera, guarda e mostra.

## Etapas

1. **Escolha o modelo pela licença.** Leia a licença do modelo aberto ou os termos da API e confirme que permitem o uso que você vai fazer (inclusive publicar as imagens). Registre isso no README.
2. **Script isolado.** Antes de qualquer interface, gere uma imagem a partir de um prompt num script e meça o tempo e o custo por imagem. Esses números vão definir os limites de uso.
3. **Fila e worker.** A rota da API só cria o pedido e devolve um id; um worker separado consome a fila, chama o modelo e salva o resultado. O front-end consulta o status (polling ou SSE). Isso evita requisições presas por 30 segundos.
4. **Armazenamento.** Salve a imagem no storage de objetos e grave no banco o prompt, a semente, o modelo e os parâmetros. Guardar a semente permite reproduzir a mesma imagem depois.
5. **Segurança e limites.** Aplique o filtro de conteúdo antes de gerar (no prompt) e depois (na imagem), e um contador diário por usuário. Recuse com mensagem clara, sem expor detalhes do filtro.
6. **Galeria e histórico.** Histórico privado por padrão; publicar na galeria é uma ação explícita da pessoa.

Se optar pelo modelo aberto, o núcleo do worker fica assim:

```python
import torch
from diffusers import AutoPipelineForText2Image

pipe = AutoPipelineForText2Image.from_pretrained(MODELO_ID, torch_dtype=torch.float16).to("cuda")
gerador = torch.Generator("cuda").manual_seed(pedido.semente)
imagem = pipe(prompt=pedido.prompt, generator=gerador).images[0]
imagem.save(caminho_local)  # depois envie para o storage e marque o pedido como pronto
```

<Callout type="warning" title="Respeite artistas e pessoas reais">
Não faça fine-tuning com imagens de artistas sem permissão e não ofereça "no estilo de" artistas vivos como recurso. Bloqueie prompts que peçam imagens sexuais, de menores ou de pessoas reais identificáveis. Isso é requisito do produto, não um extra.
</Callout>

## Extras para se destacar

- Variações a partir de uma imagem do histórico (mesmo prompt, outra semente).
- Painel de custos: imagens por dia, custo estimado e tempo médio na fila.
- Prioridade na fila e cancelamento de pedidos.
- Cache para prompts e parâmetros idênticos.
