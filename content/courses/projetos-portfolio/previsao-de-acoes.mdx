**Em uma frase:** um pipeline de séries temporais que tenta prever o preço de fechamento de uma ação e mede, com rigor, se isso é melhor que o palpite mais simples possível.

**Nível:** intermediário em ML · **Tempo:** 1 a 2 semanas · **Pré-requisito:** Python, pandas e noções de regressão

## O que você vai construir

Um projeto de previsão de séries temporais com dados diários de algumas ações: você cria features a partir de janelas do passado, treina modelos, valida com walk-forward e publica um dashboard que mostra previsão contra o valor real ao longo do tempo.

O objetivo não é "ganhar dinheiro com IA". É mostrar que você sabe avaliar um modelo num dos problemas mais traiçoeiros que existem, em que quase todo erro de método parece um resultado espetacular.

<Callout type="warning" title="Não é recomendação de investimento">
Preço de ação é quase imprevisível no curto prazo: ele já incorpora a informação pública disponível, e o que sobra se parece muito com ruído. Este projeto é um exercício de avaliação, não uma estratégia de investimento. Deixe isso escrito no README e não prometa lucro em lugar nenhum.
</Callout>

## MVP

- [ ] Dados diários de 2 a 5 ações de uma fonte pública, com a origem e os termos de uso citados
- [ ] Baseline ingênuo "amanhã = hoje" calculado antes de qualquer modelo
- [ ] Features de janelas (retornos defasados, médias móveis, volatilidade) usando só dados do passado
- [ ] Validação walk-forward, sem embaralhar as linhas
- [ ] Tabela comparando baseline e modelos em MAE e acerto de direção
- [ ] Dashboard publicado com previsão versus real e o erro ao longo do tempo

## Fora do escopo

Operar de verdade, backtest de estratégia com custos de corretagem, notícias e sentimento de redes sociais, deep learning. Tudo isso pode virar extra depois que a avaliação básica estiver sólida.

## Etapas

1. **Defina o alvo e o corte de teste.** Decida o que prever (o retorno do dia seguinte é melhor que o preço bruto, porque preço tem tendência e engana as métricas) e reserve os últimos meses como teste final antes de explorar os dados.
2. **Baseline primeiro.** Calcule o erro de prever que o preço de amanhã é igual ao de hoje (retorno zero). Esse número é a régua; quase sempre ele é surpreendentemente difícil de bater.
3. **Features sem olhar o futuro.** Toda feature da linha do dia D só pode usar informação disponível até o fechamento de D. Médias móveis centradas, normalização com estatísticas do período inteiro e preenchimento de buracos "para trás" são vazamentos clássicos.
4. **Walk-forward.** Treine com o passado, preveja o bloco seguinte, avance a janela e repita. Isso simula o uso real e mostra se o desempenho é estável ou se foi sorte de um período.
5. **Compare com honestidade.** Reporte MAE e acerto de direção do baseline e de cada modelo, por janela. Se o modelo empata com o baseline, esse é um resultado válido: escreva isso.
6. **Dashboard.** Mostre a série real, a previsão e o erro acumulado, com a linha do baseline sempre visível.

A divisão temporal com o scikit-learn é direta:

```python
from sklearn.model_selection import TimeSeriesSplit
from sklearn.metrics import mean_absolute_error

tscv = TimeSeriesSplit(n_splits=5)
for treino, val in tscv.split(X):
    modelo.fit(X.iloc[treino], y.iloc[treino])
    mae_modelo = mean_absolute_error(y.iloc[val], modelo.predict(X.iloc[val]))
    mae_base = mean_absolute_error(y.iloc[val], [0.0] * len(val))  # retorno zero
    print(f"modelo={mae_modelo:.4f}  baseline={mae_base:.4f}")
```

## Extras para se destacar

- Intervalos de previsão (quantis) em vez de um número só.
- Teste estatístico simples para ver se a diferença em relação ao baseline é significativa.
- Mini backtest com custo de transação, mostrando como uma vantagem pequena some.
- Pipeline agendado que atualiza dados e previsões todo dia.

## O que este projeto mostra no portfólio
