**Em uma frase:** um painel que mostra um indicador público por região num mapa colorido, com gráficos e filtros que contam a história dos dados.

**Nível:** intermediário · **Tempo:** 1 a 2 semanas · **Pré-requisito:** já ter feito um app que consome uma API

## O que você vai construir

Um dashboard em que a pessoa escolhe um indicador (população, renda, cobertura de saneamento, o que você preferir) e vê cada estado ou município pintado de acordo com o valor, num mapa coroplético. Ao clicar numa região, aparecem os números dela e um gráfico de evolução no tempo. Filtros de ano e de indicador atualizam tudo junto.

Use dados públicos com licença aberta, como as APIs de dados do IBGE ou portais de dados abertos do governo, e cite a fonte no app e no README. O projeto treina coisas que aparecem em qualquer vaga de front-end ou full-stack: consumir API externa lenta, transformar dados, desenhar visualização e pensar em quem vai ler.

## MVP

- [ ] Mapa coroplético por estado ou município com legenda de cores
- [ ] Pelo menos um indicador com filtro de ano
- [ ] Clique na região mostra detalhes e um gráfico de série temporal
- [ ] Dados servidos por uma rota sua com cache, não direto da fonte a cada visita
- [ ] Paleta de cores acessível e tabela alternativa com os mesmos números
- [ ] Deploy e README com GIF e a fonte dos dados citada

## Stack sugerida

| Camada | Opção principal | Alternativa |
|---|---|---|
| Front-end | Next.js ou React + Vite | SvelteKit |
| Mapa | Leaflet com GeoJSON | MapLibre GL ou D3 com projeção |
| Gráficos | Recharts ou Chart.js | Observable Plot |
| Dados | Rota de API com cache em memória ou arquivo | Script que gera JSON estático no build |

## Fora do escopo

Login, upload de dados pelo usuário, dezenas de indicadores e mapas de ruas com zoom infinito. Um indicador bem explicado vence dez mal explicados.

## Etapas

1. **Explore os dados antes de qualquer tela.** Baixe uma amostra da API, entenda o formato, os códigos de região e onde estão os valores ausentes. Anote no README o que cada campo significa; esse entendimento é metade do projeto.
2. **Junte geometria e números.** Obtenha a malha geográfica (GeoJSON) das regiões e associe cada polígono ao indicador pelo código oficial da região, não pelo nome, que tem acento, abreviação e grafia variando entre fontes.
3. **Crie a camada de dados com cache.** Sua rota busca na fonte, normaliza o formato e guarda o resultado. Dados estatísticos mudam raramente, então um cache de horas ou dias é seguro e evita que o app caia quando a API pública ficar lenta.
4. **Desenhe o mapa.** Divida os valores em 5 a 7 faixas (quantis costumam funcionar melhor que intervalos iguais quando os dados são concentrados) e use uma escala sequencial de uma só cor.
5. **Adicione gráficos e filtros.** Um estado único (indicador, ano, região selecionada) guiando mapa, gráfico e tabela evita telas dessincronizadas. Guarde esse estado na URL para que um link compartilhado abra a mesma visão.
6. **Acessibilidade e README.** Teste a paleta com simulador de daltonismo, garanta contraste do texto e ofereça a tabela com os mesmos números para quem usa leitor de tela.

O cálculo das faixas por quantil cabe em poucas linhas:

```typescript
function quantileBreaks(values: number[], classes = 5): number[] {
  const sorted = values.filter(Number.isFinite).sort((a, b) => a - b);
  return Array.from({ length: classes - 1 }, (_, i) =>
    sorted[Math.floor(((i + 1) / classes) * (sorted.length - 1))]
  );
}
```

<Callout type="tip" title="Cor não é a única pista">
Cerca de uma em cada doze pessoas do sexo masculino tem alguma deficiência na percepção de cores. Escala sequencial de uma cor, legenda com os números de cada faixa e tooltip com o valor exato resolvem a maior parte do problema.
</Callout>

## Extras para se destacar

- Comparação entre duas regiões lado a lado.
- Indicador per capita calculado a partir de dois dados brutos, com a fórmula explicada.
- Geração do JSON no build (dados estáticos) e comparação de tempo de carregamento com a versão dinâmica.
- Exportar a visão atual como CSV ou imagem.
