<Quiz question="Seu sistema de e-commerce precisa criar objetos Pedido com cliente, itens, cupom opcional, endereço opcional, observações e forma de entrega, e o pedido nunca pode existir sem itens. Qual padrão encaixa melhor?" options={["Singleton", "Builder", "Prototype", "Abstract Factory"]} answer={1} explanation="Muitos campos opcionais, montagem incremental e validação antes de entregar o produto são o caso típico do Builder." />
<Quiz question="Uma plataforma suporta MySQL e PostgreSQL, e para cada banco precisa de conexão, dialeto SQL e ferramenta de migração compatíveis entre si. Qual padrão evita misturar peças de bancos diferentes?" options={["Factory Method, com uma subclasse criadora para cada tipo de peça","Prototype, clonando uma conexão já configurada para cada banco","Abstract Factory, com uma fábrica por banco que cria todas as peças","Builder, montando passo a passo a conexão e o dialeto de cada banco"]} answer={2} explanation="Famílias de objetos relacionados escolhidas juntas são o problema que o Abstract Factory resolve." />
<Quiz question="Qual afirmação sobre Factory Method está correta?" options={["Ele cria famílias de objetos relacionados que devem ser usados juntos","Ele deixa as subclasses do criador decidirem qual produto concreto instanciar","Ele copia instâncias existentes para evitar o custo de criar objetos do zero","Ele garante que a classe tenha uma única instância acessível globalmente por todo o código"]} answer={1} explanation="O método fábrica é sobrescrito pelas subclasses, que escolhem o produto concreto." />
<Quiz question="Num jogo, cada fase cria dezenas de inimigos parecidos cuja configuração inicial é cara (carrega sprites e atributos de arquivo). Qual padrão reduz esse custo?" options={["Prototype: configure um inimigo modelo uma vez e clone-o para cada novo","Singleton: mantenha um único inimigo compartilhado por todas as posições","Facade: esconda o carregamento dos arquivos atrás de uma interface simples","Abstract Factory: crie uma fábrica com um método para cada tipo de inimigo"]} answer={0} explanation="Criar uma vez e clonar evita repetir o trabalho caro; cada clone pode ajustar posição e vida." />
<Quiz question="Duas threads chamam Config.obter() ao mesmo tempo pela primeira vez e o log mostra o arquivo de configuração sendo lido duas vezes. Qual a correção?" options={["Trocar a classe por um Prototype que clona a configuração a cada chamada","Proteger a criação com um lock e checar a instância de novo dentro dele","Usar cópia profunda da configuração em cada thread que a solicitar","Remover o método obter() e deixar cada thread ler o arquivo diretamente"]} answer={1} explanation="Sem sincronização há condição de corrida; o double-checked locking (ou criação ansiosa) resolve." />
<Quiz question="Qual é a principal desvantagem do Singleton em uma base de código grande?" options={["Exige criar muitas subclasses, uma para cada contexto em que ele é usado","Esconde dependências e compartilha estado global, dificultando testes isolados","Impede a classe de ter métodos de instância além do construtor padrão","Só funciona quando a classe é declarada como dataclass, o que limita muito seu uso"]} answer={1} explanation="Classes que acessam o Singleton não declaram essa dependência, e o estado vaza entre testes." />
<Quiz question="Qual diferença entre Prototype e Memento é correta?" options={["São o mesmo padrão, e a diferença está apenas no nome usado em cada contexto de uso","Prototype cria um objeto novo e independente; Memento guarda estado para restaurar o original","Memento cria famílias de objetos relacionados; Prototype guarda o histórico de estados do objeto original","Prototype só funciona combinado com Singleton; Memento funciona isoladamente"]} answer={1} explanation="Ambos capturam estado, mas a intenção é diferente: criar versus desfazer." />
