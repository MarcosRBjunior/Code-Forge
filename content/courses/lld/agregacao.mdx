**Agregação** é uma associação do tipo "todo e parte" em que a parte **pode existir sem o todo**. Um time agrega jogadores: se o time for extinto, os jogadores continuam existindo e podem ir para outro time. Uma playlist agrega músicas: apagar a playlist não apaga as músicas do catálogo.

## Como reconhecer

Faça duas perguntas:

1. Existe uma relação de "todo e parte" ou "contém"? Se não, é associação simples.
2. A parte sobrevive quando o todo é destruído, ou pode pertencer a outro todo? Se sim, é agregação. Se não, é composição.

Em UML, agregação é desenhada com um **losango vazio** do lado do todo:

```text
Time ◇────────── Jogador
      1      0..*
```

## Sinais no código

Na agregação, o todo normalmente **recebe** as partes prontas de fora, em vez de criá-las. Quem criou a parte continua com uma referência a ela.

```python
class Musica:
    def __init__(self, titulo: str, duracao_s: int) -> None:
        self.titulo = titulo
        self.duracao_s = duracao_s

    def __repr__(self) -> str:
        return f"Musica({self.titulo!r})"


class Playlist:
    def __init__(self, nome: str) -> None:
        self.nome = nome
        self._musicas: list[Musica] = []

    def adicionar(self, musica: Musica) -> None:  # parte vem de fora
        self._musicas.append(musica)

    def remover(self, musica: Musica) -> None:
        self._musicas.remove(musica)

    def duracao_total(self) -> int:
        return sum(m.duracao_s for m in self._musicas)

    @property
    def musicas(self) -> tuple[Musica, ...]:
        return tuple(self._musicas)


catalogo = [Musica("Asa Branca", 190), Musica("Garota de Ipanema", 290), Musica("Aquarela", 250)]

estudo = Playlist("Para estudar")
viagem = Playlist("Viagem")
estudo.adicionar(catalogo[1])
viagem.adicionar(catalogo[1])  # a mesma música em duas playlists
viagem.adicionar(catalogo[0])

print(viagem.duracao_total())  # 480
del estudo                     # playlist some...
print(catalogo[1])             # ...a música continua no catálogo
print(viagem.musicas)
```

Características visíveis:

- `Playlist` não cria `Musica`; recebe pelo método `adicionar`.
- A mesma música pertence a duas playlists ao mesmo tempo.
- Destruir a playlist não afeta as músicas.

## Outro exemplo: departamento e professores

```python
class Professor:
    def __init__(self, nome: str) -> None:
        self.nome = nome


class Departamento:
    def __init__(self, nome: str, professores: list[Professor] | None = None) -> None:
        self.nome = nome
        self._professores = list(professores or [])

    def lotar(self, professor: Professor) -> None:
        self._professores.append(professor)

    def transferir(self, professor: Professor, destino: "Departamento") -> None:
        self._professores.remove(professor)
        destino.lotar(professor)

    def nomes(self) -> list[str]:
        return [p.nome for p in self._professores]


ana, beto = Professor("Ana"), Professor("Beto")
fisica = Departamento("Física", [ana, beto])
quimica = Departamento("Química")
fisica.transferir(beto, quimica)
print(fisica.nomes(), quimica.nomes())  # ['Ana'] ['Beto']
```

A transferência é natural justamente porque a parte tem vida própria. Note também `list(professores or [])`: copiar a lista recebida evita que o departamento compartilhe a mesma lista com quem o criou.

## Agregação vs composição, lado a lado

| Pergunta | Agregação | Composição |
| --- | --- | --- |
| A parte existe sem o todo? | sim | não |
| A parte pode estar em vários todos? | pode | não |
| Quem cria a parte? | normalmente alguém de fora | normalmente o todo |
| Destruir o todo destrói a parte? | não | sim |
| UML | losango vazio | losango cheio |

<Callout type="note" title="A linha é de domínio, não de sintaxe">
Em Python, o código de agregação e de composição pode ficar quase igual: ambos guardam referências em atributos. A diferença está na **semântica do domínio** e em quem controla o ciclo de vida. Por isso, explique a escolha em palavras.
</Callout>

## Armadilhas

- **Tratar tudo como composição.** Se a parte é compartilhada (música em várias playlists), destruí-la junto com o todo é um bug de domínio.
- **Remover a parte do sistema ao removê-la do todo.** Tirar um jogador do time não deveria apagar o jogador.
- **Aliasing acidental.** Guardar a lista recebida sem copiar faz duas entidades compartilharem a mesma coleção.
