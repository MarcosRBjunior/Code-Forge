A máquina de vendas é o exemplo canônico do padrão **State**: o que um botão faz depende do estado em que a máquina está. Apertar "selecionar" sem ter inserido dinheiro, inserir moedas durante uma entrega, pedir troco sem nada pago: todas são combinações que precisam de resposta definida. O entrevistador observa se você modela esses estados explicitamente em vez de um emaranhado de ifs e flags.

## Requisitos

- **Produtos**: código, nome, preço e quantidade em estoque.
- **Dinheiro**: aceitar moedas e notas (valores em centavos, para evitar erro de ponto flutuante).
- **Fluxo**: inserir dinheiro, selecionar produto, entregar e devolver troco.
- **Cancelamento**: devolver o dinheiro inserido antes da entrega.
- **Casos de borda**: produto esgotado, dinheiro insuficiente, código inexistente.
- Fora de escopo: reposição por operador (extensão) e pagamento por cartão.

## Estados e transições

```text
SEM_DINHEIRO --inserir--> COM_DINHEIRO --selecionar(ok)--> ENTREGA --> SEM_DINHEIRO
      ^                        |   ^                                       |
      |                        |   +--inserir (acumula)                    |
      +---------cancelar-------+                                           |
      +------------------------------ troco devolvido ---------------------+
```

| Estado | inserir | selecionar | cancelar |
| --- | --- | --- | --- |
| Sem dinheiro | passa a Com dinheiro | pede para inserir dinheiro | nada a devolver |
| Com dinheiro | acumula saldo | valida e entrega | devolve saldo |

## Código

Cada estado é uma classe que implementa as mesmas operações; a máquina delega.

from abc import ABC, abstractmethod


class Produto:
    def __init__(self, nome: str, preco: int, qtd: int) -> None:
        self.nome, self.preco, self.qtd = nome, preco, qtd


class Estado(ABC):
    @abstractmethod
    def inserir(self, m: "Maquina", centavos: int) -> str: ...

    @abstractmethod
    def selecionar(self, m: "Maquina", codigo: str) -> str: ...

    @abstractmethod
    def cancelar(self, m: "Maquina") -> str: ...


class SemDinheiro(Estado):
    def inserir(self, m, centavos):
        m.saldo = centavos
        m.estado = ComDinheiro()
        return "saldo atualizado"

    def selecionar(self, m, codigo):
        return "insira dinheiro primeiro"

    def cancelar(self, m):
        return "nada a devolver"


class ComDinheiro(Estado):
    def inserir(self, m, centavos):
        m.saldo += centavos
        return "saldo atualizado"

    def selecionar(self, m, codigo):
        produto = m.estoque.get(codigo)
        if produto is None:
            return "código inválido"
        if produto.qtd == 0:
            return "esgotado"
        if m.saldo < produto.preco:
            return "saldo insuficiente"
        produto.qtd -= 1
        troco = m.saldo - produto.preco
        m.saldo = 0
        m.estado = SemDinheiro()
        return f"entregue {produto.nome}, troco {troco}"

    def cancelar(self, m):
        devolvido = m.saldo
        m.saldo = 0
        m.estado = SemDinheiro()
        return f"devolvido {devolvido}"


class Maquina:
    def __init__(self, estoque: dict[str, Produto]) -> None:
        self.estoque = estoque
        self.saldo = 0
        self.estado: Estado = SemDinheiro()

    def inserir(self, centavos: int) -> str:
        return self.estado.inserir(self, centavos)

    def selecionar(self, codigo: str) -> str:
        return self.estado.selecionar(self, codigo)

    def cancelar(self) -> str:
        return self.estado.cancelar(self)

## Decisões que merecem fala

- **Centavos inteiros**: nada de `float` para dinheiro.
- **State em vez de ifs**: adicionar o estado `FORA_DE_SERVICO` é criar uma classe, sem tocar nas existentes.
- **Troco**: aqui devolvido como valor. Em extensão, uma estratégia de troco decide quais moedas devolver (um problema de moedas com limite de caixa).
- **Atomicidade**: a entrega só ocorre depois de validar tudo; assim um erro não deixa estoque e saldo inconsistentes.

</Callout>
