## O problema

Uma empresa tem uma política de aprovação de despesas: até R$ 500 o coordenador aprova; até R$ 5.000, o gerente; até R$ 50.000, a diretoria; acima disso, só o CFO. Outra situação parecida: uma requisição HTTP precisa passar por autenticação, limite de taxa, validação de payload e só então chegar ao controlador; qualquer etapa pode barrar a requisição.

Colocar isso num único método com uma cascata de `if` acopla quem envia o pedido a todas as regras e à ordem delas. Adicionar um aprovador intermediário ou uma etapa de log exige editar o método central.

O Chain of Responsibility **encadeia objetos handlers**. O pedido entra no primeiro elo; cada handler decide se trata o pedido, se o repassa ao próximo, ou as duas coisas. Quem envia o pedido conhece só o início da cadeia.

## Estrutura

```text
 Cliente
    |
    v
+-----------+  proximo  +-----------+  proximo  +-----------+
| HandlerA  |---------->| HandlerB  |---------->| HandlerC  |----> (fim)
+-----------+           +-----------+           +-----------+
      ^                       ^                       ^
      +-----------------------+-----------------------+
                              |
                  +-------------------------+
                  |  Handler (abstrato)     |
                  |-------------------------|
                  | - proximo: Handler      |
                  | + definir_proximo(h)    |
                  | + tratar(pedido)        |
                  +-------------------------+
```

Existem duas variações comuns:

- **Um trata e para**: o primeiro handler capaz resolve e a cadeia termina (aprovação de despesas, suporte em níveis).
- **Todos podem agir, qualquer um pode interromper**: cada elo faz sua parte e repassa, mas pode cortar o fluxo (middlewares HTTP, filtros de validação).

from abc import ABC, abstractmethod
from dataclasses import dataclass
from typing import Optional


@dataclass
class Despesa:
    descricao: str
    valor: float


class Aprovador(ABC):
    def __init__(self, nome: str):
        self.nome = nome
        self._proximo: Optional["Aprovador"] = None

    def definir_proximo(self, proximo: "Aprovador") -> "Aprovador":
        self._proximo = proximo
        return proximo  # permite encadear: a.definir_proximo(b).definir_proximo(c)

    def aprovar(self, despesa: Despesa) -> str:
        if self.pode_aprovar(despesa):
            return f"{despesa.descricao} (R$ {despesa.valor:,.2f}) aprovada por {self.nome}"
        if self._proximo is None:
            return f"{despesa.descricao}: ninguém na cadeia pode aprovar"
        return self._proximo.aprovar(despesa)

    @abstractmethod
    def pode_aprovar(self, despesa: Despesa) -> bool: ...


class PorLimite(Aprovador):
    def __init__(self, nome: str, limite: float):
        super().__init__(nome)
        self.limite = limite

    def pode_aprovar(self, despesa: Despesa) -> bool:
        return despesa.valor <= self.limite


class CFO(Aprovador):
    def pode_aprovar(self, despesa: Despesa) -> bool:
        return "pessoal" not in despesa.descricao.lower()

// 7800 -> "7,800.00"
string moeda(double v) {
    char buf[64];
    snprintf(buf, sizeof buf, "%.2f", v);
    string s = buf;
    size_t ponto = s.find('.');
    for (int i = (int)ponto - 3; i > 0; i -= 3) s.insert(i, ",");

    string descricao;
    double valor;

class Aprovador {
    shared_ptr<Aprovador> proximo;

protected:
    string nome;

public:
    Aprovador(string nome) : nome(nome) {}
    virtual ~Aprovador() = default;

    shared_ptr<Aprovador> definirProximo(shared_ptr<Aprovador> p) {
        proximo = p;
        return p; // permite encadear: a->definirProximo(b)->definirProximo(c)

        if (podeAprovar(despesa)) {

        }
        if (!proximo) {

    double limite;

func moeda(v float64) string {
	s := fmt.Sprintf("%.2f", v)
	ponto := strings.Index(s, ".")
	for i := ponto - 3; i > 0; i -= 3 {
		s = s[:i] + "," + s[i:]
	}
	return s
}

type Despesa struct {
	descricao string
	valor     float64
}

type Aprovador interface {
	definirProximo(p Aprovador) Aprovador
	aprovar(d Despesa) string
}

// base guarda o nome e o elo seguinte; quem a embute informa a regra por meio de pode.
type base struct {
	nome    string
	proximo Aprovador
	pode    func(Despesa) bool
}

func (b *base) definirProximo(p Aprovador) Aprovador {
	b.proximo = p
	return p // permite encadear: a.definirProximo(b).definirProximo(c)
}

func (b *base) aprovar(d Despesa) string {
	if b.pode(d) {
		return fmt.Sprintf("%s (R$ %s) aprovada por %s", d.descricao, moeda(d.valor), b.nome)
	}
	if b.proximo == nil {
		return d.descricao + ": ninguém na cadeia pode aprovar"
	}
	return b.proximo.aprovar(d)
}

func PorLimite(nome string, limite float64) *base {
	return &base{nome: nome, pode: func(d Despesa) bool { return d.valor <= limite }}
}

func CFO(nome string) *base {
	return &base{nome: nome, pode: func(d Despesa) bool {
		return !strings.Contains(strings.ToLower(d.descricao), "pessoal")
	}}
}

## Implementação 2: pipeline de middlewares

Aqui cada elo é uma função que recebe a requisição e o "próximo". Esse formato é o que frameworks web usam por baixo dos panos.

<CodeTabs>

```python
import time
from typing import Callable, Dict, List

Requisicao = Dict[str, object]
Resposta = Dict[str, object]
Proximo = Callable[[Requisicao], Resposta]
Middleware = Callable[[Requisicao, Proximo], Resposta]

TOKENS_VALIDOS = {"abc123": "ana"}
contagem: Dict[str, int] = {}


def autenticacao(req: Requisicao, proximo: Proximo) -> Resposta:
    usuario = TOKENS_VALIDOS.get(str(req.get("token")))
    if usuario is None:
        return {"status": 401, "corpo": "não autenticado"}
    req["usuario"] = usuario
    return proximo(req)


def limite_de_taxa(req: Requisicao, proximo: Proximo) -> Resposta:
    usuario = str(req["usuario"])
    contagem[usuario] = contagem.get(usuario, 0) + 1
    if contagem[usuario] > 2:
        return {"status": 429, "corpo": "muitas requisições"}
    return proximo(req)


def cronometro(req: Requisicao, proximo: Proximo) -> Resposta:
    inicio = time.perf_counter()
    resposta = proximo(req)  # age antes E depois do restante da cadeia
    resposta["ms"] = round((time.perf_counter() - inicio) * 1000, 3)
    return resposta


def controlador(req: Requisicao) -> Resposta:
    return {"status": 200, "corpo": f"olá, {req['usuario']}"}


def montar(middlewares: List[Middleware], final: Proximo) -> Proximo:
    cadeia = final
    for mw in reversed(middlewares):
        cadeia = (lambda m, p: (lambda req: m(req, p)))(mw, cadeia)
    return cadeia


app = montar([cronometro, autenticacao, limite_de_taxa], controlador)

print(app({"token": "errado"})["status"])
for _ in range(3):
    r = app({"token": "abc123"})
    print(r["status"], r["corpo"])
```

const TOKENS_VALIDOS = { abc123: "ana" };
const contagem = {};

function autenticacao(req, proximo) {
  const usuario = TOKENS_VALIDOS[req.token];
  if (usuario === undefined) {
    return { status: 401, corpo: "não autenticado" };
  }
  req.usuario = usuario;
  return proximo(req);
}

function limiteDeTaxa(req, proximo) {
  const usuario = req.usuario;
  contagem[usuario] = (contagem[usuario] ?? 0) + 1;
  if (contagem[usuario] > 2) {
    return { status: 429, corpo: "muitas requisições" };
  }
  return proximo(req);
}

// o toFixed arredonda o valor exato do double, mas leva o empate para cima (0.125 -> "0.13");
// o Python leva o empate exato para o par ("0.12"). Com 30 casas a mais, os dígitos exatos mostram o empate.
function fixoPar(x, casas) {
  const exato = Math.abs(x).toFixed(casas + 30);
  const corte = exato.length - 30;
  if (exato.slice(corte) !== "5" + "0".repeat(29)) return x.toFixed(casas);
  const baixo = exato.slice(0, casas > 0 ? corte : corte - 1); // sem o 5 (e sem o ponto, se casas = 0)
  const par = Number(baixo[baixo.length - 1]) % 2 === 0 ? baixo : Math.abs(x).toFixed(casas);
  return (x < 0 ? "-" : "") + par;
}

// round() do Python: o mesmo arredondamento, de volta para número
function arred(x, casas) {
  return Number(fixoPar(x, casas));
}

function cronometro(req, proximo) {
  const inicio = performance.now();
  const resposta = proximo(req); // age antes E depois do restante da cadeia
  resposta.ms = arred(performance.now() - inicio, 3);
  return resposta;
}

function controlador(req) {
  return { status: 200, corpo: `olá, ${req.usuario}` };
}

function montar(middlewares, final) {
  let cadeia = final;
  for (const mw of [...middlewares].reverse()) {
    const proximo = cadeia;
    cadeia = (req) => mw(req, proximo);
  }
  return cadeia;
}

function montar(middlewares: Middleware[], final: Proximo): Proximo {

// o Python arredonda o valor binário exato do double, com empate para o par. Aqui o valor exato
// (mantissa * 2^expoente) é montado em decimal, com 28 dígitos, e arredondado para o par.
static string FixoPar(double x, int casas)
{
    long bits = BitConverter.DoubleToInt64Bits(Math.Abs(x));
    int campo = (int)(bits >> 52);
    decimal d = bits & 0xFFFFFFFFFFFFFL;
    if (campo > 0) d += 1L << 52;
    for (int e = Math.Max(campo, 1) - 1075; e > 0; e--) d *= 2;
    for (int e = Math.Max(campo, 1) - 1075; e < 0; e++) d /= 2;
    if (x < 0) d = -d;
    return Math.Round(d, casas, MidpointRounding.ToEven).ToString("F" + casas, CultureInfo.InvariantCulture);
}

O `cronometro` mostra uma vantagem desse formato: o handler pode agir antes e depois do restante da cadeia.

## Quando usar e quando evitar

**Use quando:**

- Mais de um objeto pode tratar um pedido e o tratador certo só é conhecido em tempo de execução.
- Você quer montar ou reordenar etapas de processamento por configuração (middlewares, filtros, validações).
- O remetente não deve conhecer os detalhes de quem trata.

**Evite quando:**

- Existe sempre exatamente um tratador conhecido; chame-o direto.
- A cadeia fica longa e é difícil saber por que um pedido foi barrado. Adicione logs por elo.

<Callout type="warning" title="Pedido que cai no vazio">
Se nenhum elo trata o pedido, ele pode simplesmente sumir. Sempre defina o que acontece no fim da cadeia: um handler padrão, uma exceção ou uma resposta explícita, como o 'ninguém na cadeia pode aprovar' do exemplo.
</Callout>

## Padrões parecidos

| Padrão | Diferença |
| --- | --- |
| Decorator | Estrutura idêntica (objetos que embrulham o próximo). O Decorator sempre repassa e só adiciona comportamento; o Chain pode **interromper** o fluxo ou tratar e parar. |
| Observer | Todos os observadores recebem o evento. No Chain, o pedido percorre a cadeia em ordem e normalmente um elo resolve. |
| Command | O pedido que percorre a cadeia muitas vezes é um objeto Command. |
| Composite | Em árvores (componentes de interface), o pedido pode subir de filho para pai, formando uma cadeia natural. |

## Na entrevista

- Aparece em aprovação de despesas, sistemas de suporte em níveis (bot, atendente, especialista), caixa eletrônico (dispensar notas de 100, depois 50, depois 20) e validação de requisições num rate limiter ou gateway.
- O exemplo do caixa eletrônico é clássico: cada handler entrega o máximo de notas do seu valor e repassa o restante.
- Follow-ups: "como mudar a ordem sem recompilar?" (montar a cadeia a partir de configuração), "e se nenhum tratar?", "como testar?" (cada elo isolado, com um próximo falso).
