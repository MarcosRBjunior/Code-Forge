Um **enum** (enumeração) é um tipo com um conjunto fechado e nomeado de valores possíveis. Status de pedido, direção de um elevador, naipe de uma carta, tamanho de vaga: sempre que o domínio tem uma lista finita de opções, um enum é a ferramenta certa. Em LLD eles aparecem em praticamente todo problema.

Problemas: erros de digitação não são detectados, ninguém sabe quais valores são válidos sem ler o código todo, e a IDE não ajuda a autocompletar. Com números (`status = 2`) fica ainda pior, porque o significado some.

## Como funciona em Python

O módulo `enum` da biblioteca padrão resolve isso:

<CodeTabs>

```python
from enum import Enum, auto


class StatusPedido(Enum):
    CRIADO = auto()
    PAGO = auto()
    ENVIADO = auto()
    ENTREGUE = auto()
    CANCELADO = auto()


print(StatusPedido.PAGO)              # StatusPedido.PAGO
print(StatusPedido.PAGO.name)         # PAGO
print(StatusPedido["ENVIADO"])        # busca por nome
print(len(StatusPedido))              # 5
print(StatusPedido.PAGO is StatusPedido.PAGO)  # True: membros são únicos
```

Cada membro é um objeto único (singleton), então você compara com `is` ou `==`. Tentar acessar `StatusPedido.ENVIADOO` gera `AttributeError` na hora, e não um bug silencioso semanas depois.

## Enums com comportamento

Enums em Python são classes: podem ter métodos e valores mais ricos. Isso permite colocar regras **junto** do estado. Veja uma máquina de estados simples para pedidos:

<CodeTabs>

```python
from enum import Enum


class StatusPedido(Enum):
    CRIADO = "criado"
    PAGO = "pago"
    ENVIADO = "enviado"
    ENTREGUE = "entregue"
    CANCELADO = "cancelado"

    def pode_ir_para(self, destino: "StatusPedido") -> bool:
        return destino in TRANSICOES[self]

    @property
    def final(self) -> bool:
        return not TRANSICOES[self]


TRANSICOES = {
    StatusPedido.CRIADO: {StatusPedido.PAGO, StatusPedido.CANCELADO},
    StatusPedido.PAGO: {StatusPedido.ENVIADO, StatusPedido.CANCELADO},
    StatusPedido.ENVIADO: {StatusPedido.ENTREGUE},
    StatusPedido.ENTREGUE: set(),
    StatusPedido.CANCELADO: set(),
}


class Pedido:
    def __init__(self, codigo: str) -> None:
        self.codigo = codigo
        self.status = StatusPedido.CRIADO

    def avancar(self, destino: StatusPedido) -> None:
        if not self.status.pode_ir_para(destino):
            raise ValueError(f"{self.status.value} -> {destino.value} não permitido")
        self.status = destino


pedido = Pedido("A-17")
pedido.avancar(StatusPedido.PAGO)
pedido.avancar(StatusPedido.ENVIADO)
try:
    pedido.avancar(StatusPedido.CANCELADO)
except ValueError as e:
    print(e)  # enviado -> cancelado não permitido
print(StatusPedido.ENTREGUE.final)  # True
```

```java
import java.util.*;

enum StatusPedido {
    CRIADO("criado"), PAGO("pago"), ENVIADO("enviado"), ENTREGUE("entregue"), CANCELADO("cancelado");

    final String valor;

    StatusPedido(String valor) {
        this.valor = valor;
    }

    private static final Map<StatusPedido, Set<StatusPedido>> TRANSICOES = new EnumMap<>(StatusPedido.class);

    static {
        TRANSICOES.put(CRIADO, EnumSet.of(PAGO, CANCELADO));
        TRANSICOES.put(PAGO, EnumSet.of(ENVIADO, CANCELADO));
        TRANSICOES.put(ENVIADO, EnumSet.of(ENTREGUE));
        TRANSICOES.put(ENTREGUE, EnumSet.noneOf(StatusPedido.class));
        TRANSICOES.put(CANCELADO, EnumSet.noneOf(StatusPedido.class));
    }

    boolean podeIrPara(StatusPedido destino) {
        return TRANSICOES.get(this).contains(destino);
    }

    boolean isFinal() {
        return TRANSICOES.get(this).isEmpty();
    }
}

class Pedido {
    final String codigo;
    StatusPedido status = StatusPedido.CRIADO;

    Pedido(String codigo) {
        this.codigo = codigo;
    }

    void avancar(StatusPedido destino) {
        if (!status.podeIrPara(destino)) {
            throw new IllegalStateException(status.valor + " -> " + destino.valor + " não permitido");
        }
        status = destino;
    }
}

public static void main(String[] args) {
    Pedido pedido = new Pedido("A-17");
    pedido.avancar(StatusPedido.PAGO);
    pedido.avancar(StatusPedido.ENVIADO);
    try {
        pedido.avancar(StatusPedido.CANCELADO);
    } catch (IllegalStateException e) {
        System.out.println(e.getMessage()); // enviado -> cancelado não permitido
    }
    System.out.println(StatusPedido.ENTREGUE.isFinal()); // true
}
```

```csharp
using System;
using System.Collections.Generic;

enum StatusPedido { Criado, Pago, Enviado, Entregue, Cancelado }

static class StatusInfo
{
    static readonly Dictionary<StatusPedido, HashSet<StatusPedido>> TRANSICOES = new Dictionary<StatusPedido, HashSet<StatusPedido>>
    {
        { StatusPedido.Criado, new HashSet<StatusPedido> { StatusPedido.Pago, StatusPedido.Cancelado } },
        { StatusPedido.Pago, new HashSet<StatusPedido> { StatusPedido.Enviado, StatusPedido.Cancelado } },
        { StatusPedido.Enviado, new HashSet<StatusPedido> { StatusPedido.Entregue } },
        { StatusPedido.Entregue, new HashSet<StatusPedido>() },
        { StatusPedido.Cancelado, new HashSet<StatusPedido>() },
    };

    public static string Valor(StatusPedido s)
    {
        return s.ToString().ToLower();
    }

    public static bool PodeIrPara(StatusPedido origem, StatusPedido destino)
    {
        return TRANSICOES[origem].Contains(destino);
    }

    public static bool Final(StatusPedido s)
    {
        return TRANSICOES[s].Count == 0;
    }
}

class Pedido
{
    public readonly string Codigo;
    public StatusPedido Status = StatusPedido.Criado;

    public Pedido(string codigo)
    {
        Codigo = codigo;
    }

    public void Avancar(StatusPedido destino)
    {
        if (!StatusInfo.PodeIrPara(Status, destino))
        {
            throw new InvalidOperationException(StatusInfo.Valor(Status) + " -> " + StatusInfo.Valor(destino) + " não permitido");
        }
        Status = destino;
    }
}

static void Main()
{

    pedido.Avancar(StatusPedido.Pago);
    pedido.Avancar(StatusPedido.Enviado);

    {
```

```go
import (
	"fmt"
)

type StatusPedido string

const (
	CRIADO    StatusPedido = "criado"
	PAGO      StatusPedido = "pago"
	ENVIADO   StatusPedido = "enviado"
	ENTREGUE  StatusPedido = "entregue"
	CANCELADO StatusPedido = "cancelado"
)

var transicoes = map[StatusPedido][]StatusPedido{
	CRIADO:    {PAGO, CANCELADO},
	PAGO:      {ENVIADO, CANCELADO},
	ENVIADO:   {ENTREGUE},
	ENTREGUE:  {},
	CANCELADO: {},
}

func (s StatusPedido) podeIrPara(destino StatusPedido) bool {
	for _, d := range transicoes[s] {
		if d == destino {
			return true
		}
	}
	return false
}

func (s StatusPedido) final() bool { return len(transicoes[s]) == 0 }

type Pedido struct {
	codigo string
	status StatusPedido
}

func (p *Pedido) avancar(destino StatusPedido) error {
	if !p.status.podeIrPara(destino) {
		return fmt.Errorf("%s -> %s não permitido", p.status, destino)
	}
	p.status = destino
	return nil
}

func main() {
	pedido := &Pedido{"A-17", CRIADO}
	pedido.avancar(PAGO)
	pedido.avancar(ENVIADO)
	if err := pedido.avancar(CANCELADO); err != nil {
		fmt.Println(err) // enviado -> cancelado não permitido
	}
	fmt.Println(ENTREGUE.final()) // true
}
```

## Variações úteis

| Tipo | Quando usar |
| --- | --- |
| `Enum` | caso geral |
| `IntEnum` | quando o valor precisa se comportar como inteiro (ordenar prioridades, por exemplo) |
| `StrEnum` (Python 3.11+) | quando o valor vai para JSON ou APIs como texto |
| `Flag` | combinações de opções, como permissões de leitura e escrita |

## Armadilhas

- **Enum que cresce sem parar com comportamento diferente por membro.** Se cada valor precisa de lógica muito distinta, talvez classes polimórficas (padrão State ou Strategy) sejam melhores que um `if membro == ...` gigante.
- **Persistir o `auto()`.** Valores gerados por `auto()` dependem da ordem de declaração. Se você salva no banco e depois reordena, os dados antigos mudam de significado. Para valores persistidos, use valores explícitos.
- **Comparar com string.** `StatusPedido.PAGO == "pago"` é falso num `Enum` comum. Converta com `StatusPedido("pago")`.

<Callout type="note" title="Enum ou classe?">
Use enum quando o conjunto de valores é fechado e conhecido no momento de escrever o código. Se usuários ou administradores podem criar novos tipos em tempo de execução (categorias de produto, por exemplo), isso é dado, não enum.
</Callout>

## Na entrevista

Em problemas como estacionamento, elevador ou xadrez, declare cedo os enums do domínio: `TipoVaga`, `Direcao`, `CorPeca`. Isso mostra que você reconhece valores fechados e torna o resto do código legível. Follow-up comum: "e se surgir um novo tipo?" Responda distinguindo o que é enum (fechado) do que deveria ser configurável.
