<Quiz question="Sua classe Conta permite criar instâncias com saldo negativo pelo construtor. Qual o problema de design?" options={["Nenhum problema, pois a validação do saldo pode ficar nos chamadores que criam a conta","O objeto pode nascer em estado inválido, e o resto do código precisa desconfiar dele","O construtor não deveria receber parâmetros, pois o estado da conta deve ser definido depois","A classe Conta deveria ser uma subclasse de Saldo, para herdar a validação do valor"]} answer={1} explanation="O construtor deve garantir as invariantes desde o início. Validar em cada chamador espalha a regra e abre espaço para bugs." />
<Quiz question="Um elevador pode estar SUBINDO, DESCENDO ou PARADO. Como modelar?" options={["Strings soltas como 'subindo', 'descendo' e 'parado', comparadas diretamente no código","Um enum Direcao com três membros, com nomes legíveis para cada estado do elevador","Uma classe para cada estado, mesmo sem comportamento diferente entre eles","Um inteiro de 0 a 2 guardado num atributo, com um comentário explicando cada valor"]} answer={1} explanation="É um conjunto fechado e conhecido de valores: caso típico de enum, com nomes legíveis e erros detectados cedo." />
<Quiz question="Você quer testar um serviço de cadastro sem enviar e-mails reais. Qual recurso de design ajuda mais?" options={["Herança múltipla, fazendo o serviço herdar do enviador de e-mail para poder substituí-lo no teste","Depender de uma interface Notificador e injetar no teste um dublê que só registra as chamadas","Tornar estáticos os métodos de envio, para que o teste os chame sem criar o objeto de e-mail","Usar variáveis globais para o cliente de e-mail, trocando o valor global antes de cada teste"]} answer={1} explanation="Dependendo de um contrato, o serviço aceita qualquer implementação, inclusive um falso que só registra chamadas." />

<Quiz question="Qual cenário indica uso inadequado de herança?" options={["Gerente herda de Funcionario e pode ser usado em qualquer lugar onde um Funcionario é esperado","Pilha herda de Lista só para reaproveitar o armazenamento, expondo operações que violam a pilha","Circulo herda de uma classe abstrata Forma e implementa o cálculo da própria área e do perímetro","Moto implementa a interface Veiculo e fornece o comportamento de cada método que a interface exige"]} answer={1} explanation="Pilha não é uma lista; herdar expõe operações que violam o conceito. <Quiz question="A mesma cascata if tipo == 'moto' / 'carro' / 'caminhao' aparece em quatro funções. O que fazer?" options={["Manter a cascata como está, pois repetir condicionais simples é a solução mais direta","Transformar cada tipo numa classe com métodos comuns e usar polimorfismo no lugar dos if","Trocar a cascata por um dicionário global de strings que mapeia cada tipo para um texto","Juntar as quatro funções numa só, com um parâmetro extra que indica qual operação executar"]} answer={1} explanation="Condicionais por tipo repetidas indicam que o comportamento deveria morar nos próprios tipos." />
<Quiz question="Qual a diferença entre abstração e encapsulamento?" options={["Abstração escolhe o que expor ao usuário; encapsulamento protege como o estado interno muda","Os dois são o mesmo conceito, descrito com nomes diferentes em linguagens diferentes","Encapsulamento define a interface pública; abstração esconde os atributos com prefixo de sublinhado","Abstração só existe em linguagens compiladas, enquanto encapsulamento existe em qualquer linguagem"]} answer={0} explanation="Abstração define a visão simplificada certa. Encapsulamento garante que essa visão seja o único caminho para alterar o estado." />
