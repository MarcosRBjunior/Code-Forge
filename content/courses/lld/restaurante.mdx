Um sistema de restaurante gira em torno do ciclo de vida de um pedido: o garçom registra itens, a cozinha prepara, o pedido é servido e a conta é fechada. O núcleo do problema é uma máquina de estados bem definida e a divisão de conta.

## Requisitos

- Cardápio com itens e preços.
- Mesas com pedidos abertos; itens podem ser adicionados enquanto o pedido está aberto.
- A cozinha avança o estado de cada item: pedido, preparando, pronto, servido.
- Fechar a conta com taxa de serviço e divisão entre pessoas.

## Entidades

| Entidade | Responsabilidade |
| --- | --- |
| `ItemCardapio` | Nome e preço. |
| `ItemPedido` | Item do cardápio com quantidade e estado. |
| `Pedido` | Itens de uma mesa; calcula o total. |
| `Mesa` | Número e pedido atual. |
| `Restaurante` | Cardápio, mesas e fila da cozinha. |

Estados válidos formam uma sequência. Centralizar a transição num método impede saltos como servir algo que nem foi preparado.

## Implementação

```python
from dataclasses import dataclass, field
from enum import Enum
from collections import deque
from typing import List, Optional


class Estado(Enum):
    PEDIDO = 1
    PREPARANDO = 2
    PRONTO = 3
    SERVIDO = 4


@dataclass(frozen=True)
class ItemCardapio:
    nome: str
    preco: float


@dataclass
class ItemPedido:
    prato: ItemCardapio
    qtd: int = 1
    estado: Estado = Estado.PEDIDO

    def avancar(self):
        if self.estado is Estado.SERVIDO:
            raise ValueError("item já servido")
        self.estado = Estado(self.estado.value + 1)

    @property
    def subtotal(self):
        return self.prato.preco * self.qtd


class Pedido:
    def __init__(self):
        self.itens: List[ItemPedido] = []
        self.fechado = False

    def adicionar(self, prato: ItemCardapio, qtd: int = 1) -> ItemPedido:
        if self.fechado:
            raise ValueError("pedido fechado")
        item = ItemPedido(prato, qtd)
        self.itens.append(item)
        return item

    def total(self, taxa_servico: float = 0.10) -> float:
        base = sum(i.subtotal for i in self.itens)
        return round(base * (1 + taxa_servico), 2)

    def dividir(self, pessoas: int) -> List[float]:
        total_centavos = round(self.total() * 100)
        base, resto = divmod(total_centavos, pessoas)
        return [(base + (1 if i < resto else 0)) / 100 for i in range(pessoas)]


class Cozinha:
    def __init__(self):
        self.fila = deque()

    def enviar(self, item: ItemPedido):
        item.avancar()  # PREPARANDO
        self.fila.append(item)

    def concluir_proximo(self) -> Optional[ItemPedido]:
        if not self.fila:
            return None
        item = self.fila.popleft()
        item.avancar()  # PRONTO
        return item


pizza, suco = ItemCardapio("Pizza", 40.0), ItemCardapio("Suco", 9.0)
pedido, cozinha = Pedido(), Cozinha()
for it in (pedido.adicionar(pizza, 2), pedido.adicionar(suco, 3)):
    cozinha.enviar(it)
pronto = cozinha.concluir_proximo()
pronto.avancar()  # SERVIDO
print(pronto.estado.name, pedido.total())
print(pedido.dividir(3))
```

A divisão trabalha em centavos inteiros e distribui o resto, assim a soma das partes sempre bate com o total.

## Extensões

Várias estações na cozinha (bar, grill) com uma fila por estação, cancelamento de item (permitido só antes de PREPARANDO), descontos (Decorator ou Strategy sobre o total) e Observer para avisar o garçom quando o item fica pronto.

## Concorrência

Vários garçons adicionam itens ao mesmo pedido. Proteja a lista de itens com lock por pedido, e a fila da cozinha com uma estrutura thread-safe como `queue.Queue`.

## Na entrevista

- **"Como validar transições?"** Método no próprio item, ou um mapa de transições permitidas se houver desvios (cancelado).
- **"Por que não usar float para dinheiro?"** Erros de arredondamento; use centavos inteiros ou `Decimal`.
