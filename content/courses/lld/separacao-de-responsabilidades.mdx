**Separação de responsabilidades** (*Separation of Concerns*, SoC) é a ideia de dividir um sistema em partes que tratam de assuntos diferentes, cada uma com o mínimo de conhecimento sobre as outras. Um "assunto" pode ser apresentação, regra de negócio, persistência, logging, autenticação. O SRP aplica essa ideia no nível de uma classe; a SoC vale para qualquer escala: funções, classes, módulos, camadas e serviços.

## O problema

Quando assuntos se misturam, você não consegue mudar um sem tocar nos outros. Um script que lê um CSV, calcula médias e imprime uma tabela formatada no mesmo laço é rápido de escrever, mas:

- trocar CSV por API exige mexer no cálculo;
- testar a média exige um arquivo real;
- mudar o layout da tabela pode quebrar a leitura.

## Separando os assuntos

<CodeTabs>

```python
import csv
import io
from dataclasses import dataclass

DADOS = "aluno,nota\nBia,8.5\nCaio,6.0\nDani,9.0\n"


@dataclass(frozen=True)
class Resultado:
    aluno: str
    nota: float


# 1) Entrada: só sabe ler CSV
class LeitorCsv:
    def ler(self, texto: str) -> list[Resultado]:
        return [Resultado(l["aluno"], float(l["nota"])) for l in csv.DictReader(io.StringIO(texto))]


# 2) Domínio: só sabe as regras
class Turma:
    NOTA_MINIMA = 7.0

    def __init__(self, resultados: list[Resultado]) -> None:
        self.resultados = resultados

    def media(self) -> float:
        return sum(r.nota for r in self.resultados) / len(self.resultados)

    def aprovado(self, r: Resultado) -> bool:
        return r.nota >= self.NOTA_MINIMA


# 3) Saída: só sabe formatar
class TabelaTexto:
    def render(self, turma: Turma) -> str:
        linhas = ["ALUNO   | NOTA"]
        for r in turma.resultados:
            marca = " *" if turma.aprovado(r) else ""
            linhas.append(f"{r.aluno:<7} | {r.nota:.1f}{marca}")
        linhas.append(f"Média: {turma.media():.2f}")
        return "\n".join(linhas)


turma = Turma(LeitorCsv().ler(DADOS))
assert round(turma.media(), 2) == 7.83
assert not turma.aprovado(Resultado("x", 6.9))
print(TabelaTexto().render(turma))
```

```cpp
const string DADOS = "aluno,nota\nBia,8.5\nCaio,6.0\nDani,9.0\n";

    double nota;

        double soma = 0;
        for (auto& r : resultados) soma += r.nota;
        return soma / resultados.size();

};
```

## SoC em várias escalas

```text
+----------------+     +-------------------+     +------------------+
|  Apresentação  | --> |  Domínio/Serviço  | --> |  Persistência    |
|  (CLI, HTTP)   |     |  (regras)         |     |  (banco, arquivo)|
+----------------+     +-------------------+     +------------------+
       formata             decide                    guarda
```

- **Função**: uma função que calcula não deveria imprimir.
- **Classe**: o SRP.
- **Camadas**: MVC, arquitetura hexagonal, camadas de serviço e repositório.
- **Assuntos transversais**: logging, métricas e autorização tendem a se espalhar; decorators e middlewares ajudam a isolá-los.

## Armadilhas

<Callout type="warning" title="Camadas sem conteúdo">
Separar não é criar cinco camadas obrigatórias para um CRUD de duas telas. Se uma camada só repassa chamadas, ela não está separando assunto nenhum.
</Callout>

Outra armadilha é separar pelo critério errado: dividir por tipo técnico (todos os "validadores" juntos, todos os "serviços" juntos) em vez de por assunto de negócio pode espalhar uma única funcionalidade por dez pastas.

## Na entrevista

Mostre SoC ao separar o modelo de domínio (por exemplo, `Partida`, `Tabuleiro`) da interação com o usuário (leitura do teclado, impressão do tabuleiro). Diga: "o domínio não sabe se está rodando num terminal ou numa API". Follow-ups comuns: "qual a diferença entre SoC e SRP?", "onde fica a validação de entrada?".
