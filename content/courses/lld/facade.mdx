## O problema

Pense no fluxo de "matricular um aluno num curso pago" numa plataforma de ensino. Para fazer isso direito você precisa: verificar se ainda há vagas na turma, reservar a vaga, cobrar o cartão, liberar o acesso no sistema de conteúdo, emitir nota fiscal e mandar o e-mail de boas-vindas. São cinco ou seis serviços diferentes, cada um com sua API e sua ordem certa de chamada.

Se o controller HTTP, o job de importação em lote e o painel administrativo fizerem essa coreografia cada um do seu jeito, você terá três cópias da mesma sequência, cada uma com um bug diferente. Pior: qualquer mudança no subsistema (trocar o emissor de nota, por exemplo) obriga a mexer em todos esses pontos.

O **Facade** resolve isso oferecendo **uma porta de entrada simples** para um subsistema complexo. O cliente chama `matricular(aluno, curso, cartao)` e a fachada cuida de orquestrar as peças.

## Como funciona

A fachada conhece as classes do subsistema e sabe em que ordem usá-las. Ela não adiciona capacidades novas: apenas expõe um caminho de alto nível. As classes internas continuam existindo e podem ser usadas diretamente por quem precisar de controle fino.

```text
                 +------------------------------+
  Controller --> |   MatriculaFacade            |
  Job lote   --> |  + matricular(aluno, curso)  |
  Admin      --> +------------------------------+
                    |      |       |      |      |
                    v      v       v      v      v
            +--------+ +-------+ +------+ +-----+ +-------+
            | Turmas | | Cobr. | |Acesso| | NF  | | Email |
            +--------+ +-------+ +------+ +-----+ +-------+
                     subsistema (classes independentes)
```

Uma boa fachada também concentra o tratamento de falhas da sequência. Se a cobrança falhar depois da vaga reservada, é a fachada que libera a vaga de volta.

```javascript
class ServicoTurmas {
  constructor() {
    this.vagas = { "python-101": 2 };
    this.reservas = [];
  }

  reservar(curso, aluno) {
    if ((this.vagas[curso] || 0) === 0) {

    }
    this.vagas[curso] -= 1;
    this.reservas.push([curso, aluno]);
  }

  liberar(curso, aluno) {
    const i = this.reservas.findIndex(([c, a]) => c === curso && a === aluno);

    this.vagas[curso] += 1;
```

```java
import java.util.*;

class ServicoTurmas {
    final Map<String, Integer> vagas = new HashMap<>(Map.of("python-101", 2));
    private final List<String[]> reservas = new ArrayList<>();

    void reservar(String curso, String aluno) {
        if (vagas.getOrDefault(curso, 0) == 0) {
            throw new IllegalStateException("turma " + curso + " lotada");
        }
        vagas.put(curso, vagas.get(curso) - 1);
        reservas.add(new String[] {curso, aluno});
    }

    void liberar(String curso, String aluno) {
        reservas.removeIf(r -> r[0].equals(curso) && r[1].equals(aluno));
        vagas.put(curso, vagas.get(curso) + 1);
    }
}

    String cobrar(String cartao, double valor) {

        return "tx-" + Math.abs(Objects.hash(cartao, valor)) % 10000;
    }
}
```

```csharp
    public Dictionary<string, int> Vagas = new Dictionary<string, int> { { "python-101", 2 } };
```

```go
package main

import (
	"errors"
	"fmt"
	"strings"
)

type ServicoTurmas struct {
	vagas    map[string]int
	reservas [][2]string
}

func (s *ServicoTurmas) reservar(curso, aluno string) error {
	if s.vagas[curso] == 0 {
		return fmt.Errorf("turma %s lotada", curso)
	}
	s.vagas[curso]--
	s.reservas = append(s.reservas, [2]string{curso, aluno})
	return nil
}

func (s *ServicoTurmas) liberar(curso, aluno string) {
	for i, r := range s.reservas {
		if r[0] == curso && r[1] == aluno {
			s.reservas = append(s.reservas[:i], s.reservas[i+1:]...)
			break
		}
	}
	s.vagas[curso]++
}

type ServicoCobranca struct{}

func (ServicoCobranca) cobrar(cartao string, valor float64) (string, error) {
	if strings.HasSuffix(cartao, "0000") {
		return "", errors.New("cartão recusado")
	}
	// id derivado do cartão e do valor (cada linguagem calcula o seu)
	h := 0
	for _, ch := range fmt.Sprintf("%s%v", cartao, valor) {
		h = (h*31 + int(ch)) % 10000
	}
	return fmt.Sprintf("tx-%d", h), nil
}

type ServicoAcesso struct{ liberados map[string]bool }

func (s *ServicoAcesso) liberar(aluno, curso string) { s.liberados[aluno+"|"+curso] = true }

type EmissorNota struct{}

func (EmissorNota) emitir(aluno string, valor float64) string {
	return fmt.Sprintf("NF para %s: R$ %.2f", aluno, valor)
}

type Mailer struct{}

func (Mailer) enviar(para, assunto string) { fmt.Printf("[email] %s: %s\n", para, assunto) }

type MatriculaFacade struct {
	precos   map[string]float64
	turmas   *ServicoTurmas
	cobranca ServicoCobranca
	acesso   *ServicoAcesso
	notas    EmissorNota
	mailer   Mailer
}

func (m *MatriculaFacade) matricular(aluno, curso, cartao string) (map[string]string, error) {
	preco := m.precos[curso]
	if err := m.turmas.reservar(curso, aluno); err != nil {
		return nil, err
	}
	tx, err := m.cobranca.cobrar(cartao, preco)
	if err != nil {
		m.turmas.liberar(curso, aluno) // compensação
		return nil, err
	}
	m.acesso.liberar(aluno, curso)
	nota := m.notas.emitir(aluno, preco)
	m.mailer.enviar(aluno, "Bem-vindo ao "+curso+"!")
	return map[string]string{"transacao": tx, "nota": nota}, nil
}

func main() {
	turmas := &ServicoTurmas{vagas: map[string]int{"python-101": 2}}
	facade := &MatriculaFacade{
		precos:   map[string]float64{"python-101": 199.90},
		turmas:   turmas,
```

O cliente nunca precisa saber que existe compensação de vaga, nem que a nota é emitida depois do acesso. Se amanhã o e-mail virar mensagem numa fila, só a fachada e o `Mailer` mudam.

## Quando usar

- Um caso de uso que exige coordenar vários serviços numa ordem específica.
- Expor uma API simples de uma biblioteca grande (por exemplo, "converter vídeo" escondendo codecs, buffers e containers).
- Definir camadas: cada camada conversa com a seguinte apenas pela fachada dela.

## Quando evitar

- Quando a fachada vira um **objeto Deus**: dezenas de métodos sem relação, que importam metade do sistema. Prefira várias fachadas pequenas, uma por caso de uso.
- Quando ela só repassa chamadas uma a uma, sem simplificar nada. Aí é indireção sem ganho.
- Quando os clientes precisam de controle fino sobre cada passo. Nesse caso, deixe-os usar o subsistema direto.

<Callout type="tip" title="Facade não proíbe o acesso direto">
A fachada é um atalho, não uma muralha. Classes do subsistema continuam públicas; você apenas oferece o caminho fácil para o caso comum.
</Callout>

## Padrões parecidos

- **Adapter**: também embrulha código existente, mas para casar uma interface com outra que o cliente já espera. A fachada cria uma interface nova e mais simples sobre **vários** objetos.
- **Mediator**: coordena objetos que conversam entre si; os colegas conhecem o mediador e mandam eventos para ele. Na fachada, o subsistema não sabe que a fachada existe, e a comunicação é de mão única.
- **Service layer / application service**: na prática, um serviço de aplicação em arquitetura em camadas costuma ser exatamente uma fachada sobre o domínio.

## Na entrevista

Em problemas como "projete um sistema de reserva de hotel" ou "um caixa eletrônico", é natural ter uma classe como `SistemaReservas` ou `CaixaEletronico` que expõe as operações do enunciado e delega para classes especializadas. Diga explicitamente: "essa classe é uma fachada; ela orquestra, mas a lógica fica nas classes especializadas". Follow-ups comuns:

- **Como evitar que ela cresça demais?** Separar por caso de uso e mover regras para as classes de domínio.
- **E transações distribuídas?** A fachada é um bom lugar para compensações simples (saga local), como liberar a vaga quando a cobrança falha.
- **Como testar?** Injetar dublês dos serviços no construtor, como no exemplo.
