O **Open/Closed Principle (OCP)** diz que o código deve estar **aberto para extensão e fechado para modificação**. Em termos práticos: para adicionar um comportamento novo, você deveria escrever código novo, e não editar código que já funciona e está testado. Cada edição em código estável é uma chance de quebrar o que já existia.

## O problema

O sintoma clássico é uma função com uma cadeia de `if/elif` que cresce a cada requisito. Toda nova variação obriga a abrir o mesmo arquivo, mexer no meio da lógica e retestar todos os casos.

## Exemplo que viola o OCP

## Versão corrigida

Extraia o ponto de variação para uma abstração. Cada regra de desconto vira uma classe; a calculadora depende só do contrato:

<CodeTabs>

```python
from abc import ABC, abstractmethod


class PoliticaDeDesconto(ABC):
    @abstractmethod
    def desconto(self, valor: float) -> float: ...


class SemDesconto(PoliticaDeDesconto):
    def desconto(self, valor: float) -> float:
        return 0.0


class Percentual(PoliticaDeDesconto):
    def __init__(self, pct: float) -> None:
        self.pct = pct

    def desconto(self, valor: float) -> float:
        return valor * self.pct


class PercentualComTeto(PoliticaDeDesconto):
    def __init__(self, pct: float, teto: float) -> None:
        self.pct, self.teto = pct, teto

    def desconto(self, valor: float) -> float:
        return min(valor * self.pct, self.teto)


class Caixa:
    def __init__(self, politicas: dict[str, PoliticaDeDesconto]) -> None:
        self._politicas = politicas

    def total(self, tipo_cliente: str, valor: float) -> float:
        politica = self._politicas.get(tipo_cliente, SemDesconto())
        return round(valor - politica.desconto(valor), 2)


caixa = Caixa({
    "fidelidade": Percentual(0.05),
    "vip": Percentual(0.10),
    "funcionario": PercentualComTeto(0.15, teto=50),  # extensão: nenhuma classe antiga mudou
})
print(caixa.total("vip", 300))          # 270.0
print(caixa.total("funcionario", 500))  # 450.0
print(caixa.total("comum", 100))        # 100.0
```

#include <cstdio>
#include <cstdlib>
#include <iostream>
#include <map>
#include <memory>
#include <string>
using namespace std;

class PoliticaDeDesconto {
public:
    virtual ~PoliticaDeDesconto() = default;
    virtual double desconto(double valor) const = 0;
};

class SemDesconto : public PoliticaDeDesconto {
public:
    double desconto(double valor) const override { return 0.0; }
};

class Percentual : public PoliticaDeDesconto {
    double pct;

public:
    Percentual(double pct) : pct(pct) {}
    double desconto(double valor) const override { return valor * pct; }
};

class PercentualComTeto : public PoliticaDeDesconto {
    double pct, teto;

public:
    PercentualComTeto(double pct, double teto) : pct(pct), teto(teto) {}
    double desconto(double valor) const override { return min(valor * pct, teto); }
};

// round() do Python: o printf arredonda o valor exato do double, com empate para o par
double arred(double x, int casas) {
    char texto[64];
    snprintf(texto, sizeof texto, "%.*f", casas, x);
    return strtod(texto, nullptr);
}

class Caixa {
    map<string, shared_ptr<PoliticaDeDesconto>> politicas;

public:
    Caixa(map<string, shared_ptr<PoliticaDeDesconto>> politicas) : politicas(politicas) {}

    double total(const string& tipoCliente, double valor) const {
        auto it = politicas.find(tipoCliente);
        shared_ptr<PoliticaDeDesconto> politica = it != politicas.end() ? it->second : make_shared<SemDesconto>();
        return arred(valor - politica->desconto(valor), 2);
    }
};

    public double Desconto(double valor)
    {

// o F2 do C# arredonda a forma decimal curta, e o Math.Round(x, 2) multiplica por 100 antes (2.675 vira 267.5);
// o Python arredonda o valor binário exato do double, com empate para o par. Aqui o valor exato
// (mantissa * 2^expoente) é montado em decimal, com 28 dígitos, e arredondado para o par.
static string FixoPar(double x, int casas)
{
    long bits = BitConverter.DoubleToInt64Bits(Math.Abs(x));
    int campo = (int)(bits >> 52);
    decimal d = bits & 0xFFFFFFFFFFFFFL;
    if (campo > 0) d += 1L << 52;
    for (int e = Math.Max(campo, 1) - 1075; e > 0; e--) d *= 2;
    for (int e = Math.Max(campo, 1) - 1075; e < 0; e++) d /= 2;
    if (x < 0) d = -d;
    return Math.Round(d, casas, MidpointRounding.ToEven).ToString("F" + casas, CultureInfo.InvariantCulture);
}

// round() do Python: o mesmo arredondamento, de volta para double
static double Arred(double x, int casas)
{
    return double.Parse(FixoPar(x, casas), CultureInfo.InvariantCulture);
}

class Caixa
{
    private readonly Dictionary<string, IPoliticaDeDesconto> politicas;

    public Caixa(Dictionary<string, IPoliticaDeDesconto> politicas)
    {
        this.politicas = politicas;
    }

    public double Total(string tipoCliente, double valor)
    {
        IPoliticaDeDesconto politica;
        if (!politicas.TryGetValue(tipoCliente, out politica)) politica = new SemDesconto();
        return Arred(valor - politica.Desconto(valor), 2);
    }
}

import (
	"fmt"
	"math"
	"strconv"

type PoliticaDeDesconto interface {
	desconto(valor float64) float64
}

type SemDesconto struct{}

func (SemDesconto) desconto(valor float64) float64 { return 0.0 }

type Percentual struct{ pct float64 }

func (p Percentual) desconto(valor float64) float64 { return valor * p.pct }

type PercentualComTeto struct{ pct, teto float64 }

func (p PercentualComTeto) desconto(valor float64) float64 {
	return math.Min(valor*p.pct, p.teto)
}

// round() do Python: o strconv arredonda o valor exato do double, com empate para o par
func arred(x float64, casas int) float64 {
	r, _ := strconv.ParseFloat(strconv.FormatFloat(x, 'f', casas, 64), 64)
	return r
}

type Caixa struct {
	politicas map[string]PoliticaDeDesconto
}

func (c Caixa) total(tipoCliente string, valor float64) float64 {
	politica, ok := c.politicas[tipoCliente]
	if !ok {
		politica = SemDesconto{}
	}
	return arred(valor-politica.desconto(valor), 2)
}

	fmt.Println(caixa.total("funcionario", 500))  // 450.0

## Mecanismos para chegar ao OCP

| Mecanismo | Ideia |
| --- | --- |
| Polimorfismo com interfaces | cada variação é uma classe que realiza o contrato |
| Strategy | o comportamento é injetado como objeto |
| Template Method | a base fixa o algoritmo e subclasses preenchem passos |
| Registro/plugin | novas implementações se registram num dicionário |
| Decorator | adiciona comportamento envolvendo o objeto original |

## Trade-offs

Nenhum código é fechado para **todas** as mudanças. O OCP funciona quando você identifica os eixos de variação **prováveis** (tipos de desconto, meios de pagamento) e abre só esses. Criar abstrações para variações que nunca acontecem é especulação, e o próprio princípio YAGNI vai contra isso.

<Callout type="tip" title="Regra das três vezes">
Na primeira variação, um `if` resolve. Quando a mesma condicional ganha o terceiro ramo, ou aparece em vários lugares, é hora de extrair a abstração.
</Callout>

## Na entrevista

O OCP é a resposta para "e se aparecer um novo tipo?". Mostre que a nova variação é uma nova classe e que o núcleo não muda. Follow-ups comuns: "o dicionário de políticas não é uma modificação?" (é configuração, isolada num ponto de montagem), "como decidir o que deixar aberto?", "qual padrão você usaria aqui?".
