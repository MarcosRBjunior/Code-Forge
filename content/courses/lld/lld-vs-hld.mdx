High Level Design (HLD) e Low Level Design (LLD) são duas lentes sobre o mesmo sistema, com zoom diferente. Confundir as duas é uma das formas mais rápidas de perder o rumo numa entrevista: você começa falando de classes quando o entrevistador queria sharding, ou desenha load balancers quando ele queria ver código.

## A analogia da cidade

Pense numa cidade. O HLD é o mapa: bairros, avenidas, onde fica a estação de tratamento de água, como o trânsito flui entre regiões. O LLD é a planta de um prédio: onde ficam as paredes, por onde passa o encanamento, qual porta abre para qual cômodo. Os dois são necessários, e um bom prédio num bairro mal planejado ainda sofre com trânsito.

## Comparação direta

| Aspecto | HLD | LLD |
| --- | --- | --- |
| Unidade principal | serviços, bancos, filas, caches | classes, interfaces, métodos |
| Pergunta central | como o sistema escala e se mantém disponível? | como o código se mantém fácil de mudar? |
| Artefatos | diagrama de arquitetura, estimativas de carga | diagrama de classes, diagrama de sequência, código |
| Preocupações | latência, throughput, consistência, falhas de rede | coesão, acoplamento, extensibilidade, testabilidade |
| Quem consome | arquitetos, SRE, times de plataforma | desenvolvedores que vão implementar e manter |
| Erro típico | desenhar caixas sem números | desenhar classes sem comportamento |

## O mesmo problema nas duas lentes

Considere um encurtador de URLs.

Na lente **HLD**, você discute: quantas URLs por segundo, que banco guarda o mapeamento, se um cache na frente reduz leituras, como gerar IDs únicos entre várias máquinas.

Na lente **LLD**, você discute as classes dentro do serviço:

```python
import string
from abc import ABC, abstractmethod

ALFABETO = string.digits + string.ascii_letters


class GeradorDeCodigo(ABC):
    @abstractmethod
    def proximo(self) -> str: ...


class GeradorSequencialBase62(GeradorDeCodigo):
    def __init__(self, inicio: int = 1) -> None:
        self._contador = inicio

    def proximo(self) -> str:
        n, codigo = self._contador, ""
        self._contador += 1
        while n:
            n, resto = divmod(n, 62)
            codigo = ALFABETO[resto] + codigo
        return codigo or "0"


class Encurtador:
    def __init__(self, gerador: GeradorDeCodigo) -> None:
        self._gerador = gerador
        self._urls: dict[str, str] = {}

    def encurtar(self, url: str) -> str:
        codigo = self._gerador.proximo()
        self._urls[codigo] = url
        return codigo

    def resolver(self, codigo: str) -> str:
        if codigo not in self._urls:
            raise KeyError(f"código inexistente: {codigo}")
        return self._urls[codigo]


encurtador = Encurtador(GeradorSequencialBase62(inicio=125))
c = encurtador.encurtar("https://exemplo.com/artigo")
print(c, encurtador.resolver(c))  # 21 https://exemplo.com/artigo
```

```java
import java.util.*;

interface GeradorDeCodigo {
    String proximo();
}

class GeradorSequencialBase62 implements GeradorDeCodigo {
    static final String ALFABETO = "0123456789abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ";
    private long contador;

    GeradorSequencialBase62(long inicio) { this.contador = inicio; }

    public String proximo() {
        long n = contador++;
        StringBuilder codigo = new StringBuilder();
        while (n != 0) {
            codigo.insert(0, ALFABETO.charAt((int) (n % 62)));
            n /= 62;
        }
        return codigo.length() == 0 ? "0" : codigo.toString();
    }
}

class Encurtador {
    private final GeradorDeCodigo gerador;
    private final Map<String, String> urls = new HashMap<>();

    Encurtador(GeradorDeCodigo gerador) { this.gerador = gerador; }

    String encurtar(String url) {
        String codigo = gerador.proximo();
        urls.put(codigo, url);
        return codigo;
    }

    String resolver(String codigo) {
        if (!urls.containsKey(codigo)) throw new NoSuchElementException("código inexistente: " + codigo);
        return urls.get(codigo);
    }
}

public static void main(String[] args) {
    Encurtador encurtador = new Encurtador(new GeradorSequencialBase62(125));
    String c = encurtador.encurtar("https://exemplo.com/artigo");
    System.out.println(c + " " + encurtador.resolver(c));  // 21 https://exemplo.com/artigo
}
```

```cpp
#include <iostream>
#include <map>
#include <stdexcept>
#include <string>
using namespace std;

const string ALFABETO = "0123456789abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ";

class GeradorDeCodigo {
public:
    virtual ~GeradorDeCodigo() = default;
    virtual string proximo() = 0;
};

class GeradorSequencialBase62 : public GeradorDeCodigo {
    unsigned long long contador;

public:
    GeradorSequencialBase62(unsigned long long inicio = 1) : contador(inicio) {}

    string proximo() override {
        unsigned long long n = contador++;
        string codigo;
        while (n) {
            codigo.insert(codigo.begin(), ALFABETO[n % 62]);
            n /= 62;
        }
        return codigo.empty() ? "0" : codigo;
    }
};

class Encurtador {
    GeradorDeCodigo& gerador;
    map<string, string> urls;

public:
    Encurtador(GeradorDeCodigo& gerador) : gerador(gerador) {}

    string encurtar(const string& url) {
        string codigo = gerador.proximo();
        urls[codigo] = url;
        return codigo;
    }

    string resolver(const string& codigo) const {
        auto it = urls.find(codigo);
        if (it == urls.end()) throw out_of_range("código inexistente: " + codigo);
        return it->second;
    }
};

int main() {
    GeradorSequencialBase62 gerador(125);
    Encurtador encurtador(gerador);
    string c = encurtador.encurtar("https://exemplo.com/artigo");
    cout << c << " " << encurtador.resolver(c) << endl;  // 21 https://exemplo.com/artigo
}
```

```csharp
using System.Text;

interface IGeradorDeCodigo

    string Proximo();

class GeradorSequencialBase62 : IGeradorDeCodigo
```

```go
import "fmt"

const alfabeto = "0123456789abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ"

type GeradorDeCodigo interface {
	proximo() string
}

type GeradorSequencialBase62 struct {
	contador uint64
}

func (g *GeradorSequencialBase62) proximo() string {
	n := g.contador
	g.contador++
	codigo := ""
	for n != 0 {
		codigo = string(alfabeto[n%62]) + codigo
		n /= 62
	}
	if codigo == "" {
		return "0"
	}
	return codigo
}

type Encurtador struct {
	gerador GeradorDeCodigo
	urls    map[string]string
}

func (e *Encurtador) encurtar(url string) string {
	codigo := e.gerador.proximo()
	e.urls[codigo] = url
	return codigo
}

func (e *Encurtador) resolver(codigo string) (string, error) {
	url, ok := e.urls[codigo]
	if !ok {
		return "", fmt.Errorf("código inexistente: %s", codigo)
	}
	return url, nil
}

func main() {
	encurtador := &Encurtador{&GeradorSequencialBase62{125}, map[string]string{}}
	c := encurtador.encurtar("https://exemplo.com/artigo")
	url, _ := encurtador.resolver(c)
	fmt.Println(c, url) // 21 https://exemplo.com/artigo
}
```

Aqui a decisão de LLD é isolar a geração de códigos atrás de `GeradorDeCodigo`. Isso permite trocar por um gerador aleatório ou baseado em hash sem mexer em `Encurtador`. Já a decisão de **onde** guardar os dados (dicionário em memória vs banco distribuído) é de HLD; no LLD você só garante que essa troca seja fácil.

## Como as duas se conectam

As lentes não são independentes. Uma decisão de HLD costuma virar uma restrição de LLD:

- "Vamos ter várias instâncias do serviço" → o LLD não pode guardar estado só em memória local; precisa de uma abstração de repositório.
- "Escritas vão para uma fila" → o LLD precisa de uma classe produtora e de consumidores idempotentes.

E o contrário também acontece: um LLD bem modularizado facilita extrair um pedaço para outro serviço depois.

<Callout type="warning" title="Não misture os níveis sem avisar">
Se numa entrevista de LLD você sentir necessidade de falar de infraestrutura, diga explicitamente: "isso é uma preocupação de HLD; vou assumir um repositório abstrato e seguir com as classes". Isso mostra maturidade e mantém o foco.
</Callout>

## Armadilhas

- **Responder LLD com caixas de infraestrutura.** O entrevistador pediu as classes de um estacionamento; ele não quer saber de Kubernetes.
- **Responder HLD com classes.** Num design de feed para 100 milhões de usuários, detalhar getters e setters desperdiça o tempo.
- **Achar que um nível é "mais importante".** Times maduros precisam dos dois.

## Na entrevista

Logo no início, confirme o escopo: "você quer que eu foque na arquitetura dos serviços ou no design das classes de um componente?". Muitos entrevistadores apreciam a pergunta. Follow-ups comuns depois de um LLD: "como esse design se comporta com várias instâncias?" e "onde você colocaria um cache?" são convites para conectar os dois níveis.
