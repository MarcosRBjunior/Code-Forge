Boa parte dos problemas de LLD parece sequencial até o entrevistador perguntar: "e se duas pessoas tentarem reservar o último assento ao mesmo tempo?". Essa pergunta testa se você entende **condições de corrida** e sabe proteger o estado compartilhado sem destruir o desempenho.

## O que dá errado

Uma condição de corrida acontece quando o resultado depende da ordem em que threads executam. O exemplo clássico é "verificar e depois agir":

<CodeTabs>

```python
class AssentoInseguro:
    def __init__(self) -> None:
        self.reservado_por: str | None = None

    def reservar(self, quem: str) -> bool:
        if self.reservado_por is None:   # verifica
            # outra thread pode entrar aqui!
            self.reservado_por = quem    # age
            return True
        return False
```

Entre a verificação e a atribuição, outra thread pode passar na mesma verificação. Resultado: duas pessoas "reservam" o mesmo assento.

## A correção: seção crítica com lock

<CodeTabs>

```python
import threading


class Assento:
    def __init__(self) -> None:
        self._trava = threading.Lock()
        self.reservado_por: str | None = None

    def reservar(self, quem: str) -> bool:
        with self._trava:  # verificar e agir viram uma operação indivisível
            if self.reservado_por is None:
                self.reservado_por = quem
                return True
            return False


assento = Assento()
sucessos: list[str] = []


def tentar(nome: str) -> None:
    if assento.reservar(nome):
        sucessos.append(nome)


threads = [threading.Thread(target=tentar, args=(f"p{i}",)) for i in range(50)]
for t in threads:
    t.start()
for t in threads:
    t.join()

assert len(sucessos) == 1  # exatamente um vencedor
print("vencedor:", sucessos[0])
```

```javascript
// JavaScript roda o seu código em uma única thread: a sequência "verifica e age" nunca é interrompida
// no meio. Com worker threads e memória compartilhada (SharedArrayBuffer) o problema volta, e a
// solução é Atomics.compareExchange, que faz o papel da trava.
const estado = new Int32Array(new SharedArrayBuffer(4));   // 0 = livre, 1 = reservado
const sucessos = [];

function reservar(nome) {
  return Atomics.compareExchange(estado, 0, 0, 1) === 0;   // verificar e agir viram uma operação indivisível
}

function tentar(nome) {
  if (reservar(nome)) sucessos.push(nome);
}

for (let i = 0; i < 50; i++) tentar(`p${i}`);

console.assert(sucessos.length === 1);   // exatamente um vencedor
console.log("vencedor:", sucessos[0]);
```

```java
import java.util.*;

class Assento {
    private final Object trava = new Object();
    private String reservadoPor = null;

    boolean reservar(String quem) {
        synchronized (trava) {   // verificar e agir viram uma operação indivisível
            if (reservadoPor == null) {
                reservadoPor = quem;
                return true;
            }
            return false;
        }
    }
}

public static void main(String[] args) throws InterruptedException {
    Assento assento = new Assento();
    List<String> sucessos = Collections.synchronizedList(new ArrayList<>());

    List<Thread> threads = new ArrayList<>();
    for (int i = 0; i < 50; i++) {
        String nome = "p" + i;
        Thread t = new Thread(() -> {
            if (assento.reservar(nome)) sucessos.add(nome);
        });
        threads.add(t);
        t.start();
    }
    for (Thread t : threads) t.join();

    if (sucessos.size() != 1) throw new AssertionError();   // exatamente um vencedor
```

```cpp
    Assento assento;
    vector<string> sucessos;
    mutex travaLista;

    vector<thread> threads;
    for (int i = 0; i < 50; i++) {
        string nome = "p" + to_string(i);
        threads.emplace_back([&, nome] {
            if (assento.reservar(nome)) {
                lock_guard<mutex> guarda(travaLista);
                sucessos.push_back(nome);
            }
        });
    }
    for (auto& t : threads) t.join();

    assert(sucessos.size() == 1);   // exatamente um vencedor
    cout << "vencedor: " << sucessos[0] << endl;
}
```

```csharp
using System;
using System.Collections.Generic;
using System.Threading;

class Assento
{
    private readonly object trava = new object();
    private string reservadoPor = null;

    public bool Reservar(string quem)
    {
        lock (trava)   // verificar e agir viram uma operação indivisível
        {
            if (reservadoPor == null)
            {
                reservadoPor = quem;
                return true;
            }
            return false;
        }
    }
}

static void Main()
{
    var assento = new Assento();
    var sucessos = new List<string>();

    var threads = new List<Thread>();
    for (int i = 0; i < 50; i++)
    {
        string nome = "p" + i;
        var t = new Thread(() =>
        {
            if (assento.Reservar(nome))
            {
                lock (sucessos) { sucessos.Add(nome); }
            }
        });
        threads.Add(t);
        t.Start();
    }
    foreach (var t in threads) t.Join();

    if (sucessos.Count != 1) throw new Exception("falhou");   // exatamente um vencedor
    Console.WriteLine("vencedor: " + sucessos[0]);
}
```

```go
import (
	"fmt"
	"sync"
)

type Assento struct {
	trava       sync.Mutex
	reservadoPor *string
}

func (a *Assento) reservar(quem string) bool {
	a.trava.Lock() // verificar e agir viram uma operação indivisível
	defer a.trava.Unlock()
	if a.reservadoPor == nil {
		a.reservadoPor = &quem
		return true
	}
	return false
}

func main() {
	assento := &Assento{}
	sucessos := []string{}
	var travaLista sync.Mutex
	var wg sync.WaitGroup

	for i := 0; i < 50; i++ {
		nome := fmt.Sprintf("p%d", i)
		wg.Add(1)
		go func() {
			defer wg.Done()
			if assento.reservar(nome) {
				travaLista.Lock()
				sucessos = append(sucessos, nome)
				travaLista.Unlock()
			}
		}()
	}
	wg.Wait()

	if len(sucessos) != 1 { // exatamente um vencedor
		panic("falhou")
	}
	fmt.Println("vencedor:", sucessos[0])
}
```

A trava transforma "verificar e agir" numa seção crítica: só uma thread por vez entra.

## Ferramentas e quando usar

| Ferramenta | Uso |
| --- | --- |
| `Lock` | Exclusão mútua simples sobre um recurso |
| `RLock` | Lock reentrante, quando o mesmo código se chama recursivamente |
| `Semaphore` | Limitar a N acessos simultâneos (vagas de estacionamento) |
| `Condition` / `Event` | Esperar por uma condição ou sinal |
| `queue.Queue` | Passar dados entre threads com segurança (produtor-consumidor) |
| Imutabilidade | Objetos que não mudam não precisam de trava |

## Decisões de design

- **Granularidade**: uma trava global é simples, mas serializa tudo. Uma trava por recurso (por assento, por conta) permite paralelismo.
- **Deadlock**: ao adquirir duas travas, sempre na mesma ordem. Numa transferência entre contas, ordene pelo id.
- **Onde ficam as travas**: dentro da classe que protege o estado, não espalhadas pelos chamadores. Isso é encapsulamento aplicado à concorrência.
- **Mantenha seções críticas curtas**: nunca faça I/O lento segurando uma trava.

<Callout type="warning" title="Ordem de aquisição">
Se a thread A pega a conta 1 e espera a 2, enquanto a B pega a 2 e espera a 1, ninguém avança. Ordenar as travas por id elimina esse ciclo.
</Callout>

## Onde costuma aparecer

Reserva de assentos e salas, saldo de conta, estoque, contador de limite de requisições, cache e pools de recursos. Em muitos problemas, bastar dizer onde você colocaria travas já demonstra a consciência necessária; implemente quando o entrevistador pedir.

## Na entrevista

Primeiro faça a versão correta em thread única; depois, ao ser perguntado, aponte as seções críticas, adicione locks e discuta granularidade. Follow-ups: "como evitaria deadlock?", "um lock global é aceitável?", "como escalaria em várias máquinas?" (a resposta sai da memória e vai para transações de banco ou travas distribuídas).
