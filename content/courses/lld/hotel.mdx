O coração de um sistema hoteleiro é a disponibilidade por intervalo de datas. Quarto livre não é um booleano: é a ausência de reservas sobrepostas. Entender isso separa um bom design de um ingênuo.

## Requisitos

- Quartos de tipos diferentes (solteiro, casal, suíte) com diárias distintas.
- Buscar quartos livres para um período.
- Reservar, cancelar e fazer check-in e check-out.
- Calcular o valor da estadia.

## Entidades

| Entidade | Responsabilidade |
| --- | --- |
| `Quarto` | Número, tipo, diária e suas reservas. |
| `Reserva` | Hóspede, quarto, check-in, check-out, status. |
| `Hotel` | Busca, reserva e cancelamento. |

Intervalos são meio abertos: o dia do check-out fica livre para o próximo hóspede. Dois intervalos se sobrepõem quando `a.entrada < b.saida` e `b.entrada < a.saida`.

## Implementação

```python
from dataclasses import dataclass
from enum import Enum
from typing import List


class Status(Enum):
    CONFIRMADA = "confirmada"
    CANCELADA = "cancelada"


@dataclass
class Reserva:
    hospede: str
    entrada: int   # dia (inteiro) de check-in
    saida: int     # dia de check-out (exclusivo)
    status: Status = Status.CONFIRMADA

    def sobrepoe(self, entrada: int, saida: int) -> bool:
        return self.status is Status.CONFIRMADA and self.entrada < saida and entrada < self.saida


class Quarto:
    def __init__(self, numero: int, tipo: str, diaria: float):
        self.numero, self.tipo, self.diaria = numero, tipo, diaria
        self.reservas: List[Reserva] = []

    def livre(self, entrada: int, saida: int) -> bool:
        return not any(r.sobrepoe(entrada, saida) for r in self.reservas)


class Hotel:
    def __init__(self, quartos: List[Quarto]):
        self.quartos = quartos

    def buscar(self, tipo: str, entrada: int, saida: int) -> List[Quarto]:
        if saida <= entrada:
            raise ValueError("período inválido")
        return [q for q in self.quartos if q.tipo == tipo and q.livre(entrada, saida)]

    def reservar(self, hospede: str, tipo: str, entrada: int, saida: int) -> Reserva:
        disponiveis = self.buscar(tipo, entrada, saida)
        if not disponiveis:
            raise RuntimeError("sem disponibilidade")
        quarto = min(disponiveis, key=lambda q: q.numero)
        r = Reserva(hospede, entrada, saida)
        r.quarto = quarto
        quarto.reservas.append(r)
        return r

    def cancelar(self, reserva: Reserva):
        reserva.status = Status.CANCELADA

    def valor(self, reserva: Reserva) -> float:
        return (reserva.saida - reserva.entrada) * reserva.quarto.diaria


h = Hotel([Quarto(101, "casal", 300.0), Quarto(102, "casal", 320.0)])
a = h.reservar("Ana", "casal", 1, 4)
b = h.reservar("Bia", "casal", 3, 5)    # 101 ocupado em 3, vai para 102
print(a.quarto.numero, b.quarto.numero, h.valor(a))
h.cancelar(a)
c = h.reservar("Caio", "casal", 1, 3)
print(c.quarto.numero)                  # 101 voltou a ficar livre
c2 = h.reservar("Duda", "casal", 3, 6)  # entrada no dia do check-out de Caio
print(c2.quarto.numero)
```

## Concorrência

Dois recepcionistas reservando o último quarto no mesmo período é o caso crítico. A verificação de sobreposição e a inserção devem ser atômicas: lock por quarto, ou no banco uma restrição de exclusão por intervalo. Sem isso você terá overbooking.

## Extensões

Preço dinâmico por temporada (Strategy de tarifa), múltiplos quartos por reserva, serviços extras na conta (Decorator no valor), políticas de cancelamento com multa e overbooking intencional controlado, que alguns hotéis usam de propósito.

## Na entrevista
