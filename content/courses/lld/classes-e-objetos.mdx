Classe e objeto são as peças mais básicas da orientação a objetos. A **classe** é um molde que descreve que dados uma coisa tem e o que ela sabe fazer. O **objeto** é uma instância concreta desse molde, com valores próprios. Parece simples, mas boa parte dos problemas de design nasce de classes mal recortadas.

## O problema que classes resolvem

Sem classes, dados e funções vivem soltos. Você passa dicionários de um lado para o outro e qualquer função pode alterá-los de qualquer jeito:

<CodeTabs>

```python
conta = {"titular": "Lia", "saldo": 100}


def sacar(c: dict, valor: float) -> None:
    c["saldo"] -= valor


sacar(conta, 500)
print(conta["saldo"])  # -400, nada impediu
```

```javascript
const conta = { titular: "Lia", saldo: 100 };

function sacar(c, valor) {
  c.saldo -= valor;
}

sacar(conta, 500);
console.log(conta.saldo);  // -400, nada impediu
```


Nada garante que o saldo fique coerente, e a regra "não pode sacar mais que o saldo" acaba espalhada por cada função que mexe no dicionário. Uma classe junta **estado** e **comportamento** num lugar só e passa a ser responsável pelas próprias regras.

## Como funciona em Python

<CodeTabs>

```python
class ContaCorrente:
    taxa_saque = 1.50  # atributo de classe: compartilhado por todas as contas

    def __init__(self, titular: str, saldo_inicial: float = 0.0) -> None:
        self.titular = titular          # atributo de instância
        self.saldo = saldo_inicial

    def depositar(self, valor: float) -> None:
        if valor <= 0:
            raise ValueError("depósito deve ser positivo")
        self.saldo += valor

    def sacar(self, valor: float) -> None:
        total = valor + self.taxa_saque
        if total > self.saldo:
            raise ValueError("saldo insuficiente")
        self.saldo -= total

    def __repr__(self) -> str:
        return f"ContaCorrente({self.titular!r}, saldo={self.saldo:.2f})"


lia = ContaCorrente("Lia", 100)
rui = ContaCorrente("Rui")
lia.sacar(20)
rui.depositar(50)
print(lia)  # ContaCorrente('Lia', saldo=78.50)
print(rui)  # ContaCorrente('Rui', saldo=50.00)
```

```java
import java.util.Locale;

    double saldo;

    ContaCorrente(String titular, double saldoInicial) {
        this.titular = titular;
        this.saldo = saldoInicial;
```

Pontos importantes:

- `__init__` é o inicializador: roda quando você cria o objeto e deve deixá-lo num **estado válido**.
- `self` é a referência ao próprio objeto. Cada instância tem seu `saldo`.
- `taxa_saque` é atributo de classe: todas as instâncias enxergam o mesmo valor, a menos que alguma o sobrescreva.
- `__repr__` define como o objeto aparece ao ser impresso, o que ajuda muito na depuração.

## Identidade, estado e comportamento

Todo objeto tem três características:

| Característica | Significado | Em Python |
| --- | --- | --- |
| Identidade | é "este" objeto, distinto de outros | `id(obj)`, operador `is` |
| Estado | os valores atuais dos atributos | `obj.saldo` |
| Comportamento | o que ele faz | `obj.sacar(10)` |

Duas contas com o mesmo titular e mesmo saldo continuam sendo objetos diferentes (`a is b` é falso). Se você quer que objetos sejam comparados pelo valor, defina `__eq__` ou use `@dataclass`.

## Dataclasses para objetos de valor

Quando a classe é basicamente um pacote de dados, `dataclass` elimina código repetitivo:

<CodeTabs>

```python
from dataclasses import dataclass


@dataclass(frozen=True)
class Coordenada:
    lat: float
    lon: float

    def ao_norte_de(self, outra: "Coordenada") -> bool:
        return self.lat > outra.lat


recife = Coordenada(-8.05, -34.9)
porto_alegre = Coordenada(-30.03, -51.23)
print(recife.ao_norte_de(porto_alegre))       # True
print(recife == Coordenada(-8.05, -34.9))     # True: igualdade por valor
```

```javascript
class Coordenada {
  constructor(lat, lon) {
    this.lat = lat;
    this.lon = lon;
    Object.freeze(this);
  }

  aoNorteDe(outra) { return this.lat > outra.lat; }

  igual(outra) { return this.lat === outra.lat && this.lon === outra.lon; }   // igualdade por valor
}

const recife = new Coordenada(-8.05, -34.9);
const portoAlegre = new Coordenada(-30.03, -51.23);
```

```java
import java.util.Objects;

final class Coordenada {
    final double lat, lon;

    Coordenada(double lat, double lon) {
        this.lat = lat;
        this.lon = lon;
    }

    boolean aoNorteDe(Coordenada outra) { return lat > outra.lat; }

    @Override
    public boolean equals(Object o) {   // igualdade por valor
        if (!(o instanceof Coordenada)) return false;
        Coordenada c = (Coordenada) o;
        return lat == c.lat && lon == c.lon;
    }

    @Override
    public int hashCode() { return Objects.hash(lat, lon); }
}

public static void main(String[] args) {
    Coordenada recife = new Coordenada(-8.05, -34.9);
    Coordenada portoAlegre = new Coordenada(-30.03, -51.23);
    System.out.println(recife.aoNorteDe(portoAlegre));                  // true
    System.out.println(recife.equals(new Coordenada(-8.05, -34.9)));    // true: igualdade por valor
}
```

## Armadilhas

- **Classe anêmica:** só atributos, sem comportamento, com toda a lógica em funções externas. Você perde a principal vantagem da OOP.
- **Classe Deus:** uma classe que sabe e faz tudo (`SistemaGerenciador`). Difícil de testar e de mudar.
- **Lista mutável como padrão:** `def __init__(self, itens=[])` compartilha a mesma lista entre todas as instâncias. Use `None` e crie a lista dentro, ou `field(default_factory=list)`.
- **Objeto em estado inválido:** se o construtor permite criar uma conta com saldo negativo, todo o resto do código precisa desconfiar dela.

<Callout type="tip" title="Substantivos e verbos">
Ao modelar, os substantivos do enunciado sugerem classes e atributos; os verbos sugerem métodos. É um ponto de partida, não uma regra rígida.
</Callout>

## Na entrevista

Ao propor uma classe, diga o que ela **sabe** (atributos) e o que ela **faz** (métodos), e quais invariantes ela protege ("saldo nunca fica negativo"). Follow-ups comuns: "qual a diferença entre atributo de classe e de instância?", "como comparar dois objetos por valor?", "por que essa regra está nesta classe e não em outra?".
