**Abstração** é mostrar o essencial e esconder o resto. Quando você dirige, usa volante, pedais e câmbio; não precisa saber como a injeção eletrônica calcula a mistura de combustível. Em software, abstração é desenhar objetos e interfaces que expõem **o que** fazem num nível de detalhe útil para quem usa, escondendo **como** fazem.

## Abstração vs encapsulamento

Os dois conceitos andam juntos e costumam ser confundidos:

| | Abstração | Encapsulamento |
| --- | --- | --- |
| Foco | o que o usuário do objeto enxerga | como o estado interno é protegido |
| Pergunta | qual é a visão simplificada certa? | quem pode alterar este dado e como? |
| Ferramentas | interfaces, classes abstratas, nomes de métodos bem escolhidos | atributos internos, propriedades, validação |
| Resultado | o chamador pensa em termos do domínio | o objeto não entra em estado inválido |

Uma forma de lembrar: abstração decide **qual porta existe**; encapsulamento decide **que todo mundo entra pela porta**.

## O problema: detalhes vazando para o chamador

Imagine um relatório que precisa ler dados ora de um arquivo CSV, ora de uma API:

```python
import csv
import io


def total_vendas_csv(conteudo: str) -> float:
    leitor = csv.DictReader(io.StringIO(conteudo))
    return sum(float(linha["valor"]) for linha in leitor)


def total_vendas_api(resposta: dict) -> float:
    return sum(item["amount"] for item in resposta["data"]["sales"])


print(total_vendas_csv("valor\n10\n20\n"))
print(total_vendas_api({"data": {"sales": [{"amount": 5}]}}))
```

O código de relatório conhece formato de CSV, nomes de campos da API, estrutura aninhada do JSON. Para cada nova fonte, uma nova função com lógica de negócio duplicada.

## Criando a abstração certa

O relatório não se importa com a origem; ele quer uma sequência de **vendas**. Esse é o nível de abstração adequado:

```python
import csv
import io
from abc import ABC, abstractmethod
from dataclasses import dataclass
from typing import Iterator


@dataclass(frozen=True)
class Venda:
    produto: str
    valor: float


class FonteDeVendas(ABC):
    @abstractmethod
    def vendas(self) -> Iterator[Venda]:
        """Entrega as vendas, escondendo formato e origem."""


class FonteCsv(FonteDeVendas):
    def __init__(self, conteudo: str) -> None:
        self._conteudo = conteudo

    def vendas(self) -> Iterator[Venda]:
        for linha in csv.DictReader(io.StringIO(self._conteudo)):
            yield Venda(linha["produto"], float(linha["valor"]))


class FonteApi(FonteDeVendas):
    def __init__(self, resposta: dict) -> None:
        self._resposta = resposta

    def vendas(self) -> Iterator[Venda]:
        for item in self._resposta["data"]["sales"]:
            yield Venda(item["sku"], item["amount"])


class Relatorio:
    def __init__(self, fonte: FonteDeVendas) -> None:
        self._fonte = fonte

    def total(self) -> float:
        return sum(v.valor for v in self._fonte.vendas())

    def mais_vendido(self) -> str:
        somas: dict[str, float] = {}
        for v in self._fonte.vendas():
            somas[v.produto] = somas.get(v.produto, 0) + v.valor
        return max(somas, key=somas.get)


csv_texto = "produto,valor\ncaderno,12\nlapis,3\ncaderno,12\n"
api = {"data": {"sales": [{"sku": "mochila", "amount": 90.0}]}}

for fonte in (FonteCsv(csv_texto), FonteApi(api)):
    r = Relatorio(fonte)
    print(type(fonte).__name__, r.total(), r.mais_vendido())
```

`Relatorio` agora fala a língua do domínio (`Venda`, `total`, `mais_vendido`). Os detalhes de parsing ficaram dentro de cada fonte. Uma nova fonte, como uma planilha, é só mais uma classe.

## Níveis de abstração

Um bom método opera em **um único nível** de abstração. Compare:

```text
Misturado:
  processar_pedido():
      valida estoque
      abre conexão com o banco, monta SQL, executa
      formata HTML do e-mail
      chama SMTP

Consistente:
  processar_pedido():
      reservar_estoque()
      salvar_pedido()
      notificar_cliente()
```

A versão consistente se lê como uma história. Cada passo esconde seus detalhes num método ou objeto próprio.

## Armadilhas

- **Abstração vazada (leaky abstraction).** A interface promete esconder detalhes, mas o chamador precisa saber deles mesmo assim, por exemplo tratando um erro específico do driver de banco. Traduza erros internos para erros do domínio.
- **Abstração prematura.** Criar `FonteDeVendas` quando só existe e só existirá CSV adiciona camadas sem benefício.
- **Abstração genérica demais.** Um `Processador` com método `executar(dados)` não comunica nada. Nomes devem refletir o domínio.

<Callout type="note" title="Regra prática">
Uma abstração vale a pena quando permite que alguém use o objeto sem ler a implementação. Se você sempre precisa abrir o código para entender o que acontece, a abstração está no nível errado.
</Callout>
