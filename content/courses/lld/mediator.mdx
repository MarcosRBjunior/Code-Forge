## O problema

Considere a tela de finalização de compra. Ela tem: uma caixa "retirar na loja", um campo de CEP, um campo de endereço, um seletor de frete e o botão "Pagar". As regras se cruzam:

- Marcar "retirar na loja" desabilita CEP, endereço e frete.
- Digitar um CEP válido preenche o endereço e carrega as opções de frete.
- O botão "Pagar" só fica ativo quando a entrega está resolvida.

Se cada componente conversar diretamente com os outros, a caixa de seleção precisa conhecer o CEP, o CEP precisa conhecer o frete e o botão, o frete precisa conhecer o botão... Com N componentes, você caminha para N x N dependências. Nenhum componente pode ser reaproveitado em outra tela, porque está amarrado a todos os vizinhos.

O Mediator **centraliza a comunicação entre objetos num único coordenador**. Os componentes (chamados colegas) só avisam o mediador "algo aconteceu comigo"; o mediador decide quem mais deve reagir. A malha de dependências vira uma estrela.

## Estrutura

```text
      Sem mediador                          Com mediador

   A <-----> B                          A       B
   ^ \     / ^                           \     /
   |   \ /   |                            v   v
   |   / \   |                         +----------+
   v /     \ v                         | Mediador |
   C <-----> D                         +----------+
                                          ^   ^
                                         /     \
                                        C       D

+--------------------------+         +-----------------------+
|  Mediador (iface)        |<--------|  Colega               |
|--------------------------|  avisa  |-----------------------|
| + notificar(remetente,   |         | - mediador            |
|             evento)      |         | + metodos proprios    |
+--------------------------+         +-----------------------+
            ^
            |
   MediadorConcreto (conhece todos os colegas e as regras)
```

## Implementação: tela de checkout

```python
from typing import List, Optional


class Componente:
    def __init__(self, nome: str):
        self.nome = nome
        self.habilitado = True
        self.mediador: Optional["TelaCheckout"] = None

    def _avisar(self, evento: str) -> None:
        if self.mediador:
            self.mediador.notificar(self, evento)


class CaixaSelecao(Componente):
    def __init__(self, nome: str):
        super().__init__(nome)
        self.marcada = False

    def alternar(self) -> None:
        self.marcada = not self.marcada
        self._avisar("alterada")


class CampoTexto(Componente):
    def __init__(self, nome: str):
        super().__init__(nome)
        self.valor = ""

    def digitar(self, texto: str) -> None:
        self.valor = texto
        self._avisar("alterado")


class SeletorFrete(Componente):
    def __init__(self, nome: str):
        super().__init__(nome)
        self.opcoes: List[str] = []
        self.escolhida: Optional[str] = None

    def carregar(self, opcoes: List[str]) -> None:
        self.opcoes, self.escolhida = opcoes, None

    def escolher(self, opcao: str) -> None:
        self.escolhida = opcao
        self._avisar("escolhido")


class Botao(Componente):
    pass


ENDERECOS = {"01310-100": "Av. Paulista, São Paulo/SP", "20040-002": "Centro, Rio de Janeiro/RJ"}


class TelaCheckout:
    """Mediador concreto: as regras de interação moram só aqui."""

    def __init__(self):
        self.retirar = CaixaSelecao("retirar na loja")
        self.cep = CampoTexto("cep")
        self.endereco = CampoTexto("endereço")
        self.frete = SeletorFrete("frete")
        self.pagar = Botao("pagar")
        for c in (self.retirar, self.cep, self.endereco, self.frete, self.pagar):
            c.mediador = self
        self._atualizar_botao()

    def notificar(self, remetente: Componente, evento: str) -> None:
        if remetente is self.retirar:
            for c in (self.cep, self.endereco, self.frete):
                c.habilitado = not self.retirar.marcada
        elif remetente is self.cep:
            endereco = ENDERECOS.get(self.cep.valor)
            self.endereco.valor = endereco or ""
            self.frete.carregar(["PAC", "Sedex"] if endereco else [])
        self._atualizar_botao()

    def _atualizar_botao(self) -> None:
        entrega_ok = bool(self.endereco.valor) and self.frete.escolhida is not None
        self.pagar.habilitado = self.retirar.marcada or entrega_ok

    def mostrar(self, momento: str) -> None:
        print(f"[{momento}] cep={'on' if self.cep.habilitado else 'off'} "
              f"endereço='{self.endereco.valor}' fretes={self.frete.opcoes} "
              f"pagar={'on' if self.pagar.habilitado else 'off'}")


tela = TelaCheckout()
tela.mostrar("início")

tela.cep.digitar("01310-100")
tela.mostrar("CEP digitado")

tela.frete.escolher("Sedex")
tela.mostrar("frete escolhido")

tela.cep.digitar("99999-999")
tela.mostrar("CEP inválido")

tela.retirar.alternar()
tela.mostrar("retirar na loja")
```

Note que `CampoTexto` não faz ideia de que existe um botão de pagar. Você poderia usar o mesmo campo numa tela de cadastro com outro mediador e outras regras.

## Quando usar e quando evitar

**Use quando:**

- Vários objetos interagem de formas complexas e bem definidas, e as dependências cruzadas estão difíceis de entender.
- Você quer reaproveitar componentes em contextos diferentes, trocando apenas as regras de coordenação.
- Interfaces gráficas (formulários, diálogos), salas de chat, controle de tráfego aéreo (aviões não conversam entre si, só com a torre), orquestração de dispositivos em casa inteligente.

**Evite quando:**

- São só dois ou três objetos com interação simples. O mediador vira indireção sem ganho.
- O mediador começa a acumular toda a lógica do sistema e vira um "objeto deus". Se isso acontecer, divida em mediadores menores por área.

<Callout type="warning" title="O mediador pode virar o novo problema">
Você troca muitas dependências espalhadas por uma classe central que conhece tudo. Isso é bom enquanto ela trata só de coordenação. Regras de negócio pesadas (cálculo de frete, validação fiscal) devem continuar em serviços próprios que o mediador apenas chama.
</Callout>

## Padrões parecidos

| Padrão | Diferença |
| --- | --- |
| Observer | Comunicação unidirecional e genérica: o sujeito avisa e não sabe quem reage nem o que farão. O mediador conhece os colegas e **decide** as reações. É comum implementar o canal colega para mediador usando Observer. |
| Facade | Simplifica o acesso de fora a um subsistema; os objetos do subsistema não conhecem a fachada. No Mediator, os colegas conhecem e usam o mediador, e a comunicação é em mão dupla. |
| Chain of Responsibility | Passa o pedido em sequência até alguém tratar; não há coordenador central. |

## Na entrevista

- Em design de chat, a classe `SalaDeChat` é um mediador: usuários enviam para a sala, a sala distribui. Em elevadores, o `ControladorCentral` que escolhe qual cabine atende cada chamada também é.
- Mostre o desenho "malha versus estrela"; ele explica o padrão em cinco segundos.
- Follow-ups: "isso não vira um objeto gigante?" (sim, se você deixar; divida por responsabilidade), "qual a diferença para Observer?" (quem decide a reação), "como testar?" (o mediador pode ser testado com colegas falsos e os colegas, com um mediador falso).
