O **Single Responsibility Principle (SRP)** diz que uma classe deve ter **um único motivo para mudar**. Não significa "fazer uma única coisa" no sentido de ter um método só; significa que tudo o que a classe faz deve atender ao mesmo interesse, à mesma fonte de mudança. Se o time financeiro e o time de marketing podem, cada um, pedir alterações na mesma classe, ela tem duas responsabilidades.

## O problema

Quando uma classe junta várias responsabilidades, uma mudança em uma delas arrisca quebrar as outras. Testar fica difícil porque tudo vem junto: para testar o cálculo, você precisa de banco e de e-mail configurados.

## Exemplo que viola o SRP

```python
class FolhaDePagamento:
    def __init__(self) -> None:
        self.registros: list[str] = []

    def processar(self, nome: str, horas: float, valor_hora: float) -> float:
        # 1) regra de negócio: cálculo
        bruto = horas * valor_hora
        if horas > 160:
            bruto += (horas - 160) * valor_hora * 0.5
        liquido = round(bruto * 0.89, 2)

        # 2) persistência
        self.registros.append(f"{nome};{liquido}")

        # 3) formatação e envio
        print(f"Olá {nome}, seu pagamento de R$ {liquido:.2f} foi processado.")
        return liquido


FolhaDePagamento().processar("Iara", 170, 50.0)
```

Três motivos para mudar a mesma classe:

| Quem pede a mudança | O que muda |
| --- | --- |
| RH / contabilidade | regra de horas extras, descontos |
| Infraestrutura | formato ou destino da gravação |
| Comunicação | texto e canal do aviso |

## Versão corrigida

Cada responsabilidade vai para uma classe própria, e uma classe coordenadora as conecta:

```python
from dataclasses import dataclass


@dataclass(frozen=True)
class Holerite:
    nome: str
    liquido: float


class CalculadoraSalarial:
    JORNADA = 160
    ADICIONAL_EXTRA = 0.5
    DESCONTOS = 0.11

    def calcular(self, nome: str, horas: float, valor_hora: float) -> Holerite:
        bruto = horas * valor_hora
        extras = max(0.0, horas - self.JORNADA)
        bruto += extras * valor_hora * self.ADICIONAL_EXTRA
        return Holerite(nome, round(bruto * (1 - self.DESCONTOS), 2))


class RepositorioHolerites:
    def __init__(self) -> None:
        self._linhas: list[str] = []

    def salvar(self, h: Holerite) -> None:
        self._linhas.append(f"{h.nome};{h.liquido}")

    def total_salvos(self) -> int:
        return len(self._linhas)


class AvisoDePagamento:
    def montar(self, h: Holerite) -> str:
        return f"Olá {h.nome}, seu pagamento de R$ {h.liquido:.2f} foi processado."


class ProcessadorDeFolha:
    def __init__(self, calc: CalculadoraSalarial, repo: RepositorioHolerites, aviso: AvisoDePagamento) -> None:
        self.calc, self.repo, self.aviso = calc, repo, aviso

    def processar(self, nome: str, horas: float, valor_hora: float) -> Holerite:
        holerite = self.calc.calcular(nome, horas, valor_hora)
        self.repo.salvar(holerite)
        print(self.aviso.montar(holerite))
        return holerite


repo = RepositorioHolerites()
proc = ProcessadorDeFolha(CalculadoraSalarial(), repo, AvisoDePagamento())
h = proc.processar("Iara", 170, 50.0)
assert CalculadoraSalarial().calcular("x", 160, 10).liquido == 1424.0
print(h, repo.total_salvos())
```

Agora a regra de horas extras pode ser testada sem banco e sem e-mail, e mudar o texto do aviso não toca no cálculo. `ProcessadorDeFolha` tem uma única responsabilidade também: orquestrar o fluxo.

## Como identificar violações

- O nome da classe tem "E" ou é genérico demais: `GerenciadorDeUsuarioEEmail`, `Utils`, `Manager`.
- Métodos usam grupos de atributos disjuntos: metade usa `conexao`, metade usa `template`.
- Importações de áreas muito diferentes no mesmo arquivo (SQL, HTML, HTTP).
- O teste unitário de uma regra simples exige montar meia aplicação.

## Trade-offs

<Callout type="warning" title="Não fatie demais">
Levado ao extremo, o SRP gera dezenas de classes de uma linha e um fluxo impossível de seguir. O critério é o **motivo de mudança**, não o número de métodos. Duas operações que sempre mudam juntas pertencem à mesma classe.
</Callout>
