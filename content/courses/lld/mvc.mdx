**MVC** (Model-View-Controller) separa uma aplicação em três papéis para que a interface possa mudar sem tocar nas regras, e as regras possam ser testadas sem interface. É um dos padrões arquiteturais mais antigos e aparece, com variações, em quase todo framework web e de GUI.

## Os três papéis

| Papel | Responsabilidade | Não deve |
| --- | --- | --- |
| Model | Estado e regras de negócio | Saber como é exibido |
| View | Apresentar o modelo ao usuário | Conter regras de negócio |
| Controller | Receber entradas, chamar o modelo, escolher a view | Guardar estado do domínio |

```text
Usuário --entrada--> Controller --atualiza--> Model
                         |                      |
                         +----escolhe---> View <-+ (lê o estado)
```

O fluxo típico: o usuário age, o controller interpreta, altera o model, e a view reflete o novo estado. Em variações com Observer, o model notifica a view diretamente quando muda.

## Exemplo: contador de tarefas

```python
class ModeloTarefas:
    def __init__(self) -> None:
        self._tarefas: list[tuple[str, bool]] = []

    def adicionar(self, titulo: str) -> None:
        if not titulo.strip():
            raise ValueError("título vazio")
        self._tarefas.append((titulo, False))

    def concluir(self, indice: int) -> None:
        titulo, _ = self._tarefas[indice]
        self._tarefas[indice] = (titulo, True)

    def todas(self) -> list[tuple[str, bool]]:
        return list(self._tarefas)


class VisaoTexto:
    def renderizar(self, tarefas: list[tuple[str, bool]]) -> str:
        linhas = [f"[{'x' if feita else ' '}] {t}" for t, feita in tarefas]
        return "\n".join(linhas) or "(nenhuma tarefa)"


class ControladorTarefas:
    def __init__(self, modelo: ModeloTarefas, visao: VisaoTexto) -> None:
        self.modelo = modelo
        self.visao = visao

    def comando(self, texto: str) -> str:
        acao, _, arg = texto.partition(" ")
        if acao == "add":
            self.modelo.adicionar(arg)
        elif acao == "done":
            self.modelo.concluir(int(arg))
        return self.visao.renderizar(self.modelo.todas())


c = ControladorTarefas(ModeloTarefas(), VisaoTexto())
c.comando("add estudar LLD")
c.comando("add revisar SOLID")
saida = c.comando("done 0")
assert saida == "[x] estudar LLD\n[ ] revisar SOLID"
print(saida)
```

Trocar `VisaoTexto` por uma visão HTML não exige mexer no modelo nem no controlador. E o `ModeloTarefas` pode ser testado sem nenhuma saída.

## Variações

- **MVP**: o Presenter intermedeia tudo; a view é passiva e fica ainda mais fácil de testar.
- **MVVM**: o ViewModel expõe estado observável e a view se liga a ele automaticamente (comum em front-ends reativos).
- **MVC web**: o controller recebe a requisição HTTP, o model acessa dados e a view é um template.

## Armadilhas

- **Controller gordo**: regras de negócio escorrem para o controller. Mantenha-o fino e leve a lógica para o model.
- **View que consulta o banco**: quebra a separação e dificulta testes.
- **Dependência circular**: se model, view e controller se conhecem demais, o ganho some. Use interfaces ou eventos.
