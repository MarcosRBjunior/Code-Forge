## O problema

Uma playlist pode guardar músicas numa lista, uma árvore de pastas guarda arquivos aninhados, uma API paginada devolve resultados em lotes de 50. Quem consome esses dados quer só uma coisa: "me dá o próximo item". Se o código cliente precisar saber se é lista, árvore ou paginação, ele fica acoplado à estrutura interna da coleção, e qualquer mudança de representação quebra todos os consumidores.

O Iterator **separa a forma de percorrer uma coleção da coleção em si**. A coleção oferece um objeto iterador; o cliente só chama "próximo" até acabar. Você pode ter vários percursos diferentes (ordem normal, aleatória, só favoritas) sem expor a estrutura interna.

## Estrutura

```text
+---------------------+   cria   +----------------------+
|  Colecao (iface)    |--------->|  Iterador (iface)    |
|---------------------|          |----------------------|
| + criar_iterador()  |          | + tem_proximo()      |
+---------------------+          | + proximo()          |
          ^                      +----------------------+
          |                                ^
  ColecaoConcreta  ---- conhece ---->  IteradorConcreto
                                       (guarda a posição)
```

O iterador guarda o **estado do percurso** (posição atual, pilha de pendentes, página corrente). Assim, dois clientes podem percorrer a mesma coleção ao mesmo tempo, cada um com seu iterador.

## Python já tem o padrão embutido

Em Python, o protocolo de iteração é o Iterator: `__iter__` devolve o iterador e `__next__` devolve o próximo item ou lança `StopIteration`. Qualquer objeto que siga o protocolo funciona com `for`, `list()`, `sum()`, compreensões e afins. Geradores (`yield`) são a forma mais curta de escrever um iterador.

```python
import random
from dataclasses import dataclass
from typing import Iterator, List


@dataclass(frozen=True)
class Musica:
    titulo: str
    artista: str
    favorita: bool = False


class IteradorSequencial:
    """Iterador explícito, escrito à mão, para mostrar o estado guardado."""

    def __init__(self, musicas: List[Musica]):
        self._musicas = musicas
        self._posicao = 0

    def __iter__(self):
        return self

    def __next__(self) -> Musica:
        if self._posicao >= len(self._musicas):
            raise StopIteration
        musica = self._musicas[self._posicao]
        self._posicao += 1
        return musica


class Playlist:
    def __init__(self, nome: str):
        self.nome = nome
        self._musicas: List[Musica] = []

    def adicionar(self, musica: Musica) -> None:
        self._musicas.append(musica)

    # percurso padrão: usado pelo "for musica in playlist"
    def __iter__(self) -> IteradorSequencial:
        return IteradorSequencial(self._musicas)

    # percursos alternativos, escritos como geradores
    def aleatorio(self, semente: int) -> Iterator[Musica]:
        ordem = list(self._musicas)
        random.Random(semente).shuffle(ordem)
        yield from ordem

    def so_favoritas(self) -> Iterator[Musica]:
        for musica in self._musicas:
            if musica.favorita:
                yield musica


p = Playlist("Estrada")
p.adicionar(Musica("Trem Bala", "Ana Vilela", favorita=True))
p.adicionar(Musica("Asa Branca", "Luiz Gonzaga"))
p.adicionar(Musica("Garota de Ipanema", "Tom Jobim", favorita=True))
p.adicionar(Musica("Tempo Perdido", "Legião Urbana"))

print("sequencial:", [m.titulo for m in p])
print("aleatório:", [m.titulo for m in p.aleatorio(semente=7)])
print("favoritas:", [m.titulo for m in p.so_favoritas()])

# dois iteradores independentes sobre a mesma coleção
a, b = iter(p), iter(p)
print(next(a).titulo, "|", next(a).titulo, "|", next(b).titulo)
```

```java
import java.util.*;

class Musica {
    final String titulo, artista;
    final boolean favorita;

    Musica(String titulo, String artista, boolean favorita) {
        this.titulo = titulo;
        this.artista = artista;
        this.favorita = favorita;
    }

    Musica(String titulo, String artista) {
        this(titulo, artista, false);
    }
}

// Iterador explícito, escrito à mão, para mostrar o estado guardado.
class IteradorSequencial implements Iterator<Musica> {
    private final List<Musica> musicas;
    private int posicao = 0;

    IteradorSequencial(List<Musica> musicas) {
        this.musicas = musicas;
    }

    public boolean hasNext() {
        return posicao < musicas.size();
    }

    public Musica next() {
        if (!hasNext()) throw new NoSuchElementException();
        return musicas.get(posicao++);
    }
}

class Playlist implements Iterable<Musica> {
    final String nome;
    private final List<Musica> musicas = new ArrayList<>();

    Playlist(String nome) {
        this.nome = nome;
    }

    void adicionar(Musica musica) {
        musicas.add(musica);
    }

    // percurso padrão: usado pelo "for (Musica m : playlist)"
    public Iterator<Musica> iterator() {
        return new IteradorSequencial(musicas);
    }

    // percursos alternativos (a ordem aleatória depende do gerador de cada linguagem)
    Iterator<Musica> aleatorio(long semente) {
        List<Musica> ordem = new ArrayList<>(musicas);
        Collections.shuffle(ordem, new Random(semente));
        return ordem.iterator();
    }

    Iterator<Musica> soFavoritas() {
        List<Musica> r = new ArrayList<>();
        for (Musica m : musicas) if (m.favorita) r.add(m);
        return r.iterator();
    }
}

static String titulos(Iterator<Musica> it) {
    List<String> r = new ArrayList<>();
    while (it.hasNext()) r.add("'" + it.next().titulo + "'");
    return "[" + String.join(", ", r) + "]";
}

public static void main(String[] args) {
    Playlist p = new Playlist("Estrada");
    p.adicionar(new Musica("Trem Bala", "Ana Vilela", true));
    p.adicionar(new Musica("Asa Branca", "Luiz Gonzaga"));
    p.adicionar(new Musica("Garota de Ipanema", "Tom Jobim", true));
    p.adicionar(new Musica("Tempo Perdido", "Legião Urbana"));
```

```csharp
class IteradorSequencial : IEnumerator<Musica>

        get { return Current; }

    {
        posicao++;
        return posicao < musicas.Count;

    {
        posicao = -1;
    }

    public void Dispose() { }
}

    {
        musicas.Add(musica);

    {
        return new IteradorSequencial(musicas);

    {
        return GetEnumerator();

        foreach (var musica in musicas)

            if (musica.Favorita) yield return musica;
        }
    }
```

```go
import (

	"math/rand"
	"strings"

type Musica struct {
	titulo, artista string
	favorita        bool
}

// Iterador explícito, escrito à mão, para mostrar o estado guardado.
type IteradorSequencial struct {
	musicas []Musica
	posicao int
}

func (it *IteradorSequencial) temProximo() bool { return it.posicao < len(it.musicas) }

func (it *IteradorSequencial) proximo() Musica {
	m := it.musicas[it.posicao]
	it.posicao++
	return m
}

type Playlist struct {
	nome    string
	musicas []Musica
}

func (p *Playlist) adicionar(m Musica) { p.musicas = append(p.musicas, m) }

// percurso padrão
func (p *Playlist) iterador() *IteradorSequencial { return &IteradorSequencial{musicas: p.musicas} }

// percursos alternativos (a ordem aleatória depende do gerador de cada linguagem)
func (p *Playlist) aleatorio(semente int64) []Musica {
	ordem := append([]Musica{}, p.musicas...)
	rand.New(rand.NewSource(semente)).Shuffle(len(ordem), func(i, j int) { ordem[i], ordem[j] = ordem[j], ordem[i] })
	return ordem
}

func (p *Playlist) soFavoritas() []Musica {
	r := []Musica{}
	for _, m := range p.musicas {
		if m.favorita {
			r = append(r, m)
		}
	}
	return r
}

func titulos(ms []Musica) string {
	r := []string{}
	for _, m := range ms {
		r = append(r, "'"+m.titulo+"'")
	}
	return "[" + strings.Join(r, ", ") + "]"
}
```

### Iterador sobre estrutura não linear e dados preguiçosos

O ganho fica maior quando a estrutura é complexa. Abaixo, um iterador que percorre uma árvore de pastas em profundidade e outro que busca páginas de uma API só quando precisa (avaliação preguiçosa).

<CodeTabs>

```python
from typing import Dict, Iterator, List


class Pasta:
    def __init__(self, nome: str):
        self.nome = nome
        self.arquivos: List[str] = []
        self.subpastas: List["Pasta"] = []

    def caminhar(self) -> Iterator[str]:
        pilha = [(self, self.nome)]
        while pilha:
            pasta, caminho = pilha.pop()
            for arquivo in pasta.arquivos:
                yield f"{caminho}/{arquivo}"
            for sub in reversed(pasta.subpastas):
                pilha.append((sub, f"{caminho}/{sub.nome}"))


raiz = Pasta("projeto")
raiz.arquivos = ["README.md"]
src = Pasta("src")
src.arquivos = ["main.py", "util.py"]
testes = Pasta("tests")
testes.arquivos = ["test_main.py"]
raiz.subpastas = [src, testes]

for caminho in raiz.caminhar():
    print(caminho)


# API paginada simulada: cada chamada "custa" uma requisição
BANCO = [f"pedido-{i}" for i in range(1, 8)]
chamadas: Dict[str, int] = {"total": 0}

def buscar_pagina(pagina: int, tamanho: int = 3) -> List[str]:
    chamadas["total"] += 1
    inicio = pagina * tamanho
    return BANCO[inicio:inicio + tamanho]

def todos_os_pedidos() -> Iterator[str]:
    pagina = 0
    while True:
        lote = buscar_pagina(pagina)
        if not lote:
            return
        yield from lote
        pagina += 1

for pedido in todos_os_pedidos():
    if pedido == "pedido-2":
        break
print("requisições feitas:", chamadas["total"])
```

```javascript
    this.arquivos = [];
    this.subpastas = [];

      const [pasta, caminho] = pilha.pop();
```

```java
class Pasta {
    final String nome;
    List<String> arquivos = new ArrayList<>();
    List<Pasta> subpastas = new ArrayList<>();

    Pasta(String nome) {
        this.nome = nome;
    }

    // Iterador preguiçoso: só calcula o próximo caminho quando pedem.
    Iterator<String> caminhar() {
        final Deque<Pasta> pilhaPastas = new ArrayDeque<>();
        final Deque<String> pilhaCaminhos = new ArrayDeque<>();
        final Deque<String> pendentes = new ArrayDeque<>();
        pilhaPastas.push(this);
        pilhaCaminhos.push(nome);
        return new Iterator<String>() {
            public boolean hasNext() {
                while (pendentes.isEmpty() && !pilhaPastas.isEmpty()) {
                    Pasta pasta = pilhaPastas.pop();
                    String caminho = pilhaCaminhos.pop();
                    for (String arquivo : pasta.arquivos) pendentes.addLast(caminho + "/" + arquivo);
                    for (int i = pasta.subpastas.size() - 1; i >= 0; i--) {
                        Pasta sub = pasta.subpastas.get(i);
                        pilhaPastas.push(sub);
                        pilhaCaminhos.push(caminho + "/" + sub.nome);
                    }
                }
                return !pendentes.isEmpty();
            }

            public String next() {
                if (!hasNext()) throw new NoSuchElementException();
                return pendentes.removeFirst();
            }
        };
    }
}

    totalChamadas++;
    int inicio = Math.min(pagina * tamanho, BANCO.size());
    int fim = Math.min(inicio + tamanho, BANCO.size());
    return BANCO.subList(inicio, fim);
}

static Iterator<String> todosOsPedidos() {
    return new Iterator<String>() {
        int pagina = 0;
        Iterator<String> lote = Collections.emptyIterator();
        boolean acabou = false;

        public boolean hasNext() {
            while (!lote.hasNext() && !acabou) {
                List<String> proximoLote = buscarPagina(pagina, 3);
                if (proximoLote.isEmpty()) {
                    acabou = true;
                } else {
                    lote = proximoLote.iterator();
                    pagina++;
                }
            }
            return lote.hasNext();
        }

        public String next() {
            if (!hasNext()) throw new NoSuchElementException();
            return lote.next();
        }
    };
}
```

## Quando usar e quando evitar

**Use quando:**

- A coleção tem estrutura interna que você não quer expor (árvore, grafo, paginação, stream).
- Você precisa de múltiplos percursos sobre os mesmos dados.
- Os dados são grandes ou caros de buscar e você quer processá-los sob demanda.

**Evite (ou não escreva à mão) quando:**

- A coleção é uma lista simples. Devolva a lista ou use `iter()` direto.
- O cliente precisa de acesso aleatório por índice; um iterador só anda para frente.

<Callout type="warning" title="Modificar durante a iteração">
Alterar a coleção enquanto um iterador está ativo gera bugs sutis (itens pulados ou repetidos). Ou você itera sobre uma cópia, ou o iterador detecta a modificação e falha cedo, como fazem os dicionários do Python.
</Callout>

## Padrões parecidos

| Padrão | Como diferenciar |
| --- | --- |
| Composite | Define a estrutura em árvore. O Iterator é a forma de percorrê-la. Os dois aparecem juntos com frequência. |
| Visitor | Também percorre uma estrutura, mas o foco é **executar operações diferentes por tipo de elemento**. O Iterator só entrega elementos, sem saber o que você fará com eles. |
| Factory Method | `__iter__` é, tecnicamente, um factory method que cria o iterador certo para cada coleção. |

## Na entrevista

- Em design de player de música, feed de rede social ou sistema de arquivos, comente: "a coleção expõe um iterador, assim o modo aleatório e o modo repetir são só iteradores diferentes".
- Em Python, mostre que conhece o protocolo (`__iter__`, `__next__`, geradores). Escrever uma classe `Iterator` estilo Java sem necessidade passa a impressão de não conhecer a linguagem.
- Follow-ups comuns: "como iterar um conjunto enorme sem carregar tudo na memória?" (gerador preguiçoso, paginação por cursor), "e se a coleção mudar no meio?" (snapshot ou falha rápida).
