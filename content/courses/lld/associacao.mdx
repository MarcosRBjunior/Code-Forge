**Associação** é a relação mais geral entre duas classes: um objeto **conhece** outro e pode usá-lo de forma duradoura, normalmente guardando uma referência como atributo. Professor conhece suas turmas, motorista conhece o carro que dirige, cliente conhece seus pedidos. Agregação e composição, que você verá a seguir, são formas especializadas de associação.

## O que caracteriza uma associação

- A referência é **estrutural**: fica guardada num atributo, não só passada como parâmetro de um método.
- Os dois objetos têm **ciclos de vida independentes**: um pode existir sem o outro.
- Nenhum dos dois é "dono" do outro.

Em UML, a associação é desenhada como uma linha simples entre as classes, opcionalmente com seta (direção) e multiplicidade.

```text
Medico ───────────── Paciente
        1..*    0..*
```

## Direção

| Tipo | Significado | Exemplo |
| --- | --- | --- |
| Unidirecional | só um lado conhece o outro | `Pedido` conhece `Cliente`, mas `Cliente` não guarda pedidos |
| Bidirecional | os dois lados se conhecem | `Medico` lista pacientes e `Paciente` lista médicos |

Prefira unidirecional sempre que possível. Associação bidirecional exige manter os dois lados sincronizados, o que é fonte frequente de bugs.

## Multiplicidade

Indica quantos objetos de um lado se relacionam com o outro:

- **1 para 1:** pessoa e passaporte vigente.
- **1 para muitos:** autor e posts.
- **Muitos para muitos:** alunos e disciplinas.

## Exemplo: médicos e pacientes (muitos para muitos, bidirecional)

<CodeTabs>

```python
class Paciente:
    def __init__(self, nome: str) -> None:
        self.nome = nome
        self._medicos: list["Medico"] = []

    @property
    def medicos(self) -> tuple["Medico", ...]:
        return tuple(self._medicos)

    def _vincular(self, medico: "Medico") -> None:
        if medico not in self._medicos:
            self._medicos.append(medico)


class Medico:
    def __init__(self, nome: str, especialidade: str) -> None:
        self.nome = nome
        self.especialidade = especialidade
        self._pacientes: list[Paciente] = []

    @property
    def pacientes(self) -> tuple[Paciente, ...]:
        return tuple(self._pacientes)

    def atender(self, paciente: Paciente) -> None:
        if paciente not in self._pacientes:
            self._pacientes.append(paciente)
        paciente._vincular(self)  # mantém os dois lados coerentes


helena = Medico("Helena", "cardiologia")
otavio = Medico("Otávio", "ortopedia")
joao = Paciente("João")

helena.atender(joao)
otavio.atender(joao)
print([m.nome for m in joao.medicos])          # ['Helena', 'Otávio']
print([p.nome for p in helena.pacientes])      # ['João']

del helena  # o paciente continua existindo; ciclos de vida independentes
print(joao.nome)
```

class Paciente {
  #medicos = [];

  constructor(nome) { this.nome = nome; }

  get medicos() { return Object.freeze([...this.#medicos]); }

  _vincular(medico) {
    if (!this.#medicos.includes(medico)) this.#medicos.push(medico);
  }
}

  #pacientes = [];

  constructor(nome, especialidade) {
    this.nome = nome;
    this.especialidade = especialidade;

  get pacientes() { return Object.freeze([...this.#pacientes]); }

    if (!this.#pacientes.includes(paciente)) this.#pacientes.push(paciente);

  }
}

import java.util.*;

class Paciente {
    final String nome;
    private final List<Medico> medicos = new ArrayList<>();

    List<Medico> medicos() { return Collections.unmodifiableList(medicos); }

```cpp
#include <algorithm>
#include <iostream>
#include <memory>
#include <string>
#include <vector>
using namespace std;

class Medico;

class Paciente {
    vector<weak_ptr<Medico>> medicos_;

public:
    string nome;

    Paciente(string nome) : nome(nome) {}

    vector<shared_ptr<Medico>> medicos() const {
        vector<shared_ptr<Medico>> saida;
        for (const auto& m : medicos_) if (auto p = m.lock()) saida.push_back(p);
        return saida;
    }

    void vincular(const shared_ptr<Medico>& medico) {
        for (const auto& m : medicos_) if (m.lock() == medico) return;
        medicos_.push_back(medico);
    }
};

class Medico : public enable_shared_from_this<Medico> {
    vector<shared_ptr<Paciente>> pacientes_;

public:
    string nome, especialidade;

    Medico(string nome, string especialidade) : nome(nome), especialidade(especialidade) {}

    const vector<shared_ptr<Paciente>>& pacientes() const { return pacientes_; }

    void atender(const shared_ptr<Paciente>& paciente) {
        if (find(pacientes_.begin(), pacientes_.end(), paciente) == pacientes_.end()) pacientes_.push_back(paciente);
        paciente->vincular(shared_from_this());   // mantém os dois lados coerentes
    }
};

int main() {
    auto helena = make_shared<Medico>("Helena", "cardiologia");
    auto otavio = make_shared<Medico>("Otávio", "ortopedia");
    auto joao = make_shared<Paciente>("João");

    helena->atender(joao);
    otavio->atender(joao);
    cout << "[";
    auto ms = joao->medicos();
    for (size_t i = 0; i < ms.size(); i++) cout << (i ? ", " : "") << ms[i]->nome;
    cout << "]" << endl;          // [Helena, Otávio]
    cout << "[";
    for (size_t i = 0; i < helena->pacientes().size(); i++) cout << (i ? ", " : "") << helena->pacientes()[i]->nome;
    cout << "]" << endl;          // [João]

    helena.reset();   // o paciente continua existindo; ciclos de vida independentes
    cout << joao->nome << endl;
}
```

```go
import "fmt"

type Paciente struct {
	nome    string
	medicos []*Medico
}

func (p *Paciente) vincular(m *Medico) {
	for _, x := range p.medicos {
		if x == m {
			return
		}
	}
	p.medicos = append(p.medicos, m)
}

type Medico struct {
	nome          string
	especialidade string
	pacientes     []*Paciente
}

func (m *Medico) atender(p *Paciente) {
	ja := false
	for _, x := range m.pacientes {
		if x == p {
			ja = true
		}
	}
	if !ja {
		m.pacientes = append(m.pacientes, p)
	}
	p.vincular(m) // mantém os dois lados coerentes
}

func main() {
	helena := &Medico{nome: "Helena", especialidade: "cardiologia"}
	otavio := &Medico{nome: "Otávio", especialidade: "ortopedia"}
	joao := &Paciente{nome: "João"}

	helena.atender(joao)
	otavio.atender(joao)
	nomesM := []string{}
	for _, m := range joao.medicos {
		nomesM = append(nomesM, m.nome)
	}
	fmt.Println(nomesM) // [Helena Otávio]
	nomesP := []string{}
	for _, p := range helena.pacientes {
		nomesP = append(nomesP, p.nome)
	}
	fmt.Println(nomesP) // [João]

	helena = nil // o paciente continua existindo; ciclos de vida independentes
	fmt.Println(joao.nome)
}
```

</CodeTabs>

Repare em três decisões:

1. Só `Medico.atender` cria o vínculo, e ele mesmo atualiza o outro lado. Assim não há como ficar com uma ponta só.
2. As coleções são expostas como tuplas, impedindo alterações externas.
3. Nenhum construtor recebe o outro objeto: médicos e pacientes existem sozinhos.

## Associação vs dependência

Uma confusão comum: se uma classe só recebe outra como parâmetro de um método e não guarda a referência, isso é **dependência**, não associação. Associação implica referência duradoura no estado do objeto.

<Callout type="tip" title="Associação com atributos próprios">
Quando a relação tem dados (data da matrícula, nota final), crie uma classe para ela, como `Matricula` ligando `Aluno` e `Disciplina`. Isso simplifica relações muitos para muitos.
</Callout>

## Armadilhas

- **Bidirecional sem necessidade.** Dobra o trabalho de manutenção e cria referências circulares.
- **Sincronização manual espalhada.** Se qualquer código pode fazer `medico._pacientes.append`, os lados divergem.
- **Navegação profunda.** `pedido.cliente.endereco.cidade.estado` acopla o chamador a toda a cadeia (veja a Lei de Demeter).

## Na entrevista

Ao listar entidades, descreva as associações com direção e multiplicidade: "um `Andar` tem várias `Vagas`; a vaga conhece seu andar, mas não precisa". Follow-ups comuns: "por que unidirecional?", "como modelar muitos para muitos com dados extras?", "qual a diferença entre associação e agregação?".
