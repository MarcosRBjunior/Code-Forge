**Encapsulamento** é esconder o estado interno de um objeto e permitir que ele seja alterado só por meio de operações que respeitam suas regras. Não é sobre segredo; é sobre **proteger invariantes**: condições que precisam ser sempre verdadeiras, como "o estoque nunca fica negativo" ou "a soma dos itens bate com o total".

## O problema: estado exposto

Como o dicionário é público, a regra "não pode ficar negativo" precisaria ser repetida em todo lugar que mexe nele. Basta um ponto esquecer para o sistema ficar inconsistente. E se amanhã você quiser trocar o dicionário por outra estrutura, todos os chamadores quebram.

## Como encapsular em Python

Python não tem `private` como Java. Usa convenções:

| Notação | Significado |
| --- | --- |
| `nome` | público, parte do contrato |
| `_nome` | interno; "não mexa de fora" por convenção |
| `__nome` | name mangling: vira `_Classe__nome`, evita colisão em subclasses |

O mecanismo real de proteção é oferecer **métodos e propriedades** que validam, e não expor a estrutura crua:

<CodeTabs>

```python
class Estoque:
    def __init__(self) -> None:
        self._quantidades: dict[str, int] = {}

    def entrada(self, produto: str, qtd: int) -> None:
        if qtd <= 0:
            raise ValueError("quantidade deve ser positiva")
        self._quantidades[produto] = self._quantidades.get(produto, 0) + qtd

    def saida(self, produto: str, qtd: int) -> None:
        disponivel = self._quantidades.get(produto, 0)
        if qtd > disponivel:
            raise ValueError(f"só há {disponivel} de {produto}")
        self._quantidades[produto] = disponivel - qtd

    def quantidade(self, produto: str) -> int:
        return self._quantidades.get(produto, 0)

    def produtos(self) -> dict[str, int]:
        return dict(self._quantidades)  # cópia: o chamador não altera o original


estoque = Estoque()
estoque.entrada("caneta", 5)
try:
    estoque.saida("caneta", 8)
except ValueError as e:
    print(e)  # só há 5 de caneta
copia = estoque.produtos()
copia["caneta"] = 999
print(estoque.quantidade("caneta"))  # 5, o original ficou intacto
```

```cpp
#include <iostream>
#include <map>
#include <stdexcept>
#include <string>
using namespace std;

class Estoque {
    map<string, int> quantidades;

public:
    void entrada(const string& produto, int qtd) {
        if (qtd <= 0) throw invalid_argument("quantidade deve ser positiva");
        quantidades[produto] += qtd;
    }

    void saida(const string& produto, int qtd) {
        int disponivel = quantidades.count(produto) ? quantidades[produto] : 0;
        if (qtd > disponivel) throw invalid_argument("só há " + to_string(disponivel) + " de " + produto);
        quantidades[produto] = disponivel - qtd;
    }

    int quantidade(const string& produto) const {
        auto it = quantidades.find(produto);
        return it == quantidades.end() ? 0 : it->second;
    }

    map<string, int> produtos() const { return quantidades; } // cópia: o chamador não altera o original
};

int main() {
    Estoque estoque;
    estoque.entrada("caneta", 5);
    try {
        estoque.saida("caneta", 8);
    } catch (const invalid_argument& e) {
        cout << e.what() << endl; // só há 5 de caneta
    }
    auto copia = estoque.produtos();
    copia["caneta"] = 999;
    cout << estoque.quantidade("caneta") << endl; // 5, o original ficou intacto
```

```go
import (
	"fmt"
)

type Estoque struct {
	quantidades map[string]int
}

func NovoEstoque() *Estoque { return &Estoque{quantidades: map[string]int{}} }

func (e *Estoque) entrada(produto string, qtd int) error {
	if qtd <= 0 {
		return fmt.Errorf("quantidade deve ser positiva")
	}
	e.quantidades[produto] += qtd
	return nil
}

func (e *Estoque) saida(produto string, qtd int) error {
	disponivel := e.quantidades[produto]
	if qtd > disponivel {
		return fmt.Errorf("só há %d de %s", disponivel, produto)
	}
	e.quantidades[produto] = disponivel - qtd
	return nil
}

func (e *Estoque) quantidade(produto string) int { return e.quantidades[produto] }

func (e *Estoque) produtos() map[string]int {
	copia := make(map[string]int, len(e.quantidades))
	for k, v := range e.quantidades { // cópia: o chamador não altera o original
		copia[k] = v
	}
	return copia
}

func main() {
	estoque := NovoEstoque()
	estoque.entrada("caneta", 5)
	if err := estoque.saida("caneta", 8); err != nil {
		fmt.Println(err) // só há 5 de caneta
	}
	copia := estoque.produtos()
	copia["caneta"] = 999
	fmt.Println(estoque.quantidade("caneta")) // 5, o original ficou intacto
}
```

Repare em `produtos()`: devolver o dicionário interno diretamente vazaria o estado. Devolver uma cópia mantém o controle.

## Propriedades: validação com sintaxe de atributo

`@property` permite expor um valor como atributo e ainda assim validar escritas:

<CodeTabs>

```python
class Termostato:
    MIN, MAX = 10.0, 32.0

    def __init__(self, alvo: float) -> None:
        self.alvo = alvo  # passa pelo setter

    @property
    def alvo(self) -> float:
        return self._alvo

    @alvo.setter
    def alvo(self, valor: float) -> None:
        if not self.MIN <= valor <= self.MAX:
            raise ValueError(f"alvo fora da faixa {self.MIN}-{self.MAX}")
        self._alvo = valor


t = Termostato(22)
t.alvo = 25
print(t.alvo)  # 25
try:
    t.alvo = 40
except ValueError as e:
    print(e)
```

```javascript
class Termostato {
  static MIN = 10;
  static MAX = 32;
  #alvo;

  constructor(alvo) {
    this.alvo = alvo; // passa pelo setter
  }

  get alvo() {
    return this.#alvo;
  }

  set alvo(valor) {
    if (!(Termostato.MIN <= valor && valor <= Termostato.MAX)) {
      throw new RangeError(`alvo fora da faixa ${Termostato.MIN}-${Termostato.MAX}`);
    }
    this.#alvo = valor;
  }
}

t.alvo = 25;
console.log(t.alvo); // 25
try {
  t.alvo = 40;
} catch (e) {
  console.log(e.message);
}
```

```go
)

	minimo = 10.0
	maximo = 32.0
)
```

## Encapsular comportamento, não só dados

Encapsulamento bom esconde **decisões**, não apenas campos. Prefira "diga o que fazer" a "pergunte e decida fora":

```text
Ruim:  if conta.saldo >= valor: conta.saldo -= valor
Bom:   conta.sacar(valor)
```

No primeiro caso a regra de saque vive no chamador. No segundo, vive na conta, que é dona dos dados.

## Armadilhas

- **Getter e setter para tudo.** Criar `get_saldo` e `set_saldo` sem validação é expor o atributo com mais cerimônia. Pergunte se o setter deveria existir.
- **Vazar coleções mutáveis.** Retornar a lista interna permite `obj.itens().clear()`. Retorne cópia, tupla ou um iterador.
- **Confiar em `__` como segurança.** Name mangling evita acidentes, não impede acesso intencional.

<Callout type="tip" title="Pergunte pela invariante">
Para decidir o que encapsular, liste as regras que o objeto deve garantir. Cada caminho que pode alterar o estado precisa passar por um método que verifica essas regras.
</Callout>
