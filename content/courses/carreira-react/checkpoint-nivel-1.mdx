O Nível 1 reescreveu a Quitanda em React. O site de HTML, CSS e JavaScript puro da Base virou uma SPA com Vite e React 19: catálogo montado a partir de componentes, carrinho com `useReducer` e depois Redux Toolkit, páginas com React Router 7, dados vindos do `json-server` por TanStack Query e GraphQL, checkout validado com React Hook Form e Zod, estilos com CSS Modules ou Tailwind, os primeiros testes com Jest e Testing Library e, no fim, o painel legado da Hortaliça Express lido e migrado aos poucos.

Este checkpoint confere se essas peças se encaixam na sua cabeça e no seu código. Você revisa o que cada capítulo pediu, se avalia com habilidades que dá para provar fazendo, monta uma versão da Quitanda de ponta a ponta sem copiar dos capítulos e responde a perguntas e quizzes que misturam o nível inteiro. Se algo travar, a seção final aponta o capítulo certo para revisar antes de seguir para o Nível 2.

## Desafio prático

Você vai reconstruir a Quitanda em React a partir de uma pasta vazia, usando a mesma API do Nível base: `json-server` com o `db.json` de produtos e pedidos, na porta 3000. O objetivo não é repetir os trechos dos capítulos, e sim provar que você sabe ligar as peças: rotas, dados, estado global, formulário e testes conversando entre si.

Escolha uma abordagem de estilo (CSS Modules ou Tailwind) e fique com ela. GraphQL e o painel legado ficam como extras opcionais no fim.

### Requisitos

1. **Projeto e API.** Crie o projeto com Vite e React 19, configure o proxy do Vite para que `/api` chegue ao `json-server` e isole a leitura de `import.meta.env` num módulo `src/ambiente.js`.
2. **Camada de serviço.** Em `src/servicos/`, um cliente HTTP que confere `response.ok`, lança um erro com o status e expõe funções de domínio: `listarProdutos`, `buscarProduto`, `criarPedido`, `buscarPedido` e `alterarStatus`.
3. **Rotas.** Com o modo de dados do React Router 7: catálogo em `/`, detalhe em `/produtos/:id`, carrinho, checkout, acompanhamento em `/pedidos/:id`, painel do lojista protegido e uma página 404. Um `Layout` com `Outlet` mostra o cabeçalho com o mini carrinho em todas as páginas.
4. **Catálogo com filtros na URL.** Busca por nome e filtro por categoria guardados na query string. Recarregar a página ou compartilhar o link mantém o filtro.
5. **Carrinho global.** Um slice do Redux Toolkit com `adicionou`, `alterouQuantidade`, `removeu` e `esvaziou`, que nunca deixa a quantidade passar do estoque. O total vem de um seletor memorizado, e o carrinho é salvo no `localStorage` e restaurado ao abrir a loja.
6. **Checkout validado.** Formulário com React Hook Form e um esquema Zod criado a partir do total: nome, e-mail, telefone, CEP, número, forma de pagamento e troco obrigatório e suficiente quando o pagamento for dinheiro. Ao enviar, o pedido é gravado na API, o carrinho é esvaziado e o cliente vai para `/pedidos/:id`.
7. **Acompanhamento e painel.** A página do pedido usa `useQuery` com estados de carregamento e erro explícitos. No painel, o lojista altera o status com `useMutation`, e a lista e o detalhe se atualizam pela invalidação, sem recarregar a página.
8. **Estilo e acessibilidade.** Estilos com escopo por componente, um selo de estoque com variantes (disponível, últimas unidades, esgotado) e todos os campos do checkout com rótulo associado e erro anunciado.
9. **Testes.** Jest e Testing Library configurados, com pelo menos: testes do slice do carrinho, um teste de `formatarPreco`, um teste de componente que adiciona um produto e confere o mini carrinho e um teste do checkout que cobre um erro de validação e um envio bem-sucedido com o serviço mockado.
10. **Extra opcional.** Refaça a tela de pedidos do painel com Apollo Client e um fragment, ou pegue um componente de classe do capítulo de código legado, escreva um teste de caracterização e migre-o para hooks com o teste passando antes e depois.

Uma estrutura de pastas que costuma funcionar bem para este tamanho de projeto:

```text
src/
├── ambiente.js          # única leitura de import.meta.env
├── main.jsx             # providers: store, QueryClient, roteador
├── rotas.jsx
├── servicos/            # api.js, produtos.js, pedidos.js
├── estado/              # store.js, carrinhoSlice.js
├── esquemas/            # checkout.js (Zod)
├── paginas/             # Layout, Catalogo, PaginaProduto, Checkout...
├── componentes/         # CartaoProduto, MiniCarrinho, SeloEstoque, Campo
├── utilidades/          # formatarPreco.js, cn.js
└── testes/              # renderizar.jsx e mocks
```

Um esqueleto de partida para o arquivo de rotas:

```jsx
// src/rotas.jsx
import { createBrowserRouter } from "react-router";
import Layout from "./paginas/Layout.jsx";
import PaginaDeErro from "./paginas/PaginaDeErro.jsx";

export const roteador = createBrowserRouter([
  {
    path: "/",
    element: <Layout />,
    errorElement: <PaginaDeErro />,
    children: [
      // index: catálogo com loader
      // produtos/:id, carrinho, checkout (action ou React Hook Form)
      // pedidos/:id, painel (protegido), entrar
      { path: "*", element: <p>Página não encontrada.</p> },
    ],
  },
]);
```

### Critérios de aceite

- `npx json-server db.json --port 3000` e `npm run dev` rodando juntos, sem erro de CORS no console: todas as chamadas passam por `/api`.
- Abrir `/?categoria=frutas&q=banana` direto na barra de endereços mostra o catálogo já filtrado, e o botão voltar desfaz o filtro.
- Recarregar `/produtos/2` não dá 404 no servidor de desenvolvimento, e um id inexistente mostra a página de erro da rota, não uma tela branca.
- Clicar em "Adicionar" mais vezes do que o estoque permite não aumenta a quantidade, e recarregar a página mantém o carrinho.
- Enviar o checkout vazio mostra uma mensagem em cada campo obrigatório e move o foco para o primeiro erro. Escolher dinheiro com troco menor que o total impede o envio.
- Depois de finalizar, o pedido aparece no `db.json` e no painel. Alterar o status no painel atualiza a página do pedido sem recarregar.
- `npm test` passa com pelo menos quatro arquivos de teste, e nenhum teste consulta elemento por classe CSS ou `data-testid` quando existe papel ou rótulo acessível.
- O React DevTools não mostra o catálogo inteiro renderizando a cada tecla digitada no campo de e-mail do checkout.

### Dicas

- Comece pela camada de serviço e pelas rotas, com páginas vazias. Dados e navegação funcionando primeiro tornam o resto incremental. Revise [as rotas da Quitanda](/learn/carreira-react/react-spas-react-router) e [a camada de serviço](/learn/carreira-react/react-consumindo-apis-http).
- O `fetch` não rejeita em 404 nem em 500. Se o erro não aparece na tela, confira se o cliente HTTP testa `response.ok`.
- Não guarde a lista de produtos no Redux. Dados da API são estado de servidor e ficam com o TanStack Query; o Redux guarda só o carrinho. O critério está em [Redux e Context API](/learn/carreira-react/react-redux-context-api).
- Para persistir o carrinho, assine a store (`store.subscribe`) e grave no `localStorage`; para restaurar, passe o estado salvo como `preloadedState`. Não leia o `localStorage` dentro do reducer.
- O esquema do checkout é uma função porque depende do total. Crie-o com `useMemo` a partir do total do carrinho, como em [frameworks e validação de formulários](/learn/carreira-react/react-frameworks-bibliotecas-interfaces-validacao-formularios).
- No Jest, `import.meta.env` e os arquivos `.css` quebram a execução. O `moduleNameMapper` e o módulo `ambiente.js` de [primeiros testes](/learn/carreira-react/react-primeiros-testes-jest-testing-library) resolvem os dois.
- Para testar componentes que usam a store e o roteador, escreva um utilitário `renderizar` que embrulha o componente nos providers. Você vai reaproveitá-lo no Nível 2.

## Revisão rápida

**Estado é imutável.** O React compara referências. Mutar o array mantém a mesma referência e a tela não muda. Crie sempre um valor novo.

```jsx
// src/App.jsx (trecho)
setItens((atuais) => atuais.map((i) => (i.produto.id === id ? { ...i, quantidade: i.quantidade + 1 } : i)));
```

**Atualizações em sequência usam a forma funcional.** Três chamadas `setContador(contador + 1)` no mesmo evento leem o mesmo valor e somam um. Com `setContador((c) => c + 1)`, cada chamada recebe o valor anterior.

**Key estável, nunca o índice em listas que mudam.** Com o índice como `key`, filtrar ou reordenar o catálogo faz o React reaproveitar o estado do item errado, como a quantidade escolhida num seletor.

```jsx
// src/componentes/ListaDeProdutos.jsx (trecho)
{produtos.map((produto) => (
  <CartaoProduto key={produto.id} produto={produto} />
))}
```

**Efeito é para sincronizar com fora do React.** Total do carrinho, lista filtrada e mensagens de erro derivadas são cálculos durante a renderização. Gravar no `localStorage`, assinar um evento da janela ou abrir uma conexão são efeitos, e cada um precisa de limpeza quando configura algo.

```jsx
// src/componentes/Busca.jsx (trecho)
useEffect(() => {
  function aoTeclar(evento) {
    if (evento.key === "/") campo.current?.focus();
  }
  window.addEventListener("keydown", aoTeclar);
  return () => window.removeEventListener("keydown", aoTeclar);
}, []);
```

**Estado de servidor não é estado de interface.** Produtos e pedidos são cópias de dados que vivem na API: ficam velhos, precisam de cache e de invalidação. Por isso vão para o TanStack Query, não para `useState` nem para o Redux.

```js
// src/componentes/AlterarStatus.jsx (trecho)
const cliente = useQueryClient();
const mutacao = useMutation({
  mutationFn: alterarStatus,
  onSuccess: () => cliente.invalidateQueries({ queryKey: ["pedidos"] }),
});
```

**Seletor que cria objeto novo renderiza sempre.** `useSelector` renderiza de novo quando o valor muda de referência. Um seletor que faz `filter` ou devolve um objeto literal produz um valor novo a cada ação; use `createSelector` ou selecione valores primitivos.

```js
// src/estado/carrinhoSlice.js (trecho)
export const selecionarTotal = createSelector([selecionarItens], (itens) =>
  itens.reduce((soma, i) => soma + i.produto.precoEmCentavos * i.quantidade, 0),
);
```

**Filtro na URL, não no estado.** Busca e categoria em `useSearchParams` tornam o link compartilhável e fazem o botão voltar funcionar. Em `useState`, somem no recarregamento.

**A action do formulário recebe o estado anterior.** Com `useActionState`, a função de envio recebe primeiro o estado anterior e depois o `FormData`, e o que ela devolve vira o próximo estado. Esquecer o primeiro parâmetro é o erro mais comum.

```jsx
// src/componentes/AviseMe.jsx (trecho)
async function cadastrar(estadoAnterior, dados) {
  const email = dados.get("email");
  if (!email.includes("@")) return { erro: "Informe um e-mail válido." };
  await inscreverAviso(email);
  return { sucesso: true };
}

const [estado, acao, pendente] = useActionState(cadastrar, {});
```

**Teste o que o usuário vê.** `getByRole("button", { name: /adicionar/i })` encontra o botão como um leitor de tela encontraria. Se a consulta falha, muitas vezes o problema é de acessibilidade, não do teste.

<Callout type="warning" title="Context não é cache de dados">
Um erro comum ao fim do Nível 1 é criar um `ProdutosContext` com `useEffect` e `fetch` e espalhar a lista pela aplicação. Toda mudança no `value` renderiza todos os consumidores, e você reimplementa à mão cache, revalidação e tratamento de erro. Use Context para valores que mudam pouco (tema, usuário) e o TanStack Query para dados da API.
</Callout>

## Na entrevista

**O que acontece quando o estado de um componente muda?** O React agenda uma nova renderização, chama o componente de novo para obter a descrição atualizada da interface, compara com a anterior e aplica no DOM só o que mudou. Os filhos renderizam junto, a menos que sejam memorizados.

**Quando você usaria useReducer em vez de useState?** Quando o estado tem várias partes relacionadas e várias formas de mudar com regras entre elas, como o carrinho com limite de estoque. O reducer concentra as regras numa função pura, fácil de testar.

**Por que guardar os filtros do catálogo na URL?** Porque o link fica compartilhável, sobrevive ao recarregamento e o histórico do navegador funciona como o usuário espera. Estado local some quando a página recarrega.

**Redux ou TanStack Query para os produtos?** TanStack Query. Produtos são estado de servidor, com cache, revalidação e invalidação, que a biblioteca já resolve. O Redux fica com estado de cliente compartilhado, como o carrinho.

**Por que o fetch não lançou erro quando a API respondeu 500?** Porque para o `fetch` qualquer resposta HTTP é um sucesso; a promise só rejeita em falha de rede ou cancelamento. A camada de serviço precisa conferir `response.ok` e lançar.

**Como você valida um formulário que tem regra entre campos?** Com um esquema Zod e `refine` com `path`, que atribui o erro ao campo certo, como o troco que precisa cobrir o total. O esquema é testado isoladamente e pode ser reaproveitado no servidor.

**Como você testaria o botão Adicionar do cartão de produto?** Renderizo com os providers reais (store e roteador), encontro o botão por papel e nome, clico com `user-event` e confiro o efeito visível, como o contador do mini carrinho, sem olhar estado interno.

**Como você começaria a migrar um componente de classe?** Escrevo testes de caracterização com Testing Library, que não se importam se o componente é classe ou função, e só então traduzo o estado para `useState` e os métodos de ciclo de vida para `useEffect`, com o teste passando antes e depois.

## Se travou, revise

- Não consegui atualizar o carrinho sem mutar o array, ou a tela não muda depois do clique: [React 19: JSX, componentes, form action e useState](/learn/carreira-react/react-19-jsx-componentes-form-action-usestate).
- Não consegui decidir entre efeito e cálculo, ou o carrinho não persiste no `localStorage`: [hooks para gerenciar estados](/learn/carreira-react/react-hooks-gerenciar-estados).
- Uma classe do Tailwind montada por interpolação não aparece, ou o estilo de um componente vazou para outro: [CSS Modules e Tailwind](/learn/carreira-react/react-css-modules-tailwind).
- Não consegui fazer o filtro sobreviver ao recarregamento, ou a rota protegida e a página de erro não funcionam: [SPAs com React Router](/learn/carreira-react/react-spas-react-router).
- O erro da API não aparece na tela, ou a lista não atualiza depois de alterar o status: [consumindo APIs HTTP](/learn/carreira-react/react-consumindo-apis-http).
- Não entendi por que a mutation do Apollo atualizou o detalhe mas não a lista: [GraphQL para integração de dados](/learn/carreira-react/react-graphql-integracao-dados).
- O mini carrinho renderiza a cada ação qualquer, ou não sei onde guardar cada estado: [Redux e Context API](/learn/carreira-react/react-redux-context-api).
- O erro do troco aparece no lugar errado, ou o leitor de tela não anuncia os erros: [frameworks e validação de formulários](/learn/carreira-react/react-frameworks-bibliotecas-interfaces-validacao-formularios).
- O Jest falha com `import.meta`, CSS ou `TextEncoder`: [primeiros testes com Jest e Testing Library](/learn/carreira-react/react-primeiros-testes-jest-testing-library).
- Não consegui traduzir o ciclo de vida de uma classe para hooks: [interpretando código legado](/learn/carreira-react/react-interpretando-codigo-legado).

<Callout type="tip" title="Guarde o desafio">
Faça o desafio num repositório próprio, com commits pequenos e um README curto explicando as decisões (por que Tailwind ou CSS Modules, por que TanStack Query para pedidos). O Nível 2 começa migrando exatamente esse código para TypeScript, e ter a sua versão em mãos deixa a migração muito mais concreta.
</Callout>
