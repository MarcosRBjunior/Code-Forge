A maior parte dos pedidos da Quitanda vai sair de um celular: alguém no ônibus lembrando que acabou a banana, outra pessoa no intervalo do trabalho montando a feira da semana. A vitrine e o checkout que você escreveu até aqui foram pensados numa tela de notebook. No celular, o menu estoura a largura, os cards ficam espremidos e o resumo do pedido aparece longe do botão de confirmar.

Responsividade não é encolher a página de desktop. É desenhar o layout a partir da menor tela e acrescentar colunas e detalhes conforme o espaço aumenta. Este capítulo reescreve a vitrine em CSS Grid, monta o checkout com áreas nomeadas, troca pixels fixos por unidades relativas, serve a foto do tamanho certo para cada tela e usa container queries para o card de produto se adaptar ao espaço que recebe, onde quer que esteja.

**Você vai aprender:**

- Pensar mobile first e escrever media queries com `min-width`
- Montar grades com CSS Grid, `auto-fill`, `minmax` e áreas nomeadas
- Escolher entre `px`, `rem`, `em`, `%`, `vw`, `dvh` e usar `clamp()` para tipografia fluida
- Servir imagens responsivas com `srcset`, `sizes`, `picture` e carregamento preguiçoso
- Usar container queries para componentes que se adaptam ao próprio espaço
- Testar no modo de dispositivo das DevTools e em aparelhos reais

## Viewport e mobile first

A meta `viewport` do capítulo anterior é pré-requisito: sem ela, o navegador do celular renderiza a página como se tivesse cerca de 980px e depois a reduz.

**Mobile first** significa escrever o CSS base para a tela pequena e usar media queries com `min-width` para acrescentar o que telas maiores comportam:

```css
/* estilos.css */
/* base: celular, uma coluna */
.lista-produtos {
  display: grid;
  gap: 1rem;
}

/* a partir de 600px: duas colunas */
@media (min-width: 600px) {
  .lista-produtos {
    grid-template-columns: repeat(2, 1fr);
  }
}

/* a partir de 1024px: quatro colunas */
@media (min-width: 1024px) {
  .lista-produtos {
    grid-template-columns: repeat(4, 1fr);
  }
}
```

Por que começar do pequeno:

- O layout de uma coluna é o mais simples; cada media query **adiciona** complexidade em vez de desfazer.
- O celular recebe menos CSS sobrescrito e menos trabalho de layout, justamente no aparelho mais fraco.
- Força a priorizar: se só cabe uma coisa, o que é? Na Quitanda, a busca e o botão de adicionar.

Escolha os breakpoints pelo **conteúdo**, não por modelos de aparelho. Estique a janela devagar e, quando o layout começar a parecer ruim, ali vai uma media query. Valores em `em` (`min-width: 40em`) respeitam o zoom de texto do usuário melhor que `px` em alguns navegadores; os dois funcionam.

### Outras media features úteis

| Media query | Quando aplica | Uso na Quitanda |
|---|---|---|
| `(min-width: 768px)` | Largura do viewport a partir de 768px | Layout em colunas |
| `(orientation: landscape)` | Tela deitada | Raro; prefira largura |
| `(hover: hover)` | Dispositivo com mouse | Efeitos de hover só onde existe hover |
| `(prefers-color-scheme: dark)` | Sistema em modo escuro | Tema escuro com as mesmas variáveis |
| `(prefers-reduced-motion: reduce)` | Usuário pediu menos animação | Desligar transições |

```css
/* estilos.css */
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    transition: none !important;
    animation: none !important;
  }
}

@media (prefers-color-scheme: dark) {
  :root {
    --cor-texto: #e8eaed;
    --cor-fundo: #121412;
    --cor-superficie: #1e221e;
  }
}
```

As variáveis do capítulo anterior pagam o investimento aqui: o tema escuro é só redefinir as cores.

## CSS Grid

Flexbox organiza itens em uma dimensão. **Grid** organiza em duas, linhas e colunas ao mesmo tempo, e é a ferramenta natural para a vitrine e para o esqueleto das páginas.

| Propriedade | O que faz |
|---|---|
| `grid-template-columns` | Define as colunas: `200px 1fr`, `repeat(3, 1fr)` |
| `grid-template-rows` | Define as linhas |
| `gap` | Espaço entre células |
| `grid-template-areas` | Desenha o layout com nomes |
| `grid-column`, `grid-row` | Posição e extensão de um item: `grid-column: 1 / -1` ocupa a linha toda |
| `place-items` | Alinha o conteúdo das células |

A unidade `fr` divide o espaço que sobra: `1fr 2fr` dá um terço e dois terços.

### A vitrine sem media query

A combinação mais usada do Grid gera quantas colunas couberem, sem nenhum breakpoint:

```css
/* estilos.css */
.lista-produtos {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(min(100%, 220px), 1fr));
  gap: var(--espaco-3);
  list-style: none;
  padding: 0;
}
```

Leia de dentro para fora: cada coluna tem no mínimo 220px (ou 100% do contêiner, se ele for menor que isso, graças ao `min()`) e no máximo `1fr`; `repeat(auto-fill, ...)` cria tantas colunas quantas couberem. No celular, uma; num tablet, três; num monitor largo, cinco. E, ao contrário do `flex-wrap` do capítulo anterior, a última linha mantém a largura das demais.

| | `auto-fill` | `auto-fit` |
|---|---|---|
| Poucos itens numa tela larga | Mantém colunas vazias, cards com largura normal | Colapsa as vazias, cards esticam |
| Uso típico | Vitrines e galerias | Quando poucos itens devem ocupar tudo |

### O checkout com áreas nomeadas

No celular, o checkout é uma pilha: resumo do pedido, formulário, botão. No desktop, formulário à esquerda e resumo fixo à direita.

```html
<!-- checkout.html -->
<main class="pagina-checkout">
  <section class="checkout-formulario">...</section>
  <aside class="checkout-resumo" aria-labelledby="titulo-resumo">
    <h2 id="titulo-resumo">Resumo do pedido</h2>
    ...
  </aside>
</main>
```

```css
/* estilos.css */
.pagina-checkout {
  display: grid;
  gap: var(--espaco-3);
  grid-template-areas:
    "resumo"
    "formulario";
  padding: var(--espaco-2);
}

.checkout-formulario { grid-area: formulario; }
.checkout-resumo { grid-area: resumo; }

@media (min-width: 900px) {
  .pagina-checkout {
    grid-template-columns: 1fr 360px;
    grid-template-areas: "formulario resumo";
    align-items: start;
    max-width: 1200px;
    margin-inline: auto;
  }

  .checkout-resumo {
    position: sticky;
    top: var(--espaco-2);
  }
}
```

O desenho em texto do `grid-template-areas` é lido como um mapa. O `position: sticky` mantém o resumo visível enquanto o formulário rola.

<Callout type="warning" title="A ordem visual deve seguir a ordem do HTML">
Grid e Flexbox permitem reposicionar itens (`order`, `grid-area`), mas o leitor de tela e a tecla Tab seguem a ordem do HTML. Se o resumo aparece primeiro na tela e é o último no código, quem navega pelo teclado se perde. Reordene pouco e confira com Tab.
</Callout>

### Grid ou Flexbox?

| Situação | Ferramenta |
|---|---|
| Itens numa linha, tamanho guiado pelo conteúdo (menu, botões, cabeçalho) | Flexbox |
| Grade de cards alinhados em linhas e colunas | Grid |
| Esqueleto da página (cabeçalho, conteúdo, lateral, rodapé) | Grid |
| Alinhar ícone e texto dentro de um botão | Flexbox |

Os dois convivem: a vitrine é Grid, e cada card por dentro é Flexbox em coluna.

## Unidades relativas

| Unidade | Relativa a | Bom para |
|---|---|---|
| `px` | Pixel de CSS | Bordas, sombras, detalhes finos |
| `rem` | Tamanho de fonte da raiz (16px por padrão) | Fontes, espaçamentos, larguras máximas |
| `em` | Tamanho de fonte do próprio elemento | Padding de botão que acompanha o texto |
| `%` | O contêiner | Larguras fluidas |
| `vw`, `vh` | 1% da largura ou altura do viewport | Seções de tela cheia |
| `dvh`, `svh`, `lvh` | Altura dinâmica, menor e maior do viewport | Altura no celular, onde a barra do navegador aparece e some |
| `ch` | Largura do caractere "0" | Limitar linhas de texto: `max-width: 65ch` |

Prefira `rem` para tamanhos de fonte e espaçamentos. Quem aumenta a fonte padrão do navegador (comum entre pessoas mais velhas, um público real de quitanda) vê a página inteira crescer proporcionalmente; com `px`, a fonte ficaria travada.

No celular, `100vh` inclui a área atrás da barra de endereço, e o conteúdo fica cortado. `100dvh` acompanha a altura visível de verdade.

### Tipografia fluida com clamp

```css
/* estilos.css */
.destaque h1 {
  font-size: clamp(1.75rem, 1.2rem + 2.5vw, 3rem);
}

.container {
  width: min(100% - 2rem, 1200px);
  margin-inline: auto;
}
```

`clamp(mínimo, ideal, máximo)` cresce com a tela e para nos limites. A soma com `rem` no valor ideal mantém o zoom funcionando. O `.container` usa `min()` para ter 1rem de respiro de cada lado no celular e no máximo 1200px no desktop, sem media query.

## Imagens responsivas

Mandar a foto de 2000px para um celular de 400px desperdiça dados e atrasa a página. O HTML resolve isso sem JavaScript.

### srcset e sizes: a mesma foto em tamanhos diferentes

```html
<!-- index.html -->
<img
  src="img/tomate-600.jpg"
  srcset="img/tomate-300.jpg 300w, img/tomate-600.jpg 600w, img/tomate-1200.jpg 1200w"
  sizes="(min-width: 1024px) 25vw, (min-width: 600px) 50vw, 100vw"
  alt="Tomates italianos maduros"
  width="600"
  height="400"
  loading="lazy"
  decoding="async"
/>
```

- `srcset` lista os arquivos e a largura real de cada um (`300w`).
- `sizes` diz quanto espaço a imagem vai ocupar em cada faixa de tela: um quarto do viewport no desktop (quatro colunas), metade no tablet, a tela toda no celular.
- O navegador cruza as duas informações com a densidade de pixels da tela e baixa o menor arquivo suficiente.
- `loading="lazy"` adia o download das fotos fora da tela. **Não** use nas imagens visíveis logo de cara (o banner do destaque): elas costumam ser o LCP e devem carregar imediatamente.

### picture: formatos e recortes diferentes

```html
<!-- index.html -->
<picture>
  <source srcset="img/banner-largo.avif" media="(min-width: 900px)" type="image/avif" />
  <source srcset="img/banner-largo.webp" media="(min-width: 900px)" type="image/webp" />
  <source srcset="img/banner-quadrado.webp" type="image/webp" />
  <img src="img/banner-quadrado.jpg" alt="Caixa de feira com frutas e verduras" width="800" height="800" />
</picture>
```

O navegador usa o primeiro `source` cujo `media` e `type` ele aceita; o `img` é o fallback e é quem carrega o `alt`. Use `picture` quando o **recorte** muda (banner largo no desktop, quadrado no celular) ou para oferecer AVIF e WebP, que costumam ter uma fração do tamanho do JPEG.

### aspect-ratio e object-fit

Fotos de fornecedores chegam em proporções diferentes. Para os cards ficarem alinhados:

```css
/* estilos.css */
.produto img {
  width: 100%;
  aspect-ratio: 3 / 2;
  object-fit: cover;
  border-radius: calc(var(--raio) - 4px);
}
```

`aspect-ratio` reserva a altura antes da foto chegar; `object-fit: cover` preenche a área recortando o excesso, sem distorcer.

## Container queries

Media queries perguntam o tamanho da **tela**. Mas o card de produto aparece em lugares diferentes: na vitrine (estreito), na lista de "comprados recentemente" da lateral (mais estreito ainda) e na página de ofertas, em destaque (largo). O que importa para o card é o espaço que **ele** tem. As container queries, suportadas por todos os navegadores atuais, respondem exatamente isso.

```css
/* estilos.css */
.lista-produtos > li {
  container-type: inline-size;
}

/* card padrão: foto em cima, texto embaixo */
.produto {
  display: flex;
  flex-direction: column;
  gap: var(--espaco-1);
}

/* se o card tiver 420px ou mais, foto ao lado do texto */
@container (min-width: 420px) {
  .produto {
    flex-direction: row;
    align-items: center;
  }

  .produto img {
    width: 40%;
  }
}
```

`container-type: inline-size` transforma o elemento num contêiner consultável pela largura. Dentro dele, `@container` funciona como uma media query, só que medindo o contêiner. Também existem as unidades `cqi` (1% da largura do contêiner), úteis para fontes que acompanham o card.

<Callout type="tip" title="Pense em componentes desde já">
Container queries são a forma CSS de pensar em componentes: o card não sabe em que página está, só sabe quanto espaço tem. É exatamente o modelo dos componentes React do Nível 1, em que o mesmo componente de produto aparece na vitrine, no carrinho e no painel.
</Callout>

## Menu no celular

O menu de categorias não cabe ao lado da marca numa tela de 360px. A solução mais simples e acessível, sem JavaScript, é deixá-lo rolar na horizontal:

```css
/* estilos.css */
.cabecalho {
  flex-wrap: wrap;
}

.menu {
  order: 3;
  width: 100%;
  overflow-x: auto;
  white-space: nowrap;
  scrollbar-width: none;
}

@media (min-width: 768px) {
  .menu {
    order: 0;
    width: auto;
  }
}
```

Menus que abrem e fecham (o "hambúrguer") precisam de JavaScript e de `aria-expanded`; ficam para quando você estiver manipulando o DOM.

## Testando a responsividade

- **Modo de dispositivo** nas DevTools (`Ctrl+Shift+M`): escolha aparelhos, arraste a largura livremente e simule toque.
- **Overlays de Grid e Flex** no painel Elements mostram linhas, áreas nomeadas e espaçamentos.
- **Zoom de 200%** no navegador: a WCAG pede que a página continue usável, sem rolagem horizontal.
- **Aparelho real:** com o Live Server, acesse pelo IP do computador na mesma rede Wi-Fi (`http://192.168.0.10:5500`). Emulador não substitui o dedo, o sol na tela e o 4G ruim.

## Na entrevista

**O que é mobile first?** Escrever o CSS base para telas pequenas e acrescentar regras para telas maiores com media queries de `min-width`. O layout simples vem primeiro e o celular recebe menos CSS a sobrescrever.

**Qual a diferença entre Grid e Flexbox?** Flexbox distribui itens em um eixo, com tamanho guiado pelo conteúdo. Grid define linhas e colunas ao mesmo tempo, com o layout guiado pelo contêiner. Usam-se juntos.

**Para que servem `srcset` e `sizes`?** Para oferecer a mesma imagem em várias larguras e dizer quanto espaço ela ocupa em cada faixa de tela, deixando o navegador baixar o menor arquivo que atende à tela e à densidade de pixels.

**Diferença entre media query e container query?** A media query consulta o viewport (ou preferências do usuário). A container query consulta o tamanho de um elemento ancestral marcado como contêiner, o que permite componentes que se adaptam onde quer que sejam colocados.

**Por que `rem` em vez de `px` para fonte?** Porque `rem` acompanha o tamanho de fonte que o usuário configurou no navegador. Com `px`, a preferência é ignorada.

## Pratique

1. Reescreva a vitrine com `repeat(auto-fill, minmax(min(100%, 220px), 1fr))` e confira nas DevTools quantas colunas aparecem em 360px, 768px e 1440px.
2. Monte o `checkout.html` com `grid-template-areas`, resumo primeiro no celular e lateral fixa com `position: sticky` a partir de 900px; navegue com Tab e confirme que a ordem faz sentido.
3. Gere três tamanhos de cada foto de produto (300, 600 e 1200 pixels de largura, em WebP) e use `srcset` e `sizes` nos cards; observe na aba Network qual arquivo cada largura de tela baixa.
4. Transforme o card de produto num contêiner e faça a versão horizontal aparecer quando o card tiver 420px ou mais; use o mesmo card numa lateral estreita e numa seção larga.
5. Troque os tamanhos de fonte para `rem`, aplique `clamp()` ao título do destaque e teste com a fonte padrão do navegador em "Muito grande".
6. Implemente o tema escuro com `prefers-color-scheme` e desligue as transições com `prefers-reduced-motion`.
