Até aqui, a Quitanda em React é uma tela só: catálogo, carrinho e formulários empilhados em `App.jsx`. Uma loja de verdade tem páginas: a vitrine, o detalhe de cada produto, o carrinho, o checkout, o acompanhamento de um pedido e o painel do lojista. E cada página precisa de um endereço próprio, para o cliente compartilhar o link de uma banana em promoção, usar o botão voltar do navegador e recarregar a página sem cair de novo na vitrine.

Uma SPA (single page application) entrega um único `index.html` e troca o conteúdo pelo JavaScript conforme a URL muda, sem recarregar a página. O React Router é a biblioteca de rotas mais usada no ecossistema React, e a versão 7 juntou nela o que antes era o Remix. Este capítulo organiza a Quitanda em páginas com o modo de dados do React Router 7: rotas aninhadas, parâmetros, links, carregamento de dados com loaders, envio com actions, página 404 e uma rota protegida simples.

**Você vai aprender:**

- Entender como uma SPA troca de página sem recarregar e o que o servidor precisa fazer
- Escolher entre os modos declarativo, de dados e framework do React Router 7
- Montar rotas aninhadas com layout, `Outlet`, parâmetros e query string
- Navegar com `Link`, `NavLink` e `useNavigate`
- Carregar e enviar dados com loaders, actions e o componente `Form`
- Tratar erros e 404 e proteger o painel do lojista

## Como uma SPA navega

No site do Nível base, cada link fazia o navegador pedir um novo HTML ao servidor. Numa SPA, o roteador intercepta o clique, usa a History API (`history.pushState`) para mudar a URL sem recarregar e renderiza os componentes que correspondem ao novo endereço. O botão voltar dispara o evento `popstate`, e o roteador renderiza a página anterior.

Isso tem uma consequência para o deploy: se o usuário recarregar em `/produtos/2`, o navegador pede esse caminho ao servidor, que não tem arquivo nenhum ali. O servidor precisa devolver o `index.html` para qualquer rota desconhecida (o chamado fallback de SPA). O servidor de desenvolvimento do Vite já faz isso; em produção, configure a regra na hospedagem.

## Os modos do React Router 7

```bash
npm install react-router
```

No React Router 7, tudo vem do pacote `react-router` (o antigo `react-router-dom` existe só para compatibilidade e reexporta o mesmo conteúdo). A biblioteca pode ser usada de três formas:

| Modo | Como se configura | O que oferece | Quando usar |
|---|---|---|---|
| Declarativo | `BrowserRouter`, `Routes`, `Route` no JSX | Correspondência de URL, navegação, parâmetros | Apps simples ou migração de versões antigas |
| Dados | `createBrowserRouter` e `RouterProvider` | Tudo do declarativo mais loaders, actions, estados de navegação e erros por rota | SPAs com dados, caso da Quitanda |
| Framework | Plugin do Vite, arquivo de rotas e `react-router dev` | Tudo do modo dados mais SSR, divisão de código e tipos gerados | Aplicações completas com renderização no servidor (o antigo Remix) |

O modo framework é o tema do capítulo sobre Remix no Nível 2. Aqui usamos o modo de dados, mas vale ver o declarativo, porque ele aparece em muitos projetos:

```jsx
// src/main.jsx (modo declarativo, para comparação)
import { BrowserRouter, Routes, Route } from "react-router";

createRoot(document.getElementById("root")).render(
  <BrowserRouter>
    <Routes>
      <Route path="/" element={<Layout />}>
        <Route index element={<Catalogo />} />
        <Route path="produtos/:id" element={<PaginaProduto />} />
        <Route path="*" element={<NaoEncontrada />} />
      </Route>
    </Routes>
  </BrowserRouter>,
);
```

## As rotas da Quitanda

```text
/                  Catalogo          (vitrine, com ?q= e ?categoria=)
/produtos/:id      PaginaProduto     (detalhe)
/carrinho          PaginaCarrinho
/checkout          Checkout          (formulário com action)
/pedidos/:id       PaginaPedido      (status do pedido)
/painel            PainelLojista     (protegida)
/entrar            Entrar
*                  NaoEncontrada
```

As páginas ficam em `src/paginas/` e a configuração do roteador em `src/rotas.jsx`:

```jsx
// src/rotas.jsx
import { createBrowserRouter } from "react-router";
import Layout from "./paginas/Layout.jsx";
import Catalogo, { carregarCatalogo } from "./paginas/Catalogo.jsx";
import PaginaProduto, { carregarProduto } from "./paginas/PaginaProduto.jsx";
import PaginaCarrinho from "./paginas/PaginaCarrinho.jsx";
import Checkout, { finalizarPedido } from "./paginas/Checkout.jsx";
import PaginaPedido, { carregarPedido } from "./paginas/PaginaPedido.jsx";
import PainelLojista, { exigirLojista } from "./paginas/PainelLojista.jsx";
import Entrar from "./paginas/Entrar.jsx";
import PaginaDeErro from "./paginas/PaginaDeErro.jsx";
import NaoEncontrada from "./paginas/NaoEncontrada.jsx";

export const roteador = createBrowserRouter([
  {
    path: "/",
    element: <Layout />,
    errorElement: <PaginaDeErro />,
    hydrateFallbackElement: <p>Carregando a Quitanda...</p>,
    children: [
      { index: true, element: <Catalogo />, loader: carregarCatalogo },
      { path: "produtos/:id", element: <PaginaProduto />, loader: carregarProduto },
      { path: "carrinho", element: <PaginaCarrinho /> },
      { path: "checkout", element: <Checkout />, action: finalizarPedido },
      { path: "pedidos/:id", element: <PaginaPedido />, loader: carregarPedido },
      { path: "painel", element: <PainelLojista />, loader: exigirLojista },
      { path: "entrar", element: <Entrar /> },
      { path: "*", element: <NaoEncontrada /> },
    ],
  },
]);
```

```jsx
// src/main.jsx
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import { RouterProvider } from "react-router/dom";
import { roteador } from "./rotas.jsx";
import "./index.css";

createRoot(document.getElementById("root")).render(
  <StrictMode>
    <RouterProvider router={roteador} />
  </StrictMode>,
);
```

Caminhos filhos são relativos ao pai (sem barra inicial). A rota com `index: true` é a que aparece quando a URL é exatamente a do pai.

## Layout, Outlet e estado compartilhado

O `Layout` desenha o que é comum a todas as páginas (cabeçalho, rodapé) e um `Outlet`, o lugar onde a rota filha correspondente é renderizada. Como o `Layout` não é desmontado ao trocar de página, ele é um bom dono para o carrinho, que vem do `useCarrinho` do capítulo de hooks:

```jsx
// src/paginas/Layout.jsx
import { NavLink, Outlet, useNavigation } from "react-router";
import { useCarrinho } from "../estado/useCarrinho.js";

const classeDoLink = ({ isActive }) => (isActive ? "font-semibold underline" : "hover:underline");

export default function Layout() {
  const carrinho = useCarrinho();
  const navegacao = useNavigation();

  return (
    <>
      <header className="flex items-center gap-4 p-4">
        <NavLink to="/" end className={classeDoLink}>Quitanda</NavLink>
        <nav aria-label="Principal" className="flex gap-4">
          <NavLink to="/carrinho" className={classeDoLink}>
            Carrinho ({carrinho.quantidadeTotal})
          </NavLink>
          <NavLink to="/painel" className={classeDoLink}>Painel</NavLink>
        </nav>
      </header>
      {navegacao.state === "loading" && <div role="progressbar" aria-label="Carregando página" className="h-1 animate-pulse bg-folha-500" />}
      <main className="p-4">
        <Outlet context={carrinho} />
      </main>
    </>
  );
}
```

As páginas filhas leem esse valor com `useOutletContext()`. É uma solução simples enquanto o carrinho só é usado dentro do layout; no capítulo de Context e Redux ele ganha uma casa melhor.

`NavLink` é um `Link` que sabe se está ativo: a prop `className` (e também `style` e `children`) pode ser uma função que recebe `isActive` e `isPending`. Ele também aplica `aria-current="page"` no link ativo, o que leitores de tela anunciam. O `end` no link da vitrine evita que `/` fique ativo em todas as páginas.

## Links, parâmetros e query string

```jsx
// src/componentes/CartaoProduto.jsx (trecho)
import { Link } from "react-router";

<h2>
  <Link to={`/produtos/${produto.id}`}>{produto.nome}</Link>
</h2>
```

Nunca use `<a href>` para navegar dentro da SPA: ele recarrega a página inteira e perde o estado. `Link` renderiza um `<a>` de verdade (abre em nova aba, mostra a URL no rodapé), mas intercepta o clique.

Na página de detalhe, `useParams` lê os segmentos dinâmicos da URL. Parâmetros chegam sempre como string, o que combina com os ids em string da Quitanda:

```jsx
// src/paginas/PaginaProduto.jsx
import { data, useLoaderData, useNavigate, useOutletContext } from "react-router";
import { buscarProduto } from "../servicos/produtos.js";
import { formatarPreco } from "../utilidades/formatarPreco.js";

export async function carregarProduto({ params }) {
  const produto = await buscarProduto(params.id);
  if (!produto) {
    throw data("Produto não encontrado", { status: 404 });
  }
  return { produto };
}

export default function PaginaProduto() {
  const { produto } = useLoaderData();
  const { adicionar } = useOutletContext();
  const navigate = useNavigate();

  return (
    <article>
      <button type="button" onClick={() => navigate(-1)}>Voltar</button>
      <h1>{produto.nome}</h1>
      <p>{formatarPreco(produto.precoEmCentavos)} / {produto.unidade}</p>
      <button type="button" onClick={() => adicionar(produto)}>Adicionar ao carrinho</button>
    </article>
  );
}
```

Filtros da vitrine ficam melhor na **query string** do que em estado: `/` com `?q=manga&categoria=frutas` pode ser compartilhado, e o botão voltar desfaz o filtro. `useSearchParams` lê e escreve esses valores:

```jsx
// src/paginas/Catalogo.jsx
import { Form, useLoaderData, useOutletContext, useSearchParams } from "react-router";
import { listarProdutos } from "../servicos/produtos.js";
import ListaDeProdutos from "../componentes/ListaDeProdutos.jsx";

export async function carregarCatalogo({ request }) {
  const url = new URL(request.url);
  const q = url.searchParams.get("q") ?? "";
  const categoria = url.searchParams.get("categoria") ?? "";
  return { produtos: await listarProdutos({ q, categoria }) };
}

export default function Catalogo() {
  const { produtos } = useLoaderData();
  const [params, setParams] = useSearchParams();
  const { adicionar } = useOutletContext();

  return (
    <>
      <Form role="search">
        <input type="search" name="q" defaultValue={params.get("q") ?? ""} aria-label="Buscar produtos" />
        <button type="submit">Buscar</button>
      </Form>
      <button type="button" onClick={() => setParams({ categoria: "frutas" })}>Só frutas</button>
      <ListaDeProdutos produtos={produtos} onAdicionar={adicionar} />
    </>
  );
}
```

Um `Form` sem `method` faz um GET: os campos viram a query string da URL atual, e o loader da rota roda de novo. É o mesmo comportamento de um formulário HTML, só que sem recarregar.

## Loaders: dados antes de renderizar

Um **loader** é uma função associada à rota que o roteador chama **antes** de renderizar a página, a cada navegação para ela. O componente lê o resultado com `useLoaderData()` e não precisa lidar com estado de "carregando" nem com `useEffect`. Enquanto o loader roda, a página anterior continua na tela e `useNavigation().state` vale `"loading"`, o que o `Layout` usa para mostrar a barra de progresso.

Por enquanto, `src/servicos/produtos.js` lê os dados locais, devolvendo promises para imitar uma API. No próximo capítulo, essas mesmas funções passam a chamar o `json-server` com `fetch`, e as páginas não mudam.

```js
// src/servicos/produtos.js
import { produtos } from "../dados/produtos.js";

export async function listarProdutos({ q = "", categoria = "" } = {}) {
  return produtos.filter(
    (p) =>
      p.nome.toLowerCase().includes(q.toLowerCase()) &&
      (categoria === "" || p.categoria === categoria),
  );
}

export async function buscarProduto(id) {
  return produtos.find((p) => p.id === id) ?? null;
}
```

## Actions: enviando dados

Uma **action** recebe as submissões de `Form` com método diferente de GET. O roteador chama a action com o `request`, e depois dela roda de novo os loaders da página, mantendo a tela coerente com os dados recém-alterados.

```jsx
// src/paginas/Checkout.jsx
import { Form, redirect, useActionData, useNavigation, useOutletContext } from "react-router";
import { criarPedido } from "../servicos/pedidos.js";

export async function finalizarPedido({ request }) {
  const formData = await request.formData();
  const nome = String(formData.get("nome") ?? "").trim();
  const endereco = String(formData.get("endereco") ?? "").trim();
  const itens = JSON.parse(formData.get("itens"));

  const erros = {};
  if (nome.length < 3) erros.nome = "Informe seu nome completo.";
  if (endereco.length < 10) erros.endereco = "Informe o endereço de entrega.";
  if (itens.length === 0) erros.geral = "Seu carrinho está vazio.";
  if (Object.keys(erros).length > 0) return { erros };

  const pedido = await criarPedido({ nome, endereco, itens });
  return redirect(`/pedidos/${pedido.id}?novo=1`);
}

export default function Checkout() {
  const { itens } = useOutletContext();
  const resultado = useActionData();
  const enviando = useNavigation().state === "submitting";

  return (
    <Form method="post" noValidate>
      <input type="hidden" name="itens" value={JSON.stringify(itens)} />
      <label htmlFor="nome">Nome</label>
      <input id="nome" name="nome" aria-invalid={Boolean(resultado?.erros?.nome)} />
      {resultado?.erros?.nome && <p role="alert">{resultado.erros.nome}</p>}
      <label htmlFor="endereco">Endereço</label>
      <input id="endereco" name="endereco" aria-invalid={Boolean(resultado?.erros?.endereco)} />
      {resultado?.erros?.endereco && <p role="alert">{resultado.erros.endereco}</p>}
      {resultado?.erros?.geral && <p role="alert">{resultado.erros.geral}</p>}
      <button type="submit" disabled={enviando}>{enviando ? "Enviando..." : "Finalizar pedido"}</button>
    </Form>
  );
}
```

`redirect` devolve uma resposta de redirecionamento que o roteador segue. `useActionData` traz o retorno da action quando ela não redireciona, perfeito para mensagens de validação. Esvaziar o carrinho depois do pedido fica a cargo da página de pedido, que lê `?novo=1`.

| Necessidade | Hook ou componente |
|---|---|
| Dados da rota | `useLoaderData()` |
| Retorno da action | `useActionData()` |
| Estado da navegação (`idle`, `loading`, `submitting`) | `useNavigation()` |
| Enviar sem navegar (favoritar, por exemplo) | `useFetcher()` |
| Ler parâmetros da URL | `useParams()`, `useSearchParams()` |
| Navegar por código | `useNavigate()` ou `redirect` em loaders e actions |

<Callout type="tip" title="Loader ou TanStack Query?">
Loaders resolvem bem o "busque antes de mostrar a página". O próximo capítulo apresenta o TanStack Query, que acrescenta cache entre páginas, revalidação em segundo plano e mutações com invalidação. Os dois combinam: o loader pode garantir os dados no cache do Query (`queryClient.ensureQueryData`) e o componente lê com `useQuery`.
</Callout>

## Erros e página 404

Quando um loader, uma action ou a renderização lança um erro, o roteador mostra o `errorElement` da rota mais próxima, mantendo o resto do layout se o erro estiver numa rota filha. No elemento de erro, `useRouteError` traz o que foi lançado, e `isRouteErrorResponse` diferencia respostas HTTP (como o `data(..., { status: 404 })` do loader de produto) de exceções comuns.

```jsx
// src/paginas/PaginaDeErro.jsx
import { isRouteErrorResponse, Link, useRouteError } from "react-router";

export default function PaginaDeErro() {
  const erro = useRouteError();
  if (isRouteErrorResponse(erro) && erro.status === 404) {
    return (
      <main>
        <h1>Não encontramos essa página</h1>
        <p>{erro.data}</p>
        <Link to="/">Voltar para a vitrine</Link>
      </main>
    );
  }
  return (
    <main>
      <h1>Algo deu errado</h1>
      <p>Tente recarregar a página. Se continuar, fale com a gente.</p>
    </main>
  );
}
```

A rota `*` captura URLs que não correspondem a nenhuma outra e renderiza `NaoEncontrada` dentro do layout. Já o `errorElement` cobre o produto que não existe (`/produtos/999`) e falhas inesperadas.

## Rota protegida simples

O painel do lojista só deve abrir para quem entrou como lojista. No modo de dados, a forma mais limpa é verificar no loader e redirecionar antes de renderizar qualquer coisa:

```jsx
// src/paginas/PainelLojista.jsx (trecho)
import { redirect } from "react-router";
import { usuarioAtual } from "../servicos/sessao.js";

export async function exigirLojista({ request }) {
  const usuario = usuarioAtual();
  if (!usuario || usuario.papel !== "lojista") {
    const destino = new URL(request.url).pathname;
    throw redirect(`/entrar?voltarPara=${encodeURIComponent(destino)}`);
  }
  return { usuario };
}
```

Depois do login, a página `Entrar` lê `voltarPara` da query string e chama `navigate(voltarPara, { replace: true })`, para que o botão voltar não leve de novo ao formulário de login. No modo declarativo, o equivalente é um componente que devolve `<Navigate to="/entrar" replace />` quando não há usuário.

<Callout type="warning" title="Proteger rota no front não é segurança">
Todo código da SPA chega ao navegador, e qualquer pessoa pode alterar o localStorage ou chamar a API diretamente. A rota protegida melhora a experiência: esconde telas inúteis para quem não tem acesso. Quem protege os dados é a API, verificando a sessão em cada requisição. Autenticação de verdade, com cookies seguros e sessões no servidor, é tema do Nível 2.
</Callout>

## Na entrevista

**O que o servidor precisa fazer para uma SPA com rotas funcionar?** Devolver o `index.html` para qualquer caminho que não seja um arquivo estático. Sem isso, recarregar `/produtos/2` dá 404, porque o servidor procura um arquivo que não existe; quem resolve a rota é o JavaScript.

**Qual a diferença entre Link e uma tag a comum?** O `Link` renderiza um `<a>`, mas intercepta o clique e troca a URL com a History API, sem recarregar a página nem perder o estado. Um `<a href>` interno faz o navegador buscar a página de novo.

**O que são loaders e actions?** Funções associadas à rota. O loader busca dados antes de a página renderizar, e o componente os lê com `useLoaderData`. A action recebe submissões de `Form` com POST, PUT ou DELETE e, ao terminar, o roteador revalida os loaders da página.

**Onde guardar filtros de uma listagem: estado ou URL?** Na URL, com query string. O filtro fica compartilhável, sobrevive ao recarregamento e o botão voltar funciona como o usuário espera.

**Como o React Router 7 se relaciona com o Remix?** O Remix v2 foi incorporado ao React Router 7 como o modo framework, com SSR, divisão de código e tipos gerados. Os modos declarativo e de dados continuam disponíveis para SPAs.

## Pratique

1. Instale o React Router, crie `src/rotas.jsx` com as oito rotas da Quitanda e mova o conteúdo de `App.jsx` para `Layout` e `Catalogo`.
2. Faça cada `CartaoProduto` levar a `/produtos/:id` e mostre a página de erro amigável para um id inexistente.
3. Leve a busca e o filtro de categoria para a query string e confirme que o botão voltar desfaz o último filtro.
4. Implemente o checkout com `Form` e action, validando nome e endereço e redirecionando para `/pedidos/:id`.
5. Proteja `/painel` com um loader que redireciona para `/entrar?voltarPara=/painel` e, após o login simulado, volte ao painel com `replace`.
6. Gere o build, sirva `dist/` com `npx serve -s dist` e confirme que recarregar em `/carrinho` funciona. Repita sem o `-s` e explique o 404.
