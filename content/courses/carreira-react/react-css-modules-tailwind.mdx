Na reescrita em React, a Quitanda herdou o `estilos.css` do Nível base: um arquivo único com `.cartao`, `.botao`, `.selo` e dezenas de outras classes globais. Em um projeto pequeno isso funciona. Mas componentes são reutilizados em lugares diferentes, e um CSS global não sabe disso: alguém cria `.titulo` para o carrinho e muda o título do catálogo sem perceber, a ordem de importação dos arquivos decide quem ganha a especificidade, e ninguém tem coragem de apagar uma classe porque não sabe onde ela é usada.

Existem duas respostas populares e bem diferentes para esse problema no React. **CSS Modules** mantém o CSS que você já sabe, mas dá a cada arquivo um escopo próprio. **Tailwind CSS** troca as folhas de estilo por classes utilitárias aplicadas direto no JSX. Este capítulo estiliza os mesmos componentes da Quitanda das duas formas, mostra como lidar com classes condicionais e termina com critérios para escolher.

**Você vai aprender:**

- Entender por que CSS global escala mal em projetos com componentes
- Escrever estilos com escopo por componente usando CSS Modules no Vite
- Configurar Tailwind CSS 4 com o plugin do Vite e definir o tema da Quitanda com `@theme`
- Aplicar classes condicionais com `clsx` e variantes por estado
- Escolher entre CSS Modules, Tailwind e as alternativas para cada contexto

## O problema do CSS global

Todo seletor de classe em CSS puro vale para a página inteira. Em uma aplicação React, isso gera três dores:

- **Colisão de nomes.** Dois componentes com `.titulo` interferem um no outro. Convenções como BEM (`.cartao__titulo--destaque`) ajudam, mas dependem de disciplina.
- **Código morto.** Não há como saber, com segurança, se uma classe ainda é usada. O CSS só cresce.
- **Dependência da ordem.** Com especificidades iguais, vence a regra que vem por último, e a ordem depende de quais componentes foram importados primeiro.

O objetivo das duas abordagens deste capítulo é o mesmo: que o estilo de um componente só afete aquele componente, e que apagar o componente apague o estilo junto.

## CSS Modules

Qualquer arquivo terminado em `.module.css` é tratado pelo Vite como um módulo CSS, sem instalar nada. Ao importá-lo, você recebe um objeto que mapeia os nomes que escreveu para nomes únicos gerados no build.

```css
/* src/componentes/CartaoProduto.module.css */
.cartao {
  display: grid;
  gap: 0.5rem;
  padding: 1rem;
  border: 1px solid var(--cor-borda);
  border-radius: 0.75rem;
  background: var(--cor-superficie);
}

.nome {
  font-size: 1.125rem;
  font-weight: 600;
}

.preco {
  color: var(--cor-primaria);
  font-variant-numeric: tabular-nums;
}

.esgotado {
  opacity: 0.55;
}

.botao {
  padding: 0.5rem 1rem;
  border: 0;
  border-radius: 999px;
  background: var(--cor-primaria);
  color: white;
  cursor: pointer;
}

.botao:disabled {
  background: var(--cor-desabilitado);
  cursor: not-allowed;
}
```

```jsx
// src/componentes/CartaoProduto.jsx
import estilos from "./CartaoProduto.module.css";
import { formatarPreco } from "../utilidades/formatarPreco.js";

export default function CartaoProduto({ produto, onAdicionar }) {
  const esgotado = produto.estoque === 0;
  return (
    <article className={esgotado ? `${estilos.cartao} ${estilos.esgotado}` : estilos.cartao}>
      <img src={produto.foto} alt={produto.nome} width="160" height="120" />
      <h2 className={estilos.nome}>{produto.nome}</h2>
      <p className={estilos.preco}>
        {formatarPreco(produto.precoEmCentavos)} / {produto.unidade}
      </p>
      <button type="button" className={estilos.botao} disabled={esgotado} onClick={() => onAdicionar(produto)}>
        {esgotado ? "Esgotado" : "Adicionar"}
      </button>
    </article>
  );
}
```

No navegador, `estilos.cartao` vira algo como `_cartao_1x9k2_1`. Outro componente pode ter sua própria `.cartao` sem conflito. Se você apagar `CartaoProduto.jsx` e seu `.module.css`, o estilo vai embora junto, e o build não carrega CSS de componentes que não são importados.

### O que fica global e como compartilhar

Variáveis CSS (custom properties) continuam globais, e isso é uma vantagem: elas viram os tokens da Quitanda, definidos uma vez e usados em todos os módulos.

```css
/* src/index.css */
:root {
  --cor-primaria: #2f7d32;
  --cor-borda: #d9e2d3;
  --cor-superficie: #ffffff;
  --cor-fundo: #f6f8f3;
  --cor-desabilitado: #9aa59a;
}

@media (prefers-color-scheme: dark) {
  :root {
    --cor-borda: #34412f;
    --cor-superficie: #1b2219;
    --cor-fundo: #121711;
  }
}

body {
  margin: 0;
  font-family: system-ui, sans-serif;
  background: var(--cor-fundo);
}
```

Outros recursos úteis:

- **`composes`** reaproveita uma classe dentro de outra: `.botaoPerigo { composes: botao; background: #b3261e; }`. Também funciona entre arquivos: `composes: botao from "./Botao.module.css";`.
- **`:global(...)`** escapa do escopo quando é necessário estilizar algo de fora, como uma classe de biblioteca: `.carrinho :global(.swiper-slide) { ... }`.
- **Nomes em camelCase** são os mais confortáveis (`estilos.precoAntigo`). Com hífen, você precisa de `estilos["preco-antigo"]`.

## Tailwind CSS 4

Tailwind é um framework de classes utilitárias: cada classe aplica uma propriedade (`p-4` é padding de 1rem, `rounded-xl` arredonda, `text-green-700` define a cor). Em vez de inventar nomes e escrever CSS, você compõe o visual no próprio JSX. O build gera só as classes que aparecem no código.

A versão 4 simplificou a configuração: não há mais `tailwind.config.js` obrigatório nem lista de arquivos de conteúdo, e o tema é definido no próprio CSS.

```bash
npm install tailwindcss @tailwindcss/vite
```

```js
// vite.config.js
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";
import tailwindcss from "@tailwindcss/vite";

export default defineConfig({
  plugins: [react(), tailwindcss()],
});
```

```css
/* src/index.css */
@import "tailwindcss";

@theme {
  --color-folha-50: #f1f8ef;
  --color-folha-500: #3f9142;
  --color-folha-700: #2f7d32;
  --color-tomate-600: #c8372d;
  --font-sans: "Inter", system-ui, sans-serif;
  --radius-cartao: 0.75rem;
}
```

Cada variável em `@theme` vira classes automaticamente: `--color-folha-700` gera `bg-folha-700`, `text-folha-700`, `border-folha-700` e assim por diante; `--radius-cartao` gera `rounded-cartao`. As variáveis também ficam disponíveis como CSS comum (`var(--color-folha-700)`), o que facilita misturar com outras abordagens. O Tailwind detecta sozinho os arquivos do projeto onde procurar classes, ignorando o que está no `.gitignore`.

```jsx
// src/componentes/CartaoProduto.jsx (versão Tailwind)
import { formatarPreco } from "../utilidades/formatarPreco.js";

export default function CartaoProduto({ produto, onAdicionar }) {
  const esgotado = produto.estoque === 0;
  return (
    <article
      data-esgotado={esgotado}
      className="grid gap-2 rounded-cartao border border-stone-200 bg-white p-4 data-[esgotado=true]:opacity-55 dark:border-stone-700 dark:bg-stone-900"
    >
      <img src={produto.foto} alt={produto.nome} width="160" height="120" className="aspect-4/3 w-full rounded-lg object-cover" />
      <h2 className="text-lg font-semibold">{produto.nome}</h2>
      <p className="text-folha-700 tabular-nums">
        {formatarPreco(produto.precoEmCentavos)} / {produto.unidade}
      </p>
      <button
        type="button"
        disabled={esgotado}
        onClick={() => onAdicionar(produto)}
        className="rounded-full bg-folha-700 px-4 py-2 text-white hover:bg-folha-500 focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-folha-700 disabled:cursor-not-allowed disabled:bg-stone-400"
      >
        {esgotado ? "Esgotado" : "Adicionar"}
      </button>
    </article>
  );
}
```

As **variantes** são prefixos que aplicam a classe só em certas condições:

| Variante | Exemplo | Quando aplica |
|---|---|---|
| Estado | `hover:`, `focus-visible:`, `disabled:` | Pseudo-classes do elemento |
| Responsiva | `sm:`, `md:`, `lg:` | A partir da largura (mobile first) |
| Tema | `dark:` | `prefers-color-scheme: dark` por padrão |
| Atributo | `data-[esgotado=true]:`, `aria-expanded:` | Atributos `data-*` e `aria-*` |
| Grupo | `group-hover:` | Quando o ancestral com `group` está em hover |

Layout responsivo do catálogo, com uma coluna no celular e quatro em telas largas:

```jsx
// src/componentes/ListaDeProdutos.jsx (trecho)
<ul className="grid grid-cols-1 gap-4 p-4 sm:grid-cols-2 lg:grid-cols-4">
  {produtos.map((produto) => (
    <li key={produto.id}>
      <CartaoProduto produto={produto} onAdicionar={onAdicionar} />
    </li>
  ))}
</ul>
```

### Classe dinâmica precisa ser string completa

O Tailwind lê o código-fonte como texto e gera as classes que encontra. Ele não executa JavaScript. Logo, classes montadas por interpolação não existem no CSS final:

```jsx
// errado: "bg-folha-700" nunca aparece inteira no código
const cor = destaque ? "folha" : "stone";
<span className={`bg-${cor}-700`}>Oferta</span>

// certo: as duas classes aparecem por extenso
<span className={destaque ? "bg-folha-700" : "bg-stone-700"}>Oferta</span>
```

Para mapear valores do domínio em classes, use um objeto com as classes escritas por extenso:

```js
// src/utilidades/coresDaCategoria.js
export const coresDaCategoria = {
  frutas: "bg-amber-100 text-amber-900",
  verduras: "bg-folha-50 text-folha-700",
  legumes: "bg-orange-100 text-orange-900",
};
```

## Classes condicionais com clsx

Concatenar strings com ternários fica ilegível rápido. A biblioteca `clsx` (minúscula, sem dependências) recebe strings, objetos e arrays e devolve só as classes verdadeiras. Ela funciona igual com CSS Modules e com Tailwind.

```bash
npm install clsx
```

```jsx
// src/componentes/SeloEstoque.jsx
import clsx from "clsx";

export default function SeloEstoque({ estoque }) {
  const ultimas = estoque > 0 && estoque <= 5;
  return (
    <span
      className={clsx("rounded-full px-2 py-0.5 text-xs font-medium", {
        "bg-tomate-600 text-white": estoque === 0,
        "bg-amber-100 text-amber-900": ultimas,
        "bg-folha-50 text-folha-700": estoque > 5,
      })}
    >
      {estoque === 0 ? "Esgotado" : ultimas ? "Últimas unidades" : "Em estoque"}
    </span>
  );
}
```

```jsx
// com CSS Modules
import clsx from "clsx";
import estilos from "./CartaoProduto.module.css";

<article className={clsx(estilos.cartao, esgotado && estilos.esgotado)}>
```

Quando um componente aceita `className` de fora para customização (`<Botao className="w-full" />`), duas classes Tailwind da mesma propriedade podem conflitar, e vence a que vier por último **no CSS gerado**, não no atributo. A biblioteca `tailwind-merge` resolve isso removendo a classe conflitante. O padrão comum, usado pelo shadcn/ui, é uma função `cn` que combina as duas:

```js
// src/utilidades/cn.js
import clsx from "clsx";
import { twMerge } from "tailwind-merge";

export function cn(...entradas) {
  return twMerge(clsx(entradas));
}
```

<Callout type="tip" title="Componente é a unidade de reúso, não a classe">
A crítica mais comum ao Tailwind é a repetição de longas listas de classes. A resposta é não copiar o JSX: extraia um componente `Botao` com as classes uma única vez e reutilize o componente. Recorrer a `@apply` para recriar classes semânticas (`.botao` com `@apply px-4 py-2 ...`) devolve os problemas do CSS global que você queria evitar; use-o com moderação.
</Callout>

## Tema escuro e acessibilidade visual

Por padrão, `dark:` segue a preferência do sistema operacional. Para um botão de tema controlado pela aplicação, redefina a variante para depender de uma classe no `html`:

```css
/* src/index.css */
@import "tailwindcss";

@custom-variant dark (&:where(.dark, .dark *));
```

Com isso, `document.documentElement.classList.toggle("dark", ativo)` liga e desliga o tema; o capítulo de Context API guarda essa escolha num contexto de tema.

Em qualquer abordagem, três cuidados de acessibilidade:

- **Contraste.** Texto normal precisa de contraste de pelo menos 4,5:1 com o fundo. Verde claro sobre branco quase sempre reprova; confira no DevTools.
- **Foco visível.** Nunca remova o contorno de foco sem substituí-lo. `focus-visible:outline-2` mostra o foco só para quem navega por teclado.
- **Estado não só por cor.** O produto esgotado tem texto "Esgotado" e botão desabilitado, não apenas opacidade reduzida.

## Comparação

| Critério | CSS global | CSS Modules | Tailwind CSS 4 | CSS-in-JS (styled-components) |
|---|---|---|---|---|
| Escopo | Nenhum | Por arquivo, no build | Classes utilitárias, sem nomes próprios | Por componente, em tempo de execução |
| Onde fica o estilo | Arquivo separado | Arquivo ao lado do componente | No JSX | No arquivo JS do componente |
| Curva de aprendizado | Baixa | Baixa, é CSS | Média: vocabulário de classes | Média |
| Custo em tempo de execução | Zero | Zero | Zero | Gera estilos no navegador |
| Tema | Variáveis CSS | Variáveis CSS | `@theme` e variantes | `ThemeProvider` |
| Código morto | Difícil de achar | Some com o componente | Só gera o que é usado | Some com o componente |
| Uso típico | Reset e tokens | Equipes fortes em CSS, componentes com estilo complexo | Produtos que iteram rápido, bibliotecas como shadcn/ui | Design systems com tema dinâmico |

Para a Quitanda, a recomendação desta carreira é Tailwind nas telas da aplicação e um `index.css` pequeno com tokens e reset. CSS Modules segue válido e é ótimo para componentes com CSS complexo (animações, seletores avançados) ou equipes que preferem CSS clássico, e os dois convivem no mesmo projeto sem conflito. O styled-components volta no Nível 3, quando a Quitanda ganha um design system com temas.

<Callout type="warning" title="Não misture abordagens no mesmo componente">
Um componente com metade do visual em `.module.css` e metade em classes Tailwind obriga quem mantém a abrir dois lugares para entender um botão. Escolha uma abordagem por componente e, idealmente, uma por camada (aplicação, design system).
</Callout>

## Na entrevista

**Como o CSS Modules evita conflito de nomes?** No build, cada classe do arquivo `.module.css` ganha um nome único, e o import devolve um objeto que mapeia o nome escrito para o gerado. Duas `.titulo` em arquivos diferentes viram classes distintas no navegador.

**Como o Tailwind sabe quais classes gerar?** Ele varre os arquivos do projeto como texto e gera CSS só para os nomes de classe completos que encontra. Por isso classes montadas por interpolação não funcionam: o nome inteiro precisa aparecer no código.

**O que mudou na configuração do Tailwind 4?** A configuração passou para o CSS: `@import "tailwindcss"` substitui as diretivas antigas, o tema é definido com variáveis em `@theme`, a detecção de arquivos é automática e, no Vite, existe um plugin próprio em vez da configuração via PostCSS.

**Para que servem clsx e tailwind-merge?** `clsx` monta a string de classes a partir de condições. `tailwind-merge` resolve conflitos entre classes Tailwind da mesma propriedade, mantendo a última, o que permite que um componente aceite `className` de fora sem brigar com as classes internas.

**Quando você escolheria CSS Modules em vez de Tailwind?** Quando a equipe domina CSS e quer manter estilos em arquivos próprios, quando o componente tem CSS complexo, como animações e seletores elaborados, ou num projeto que já usa CSS Modules e funciona bem. Os dois têm custo zero em tempo de execução.

## Pratique

1. Converta `CartaoProduto`, `Carrinho` e `Cabecalho` para CSS Modules, usando as variáveis de `index.css` para todas as cores.
2. Em um branch separado, configure Tailwind 4 com o plugin do Vite, defina as cores `folha` e `tomate` em `@theme` e refaça os mesmos três componentes.
3. Crie o componente `SeloEstoque` com `clsx` e o mapa `coresDaCategoria`, e confirme no CSS gerado em `dist/` que todas as classes existem.
4. Faça a grade do catálogo ter 1, 2, 3 e 4 colunas conforme a largura e teste no modo responsivo do DevTools.
5. Implemente um botão de tema claro e escuro com a variante `dark` baseada em classe e verifique o contraste dos preços nos dois temas.
6. Crie um componente `Botao` com variantes `primario`, `secundario` e `perigo` usando a função `cn`, e permita sobrescrever a largura via `className`.
