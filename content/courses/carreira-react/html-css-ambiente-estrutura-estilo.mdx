Você já sabe o que acontece quando alguém abre `quitanda.dev`: o navegador pede um HTML, descobre o CSS e as imagens e desenha a página. Agora é hora de escrever esses arquivos. O objetivo é a página inicial da Quitanda: cabeçalho com a marca e o link do carrinho, um destaque da semana, a vitrine com os cards de produto (foto, nome, preço, unidade e botão de adicionar) e um rodapé.

HTML e CSS parecem fáceis até o primeiro layout que não alinha. A diferença entre um iniciante e alguém pronto para React está em três coisas: usar a tag com o significado certo, entender como o CSS escolhe qual regra vence e dominar o box model e o Flexbox. Os componentes React que você vai escrever no Nível 1 devolvem exatamente esse HTML, e o CSS deles segue exatamente essas regras.

**Você vai aprender:**

- Montar o ambiente com VS Code, extensões úteis e a estrutura de pastas da Quitanda
- Escrever o esqueleto de um documento HTML válido e escolher tags semânticas
- Ligar o CSS ao HTML e usar seletores, especificidade e cascata sem brigar com eles
- Controlar tamanhos com o box model e `box-sizing`
- Alinhar o cabeçalho e os cards com Flexbox
- Organizar cores e espaçamentos com variáveis CSS

## O ambiente

O mínimo é um editor e um navegador. O editor padrão do mercado é o **VS Code**. Instale estas extensões:

| Extensão | Para que serve |
|---|---|
| Live Server (ou Live Preview) | Abre a página por `http://localhost` e recarrega ao salvar |
| Prettier | Formata HTML, CSS e JS ao salvar |
| ESLint | Aponta problemas no JavaScript (configurado no capítulo de Node.js) |
| Auto Rename Tag | Renomeia a tag de fechamento junto com a de abertura |

Ative "Format On Save" nas configurações. Use o atalho `!` seguido de `Tab` num arquivo `.html` vazio para o VS Code (via Emmet) gerar o esqueleto do documento. Emmet também expande abreviações como `ul>li*3` numa lista com três itens.

<Callout type="tip" title="Abra por um servidor, não pelo arquivo">
Dar dois cliques no `index.html` abre a página como `file:///...`. Funciona para HTML e CSS, mas módulos JavaScript, `fetch` e várias APIs do navegador falham nesse modo. Acostume-se desde já a abrir pelo Live Server, em `http://127.0.0.1:5500`.
</Callout>

A estrutura de pastas da Quitanda no Nível base:

```text
quitanda/
├── index.html
├── estilos.css
├── img/
│   ├── logo.svg
│   ├── tomate.jpg
│   └── banana.jpg
└── js/            (a partir dos capítulos de JavaScript)
```

Nomes de arquivo em minúsculas, sem espaço e sem acento. Servidores de produção costumam diferenciar `Tomate.jpg` de `tomate.jpg`, mesmo que o Windows não diferencie.

## O esqueleto do documento

```html
<!-- index.html -->
<!doctype html>
<html lang="pt-BR">
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1" />
    <title>Quitanda | Hortifrúti fresquinho na sua casa</title>
    <link rel="icon" href="img/logo.svg" type="image/svg+xml" />
    <link rel="stylesheet" href="estilos.css" />
  </head>
  <body>
    <!-- conteúdo visível -->
  </body>
</html>
```

Cada linha tem motivo:

- `<!doctype html>` coloca o navegador no modo padrão. Sem ele, entra no "quirks mode", que imita navegadores dos anos 1990.
- `lang="pt-BR"` informa o idioma a leitores de tela, tradutores e buscadores.
- `charset="utf-8"` garante que "maçã" e "R$" apareçam corretamente. Precisa estar no começo do `head`.
- A meta `viewport` impede que o celular finja ter 980px de largura e reduza a página. Ela é a base da responsividade.
- `title` aparece na aba, nos favoritos e no resultado de busca.

## Tags semânticas

HTML descreve o **significado** do conteúdo; a aparência é trabalho do CSS. Uma página feita só de `div` funciona visualmente, mas leitores de tela, buscadores e o próprio time perdem a estrutura.

| Tag | Uso | Na Quitanda |
|---|---|---|
| `header` | Cabeçalho da página ou de uma seção | Logo, busca, link do carrinho |
| `nav` | Bloco de navegação principal | Links para Frutas, Legumes, Verduras |
| `main` | Conteúdo principal, uma vez por página | Destaque e vitrine |
| `section` | Agrupamento temático com título | "Ofertas da semana" |
| `article` | Conteúdo que faz sentido isolado | Cada card de produto |
| `aside` | Conteúdo complementar | Resumo do carrinho na lateral |
| `footer` | Rodapé | Endereço, horário, redes |
| `h1` a `h6` | Títulos em hierarquia | Um `h1` por página, sem pular níveis |
| `button` | Ação na página | "Adicionar ao carrinho" |
| `a` | Navegação para outro endereço | "Ver carrinho" |

A regra mais cobrada: **link navega, botão age**. "Adicionar ao carrinho" é `button`, porque não muda de página. "Ver carrinho" é `a`, porque leva a `carrinho.html`. Um `div` com clique não recebe foco pelo teclado nem é anunciado como botão.

A página inicial completa:

```html
<!-- index.html (dentro do body) -->
<header class="cabecalho">
  <a href="/" class="marca">
    <img src="img/logo.svg" alt="" width="32" height="32" />
    Quitanda
  </a>
  <nav aria-label="Categorias">
    <ul class="menu">
      <li><a href="#frutas">Frutas</a></li>
      <li><a href="#legumes">Legumes</a></li>
      <li><a href="#verduras">Verduras</a></li>
    </ul>
  </nav>
  <a href="carrinho.html" class="link-carrinho">Carrinho (0)</a>
</header>

<main>
  <section class="destaque">
    <h1>Hortifrúti fresquinho, direto do produtor</h1>
    <p>Pedidos até as 11h chegam no mesmo dia.</p>
  </section>

  <section id="frutas" class="vitrine">
    <h2>Frutas</h2>
    <ul class="lista-produtos">
      <li>
        <article class="produto">
          <img src="img/banana.jpg" alt="Cacho de banana prata" width="300" height="200" />
          <h3 class="produto-nome">Banana prata</h3>
          <p class="produto-preco">R$ 6,49 <span>/ kg</span></p>
          <button type="button" class="botao">Adicionar</button>
        </article>
      </li>
      <!-- mais produtos -->
    </ul>
  </section>
</main>

<footer class="rodape">
  <p>Quitanda: Rua das Hortaliças, 120. Seg a sáb, 7h às 19h.</p>
</footer>
```

Detalhes que valem ouro:

- O `alt` descreve a imagem para quem não a vê. O logo tem `alt=""` porque o texto "Quitanda" já está ao lado; um `alt` repetido seria lido duas vezes.
- `width` e `height` nas imagens reservam o espaço antes de a foto chegar e evitam que a página "pule" (o que o Lighthouse mede como CLS).
- A vitrine é uma lista (`ul`), porque é uma coleção de itens. Leitores de tela anunciam "lista, 12 itens".

## Ligando o CSS e entendendo a cascata

Uma regra CSS é **seletor + declarações**:

```css
/* estilos.css */
.produto-preco {
  color: #1b5e20;
  font-weight: 700;
}
```

### Seletores essenciais

| Seletor | Seleciona | Exemplo |
|---|---|---|
| Tipo | Todas as tags daquele tipo | `h2` |
| Classe | Elementos com a classe | `.produto` |
| ID | O elemento com aquele id | `#frutas` |
| Descendente | B dentro de A, em qualquer nível | `.produto img` |
| Filho direto | B filho imediato de A | `.menu > li` |
| Atributo | Pelo atributo | `button[disabled]` |
| Pseudoclasse | Por estado ou posição | `a:hover`, `li:first-child`, `:focus-visible` |
| Pseudoelemento | Parte do elemento | `.produto-nome::after` |

No dia a dia, estilize por **classe**. IDs servem para âncoras e para o JavaScript; usá-los no CSS cria especificidade alta demais.

### Especificidade e cascata

Quando duas regras atingem o mesmo elemento e a mesma propriedade, vence:

1. A de maior **especificidade**, contada como (IDs, classes/atributos/pseudoclasses, tipos). `#frutas .produto` vale (1,1,0) e ganha de `.vitrine .produto` (0,2,0).
2. Em empate, a que aparece **por último**.
3. Estilo inline e `!important` passam por cima de tudo, e por isso devem ser exceção.

```css
/* estilos.css */
.produto h3 { color: black; }        /* (0,1,1) */
.produto-nome { color: darkgreen; }  /* (0,1,0): perde, apesar de vir depois */
```

Se uma regra "não pega", abra as DevTools, aba **Elements**, painel **Styles**: a regra vencida aparece riscada, e você vê qual a venceu.

**Herança**: propriedades de texto (`color`, `font-family`, `line-height`) passam dos pais para os filhos; propriedades de caixa (`margin`, `border`, `width`) não. Por isso definir a fonte no `body` basta para a página toda.

## Box model

Todo elemento é uma caixa com quatro camadas, de dentro para fora: **conteúdo**, **padding** (espaço interno), **border** e **margin** (espaço externo).

Por padrão (`box-sizing: content-box`), `width: 300px` vale só para o conteúdo; padding e borda somam por fora, e o card de 300px vira 342px. Quase todo projeto muda isso no início:

```css
/* estilos.css */
*,
*::before,
*::after {
  box-sizing: border-box;
}

body {
  margin: 0;
  font-family: system-ui, sans-serif;
  line-height: 1.5;
  color: var(--cor-texto);
  background: var(--cor-fundo);
}

img {
  max-width: 100%;
  height: auto;
  display: block;
}
```

Com `border-box`, `width` inclui padding e borda, e a conta fecha.

Outros pontos do box model que confundem:

- Elementos **block** (`div`, `p`, `section`) ocupam a linha inteira; **inline** (`span`, `a`) ignoram `width`, `height` e margens verticais. `inline-block` aceita tamanho sem quebrar a linha.
- Margens verticais de blocos vizinhos **colapsam**: 20px embaixo de um e 30px em cima do outro resultam em 30px, não 50px. Dentro de um contêiner flex ou grid isso não acontece.

## Variáveis CSS

Antes de estilizar, defina as decisões visuais num lugar só, com **custom properties**:

```css
/* estilos.css */
:root {
  --cor-primaria: #2e7d32;
  --cor-primaria-escura: #1b5e20;
  --cor-texto: #1f2933;
  --cor-fundo: #fafaf5;
  --cor-superficie: #ffffff;
  --raio: 12px;
  --espaco-1: 0.5rem;
  --espaco-2: 1rem;
  --espaco-3: 1.5rem;
  --sombra: 0 2px 8px rgb(0 0 0 / 0.08);
}
```

Trocar o verde da marca vira uma linha. Esta ideia cresce até os design tokens do Nível 3.

## Flexbox

Flexbox distribui itens em **uma dimensão** (linha ou coluna). Você ativa no **pai** com `display: flex`, e os filhos viram itens flexíveis.

| Propriedade (no pai) | Controla | Valores comuns |
|---|---|---|
| `flex-direction` | Eixo principal | `row`, `column` |
| `justify-content` | Distribuição no eixo principal | `flex-start`, `center`, `space-between` |
| `align-items` | Alinhamento no eixo cruzado | `stretch`, `center`, `flex-start` |
| `flex-wrap` | Quebra de linha | `nowrap`, `wrap` |
| `gap` | Espaço entre itens | `1rem` |

| Propriedade (no filho) | Controla |
|---|---|
| `flex-grow` | Quanto cresce para ocupar sobra |
| `flex-shrink` | Quanto encolhe quando falta espaço |
| `flex-basis` | Tamanho inicial antes de crescer ou encolher |
| `flex` | Atalho dos três: `flex: 1 1 220px` |

O cabeçalho: marca à esquerda, menu no meio, carrinho à direita, tudo centralizado na vertical.

```css
/* estilos.css */
.cabecalho {
  display: flex;
  align-items: center;
  justify-content: space-between;
  gap: var(--espaco-2);
  padding: var(--espaco-2) var(--espaco-3);
  background: var(--cor-superficie);
  box-shadow: var(--sombra);
}

.marca {
  display: flex;
  align-items: center;
  gap: var(--espaco-1);
  font-weight: 700;
  color: var(--cor-primaria);
  text-decoration: none;
}

.menu {
  display: flex;
  gap: var(--espaco-2);
  list-style: none;
  margin: 0;
  padding: 0;
}
```

A vitrine: cards que quebram de linha, cada um com no mínimo 220px.

```css
/* estilos.css */
.lista-produtos {
  display: flex;
  flex-wrap: wrap;
  gap: var(--espaco-3);
  list-style: none;
  padding: 0;
}

.lista-produtos > li {
  flex: 1 1 220px;
}

.produto {
  display: flex;
  flex-direction: column;
  height: 100%;
  padding: var(--espaco-2);
  background: var(--cor-superficie);
  border-radius: var(--raio);
  box-shadow: var(--sombra);
}

.produto .botao {
  margin-top: auto; /* empurra o botão para o fim do card */
}
```

O `margin-top: auto` num item flex absorve toda a sobra, alinhando os botões na base mesmo quando um nome de produto ocupa duas linhas. No capítulo de responsividade, esta grade passa para CSS Grid, que resolve a última linha "esticada" do `flex-wrap`.

## Estados interativos

```css
/* estilos.css */
.botao {
  padding: var(--espaco-1) var(--espaco-2);
  border: 0;
  border-radius: var(--raio);
  background: var(--cor-primaria);
  color: #fff;
  font: inherit;
  cursor: pointer;
  transition: background-color 150ms ease;
}

.botao:hover {
  background: var(--cor-primaria-escura);
}

.botao:focus-visible {
  outline: 3px solid #f9a825;
  outline-offset: 2px;
}
```

<Callout type="warning" title="Não remova o contorno de foco">
`outline: none` sem substituto deixa quem navega pelo teclado sem saber onde está. Use `:focus-visible`, que mostra o contorno ao navegar com Tab e o esconde no clique do mouse.
</Callout>

## Na entrevista

**O que é HTML semântico e por que importa?** É usar a tag que descreve o significado do conteúdo (`nav`, `main`, `article`, `button`) em vez de `div` genérica. Melhora acessibilidade (leitores de tela navegam por regiões e títulos), SEO e manutenção, e traz comportamento de graça, como foco e ativação por teclado no `button`.

**Como funciona a especificidade?** O navegador compara (IDs, classes/atributos/pseudoclasses, tipos) da esquerda para a direita. Em empate, vence a regra declarada por último. Estilo inline e `!important` passam por cima, por isso são exceção.

**Diferença entre `content-box` e `border-box`?** Em `content-box`, `width` define só o conteúdo e padding e borda somam por fora. Em `border-box`, `width` já inclui padding e borda, o que torna os tamanhos previsíveis.

**Como centralizar um elemento na horizontal e na vertical?** No pai, `display: flex; justify-content: center; align-items: center;`. Com Grid, `display: grid; place-items: center;`.

**Quando usar `section`, `article` e `div`?** `article` para conteúdo que faz sentido sozinho (um card de produto, um post); `section` para agrupar um tema com título; `div` quando o agrupamento é só para estilo, sem significado.

## Pratique

1. Monte a pasta `quitanda/` com `index.html` e `estilos.css`, abra pelo Live Server e valide o HTML no validador do W3C.
2. Escreva a vitrine com pelo menos seis produtos em duas seções (Frutas e Legumes), cada card com foto, `alt` descritivo, nome, preço e unidade.
3. Crie o reset com `box-sizing: border-box` e as variáveis de cor e espaço; troque o verde da marca e confira que a página inteira muda.
4. Faça o cabeçalho com Flexbox e, nas DevTools, ative o overlay de flex (o selo "flex" no painel Elements) para ver eixos e espaçamentos.
5. Crie uma regra que "não pega" de propósito por causa de especificidade e use o painel Styles para explicar qual regra venceu.
6. Navegue pela página só com Tab e Enter e confirme que todo link e botão tem foco visível.
