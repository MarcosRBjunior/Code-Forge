Até aqui, a vitrine da Quitanda é HTML escrito à mão: para cadastrar uma manga nova, alguém edita o `index.html`. E as funções de carrinho do capítulo anterior calculam tudo certo, mas só no console. Falta a ponte entre os dados e a tela: gerar os cards a partir do array de produtos, reagir ao clique em "Adicionar", atualizar o contador do carrinho, filtrar por categoria enquanto a pessoa digita na busca.

Essa ponte é o **DOM** (Document Object Model), a árvore de objetos que o navegador monta a partir do HTML e expõe ao JavaScript. Tudo que o React faz por baixo dos panos é manipular o DOM. Escrever essa manipulação à mão uma vez é a melhor forma de entender por que o React existe, e o que ele resolve, quando você chegar ao Nível 1.

**Você vai aprender:**

- Como o HTML vira uma árvore de nós e como selecionar elementos nela
- Ler e alterar texto, atributos, classes e `data-*` com segurança
- Criar elementos com `createElement` e com o elemento `template`
- Reagir a eventos e usar o objeto de evento, `preventDefault` e a propagação
- Aplicar delegação de eventos para listas que mudam
- Organizar o código em dados, funções de renderização e manipuladores de evento

## A árvore do DOM

O navegador lê o HTML e cria um objeto para cada tag, texto e comentário, encaixados numa árvore. O ponto de entrada é `document`:

```text
document
└── html
    ├── head
    │   └── title
    └── body
        ├── header.cabecalho
        │   └── a.link-carrinho  ("Carrinho (0)")
        └── main
            └── section.vitrine
                └── ul#lista-produtos
                    └── li > article.produto
```

Cada nó tem pai (`parentElement`), filhos (`children`) e irmãos (`nextElementSibling`). Alterar esses objetos altera a página imediatamente; o navegador recalcula o layout e repinta.

Na aba **Elements** das DevTools, selecione um elemento e digite `$0` no console: é uma referência para ele. Ótimo para experimentar antes de escrever o código.

## Selecionando elementos

| Método | Devolve | Exemplo |
|---|---|---|
| `document.querySelector(seletor)` | O primeiro elemento que casa, ou `null` | `document.querySelector(".link-carrinho")` |
| `document.querySelectorAll(seletor)` | Uma `NodeList` estática com todos | `document.querySelectorAll(".filtro")` |
| `document.getElementById(id)` | O elemento com o id, ou `null` | `document.getElementById("lista-produtos")` |
| `elemento.querySelector(seletor)` | Busca só dentro do elemento | `card.querySelector(".produto-preco")` |
| `elemento.closest(seletor)` | O ancestral mais próximo (ou ele mesmo) que casa | `botao.closest(".produto")` |

Os seletores são os mesmos do CSS. A `NodeList` de `querySelectorAll` aceita `forEach` e `for...of`; para usar `map` e `filter`, converta com `Array.from(lista)` ou `[...lista]`.

```js
// js/vitrine.js
const listaProdutos = document.querySelector("#lista-produtos");
const contador = document.querySelector("#contador-carrinho");
const campoBusca = document.querySelector("#busca");
const filtros = document.querySelectorAll(".filtro");
```

Se o seletor não encontrar nada, o resultado é `null`, e a próxima linha estoura com "Cannot read properties of null". A causa mais comum é o script rodar antes de o HTML existir; `defer` (ou `type="module"`) resolve.

## Lendo e alterando elementos

```js
// js/exemplos/dom.js
const titulo = document.querySelector("h1");

titulo.textContent = "Feira completa em casa";       // texto puro
titulo.classList.add("destaque-titulo");             // classes
titulo.classList.toggle("oculto", false);            // liga ou desliga com condição
titulo.setAttribute("aria-live", "polite");          // atributos
titulo.style.color = "var(--cor-primaria)";          // estilo inline (use pouco)

const botao = document.querySelector(".produto .botao");
botao.disabled = true;                               // propriedade booleana
console.log(botao.dataset.id);                       // lê data-id="2"
```

| Propriedade | Para que serve |
|---|---|
| `textContent` | Ler ou trocar o texto, sem interpretar HTML |
| `innerHTML` | Ler ou trocar o conteúdo como HTML |
| `classList` | `add`, `remove`, `toggle`, `contains` |
| `dataset` | Atributos `data-*` como objeto: `data-produto-id` vira `dataset.produtoId` |
| `hidden` | Esconde o elemento (equivale a `display: none`) |
| `value` | Valor atual de `input`, `select` e `textarea` |

Prefira trocar **classes** a mexer em `style`: o visual fica no CSS e o JavaScript só diz em que estado o elemento está.

<Callout type="warning" title="innerHTML com dados de fora é uma porta para XSS">
`card.innerHTML = produto.nome` interpreta o texto como HTML. Se o nome vier de um formulário ou de uma API e contiver uma tag de imagem com um atributo `onerror`, esse código roda na página de todos os clientes. Use `textContent` para qualquer dado que não seja HTML escrito por você. O React escapa os textos automaticamente por esse motivo.
</Callout>

## Criando elementos

A vitrine passa a ser gerada a partir do array `produtos` do capítulo anterior. No HTML fica só o contêiner vazio:

```html
<!-- index.html -->
<ul id="lista-produtos" class="lista-produtos" aria-live="polite"></ul>
<p id="vitrine-vazia" hidden>Nenhum produto encontrado.</p>
```

### Com createElement

```js
// js/vitrine.js
function criarCardProduto(produto) {
  const item = document.createElement("li");

  const card = document.createElement("article");
  card.className = "produto";
  card.dataset.id = produto.id;

  const foto = document.createElement("img");
  foto.src = produto.foto;
  foto.alt = produto.nome;
  foto.width = 300;
  foto.height = 200;
  foto.loading = "lazy";

  const nome = document.createElement("h3");
  nome.className = "produto-nome";
  nome.textContent = produto.nome;

  const preco = document.createElement("p");
  preco.className = "produto-preco";
  preco.textContent = `${formatarPreco(produto.precoEmCentavos)} / ${produto.unidade}`;

  const botao = document.createElement("button");
  botao.type = "button";
  botao.className = "botao";
  botao.dataset.acao = "adicionar";
  botao.disabled = produto.estoque === 0;
  botao.textContent = produto.estoque > 0 ? "Adicionar" : "Esgotado";

  card.append(foto, nome, preco, botao);
  item.append(card);
  return item;
}
```

É verboso, mas seguro e explícito. `append` aceita vários nós e textos de uma vez; `prepend`, `before`, `after`, `replaceWith` e `remove` completam o kit.

### Com template

O elemento `template` guarda HTML que o navegador não renderiza; o JavaScript clona e preenche:

```html
<!-- index.html -->
<template id="modelo-produto">
  <li>
    <article class="produto">
      <img alt="" width="300" height="200" loading="lazy" />
      <h3 class="produto-nome"></h3>
      <p class="produto-preco"></p>
      <button type="button" class="botao" data-acao="adicionar">Adicionar</button>
    </article>
  </li>
</template>
```

```js
// js/vitrine.js
const modelo = document.querySelector("#modelo-produto");

function criarCardProduto(produto) {
  const fragmento = modelo.content.cloneNode(true);
  const card = fragmento.querySelector(".produto");
  card.dataset.id = produto.id;
  card.querySelector("img").src = produto.foto;
  card.querySelector("img").alt = produto.nome;
  card.querySelector(".produto-nome").textContent = produto.nome;
  card.querySelector(".produto-preco").textContent =
    `${formatarPreco(produto.precoEmCentavos)} / ${produto.unidade}`;

  const botao = card.querySelector(".botao");
  botao.disabled = produto.estoque === 0;
  botao.textContent = produto.estoque > 0 ? "Adicionar" : "Esgotado";
  return fragmento;
}
```

O HTML continua no arquivo HTML, legível para quem cuida do layout, e o JavaScript só preenche. É a ideia que o JSX leva ao extremo.

### Renderizando a lista

```js
// js/vitrine.js
function renderizarProdutos(lista) {
  const itens = lista.map(criarCardProduto);
  listaProdutos.replaceChildren(...itens);
  document.querySelector("#vitrine-vazia").hidden = lista.length > 0;
}

renderizarProdutos(produtos);
```

`replaceChildren` remove o conteúdo antigo e insere o novo numa operação só. Inserir cem cards um por um num elemento visível força o navegador a trabalhar mais; montar a lista e inserir de uma vez é o hábito certo. Repare no formato: `lista.map(criarCardProduto)` transforma dados em elementos, exatamente o que você vai escrever em JSX.

## Eventos

O navegador dispara eventos para tudo: clique, tecla, envio de formulário, rolagem, carregamento. Você registra um **listener** com `addEventListener`:

```js
// js/vitrine.js
campoBusca.addEventListener("input", (evento) => {
  const termo = evento.target.value;
  renderizarProdutos(buscarProdutos(produtos, termo));
});
```

| Evento | Quando dispara |
|---|---|
| `click` | Clique, toque, ou Enter e Espaço num botão |
| `input` | A cada alteração do valor de um campo |
| `change` | Ao confirmar a alteração (sair do campo, escolher no select) |
| `submit` | Envio do formulário (no `form`, não no botão) |
| `keydown` | Tecla pressionada (`evento.key === "Escape"`) |
| `focus` / `blur` | Elemento ganha ou perde foco |
| `DOMContentLoaded` | HTML lido e DOM pronto |

O **objeto de evento** traz o contexto: `evento.target` é o elemento onde o evento nasceu, `evento.currentTarget` é o elemento que tem o listener, `evento.key` é a tecla. `evento.preventDefault()` cancela o comportamento padrão, como o envio do formulário com recarga da página.

### Propagação

Um clique no botão dentro do card dispara o evento no botão e depois ele **sobe** (bubbling) pelos ancestrais: `article`, `li`, `ul`, `main`, `body`, `document`. Qualquer um deles pode ouvir. `evento.stopPropagation()` interrompe a subida, mas raramente é necessário e costuma esconder bugs.

## Delegação de eventos

Os cards são recriados a cada busca. Se cada botão tiver o próprio listener, você precisa registrá-los de novo a cada renderização, e listeners de elementos removidos são lixo. A **delegação** registra um único listener no contêiner, que existe sempre, e descobre pelo `target` qual item foi clicado:

```js
// js/vitrine.js
let carrinho = [];

listaProdutos.addEventListener("click", (evento) => {
  const botao = evento.target.closest('[data-acao="adicionar"]');
  if (!botao) return; // o clique foi em outra parte do card

  const card = botao.closest(".produto");
  const produto = produtos.find((p) => p.id === card.dataset.id);
  if (!produto) return;

  carrinho = adicionarAoCarrinho(carrinho, produto, 1);
  atualizarCarrinho();
  anunciar(`${produto.nome} adicionado ao carrinho`);
});
```

`closest` sobe a partir do elemento clicado (que pode ser um ícone dentro do botão) até achar o botão. Um listener atende a lista inteira, inclusive aos cards que ainda não existem.

A função `adicionarAoCarrinho` é a do exercício do capítulo anterior, que devolve um array novo:

```js
// js/carrinho.js
function adicionarAoCarrinho(itens, produto, quantidade) {
  const existente = itens.find((item) => item.produtoId === produto.id);
  if (existente) {
    return itens.map((item) =>
      item.produtoId === produto.id
        ? { ...item, quantidade: item.quantidade + quantidade }
        : item,
    );
  }
  const { id, nome, precoEmCentavos, unidade } = produto;
  return [...itens, { produtoId: id, nome, precoEmCentavos, unidade, quantidade }];
}

function removerDoCarrinho(itens, produtoId) {
  return itens.filter((item) => item.produtoId !== produtoId);
}
```

## Atualizando a interface a partir do estado

O carrinho aparece em dois lugares: o contador no cabeçalho e o resumo lateral com os itens e o total. A regra que evita inconsistência é ter **uma fonte de verdade** (o array `carrinho`) e uma função que redesenha tudo a partir dela:

```html
<!-- index.html -->
<aside class="resumo-carrinho" aria-labelledby="titulo-carrinho">
  <h2 id="titulo-carrinho">Seu carrinho</h2>
  <ul id="itens-carrinho"></ul>
  <p>Total: <strong id="total-carrinho">R$ 0,00</strong></p>
</aside>
<p id="aviso-carrinho" class="sr-only" aria-live="polite"></p>
```

```js
// js/vitrine.js
const itensCarrinho = document.querySelector("#itens-carrinho");
const totalCarrinho = document.querySelector("#total-carrinho");
const aviso = document.querySelector("#aviso-carrinho");

function atualizarCarrinho() {
  const resumo = resumirCarrinho(carrinho);
  contador.textContent = `Carrinho (${resumo.quantidadeDeItens})`;
  totalCarrinho.textContent = formatarPreco(resumo.total);

  const linhas = carrinho.map((item) => {
    const li = document.createElement("li");
    li.dataset.id = item.produtoId;
    li.textContent = `${item.quantidade} ${item.unidade} de ${item.nome} `;

    const remover = document.createElement("button");
    remover.type = "button";
    remover.dataset.acao = "remover";
    remover.textContent = "Remover";
    remover.setAttribute("aria-label", `Remover ${item.nome} do carrinho`);

    li.append(remover);
    return li;
  });
  itensCarrinho.replaceChildren(...linhas);
}

itensCarrinho.addEventListener("click", (evento) => {
  const botao = evento.target.closest('[data-acao="remover"]');
  if (!botao) return;
  carrinho = removerDoCarrinho(carrinho, botao.closest("li").dataset.id);
  atualizarCarrinho();
});

function anunciar(mensagem) {
  aviso.textContent = mensagem;
}
```

Estado muda, função de renderização roda, tela reflete o estado. Esse ciclo (estado, renderização, evento que muda o estado) é o modelo mental do React. A diferença é que, à mão, você redesenha a lista inteira a cada mudança e precisa lembrar de chamar `atualizarCarrinho()` em todo lugar; o React descobre sozinho o que mudou.

<Callout type="tip" title="Uma fonte de verdade">
Nunca leia o estado de volta da tela (por exemplo, contar os `li` para saber quantos itens há no carrinho). A tela é consequência dos dados. Quando os dois divergem, o bug é quase sempre alguém ter alterado o DOM sem alterar o estado.
</Callout>

## Filtros por categoria

```html
<!-- index.html -->
<div class="filtros" role="group" aria-label="Filtrar por categoria">
  <button type="button" class="filtro" data-categoria="todas" aria-pressed="true">Todas</button>
  <button type="button" class="filtro" data-categoria="frutas" aria-pressed="false">Frutas</button>
  <button type="button" class="filtro" data-categoria="legumes" aria-pressed="false">Legumes</button>
</div>
```

```js
// js/vitrine.js
let categoriaAtual = "todas";

document.querySelector(".filtros").addEventListener("click", (evento) => {
  const botao = evento.target.closest(".filtro");
  if (!botao) return;

  categoriaAtual = botao.dataset.categoria;
  filtros.forEach((f) => f.setAttribute("aria-pressed", String(f === botao)));
  aplicarFiltros();
});

function aplicarFiltros() {
  const porCategoria =
    categoriaAtual === "todas"
      ? produtos
      : produtos.filter((p) => p.categoria === categoriaAtual);
  renderizarProdutos(buscarProdutos(porCategoria, campoBusca.value));
}
```

`aria-pressed` comunica ao leitor de tela qual filtro está ativo, e o CSS pode estilizar `[aria-pressed="true"]`, juntando estado visual e acessível num só atributo.

## Formulários com o DOM

O checkout do capítulo de formulários ganha mensagens próprias:

```js
// js/checkout.js
const formulario = document.querySelector("#form-checkout");

formulario.addEventListener("submit", (evento) => {
  evento.preventDefault();
  const cep = formulario.elements.cep;
  const erro = document.querySelector("#cep-erro");

  const valido = cep.checkValidity();
  erro.hidden = valido;
  cep.setAttribute("aria-invalid", String(!valido));
  if (!valido) {
    cep.focus();
    return;
  }

  const dados = Object.fromEntries(new FormData(formulario));
  console.log(dados); // { nome: "...", email: "...", cep: "...", entrega: "entrega", ... }
});
```

`FormData` lê todos os campos com `name` de uma vez, e `Object.fromEntries` transforma em objeto. Esse objeto vira o corpo do `POST /api/pedidos` no capítulo de CRUD.

## Na entrevista

**O que é o DOM?** É a representação do documento HTML como uma árvore de objetos que o navegador expõe ao JavaScript. Alterar esses objetos altera a página.

**Qual a diferença entre `textContent` e `innerHTML`?** `textContent` trata o valor como texto puro; `innerHTML` interpreta como HTML. Com dados de usuário ou de API, `innerHTML` abre espaço para XSS, então `textContent` é o padrão.

**O que é delegação de eventos?** Registrar um único listener num ancestral comum e identificar o item pelo `evento.target` (com `closest`). Funciona para elementos criados depois e reduz o número de listeners, aproveitando a propagação dos eventos.

**Diferença entre `target` e `currentTarget`?** `target` é onde o evento nasceu (o ícone dentro do botão, por exemplo); `currentTarget` é o elemento cujo listener está executando.

**Por que o React existe se dá para fazer tudo com o DOM?** Porque à mão você precisa lembrar de sincronizar cada pedaço da tela com o estado, e redesenhar tudo a cada mudança é ineficiente. O React deixa você descrever a tela em função do estado e calcula as alterações mínimas no DOM.

## Pratique

1. Apague os cards fixos do `index.html`, crie o `template` e renderize a vitrine a partir do array `produtos`.
2. Implemente a busca com o evento `input`, ignorando maiúsculas e acentos, e mostre a mensagem "Nenhum produto encontrado" quando a lista ficar vazia.
3. Adicione os botões de filtro por categoria com `aria-pressed` e faça busca e filtro funcionarem juntos.
4. Use delegação para "Adicionar" e "Remover" e mostre contador, itens e total do carrinho; anuncie as adições na região `aria-live`.
5. Coloque botões "+" e "−" em cada item do carrinho que alteram a quantidade (0,5 kg para itens em kg, 1 para itens em unidade) e removem o item ao chegar a zero.
6. No checkout, exiba as mensagens de erro de CEP e e-mail com `aria-invalid` e foque o primeiro campo inválido ao enviar.
