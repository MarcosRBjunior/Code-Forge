Depois de transformar textos em vetores, você precisa de uma régua: dado o vetor da pergunta, quais vetores da base estão "mais perto"? A escolha da métrica parece detalhe, mas configurar o índice com uma métrica diferente da usada no treino do modelo de embedding piora a busca sem gerar nenhum erro visível. Vale entender as três opções que aparecem em todo banco vetorial.

## As três métricas

- **Produto escalar** (dot product): soma dos produtos coordenada a coordenada. Cresce com o alinhamento **e** com o tamanho (norma) dos vetores.
- **Similaridade de cosseno:** o produto escalar dividido pelas normas. Mede só o ângulo entre os vetores, de -1 (opostos) a 1 (mesma direção), ignorando o tamanho.
- **Distância euclidiana (L2):** comprimento do segmento entre os dois pontos. Quanto menor, mais parecidos.

```text
cos(a, b) = (a · b) / (|a| · |b|)
L2(a, b)  = raiz( soma (a_i - b_i)² )
```

O exemplo mostra como a norma muda o resultado. O vetor `b` aponta exatamente na mesma direção que `a`, só que é três vezes maior; `c` aponta numa direção um pouco diferente.

<CodeTabs>

```python
import math

def dot(a, b):
    return sum(x * y for x, y in zip(a, b))

def norma(a):
    return math.sqrt(dot(a, a))

def cosseno(a, b):
    return dot(a, b) / (norma(a) * norma(b))

def l2(a, b):
    return math.sqrt(sum((x - y) ** 2 for x, y in zip(a, b)))

a = [1.0, 2.0, 0.0]
b = [3.0, 6.0, 0.0]   # mesma direcao que a, 3x maior
c = [1.0, 1.5, 0.8]   # direcao diferente, tamanho parecido com a

for nome, v in (("b", b), ("c", c)):
    print(f"a vs {nome}: dot={dot(a, v):.2f} cos={cosseno(a, v):.3f} l2={l2(a, v):.2f}")
```

## Normalização unifica tudo

Se todos os vetores tiverem norma 1, as três métricas passam a ordenar os vizinhos **da mesma forma**: o cosseno vira o próprio produto escalar, e a distância euclidiana ao quadrado vira `2 - 2·cos`. Por isso muitos modelos de embedding já devolvem vetores normalizados, e muitos sistemas normalizam na ingestão e usam produto escalar, que é a conta mais barata.

<CodeTabs>

```python
import math

def normalizar(v):
    n = math.sqrt(sum(x * x for x in v))
    return [x / n for x in v]

def dot(a, b):
    return sum(x * y for x, y in zip(a, b))

def l2(a, b):
    return math.sqrt(sum((x - y) ** 2 for x, y in zip(a, b)))

consulta = normalizar([0.9, 0.3, 0.1])
base = {
    "doc_frete": normalizar([0.8, 0.4, 0.0]),
    "doc_senha": normalizar([0.1, 0.2, 0.9]),
    "doc_prazo": normalizar([0.7, 0.1, 0.4]),
}

por_dot = sorted(base, key=lambda k: -dot(consulta, base[k]))
por_l2 = sorted(base, key=lambda k: l2(consulta, base[k]))
print("ranking por dot:", por_dot)
print("ranking por L2: ", por_l2)
for k in por_dot:
    cos = dot(consulta, base[k])
    print(f"{k}: cos={cos:.3f} l2^2={l2(consulta, base[k]) ** 2:.3f} 2-2cos={2 - 2 * cos:.3f}")
```

import java.util.*;

static double[] normalizar(double[] v) {
    double s = 0;
    for (double x : v) s += x * x;
    double n = Math.sqrt(s);
    double[] r = new double[v.length];
    for (int i = 0; i < v.length; i++) r[i] = v[i] / n;
    return r;
}

static double dot(double[] a, double[] b) {
    double s = 0;
    for (int i = 0; i < a.length; i++) s += a[i] * b[i];
    return s;
}

static double l2(double[] a, double[] b) {
    double s = 0;
    for (int i = 0; i < a.length; i++) s += (a[i] - b[i]) * (a[i] - b[i]);
    return Math.sqrt(s);
}

public static void main(String[] args) {
    double[] consulta = normalizar(new double[]{0.9, 0.3, 0.1});
    LinkedHashMap<String, double[]> base = new LinkedHashMap<>();
    base.put("doc_frete", normalizar(new double[]{0.8, 0.4, 0.0}));
    base.put("doc_senha", normalizar(new double[]{0.1, 0.2, 0.9}));
    base.put("doc_prazo", normalizar(new double[]{0.7, 0.1, 0.4}));

    // List.sort é estável, como o sorted do Python
    List<String> porDot = new ArrayList<>(base.keySet());
    porDot.sort(Comparator.comparingDouble(k -> -dot(consulta, base.get(k))));
    List<String> porL2 = new ArrayList<>(base.keySet());
    porL2.sort(Comparator.comparingDouble(k -> l2(consulta, base.get(k))));
    System.out.println("ranking por dot: " + porDot);
    System.out.println("ranking por L2:  " + porL2);
    for (String k : porDot) {
        double cos = dot(consulta, base.get(k));
        double d = l2(consulta, base.get(k));
        System.out.println(String.format(Locale.US, "%s: cos=%.3f l2^2=%.3f 2-2cos=%.3f", k, cos, d * d, 2 - 2 * cos));
    }
}

import (
	"fmt"
	"math"
	"sort"
)

func normalizar(v []float64) []float64 {
	s := 0.0
	for _, x := range v {
		s += x * x
	}
	n := math.Sqrt(s)
	r := make([]float64, len(v))
	for i, x := range v {
		r[i] = x / n
	}
	return r
}

func dot(a, b []float64) float64 {
	s := 0.0
	for i := range a {
		s += a[i] * b[i]
	}
	return s
}

func l2(a, b []float64) float64 {
	s := 0.0
	for i := range a {
		s += (a[i] - b[i]) * (a[i] - b[i])
	}
	return math.Sqrt(s)
}

func main() {
	consulta := normalizar([]float64{0.9, 0.3, 0.1})
	nomes := []string{"doc_frete", "doc_senha", "doc_prazo"} // ordem de inserção do dict
	base := map[string][]float64{
		"doc_frete": normalizar([]float64{0.8, 0.4, 0.0}),
		"doc_senha": normalizar([]float64{0.1, 0.2, 0.9}),
		"doc_prazo": normalizar([]float64{0.7, 0.1, 0.4}),
	}

	// SliceStable, como o sorted do Python
	porDot := append([]string{}, nomes...)
	sort.SliceStable(porDot, func(i, j int) bool { return -dot(consulta, base[porDot[i]]) < -dot(consulta, base[porDot[j]]) })
	porL2 := append([]string{}, nomes...)
	sort.SliceStable(porL2, func(i, j int) bool { return l2(consulta, base[porL2[i]]) < l2(consulta, base[porL2[j]]) })
	fmt.Printf("ranking por dot: %q\n", porDot)
	fmt.Printf("ranking por L2:  %q\n", porL2)
	for _, k := range porDot {
		cos := dot(consulta, base[k])
		d := l2(consulta, base[k])
		fmt.Printf("%s: cos=%.3f l2^2=%.3f 2-2cos=%.3f\n", k, cos, d*d, 2-2*cos)
	}
}

## Qual usar

| Situação | Métrica |
| --- | --- |
| Vetores já normalizados (caso mais comum em embeddings de texto) | Produto escalar (equivale ao cosseno, é mais barato) |
| Vetores sem normalização e você só quer a direção | Cosseno |
| A norma carrega informação útil (alguns modelos de recomendação, popularidade) | Produto escalar sem normalizar |
| Dados geométricos, agrupamento com k-means | Euclidiana |

A regra de ouro: use a métrica que a documentação do modelo de embedding recomenda, porque foi ela que o treino otimizou.

<Callout type="warning" title="Limiar de similaridade não é universal">
Um cosseno de 0,8 pode ser "quase idêntico" num modelo e "vagamente relacionado" em outro. Cada modelo tem sua própria distribuição de scores. Se você usa limiar (para cache semântico ou para descartar resultados fracos), calibre com pares rotulados do seu domínio e recalibre ao trocar de modelo.
</Callout>

## Armadilhas

- **Maldição da dimensionalidade:** em muitas dimensões, as distâncias tendem a se concentrar, e a diferença entre o mais próximo e o mais distante encolhe. Os scores absolutos dizem pouco; o ranking diz mais.
- **Comparar scores entre consultas:** um top-1 com 0,62 numa pergunta pode ser ótimo, e um com 0,75 noutra, ruim.
- **Misturar métricas:** indexar pensando em cosseno e configurar o índice como L2 sem normalizar os vetores.
- **Custo:** a busca exata calcula a métrica contra todos os vetores (O(N·d)). Com milhões de vetores, entram os índices aproximados do próximo capítulo.
