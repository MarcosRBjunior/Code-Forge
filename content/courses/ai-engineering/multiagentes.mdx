Um único agente com 40 ferramentas, um system prompt de 5 páginas e um histórico que cresce a cada passo começa a se perder: escolhe a ferramenta errada, esquece instruções e enche o contexto de resultados irrelevantes. Uma resposta é dividir o trabalho entre vários agentes, cada um com um papel, poucas ferramentas e um contexto limpo. Isso é um **sistema multiagente**. A ideia é poderosa, mas também é uma das formas mais fáceis de multiplicar custo e complexidade sem ganho real.

## Por que dividir

- **Contexto isolado:** cada subagente vê só o que precisa. Uma pesquisa que lê 30 páginas devolve ao coordenador um resumo de 10 linhas, não as 30 páginas.
- **Especialização:** prompts e ferramentas focados num papel (pesquisador, programador, revisor) funcionam melhor do que um prompt que tenta cobrir tudo.
- **Paralelismo:** subtarefas independentes rodam ao mesmo tempo, reduzindo a latência total.
- **Separação de permissões:** o agente que lê e-mails não precisa da ferramenta que faz pagamentos.

## Padrões comuns

```text
ORQUESTRADOR E TRABALHADORES          PIPELINE                 GERADOR E CRÍTICO
        orquestrador                  A ──► B ──► C            gerador ──► crítico
       /     |      \                                              ▲          │
  trab. 1  trab. 2  trab. 3                                        └─ ajustes ┘
       \     |      /
         síntese
```

- **Orquestrador e trabalhadores:** um agente decompõe a tarefa, delega subtarefas e sintetiza os resultados. Bom para pesquisa ampla e tarefas paralelizáveis.
- **Roteamento e handoff:** um agente de triagem identifica a intenção e passa a conversa a um especialista (cobrança, suporte técnico).
- **Pipeline:** etapas fixas, cada uma feita por um agente. Na prática é um workflow.
- **Gerador e crítico:** um produz, outro avalia com critérios explícitos, e o ciclo se repete até aprovar ou atingir um limite.

O programa simula o orquestrador com trabalhadores em paralelo. Os "agentes" são funções determinísticas, mas a estrutura (decompor, executar com contexto isolado, sintetizar) é a de um sistema real.

from concurrent.futures import ThreadPoolExecutor

FONTES = {
    "preco": "Concorrente A cobra 49 por mês; concorrente B cobra 59 por mês.",
    "recursos": "A tem integração com ERP; B tem app mobile e API pública.",
    "reclamacoes": "A recebe queixas de suporte lento; B de cobrança duplicada.",
}

def orquestrador_planejar(tarefa):
    return [f"pesquisar {aspecto}" for aspecto in FONTES]

def trabalhador(subtarefa):
    aspecto = subtarefa.split()[-1]
    contexto = FONTES[aspecto]                 # só o que esse trabalhador precisa
    resumo = contexto.split(";")[0]           # "resumir": devolve algo curto
    return {"aspecto": aspecto, "resumo": resumo, "tokens_lidos": len(contexto.split())}

def sintetizar(resultados):
    return " | ".join(f"{r['aspecto']}: {r['resumo']}" for r in resultados)

tarefa = "Compare os concorrentes A e B"
subtarefas = orquestrador_planejar(tarefa)
with ThreadPoolExecutor(max_workers=3) as pool:
    resultados = list(pool.map(trabalhador, subtarefas))   # map preserva a ordem

for r in resultados:
    print(f"{r['aspecto']:12s} leu {r['tokens_lidos']} palavras, devolveu: {r['resumo']}")
print("síntese:", sintetizar(resultados))

import java.util.*;
import java.util.concurrent.*;

static final Map<String, String> FONTES = new LinkedHashMap<>();
static {
    FONTES.put("preco", "Concorrente A cobra 49 por mês; concorrente B cobra 59 por mês.");
    FONTES.put("recursos", "A tem integração com ERP; B tem app mobile e API pública.");
    FONTES.put("reclamacoes", "A recebe queixas de suporte lento; B de cobrança duplicada.");
}

static class Resultado {
    String aspecto, resumo;
    int tokensLidos;
    Resultado(String aspecto, String resumo, int tokensLidos) {
        this.aspecto = aspecto;
        this.resumo = resumo;
        this.tokensLidos = tokensLidos;
    }
}

static List<String> orquestradorPlanejar(String tarefa) {
    List<String> subtarefas = new ArrayList<>();
    for (String aspecto : FONTES.keySet()) subtarefas.add("pesquisar " + aspecto);
    return subtarefas;
}

static Resultado trabalhador(String subtarefa) {
    String[] partes = subtarefa.split(" ");
    String aspecto = partes[partes.length - 1];
    String contexto = FONTES.get(aspecto);          // só o que esse trabalhador precisa
    String resumo = contexto.split(";")[0];         // "resumir": devolve algo curto
    return new Resultado(aspecto, resumo, contexto.split("\\s+").length);
}

static String sintetizar(List<Resultado> resultados) {
    StringJoiner j = new StringJoiner(" | ");
    for (Resultado r : resultados) j.add(r.aspecto + ": " + r.resumo);
    return j.toString();
}

public static void main(String[] args) throws Exception {
    String tarefa = "Compare os concorrentes A e B";
    List<String> subtarefas = orquestradorPlanejar(tarefa);
    ExecutorService pool = Executors.newFixedThreadPool(3);
    List<Callable<Resultado>> trabalhos = new ArrayList<>();
    for (String s : subtarefas) trabalhos.add(() -> trabalhador(s));
    List<Resultado> resultados = new ArrayList<>();
    for (Future<Resultado> f : pool.invokeAll(trabalhos)) resultados.add(f.get());  // invokeAll preserva a ordem
    pool.shutdown();

    for (Resultado r : resultados) {
        System.out.println(String.format("%-12s leu %d palavras, devolveu: %s", r.aspecto, r.tokensLidos, r.resumo));
    }
    System.out.println("síntese: " + sintetizar(resultados));
}

using System.Collections.Generic;
using System.Linq;
using System.Threading.Tasks;

static readonly Dictionary<string, string> Fontes = new Dictionary<string, string>
{
    ["preco"] = "Concorrente A cobra 49 por mês; concorrente B cobra 59 por mês.",
    ["recursos"] = "A tem integração com ERP; B tem app mobile e API pública.",
    ["reclamacoes"] = "A recebe queixas de suporte lento; B de cobrança duplicada.",

class Resultado
{
    public string Aspecto, Resumo;
    public int TokensLidos;
}

static List<string> OrquestradorPlanejar(string tarefa)
{
    return Fontes.Keys.Select(aspecto => $"pesquisar {aspecto}").ToList();
}

static Resultado Trabalhador(string subtarefa)
{
    string aspecto = subtarefa.Split(' ').Last();
    string contexto = Fontes[aspecto];              // só o que esse trabalhador precisa
    string resumo = contexto.Split(';')[0];         // "resumir": devolve algo curto
    int total = contexto.Split((char[])null, StringSplitOptions.RemoveEmptyEntries).Length;
    return new Resultado { Aspecto = aspecto, Resumo = resumo, TokensLidos = total };
}

static string Sintetizar(IEnumerable<Resultado> resultados)
{
    return string.Join(" | ", resultados.Select(r => $"{r.Aspecto}: {r.Resumo}"));

import (
	"fmt"
	"strings"
	"sync"
)

// slice: guarda a ordem de inserção, que um map do Go não guarda
type Fonte struct {
	Aspecto  string
	Contexto string
}

var FONTES = []Fonte{
	{"preco", "Concorrente A cobra 49 por mês; concorrente B cobra 59 por mês."},
	{"recursos", "A tem integração com ERP; B tem app mobile e API pública."},
	{"reclamacoes", "A recebe queixas de suporte lento; B de cobrança duplicada."},
}

type Resultado struct {
	Aspecto     string
	Resumo      string
	TokensLidos int
}

func orquestradorPlanejar(tarefa string) []string {
	subtarefas := []string{}
	for _, f := range FONTES {
		subtarefas = append(subtarefas, "pesquisar "+f.Aspecto)
	}
	return subtarefas
}

func trabalhador(subtarefa string) Resultado {
	partes := strings.Fields(subtarefa)
	aspecto := partes[len(partes)-1]
	contexto := "" // só o que esse trabalhador precisa
	for _, f := range FONTES {
		if f.Aspecto == aspecto {
			contexto = f.Contexto
		}
	}
	resumo := strings.Split(contexto, ";")[0] // "resumir": devolve algo curto
	return Resultado{aspecto, resumo, len(strings.Fields(contexto))}
}

func sintetizar(resultados []Resultado) string {
	partes := []string{}
	for _, r := range resultados {
		partes = append(partes, r.Aspecto+": "+r.Resumo)
	}
	return strings.Join(partes, " | ")
}

func main() {
	tarefa := "Compare os concorrentes A e B"
	subtarefas := orquestradorPlanejar(tarefa)
	resultados := make([]Resultado, len(subtarefas))
	var wg sync.WaitGroup
	for i, s := range subtarefas {
		wg.Add(1)
		go func(i int, s string) {
			defer wg.Done()
			resultados[i] = trabalhador(s) // cada goroutine grava no próprio índice: a ordem se mantém
		}(i, s)
	}
	wg.Wait()

	for _, r := range resultados {
		fmt.Printf("%-12s leu %d palavras, devolveu: %s\n", r.Aspecto, r.TokensLidos, r.Resumo)
	}
	fmt.Println("síntese:", sintetizar(resultados))
}

## Gerador e crítico

Separar quem escreve de quem avalia ajuda porque o crítico recebe critérios objetivos e não está "comprometido" com o texto. O exemplo usa regras simples no lugar de um LLM crítico.

		"Olá! Seu reembolso foi aprovado e cai em até 10 dias úteis.",
		"Olá! Seu reembolso de R$ 120 foi aprovado e cai em até 10 dias úteis.",
	}
	return rascunhos[tentativa]
}

func critico(texto string) []string {
	problemas := []string{}
	if !strings.Contains(texto, "dias") {
		problemas = append(problemas, "falta o prazo")
	}
	if !strings.Contains(texto, "R$") {
		problemas = append(problemas, "falta o valor")
	}
	return problemas
}

func main() {
	feedback := []string{}
	for tentativa := 0; tentativa < 3; tentativa++ {
		texto := gerador(tentativa, feedback)
		feedback = critico(texto)
		if len(feedback) == 0 {
			fmt.Printf("tentativa %d: aprovado\n", tentativa+1)
			fmt.Println("final:", texto)
			break
		}
		fmt.Printf("tentativa %d: %q\n", tentativa+1, feedback)
	}
}

## Os custos reais

- **Tokens:** cada agente tem seu system prompt, ferramentas e raciocínio. Sistemas multiagente costumam gastar várias vezes mais tokens que um agente único na mesma tarefa.
- **Perda de informação entre agentes:** o resumo que o trabalhador devolve pode omitir justo o detalhe decisivo. Defina o formato do que cada um retorna.
- **Coordenação:** trabalhadores podem duplicar esforço ou tomar decisões conflitantes (dois agentes editando o mesmo arquivo). Tarefas com muita dependência entre partes se beneficiam pouco.
- **Depuração:** um erro pode nascer num agente e aparecer três agentes depois. Sem tracing com a árvore de chamadas, é quase impossível investigar.

<Callout type="tip" title="Comece com um agente">
Só divida quando houver um motivo mensurável: contexto que não cabe, subtarefas independentes e paralelizáveis, ou permissões que precisam ser separadas. Um agente bem desenhado com boas ferramentas resolve a maioria dos casos com menos custo.
</Callout>
