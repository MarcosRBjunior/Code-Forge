O RAG básico (embeda a pergunta, pega o top-k, gera) funciona bem quando a pergunta do usuário se parece com o texto do documento e a resposta está num trecho só. Na prática, usuários escrevem perguntas vagas, com gírias ou siglas, e fazem perguntas que exigem juntar informações de lugares diferentes. As técnicas avançadas atacam essas falhas em três pontos: **antes** da busca (a consulta), **durante** a indexação (os chunks) e **depois** da busca (verificação e iteração).

## Melhorando a consulta

- **Reescrita:** um LLM transforma a mensagem do usuário numa consulta autocontida. Em chat, isso resolve referências ("e para o plano anual?" vira "política de reembolso do plano anual").
- **Multi-query:** gera várias formulações da mesma pergunta, busca cada uma e funde os resultados (por RRF). Aumenta o recall quando o vocabulário do usuário difere do da documentação.
- **HyDE:** pede ao LLM uma resposta hipotética e busca com o embedding dela, já que uma resposta se parece mais com um documento do que uma pergunta. Cuidado: se o modelo inventar algo muito errado, a busca vai junto.
- **Roteamento:** decide em qual índice ou fonte buscar (manual técnico, base de tickets, banco SQL) antes da recuperação.

O programa mostra multi-query: a pergunta original usa "grana de volta", que não aparece nos documentos; as reformulações (que aqui vêm de uma tabela fixa, no lugar de um LLM) trazem o vocabulário certo.

```python
import re

DOCS = {
    "d1": "Reembolso é feito em até 10 dias úteis após aprovação.",
    "d2": "Estorno no cartão aparece na fatura seguinte.",
    "d3": "Cancelamento pode ser feito pelo aplicativo.",
    "d4": "Frete grátis para compras acima de 200 reais.",
}
REFORMULACOES = {  # num sistema real, um LLM gera estas variações
    "quando recebo minha grana de volta": [
        "prazo do reembolso ou estorno",
        "quando o estorno do reembolso aparece no cartão",
    ],
}

def buscar(consulta, k=2):
    q = set(re.findall(r"\w+", consulta.lower()))
    scores = {d: len(q & set(re.findall(r"\w+", t.lower()))) for d, t in DOCS.items()}
    return [d for d, s in sorted(scores.items(), key=lambda kv: -kv[1]) if s > 0][:k]

def rrf(listas, k=60):
    pontos = {}
    for lista in listas:
        for pos, d in enumerate(lista, start=1):
            pontos[d] = pontos.get(d, 0) + 1 / (k + pos)
    return sorted(pontos, key=lambda d: -pontos[d])

pergunta = "quando recebo minha grana de volta"
print("só a original:", buscar(pergunta))
consultas = [pergunta] + REFORMULACOES[pergunta]
for c in consultas:
    print(f"  {c!r} -> {buscar(c)}")
print("multi-query + RRF:", rrf([buscar(c) for c in consultas]))
```

```java
import java.util.*;
import java.util.regex.*;

// UNICODE_CHARACTER_CLASS faz o \w aceitar letras acentuadas, como no Python
static final Pattern PALAVRA = Pattern.compile("\\w+", Pattern.UNICODE_CHARACTER_CLASS);

static final Map<String, String> DOCS = new LinkedHashMap<>();
static final Map<String, List<String>> REFORMULACOES = new HashMap<>();  // num sistema real, um LLM gera estas variações
static {
    DOCS.put("d1", "Reembolso é feito em até 10 dias úteis após aprovação.");
    DOCS.put("d2", "Estorno no cartão aparece na fatura seguinte.");
    DOCS.put("d3", "Cancelamento pode ser feito pelo aplicativo.");
    DOCS.put("d4", "Frete grátis para compras acima de 200 reais.");
    REFORMULACOES.put("quando recebo minha grana de volta", Arrays.asList(
        "prazo do reembolso ou estorno",
        "quando o estorno do reembolso aparece no cartão"));
}

static Set<String> termos(String t) {
    Set<String> s = new HashSet<>();
    Matcher m = PALAVRA.matcher(t.toLowerCase(Locale.ROOT));
    while (m.find()) s.add(m.group());
    return s;
}

static List<String> buscar(String consulta, int k) {
    Set<String> q = termos(consulta);
    Map<String, Integer> scores = new LinkedHashMap<>();
    for (Map.Entry<String, String> e : DOCS.entrySet()) {
        Set<String> comuns = new HashSet<>(q);
        comuns.retainAll(termos(e.getValue()));
        scores.put(e.getKey(), comuns.size());
    }
    List<String> ids = new ArrayList<>(scores.keySet());
    // List.sort é estável, como o sorted do Python
    ids.sort(Comparator.comparingInt(d -> -scores.get(d)));
    List<String> saida = new ArrayList<>();
    for (String d : ids) {
        if (scores.get(d) > 0 && saida.size() < k) saida.add(d);
    }
    return saida;
}

static List<String> rrf(List<List<String>> listas, int k) {
    Map<String, Double> pontos = new LinkedHashMap<>();
    for (List<String> lista : listas) {
        for (int i = 0; i < lista.size(); i++) {
            int pos = i + 1;
            pontos.merge(lista.get(i), 1.0 / (k + pos), Double::sum);
        }
    }
    List<String> ids = new ArrayList<>(pontos.keySet());
    ids.sort(Comparator.comparingDouble(d -> -pontos.get(d)));
    return ids;
}

static String mostrar(List<String> lista) {
    List<String> partes = new ArrayList<>();
    for (String d : lista) partes.add("'" + d + "'");
    return "[" + String.join(", ", partes) + "]";
}

public static void main(String[] args) {
    String pergunta = "quando recebo minha grana de volta";
    System.out.println("só a original: " + mostrar(buscar(pergunta, 2)));
    List<String> consultas = new ArrayList<>();
    consultas.add(pergunta);
    consultas.addAll(REFORMULACOES.get(pergunta));
    List<List<String>> resultados = new ArrayList<>();
    for (String c : consultas) {
        System.out.println("  '" + c + "' -> " + mostrar(buscar(c, 2)));
        resultados.add(buscar(c, 2));
    }
    System.out.println("multi-query + RRF: " + mostrar(rrf(resultados, 60)));
}
```

```cpp
#include <cctype>
#include <cstdio>
#include <map>
#include <set>
#include <string>
#include <utility>
#include <vector>
using namespace std;

vector<pair<string, string>> DOCS = {
    {"d1", "Reembolso é feito em até 10 dias úteis após aprovação."},
    {"d2", "Estorno no cartão aparece na fatura seguinte."},
    {"d3", "Cancelamento pode ser feito pelo aplicativo."},
    {"d4", "Frete grátis para compras acima de 200 reais."},
};
map<string, vector<string>> REFORMULACOES = {  // num sistema real, um LLM gera estas variações
    {"quando recebo minha grana de volta", {
        "prazo do reembolso ou estorno",
        "quando o estorno do reembolso aparece no cartão",
    }},
};

// imita set(re.findall(r"\w+", t.lower())): o std::regex não entende UTF-8, então a
// tokenização é à mão; bytes >= 0x80 (pedaços de letras acentuadas) contam como letra
set<string> termos(const string& t) {
    set<string> saida;
    string atual;
    for (unsigned char c : t) {
        if (isalnum(c) || c == '_' || c >= 0x80) {
            atual += (char)(c < 0x80 ? tolower(c) : c);
        } else if (!atual.empty()) {
            saida.insert(atual);
            atual.clear();
        }
    }
    if (!atual.empty()) saida.insert(atual);
    return saida;
}

vector<string> buscar(const string& consulta, size_t k = 2) {
    set<string> q = termos(consulta);
    vector<pair<string, int>> scores;
    for (const auto& [d, t] : DOCS) {
        set<string> palavras = termos(t);
        int comuns = 0;
        for (const string& x : q) comuns += palavras.count(x);
        scores.push_back({d, comuns});
    }
    // stable_sort mantém a ordem original nos empates, como o sorted do Python
    stable_sort(scores.begin(), scores.end(), [](const auto& a, const auto& b) { return a.second > b.second; });
    vector<string> saida;
    for (const auto& [d, s] : scores)
        if (s > 0 && saida.size() < k) saida.push_back(d);
    return saida;
}

vector<string> rrf(const vector<vector<string>>& listas, int k = 60) {
    vector<string> ordem;  // ordem de inserção do dict do Python
    map<string, double> pontos;
    for (const auto& lista : listas) {
        for (size_t i = 0; i < lista.size(); i++) {
            int pos = i + 1;
            if (!pontos.count(lista[i])) ordem.push_back(lista[i]);
            pontos[lista[i]] += 1.0 / (k + pos);
        }
    }
    stable_sort(ordem.begin(), ordem.end(), [&](const string& a, const string& b) { return pontos[a] > pontos[b]; });
    return ordem;
}

string mostrar(const vector<string>& lista) {
    string s = "[";
    for (size_t i = 0; i < lista.size(); i++) s += (i ? ", '" : "'") + lista[i] + "'";
    return s + "]";
}

int main() {
    string pergunta = "quando recebo minha grana de volta";
    printf("só a original: %s\n", mostrar(buscar(pergunta)).c_str());
    vector<string> consultas = {pergunta};
    for (const string& r : REFORMULACOES[pergunta]) consultas.push_back(r);
    vector<vector<string>> resultados;
    for (const string& c : consultas) {
        printf("  '%s' -> %s\n", c.c_str(), mostrar(buscar(c)).c_str());
        resultados.push_back(buscar(c));
    }
    printf("multi-query + RRF: %s\n", mostrar(rrf(resultados)).c_str());
}
```

```csharp
static Dictionary<string, string> DOCS = new Dictionary<string, string> {
    ["d1"] = "Reembolso é feito em até 10 dias úteis após aprovação.",
    ["d2"] = "Estorno no cartão aparece na fatura seguinte.",
    ["d3"] = "Cancelamento pode ser feito pelo aplicativo.",
    ["d4"] = "Frete grátis para compras acima de 200 reais.",
};
static Dictionary<string, string[]> REFORMULACOES = new Dictionary<string, string[]> {  // num sistema real, um LLM gera estas variações
    ["quando recebo minha grana de volta"] = new[] {
        "prazo do reembolso ou estorno",
        "quando o estorno do reembolso aparece no cartão",
    },
};

// o \w do .NET já aceita letras acentuadas, como o do Python
static HashSet<string> Termos(string t) {
    return new HashSet<string>(Regex.Matches(t.ToLowerInvariant(), @"\w+").Cast<Match>().Select(m => m.Value));
}

static List<string> Buscar(string consulta, int k = 2) {
    var q = Termos(consulta);
    // OrderBy é estável, como o sorted do Python
    return DOCS.Select(par => new { Id = par.Key, Score = q.Intersect(Termos(par.Value)).Count() })
        .OrderBy(x => -x.Score)
        .Where(x => x.Score > 0)
        .Select(x => x.Id)
        .Take(k)
        .ToList();
}

static List<string> Rrf(List<List<string>> listas, int k = 60) {
    var pontos = new Dictionary<string, double>();
    foreach (var lista in listas) {
        for (int i = 0; i < lista.Count; i++) {
            int pos = i + 1;
            pontos.TryGetValue(lista[i], out double atual);
            pontos[lista[i]] = atual + 1.0 / (k + pos);
        }
    }
    return pontos.Keys.OrderBy(id => -pontos[id]).ToList();
}

static string Mostrar(List<string> lista) {
    return "[" + string.Join(", ", lista.Select(id => $"'{id}'")) + "]";
}

static void Main() {
    string pergunta = "quando recebo minha grana de volta";
    Console.WriteLine("só a original: " + Mostrar(Buscar(pergunta)));
    var consultas = new List<string> { pergunta };
    consultas.AddRange(REFORMULACOES[pergunta]);
    foreach (string c in consultas) {
        Console.WriteLine($"  '{c}' -> {Mostrar(Buscar(c))}");
    }
    var resultados = consultas.Select(x => Buscar(x)).ToList();
    Console.WriteLine("multi-query + RRF: " + Mostrar(Rrf(resultados)));
}
```

```go
// fatia de pares: o dict do Python mantém a ordem de inserção, o map do Go não
var docs = []struct{ id, texto string }{
	{"d1", "Reembolso é feito em até 10 dias úteis após aprovação."},
	{"d2", "Estorno no cartão aparece na fatura seguinte."},
	{"d3", "Cancelamento pode ser feito pelo aplicativo."},
	{"d4", "Frete grátis para compras acima de 200 reais."},
}
var reformulacoes = map[string][]string{ // num sistema real, um LLM gera estas variações
	"quando recebo minha grana de volta": {
		"prazo do reembolso ou estorno",
		"quando o estorno do reembolso aparece no cartão",
	},
}

// o \w do Go só conhece ASCII; \p{L}\p{N} aceita letras acentuadas, como o \w do Python
var palavra = regexp.MustCompile(`[\p{L}\p{N}_]+`)

func termos(t string) map[string]bool {
	s := map[string]bool{}
	for _, w := range palavra.FindAllString(strings.ToLower(t), -1) {
		s[w] = true
	}
	return s
}

type pontuado struct {
	id    string
	score int
}

func buscar(consulta string, k int) []string {
	q := termos(consulta)
	scores := []pontuado{}
	for _, d := range docs {
		palavras := termos(d.texto)
		comuns := 0
		for x := range q {
			if palavras[x] {
				comuns++
			}
		}
		scores = append(scores, pontuado{d.id, comuns})
	}
	// SliceStable mantém a ordem original nos empates, como o sorted do Python
	sort.SliceStable(scores, func(i, j int) bool { return scores[i].score > scores[j].score })
	saida := []string{}
	for _, p := range scores {
		if p.score > 0 && len(saida) < k {
			saida = append(saida, p.id)
		}
	}
	return saida
}

func rrf(listas [][]string, k int) []string {
	ordem := []string{} // ordem de inserção do dict do Python
	pontos := map[string]float64{}
	for _, lista := range listas {
		for i, d := range lista {
			pos := i + 1
			if _, existe := pontos[d]; !existe {
				ordem = append(ordem, d)
			}
			pontos[d] += 1.0 / float64(k+pos)
		}
	}
	sort.SliceStable(ordem, func(i, j int) bool { return pontos[ordem[i]] > pontos[ordem[j]] })
	return ordem
}

func mostrar(lista []string) string {
	partes := []string{}
	for _, d := range lista {
		partes = append(partes, "'"+d+"'")
	}
	return "[" + strings.Join(partes, ", ") + "]"
}

func main() {
	pergunta := "quando recebo minha grana de volta"
	fmt.Println("só a original:", mostrar(buscar(pergunta, 2)))
	consultas := append([]string{pergunta}, reformulacoes[pergunta]...)
	resultados := [][]string{}
	for _, c := range consultas {
		fmt.Printf("  '%s' -> %s\n", c, mostrar(buscar(c, 2)))
		resultados = append(resultados, buscar(c, 2))
	}

}
```

A pergunta original só casou com um documento irrelevante, por causa da palavra "de". As variações encontraram os dois relevantes, e a fusão os coloca acima do ruído.

## Melhorando os chunks

- **Contexto no chunk:** antes de embedar, gere (com um LLM) uma ou duas frases situando o trecho no documento ("Este trecho é da seção de reembolso do contrato do plano empresarial") e prefixe ao chunk. Resolve chunks que, sozinhos, são ambíguos.
- **Recuperar pequeno, entregar grande:** indexe chunks pequenos, mas entregue ao LLM a seção ou os vizinhos.
- **Índices de resumos e perguntas:** indexe também um resumo de cada documento ou perguntas que o trecho responde, apontando para o original.
- **Grafo de conhecimento (GraphRAG):** extraia entidades e relações e combine busca no grafo com busca vetorial. Ajuda em perguntas sobre relações e em perguntas globais ("quais os temas principais destes relatórios?"), com custo de ingestão bem maior.

## Iterando: multi-hop e RAG agêntico

Algumas perguntas exigem encadear buscas: "quem é o gestor do time que mantém o serviço de pagamentos?" Primeiro você descobre o time, depois o gestor do time. Nenhuma busca única encontra a resposta. A solução é **decompor** a pergunta e usar a resposta de um passo na consulta do próximo, deixando um LLM (ou um agente) decidir quando já tem informação suficiente.

```python
BASE = [
    "O serviço de pagamentos é mantido pelo time Atlas.",
    "O serviço de busca é mantido pelo time Orion.",
    "O time Atlas tem como gestora a Marina Souza.",
    "O time Orion tem como gestor o Paulo Lima.",
]

def buscar(termo):
    return [t for t in BASE if termo.lower() in t.lower()]

def llm_falso_planejar(pergunta, fatos):
    # roteiro fixo: no lugar de um LLM que decide o próximo passo
    if not fatos:
        return ("buscar", "serviço de pagamentos")
    if len(fatos) == 1:
        time = fatos[0].split("time ")[1].rstrip(".")
        return ("buscar", f"time {time} tem")
    return ("responder", fatos[-1].split("gestora a ")[1].rstrip("."))

pergunta = "Quem é a gestora do time que mantém o serviço de pagamentos?"
fatos = []
for passo in range(1, 4):
    acao, arg = llm_falso_planejar(pergunta, fatos)
    if acao == "responder":
        print(f"resposta: {arg}")
        break
    achados = buscar(arg)
    print(f"passo {passo}: buscar({arg!r}) -> {achados}")
    fatos.extend(achados)
```

```javascript

  "O serviço de pagamentos é mantido pelo time Atlas.",
```

```cpp
// imita s.split(sep)[1].rstrip("."): o trecho entre a 1ª e a 2ª ocorrência, sem pontos no fim
string segundoPedaco(const string& s, const string& sep) {
    size_t ini = s.find(sep) + sep.size();
    size_t fim = s.find(sep, ini);
    string pedaco = s.substr(ini, fim == string::npos ? string::npos : fim - ini);
    while (!pedaco.empty() && pedaco.back() == '.') pedaco.pop_back();
    return pedaco;
}
```

Variações desse padrão incluem o **RAG corretivo** (avaliar se os trechos são relevantes e, se não forem, reformular ou buscar em outra fonte) e a **autoverificação** (checar se cada afirmação da resposta tem suporte nos trechos antes de devolvê-la).

<Callout type="warning" title="Cada técnica custa latência">
Reescrita, multi-query, HyDE e verificação adicionam chamadas de LLM em série. Um pipeline com quatro etapas extras pode multiplicar a latência. Adicione técnicas uma a uma, medindo ganho de qualidade contra custo, e use modelos pequenos nas etapas auxiliares.
</Callout>

## Como escolher

| Sintoma | Técnica |
| --- | --- |
| Usuário escreve diferente da documentação | Reescrita, multi-query, busca híbrida |
| Perguntas de acompanhamento em chat | Reescrita com o histórico |
| Chunk certo, mas ambíguo sozinho | Contexto no chunk, título prefixado |
| Resposta depende de várias fontes encadeadas | Decomposição, multi-hop, RAG agêntico |
| Perguntas globais sobre o corpus inteiro | Resumos hierárquicos, GraphRAG |
| Respostas com afirmações sem suporte | Verificação de fidelidade, citações obrigatórias |

## Na entrevista

Não liste técnicas aleatoriamente: diagnostique primeiro (a falha é de consulta, de chunk ou de raciocínio entre fontes?) e associe a técnica ao sintoma, com o custo de latência. Follow-ups: "como você sabe que o multi-query ajudou?" (recall@k no conjunto de avaliação, antes e depois) e "quando usar um agente em vez de um pipeline fixo?" (quando o número de buscas e as fontes variam por pergunta; caso contrário, pipeline fixo é mais barato e previsível).
