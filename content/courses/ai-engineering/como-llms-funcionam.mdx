Você não precisa treinar um modelo para construir produtos com LLMs, mas precisa de um modelo mental correto do que acontece dentro dele. Quase todo comportamento estranho que você vai depurar (respostas inventadas, instruções ignoradas, custo que explode com o tamanho do prompt) se explica por uma ideia simples: um LLM é uma função que recebe uma sequência de tokens e devolve uma distribuição de probabilidade para o **próximo** token.

## Prever o próximo token

Durante o pré-treinamento, o modelo lê uma quantidade enorme de texto e é ajustado para acertar a palavra seguinte. Não existe banco de fatos nem consulta a uma tabela: o conhecimento fica espalhado em bilhões de pesos, como padrões estatísticos. Para gerar uma resposta, o sistema repete um laço:

```text
prompt ──► [modelo] ──► probabilidades do próximo token
                              │
                     escolhe um token (amostragem)
                              │
          prompt + token ◄────┘   (repete até um token de fim ou um limite)
```

Esse laço é chamado de geração **autorregressiva**. Cada token novo depende de todos os anteriores, por isso a saída sai em streaming, um pedaço por vez, e gerar mil tokens custa bem mais tempo do que ler mil tokens.

O programa abaixo faz a mesma coisa em miniatura: conta quais palavras seguem quais num corpus pequeno (um modelo de bigramas) e gera texto escolhendo sempre a mais provável.

```python
from collections import Counter, defaultdict

corpus = (
    "o cache guarda respostas . o cache reduz custo . "
    "o modelo gera tokens . o modelo gera texto . o token seguinte ."
).split()

seguintes = defaultdict(Counter)
for atual, prox in zip(corpus, corpus[1:]):
    seguintes[atual][prox] += 1

def probabilidades(palavra):
    total = sum(seguintes[palavra].values())
    return {p: round(c / total, 2) for p, c in seguintes[palavra].most_common()}

print("depois de 'o':", probabilidades("o"))

def gerar(inicio, passos):
    saida = [inicio]
    for _ in range(passos):
        candidatos = seguintes[saida[-1]]
        if not candidatos:
            break
        saida.append(candidatos.most_common(1)[0][0])
    return " ".join(saida)

print(gerar("o", 4))
```

```java
import java.math.BigDecimal;
import java.math.RoundingMode;
import java.util.*;

// palavra -> (seguinte -> contagem); LinkedHashMap guarda a ordem de inserção, como o Counter
static Map<String, LinkedHashMap<String, Integer>> seguintes = new LinkedHashMap<>();

// como most_common: maior contagem primeiro; List.sort é estável e mantém a ordem de inserção no empate
static List<Map.Entry<String, Integer>> maisComuns(Map<String, Integer> cont) {
    List<Map.Entry<String, Integer>> lista = new ArrayList<>(cont.entrySet());
    lista.sort((a, b) -> b.getValue() - a.getValue());
    return lista;
}

// round() do Python: arredonda o valor exato do double, com empate para o par
static double arred(double x, int casas) {
    return new BigDecimal(x).setScale(casas, RoundingMode.HALF_EVEN).doubleValue();
}

static String probabilidades(String palavra) {
    Map<String, Integer> cont = seguintes.getOrDefault(palavra, new LinkedHashMap<>());
    int total = 0;
    for (int c : cont.values()) total += c;
    List<String> partes = new ArrayList<>();
    for (Map.Entry<String, Integer> e : maisComuns(cont)) {
        double p = arred((double) e.getValue() / total, 2);
        partes.add("'" + e.getKey() + "': " + p);
    }
    return "{" + String.join(", ", partes) + "}";
}

static String gerar(String inicio, int passos) {
    List<String> saida = new ArrayList<>(List.of(inicio));
    for (int i = 0; i < passos; i++) {
        Map<String, Integer> candidatos = seguintes.get(saida.get(saida.size() - 1));
        if (candidatos == null || candidatos.isEmpty()) break;
        saida.add(maisComuns(candidatos).get(0).getKey());
    }
    return String.join(" ", saida);
}

    String[] corpus = ("o cache guarda respostas . o cache reduz custo . "
            + "o modelo gera tokens . o modelo gera texto . o token seguinte .").split(" ");

    for (int i = 0; i + 1 < corpus.length; i++) {
        seguintes.computeIfAbsent(corpus[i], k -> new LinkedHashMap<>()).merge(corpus[i + 1], 1, Integer::sum);

    System.out.println("depois de 'o': " + probabilidades("o"));
    System.out.println(gerar("o", 4));
}
```

```csharp
using System;
using System.Collections.Generic;
using System.Globalization;
using System.Linq;

// palavra -> lista (seguinte, contagem) na ordem de inserção, como o Counter do Python
static Dictionary<string, List<KeyValuePair<string, int>>> seguintes = new Dictionary<string, List<KeyValuePair<string, int>>>();

static void Somar(string atual, string prox)
{
    if (!seguintes.ContainsKey(atual)) seguintes[atual] = new List<KeyValuePair<string, int>>();
    var cont = seguintes[atual];
    int i = cont.FindIndex(kv => kv.Key == prox);
    if (i >= 0) cont[i] = new KeyValuePair<string, int>(prox, cont[i].Value + 1);
    else cont.Add(new KeyValuePair<string, int>(prox, 1));
}

// como most_common: maior contagem primeiro; OrderBy é estável e mantém a ordem de inserção no empate
static List<KeyValuePair<string, int>> MaisComuns(List<KeyValuePair<string, int>> cont)
{
    return cont.OrderByDescending(kv => kv.Value).ToList();
}

// o F2 do C# arredonda a forma decimal curta, e o Math.Round(x, 2) multiplica por 100 antes (2.675 vira 267.5);
// o Python arredonda o valor binário exato do double, com empate para o par. Aqui o valor exato
// (mantissa * 2^expoente) é montado em decimal, com 28 dígitos, e arredondado para o par.
static string FixoPar(double x, int casas) {
    long bits = BitConverter.DoubleToInt64Bits(Math.Abs(x));
    int campo = (int)(bits >> 52);
    decimal d = bits & 0xFFFFFFFFFFFFFL;
    if (campo > 0) d += 1L << 52;
    for (int e = Math.Max(campo, 1) - 1075; e > 0; e--) d *= 2;
    for (int e = Math.Max(campo, 1) - 1075; e < 0; e++) d /= 2;
    if (x < 0) d = -d;
    return Math.Round(d, casas, MidpointRounding.ToEven).ToString("F" + casas, CultureInfo.InvariantCulture);
}

// round() do Python: o mesmo arredondamento, de volta para double
static double Arred(double x, int casas) {
    return double.Parse(FixoPar(x, casas), CultureInfo.InvariantCulture);
}

static string Probabilidades(string palavra)
{
    var cont = seguintes.ContainsKey(palavra) ? seguintes[palavra] : new List<KeyValuePair<string, int>>();
    int total = cont.Sum(kv => kv.Value);
    var partes = MaisComuns(cont).Select(kv => "'" + kv.Key + "': " +
        Arred((double)kv.Value / total, 2).ToString(CultureInfo.InvariantCulture));
    return "{" + string.Join(", ", partes) + "}";
}

static string Gerar(string inicio, int passos)
{
    var saida = new List<string> { inicio };
    for (int i = 0; i < passos; i++)
    {
        string ultima = saida[saida.Count - 1];
        if (!seguintes.ContainsKey(ultima) || seguintes[ultima].Count == 0) break;
        saida.Add(MaisComuns(seguintes[ultima])[0].Key);
    }
    return string.Join(" ", saida);
}

static void Main()
{
    string[] corpus = ("o cache guarda respostas . o cache reduz custo . " +
        "o modelo gera tokens . o modelo gera texto . o token seguinte .").Split(' ');

    for (int i = 0; i + 1 < corpus.Length; i++) Somar(corpus[i], corpus[i + 1]);

    Console.WriteLine("depois de 'o': " + Probabilidades("o"));
    Console.WriteLine(Gerar("o", 4));
}
```

```go
import (
	"fmt"
	"sort"
	"strconv"
	"strings"

// par (seguinte, contagem); o slice guarda a ordem de inserção, como o Counter do Python
type Contagem struct {
	Palavra string
	N       int
}

var seguintes = map[string][]Contagem{}

func somar(atual, prox string) {
	cont := seguintes[atual]
	for i := range cont {
		if cont[i].Palavra == prox {
			cont[i].N++
			return
		}
	}
	seguintes[atual] = append(cont, Contagem{prox, 1})
}

// como most_common: maior contagem primeiro; SliceStable mantém a ordem de inserção no empate
func maisComuns(cont []Contagem) []Contagem {
	r := append([]Contagem{}, cont...)
	sort.SliceStable(r, func(i, j int) bool { return r[i].N > r[j].N })
	return r
}

// round() do Python: o strconv arredonda o valor exato do double, com empate para o par
func arred(x float64, casas int) float64 {
	r, _ := strconv.ParseFloat(strconv.FormatFloat(x, 'f', casas, 64), 64)
	return r
}

func probabilidades(palavra string) string {
	cont := seguintes[palavra]
	total := 0
	for _, c := range cont {
		total += c.N
	}
	partes := []string{}
	for _, c := range maisComuns(cont) {
		p := arred(float64(c.N)/float64(total), 2)
		partes = append(partes, fmt.Sprintf("'%s': %v", c.Palavra, p))
	}
	return "{" + strings.Join(partes, ", ") + "}"
}

func gerar(inicio string, passos int) string {
	saida := []string{inicio}
	for i := 0; i < passos; i++ {
		candidatos := seguintes[saida[len(saida)-1]]
		if len(candidatos) == 0 {
			break
		}
		saida = append(saida, maisComuns(candidatos)[0].Palavra)
	}
	return strings.Join(saida, " ")
}

func main() {
	corpus := strings.Fields("o cache guarda respostas . o cache reduz custo . " +
		"o modelo gera tokens . o modelo gera texto . o token seguinte .")

	for i := 0; i+1 < len(corpus); i++ {
		somar(corpus[i], corpus[i+1])
	}

	fmt.Println("depois de 'o':", probabilidades("o"))
	fmt.Println(gerar("o", 4))
}
```

Um LLM real troca a contagem por uma rede neural que olha para o contexto inteiro, não só para a palavra anterior, mas a interface é a mesma: contexto entra, distribuição sai.

## Por dentro do transformer

A arquitetura dominante é o **transformer**. Em alto nível:

1. O texto vira tokens, e cada token vira um vetor (embedding) somado a uma informação de posição.
2. Uma pilha de camadas aplica **atenção**: cada posição calcula o quanto deve "olhar" para cada posição anterior e mistura os vetores com esses pesos. É assim que "ele" consegue se referir a um substantivo três frases atrás.
3. A última camada produz um número (logit) por token do vocabulário, e uma **softmax** transforma esses números em probabilidades.

A atenção é, no fundo, um produto escalar seguido de softmax. Veja a conta para uma única consulta:

<CodeTabs>

```python
import math

def softmax(xs):
    m = max(xs)
    exps = [math.exp(x - m) for x in xs]
    s = sum(exps)
    return [e / s for e in exps]

# vetores de "chave" de três tokens anteriores e a "consulta" do token atual
chaves = {"gato": [1.0, 0.2], "subiu": [0.1, 1.0], "telhado": [0.9, 0.4]}
consulta = [1.0, 0.3]
d = len(consulta)

scores = [sum(q * k for q, k in zip(consulta, v)) / math.sqrt(d) for v in chaves.values()]
pesos = softmax(scores)
for token, p in zip(chaves, pesos):
    print(f"{token:8s} peso = {p:.3f}")
```

```java
import java.math.*;
import java.util.*;

// o %.2f do Java arredonda a forma decimal curta e leva o empate para cima; o Python arredonda o valor
// binário exato do double (o que o construtor BigDecimal(double) guarda), com empate para o par
static String fixoPar(double x, int casas) {
    return new BigDecimal(x).setScale(casas, RoundingMode.HALF_EVEN).toPlainString();
}

static double[] softmax(double[] xs) {
    double m = Arrays.stream(xs).max().getAsDouble();
    double[] exps = new double[xs.length];
    double s = 0;
    for (int i = 0; i < xs.length; i++) {
        exps[i] = Math.exp(xs[i] - m);
        s += exps[i];
    }
    for (int i = 0; i < exps.length; i++) exps[i] /= s;
    return exps;
}
```

```csharp
// o F2 do C# arredonda a forma decimal curta, e o Math.Round(x, 2) multiplica por 100 antes (2.675 vira 267.5);
// o Python arredonda o valor binário exato do double, com empate para o par. Aqui o valor exato
// (mantissa * 2^expoente) é montado em decimal, com 28 dígitos, e arredondado para o par.
static string FixoPar(double x, int casas) {
    long bits = BitConverter.DoubleToInt64Bits(Math.Abs(x));
    int campo = (int)(bits >> 52);
    decimal d = bits & 0xFFFFFFFFFFFFFL;
    if (campo > 0) d += 1L << 52;
    for (int e = Math.Max(campo, 1) - 1075; e > 0; e--) d *= 2;
    for (int e = Math.Max(campo, 1) - 1075; e < 0; e++) d /= 2;
    if (x < 0) d = -d;
    return Math.Round(d, casas, MidpointRounding.ToEven).ToString("F" + casas, CultureInfo.InvariantCulture);
}

static double[] Softmax(double[] xs)
{
    double m = xs.Max();
    double[] exps = xs.Select(x => Math.Exp(x - m)).ToArray();
    double s = 0;
    foreach (double e in exps) s += e;
    return exps.Select(e => e / s).ToArray();
}
```

```go
func softmax(xs []float64) []float64 {
	m := math.Inf(-1)
	for _, x := range xs {
		m = math.Max(m, x)
	}
	exps := make([]float64, len(xs))
	s := 0.0
	for i, x := range xs {
		exps[i] = math.Exp(x - m)
		s += exps[i]
	}
	for i := range exps {
		exps[i] /= s
	}
	return exps
}
```

Num modelo real isso acontece em dezenas de camadas, com várias "cabeças" de atenção em paralelo e vetores com milhares de dimensões. O custo da atenção cresce com o quadrado do tamanho do contexto, um dos motivos de contextos longos serem caros.

## Do modelo base ao assistente

O modelo que sai do pré-treinamento só completa texto. Para virar um assistente que segue instruções, ele passa por **ajuste fino supervisionado** com exemplos de conversa e por alguma forma de **aprendizado por preferências** (como RLHF), em que respostas melhores são reforçadas. É nessa fase que surgem o formato de chat, as recusas e o estilo de resposta.

<Callout type="note" title="O modelo não tem memória entre chamadas">
A API é sem estado: cada requisição envia o histórico inteiro da conversa. A "memória" de um chat é a sua aplicação reenviando as mensagens anteriores, e cada uma delas custa tokens de novo.
</Callout>

## Consequências práticas

- **Alucinação:** o modelo gera o texto mais plausível, não o mais verdadeiro. Sem fonte no contexto, ele preenche lacunas com algo que soa certo.
- **Corte de conhecimento:** o que aconteceu depois do treinamento não está nos pesos. Para dados atuais ou privados, você precisa colocar a informação no prompt (é a ideia do RAG).
- **Não determinismo:** a etapa de escolha do token normalmente sorteia, então a mesma pergunta pode ter respostas diferentes.
- **Custo proporcional a tokens:** entrada e saída são cobradas e medidas em tokens, e a latência cresce com o tamanho da saída.
